**목적·설명** — PDCA 세트(업무 묶음) 단위로 업무문서 현황을 한눈에 보는 목록 화면이다. 대메뉴(법령 분류)별로 세트를 묶고, 세트 안의 문서를 PDCA 단계(계획·실행·점검·조치)로 정리해 보여준다. 상단에서 분류 기준(기존 분류 ↔ 법적의무 재분류)을 전환할 수 있으며, 기본은 법적의무 재분류 기준이다. 재분류 기준에서는 세트별 PDCA 구성의 적정성(정상·주의·오류)을 검증 배너로 함께 표시한다. 같은 세트·문서 데이터를 **두 가지 형태**로 본다 — 업무 목록(테이블형, docs-preset.html)과 이행 목록(격자 카드형, docs-exec.html)이며, 둘은 같은 구성 요소의 레이아웃 변형이다(데이터·필터·툴바·검증 배너 동일, 표시 형태만 다름).

목록은 조회·검색·이동에 더해 **등록·수정·삭제 진입점**을 제공한다 — 툴바의 [+ 업무 등록] 버튼으로 등록 마법사를 열고(SCR-DOC-007), 사용자가 등록한 문서 행에서는 [편집]·[삭제]를 직접 수행한다. 기본 제공(시드) 문서는 조회만 가능하다. 문서를 클릭하면 문서 상세로 이동하며, 문서의 처리 유형(전자문서·첨부파일·프로그램)에 따라 상세에서의 작업이 달라진다.

분류 기준별 규모는 화면 표기상 **법적의무 재분류(v2)=9대메뉴·53세트**, **기존 분류(v1)=51세트**로 안내된다.

**사용자 시나리오**

| 단계 | 사용자 행동 | 화면 반응 |
|:--:|---|---|
| 1 | 업무 목록 진입 | 분류 기준(기본: 법적의무 재분류)으로 대메뉴별 세트 카드 + PDCA 단계별 문서 표 표시. 재분류 기준이면 검증 요약(정상·주의·오류) 배너 노출 |

| 4 | (무결성 오류 발생 시) [구성 오류만 보기] | 주의·오류로 표시된 세트만 노출(다시 누르면 [전체 보기]) |
| 5 | [+ 업무 등록] | 등록 마법사 팝업 열림(현재 선택된 대메뉴가 기본값) → 저장 시 목록 즉시 재구성(SCR-DOC-007) |
| 6 | (사용자 등록 문서 행) [편집] / [삭제] | [편집]은 기존 값이 채워진 수정 팝업, [삭제]는 삭제 확인 팝업 |
| 7 | 문서명 또는 행 액션 클릭 | 문서 상세로 이동(처리유형에 따라 입력/미리보기/이동 형태가 달라짐) |
| 8 | [목록 다운로드] | 다운로드 안내 표시(현재 프로토타입은 고정 파일명 안내만 표시) |

**분기 로직**

- **분류 기준을 바꾸면 목록이 통째로 다시 구성된다** — 세트 구성·세트 수·검증 배너가 모두 그 기준의 것으로 바뀐다. 화면 이동이 아니라 같은 화면의 재구성이며, 어느 기준으로 보고 있는지가 항상 화면에 남는다.
- **검증 배너는 재분류 기준에서만 나온다** — 기존 기준에는 세트 무결성 판정이 없기 때문이다. 현재 V2는 53세트 모두 정상이며, 향후 주의·오류가 생길 때만 건수와 해당 세트를 나열하고 [구성 오류만 보기]를 제공한다.
- **[구성 오류만 보기]는 정상 세트를 감춘다** — 실제 무결성 오류가 있을 때만 나타나며, 계획 질문이나 운영 적용성 검토를 뜻하지 않는다.
- **네 가지 조회 조건은 서로 독립이고 함께 걸린다** — 대메뉴 탭 · 검색어(문서명·담당자) · 상태 · PDCA 단계는 모두 만족하는 문서만 남긴다.
- **표시 단위가 목록형과 격자형으로 갈린다** — 같은 세트·문서를 업무 목록은 PDCA 단계별 표로, 이행 목록은 진행률 바와 단계 도트를 가진 카드로 보여준다. 데이터는 같고 보는 방식만 다르다.
- **문서마다 이동 방식이 갈린다** — 문서를 고르면 처리유형에 따라 첨부파일은 미리보기, 전자문서는 입력 폼, 프로그램은 연결 화면 안내로 나뉜다(SCR-DOC-004~006).
- **사용자가 등록한 문서에만 편집·삭제가 붙는다** — 기본 제공 문서는 조회만 되며 행에 편집 수단이 나타나지 않는다.

**엣지케이스**

- **조건에 맞는 문서가 0건이면** 표 자리에 "조건에 맞는 문서가 없습니다" 안내를 둔다.
- **V2에서 문서가 없는 PDCA 단계도 행을 남긴다** — `문서 없음`을 표시해 빠진 단계를 감추지 않는다. G4·H1의 A처럼 조건부 조치인 경우에는 `미흡 발생 시 개선조치 메뉴에 A 조치 생성`을 표시한다. 기존 V1 비교 조회만 원래 행 구성을 유지한다.
- **세트가 없는 과거 저장 문서는 "세트 지정 필요" 묶음으로 따로 모은다** — 신규 등록은 세트를 필수로 검사하므로 정상 경로에서는 생기지 않는다. 이전 버전·오류 데이터만 감추지 않고 교정 대상으로 표시한다.
- **검색은 문서명과 담당자 두 곳을 함께 본다** — 담당자 이름으로 자기 업무를 찾는 동선이 실제로 쓰이기 때문이다.
- **세트 카드의 진행률은 확정된 문서 수로 센다** — 전자문서는 확정 상태를, 그 밖은 완료 상태를 완료로 본다. 두 계열의 상태 용어가 달라 한쪽만 세면 진행률이 실제보다 낮게 나온다.
- **[목록 다운로드]는 현재 안내만 표시한다** — 조회 조건이 반영되는지, 어느 항목이 포함되는지는 §6에서 확정했다.

## 4. 화면 구성별 정리

### 4-1. 상단 — 분류 기준 전환 / PDCA 검증 배너
- 구성: 분류 기준 토글(라벨 "분류 버전" + 버튼 2개: [기존 분류 (51세트)] / [법적의무 재분류 v2 (53세트)], 현재 기준 버튼에 선택 표시), (재분류 기준 + 전체 목록 화면에서만) PDCA 검증 배너. 대메뉴 화면에 끼워 넣은 형태(메뉴 임베드)에서는 분류 토글·검증 배너·대메뉴 탭을 표시하지 않는다.
- 검증 배너 문구: 현재 V2 53세트는 모두 정상이다. G4·H1처럼 C 뒤 A문서가 상시 존재하지 않는 세트는 미흡 발생 시 개선조치 메뉴에 A 조치를 생성하는 조건부 후속 규칙으로 완결한다. 향후 데이터 변경으로 계획(P) 누락 등 실제 무결성 오류가 생길 때만 경고 건수·세트 ID와 [경고 세트만 보기]를 표시한다.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 분류 기준 토글 | 선택한 기준의 세트 구성으로 목록 전체를 다시 구성(대메뉴 탭·검색·필터 모두 초기화) | 화면 내 재구성(이동 없음) |
| 검증 배너(재분류) | 세트 PDCA 구성의 정상·주의·오류 건수와 해당 세트ID를 요약 표시 | 주의·오류 세트는 카드 헤더에 경고 배지 표시 |
| [구성 오류만 보기] | 주의·오류 세트만 노출, 라벨이 [전체 보기]로 바뀜 | 오류가 있을 때만 표시 |

- 상태: 기본 분류 기준은 법적의무 재분류이며, 기존 분류는 토글 또는 URL 지정으로 본다. 검증 판정 규칙·후속 처리는 §6 참조.

### 4-2. 툴바 — 검색·필터
- 구성: 대메뉴 탭([전체] + 9개 대메뉴), 문서명·담당자 검색 입력 + [검색] 버튼, 상태 셀렉트(상태 전체·완료·진행·미시행), PDCA 단계 필터 버튼군([전체]·P 계획·D 실행·C 점검·A 조치), 요약 텍스트("세트 N개 · 문서 M건 · 9개 대메뉴"), [+ 업무 등록] 버튼(재분류 기준 + 등록 기능 사용 시 노출), [목록 다운로드] 버튼. 기존 V1 비교 조회에서만 과거 `미확정` 필터가 추가된다.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 대메뉴 탭 | 해당 대메뉴 세트만 표시 | — |
| 문서명·담당자 검색 | 입력 즉시 부분일치로 좁힘([검색] 버튼은 표시용, 입력만으로 즉시 반영) | 0건이면 "조건에 맞는 문서가 없습니다" |
| 상태 셀렉트 | 선택한 상태(완료/진행/미시행)의 문서만 표시 | — |
| PDCA 단계 필터 | 선택 단계(P·D·C·A)의 문서만 표시 | 기존 V1 비교 조회에서만 미확정 추가 |
| [+ 업무 등록] | 등록 마법사 팝업 열림(현재 선택된 대메뉴 기본값), 저장 후 목록 재구성 | SCR-DOC-007 |
| [목록 다운로드] | 다운로드 안내 표시 | 4-5 참조 |

- 상태: 대메뉴 탭 + 검색 + 상태 + PDCA 단계 + (무결성 경고가 있을 때) 경고 세트만 보기 조합이 함께 적용된다. 분류 기준을 바꾸면 모든 필터가 초기화된다. V2 기본·신규 문서는 P·D·C·A 중 하나가 필수이며, 과거 V1 비교 조회에서만 미확정이 보인다. 결과 0건·로딩·조회 실패는 공통 상태 규칙을 따른다.

### 4-3. 세트 카드 목록(테이블형)
- 카드 헤더 구성: 대메뉴 칩 + 세트명 + (기준문서 세트인 경우) "기준문서" 칩 + "N건 · 완료 M" + (재분류) PDCA 흐름 배지(예: P·D·C·A) + (재분류) 검증 배지(주의 ⚠ / 오류 ⛔, 검증 사유를 툴팁으로 표시) + (선행 관계가 있으면) "선행: …" 표기 + (세트 보조 설명이 있으면) 회색 보조 텍스트.
- 본문 표 구성: V2는 PDCA 단계(P 계획·D 실행·C 점검·A 조치) 순으로 그룹화하고 빈 단계도 `문서 없음` 또는 조건부 후속 규칙으로 표시한다. 기존 V1 비교 조회는 원래 문서가 있는 미확정·단계 없음 그룹을 추가한다. 단계 칸은 묶어서 표시한다. 행 컬럼: 문서명(링크)·담당자·부서·수정일·상태칩·액션열.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|

## 6. 정책

- **정본은 법적의무 재분류 기준 하나다(TBD-002 확정)** — 법적의무 재분류(9대메뉴·53세트)를 정본으로 하고 등록·집계·상태 판정을 전부 이 기준으로 한다. **기존 분류(51세트)는 조회 전용으로만 남긴다** — 과거 문서를 그 이름으로 찾는 사람이 있어 없애면 길이 끊기지만, 두 기준에서 모두 등록·집계를 받으면 같은 문서가 기준마다 다른 자리에 놓여 어느 쪽이 실제 현황인지 알 수 없게 된다. 전환은 눈에 잘 띄는 토글이 아니라 **조회 조건 안의 한 항목**으로 내려 기본 화면에서는 정본만 보이게 한다.
- **세트 없는 과거 데이터는 감추지 않고 맨 아래 따로 모은다(TBD-003 확정)** — 신규 등록은 세트 필수이므로 새 미지정 문서는 만들지 않는다. 이전 버전·오류 데이터가 있으면 **"세트 지정 필요" 그룹을 목록 맨 아래 두고 건수를 함께** 표시하며 편집에서 세트를 지정하게 한다. 교정 전 문서는 PDCA 집계에서 제외하되 전체 원본 건수에는 포함한다.
- **사용자 등록 문서 구분** — 사용자가 등록한 문서는 기본 제공(시드) 문서와 구분해 관리하며, [편집]·[삭제]는 사용자 등록 문서에 한한다(기본 제공 문서는 조회만). 사용자 등록 문서는 새로고침 후에도 유지되고 기본 제공 문서 원본은 변경되지 않는다. 등록·수정·삭제 결과는 업무 목록·이행 목록·문서 상세에 동일하게 즉시 반영된다(SCR-DOC-007 연계).
- **등록·수정·삭제 동선** — [+ 업무 등록]·[편집]은 업무 등록·수정 마법사(SCR-DOC-007)로, [삭제]는 같은 확인 흐름으로 연결된다.
- **처리유형에 따른 표시·동작** — 상태칩과 완료 집계가 처리유형에 따라 갈린다(전자문서=작성중/등록완료/확정 및 확정 기준 집계, 그 외=완료/진행/미시행 및 완료 기준 집계). 문서 상세에서도 첨부파일=미리보기·다운로드, 전자문서=입력 폼, 프로그램=연결 화면 이동으로 갈린다(SCR-DOC-004·005·006 연계).
- **PDCA 판정은 구성과 조건부 후속을 함께 본다(TBD-004 확정)** — 계획(P)이 없으면 오류다. 점검(C) 뒤 A문서도 없고 개선조치 연계 규칙도 없으면 주의다. 반대로 G4·H1처럼 미흡 발생 시 개선조치 메뉴에 A 조치를 생성하도록 정한 세트는 상시 빈 A문서를 만들지 않아도 정상이다. 단계별 문서 수는 판정에 넣지 않는다.
- **상태는 그 문서가 실제로 있는지로 판정한다(TBD-005 확정)** — **미시행**은 그 회차의 결과물이 하나도 없는 상태, **진행**은 만들어졌으나 확정되지 않은 상태, **완료**는 확정된 상태다. 전자문서는 **작성중 / 등록완료 / 확정** 세 단계를 그대로 쓰고 집계는 **확정만 완료로** 센다 — 등록만 하고 확정하지 않은 문서를 완료로 세면 회수율이 부풀고, 부푼 수치는 아무도 들여다보지 않는다. 첨부파일 유형은 파일이 붙으면 완료다. **판정은 각 도메인 화면의 상태를 읽어 오고 이 화면이 따로 저장하지 않는다** — 자기 상태를 따로 저장하면 도메인 화면은 완료인데 목록은 미시행인 상태가 조용히 생긴다.
- **내려받기는 화면에 보이는 그대로다(TBD-006 확정)** — 형식은 표 계산 프로그램에서 바로 열리는 표 파일이고, 포함 항목은 **화면의 표시 열과 같으며**, 범위는 **현재 조회 조건이 반영된 결과**다. 화면에 없는 항목을 파일에만 담지 않는다 — 파일이 화면보다 많이 알면 사람들이 화면을 안 보게 된다. 파일명에는 **기준 날짜와 적용된 조건**을 넣어, 나중에 파일만 보고도 무엇을 언제 뽑은 것인지 알 수 있게 한다.
- **문서가 없는 단계도 자리를 남긴다(TBD-007 확정)** — 빠진 단계를 표시에서 지우면 세트가 완결된 것처럼 보인다. 단계 이름은 그대로 두고 **"문서 없음"**으로 밝히며, 그 표시가 곧 위 PDCA 판정의 근거다. 빈 자리가 보여야 무엇을 채워야 하는지 알 수 있다.
- **두 표시 형태를 모두 유지한다(TBD-010 확정)** — 테이블형은 문서를 찾고 상태를 훑는 데 쓰고, 격자 카드형은 세트 단위 진척을 한눈에 보는 데 쓴다. 목적이 달라 하나로 합치면 둘 다 어중간해진다. 다만 **데이터는 하나**이고 표시만 다르다 — 두 화면이 다른 수치를 보이면 안 된다. **진행률은 그 세트의 문서 중 완료 상태의 비율**이고(위 상태 판정과 같은 기준), **마감일은 그 세트의 문서 중 가장 이른 미완료 기한**이다 — 가장 늦은 것을 쓰면 이미 지난 기한이 감춰진다. 기한이 없는 문서만 남으면 마감일을 표시하지 않는다.

## 7. 미결사항

없음. 분류 기준의 정본·세트 미지정 문서 처리·PDCA 판정 규칙과 후속 주체·상태 판정과 집계 기준·목록 내려받기 사양·빈 단계 표기·두 표시 형태의 운영은 모두 §6에서 확정했다. 기본 제공 문서의 편집 범위는 업무 등록 마법사(SCR-DOC-007 §6)에서 확정했다.

실데이터 연동 시의 로딩·오류 표시는 미결이 아니라 **본개발 구현 범위**이며, 이 시스템 전반의 빈 상태·오류 표현 규칙을 따른다.
