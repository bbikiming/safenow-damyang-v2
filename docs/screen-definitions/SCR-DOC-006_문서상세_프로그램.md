문서가 **파일이 아니라 시스템의 어느 화면**인 경우를 다룬다. 위험성평가·교육처럼 전용 화면에서 처리하는 업무는 별도 문서를 만들 필요가 없고, 그 화면 자체가 이행의 산출물이다. 그래서 이 화면은 내용을 담지 않고 **어디로 가야 하는지** 알려 준다. 구성은 이동 경로·문서 정보·이동 안내·관련 문서 네 덩어리다.

---

## 2. 권한 정보

- 메뉴 접근·보기·수정은 시스템 관리의 메뉴 관리(SCR-ADMIN-005)와 권한 관리(SCR-ADMIN-006)에서 설정한다.
- 이 화면 정의서에서는 역할별 권한과 열람 범위를 별도로 정하지 않는다.
- 편집·삭제는 **사용자가 등록한 문서**에만 나타난다 — 기본 제공 문서는 조회만 한다(SCR-DOC-007 §6).

## 3. 진입 / 이탈 경로 및 사용자 시나리오

| 구분 | 연결 화면 | 조건 / 트리거 |
|---|---|---|
| 진입 | 문서 목록(SCR-CMP-002) | 문서 행 선택 — 돌아갈 화면을 함께 받는다 |
| 진입 | 이행 관리(SCR-CMP-001) | 단계별 증빙 목록의 문서 선택 |
| 진입 | 기준문서함(SCR-DOC-001) | [미리보기] 선택 |
| 진입 | 업무 목록 · 이행 목록 (메뉴 제외) | 주소로 그 화면을 연 경우에 한해 — 메뉴로는 도달하지 않는다 |
| 이탈 | 업무 목록 | 이동 경로 줄에서 되돌아간다 |
| 이탈 | 관련 문서 상세 | 우측 기준·선행·후행 문서 선택 |
| 이탈 | 업무 업로드 | [편집] 선택(SCR-DOC-007) |

| 단계 | 사용자 행동 | 화면 반응 |
|:--:|---|---|
| 1 | 목록에서 문서를 고른다 | 이동 경로와 문서 정보를 먼저 보여 준다 |
| 2 | 처리유형에 맞는 본문을 본다 | 프로그램 문서는 어느 화면으로 가야 하는지 안내하고 이동 수단을 준다 |
| 3 | 우측에서 관련 문서를 확인한다 | 기준·선행·후행 세 묶음으로 나눠 보여 준다 |
| 4 | 관련 문서를 고른다 | 그 문서의 상세로 이동한다 |

### 분기 로직

- **처리유형이 본문 전체를 가른다** — 같은 주소로 들어와도 **첨부파일**이면 미리보기와 파일 목록, **전자문서**면 입력 폼, **프로그램**이면 이동 안내가 나온다. 사용자는 같은 자리를 눌렀지만 그 문서의 성격에 맞는 화면을 만난다.
- **상태 표시가 두 축에서 나온다** — 전자문서는 **작성중 / 등록완료 / 확정**을, 그 밖은 **시작 전 / 진행중 / 활성(완료)**을 쓴다. 같은 자리에 다른 어휘가 나오는 이유는 두 축이 실제로 다른 것을 세기 때문이다.
- **사용자 등록 문서에만 편집·삭제가 나온다** — 기본 제공 문서는 고칠 수 없고 복제해 쓴다.
- **관련 문서는 세트 구조에서 파생한다** — 기준·선행·후행을 문서마다 손으로 적지 않고 세트의 순서 관계에서 만든다.
- **이 문서에는 담을 내용이 없다** — 이행의 실체가 다른 화면에 있으므로 여기서 값을 받거나 파일을 올리지 않는다. 내용을 담게 하면 전용 화면과 두 곳에 같은 기록이 쌓인다.

### 예외·경계 시나리오

| 상황 | 화면 반응 |
|---|---|
| 없는 문서 식별값으로 진입 | 본문을 내지 않고 "문서를 찾을 수 없습니다"와 목록으로 돌아가는 길을 준다 |
| 세트에 속하지 않은 문서 | 관련 문서 묶음이 비어 있다는 사실을 그대로 보여 준다 — 억지로 채우지 않는다 |
| 선행·후행이 없는 세트 | 그 묶음만 비고 나머지는 정상 표시한다 |
| 기획자 확인이 필요한 문서 | 그 사실과 사유를 문서 머리에 드러낸다 |
| 연결 화면이 지정되지 않은 문서 | 대메뉴의 첫 화면으로 보낸다 — 막다른 길을 만들지 않는다 |
| 연결 화면에 접근 권한이 없음 | 이동한 화면이 그 사실을 알린다 — 여기서 미리 막지 않는다 |

## 4. 화면 구성별 정리

### 4-1. 이동 경로

- 구성: 업무 관리 › 왔던 목록 › 대메뉴 › 세트 › 현재 문서 순의 경로 줄. 첫 칸은 이 화면이 속한 대메뉴이고, 둘째 칸은 **이 문서를 연 목록**이다 — 이행 관리·문서 목록·이행 목록 중 어디에서 왔는지에 따라 달라진다.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 경로 항목 선택 | 그 단계의 목록으로 이동한다 | 브라우저 뒤로가기와 달리 **정해진 자리**로 간다 |
| 세트가 없는 문서 | 세트 단계를 건너뛴다 | 빈 단계를 만들지 않는다 |

- 상태: 항상 표시되며 현재 문서는 이동 대상이 아니다.

### 4-2. 문서 정보 머리

- 구성: 처리유형 배지 · 상태 배지 · 버전 · 문서명 · (사용자 등록 문서면) 편집·삭제 · 문서번호 · 최종 업데이트일 · 작성자 · 담당부서 · 문서 역할 · 법적 근거.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 화면 진입 | 문서의 신원과 지금 상태를 한 자리에 보여 준다 | — |
| [편집] | 업무 업로드로 이동한다 | SCR-DOC-007 |
| [삭제] | 확인 단계를 거쳐 지우고 목록으로 돌아간다 | 사용자 등록 문서만 |
| 기본 제공 문서 | 편집·삭제를 그리지 않는다 | 복제해 쓴다 |

- 상태: 문서 상태는 처리유형에 따라 어휘가 갈린다(§3 분기). 문서번호는 **세트와 순번에서 파생**하며 사람이 정하지 않는다.

### 4-3. 이동 안내

- 구성: 연결된 메뉴 › 화면 경로 표시 · 그 화면으로 가는 버튼.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 화면 진입 | 어느 메뉴의 어느 화면인지 경로로 보여 준다 | 이름만 두면 어디 있는지 못 찾는다 |
| 이동 버튼 선택 | 그 화면으로 간다 | — |
| 연결 화면이 지정되지 않음 | 그 문서가 속한 대메뉴의 첫 화면으로 보낸다 | 아무 데도 못 가게 두지 않는다 |

- 상태: **연결 지정됨 / 지정 안 됨** 둘이며, 어느 쪽이든 갈 곳은 있다. 이 화면은 내용을 담지 않으므로 빈 상태·작성 상태를 갖지 않는다.

### 4-4. 관련 문서

- 구성: **기준 문서** · **↑ 선행 문서** · **↓ 후행 문서** 세 묶음.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 관련 문서 선택 | 그 문서의 상세로 이동한다 | 같은 화면 구조로 열린다 |
| 법령 항목 선택 | 근거를 확인하는 자리로 보낸다 | 원문 연계는 근거 연계가 관리한다(SCR-COM-008) |
| 해당 묶음이 비어 있음 | 비었다는 사실을 그대로 보여 준다 | 억지로 채우지 않는다 |

- 상태: 묶음마다 **있음 / 없음**이며 셋이 모두 빌 수 있다(세트에 속하지 않은 문서). 관계는 세트 순서에서 파생하므로 이 화면에서 고치지 않는다.

## 6. 정책

**P0. 이 정의서는 세트 축 문서의 상세다.**
업무문서에는 축이 둘 있다. 하나는 대메뉴·세트·계획–실행–점검–조치로 묶인 **기존 업무문서**이고, 다른 하나는 법정 이행항목·업무단계로 묶인 **문서 원장과 새로 등록한 증빙**이다. 이 정의서가 다루는 것은 앞의 축이며, 뒤의 축은 이행항목·업무단계 연결과 첨부·지면을 보여 주는 다른 지면으로 열린다(SCR-DOC-002 §6, SCR-DOC-003 §6). 같은 주소로 들어와도 문서가 어느 축인지에 따라 지면이 갈리며, 사용자에게는 두 지면이 각각 완결돼 보여야 한다.

**P0-1. 세트 축 문서에는 이행항목 연결이 없다.**
없는 것을 억지로 채우지 않는다. 업무 목록에서도 이 문서들은 미분류가 아니라 **이행항목 축 없음**으로 구분한다 — 미분류로 묶으면 교정해야 할 문서가 무엇인지 알 수 없어진다.


- **한 주소가 세 화면을 겸한다** — 문서를 여는 동작은 하나이고, 처리유형이 무엇을 보여 줄지 정한다. 유형별로 주소를 나누면 목록에서 어느 주소로 보낼지 매번 판단해야 하고, 유형이 바뀌면 링크가 끊긴다.
- **관련 문서를 손으로 적지 않는다** — 세트 순서에서 파생한다. 문서마다 적으면 세트가 바뀔 때 관계만 옛 상태로 남는다.
- **문서번호를 사람이 정하지 않는다** — 세트와 순번에서 만든다. 손으로 정하면 중복과 건너뜀이 생긴다.
- **기본 제공 문서는 고치지 않는다** — 법정 의무에서 도출한 목록이라 고치면 원래 무엇이었는지 잃는다. 복제해 사용자 등록 문서로 만든 뒤 고친다(SCR-DOC-007 §6).
- **비어 있는 관계를 채우지 않는다** — 세트에 속하지 않은 문서는 관련 문서가 없는 것이 정상이다.
- **이행 여부를 이 화면이 판정하지 않는다** — 실제로 했는지는 연결된 전용 화면이 안다. 여기서 따로 완료를 표시하면 두 곳의 상태가 어긋난다.
- **법령 근거는 문서가 갖는다** — 이 화면은 문서에 붙은 근거를 표시할 뿐이며, 규칙은 공통 근거 연계(SCR-COM-008)를 따른다.
