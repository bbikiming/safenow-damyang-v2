# 화면 정의서 — 공통 모달 인프라

> 화면 ID: SCR-COM-005 · 화면 유형: 공통 인프라 · 기획 관점(v6) · 구현 정합 2026-08-11
> 판단이 필요했던 항목은 §6 정책에서 확정했습니다.

---

## 1. 화면 정보

| 항목 | 내용 |
|---|---|
| 화면 ID | SCR-COM-005 |
| 화면명 | 공통 모달 인프라 |
| URL 경로 | 전 화면 공통 — 화면이 팝업을 열 때 |
| 상위 메뉴 | 공통/전역 |
| 화면 유형 | 공통 인프라 |

이 시스템의 **모든 팝업이 같은 모양·같은 닫기 방식**을 갖게 하는 한 벌의 틀이다. 화면마다 팝업을 따로 만들면 닫기 버튼 위치가 제각각이 되고, 팝업 위에 팝업이 겹쳐 어느 것이 닫히는지 알 수 없게 된다. 그래서 팝업은 이 틀로만 연다. 구성은 가림막·머리(제목·닫기)·본문·바닥(버튼) 네 덩어리이며, 전 화면의 등록·확인·상세 팝업이 이것을 쓴다.

---

## 2. 권한 정보

- 메뉴 접근·보기·수정은 시스템 관리의 메뉴 관리(SCR-ADMIN-005)와 권한 관리(SCR-ADMIN-006)에서 설정한다.
- 이 화면 정의서에서는 역할별 권한과 열람 범위를 별도로 정하지 않는다.
- 이 틀은 권한을 판단하지 않는다 — 팝업을 열 수 있는지는 **부른 화면**이 정하고, 이 틀은 받은 내용을 그린다.

---

## 3. 진입 / 이탈 경로 및 사용자 시나리오

| 구분 | 연결 화면 | 조건 / 트리거 |
|---|---|---|
| 진입 | 모든 화면 | 등록·수정·확인·상세 등 팝업이 필요할 때 |
| 이탈 | 부른 화면 | 닫기·취소·가림막 선택·ESC |

| 단계 | 사용자 행동 | 화면 반응 |
|:--:|---|---|
| 1 | 팝업을 여는 동작을 한다 | 뒤 화면을 가림막으로 덮고 팝업을 띄운다 |
| 2 | 본문을 읽거나 입력한다 | 뒤 화면은 조작할 수 없다 |
| 3 | 바닥 버튼을 고른다 | 부른 화면이 정한 동작을 실행한다 |
| 4 | 닫기·가림막·ESC | 저장하지 않고 닫는다 |

### 분기 로직

- **한 시점에 팝업은 하나다** — 새 팝업을 열면 기존 팝업을 먼저 거둔다. 겹쳐 쌓지 않는 이유는 ① 닫기·ESC·가림막이 어느 팝업을 닫는지 모호해지고 ② 뒤 팝업이 가려 맥락을 잃으며 ③ 닫아도 남는 잔여 레이어가 생기기 때문이다.
- **부가 선택은 팝업 안에서 편다** — 담당자·부서·조문처럼 팝업 안에서 무언가를 더 골라야 하면 **새 팝업을 띄우지 않고** 본문 안에 접었다 펴는 영역으로 넣는다.
- **단계가 많은 입력은 본문을 갈아 끼운다** — 팝업을 여러 개 띄우지 않고 같은 팝업 안에서 단계를 바꾼다.
- **바닥 버튼은 부른 화면이 정한다** — 이 틀은 버튼 자리를 제공할 뿐 무슨 버튼을 둘지 정하지 않는다. 바닥을 넘기지 않으면 바닥 영역 자체를 그리지 않는다.
- **셸 크롬 팝업은 업무 팝업과 구분한다** — 헤더에서 언제든 여는 팝업(자료 준비 등)에는 표시를 달아, 시연 안내가 엉뚱한 맥락의 지시를 붙이지 않게 한다.

### 예외·경계 시나리오

| 상황 | 화면 반응 |
|---|---|
| 팝업이 열린 상태에서 새 팝업 요청 | 기존 팝업을 거두고 새 팝업만 남긴다 |
| 팝업을 닫음 | 본 팝업과 함께 딸린 부수 레이어까지 함께 거둔다 — 잔여 레이어를 남기지 않는다 |
| ESC | 닫는다 |
| 가림막 선택 | 닫는다 |
| 바닥 버튼을 넘기지 않음 | 바닥 영역을 그리지 않는다 — 빈 띠를 두지 않는다 |
| 본문이 화면보다 길다 | 본문만 스크롤하고 머리·바닥은 고정한다 |
| 넓은 지면이 필요한 팝업 | 넓은 형태로 열 수 있다 — 문서 미리보기처럼 지면을 그대로 보여 줘야 하는 경우다 |
| 저장하지 않고 닫음 | 이 틀은 확인하지 않는다 — 되물을지는 **부른 화면**이 정한다 |

## 4. 화면 구성별 정리

### 4-1. 가림막

- 구성: 뒤 화면을 덮는 반투명 층.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 팝업 열림 | 뒤 화면을 덮고 조작을 막는다 | — |
| 가림막 선택 | 팝업을 닫는다 | 저장하지 않는다 |

- 상태: 팝업이 있을 때만 존재한다. 팝업이 닫히면 함께 사라진다.

### 4-2. 머리 — 제목과 닫기

- 구성: 팝업 제목 · (있으면) 머리 도구 · 닫기 버튼.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 팝업 열림 | 부른 화면이 준 제목을 표시한다 | 무엇을 하는 팝업인지 제목으로 알린다 |
| 닫기 선택 | 닫는다 | 저장하지 않는다 |

- 상태: 제목은 항상 있다. 머리 도구는 넘겨받았을 때만 그린다.

### 4-3. 본문

- 구성: 부른 화면이 넘긴 내용을 그대로 담는 영역.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 내용이 길다 | 본문만 스크롤한다 | 머리·바닥은 고정 |
| 부가 선택이 필요하다 | 본문 안에서 접었다 편다 | 새 팝업을 띄우지 않는다 |
| 여러 단계 입력 | 같은 팝업 안에서 본문을 바꾼다 | 팝업을 새로 열지 않는다 |

- 상태: 내용은 부른 화면 소관이라 이 틀이 빈 상태·오류 상태를 갖지 않는다. **길이에 따라 스크롤 유무**만 갈린다.

### 4-4. 바닥 — 버튼

- 구성: 부른 화면이 넘긴 버튼 묶음.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 버튼 선택 | 부른 화면이 정한 동작을 실행한다 | 이 틀은 동작을 정하지 않는다 |
| 버튼을 넘기지 않음 | 바닥을 그리지 않는다 | — |

- 상태: **있음 / 없음** 둘이다. 되돌릴 수 없는 동작의 확인 문구는 부른 화면이 본문에 담는다.

## 6. 정책

- **한 시점에 팝업은 하나다** — 이 시스템의 강한 규칙이다. 겹쳐 쌓으면 닫기 대상이 모호해지고 맥락을 잃으며 잔여 레이어가 남는다.
- **부가 선택은 팝업 안 영역으로 푼다** — 담당자·부서·조문 선택 때문에 팝업을 하나 더 띄우지 않는다.
- **팝업을 화면이 직접 만들지 않는다** — 반드시 이 틀로 연다. 직접 만들면 닫기 방식이 제각각이 되고 위 규칙이 깨진다.
- **닫을 때 딸린 레이어까지 함께 거둔다** — 본 팝업만 지우면 화면을 덮은 채 남는 층이 생긴다.
- **저장 여부를 이 틀이 묻지 않는다** — 무엇이 사라지는지는 부른 화면만 안다. 되물을지 여부도 그 화면이 정한다.
- **셸 크롬 팝업을 업무 팝업과 구분한다** — 헤더에서 언제든 여는 팝업은 업무 흐름의 일부가 아니므로 표시를 달아, 시연 안내가 무관한 지시를 붙이지 않게 한다.
- **법령 근거를 붙이지 않는다** — 표시 인프라는 법령이 명한 의무의 직접 이행 수단이 아니다. 규칙은 공통 근거 연계(SCR-COM-008)를 따른다.
