# 화면 정의서 — 보고서·제증명

## 1. 화면 정보

| 항목 | 내용 |

| 화면 유형 | 출력 |

시스템에 쌓인 이행 기록을 **밖으로 낼 수 있는 문서 형태**로 만드는 화면이다. 안전보건 이행은 감사·점검·의회 요구처럼 시스템 밖에서 증명해야 하는 일이 생기는데, 그때마다 여러 화면을 옮겨 다니며 손으로 옮겨 적으면 옮기는 과정에서 틀린다. 구성은 보고서 미리보기와 출력 이력 두 덩어리이며, 수치는 모두 각 업무 자료에서 파생한다.

## 2. 권한 정보

- 메뉴 접근·보기·수정은 시스템 관리의 메뉴 관리(SCR-ADMIN-005)와 권한 관리(SCR-ADMIN-006)에서 설정한다.
- 이 화면 정의서에서는 역할별 권한과 열람 범위를 별도로 정하지 않는다.
- 출력한 문서는 **밖으로 나가는 자료**라 누가 언제 뽑았는지가 이력에 남는다(§6).

## 3. 진입 / 이탈 경로 및 사용자 시나리오

| 구분 | 연결 화면 | 조건 / 트리거 |
|---|---|---|

| 진입 | 현황 통계 | 집계를 문서로 낼 때(SCR-RPT-001) |
| 이탈 | 각 업무 화면 | 수치의 근거를 확인할 때 |

| 단계 | 사용자 행동 | 화면 반응 |
|:--:|---|---|

| 4 | 출력한다 | 출력 이력에 누가 언제 뽑았는지 남긴다 |

### 분기 로직

- **보고서 종류가 내용을 정한다** — 총괄보고서는 기간의 이행 전반을, 제증명은 특정 사실 하나를 증명한다. 앞은 여러 축을 모으고 뒤는 한 축만 확인한다.
- **대상 기간이 수치를 정한다** — 반기·연간처럼 기간을 고르면 그 기간의 자료로 다시 계산한다. 기간을 바꿨는데 수치가 그대로면 어느 기간의 값인지 알 수 없다.
- **수치는 파생값이지 입력값이 아니다** — 보고서에 들어가는 숫자를 여기서 고칠 수 없다. 고칠 수 있으면 그것은 보고서가 아니라 작문이다.
- **미리보기와 출력물이 같아야 한다** — 화면에서 본 것과 나간 것이 다르면 미리보기가 의미를 잃는다.

### 예외·경계 시나리오

| 상황 | 화면 반응 |

| 대상 기간에 자료가 없음 | 0으로 채우지 않고 **자료 없음**으로 표시한다 — 0건과 기록이 없는 것은 다르다 |

## 4. 화면 구성별 정리

### 4-1. 보고서 미리보기

- 구성: 보고서 종류·대상 기간 선택 + 지면 형태의 미리보기(구분·내용 표).

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 보고서 종류 선택 | 그 종류의 지면 구성으로 바꾼다 | 총괄보고서와 제증명은 구성이 다르다 |
| 대상 기간 선택 | 그 기간의 수치로 다시 계산한다 | 수치는 업무 자료에서 파생한다 |
| 수치를 고치려 함 | 고칠 수 없다 | 근거는 각 업무 화면에서 바꾼다 |
| 자료가 없는 항목 | 자료 없음으로 표시한다 | 0으로 채우지 않는다 |
| [출력] | 지면 그대로 낸다 | 미리보기와 다르지 않다 |

- 상태: **자료 있음 / 일부 있음 / 없음** 세 가지다. 담양군 고유 기관정보가 비어 있으면 그 자리를 미등록으로 표시한다.

### 4-2. 출력 이력

- 구성: 보고서 · 출력일 · 출력자 세 열.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 출력 실행 | 이력에 한 줄을 남긴다 | 누가 언제 무엇을 뽑았는지 |
| 화면 진입 | 최근 출력을 최신 순으로 보여 준다 | — |
| 이력이 0건 | 아직 출력이 없음을 표시한다 | — |

- 상태: **없음 / 있음** 둘이며 조회 전용이다. 고치거나 지울 수 없다 — 밖으로 나간 자료의 기록이기 때문이다.

## 6. 정책

- **수치를 이 화면에서 고칠 수 없다** — 보고서에 들어가는 숫자는 업무 자료에서 파생한다. 고칠 수 있으면 그것은 보고서가 아니라 작문이고, 밖으로 나간 뒤 근거를 대지 못한다.
- **미리보기와 출력물을 같게 한다** — 다르면 미리보기가 의미를 잃고, 무엇이 나갔는지 확인할 방법이 없다.
- **자료 없음을 0으로 채우지 않는다** — 0건인 것과 기록이 없는 것은 다르다. 특히 밖으로 나가는 문서에서 이 둘을 섞으면 "안 했다"와 "기록이 없다"가 구분되지 않는다.
- **없는 축을 빼지 않는다** — 자료가 없는 축도 지면에 남기고 자료 없음으로 표시한다. 빼면 무엇이 빠졌는지 알 수 없다.
- **출력 이력을 남기고 지우지 않는다** — 밖으로 나간 자료라 누가 언제 뽑았는지가 사후에 문제가 됐을 때 근거가 된다.
- **담양군 고유값의 공백을 드러낸다** — 기관정보가 아직 없으면 미등록으로 표시한다. 빈칸으로 두면 값이 없는 것인지 안 넣은 것인지 모른다.
- **법령 근거를 붙이지 않는다** — 보고서 출력은 이행 결과를 밖으로 내는 형식이지 그 자체가 법령이 명한 의무의 직접 이행 수단이 아니다. 근거는 보고서가 담는 **각 업무**에 있으며, 규칙은 공통 근거 연계(SCR-COM-008)를 따른다.

## 7. 미결사항

없음. 수치의 편집 불가·미리보기와 출력물의 일치·자료 없음의 표시·빈 축 처리·출력 이력의 보관·고유값 공백 표시·법령 근거의 위치는 모두 §6에서 확정했다.

> ⚠ **§3·§4 는 to-be 다 — 현재 화면은 미구현이다.** 프로토타입 `reports.html` 에는 **보고서 종류·대상 기간 선택 수단이 없고** 총괄보고서 한 장이 고정 수치로 그려진다(화면 자체가 "양식·항목은 협의 후 확정"이라 밝히고 있다). 제증명 축도 화면에 없다. **개발 범위는 §4 기준**이며, 프로토타입 상태를 완성으로 오해하지 않도록 이 문단을 남긴다.

**담양군 기관정보**는 이 화면의 미결이 아니라 담양군이 제공할 자료이며, 그때까지 지면에 미등록으로 드러낸다.
