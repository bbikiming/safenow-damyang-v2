업무 목록과 **같은 세트·같은 문서**를 세트 단위 카드로 보여 준다. 업무 목록(SCR-DOC-002)이 문서를 찾고 상태를 훑는 자리라면, 이곳은 **세트가 계획–실행–점검–조치로 온전히 갖춰졌는지**를 한눈에 보는 자리다. 안전보건 업무는 점검만 있고 조치가 없거나 계획 없이 실행만 쌓이는 일이 흔해, 그 빠짐을 세트 단위로 드러내는 것이 이 화면의 목적이다. 구성은 조회 조건과 세트 카드 목록 두 덩어리이며, 문서를 고르면 문서 상세(SCR-DOC-004~006)로 간다.

## 3. 진입 / 이탈 경로 및 사용자 시나리오

| 구분 | 연결 화면 | 조건 / 트리거 |
|---|---|---|
| 진입 | 업무문서 > 이행 목록 | 메뉴 선택 |
| 이탈 | 문서 상세 | 세트 카드 안의 문서 선택(SCR-DOC-004~006) |
| 이탈 | 업무 목록 | 같은 자료를 표로 볼 때(SCR-DOC-002) |

| 단계 | 사용자 행동 | 화면 반응 |
|:--:|---|---|
| 1 | 화면에 들어온다 | 세트를 카드로 늘어놓고 각 카드에 건수와 완료 수를 붙인다 |
| 2 | 카드 안을 본다 | 그 세트의 문서를 PDCA 단계별로 묶어 보여 준다 |
| 3 | 빠진 단계를 확인한다 | 문서가 없는 단계도 자리를 남겨 무엇이 비었는지 드러낸다 |
| 4 | 문서를 고른다 | 그 문서의 상세로 이동한다 |

### 분기 로직

- **업무 목록과 같은 자료를 다른 형태로 본다** — 데이터는 하나이고 표시만 다르다. 두 화면이 다른 수치를 보이면 안 된다. 표 형태는 문서를 **찾는** 데, 카드 형태는 세트 진척을 **훑는** 데 쓴다.
- **V2 문서는 PDCA 단계로 묶인다** — 계획(P)·실행(D)·점검(C)·조치(A) 중 하나가 필수다. 기존 V1 비교 조회에서만 과거 미확정·단계 없음 그룹을 읽기 전용으로 표시한다.
- **분류 기준을 바꾸면 세트 구성이 통째로 바뀐다** — 정본은 법적의무 재분류이며, 기존 분류는 조회 전용으로만 남긴다(SCR-DOC-002 §6). 기준을 바꾸면 조회 조건도 함께 초기화된다.
- **세트 구성이 온전하지 않으면 카드에 표시한다** — 계획이 없으면 오류, 점검은 있는데 조치가 없으면 주의다. 판정 기준은 업무 목록과 하나를 공유한다.

### 예외·경계 시나리오

| 상황 | 화면 반응 |
|---|---|
| 문서가 없는 PDCA 단계 | 단계 이름은 남기고 **문서 없음**으로 밝힌다 — 지우면 세트가 완결된 것처럼 보인다 |
| 세트에 속하지 않은 과거 문서 | 맨 아래 **세트 지정 필요** 묶음에 건수와 함께 모은다 — 신규 등록에서는 발생하지 않는다 |
| 조회 결과가 0건 | 조건에 맞는 세트가 없음을 표시하고 조건을 풀 수 있게 한다 |
| 문서가 하나뿐인 세트 | 정상으로 본다 — 단계별 문서 수는 판정에 넣지 않는다 |
| 완료가 0건인 세트 | 진행률을 0%로 그대로 표시한다 — 감추면 손대지 않은 세트가 보이지 않는다 |
| 기한이 없는 문서만 남은 세트 | 마감일을 표시하지 않는다 — 없는 날짜를 지어내지 않는다 |

## 4. 화면 구성별 정리

### 4-1. 조회 조건

- 구성: 문서명 검색 · 상태 · PDCA 단계 · 분류 기준 전환.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 검색어 입력 | 문서명으로 좁힌다 | 입력 도중 포커스가 유지된다 |
| 상태 선택 | 그 상태의 문서만 남긴다 | 세트 카드는 남은 문서로 다시 그려진다 |
| PDCA 단계 선택 | 그 단계 문서만 남긴다 | V2는 P·D·C·A, 기존 V1만 미확정 추가 |
| 분류 기준 전환 | 세트 구성을 통째로 바꾼다 | **조회 조건이 함께 초기화된다** |
| 결과 0건 | 빈 상태를 표시한다 | 조건을 풀 수 있게 한다 |

- 상태: **조건 없음 / 조건 적용 중**이며, 적용 중일 때 남은 세트·문서 수를 함께 보여 준다.

### 4-2. 세트 카드

- 구성: 대메뉴 칩 · 세트 이름 · 문서 수와 완료 수 · 선행 세트 표시 · PDCA 구성 표시 · 단계별 문서 목록.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 카드 진입 | 그 세트 문서를 PDCA 단계로 묶어 보여 준다 | 단계 순서는 계획·실행·점검·조치 |
| 문서 선택 | 그 문서의 상세로 이동한다 | SCR-DOC-004~006 |
| 문서가 없는 단계 | 자리를 남기고 문서 없음으로 밝힌다 | 세트의 빠진 곳이 보여야 한다 |
| 구성이 온전하지 않은 세트 | 오류 또는 주의로 표시한다 | 계획 없음은 오류, 점검 후 조치 없음은 주의 |
| 선행 세트가 있는 세트 | 어느 세트 다음인지 표시한다 | 순서를 알아야 무엇부터 할지 정한다 |

- 상태: 세트 단위로 **정상 / 주의 / 오류** 세 판정과 **미착수(완료 0) / 진행 / 완료** 진척이 겹쳐 표시된다. 진행률은 그 세트 문서 중 완료 상태의 비율이며 업무 목록과 같은 기준을 쓴다.

### 4-3. 세트 지정 필요 묶음

- 구성: 어느 세트에도 속하지 않은 문서를 모은 맨 아래 묶음.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 세트 없는 과거 문서가 있음 | 맨 아래에 건수와 함께 모아 보여 준다 | 편집에서 세트를 지정한다 |
| 세트 없는 문서가 0건 | 묶음을 그리지 않는다 | 정상 상태 |
| 문서 선택 | 그 문서의 상세로 이동한다 | 거기서 세트를 지정할 수 있다 |

- 상태: **정상 / 교정 필요** 둘이다. 신규 등록은 세트가 필수이며, 교정 필요는 이전 버전·오류 데이터에만 쓴다.

## 6. 정책

- **업무 목록과 같은 자료를 쓴다** — 표시 형태만 다르다. 두 화면이 다른 수치를 보이면 어느 쪽이 실제인지 알 수 없다. 진행률·상태·PDCA 판정 기준은 모두 업무 목록(SCR-DOC-002 §6)과 하나를 공유한다.
- **두 형태를 모두 유지한다** — 문서를 찾는 일과 세트 진척을 훑는 일은 목적이 달라, 하나로 합치면 둘 다 어중간해진다.
- **빠진 단계를 지우지 않는다** — 문서가 없는 단계도 자리를 남긴다. 지우면 세트가 완결된 것처럼 보이고, 그 빈자리가 곧 다음에 할 일이다.
- **세트 없는 과거 데이터를 감추지 않는다** — 신규 등록에서는 막고, 이미 존재하면 맨 아래 교정 대상으로 모아 건수를 밝힌다.
- **분류 기준을 바꾸면 조건을 초기화한다** — 세트 구성 자체가 달라지므로 이전 기준의 조건을 유지하면 엉뚱한 결과가 나온다.
- **이 화면에서 고치지 않는다** — 조회 전용이며 등록·수정·삭제는 업무 등록·수정(SCR-DOC-007)에서 한다. 두 곳에서 고치면 어느 쪽이 최신인지 알 수 없다.
- **법령 근거는 문서가 갖는다** — 세트는 업무의 묶음이지 그 자체가 조문의 이행 수단이 아니다. 근거는 문서마다 붙으며 규칙은 공통 근거 연계(SCR-COM-008)를 따른다.
