# 화면 정의서 — 점검표(F5) 폼 — 체크리스트(부적정 시 개선조치 자동 등록)

> 화면 ID: SCR-EDOC-005 · 화면 유형: 공통 입력 폼 — 호출처가 팝업이면 모달, 문서 상세에서는 좌측 패널 인라인 폼 · 기획 관점(v6)
> 판단이 필요했던 항목은 §6 정책에서 확정했습니다.

**목적·설명** — 점검일·점검자·점검 항목(O/X/해당없음 + 비고 또는 텍스트형)·증빙 첨부를 입력하는 표준 점검표다. 전용 메뉴 없이 5개 호출 화면이 각자의 점검 목적에 맞는 항목 세트·제목·메뉴라벨을 주입해 같은 폼을 띄운다. 작성중 → 등록완료 → 확정 3단계로 진행하며, 확정 시 부적정(X) 판정 항목을 개선조치로 자동 등록하고 온나라 결재요청 안내로 전환한다. 점검자는 자유 입력이 아니라 조직도 트리에서만 선택하며, 경영방침 점검표에서는 항목별 관련 법령 상세를 별도 창으로 열어볼 수 있다. 호출 형태(모달 / 문서 상세 인라인)에 따라 푸터 버튼 구성과 저장 후 동작(닫힘 / 그 자리 갱신)이 달라진다. 연관 화면: 개선조치 목록(SCR-EDOC 계열 자동 유입 대상), 평가서(F6, SCR-EDOC-006 — 도급관리에서 점검표와 나란히 노출되는 별도 폼), 업무 등록·수정 마법사(SCR-DOC-007).

## 2. 권한 정보

- 이 요소는 자체 메뉴를 갖지 않는다. 접근·보기·수정은 **호출한 화면의 메뉴 권한**을 따르며, 그 설정은 시스템 관리의 메뉴 관리(SCR-ADMIN-005)·권한 관리(SCR-ADMIN-006)에서 한다.
- 이 화면 정의서에서는 역할별 권한과 열람 범위를 별도로 정하지 않는다.
- 점검표 작성·등록·확정과 부적정 항목의 개선조치 연계는 §3~§6의 업무 흐름과 상태 전이 조건을 따른다.

**분기 로직**

- **확정 직전에 결재선을 묻는다** — 확정이 곧 상신이므로 결재선 없이 확정할 수 없다. 결재선 영역은 **등록완료 상태에서만** 나타나며(작성중에는 아직 물을 단계가 아니다), 확정 뒤에는 그 문서에 실린 결재선을 조회로만 보여준다.
- **결재선은 기안 → 검토 → 결재 3단계이고 서로 다른 계정이어야 한다(2026-08-27 확정)** — 상신은 결재선 전체를 **한 번에** 온나라로 넘기므로(호출기안) 한 계정이 두 단계에 들어가면 결재선이 성립하지 않는다. 규칙과 판정은 공통 권한 정의 §7 이 정본이며 전 도메인이 같은 형태를 쓴다.
  - **결재선을 코드에 고정하지 않는다** — 결재권자는 지자체 위임전결규칙 소관이라 조직 개편·규칙 개정으로 바뀐다. 기본값만 조직도에서 직위명으로 파생하고 변경은 조직도 선택기로 받는다.
  - **위반은 고르는 단계에서 먼저 막는다** — 기안자와 이미 지정된 사람은 조직도에서 사유와 함께 고를 수 없게 표시하고, 상신 경로에서 다시 확인한다.
  - **결재선은 이름이 아니라 계정 식별자로 보관한다** — 온나라 결재선이 계정 식별자 배열이고, 동명이인·개명에 어긋나지 않아야 한다.
- **상태가 하단 버튼 구성을 결정한다** — 작성중이면 [취소]·[임시저장]·[등록], 등록완료면 [취소]·[임시저장]·[확정 · 온나라 결재 상신], 확정이면 [닫기]·[개정]만 남는다. 즉 **등록을 거치지 않고 바로 확정할 수 없다.**
- **확정에서만 개선조치가 만들어진다** — 임시저장·등록은 값을 담아 둘 뿐이고, 부적정(X) 항목이 개선조치로 넘어가는 것은 확정 시점 단 한 번이다. 확정 직후 온나라 결재 안내로 화면이 전환되고, X 항목이 있었으면 몇 건이 만들어졌는지 함께 알린다.
- **항목 판정은 셋 중 하나만 선택된다** — O·X·해당없음은 서로 배타이며 X만 강조 표시된다. 판정과 별개로 비고를 적을 수 있고, 비고를 적으면 그 내용이 개선조치 제목에 함께 실린다.
- **호출한 화면에 따라 점검 항목 세트와 표시 라벨이 달라진다** — 같은 점검표 폼이지만 경영방침·이행관리·도급관리에서 각각 다른 항목 묶음으로 열리며, 호출 화면이 항목을 넘기지 않으면 기본 항목 묶음으로 그린다.
- **표시 방식이 두 가지다** — 모달로 열리는 경우와 호출 화면 안에 인라인으로 그려지는 경우가 있고, 저장·등록·확정 동작은 같으나 모달은 닫히고 인라인은 그 자리에서 다시 그려진다.

**엣지케이스**

- **판정하지 않은 항목이 있어도 등록·확정을 막지 않는다** — 전 항목 응답을 강제하지 않아 빈 점검표로도 확정이 가능하다. 무엇을 필수로 할지는 확정 대상이다(§6 확정).
- **확정은 되돌릴 수 없다** — 확정 시 개선조치가 만들어지고 상신 안내까지 나가는데, 되돌리는 수단은 [개정](새 버전 작성)뿐이고 현재 프로토타입은 실제로 새 버전을 만들지 않는다. 확정 전 확인 단계도 없다.
- **확정 후에도 입력칸이 잠기지 않는다** — 버튼만 [닫기]·[개정]으로 바뀔 뿐이라, 확정 문서를 열어 값을 바꿔 볼 수 있다. 확정본 잠금은 §6에서 확정했다.
- **같은 점검표를 두 번 확정하면 개선조치가 다시 만들어질 수 있다** — 중복 생성 방지 규칙이 없다.
- **개선조치 기한과 담당자가 고정값이다** — 자동 생성되는 개선조치의 기한이 정해진 날짜로 들어가고 담당자는 비어 있다. 실제 기한 산정 규칙은 §6에서 확정했다.
- **점검자는 직접 타이핑하지 않는다** — 조직도에서 고르며, 그 목록은 공용 조직도에서 파생한다.
- **증빙 첨부는 아직 안내만 표시한다** — 파일이 실제로 붙지 않는다.
- **관련 근거는 항목 아래에서 펼쳐진다** — 새 창을 겹치지 않고 그 행 아래에 열려, 점검표를 보면서 근거를 확인할 수 있다.

## 4. 화면 구성별 정리

### 4-1. 헤더 영역 (폼종류·상태·메뉴라벨)
- 구성: 폼종류 칩("점검표") + 상태 칩(작성중 / 등록완료 / 확정 · 온나라 상신) + 메뉴라벨 칩(호출처가 주입한 "{대메뉴} · {주기}", 예: "경영방침 · 반기").

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| (표시 전용) | 현재 폼 종류·진행 상태·소속 메뉴를 한눈에 안내 | — |

- 상태: 저장본이 없으면 작성중으로 표시된다. 상태 칩은 저장된 상태에 따라 자동으로 바뀐다.

### 4-2. 연동 정보 카드 (옵션)
- 구성: 호출처가 연동 정보를 주입한 경우에만 "🔗 연동 정보 — {내용}" 한 줄을 헤더 아래 표시(문서 상세 인라인에서 소속 세트 정보 표시). 주입이 없으면 영역 자체가 나타나지 않는다.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| (표시 전용) | 이 점검표가 어느 세트·문서에 연동되는지 안내 | — |

- 상태: 연동 정보가 없으면 미표시.

### 4-3. 입력 폼 — 점검일 / 점검자 / 점검 항목 / 증빙 첨부
- 구성: 라벨 + 입력칸 4행. 점검일(날짜), 점검자(조직도 선택), 점검 항목(체크리스트), 증빙 첨부(파일 영역).

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 점검일 입력 | 날짜 선택. 저장값이 없으면 기본값 "2026-06-11"이 자동으로 채워져 있음(빈칸 아님) | — |
| [조직도] (점검자) | 조직도 선택 창을 폼 위에 띄움(§4-7) — 점검자 칸은 직접 타이핑 불가, 조직도에서만 채워짐 | 입력 도움말 "조직도에서 점검자를 선택하세요" |
| 항목 [O]·[X]·[해당없음] (점검 항목) | 같은 행에서 한 버튼만 선택(다른 선택 자동 해제). X 선택 시 빨강 강조 | 체크리스트 하단 고정 안내 "X 판정 항목은 확정 시 개선조치로 자동 등록됩니다."(빨강) |
| 비고/사유 입력 (점검 항목) | 각 행의 텍스트 입력("비고 / X 사유" 또는 "비고 및 판단 근거") | — |
| "관련 근거 · {법령} ⓘ" (객체형 항목) | 관련 법령 상세 창을 폼 위에 띄움(§4-8) | — |
| 증빙 첨부 영역 클릭 | 드롭존("파일을 끌어다 놓거나 클릭하여 첨부 (다중 가능)") 클릭 | 안내 "파일 첨부 (프로토타입 — 다중 가능)"만 표시, 실제 업로드 없음 |

- 점검 항목 표시 분기: 호출처가 객체형 세트(경영방침 policy)를 주입하면 각 행 상단에 영역 칩 + 항목명 + 결과유형 칩(O/X 또는 텍스트) + 관련 근거 버튼이 함께 표시된다. 결과유형이 "텍스트"인 항목은 O/X 버튼 대신 자유 텍스트 입력칸("점검 결과를 입력하세요")이 나온다. 결과유형은 항목마다 미리 지정되어 있다. 나머지 호출처(도급관리·이행관리·안전보건교육·문서상세)는 단순 문자열 항목으로, 모든 항목이 O/X/해당없음 + 비고 형식이다.
- 상태: 확정 상태에서도 점검일·점검 항목 등 입력칸은 읽기전용으로 잠기지 않는다(현재 동작 — 잠금 정책은 §6에서 확정). 입력값에 대한 형식·필수 검증은 없다(§5).

|---|---|---|

## 6. 정책

- **필수는 셋이고, 나머지는 막지 않는다(CHK-01 확정)** — 저장을 막는 것은 **점검일 · 점검자 · 모든 항목의 응답** 셋이다. 점검일이 없으면 언제 점검한 기록인지 알 수 없고, 점검자가 없으면 누가 확인했는지 알 수 없으며, 응답이 비면 점검하지 않은 것과 구분되지 않는다. **비고는 필수가 아니다** — 적을 것이 없는 항목이 대부분인데 강제하면 "이상 없음"만 채워 넣게 되어 정말 적어야 할 비고가 묻힌다. 점검일은 미래 날짜를 막는다 — 아직 하지 않은 점검을 기록할 수 없다.
- **전 항목 응답을 강제하고, 부적정에는 사유를 받는다(CHK-02 확정)** — 미응답 항목이 하나라도 있으면 확정할 수 없고, 무엇이 비었는지 목록으로 밝힌다. **"부적정"을 고르면 사유가 필수**다 — 무엇이 왜 부적정인지 없으면 뒤이어 만들어지는 개선조치가 "무엇을 고쳐야 하는지 모르는 조치"가 된다. **"해당없음"에도 사유를 받는다** — 종이 서식에서 가장 흔한 회피 경로가 해당없음이고, 사유 없이 통과시키면 그 문제를 그대로 옮기게 된다. 이는 부서 전수 이행 체크리스트와 같은 원칙이다.
- **확정은 확인을 거치고, 확정하면 잠긴다(CHK-03·CHK-04 확정)** — 확정은 개선조치를 만들고 결재를 올리는 비가역 동작이라 **무엇이 일어나는지 밝힌 확인 단계**를 거친다(부적정 N건 → 개선조치 N건 생성, 결재 상신). 확정 후에는 점검일·항목·비고가 **읽기 전용으로 잠긴다** — 확정본은 기록이고, 고칠 수 있으면 결재를 올린 뒤 내용을 바꾸는 것이 가능해진다. 고쳐야 하면 반려를 거치거나 개정으로 새 버전을 만든다.
- **개선조치의 기한과 담당자는 점검 맥락에서 나온다(CHK-05 확정)** — 고정값을 쓰지 않는다. **기한은 확정일부터 30일**을 기본으로 하고 담당자가 앞당길 수 있다 — 점검에서 나온 부적정은 대개 즉시 조치가 가능한 것들이라 긴 기한을 기본으로 두면 미뤄진다. **담당자는 그 점검 대상 부서의 책임자**를 기본으로 지목하고 부서가 실제 담당자로 바꾼다 — 주관부서가 남의 부서 담당자를 정하지 않는다는 원칙과 같다. **항목의 법령 근거는 개선조치로 그대로 전이**한다 — 왜 고쳐야 하는지가 조치에 없으면 담당자가 판단할 근거를 잃는다. **"해당없음" 항목은 개선조치를 만들지 않고 분모에서도 뺀다** — 해당하지 않는 항목을 분모에 두면 이행률이 실제보다 낮게 나온다.
- **항목 세트는 호출 화면이 갖고, 이 폼은 그리기만 한다(CHK-06 확정)** — 점검 항목·제목·점검자 기본값·첨부 목록의 정본은 **그 업무를 아는 화면**에 있다(경영방침·도급관리·이행관리·안전보건교육). 이 폼이 세트를 갖고 있으면 업무가 바뀔 때 폼을 고쳐야 하고, 폼 하나가 네 업무의 변경을 다 떠안는다. 갱신 주체는 각 업무의 소관 부서이며, 폼은 주입받은 것을 그대로 그린다.
- **작성자와 결재선은 파생값이다(CHK-09 확정)** — 작성자는 **점검을 수행한 사람**(점검자)이고, 결재선은 **그 사람이 속한 부서의 결재 경로**다. 기본값(팀장 → 부서장)만 조직도에서 직위로 파생하고 변경은 조직도 선택기로 받는다. **결재선을 코드에 고정하지 않는다** — 결재권자는 안전보건 법령이 아니라 지자체 위임전결규칙 소관이라 조직 개편·규칙 개정으로 바뀐다.
- **점검자는 조직도에서 고르고 외부 인력은 넣지 않는다(CHK-10 확정)** — 출처는 조직도 전체이며 현재의 6개 부서 고정은 프로토타입 시드다. **용역·위탁 인력을 점검자로 지정하지 않는다** — 점검은 의무 이행의 확인 행위라 그 책임은 외부에 넘길 수 없다. 외부가 실제 작업을 하더라도 점검자는 소관 부서의 공무원이다.
- **개정은 새 버전을 만들고 이전 본을 남긴다(CHK-08 확정)** — 확정본을 고치는 것이 아니라 **버전을 하나 더 만든다**. 새 버전의 초기 상태는 **작성중**이고 이전 버전의 응답을 복사해 시작한다 — 대부분 일부만 바뀌므로 처음부터 다시 채우게 하면 개정 자체를 안 하게 된다. 이전 버전은 확정 상태 그대로 이력에 남고 지워지지 않는다. **개선조치는 새로 만들지 않는다** — 같은 부적정이 두 번 조치로 나가는 것을 막고, 이전 버전에서 만들어진 조치가 그대로 이어진다.
- **문서번호는 온나라가 부여한다(CHK-07 확정)** — 이 화면이 자체 채번하지 않는다. 상신 전에는 **"(온나라에서 부여)"**로 표시하고, 상신 후 받은 번호를 그대로 싣는다. 자체 번호를 붙이면 온나라 번호와 두 개가 돌아 담당자가 어느 것을 공문에 적어야 하는지 알 수 없게 된다. **승인되면 확정으로 잠기고, 반려되면 작성중으로 풀리며 반려 사유가 함께 표시**된다. **반려 시 이미 만들어진 개선조치는 되돌리지 않는다** — 부적정 사실 자체가 사라진 것이 아니고, 담당자가 이미 착수했을 수 있다. 결재가 다시 올라가도 조치는 새로 만들지 않는다.

## 7. 미결사항

없음. 입력 유효성·전 항목 응답과 미점검 차단·확정 사전 확인·확정본 잠금·개선조치 자동 등록 규칙·호출처별 항목 세트의 정본·온나라 결재 결과 반영과 문서번호·개정 규칙·작성자와 결재선 구성·점검자 선택 범위는 모두 §6에서 확정했다.

온나라 **실연계** 자체는 미결이 아니라 본개발 구현 범위이며, 승인·반려가 무엇을 바꾸는지는 §6에 정해져 있다.
