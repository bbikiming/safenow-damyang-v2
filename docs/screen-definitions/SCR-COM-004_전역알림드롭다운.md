# 화면 정의서 — 전역 알림 드롭다운

> 화면 ID: SCR-COM-004 · 화면 유형: 공통 크롬 · 기획 관점(v6) · 구현 정합 2026-08-11
> 판단이 필요했던 항목은 §6 정책에서 확정했습니다.

## 1. 화면 정보

| 항목 | 내용 |
|---|---|
| 화면 ID | SCR-COM-004 |
| 화면명 | 전역 알림 드롭다운 |
| URL 경로 | 전 화면 공통 — 헤더 알림 벨에서 연다 |
| 상위 메뉴 | 공통/전역 |
| 화면 유형 | 공통 크롬(드롭다운) |

지금 **내가 처리해야 할 것이 무엇인지**를 화면을 옮기지 않고 확인하는 자리다. 안전보건 업무는 결재·배정·이행·점검·위험성평가가 서로 다른 화면에서 진행돼, 한곳에 모아 보여 주지 않으면 담당자가 매일 여러 화면을 순회해야 한다. 구성은 머리(건수·모두 읽음)·분류 칩·목록·바닥 링크 네 덩어리이며, 헤더(SCR-COM-001)에서 열고 내 할일·알림 관리(SCR-ADMIN-002)로 이어진다.

---

## 2. 권한 정보

- 메뉴 접근·보기·수정은 시스템 관리의 메뉴 관리(SCR-ADMIN-005)와 권한 관리(SCR-ADMIN-006)에서 설정한다.
- 이 화면 정의서에서는 역할별 권한과 열람 범위를 별도로 정하지 않는다.
- 알림은 **받는 사람에게만** 보인다 — 남의 알림을 열람하지 않으며, 무엇을 누구에게 보낼지는 발송을 유발한 업무 화면이 정한다(SCR-EDOC-009).

## 3. 진입 / 이탈 경로 및 사용자 시나리오

| 구분 | 연결 화면 | 조건 / 트리거 |
|---|---|---|
| 진입 | 헤더 알림 벨 | 벨 선택(SCR-COM-001) |
| 이탈 | 각 업무 화면 | 알림 항목 선택 시 그 건으로 이동 |
| 이탈 | 내 할일 | 바닥 링크 |
| 이탈 | 알림 관리 | 바닥 링크 — 전체 이력 조회(SCR-ADMIN-002) |

| 단계 | 사용자 행동 | 화면 반응 |
|:--:|---|---|
| 1 | 벨을 연다 | 읽지 않은 건이 위에 오도록 최근 순으로 보여 준다 |
| 2 | 분류 칩으로 좁힌다 | 결재·지정·이행·점검·위험 중 하나만 남긴다 |
| 3 | 항목을 고른다 | 그 건의 업무 화면으로 이동하며 읽음으로 바뀐다 |
| 4 | [모두 읽음] | 목록을 지우지 않고 읽음 표시만 바꾼다 |

### 분기 로직

- **분류 칩이 목록을 좁힌다** — 결재·지정·이행·점검·위험 다섯이며 전체가 기본이다. 분류를 나눈 기준은 **누가 다음에 무엇을 해야 하는가**이지 어느 메뉴에서 왔는가가 아니다.
- **읽음 여부가 표시를 가른다** — 읽지 않은 항목은 강조되고 헤더 배지 숫자에 포함된다. 읽으면 배지에서 빠지되 목록에는 남는다.
- **항목을 고르면 그 건으로 바로 간다** — 목록 화면이 아니라 해당 건이다. 목록으로 보내면 다시 찾아야 해서 알림의 의미가 없다.
- **드롭다운이 열리면 떠 있는 안내 패널을 접는다** — 겹쳐서 목록을 가리면 안 된다.

### 예외·경계 시나리오

| 상황 | 화면 반응 |
|---|---|
| 알림이 하나도 없음 | 빈 상태를 표시한다 — 목록 자리를 비워 두지 않는다 |
| 분류를 걸어 0건 | 해당 분류에 알림이 없음을 밝히고 전체로 되돌릴 수 있게 한다 |
| 읽지 않은 건이 0건 | 헤더 배지를 그리지 않는다(SCR-COM-001) |
| 이미 처리된 건의 알림 | 목록에 남긴다 — 지우면 무엇을 처리했는지 되짚을 수 없다. 이동하면 그 화면이 처리 완료 상태를 보여 준다 |
| 알림이 가리키는 건이 삭제됨 | 이동한 화면이 "찾을 수 없습니다"로 받는다 — 알림 쪽에서 미리 지우지 않는다 |
| 목록이 상한을 넘김 | 오래된 것부터 밀려난다. 전체 이력은 알림 관리(SCR-ADMIN-002)에서 본다 |
| 드롭다운이 열린 채 다른 곳 선택 | 닫는다 |

## 4. 화면 구성별 정리

### 4-1. 머리 — 건수와 모두 읽음

- 구성: 알림 제목 + 읽지 않은 건수 + [모두 읽음].

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 드롭다운 열기 | 읽지 않은 건수를 표시한다 | — |
| [모두 읽음] | 전부 읽음으로 바꾼다 | 목록은 그대로 남는다 |

- 상태: **읽지 않음 있음 / 없음** 둘이다. 모두 읽음은 되돌릴 수 없으므로 항목을 지우지는 않는다.

### 4-2. 분류 칩

- 구성: 전체 · 결재 · 지정 · 이행 · 점검 · 위험 여섯 개.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 칩 선택 | 그 분류만 남긴다 | 선택된 칩을 활성으로 표시한다 |
| 전체 선택 | 조건을 푼다 | — |

- 상태: 하나만 선택되며 기본은 전체다. 해당 분류에 알림이 없어도 칩은 남긴다 — 사라지면 그 분류가 있는지조차 알 수 없다.

### 4-3. 알림 목록

- 구성: 분류 배지 · 내용 · 시각. 읽지 않은 항목은 강조.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 항목 선택 | 그 건의 업무 화면으로 이동하고 읽음으로 바꾼다 | 목록이 아니라 해당 건으로 간다 |
| 알림이 0건 | 빈 상태를 표시한다 | — |
| 분류 결과가 0건 | 그 분류에 없음을 밝힌다 | 전체로 되돌릴 수 있게 한다 |

- 상태: 항목별 **읽지 않음 / 읽음**이며, 목록 전체로는 **비어 있음 / 있음 / 분류 결과 없음** 세 상태를 갖는다. 최근 것이 위에 온다.

### 4-4. 바닥 링크

- 구성: 내 할일 열기 · 알림 전체 보기.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 내 할일 열기 | 처리할 일을 모아 보는 화면으로 간다 | — |
| 알림 전체 보기 | 알림 관리로 간다 | SCR-ADMIN-002 |

- 상태: 항상 표시된다. 알림이 0건이어도 남긴다 — 알림이 없을 때가 오히려 전체 이력을 확인하고 싶은 때다.

## 5. 유효성 검사

해당 없음 — 조회 전용이며 저장형 입력이 없다. 무엇을 누구에게 보낼지는 발송 시점(SCR-EDOC-009)과 알림 규칙(SCR-ADMIN-002)이 정한다.

## 6. 정책

- **분류는 다음 행동 기준이다** — 어느 메뉴에서 왔는가가 아니라 **무엇을 해야 하는가**로 나눈다. 메뉴 기준으로 나누면 메뉴가 개편될 때마다 분류가 흔들린다.
- **읽었다고 지우지 않는다** — 무엇을 처리했는지 되짚을 수 있어야 한다. 지우는 것은 상한을 넘겨 밀려날 때뿐이다.
- **항목은 그 건으로 데려간다** — 목록으로 보내면 다시 찾아야 해서 알림이 일을 줄이지 못한다.
- **가리키는 건이 없어졌다고 알림을 미리 지우지 않는다** — 도착한 화면이 그 사실을 알려 주는 편이 낫다. 조용히 사라지면 "분명 알림이 있었는데" 가 된다.
- **이 목록은 이력 대장이 아니다** — 상한이 있고 밀려난다. 전체 이력은 알림 관리(SCR-ADMIN-002)에서 본다.
- **떠 있는 안내 패널과 겹치지 않는다** — 드롭다운이 열리면 패널을 접는다.
- **법령 근거를 붙이지 않는다** — 알림 조회는 법령이 명한 의무의 직접 이행 수단이 아니다. 규칙은 공통 근거 연계(SCR-COM-008)를 따른다.

---

## 7. 미결사항

없음. 분류 기준·읽음 처리와 삭제 여부·이동 대상·끊어진 알림 처리·목록 상한과 이력의 소속·겹침 처리는 모두 §6에서 확정했다.

실제 알림 생성 연동은 미결이 아니라 **본개발 구현 범위**이며, 발송 시점과 채널 방침은 SCR-EDOC-009 §6에 정해져 있다.
