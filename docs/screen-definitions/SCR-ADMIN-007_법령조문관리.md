# 화면 정의서 — 법령·조문

> 화면 ID: SCR-ADMIN-007 · 화면 유형: 기타(관리) · 기획 관점(v6)
> 확정이 필요한 항목은 §7 미결사항에 모았습니다.

---

## 1. 화면 정보

| 항목 | 내용 |
|---|---|
| 화면 ID | SCR-ADMIN-007 |
| 화면명 | 법령·조문 |
| URL 경로 | admin-law.html |
| 상위 메뉴 | 시스템 관리 > 법령 관리 |
| 화면 유형 | 기타 (관리) |

**목적·설명** — 시스템이 수록한 법령·조문의 **대장(臺帳)** 이다. 조문 하나를 건드리기 전에 그 조문을 쓰는 곳이 어디인지 먼저 보여주고(왜: 근거 조문이 저장 데이터의 키로 쓰여 잘못 지우면 유해위험요인·개선조치의 근거가 조용히 끊긴다), 갱신으로 무엇이 바뀌었는지 검토·승인하게 한다. 구성은 ① 정비 큐 ② 무결성 검사 ③ 법령·조문 목록 ④ 미연계 근거 표기 ⑤ 조문 상세(원문·영향 범위·운영 판단) ⑥ 수집 결과 검토 ⑦ 변경 이력 7영역이다. 핵심 연계는 여기서 확인한 조문을 메뉴 근거 매핑(SCR-ADMIN-008)에서 화면에 붙이는 흐름이며, 붙은 결과는 전 화면 상단 근거 표시(SCR-COM-008)로 나타난다. **이 화면에서 조문 본문은 고칠 수 없다** — 본문은 법제처에서 받아온 것이고, 고쳐야 한다면 재수집으로 바로잡는다.

## 3. 진입 / 이탈 경로 및 사용자 시나리오

**진입 / 이탈**

| 구분 | 연결 화면 | 조건 / 트리거 |
|---|---|---|
| 진입 | 시스템 관리 좌측 메뉴 | [법령·조문] 선택 |
| 진입 | 메뉴 근거 매핑(SCR-ADMIN-008) | 상단 [법령·조문] 링크 |
| 이탈 | 메뉴 근거 매핑 | 재검증 대상 항목에서 [메뉴 근거 매핑으로 이동] |
| 이탈 | 현재 화면 유지 | 조문 선택·검토·승인은 화면 이동을 만들지 않는다 |

**사용자 시나리오**

| 단계 | 사용자 행동 | 화면 반응 |
|:--:|---|---|
| 1 | 화면 진입 | 상단에 스냅샷 기준일·법령 수·조문 수와 **"조문 원문은 이 화면에서 고칠 수 없습니다"** 안내. 좌측에 정비 큐·무결성·조문 목록 |
| 2 | 좌측에서 조문 선택 | 우측에 원문(읽기 전용)과 **이 조문을 쓰는 곳**(영향 범위)이 함께 표시 |
| 3 | 영향 범위 확인 | 소스별 건수와 변경 시 처리 방법. 참조가 0이어도 "미사용이 아니다"라는 안내가 함께 나온다 |
| 4 | 적용 축 지정 | 중대산업재해/중대시민재해/양쪽/미판정 중 선택. 조문 사실과 분리 저장 |
| 5 | 참조 0인 조문에 [보관] | 확인 후 목록에서 내려감. **원문은 지워지지 않는다** |
| 6 | 참조가 있는 조문에 [보관] 시도 | 버튼이 비활성이고, 남은 참조 건수와 사유가 함께 표시 |
| 7 | [수집 요청 등록] | 배치가 받아온 결과를 변화 유형별로 표시. 실제 조회가 아님을 명시 |
| 8 | 수집 결과 [승인]/[보류] | 결정이 이력에 남는다. 조문 본문은 바뀌지 않는다 |
| 9 | [내보내기] | 매핑·판단·검증 기록을 재생성 입력 형태로 확인·복사 |
| 10 | 미연계 근거 표기 선택 | 업무문서가 들고 있으나 해석되지 않는 근거 문자열을 4가지로 분류 |

**분기 로직**

- **보관 가능 여부는 영향 범위가 결정한다** — 참조가 1건이라도 있으면 [보관]이 비활성이고 사유가 함께 나온다. 사용자가 판단하는 것이 아니라 화면이 막는다.
- **수집 결과 처리는 변화 유형에 따라 갈린다** — `신규`·`내용 변경`·`시행일 변경`은 승인/보류를 받고, `변경 없음`은 조치 불필요, `수집 실패`는 다음 배치 재시도로 표시하며 **승인 액션을 제공하지 않는다**.
- **검색은 표기 체계가 둘이라 정규화가 필요하다** — 목록의 조문 표기와 원문의 조문 번호가 서로 다른 형식이어서, 정규화 없이 숫자만 입력하면 결과가 0건이 된다.

**엣지케이스**

- **참조 0 ≠ 미사용** — 어느 화면 매핑에도 안 쓰이는 조문이 다수 있는데, 이들은 유해위험요인의 항목 근거나 법정 의무 캘린더의 주기 근거로 쓰인다. 화면이 이 사실을 문구로 밝힌다.
- **탐지 불가 소스** — 대시보드·알림에 하드코딩된 근거는 화면이 셀 수 없다. 건수를 추정하지 않고 **"탐지 불가"** 로 표시한다.
- **정비 큐가 비었을 때** — "처리할 항목 없음"으로 끝내지 않고, **자동 검사가 잡지 못하는 오배정**(조문 번호는 맞는데 내용이 다른 경우)이 있다는 사실을 빈 상태 문구로 밝힌다.
- **검색 0건** — 검색어를 함께 보여주고 초기화 수단을 제공한다.
- **이력 상한** — 프로토타입은 보관 상한이 있어 초과분이 삭제되며, 그 사실을 배너로 알린다. 실 서비스는 무절삭 보존이다.

## 4. 화면 구성별 정리

### 4-1. 상단바

- 구성: 스냅샷 기준일·법령 수·조문 수 · 편집 불가 안내 · 관계 법령 목록 미확정 안내 · [무결성 N건] · [수집 요청 등록] · [내보내기] · [데모 데이터 초기화].

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| [수집 요청 등록] | 우측이 수집 결과 검토로 전환 | "수집 요청을 등록했습니다 — 프로토타입은 실제 조회를 하지 않습니다" |
| [무결성 N건] | 우측이 무결성 검사 결과로 전환 | — |
| [내보내기] | 재생성 입력 내용을 확인·복사하는 팝업 | 조문 원문은 포함하지 않음을 명시 |
| [데모 데이터 초기화] | 삭제될 건수를 항목별로 밝힌 뒤 초기화 | 조문 원문은 영향받지 않음을 명시 |

- 상태: **수집 이력 없음**(버튼이 [수집 요청 등록]) / **검토 대기**(버튼이 [수집 결과 검토]). 무결성 이상이 없으면 무결성 버튼 자체가 나타나지 않는다.

### 4-2. 좌측 — 정비 큐

- 구성: 처리 대상만 모은 목록. 유형은 개발 수정이 필요한 무결성 이상 · 조문 변경으로 재검증이 필요한 매핑 · 수집 결과 검토 대기.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 큐 항목 선택 | 해당 상세 패널로 전환 | 재검증 항목은 매핑 화면 이동 안내 |

- 상태: **처리 대상 있음**(건수 표시) / **비어 있음**. 비어 있을 때도 "자동 검사가 못 잡는 오배정이 있다"를 함께 알린다 — 큐가 비었다고 안전한 것이 아니다.

### 4-3. 좌측 — 무결성 검사

- 구성: 검사 결과 요약 한 줄. 선택 시 상세 패널.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 무결성 행 선택 | 검사 항목별 건수·의미·해당 대상 표시 | — |

- 상태: **적합** / **보완 필요**(이상 건수 표시).

### 4-4. 좌측 — 법령·조문 목록

- 구성: 검색 입력 + 법령별 접기/펼치기 + 조문 행(표기·제목·참조 건수).

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 검색어 입력 | 조문 표기·제목·본문을 함께 찾아 목록을 좁힘. 검색 중에는 법령이 모두 펼쳐짐 | 결과 건수를 전체 대비로 표시 |
| 법령 행 선택 | 그 법령의 조문 접기/펼치기 | — |
| 조문 행 선택 | 우측을 조문 상세로 전환 | — |

- 상태: **전체 표시** / **검색 결과**(건수 표시) / **결과 없음**(검색어와 초기화 수단 노출).

### 4-5. 우측 — 조문 상세

- 구성: 원문(법령명·조·호·제목·본문·시행 정보) · **읽기 전용 표시** · 정본 고지 · 영향 범위 표 · 운영 판단(적용 축·생애주기).
- **원문 옆에 편집 수단이 없는 것이 이 화면의 핵심**이다. 규칙 문구보다 없는 입력란이 강하다.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 적용 축 선택 | 조문의 운영 판단으로 저장. 조문 사실과 분리 | "축을 지정했습니다 — 검증 항목 경고에 반영됩니다" |
| [보관] (참조 0) | 확인 팝업 후 보관 상태로 전환 | "보관했습니다. 참조가 생기면 자동으로 현행으로 돌아옵니다" |
| [보관] (참조 있음) | 비활성 | 남은 참조 건수와 "삭제 기능은 두지 않습니다" 안내 |

- 상태: **현행 / 보관 / 대체됨**. 영향 범위는 소스별로 **건수를 셀 수 있는 것**과 **탐지 불가**를 구분해 표시한다. 로딩 상태는 두지 않는다 — 조문은 화면과 함께 즉시 표시되는 기준 정보다.

### 4-6. 우측 — 수집 결과 검토

- 구성: 조문별 변화 유형 · 변경 전/후 · 영향 화면 · 처리(승인/보류). 상단에 **실제 조회를 하지 않았다는 고지**.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| [승인] | 결정이 이력에 남음 | "승인했습니다 — 실제 반영은 배치 재생성이 합니다" |
| [보류] | 동상 | "보류했습니다" |
| 변경 없음 행 | 처리 액션 없음 | "조치 불필요" |
| 수집 실패 행 | 처리 액션 없음 | "다음 배치에서 재시도" |

- 상태: **결과 없음** / **검토 대기**(미처리 건수) / **처리 완료**. 승인해도 프로토타입은 조문 원문을 바꾸지 않으며 그 사실을 명시한다.

### 4-7. 우측 — 미연계 근거 표기

- 구성: 업무문서가 들고 있으나 수록 조문으로 해석되지 않는 근거 문자열 목록 + 사용 건수 + 분류 선택.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 분류 선택 | 조문 매핑 가능 / 범위 표기 — 분해 필요 / 미수록 조문 — 수집 필요 / 법령 아님(확정) 중 하나로 지정 | "분류했습니다" |

- 상태: **미분류**(건수) / **분류 완료**. 이 영역이 이 화면의 가장 큰 실제 일감이며, 규모를 상단에 밝힌다.

### 4-8. 하단 — 변경 이력

- 구성: 일시 · 층위 · 대상 · 행위 · 변경 전→후 · 처리자. 단일 타임라인.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 화면 내 모든 변경 | 전·후 값과 함께 자동 기록 | — |

- 상태: **이력 없음** / **기록 있음** / **상한 도달**(초과분 삭제 안내). 전·후 값을 함께 남기지 않으면 되돌리기도 소명도 불가능하다.

## 5. 유효성 검사

> 이 화면에서 사용자가 값을 입력·저장하는 지점은 **운영 판단(적용 축)과 미연계 표기 분류** 두 곳이다. 조문 본문·법령 메타는 입력란 자체가 없다.

| 입력 항목 | 필수 | 형식/규칙 | 오류 안내 |
|---|---|---|---|
| 적용 축 | 선택 | 제공 목록에서 선택. 직접 입력 불가 | 미지정은 오류가 아니다 |
| 미연계 표기 분류 | 선택 | 제공된 4분류 중 선택 | 미분류는 오류가 아니라 남은 일감으로 집계 |
| 조문 본문·제목·시행일 | — | **입력란을 제공하지 않는다** | 해당 없음 |
| 수집 결과 처리 | 선택 | 승인 또는 보류. 변경 없음·수집 실패 행은 처리 대상 아님 | 처리하지 않아도 진행 가능 |

- **자유 입력을 막는 것이 기획 의도다.** 조문을 손으로 고칠 수 있으면 "법제처 원문"이라는 화면의 약속이 깨지고, 출처를 위조하는 도구가 된다.

## 6. 정책

- **조문은 사실, 나머지는 판단** — 법령 메타와 조문 본문은 수집 결과이고 사람이 고치지 않는다. 사람이 남기는 값(적용 축·생애주기·분류)은 별도 영역에 저장되어 조문 사실을 덮을 수 없다.
- **삭제라는 조작을 두지 않는다** — 조문 식별자가 저장 데이터의 키로 쓰이므로 지우면 유해위험요인·개선조치의 근거가 조용히 끊긴다. 참조가 없을 때만 **보관**으로 내리고, 원문은 남긴다. 참조가 생기면 다시 현행으로 돌아온다.
- **영향을 먼저 보여준다** — 조문을 바꾸는 모든 조작은 영향 범위 확인이 선행된다. 화면이 세지 못하는 소스는 건수를 추정하지 않고 탐지 불가로 표시한다(SCR-COM-008 연계).
- **화면이 법제처를 직접 조회하지 않는다** — 외부 연계는 배치가 담당하고 화면은 그 결과를 검토·승인한다. 화면이 직접 조회하면 보안 심의에 제출한 연계 구조와 실제가 어긋난다. 프로토타입은 이 흐름을 시뮬레이션으로 보여주며 그 사실을 명시한다.
- **정본 고지** — 화면의 조문은 수집일 기준 사본이며 법적 효력은 국가법령정보센터 정본에 있다는 안내를 상시 노출한다. 소명 자료로 쓰겠다면서 정본이 아님을 밝히지 않으면 낡은 사본으로 판단한 책임이 시스템으로 온다.
- **수록 목록은 완결이 아니다** — 관계 법령 목록은 발주처 확정 대기 상태이며 상단에 상시 표기한다. 수록된 것이 전부라는 착시를 막는다(SCR-COM-008 연계).
- **자동 검사의 한계를 숨기지 않는다** — 무결성 검사는 끊어진 참조·미반영 매핑 같은 구조적 이상만 잡는다. 조문 번호는 맞는데 내용이 다른 오배정은 전수 대조로만 발견되며, 실제로 그렇게 발견된 사례가 있다.
