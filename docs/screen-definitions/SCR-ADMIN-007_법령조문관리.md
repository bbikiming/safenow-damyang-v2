# 화면 정의서 — 법령·조문

> 화면 ID: SCR-ADMIN-007 · 화면 유형: 기타 (관리) · 기획 관점(v6)
> 판단이 필요했던 항목은 §6 정책에서 확정했습니다.

---

## 1. 화면 정보

| 항목 | 내용 |
|---|---|
| 화면 ID | SCR-ADMIN-007 |
| 화면명 | 법령·조문 |
| URL 경로 | admin-law.html |
| 상위 메뉴 | 시스템 관리 > 법령 관리 |
| 화면 유형 | 기타 (관리) |

**목적·설명** — 시스템이 수록한 법령·조문의 **대장(臺帳)** 이다. 조문 하나를 건드리기 전에 그 조문을 쓰는 곳이 어디인지 먼저 보여주고(왜: 근거 조문이 저장 데이터의 키로 쓰여 잘못 지우면 유해위험요인·개선조치의 근거가 조용히 끊긴다), 갱신으로 무엇이 바뀌었는지 검토·승인하게 한다. 구성은 ① 정비 큐 ② 무결성 검사 ③ 법령·조문 목록 ④ 미연계 근거 표기 ⑤ 조문 상세(원문·영향 범위·운영 판단) ⑥ 수집 결과 검토 ⑦ 변경 이력 7영역이다. 핵심 연계는 여기서 확인한 조문을 메뉴 근거 매핑(SCR-ADMIN-008)에서 화면에 붙이는 흐름이며, 붙은 결과는 전 화면 상단 근거 표시(SCR-COM-008)로 나타난다. **이 화면에서 조문 본문은 고칠 수 없다** — 본문은 법제처에서 받아온 것이고, 고쳐야 한다면 재수집으로 바로잡는다. **수집이 실패했을 때의 알림과 재시도도 이 화면 몫이 아니다** — 연계 관리(SCR-ADMIN-004)가 단일 창구이고, 이 화면은 그 화면을 지목한다(§6 LWA-12).

## 2. 권한 정보

- 메뉴 접근·보기·수정은 시스템 관리의 메뉴 관리(SCR-ADMIN-005)와 권한 관리(SCR-ADMIN-006)에서 설정한다.
- 이 화면 정의서에서는 역할별 권한과 열람 범위를 별도로 정하지 않는다.
- 이 화면은 시스템 관리 메뉴군에 속한다. 조문 조회, 운영 판단 지정, 수집 결과 승인·보류는 §3~§6의 업무 흐름과 상태 전이 조건을 따른다.

**사용자 시나리오**

| 단계 | 사용자 행동 | 화면 반응 |
|:--:|---|---|
| 1 | 화면 진입 | 상단에 스냅샷 기준일·법령 수·조문 수와 **"조문 원문은 이 화면에서 고칠 수 없습니다"** 안내. 좌측에 정비 큐·무결성·조문 목록 |
| 2 | 좌측에서 조문 선택 | 우측에 원문(읽기 전용)과 **이 조문을 쓰는 곳**(영향 범위)이 함께 표시 |
| 3 | 영향 범위 확인 | 소스별 건수와 변경 시 처리 방법. 참조가 0이어도 "미사용이 아니다"라는 안내가 함께 나온다 |
| 4 | 적용 축 지정 | 중대산업재해/중대시민재해/양쪽/미판정 중 선택. 조문 사실과 분리 저장 |
| 5 | 참조 0인 조문에 [보관] | 확인 후 목록에서 내려감. **원문은 지워지지 않는다** |
| 6 | 참조가 있는 조문에 [보관] 시도 | 버튼이 비활성이고, 남은 참조 건수와 사유가 함께 표시 |
| 7 | [수집 요청 등록] | 배치가 받아온 결과를 변화 유형별로 표시. 실제 조회가 아님을 명시 |
| 8 | 수집 결과 [승인]/[보류] | 결정이 이력에 남는다. 조문 본문은 바뀌지 않는다 |
| 9 | [내보내기] | 매핑·판단·검증 기록을 재생성 입력 형태로 확인·복사 |
| 10 | 미연계 근거 표기 선택 | 업무문서가 들고 있으나 해석되지 않는 근거 문자열을 4가지로 분류 |

**분기 로직**

- **보관 가능 여부는 영향 범위가 결정한다** — 참조가 1건이라도 있으면 [보관]이 비활성이고 사유가 함께 나온다. 사용자가 판단하는 것이 아니라 화면이 막는다.
- **수집 결과 처리는 변화 유형에 따라 갈린다** — `신규`·`내용 변경`·`시행일 변경`은 승인/보류를 받고, `변경 없음`은 조치 불필요이며, `수집 실패`는 **승인 액션을 제공하지 않는다** — 받아오지 못한 것을 승인할 수는 없다. 실패 건의 재시도도 이 표가 아니라 연계 관리(SCR-ADMIN-004)에서 사람이 누른다(§6 LWA-12).
- **검색은 표기 체계가 둘이라 정규화가 필요하다** — 목록의 조문 표기와 원문의 조문 번호가 서로 다른 형식이어서, 정규화 없이 숫자만 입력하면 결과가 0건이 된다.

**엣지케이스**

- **참조 0 ≠ 미사용** — 어느 화면 매핑에도 안 쓰이는 조문이 다수 있는데, 이들은 유해위험요인의 항목 근거나 법정 의무 캘린더의 주기 근거로 쓰인다. 화면이 이 사실을 문구로 밝힌다.
- **탐지 불가 소스** — 대시보드·알림에 하드코딩된 근거는 화면이 셀 수 없다. 건수를 추정하지 않고 **"탐지 불가"** 로 표시한다.
- **정비 큐가 비었을 때** — "처리할 항목 없음"으로 끝내지 않고, **자동 검사가 잡지 못하는 오배정**(조문 번호는 맞는데 내용이 다른 경우)이 있다는 사실을 빈 상태 문구로 밝힌다.
- **검색 0건** — 검색어를 함께 보여주고 초기화 수단을 제공한다.
- **이력 상한** — 프로토타입은 보관 상한이 있어 초과분이 삭제되며, 그 사실을 배너로 알린다. 실 서비스는 무절삭 보존이다.

## 4. 화면 구성별 정리

### 4-1. 상단바

- 구성: 스냅샷 기준일·법령 수·조문 수 · 편집 불가 안내 · 관계 법령 목록 미확정 안내 · [무결성 N건] · [수집 요청 등록] · [내보내기] · [데모 데이터 초기화].

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| [수집 요청 등록] | 우측이 수집 결과 검토로 전환 | "수집 요청을 등록했습니다 — 프로토타입은 실제 조회를 하지 않습니다" |
| [무결성 N건] | 우측이 무결성 검사 결과로 전환 | — |
| [내보내기] | 재생성 입력 내용을 확인·복사하는 팝업 | 조문 원문은 포함하지 않음을 명시 |
| [데모 데이터 초기화] | 삭제될 건수를 항목별로 밝힌 뒤 초기화 | 조문 원문은 영향받지 않음을 명시 |

- 상태: **수집 이력 없음**(버튼이 [수집 요청 등록]) / **검토 대기**(버튼이 [수집 결과 검토]). 무결성 이상이 없으면 무결성 버튼 자체가 나타나지 않는다.

### 4-2. 좌측 — 정비 큐

- 구성: 처리 대상만 모은 목록. 유형은 개발 수정이 필요한 무결성 이상 · 조문 변경으로 재검증이 필요한 매핑 · 수집 결과 검토 대기.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 큐 항목 선택 | 해당 상세 패널로 전환 | 재검증 항목은 매핑 화면 이동 안내 |

- 상태: **처리 대상 있음**(건수 표시) / **비어 있음**. 비어 있을 때도 "자동 검사가 못 잡는 오배정이 있다"를 함께 알린다 — 큐가 비었다고 안전한 것이 아니다.

### 4-3. 좌측 — 무결성 검사

- 구성: 검사 결과 요약 한 줄. 선택 시 상세 패널.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 무결성 행 선택 | 검사 항목별 건수·의미·해당 대상 표시 | — |

- 상태: **적합** / **보완 필요**(이상 건수 표시).

### 4-4. 좌측 — 법령·조문 목록

- 구성: 검색 입력 + 법령별 접기/펼치기 + 조문 행(표기·제목·참조 건수).

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 검색어 입력 | 조문 표기·제목·본문을 함께 찾아 목록을 좁힘. 검색 중에는 법령이 모두 펼쳐짐 | 결과 건수를 전체 대비로 표시 |
| 법령 행 선택 | 그 법령의 조문 접기/펼치기 | — |
| 조문 행 선택 | 우측을 조문 상세로 전환 | — |

- 상태: **전체 표시** / **검색 결과**(건수 표시) / **결과 없음**(검색어와 초기화 수단 노출).

### 4-5. 우측 — 조문 상세

- 구성: 원문(법령명·조·호·제목·본문·시행 정보) · **읽기 전용 표시** · 정본 고지 · 영향 범위 표 · 운영 판단(적용 축·생애주기).
- **원문 옆에 편집 수단이 없는 것이 이 화면의 핵심**이다. 규칙 문구보다 없는 입력란이 강하다.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 적용 축 선택 | 조문의 운영 판단으로 저장. 조문 사실과 분리 | "축을 지정했습니다 — 검증 항목 경고에 반영됩니다" |
| [보관] (참조 0) | 확인 팝업 후 보관 상태로 전환 | "보관했습니다. 참조가 생기면 자동으로 현행으로 돌아옵니다" |
| [보관] (참조 있음) | 비활성 | 남은 참조 건수와 "삭제 기능은 두지 않습니다" 안내 |

- 상태: **현행 / 보관 / 대체됨**. 영향 범위는 소스별로 **건수를 셀 수 있는 것**과 **탐지 불가**를 구분해 표시한다. 로딩 상태는 두지 않는다 — 조문은 화면과 함께 즉시 표시되는 기준 정보다.

### 4-6. 우측 — 수집 결과 검토

- 구성: 조문별 변화 유형 · 변경 전/후 · 영향 화면 · 처리(승인/보류). 상단에 **실제 조회를 하지 않았다는 고지**.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| [승인] | 결정이 이력에 남음 | "승인했습니다 — 실제 반영은 배치 재생성이 합니다" |
| [보류] | 동상 | "보류했습니다" |
| 변경 없음 행 | 처리 액션 없음 | "조치 불필요" |
| 수집 실패 행 | 처리 액션 없음 — 승인·보류 대상이 아니다 | 재시도는 연계 관리(SCR-ADMIN-004)에서 사람이 누른다. **현재 안내 문구는 「다음 배치에서 재시도」로 남아 있어 §6 LWA-12와 어긋난다 — 개발 시 §6을 따른다** |

- 상태: **결과 없음** / **검토 대기**(미처리 건수) / **처리 완료**. 승인해도 프로토타입은 조문 원문을 바꾸지 않으며 그 사실을 명시한다. **수집 실패한 법령은 그동안 마지막 성공 수집분을 그대로 보여준다** — 빈 화면이 되지 않는 대신 낡은 조문을 근거로 쓰게 되므로, 그 사실과 마지막 성공 수집일을 화면이 함께 밝힌다(§6 LWA-06).

### 4-7. 우측 — 미연계 근거 표기

- 구성: 업무문서가 들고 있으나 수록 조문으로 해석되지 않는 근거 문자열 목록 + 사용 건수 + 분류 선택.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 분류 선택 | 조문 매핑 가능 / 범위 표기 — 분해 필요 / 미수록 조문 — 수집 필요 / 법령 아님(확정) 중 하나로 지정 | "분류했습니다" |

- 상태: **미분류**(건수) / **분류 완료**. 이 영역이 이 화면의 가장 큰 실제 일감이며, 규모를 상단에 밝힌다.

### 4-8. 하단 — 변경 이력

- 구성: 일시 · 층위 · 대상 · 행위 · 변경 전→후 · 처리자. 단일 타임라인.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 화면 내 모든 변경 | 전·후 값과 함께 자동 기록 | — |

- 상태: **이력 없음** / **기록 있음** / **상한 도달**(초과분 삭제 안내). 전·후 값을 함께 남기지 않으면 되돌리기도 소명도 불가능하다.

## 5. 유효성 검사

> 이 화면에서 사용자가 값을 입력·저장하는 지점은 **운영 판단(적용 축)과 미연계 표기 분류** 두 곳이다. 조문 본문·법령 메타는 입력란 자체가 없다.

| 입력 항목 | 필수 | 형식/규칙 | 오류 안내 |
|---|---|---|---|
| 적용 축 | 선택 | 제공 목록에서 선택. 직접 입력 불가 | 미지정은 오류가 아니다 |
| 미연계 표기 분류 | 선택 | 제공된 4분류 중 선택 | 미분류는 오류가 아니라 남은 일감으로 집계 |
| 조문 본문·제목·시행일 | — | **입력란을 제공하지 않는다** | 해당 없음 |
| 수집 결과 처리 | 선택 | 승인 또는 보류. 변경 없음·수집 실패 행은 처리 대상 아님 | 처리하지 않아도 진행 가능 |

- **자유 입력을 막는 것이 기획 의도다.** 조문을 손으로 고칠 수 있으면 "법제처 원문"이라는 화면의 약속이 깨지고, 출처를 위조하는 도구가 된다.

## 6. 정책

- **조문은 사실, 나머지는 판단** — 법령 메타와 조문 본문은 수집 결과이고 사람이 고치지 않는다. 사람이 남기는 값(적용 축·생애주기·분류)은 별도 영역에 저장되어 조문 사실을 덮을 수 없다.
- **삭제라는 조작을 두지 않는다** — 조문 식별자가 저장 데이터의 키로 쓰이므로 지우면 유해위험요인·개선조치의 근거가 조용히 끊긴다. 참조가 없을 때만 **보관**으로 내리고, 원문은 남긴다. 참조가 생기면 다시 현행으로 돌아온다.
- **영향을 먼저 보여준다** — 조문을 바꾸는 모든 조작은 영향 범위 확인이 선행된다. 화면이 세지 못하는 소스는 건수를 추정하지 않고 탐지 불가로 표시한다(SCR-COM-008 연계).
- **화면이 법제처를 직접 조회하지 않는다** — 외부 연계는 배치가 담당하고 화면은 그 결과를 검토·승인한다. 화면이 직접 조회하면 보안 심의에 제출한 연계 구조와 실제가 어긋난다. 프로토타입은 이 흐름을 시뮬레이션으로 보여주며 그 사실을 명시한다.
- **정본 고지** — 화면의 조문은 수집일 기준 사본이며 법적 효력은 국가법령정보센터 정본에 있다는 안내를 상시 노출한다. 소명 자료로 쓰겠다면서 정본이 아님을 밝히지 않으면 낡은 사본으로 판단한 책임이 시스템으로 온다.
- **수록 목록은 완결이 아니다** — 담양군 적용 관계 법령 목록이 들어오기 전까지 상단에 "기관 적용 목록 미등록"을 상시 표기한다. 확인된 조문은 그대로 조회할 수 있고, 수록된 것이 전부라는 착시만 막는다(SCR-COM-008 연계).
- **조회와 승인은 다른 단계다** — 수집 결과 승인은 "조문 내용이 이렇게 바뀌었다"를 확정하는 행위라 되돌리기 어렵고, 그 판단 주체는 화면이 놓인 시스템 관리가 아니라 재난안전과다. 승인은 조회와 같은 동작으로 묶지 않고 변화 유형별로 명시적으로 처리하며 결정은 이력에 남는다. **승인 주체는 재난안전과 담당자**다(LWA-09 확정) — 화면이 시스템 관리에 있다는 것과 판단 주체가 누구인가는 다른 문제이고, 조문 개정이 어느 화면의 근거를 흔드는지는 안전보건 업무를 아는 사람만 판단할 수 있다. 시스템 관리자는 배치 실행·실패 조치까지 맡고 조문 내용 승인은 하지 않는다.
- **조문을 짝짓는 키는 법령 식별자와 조문 번호다(LWA-01 확정)** — 수집처가 조문마다 고유 식별자를 주지 않으므로 **법령 식별자 + 조 번호(+ 항·호 구분)**를 시스템 조문 식별자로 삼는다. 이 조합은 개정으로 조문이 신설·삭제돼도 유지되며, 조문 번호가 바뀌는 전면 개정에서만 짝짓기가 끊긴다. **끊기면 자동으로 이어 붙이지 않고 "대응 없음"으로 드러낸다** — 번호가 비슷하다는 이유로 다른 조문에 이어 붙이면 화면의 근거가 조용히 다른 조문을 가리키게 된다.
- **호 단위 조문은 자동으로 다시 나누지 않는다(LWA-02 확정)** — 시행령 제4조를 아홉 개 호로 나눠 수록한 것처럼, 한 조를 호 단위로 절취한 조문이 있다. 재수집하면 **조 본문 전체를 받아 기존 절취분과 대조**하고, 본문이 바뀌었으면 **절취분 전부를 재검토 대상으로 올린다**. 자동 분할하지 않는 이유는 개정이 호 구조 자체를 바꾸기 때문이다 — 실제로 시행령 제15조 제5호가 각 목 구조로 전면 개편된 적이 있다. 사람이 보고 다시 절취한다.
- **시행일은 조문마다 따로 갖는다(LWA-03 확정)** — 한 공포본이 조문마다 시행일을 달리 정하는 경우가 실재하므로, 시행일을 법령 단위가 아니라 **조문 단위 값**으로 둔다. 현행 여부 판정도 조문 단위이며, 아직 시행되지 않은 조문은 **수록하되 "시행 예정"으로 표시**하고 화면 근거로는 쓰지 않는다 — 시행 전 조문을 근거로 대면 지금 없는 의무를 있다고 말하는 것이 된다.
- **공백과 줄바꿈은 변경으로 보지 않는다(LWA-04 확정)** — 비교 전에 **연속 공백을 하나로 줄이고 앞뒤 공백을 지운 뒤** 대조한다. 줄바꿈은 항·호 구분이라 지우지 않되, 개행 문자의 종류 차이는 무시한다. 문장부호와 한자 병기는 **변경으로 본다** — 조문에서 괄호 안 한자는 용어를 확정하는 장치라 바뀌면 뜻이 달라질 수 있다. 서식만 바뀐 것으로 판정된 건도 이력에는 남기되 재검토 대상으로 올리지 않는다.
- **과거 본문은 지우지 않는다(LWA-05 확정)** — 보관 기간을 숫자로 정하지 않는다. 조문 본문은 용량이 작고, "그때는 조문이 이랬다"를 보일 수 없으면 과거 판단의 정당성을 설명할 방법이 사라진다. 사고 소명은 몇 년 뒤에도 들어올 수 있으므로 임의 연한으로 지우는 쪽의 위험이 훨씬 크다.
- **수집 실패는 첫날부터 알린다(LWA-06 확정)** — 며칠을 기다리지 않는다. 실패한 날 바로 시스템 관리자에게 알리고, **3일 연속 실패하면 재난안전과 담당자에게도** 알린다. 앞은 배치를 고칠 사람이고 뒤는 낡은 조문을 근거로 판단하고 있을 사람이라 알려야 할 이유가 다르다. 화면 상단에는 마지막 성공 수집일을 항상 띄워, 알림을 놓쳐도 화면을 열면 보이게 한다.
- **수집 실패의 재시도는 이 화면에 두지 않는다(LWA-12 확정)** — 실패의 알림과 재시도는 연계 관리(SCR-ADMIN-004)가 **단일 창구**다. 도메인마다 재시도 버튼을 두면 담당자는 어디서 눌러야 하는지 알 수 없고, 결국 한쪽이 방치된다. 그래서 이 화면의 수집 결과 표는 실패 행에 처리 액션을 두지 않고, 수집 상태 안내가 연계 관리를 지목한다. **재시도는 사람이 누르는 것 하나뿐이고 자동 재시도는 두지 않는다** — 인증키 만료·응답 없음·규격 변경처럼 다시 보내도 같은 결과인 실패가 대부분이라, 자동 재시도는 이력을 같은 실패로 채워 진짜 원인을 덮는다(연계 관리 §6과 같은 규칙). **정해진 때에 다음 배치가 도는 것은 재시도가 아니다** — 배치는 대상 법령 전체를 주기대로 다시 받아올 뿐 실패한 그 건을 겨냥하지 않고, 주기가 하루면 그 하루 동안 화면은 마지막 성공 수집분을 계속 근거로 내세운다. 실패 행에 "다음 배치에서 재시도"라고 적으면 기다리면 해결된다는 뜻이 되어 아무도 손대지 않는다 — 낡은 조문을 근거로 판단하는 시간이 그만큼 늘어난다.
- **적용 축은 재난안전과가 정하고, 미판정을 허용한다(LWA-07 확정)** — 중대산업재해 축인지 중대시민재해 축인지(또는 둘 다인지)는 안전보건 업무 판단이다. **미판정 상태를 허용**하되 목록에 "축 미판정"으로 드러내고 그 조문은 화면 근거로 붙일 수 없게 막는다 — 축을 모르는 조문을 근거로 쓰면 한 축만 붙이는 반쪽 근거가 생긴다.
- **정본 고지 문구는 확정해 고정한다(LWA-08 확정)** — "이 화면의 조문은 (수집일) 기준 사본이며, 법적 효력은 국가법령정보센터의 정본에 있습니다." 한 문장이다. 법무 검토를 별도로 태우지 않는다 — 사본임을 밝히고 정본의 소재를 가리키는 것이 고지의 전부이고, 그 이상을 쓰면 오히려 책임 범위를 스스로 넓히게 된다. 수집일은 문구 안에서 실제 값으로 채운다.
- **별표는 수록하되 발췌 표시를 단다(LWA-10 확정)** — 표 구조라 조문과 다르게 다뤄야 하지만, 수록하지 않으면 교육 시간·안전등급 구간·공중이용시설 범위처럼 **화면이 실제로 쓰는 숫자의 근거가 통째로 빠진다**. 전문을 옮기기 어려운 별표는 **시스템이 쓰는 부분만 발췌하고 발췌임을 명시**하며 전문은 정본 링크로 잇는다. 발췌 조문에는 승인 액션을 제공하되, 재수집 시 **발췌 범위 밖의 변경은 자동 판정하지 않고 사람이 확인**한다.
- **이용 조건은 출처 표기와 정본 고지로 충족한다(LWA-11 확정)** — 국가법령정보는 공공데이터라 저장·표시가 허용되며, 조건은 출처를 밝히고 정본이 아님을 고지하는 것이다. 둘 다 화면에 상시 노출하고 있다. **조문을 요약·의역해 싣지 않는 규칙**도 여기에 걸린다 — 원문이라고 하면서 고친 문장을 내면 출처 표기 자체가 거짓이 된다. 쉬운 설명은 원문과 분리된 레이어로 두고 "요약 — 원문 아님"을 함께 표시한다.
- **자동 검사의 한계를 숨기지 않는다** — 무결성 검사는 끊어진 참조·미반영 매핑 같은 구조적 이상만 잡는다. 조문 번호는 맞는데 내용이 다른 오배정은 전수 대조로만 발견되며, 실제로 그렇게 발견된 사례가 있다.
- **계열에 담기지 않은 법령을 조용히 숨기지 않는다** — 좌측 목록은 법령을 계열(중대재해처벌법·산업안전보건법·시설물안전법)로 묶어 보여주는데, 계열 구조에 넣지 않은 법령은 **총 조문 수에는 더해지면서 목록에는 나타나지 않는다**. 실제로 시설물안전법을 새로 수록했을 때 그렇게 됐다 — 수집은 됐는데 열어볼 수가 없으니 "사라졌다"로 읽힌다. 그래서 계열에 담기지 않은 법령이 있으면 목록 위에 어느 법령인지 이름과 함께 알린다.

## 7. 미결사항

없음. 조문 식별자 대응 규칙·호 단위 조문의 재수집·조문 단위 시행일·변경 비교 기준·본문 이력 보존·수집 실패 알림과 재시도 창구·적용 축 판정 주체·정본 고지 문구·수집 승인 주체·별표 수록 방식·이용 조건은 모두 §6에서 확정했다.
