관리대상·구성원·기준문서처럼 **여러 건을 한 번에 넣어야 하는 자료**를 표 파일로 올리는 화면이다. 사업장 수십 개와 시설물 수십 건을 한 건씩 등록하게 하면 초기 구축이 사실상 불가능하고, 검증 없이 밀어 넣으면 틀린 대상 위에 이행이 쌓인다. 그래서 이 화면은 **서식 내려받기 → 파일 올리기 → 유효성 확인** 세 단계로 구성되고, 확인을 통과한 건만 관리대상 현황(SCR-BASE-001~003)에 반영된다.

## 3. 진입 / 이탈 경로 및 사용자 시나리오

| 구분 | 연결 화면 | 조건 / 트리거 |
|---|---|---|
| 진입 | 기본정보 > 데이터 일괄등록 | 메뉴 선택 |
| 진입 | 관리대상 현황 | 여러 건을 한 번에 넣을 때(SCR-BASE-001~003) |
| 이탈 | 관리대상 현황 | 반영 후 결과 확인 |

| 단계 | 사용자 행동 | 화면 반응 |
|:--:|---|---|
| 1 | 어떤 자료를 넣을지 정한다 | 자료 종류별 서식을 내려받게 한다 |
| 2 | 서식을 채워 올린다 | 파일을 받아 행 단위로 검사한다 |
| 3 | 검사 결과를 본다 | 정상·오류를 행마다 사유와 함께 보여 준다 |
| 4 | 정상 건을 반영한다 | 오류 건은 반영하지 않고 남긴다 |

### 분기 로직

- **자료 종류가 서식과 검사 규칙을 가른다** — 서식은 **사업장과 기준문서 목록 둘**이고(§6 BLK-01), 필요한 항목이 서로 달라 검사도 따로다. 하나의 서식으로 통합하지 않는다 — 통합하면 대부분의 칸이 비는 표가 되어 어느 칸이 필수인지 알 수 없게 된다.
- **정본이 밖에 있는 자료는 이 화면으로 들어오지 않는다** — 공중이용시설(시설물 대장·FMS 연계) · 구성원·인력(행정포털 연계) · 원료·제조물(명단 미확보, 개별 등록)은 서식을 두지 않고 **뺀 이유와 갈 곳을 화면에 적는다**. 목록에서 지우기만 하면 담당자가 사업장 서식에 시설물을 적어 올린다.
- **검사 결과가 행 단위로 갈린다** — **정상**은 반영 대상, **오류**는 반영하지 않고 사유를 붙인다. 파일 하나가 통째로 성공하거나 실패하는 방식을 쓰지 않는다.
- **오류가 있어도 정상 건은 반영한다** — 한 행이 틀렸다고 나머지를 막으면 담당자는 결국 검사를 우회하려 하고, 47행 중 3행 때문에 44행을 다시 올리게 된다.
- **반영은 확인을 거친다** — 파일을 올리는 것과 반영하는 것을 나눈다. 올리자마자 반영하면 검사 결과를 보기 전에 자료가 들어간다.

### 예외·경계 시나리오

| 상황 | 화면 반응 |
|---|---|
| 서식과 다른 파일을 올림 | 반영하지 않고 서식이 다르다는 사실을 알린다 — 항목이 어긋난 채 넣으면 값이 밀려 전 건이 오염된다 |
| 필수 항목이 빈 행 | 그 행을 오류로 표시하고 무엇이 비었는지 사유에 적는다 |
| 이미 있는 자료와 중복되는 행 | 오류가 아니라 **중복**으로 구분해 표시한다 — 덮어쓸지 건너뛸지 사람이 정한다 |
| 전 행이 오류 | 반영 수단을 내지 않고 사유를 목록으로 보여 준다 |
| 검사 결과를 보지 않고 나감 | 반영되지 않는다 — 올린 것만으로는 아무 일도 일어나지 않는다 |
| 프로토타입에서 실행 | 실제 파일 내용을 해석하지 않고 예시 결과를 보여 준다는 사실을 밝힌다 |

## 4. 화면 구성별 정리

### 4-1. 서식 내려받기

- 구성: 실제 일괄등록 대상인 **사업장 · 기준문서 목록** 두 서식과, 일괄등록에서 제외한 자료의 사유·대체 경로 안내.
- 원료·제조물은 이 화면을 진입 경로로 안내하지 않고 관리대상 현황의 해당 탭에서 개별 등록한다. 서식 부재는 끊긴 경로가 아니라 의도적으로 닫은 일괄등록 범위다.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 서식 선택 | 그 자료의 서식을 내려받는다 | 프로토타입에서는 안내만 표시한다 |
| 화면 진입 | 어떤 자료를 넣을 수 있는지 목록으로 보여 준다 | 서식이 곧 넣을 수 있는 자료의 범위다 |

- 상태: 자료 종류마다 서식이 하나씩 있다. 서식이 없는 자료는 일괄등록 대상이 아니며, 그 사실이 이 목록으로 드러난다.

### 4-2. 파일 올리기

- 구성: 파일을 고르거나 끌어다 놓는 영역과 지원 형식 안내.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 파일 선택·끌어놓기 | 파일을 받아 검사를 시작한다 | 지원 형식·용량 기준을 함께 안내한다 |
| 서식과 다른 파일 | 검사 단계에서 걸러 낸다 | 반영하지 않는다 |
| 파일을 고르지 않고 진행 | 아무 일도 하지 않는다 | — |

- 상태: **파일 미선택 / 선택됨 / 검사 완료** 세 단계다. 올린 것만으로는 반영되지 않는다.

### 4-3. 유효성 확인 결과

- 구성: 파일명과 총 행 수 · 정상 건수 · 오류 건수 · 행별 결과 표(행 번호 · 대상 이름 · 판정 · 사유).

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 검사 완료 | 전체 행 수와 정상·오류 건수를 먼저 보여 준다 | 몇 건이 들어가고 몇 건이 막히는지 먼저 알린다 |
| 오류 행 | 행 번호와 사유를 함께 표시한다 | 어느 줄을 고쳐야 하는지 알 수 있어야 한다 |
| 중복 행 | 오류와 구분해 표시하고 **그 행에서** 갱신·건너뛰기를 고르게 한다 | 기본값은 **건너뛰기**다 |
| 중복 행 [갱신] | 그 한 건만 갱신 대상으로 표시한다 | 무엇이 바뀌는지 항목 단위로 함께 보여 준다 |
| 반영 실행 | 정상 건과 갱신으로 고른 중복 건을 넣는다 | “신규 N건 · 갱신 N건 · 건너뜀 N건 · 오류 N건” |
| 갱신이 포함된 반영 | 확인 단계를 한 번 더 거친다 | 되돌리기 가장 어려운 동작이다 |
| 미리보기를 떠남 | 대기 중이던 내용은 사라지고 기존 자료는 그대로다 | 파일을 다시 올리면 처음부터 검사한다 |
| 전 행 오류 | 반영 수단을 내지 않는다 | 사유 목록만 보여 준다 |

- 상태: 행별로 **정상 / 오류 / 중복** 세 판정이고, 파일 전체로는 **검사 전 / 검사 완료(반영 가능) / 검사 완료(반영 불가)** 세 상태를 갖는다.

**중복 행을 어떻게 처리하나 (BLK-03 확정)** — 이 여섯 가지가 정해져 있지 않으면 개발이 임의로 정하게 된다.

| 물음 | 결정 | 왜 |
|---|---|---|
| 고르는 단위 | **행별** | 파일 전체로 묶으면 47행 중 3행이 중복일 때 나머지 44행 때문에 잘못된 선택을 하게 된다. FMS 연계가 같은 이유로 건별 반영을 택했다(SCR-FAC-004 §6) |
| 기본값 | **건너뛰기** | 갱신은 되돌릴 수 없고, 기존 값 위에는 이미 다른 화면의 판단(소관부서 배정·관리대상 판정)이 얹혀 있다. 기본값이 파괴적이면 안 된다 |
| 빈 칸의 뜻 | **덮지 않는다** | 서식의 빈 칸은 “지우라”가 아니라 “이번에 안 적었다”이다. 빈 칸으로 기존 값을 날리면 일부 열만 채운 서식을 올릴 때마다 나머지가 사라진다 |
| 갱신 범위 | **서식에 있는 항목만** | 서식 밖 항목(개별 등록으로만 채우는 값)은 건드리지 않는다. **중복 판정 키 자체는 갱신하지 않는다** — 키를 바꾸면 같은 건이 아니라 다른 건이다 |
| 반영 건수 | **신규 · 갱신 · 건너뜀 · 오류를 따로 센다** | 한 숫자로 뭉치면 무엇이 실제로 들어갔는지 알 수 없다. 상시근로자처럼 비워 둘 수 있는 항목은 **미확보 N건**을 함께 낸다 |
| 취소 | 갱신이 포함된 반영만 **확인 단계를 한 번 더** 두고, 미리보기를 떠나면 대기 내용은 사라진다 | 확인 단계를 모든 반영에 걸면 아무도 읽지 않는 절차가 된다(SCR-FAC-004 §6과 같은 기준) |

|---|---|---|---|

| 행별 필수 항목 | 예 | 아래 서식별 표를 따른다 | 행 번호와 비어 있는 항목을 함께 알린다 |

- 개별 등록으로 넣을 때와 **같은 기준**을 쓴다. 두 경로가 다른 기준을 쓰면 일괄등록이 검증 우회 통로가 된다.

**서식별 검증 매트릭스** — 항목은 각 자료가 실제로 쓰이는 화면에서 그대로 가져왔다. 관리대상 현황(SCR-BASE-001)이 사업장을 사업장명·구분·소관부서·상시근로자로 보여 주므로, 서식이 그보다 적으면 목록이 빈칸으로 뜨고 많으면 아무 데도 쓰이지 않는 칸이 된다.

*사업장 서식*

| 항목 | 필수 | 형식·허용값 | 비고 |
|---|---|---|---|
| 사업장명 | 예 | 글자 | 중복 판정 키 ① |
| 소재지 | 예 | 글자 | 중복 판정 키 ② — 같은 이름의 사업장이 실재하므로 이름만으로 판정하지 않는다 |
| 구분 | 예 | 정해진 선택지 중 하나 | 목록에 없는 값은 오류다. 새 구분이 필요하면 서식이 아니라 구분 자체를 먼저 늘린다 |
| 소관부서 | 예 | 조직도에 있는 부서명 | 조직도에 없는 부서는 오류다 — 부서를 지어내면 그 사업장은 아무에게도 배정되지 않는다 |
| 상시근로자 수 | 아니오 | 0 이상 정수 | 개별 등록(SCR-BASE-001 §5)과 **같은 기준**이다 — 비면 미확보로 표시된다. 필수로 만들면 모르는 담당자가 아무 숫자나 적고, 그 숫자가 안전보건관리체계 적용 범위를 정해 버린다. 대신 미확보 건수를 반영 결과에 함께 내고 적용 범위 판정은 **판정 불가**로 남긴다 |

*기준문서 목록 서식*

| 항목 | 필수 | 형식·허용값 | 비고 |
|---|---|---|---|
| 문서 코드 | 예 | 글자·숫자 | 중복 판정 키 — 이 값이 같으면 같은 문서다 |
| 대메뉴 | 예 | 정해진 아홉 갈래 중 하나 | 갈래 밖 값은 오류다. 미배치는 별도 값으로 받아 나중에 배치한다 |
| 문서명 | 예 | 글자 | |
| 표시 순서 | 아니오 | 0 이상 정수 | 비면 목록 맨 뒤에 붙는다 |
| 예상 건수 | 아니오 | 0 이상 정수 | 이행률의 분모다 — 비면 분모 없이 건수만 센다 |
| 대표 처리유형 | 예 | 프로그램 · 전자문서 · 첨부파일 중 하나 | 이 값이 그 문서를 어느 화면에서 처리할지 정한다 |

- **중복 판정 키가 모두 같을 때만 중복이다** — 하나만 같으면 중복이 아니다. 이름이 같고 소재지가 다른 사업장은 실제로 다른 사업장이다.
- **선택지 항목은 자유 입력을 받지 않는다** — 받으면 표기가 갈려("사업소"/"사업장"/"사업소(직영)") 목록·통계가 같은 대상을 다른 것으로 센다.

## 6. 정책

- **검사를 통과한 건만 들어간다** — 검증 없이 밀어 넣으면 틀린 대상 위에 이행이 쌓인다. 관리대상은 후속 업무 전체의 범위를 정하는 자료라 특히 그렇다.
- **오류가 있어도 정상 건은 반영한다** — 전부 아니면 전무로 두면 담당자는 검사를 우회하려 하고, 몇 행 때문에 수십 행을 다시 올리게 된다.
- **올리기와 반영을 나눈다** — 올리자마자 반영하면 검사 결과를 보기 전에 자료가 들어간다.
- **서식을 자료 종류별로 나눈다** — 하나로 통합하면 대부분의 칸이 비는 표가 되고 어느 칸이 필수인지 알 수 없게 된다.
- **정본이 이 시스템 밖에 있는 자료에는 서식을 두지 않는다(BLK-01 확정)** — 엑셀본과 연계본 두 명단이 생기면 어느 쪽이 맞는지 아무도 판단할 수 없고, 뒤에 쌓이는 이행·위험도·예산이 어느 명단 위에 얹혔는지도 알 수 없게 된다. 그래서 서식은 **사업장 · 기준문서 목록** 둘뿐이다.
  - **공중이용시설** — 시설물 정보의 단일 출처는 시설물 대장(SCR-FAC-001)이고 FMS 연계(SCR-FAC-004)로 받는다. 엑셀 업로드를 두면 관리대상 현황이 폐지한 자체 명단(SCR-BASE-002 §6)이 되살아난다.
  - **구성원·인력** — 조직도는 행정포털(새올) 연계가 정본으로 확정이다. 실무 호칭 &lsquo;온나라 조직도&rsquo;는 같은 것을 가리키는 것으로 보며 명칭 대조는 연계 협의에서 확인한다. 서식을 두지 않는 이유는 호칭이 아니라 **정본이 이 시스템 밖에 있다는 것**(BLK-01)이다.
  - **원료·제조물(BLK-02 확정)** — 관리대상 명단 자체가 미확보라(SCR-BASE-003) 서식을 먼저 만드는 것은 순서가 거꾸로다. 무엇을 관리대상으로 볼지 정해지고 건수가 쌓인 뒤에 만든다. 그때까지는 개별 등록만 둔다.
- **서식을 두지 않는 자료도 화면에 적는다** — 목록에서 빼기만 하면 "왜 없지"를 묻게 되고, 담당자는 결국 사업장 서식에 시설물을 적어 올린다. 빠진 이유와 대신 갈 곳을 함께 낸다.
- **중복을 오류로 처리하지 않는다** — 같은 이름이라도 다른 대상일 수 있다. 판단은 사람이 하며, **행별로 · 기본값은 건너뛰기 · 빈 칸은 덮지 않음**이다(§4 BLK-03).
- **개별 등록과 같은 검증 기준을 쓴다 — 느슨해서도 엄해서도 안 된다.** 느슨하면 일괄등록이 검증 우회 통로가 되고, 엄하면 개별로는 넣을 수 있는 자료를 일괄로는 못 넣어 담당자가 두 경로를 오간다. 상시근로자 수를 선택으로 맞춘 것이 그 예다.
- **개별 등록과 같은 검증 기준을 쓴다** — 다르면 일괄등록이 검증 우회 통로가 된다.
- **없는 동작을 약속하지 않는다** — 프로토타입은 파일 내용을 해석하지 않고 예시 결과를 보여 주며, 그 사실을 화면에 밝힌다.
- **법령 근거 표시** — 중대산업재해 확보의무와 중대시민재해 확보의무를 함께 붙인다. 이 화면은 관리대상 현황과 같은 자료를 넣는 다른 경로이므로 근거도 같다. 근거 조문은 공통 근거 연계(SCR-COM-008)가 관리한다.

---

## 7. 미결사항

없음. 서식별 검증 매트릭스(BLK-01)는 §5에서, 일괄등록 대상 선정과 원료·제조물 서식(BLK-02)은 §6에서 확정했다.

실제 파일 해석과 저장은 미결이 아니라 **본개발 구현 범위**이며, 무엇을 검사하고 무엇을 반영할지는 §5·§6에 정해져 있다.
