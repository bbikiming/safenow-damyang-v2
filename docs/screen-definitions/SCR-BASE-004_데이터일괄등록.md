관리대상·구성원·기준문서처럼 **여러 건을 한 번에 넣어야 하는 자료**를 표 파일로 올리는 화면이다. 사업장 수십 개와 시설물 수십 건을 한 건씩 등록하게 하면 초기 구축이 사실상 불가능하고, 검증 없이 밀어 넣으면 틀린 대상 위에 이행이 쌓인다. 그래서 이 화면은 **서식 내려받기 → 파일 올리기 → 유효성 확인** 세 단계로 구성되고, 확인을 통과한 건만 관리대상 현황(SCR-BASE-001~003)에 반영된다.

## 3. 진입 / 이탈 경로 및 사용자 시나리오

| 구분 | 연결 화면 | 조건 / 트리거 |
|---|---|---|
| 진입 | 기본정보 > 데이터 일괄등록 | 메뉴 선택 |
| 진입 | 관리대상 현황 | 여러 건을 한 번에 넣을 때(SCR-BASE-001~003) |
| 이탈 | 관리대상 현황 | 반영 후 결과 확인 |

| 단계 | 사용자 행동 | 화면 반응 |
|:--:|---|---|
| 1 | 어떤 자료를 넣을지 정한다 | 자료 종류별 서식을 내려받게 한다 |
| 2 | 서식을 채워 올린다 | 파일을 받아 행 단위로 검사한다 |
| 3 | 검사 결과를 본다 | 정상·오류를 행마다 사유와 함께 보여 준다 |
| 4 | 정상 건을 반영한다 | 오류 건은 반영하지 않고 남긴다 |

### 분기 로직

- **자료 종류가 서식과 검사 규칙을 가른다** — 사업장·공중이용시설·구성원·기준문서 목록은 필요한 항목이 각각 다르므로 서식도 검사도 따로다. 하나의 서식으로 통합하지 않는다 — 통합하면 대부분의 칸이 비는 표가 되고, 어느 칸이 필수인지 알 수 없게 된다.
- **검사 결과가 행 단위로 갈린다** — **정상**은 반영 대상, **오류**는 반영하지 않고 사유를 붙인다. 파일 하나가 통째로 성공하거나 실패하는 방식을 쓰지 않는다.
- **오류가 있어도 정상 건은 반영한다** — 한 행이 틀렸다고 나머지를 막으면 담당자는 결국 검사를 우회하려 하고, 47행 중 3행 때문에 44행을 다시 올리게 된다.
- **반영은 확인을 거친다** — 파일을 올리는 것과 반영하는 것을 나눈다. 올리자마자 반영하면 검사 결과를 보기 전에 자료가 들어간다.

### 예외·경계 시나리오

| 상황 | 화면 반응 |
|---|---|
| 서식과 다른 파일을 올림 | 반영하지 않고 서식이 다르다는 사실을 알린다 — 항목이 어긋난 채 넣으면 값이 밀려 전 건이 오염된다 |
| 필수 항목이 빈 행 | 그 행을 오류로 표시하고 무엇이 비었는지 사유에 적는다 |
| 이미 있는 자료와 중복되는 행 | 오류가 아니라 **중복**으로 구분해 표시한다 — 덮어쓸지 건너뛸지 사람이 정한다 |
| 전 행이 오류 | 반영 수단을 내지 않고 사유를 목록으로 보여 준다 |
| 검사 결과를 보지 않고 나감 | 반영되지 않는다 — 올린 것만으로는 아무 일도 일어나지 않는다 |
| 프로토타입에서 실행 | 실제 파일 내용을 해석하지 않고 예시 결과를 보여 준다는 사실을 밝힌다 |

## 4. 화면 구성별 정리

### 4-1. 서식 내려받기

- 구성: 자료 종류별 서식 파일 목록(사업장 · 공중이용시설 · 구성원·인력 · 기준문서 목록).

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 서식 선택 | 그 자료의 서식을 내려받는다 | 프로토타입에서는 안내만 표시한다 |
| 화면 진입 | 어떤 자료를 넣을 수 있는지 목록으로 보여 준다 | 서식이 곧 넣을 수 있는 자료의 범위다 |

- 상태: 자료 종류마다 서식이 하나씩 있다. 서식이 없는 자료는 일괄등록 대상이 아니며, 그 사실이 이 목록으로 드러난다.

### 4-2. 파일 올리기

- 구성: 파일을 고르거나 끌어다 놓는 영역과 지원 형식 안내.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 파일 선택·끌어놓기 | 파일을 받아 검사를 시작한다 | 지원 형식·용량 기준을 함께 안내한다 |
| 서식과 다른 파일 | 검사 단계에서 걸러 낸다 | 반영하지 않는다 |
| 파일을 고르지 않고 진행 | 아무 일도 하지 않는다 | — |

- 상태: **파일 미선택 / 선택됨 / 검사 완료** 세 단계다. 올린 것만으로는 반영되지 않는다.

### 4-3. 유효성 확인 결과

- 구성: 파일명과 총 행 수 · 정상 건수 · 오류 건수 · 행별 결과 표(행 번호 · 대상 이름 · 판정 · 사유).

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 검사 완료 | 전체 행 수와 정상·오류 건수를 먼저 보여 준다 | 몇 건이 들어가고 몇 건이 막히는지 먼저 알린다 |
| 오류 행 | 행 번호와 사유를 함께 표시한다 | 어느 줄을 고쳐야 하는지 알 수 있어야 한다 |
| 중복 행 | 오류와 구분해 표시한다 | 덮어쓸지 건너뛸지 사람이 정한다 |
| 반영 실행 | 정상 건만 넣고 오류 건은 남긴다 | 반영 결과를 건수로 알린다 |
| 전 행 오류 | 반영 수단을 내지 않는다 | 사유 목록만 보여 준다 |

- 상태: 행별로 **정상 / 오류 / 중복** 세 판정이고, 파일 전체로는 **검사 전 / 검사 완료(반영 가능) / 검사 완료(반영 불가)** 세 상태를 갖는다.

## 5. 유효성 검사

| 입력 항목 | 필수 | 형식·길이 | 오류 안내 |
|---|---|---|---|
| 업로드 파일 | 예 | 표 계산 파일 · 공통 용량 기준 | 지원하지 않는 형식입니다 |
| 서식 일치 | 예 | 항목 구성이 서식과 같아야 한다 | 서식과 항목이 다릅니다 — 서식을 다시 내려받아 주세요 |
| 행별 필수 항목 | 예 | 자료 종류별 필수 항목을 따른다 | 행 번호와 비어 있는 항목을 함께 알린다 |
| 행별 형식 | 예 | 숫자·날짜·선택지 등 항목별 형식 | 행 번호와 잘못된 값을 함께 알린다 |
| 중복 | 아니오 | 이미 있는 자료와 같은 건 | 오류가 아니라 중복으로 구분해 표시한다 |

- 개별 등록으로 넣을 때와 **같은 기준**을 쓴다. 두 경로가 다른 기준을 쓰면 일괄등록이 검증 우회 통로가 된다.

## 6. 정책

- **검사를 통과한 건만 들어간다** — 검증 없이 밀어 넣으면 틀린 대상 위에 이행이 쌓인다. 관리대상은 후속 업무 전체의 범위를 정하는 자료라 특히 그렇다.
- **오류가 있어도 정상 건은 반영한다** — 전부 아니면 전무로 두면 담당자는 검사를 우회하려 하고, 몇 행 때문에 수십 행을 다시 올리게 된다.
- **올리기와 반영을 나눈다** — 올리자마자 반영하면 검사 결과를 보기 전에 자료가 들어간다.
- **서식을 자료 종류별로 나눈다** — 하나로 통합하면 대부분의 칸이 비는 표가 되고 어느 칸이 필수인지 알 수 없게 된다.
- **중복을 오류로 처리하지 않는다** — 같은 이름이라도 다른 대상일 수 있다. 판단은 사람이 한다.
- **개별 등록과 같은 검증 기준을 쓴다** — 다르면 일괄등록이 검증 우회 통로가 된다.
- **없는 동작을 약속하지 않는다** — 프로토타입은 파일 내용을 해석하지 않고 예시 결과를 보여 주며, 그 사실을 화면에 밝힌다.
- **법령 근거 표시** — 중대산업재해 확보의무와 중대시민재해 확보의무를 함께 붙인다. 이 화면은 관리대상 현황과 같은 자료를 넣는 다른 경로이므로 근거도 같다. 근거 조문은 공통 근거 연계(SCR-COM-008)가 관리한다.

## 7. 미결사항

없음. 검사 통과 기준·부분 반영 여부·올리기와 반영의 분리·서식 구성 단위·중복 처리·개별 등록과의 기준 일치·프로토타입 표기는 모두 §6에서 확정했다.

실제 파일 해석과 저장은 미결이 아니라 **본개발 구현 범위**이며, 무엇을 검사하고 무엇을 반영할지는 §5·§6에 정해져 있다.
