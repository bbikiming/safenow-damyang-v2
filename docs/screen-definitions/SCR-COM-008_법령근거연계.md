> 화면 ID: SCR-COM-008 · 화면 유형: 기타 (전역 공통 요소) · 기획 관점(v6)
> 판단이 필요했던 항목은 §6 정책에서 확정했습니다.

**목적·설명** — 각 메뉴가 **어떤 법 조문 때문에 존재하는지**를 화면에서 바로 확인하게 하고, 조문이 개정되면 **어느 메뉴가 영향을 받는지 역추적**할 수 있게 하는 전역 공통 요소다. 중대재해처벌법·산업안전보건법 체계는 "의무를 이행했다"만으로 부족하고 **무슨 조문에 근거해 무엇을 했는지**를 소명해야 하므로(중처법 시행령 제5조 관계 법령 의무이행 점검), 근거를 화면에 상시 노출해 담당자가 업무의 법적 뿌리를 알고 처리하도록 한다. 구성은 ① 화면 상단 근거 줄 ② 조문 상세 펼침 ③ 유해위험요인 근거 지정 ④ 유해위험요인 근거 표시 ⑤ 점검 항목 근거 안내 ⑥ **알림·업무 요청 문면 근거** 6영역이다. 핵심 연계는 정기 위험성평가(SCR-RISK-001)에서 지정한 근거가 개선조치 목록(SCR-IMP-001)·개선조치 상세(SCR-IMP-002)까지 따라붙는 흐름이며, 상단 근거 줄은 공통 페이지 크롬(SCR-COM-007)과 같은 방식으로 전 화면에 자동 노출된다.

## 2. 권한 정보

- 이 요소는 자체 메뉴를 갖지 않는다. 접근·보기·수정은 **호출한 화면의 메뉴 권한**을 따르며, 그 설정은 시스템 관리의 메뉴 관리(SCR-ADMIN-005)·권한 관리(SCR-ADMIN-006)에서 한다.
- 이 화면 정의서에서는 역할별 권한과 열람 범위를 별도로 정하지 않는다.
- 근거 열람과 유해위험요인 근거 지정은 §3~§6의 업무 흐름을 따른다.

**분기 로직**

- **메뉴별 분기** — 화면에 표시되는 근거는 메뉴마다 다르다. 근거가 지정되지 않은 메뉴(시스템 관리 계열·연계 설정·정보센터)는 **근거 줄을 만들지 않는다**. "근거 없음"을 빈칸이나 "없음" 문구로 보여주지 않는 이유는, 근거가 없는 것이 정상인 화면에 불필요한 잔여물을 남기지 않기 위해서다.
- **상세 화면은 소속 목록 메뉴의 근거를 상속한다** — 상세 화면은 좌측 메뉴 활성 표시를 위해 목록 화면과 같은 메뉴 식별자를 쓰므로, 근거도 목록과 동일하게 표시된다(예: 정기교육 상세는 정기교육의 근거를 그대로 표시). 상세 고유의 근거를 따로 두는 구조는 두지 않는다 — 다른 근거가 필요하면 그것은 별개의 화면이라는 뜻이다(§6 확정).
- **개정 시행예정 분기** — 해당 법령에 시행예정 개정이 있으면 조문 상세 안에 예정 건수와 시행일이 경고로 함께 표시된다. 없으면 이 영역 자체가 나타나지 않는다.
- **유해위험요인 분기** — 근거가 지정된 요인은 조문 표시, 지정되지 않은 요인은 "법령 매핑 대기"로 갈린다. 대기 상태에서는 펼칠 조문이 없으므로 선택 동작도 없다.

**엣지케이스**

- **표 안에서의 독립성** — 목록·표에서는 행마다 근거가 독립적으로 펼쳐진다. 한 행을 펼쳐도 다른 행은 닫히지 않는다. 반면 화면 상단 근거 줄은 한 번에 하나만 펼친다.
- **행 전체가 클릭 대상인 목록** — 개선조치 목록처럼 행을 누르면 상세로 이동하는 화면에서, **근거 표시를 눌렀을 때는 상세로 이동하지 않고 조문만 펼친다.**
- **긴 조문** — 조문이 길어도 표의 행 높이가 무한정 늘어나지 않도록 조문 영역 안에서만 스크롤한다. 좁은 팝업 표에서는 표 자체를 가로로 스크롤해 조문이 읽을 수 있는 폭을 확보한다.
- **화면 다시 그림** — 목록 필터 변경·저장 등으로 화면이 다시 그려지면 펼쳐 둔 조문은 닫힌 상태로 돌아간다.
- **근거 없는 화면·0건** — 근거가 없는 메뉴는 근거 줄이 없고, 유해위험요인이 하나도 없는 목록에는 근거 표시도 없다.
- **법령이 아닌 근거** — 지침·자체 기준처럼 법령이 아닌 근거는 조문으로 연결하지 않고 적힌 그대로 둔다. 억지로 조문에 붙이면 없는 법적 근거를 주장하게 된다.

## 4. 화면 구성별 정리

### 4-1. 화면 상단 법령 근거 줄 (전 화면 공통)

- 구성: 제목(부제가 있으면 부제) 바로 아래 한 줄. "법령 근거" 머리말 + 근거 조문 표시 1개 이상. 표시 문구는 **법령 약칭 + 조·호**로 짧게 쓴다(예: 중처법 시행령 제4조 제3호 → "중처법 시행령 §4 3호"). 전체 화면 중 근거가 매핑된 화면에만 나타난다.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 화면 진입 | 그 메뉴에 지정된 근거 조문을 순서대로 표시 | 근거 미매핑 화면은 줄을 만들지 않음 |
| 근거 조문 표시 선택 | 줄 아래로 해당 조문 상세를 펼침 | 화면 이동 없음 |
| 다른 조문 표시 선택 | 이전 조문을 닫고 선택한 조문을 펼침 | 한 줄에 하나만 펼침 |
| 같은 표시 다시 선택 | 펼친 조문을 접음 | — |

- 상태: **근거 있음**(표시 1개 이상) / **근거 없음**(줄 자체 미노출) / **펼침·접힘**. 각 표시는 현재 펼쳐진 상태인지 아닌지를 시각적으로 구분한다. 로딩 상태는 두지 않는다 — 근거는 화면과 함께 즉시 표시되는 기준 정보이며 별도 조회를 기다리지 않는다.

### 4-2. 조문 상세 펼침

- 구성: 법령명 · 조·호 · 조문 제목 · **조문 원문** · (해당 시) 개정 시행예정 경고 · 시행일·법령 식별번호·조회일 · [법제처 원문] 링크. 별도 팝업을 띄우지 않고 **선택한 자리 바로 아래에 펼친다**.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 조문 펼침 | 조문 원문 전문을 항·호 구분이 보이도록 표시 | — |
| [법제처 원문] 선택 | 국가법령정보센터의 해당 조문으로 이동 | 새 창으로 열림, 현재 화면 유지 |
| 개정 시행예정이 있는 법령 | 예정 건수와 시행일을 경고로 함께 표시 | "개정 시행예정 N건 — (시행일 목록)" |

- 상태: **원문 표시**(정상) / **개정 시행예정 있음**(경고 동반) / **접힘**. 조문 원문은 요약·의역하지 않은 원문 그대로이며, 화면 하단에 **조회일**을 함께 보여 언제 기준의 내용인지 알 수 있게 한다(§6 갱신 정책과 연결). 조문이 길면 조문 영역 안에서 스크롤한다.

### 4-3. 유해위험요인 근거 지정 (정기 위험성평가 보고서 검수)

- 구성: 정기 위험성평가에서 보고서를 올려 파싱한 결과를 검수하는 표에 **"법령 근거" 열**이 있다. 유해위험요인 행마다 근거 조문을 하나 고른다. 선택 목록은 **법령별로 묶어** 보여주고, 각 항목은 조·호와 조문 제목을 함께 표시한다. 기본값은 "법령 매핑 대기".

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 부서 블록 펼침 | 그 부서에서 추출된 유해위험요인 행이 표시됨 | 추출 0건이면 안내 문구 |
| 근거 조문 선택 | 해당 행의 근거로 지정 | — |
| "법령 매핑 대기" 선택 | 지정을 해제하고 대기 상태로 되돌림 | — |
| [행 추가] | 빈 행이 추가되며 근거는 대기 상태로 시작 | — |
| [검토완료 · 조치기한 설정] | 지정한 근거를 포함해 다음 단계로 진행 | 조치기한 설정 팝업 |

- 상태: **대기**(법령 매핑 대기) / **지정됨**(조문 표시). 업무 단계상으로는 보고서 업로드 → **검수(근거 지정 시점)** → 조치기한 설정 → 부서 전달 순이며, 근거를 지정할 수 있는 시점은 **검수 단계 한 곳뿐**이다. 전달 이후에는 이 화면이 아니라 개선조치 상세에서 바꾼다(§6 확정).

### 4-4. 유해위험요인 근거 표시 (개선조치 계열)

- 구성: 개선조치 목록(SCR-IMP-001)·개선조치 상세(SCR-IMP-002)·정기 위험성평가의 부서별 개선조치 팝업에서, 유해위험요인 옆에 근거 조문 표시 또는 "법령 매핑 대기" 표시가 함께 나온다. 검수 단계에서 지정한 근거가 개선조치로 그대로 이어진다.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 목록 진입 | 각 개선조치의 유해위험요인과 근거를 함께 표시 | 근거 미지정 항목은 "법령 매핑 대기" |
| 근거 조문 표시 선택 | 그 자리에서 조문 상세를 펼침 | **행 선택으로 상세 화면에 이동하지 않는다** |
| 행 선택(근거 표시 밖) | 개선조치 상세로 이동 | rsk-imp-detail.html |
| 부서별 개선조치 팝업 열기 | 전달된 개선조치와 각 근거를 표 형태로 표시 | 좁은 폭에서는 표를 가로로 스크롤 |

- 상태: **근거 지정됨** / **법령 매핑 대기**(경고 색으로 구분) / **펼침·접힘**. 업무 단계상태는 개선조치 자체의 예정 → 진행중 → 완료를 따르며, 근거 표시는 단계와 무관하게 항상 같이 보인다. 유해위험요인이 없는 수동 등록 개선조치에는 근거 표시가 나타나지 않는다.

### 4-5. 유해위험요인 근거 표시 (작업공정 관리 · 위험성 추정)

- 구성: 작업공정 관리(SCR-PRC-001)의 공정 편집 화면과 위험성 추정(SCR-RISK-003)의 추정 표에서, 유해위험요인마다 근거 조문 표시가 붙는다. 두 화면은 **현재 좌측 메뉴에서 제외된 보존 화면**이라 직접 주소로만 접근한다.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 공정 [수정] | 편집 영역에 유해위험요인 목록과 각 근거가 표시됨 | — |
| 근거 조문 표시 선택 | 그 자리에서 조문 상세를 펼침 | — |
| 근거가 지정되지 않은 요인 | "법령 매핑 대기"로 표시 | 펼칠 조문 없음 |

- 상태: **근거 지정됨** / **법령 매핑 대기**. 표준 유해위험요인 목록에서 불러온 요인은 근거가 함께 따라오고, 직접 추가한 요인은 대기 상태로 시작한다.

### 4-6. 점검 항목 근거 안내 (전자문서 점검표)

- 구성: 점검표 폼(SCR-EDOC-005) 등 전자문서의 점검 항목에 붙는 "관련 근거" 표시. 마우스를 올리거나 키보드 포커스를 주면 조문 안내가 뜨고, 벗어나면 사라진다.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 근거 표시에 마우스 올림·포커스 | 법령명·조·호·조문 제목·조문 내용을 안내로 표시 | — |
| 벗어남·포커스 해제 | 안내가 사라짐 | — |
| 조문 정보가 없는 근거 표기 | 적힌 근거 문구를 그대로 보여주고 상세는 표시하지 않음 | "상세 조문 정보가 아직 등록되지 않았습니다" |

- 상태: **요약 안내**(간추린 설명이 등록된 항목) / **원문 안내**(조문 원문으로 대체 표시) / **정보 없음**. 안내는 화면을 가리지 않도록 화면 경계 안에서 위치를 잡고, 내용이 길면 일정 높이까지만 보여준다.

### 4-7. 알림·업무 요청 문면 근거

- 구성: 전역 알림 드롭다운(SCR-COM-004) 항목과 내 할일 카드에 근거를 함께 싣는다. 담당자가 **업무를 요청받은 그 자리에서** 이유를 알 수 있어야 하며, 근거를 보려고 다른 화면으로 이동하게 만들지 않는다. 개선조치를 부서에 전달할 때 남는 처리 이력 문구에도 근거를 함께 적는다.
- 표기: **조문 표기 + 조문 제목**을 함께 쓴다. 조문 번호만으로는 이유가 전달되지 않기 때문이다. 조 제목과 호의 요지가 함께 있는 조문은 **호의 요지만** 쓴다(조 제목은 조문 표기에 이미 드러나 중복이다).

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 알림 목록 열기 | 각 알림 아래에 근거 한 줄이 함께 표시 | 예: "근거 산안기준규칙 §43 개구부 등의 방호 조치" |
| 알림 항목 선택 | 내 할일로 이동(기존 동작 유지) | 근거 표시는 **선택 대상이 아니다** |
| 내 할일 카드의 근거 선택 | 그 자리에서 조문 상세를 펼침 | **카드의 대표 동작(이동·첨부 팝업)은 실행되지 않는다** |
| 개선조치 부서 전달 | 처리 이력 문구에 근거를 함께 기록 | "개선조치 전달 (기한 …) · 근거 …" |

- 상태: **근거 있음**(문면에 한 줄 표시) / **근거 없음**(아무것도 표시하지 않음 — 빈 자리를 남기지 않는다). 알림에서는 근거를 **읽기 전용**으로 두고, 내 할일에서는 조문 원문까지 펼칠 수 있다. 이 차이는 의도된 것이다 — 알림 항목은 항목 전체가 이동 대상이라 그 안에 또 다른 선택 대상을 두면 어디를 눌렀는지에 따라 결과가 갈려 혼란스럽다. 반면 내 할일은 실제로 업무를 처리하는 자리여서 근거를 확인한 뒤 처리하는 흐름이 자연스럽다.

## 5. 유효성 검사

> 이 공통 요소에서 사용자가 값을 입력·저장하는 지점은 **유해위험요인 근거 지정 한 곳**이다(§4-3). 나머지 영역은 조회·표시 전용이라 검증 대상이 아니다.

| 입력 항목 | 필수 | 형식/규칙 | 오류 안내 |
|---|---|---|---|
| 법령 근거(유해위험요인별) | 선택 — 미지정 허용 | 제공되는 근거 조문 목록에서 하나 선택. 직접 입력은 허용하지 않는다 | 미지정 시 오류가 아니라 "법령 매핑 대기" 상태로 표시 |
| 법령 근거 — 부서 전달 시 | 선택, 미지정 허용 | 미지정 건수를 세고 전달 직전에 확인을 받되 차단하지 않는다 | "근거가 지정되지 않은 항목이 N건 있습니다. 미지정 상태로 전달하시겠습니까?" |

- **직접 입력을 막는 것이 기획 의도다.** 근거를 자유 문자열로 적게 하면 같은 조문이 화면마다 다르게 적히고, 조문이 개정돼도 아무도 알아채지 못한다. 반드시 제공 목록에서 고르게 한다.
- **미지정을 오류로 처리하지 않는다.** 조문이 하나로 특정되지 않는 위험요인이 실제로 존재하므로(예: 다른 법령 소관 사항), 억지 지정보다 대기 상태로 두는 편이 정확하다. 전달 단계에서는 미지정 건수를 밝히고 진행하며, 차단하지 않는다(§6 확정).

## 6. 정책

- **열람과 지정은 다른 성격이다** — 근거를 **보는 것**은 막지 않는 것이 기본이다. 법령은 공개 정보이고 담당자가 자기 업무의 근거를 못 보는 상태가 더 위험하다. 반면 근거를 **지정하는 것**은 시스템이 특정 법조문을 주장하게 만드는 행위라, 잘못 지정하면 틀린 근거로 의무를 이행했다고 기록된다. 그래서 **항목 근거의 지정은 정기 위험성평가 검수 단계 안에서만** 이루어지고 그 밖의 화면에는 지정 수단을 두지 않는다(LAW-01 확정). 검수는 용역 보고서를 옮겨 적으며 내용을 확인하는 단계라 근거를 함께 정하기에 자연스럽고, 그 뒤 단계(전달·조치)에서 근거를 새로 만들면 이미 나간 지시와 어긋난다.
- **근거는 단일 출처로 관리한다** — 화면·문서마다 근거를 따로 적지 않는다. 근거 조문 목록을 한 곳에서 관리하고 모든 화면이 그것을 참조한다. 화면에서 근거 문구를 직접 작성하는 방식은 허용하지 않는다.
- **조문 원문은 손으로 고치지 않는다** — 조문 내용은 국가법령정보센터에서 받아 온 원문이며, 사람이 요약·의역해 넣지 않는다. 내용이 틀렸다면 고쳐 쓰는 것이 아니라 **다시 받아 온다**. 화면에 "조회일"을 함께 노출해 언제 기준인지 드러낸다.
- **근거가 없는 화면은 없다고 명시한다** — 시스템 관리 계열처럼 법령이 정한 의무가 아니라 시스템 운영 기능인 화면은 근거를 비워 두는 것이 정상이다. 억지로 조문을 붙이지 않는다. "근거 없음"도 관리 대상 정보이므로 매핑 표에 빈 값으로 명시해 관리한다.
- **화면 근거와 항목 근거를 구분한다** — 화면 근거는 "이 메뉴가 어떤 법정 의무의 이행 수단인가"이고, 항목 근거는 "이 개별 업무가 어떤 조문에서 나왔는가"다. 여러 도메인의 업무가 모이는 화면(내 할일)이나 시스템 간 연계 화면은 **화면 근거가 성립하지 않으므로 붙이지 않는다**. 화면 근거를 억지로 붙이면 그 메뉴가 그 조문 때문에 존재한다는 잘못된 인상을 준다. 이런 화면에는 항목 근거만 둔다.
- **"관련이 있다"는 근거가 아니다** — 매핑 기준은 그 조문이 요구하는 의무의 **직접 이행 수단**인지다. 데이터를 준비하거나 결과를 보관하는 화면은 관련은 있어도 이행 수단이 아니다. 이 기준을 느슨하게 하면 거의 모든 화면에 같은 조문을 붙일 수 있게 되어 근거가 정보로서 값을 잃는다.
- **근거는 메뉴 단위로 부여한다** — 화면 하나하나가 아니라 메뉴 단위로 근거를 지정하고, 상세 화면은 소속 목록 메뉴의 근거를 상속한다. 신규 메뉴를 만들면 근거 매핑을 함께 등록해야 하며, 등록하지 않으면 그 화면에는 근거가 표시되지 않는다(신규 화면 작성 시 필수 점검 항목).
- **갱신 주기 — 하루 1회로 충분하다** — 법령은 공포와 시행 사이에 유예기간이 있어 실시간 조회가 필요 없다. 조문 내용과 시행일을 주기적으로 다시 받아 저장해 두고, 화면은 저장된 내용만 읽는다.
- **개정 감지 — 시행일 변화를 기준으로 한다** — 다시 받아 온 시행일이 저장된 값과 달라지면 개정으로 보고 정비 대상으로 올린다. 개정이 감지되면 **그 조문을 근거로 쓰는 메뉴 목록을 역으로 뽑아** 담당 부서에 알린다. 이것이 근거를 단일 출처로 두는 가장 큰 이유다.
- **시행예정 개정은 미리 보여준다** — 아직 시행되지 않았지만 공포된 개정이 있으면 조문 상세에 예정 건수와 시행일을 함께 표시한다. 담당자가 시행 전에 대비할 수 있어야 한다.
- **조회 실패가 업무를 막지 않는다** — 법령 조회에 실패해도 화면은 **마지막으로 저장된 내용**을 그대로 보여준다. 근거 표시가 사라지거나 화면이 열리지 않는 상황을 만들지 않는다. 실패는 관리자에게만 알린다.
- **근거 조문 목록은 화면에서 편집하지 않는다** — 사용자가 화면에서 조문을 추가·수정하는 기능은 두지 않는다. 수록 대상 조문을 늘리는 것은 기획·운영 판단이다. **관리 화면은 두되 편집 화면이 아니라 검토 대장으로 둔다**(LAW-06 확정) — 조문·매핑은 생성물이라 화면에서 고치면 재생성 때 되돌아간다. 관리 화면은 무엇이 어떻게 매핑돼 있고 왜 그렇게 판정했는지를 보여주고, 이견은 재검토 요청으로 기록만 받는다(SCR-ADMIN-007·SCR-ADMIN-008).
- **근거는 화면 안에만 두지 않는다** — 담당 직원은 시스템에 들어와 조문을 눌러보지 않는다. 업무를 요청받는 통로(알림·내 할일·전달 이력)에 근거를 함께 실어야 "왜 하는지"가 실제로 전달된다. **공문 문면의 근거는 담당자가 고른 것만 싣는다**(LAW-12 확정) — 전 문서에 자동으로 싣지 않는다. 공문 본문은 사람이 쓰는 글이고, 근거 조문을 기계가 밀어 넣으면 문맥과 맞지 않는 조문이 붙는다. 시스템은 그 업무에 매핑된 조문을 **고를 수 있게 건네주고**, 고르지 않으면 근거 절 자체가 나타나지 않는다.
- **수범자가 다르다는 점을 유의한다** — 중대재해처벌법 계열 조문은 의무 주체가 기관·경영책임자이고, 산업안전보건기준에 관한 규칙 계열은 현장 행동 규범이라 담당 직원에게 직접 해당한다. 담당 직원이 받는 문면에는 후자가 훨씬 잘 전달된다. **담당 직원이 받는 문면에는 현장 행동 규범 조문을 먼저 놓는다**(LAW-13 확정) — 기관 의무 조문(중대재해처벌법 계열)은 왜 이 업무가 존재하는지를 설명하지만 담당자가 무엇을 해야 하는지는 말해 주지 않는다. 두 계층이 모두 있으면 행동 규범을 앞에 두고 기관 의무를 뒤에 둔다. 기관 의무만 있는 업무는 그대로 쓰되, 그때는 조문 번호보다 **쉬운 설명 한 줄**을 함께 낸다.
- **근거가 없어도 전달을 막지 않고, 대신 드러낸다(LAW-02 확정)** — 차단하면 담당자가 아무 조문이나 붙여 통과시키고, 그 순간 근거는 정보가 아니라 통과 절차가 된다. 실제로 근거가 없는 유해위험요인이 정상적으로 존재한다(작업 행동·정리정돈 등). **근거 미지정 건수를 전달 전에 밝히고** 진행하며, 전달 이후에도 목록에 "법령 매핑 대기"로 계속 남는다 — 사라지지 않아야 나중에 채울 수 있다.
- **전달 이후에는 검수 화면을 다시 열지 않고 개선조치에서 고친다(LAW-03 확정)** — 이미 부서로 나간 검수 내용을 되돌리면 부서가 받은 것과 시스템에 남은 것이 달라진다. 근거를 바꿔야 하면 **그 근거로 만들어진 개선조치 상세에서** 고치고, 바꾼 이력을 남긴다. 근거 변경은 조치 내용 자체를 바꾸는 것이 아니라 "왜 하는지"의 표기를 바로잡는 것이라 진행 중이어도 허용한다.
- **상세 화면이 목록과 다른 근거를 가져야 하면 그것은 별개의 화면이다(LAW-04 확정)** — 상속을 예외로 깨지 않는다. 한 식별자에 화면별 예외를 두기 시작하면 "이 화면의 근거"를 한 곳에서 답할 수 없게 된다. 근거를 나누는 대신 **식별자를 나눈다**.
- **수록 조문은 담양군이 실제로 이행하는 의무까지만 늘린다(LAW-05 확정)** — 관련 있는 법을 모두 담지 않는다. 판단 기준은 화면 매핑과 같다 — **그 조문의 의무를 담양군이 지고, 이 시스템의 어느 화면이 그 이행 수단인가**. 소방시설법처럼 소관이 다른 법은 담양군이 관리주체인 범위에서만 수록하고, 어느 화면도 이행 수단이 아니면 수록하지 않는다. 수록되지 않아 "법령 매핑 대기"로 남는 항목은 감추지 않는다 — 그 목록이 다음에 검토할 대상이다.
- **개정 알림은 두 갈래로 보낸다(LAW-07 확정)** — **시스템 관리자**에게는 수집·감지 사실을, **그 조문을 근거로 쓰는 메뉴의 소관 부서**에는 "귀 부서 업무의 근거 조문이 바뀌었다"를 보낸다. 전담부서(재난안전과)는 두 번째에 항상 포함된다 — 총괄이 모르는 개정이 있어서는 안 된다. 방식은 시스템 내부 알림이며, 개정은 드물게 일어나므로 외부 채널을 붙이지 않는다.
- **조례는 근거 대상에 넣지 않는다(LAW-08 확정)** — 담양군 자체 조례는 법령 정보 제공처의 수집 대상 구조가 다르고, 무엇보다 **조례는 상위법의 이행 수단이지 의무의 출처가 아니다**. 근거로 조례를 붙이면 "왜 하는가"의 답이 한 단계 얕아진다. 다만 상위법이 개정되면 조례 정비가 필요할 수 있으므로, 개정 알림에 **"관련 조례 정비 검토 필요"**를 문구로 덧붙인다 — 조례 자체를 관리하지는 않되 신호는 준다.
- **외부 링크는 열되 없어도 되도록 만든다(LAW-09 확정)** — 조문 **원문 전체를 시스템 안에 저장**하고 있으므로, 외부 사이트로 나가지 않아도 담당자가 필요한 내용은 다 볼 수 있다. 외부 링크는 정본 확인용 보조 수단이라 업무망에서 막혀 있어도 업무가 멈추지 않는다. 링크 옆에 **"정본 확인"**임을 밝혀, 눌리지 않을 때 무엇을 못 하는 것인지 알 수 있게 한다.
- **수집은 기관 명의로 하고 실패해도 다시 보내지 않는다(LAW-10 확정)** — 법령 정보는 공공데이터라 저장·표시가 허용되며 조건은 출처 표기와 정본 고지다(둘 다 상시 노출). 인증 정보는 **담양군 기관 명의**로 발급받는다 — 개인 명의로 받으면 그 사람이 떠날 때 수집이 멈춘다. **자동 재시도를 두지 않는다** — 규격 오류나 인증 만료는 몇 번을 보내도 같은 결과이고, 재시도가 이력을 같은 실패로 채워 원인을 덮는다. 실패한 날 바로 알린다.
- **별표는 조문과 같은 자리에 두되 발췌임을 밝힌다(LAW-11 확정)** — 교육 시간·안전등급 구간·공중이용시설 범위처럼 **화면이 실제로 쓰는 숫자가 별표에 있다**. 수록하지 않으면 그 숫자의 근거가 통째로 빠지므로, 조문과 같은 방식으로 싣고 표 구조는 줄글로 펴서 보관한다. 전문을 옮기기 어려우면 **시스템이 쓰는 부분만 발췌하고 발췌임을 명시**하며 전문은 정본 링크로 잇는다.
- **지정한 근거는 후속 업무로 따라간다** — 정기 위험성평가 검수(SCR-RISK-001)에서 지정한 근거는 그 요인에서 생성되는 개선조치(SCR-IMP-001·SCR-IMP-002)까지 그대로 이어진다. 중간에 근거가 끊기면 개선조치가 무슨 법적 근거로 만들어졌는지 소명할 수 없다.
- **법령이 아닌 근거는 조문에 붙이지 않는다** — 안전보건 지침이나 자체 점검 기준처럼 법령이 아닌 근거는 적힌 그대로 표시하고 조문으로 연결하지 않는다.

## 7. 미결사항

없음. 근거 지정 수행 단계·미지정 전달 허용·전달 이후 근거 수정 경로·상세 화면의 고유 근거·수록 조문 확대 기준·근거 목록 관리 화면의 성격·개정 알림 수신자·조례 연계·외부 링크 정책·조문 수집 방식과 이용 조건·별표 표현·공문 문면 근거의 범위·문면 근거의 수범자 계층은 모두 §6에서 확정했다.

관계 법령 **목록 자체**는 담양군 외부 제공 자료다(중대재해처벌법 시행령 제5조·제11조가 기관별 목록을 열거하지 않고 범위만 정의한다). 미수신 동안 확인된 조문만 표시하고 "관계 법령 목록 미등록"을 상시 표시하므로 개발을 막지 않는다.
