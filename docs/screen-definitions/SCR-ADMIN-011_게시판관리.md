## 3. 진입 / 이탈 경로 및 사용자 시나리오

| 구분 | 연결 화면 | 조건 / 트리거 |
|---|---|---|
| 진입 | 시스템 관리 > 기준정보 > 게시판 관리 | 메뉴 선택 |
| 연계 | 통계·보고 > 정보센터(SCR-RPT-003) | 사용 중인 게시판이 탭으로 보인다 |

| 단계 | 사용자 행동 | 화면 반응 |
|:--:|---|---|
| 1 | 화면에 들어온다 | 게시판을 순서대로 보이고, 정보센터에 몇 개가 탭으로 보이는지 한 줄로 말한다 |
| 2 | `[＋ 게시판 만들기]`에서 이름·유형·글을 올리는 사람을 정한다 | 목록 끝에 추가하고, 사용으로 두면 정보센터에 탭이 생긴다 |
| 3 | 순서 버튼(↑·↓)으로 자리를 바꾼다 | 정보센터 탭 순서가 같이 바뀐다 |
| 4 | `[사용 끄기]`로 내린다 | 정보센터에서 탭이 빠지고 글은 남는다 |
| 5 | 글이 없는 게시판을 `[삭제]`한다 | 같은 창에서 확인받고 지운다 |

### 예외·경계 시나리오

| 상황 | 화면 반응 |
|---|---|
| 글이 있는 게시판을 지우려 함 | `[삭제]`를 내지 않는다. 호출로 들어와도 «글이 n건 있어 지울 수 없습니다 — 사용을 끄면 정보센터에서 내려갑니다»로 막는다 |
| 글이 있는 게시판의 유형을 바꾸려 함 | 유형 칸을 잠그고 이유를 보인다 — 기존 글의 항목(구분·부서)이 새 유형과 맞지 않는다 |
| 같은 이름의 게시판이 있음 | 저장을 막는다 — 정보센터에 같은 이름의 탭이 두 개 생긴다 |
| 사용 중인 게시판이 0개 | 정보센터는 탭 없이 «등록된 글이 없습니다» 한 줄만 보인다 |
| 조회만 할 수 있는 사람이 들어옴 | 만들기·수정·순서·사용·삭제 버튼을 내지 않는다. 저장 경로도 같은 판정으로 막는다 |

## 4. 화면 구성별 정리

### 4-1. 목록

- 열: 순서 · 게시판 · 유형 · 글을 올리는 사람 · 글(건수) · 정보센터(`보임` / `사용 안 함`) · 관리.
- 처음 상태는 기본 게시판 3개다 — 공지사항(공지형 · 주관부서) · 자료실(자료형 · 각 부서) · 우수사례(사례형 · 각 부서).

### 4-2. 만들기·수정

| 항목 | 값 |
|---|---|
| 게시판 이름 | 20자 이내 |
| 유형 | 공지형(제목·작성·등록일·조회) · 자료형(자료명·구분·등록일·첨부) · 사례형(사례·부서·등록일·추천) |
| 글을 올리는 사람 | 주관부서(재난안전과) 담당자 · 각 부서 담당자 |
| 정보센터에 보이기 | 켬 / 끔 |

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| `[만들기]`·`[저장]` | 검사를 지나면 목록과 정보센터에 반영한다 | «○○ 게시판을 만들었습니다» |
| `[사용 끄기]`·`[사용 켜기]` | 정보센터 탭에서 내리거나 다시 보인다 | 끌 때 «글은 그대로 남습니다» |

## 6. 정책

- **정보센터 탭의 정본은 이 화면이다** — 정보센터가 탭을 따로 들고 있으면 여기서 바꾼 것이 반영되지 않는다. 기본 3개(공지사항·자료실·우수사례)도 이 목록의 처음 값이다(운영 요청서 S2).
- **유형은 정보센터 세 영역의 성격에서 왔다** — 공지는 읽었는지(조회), 자료는 찾는 것(구분·첨부), 사례는 누가 했는지(부서·추천)가 중요하다(SCR-RPT-003 §3). 새 게시판도 셋 중 하나를 고른다 — 열 구성을 게시판마다 새로 만들지 않는다.
- **글을 올리는 사람을 게시판마다 정한다** — 공지는 주관부서가 낸다(아무나 공지를 내면 무엇이 공식인지 알 수 없다). 자료·사례는 각 부서가 올린다(SCR-RPT-003 §6). 등록 화면의 부서는 부서 담당자에게 소속 부서로 고정된다.
- **글이 있는 게시판은 지우지 않고 내린다** — 언제 무엇을 알렸는지가 나중에 근거가 된다. 삭제는 글이 0건일 때만이고, 확인은 같은 창 안에서 한다.
- **법령 근거를 붙이지 않는다** — 시스템 운영 기능이다(SCR-COM-008).
