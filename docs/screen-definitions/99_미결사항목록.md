# 99. 미결사항 목록 — 연계 구현 범위와 담양군 확인 항목

> 2026-08-14 전 메뉴 재검토(연계 축 재분류 반영) · 2026-08-19 연계 대상 시스템을 **온나라·FMS·행정포털·법제처 네 곳으로 확정**(법제처 편입과 재정 시스템 제외는 별개의 결정 — §4·§6) · 2026-10-07 온나라 공문 회신 반영(§4 기관정보·결재 행 정리, EXT-21·22 신설) · 2026-10-15 e호조 계약대장 파일 반입(§4 도급 행 갱신, EXT-23·24 신설) · 2026-10-21 온나라 문서 연계 회신(EXT-21에 연계 문서의 공개구분별 노출 범위 질의 추가) · 2026-10-28 온나라 연결 방식 개정(EXT-21 ②를 부서 기준 노출 · 붙임 받기 조건으로 바꿈) · 2026-11-23 11-20 팀장 보고 회의 후속 반영(§5-1 도급관리 개편 보류 · §5-2 열린 결정·입력 대기 신설 · EXT-15 C 재분류 · EXT-16 기한 · EXT-21 교육 공문 제외 · EXT-22 질의 11개 · EXT-23 수신 확인 필요 · §4 기관정보 행 «온나라가 채움» — 요구 번호 전체의 연결은 [`기획-1120회의-후속과제-연계맵-20261123-v1.md`](../planning/기획-1120회의-후속과제-연계맵-20261123-v1.md)). 화면별 판단은 각 정의서 §6, 공통 기능은 `_규칙.md`, 초기 권한·열람 범위는 `_공통_권한정의.md`가 정본이다.

## 1. 결론

- **자체 기획으로 소거할 수 있는 미결사항: 0건.** 법령·업무 논리·화면 간 정합으로 정할 수 있는 기능·UX는 모두 확정했다. 판단이 갈릴 수 있는 것도 기본값과 근거를 정해 §3에 적었다 — 발주처가 다르게 정하면 그 기본값만 바꾼다.
- **외부 시스템이 정본인 데이터는 미결이 아니라 연계 구현 범위다(§4).** 시설물(FMS)·기관정보와 결재(온나라)·조직도와 인원(행정포털·새올)·문서 담당정보(새올·온나라)·파일 실물(파일관리)은 RFP가 연계를 명시한 축이다(SFR-002·005·006·015·016·017). **법령 조문 원문(법제처)만은 RFP 외부 연계 목록에 없다** — 관계법령을 현행으로 유지하라는 요구(SFR-014)를 이행하려면 조문 원문의 출처가 필요해 이 시스템이 연계 대상으로 정했고, 수집 배치는 이미 실행 기록을 남기고 있다. 연계 규격 수령·협의는 사업 절차이지 기획 미결이 아니다.
- **연계 수신 전 프로토타입 데이터는 전부 시연용 더미다.** 각 화면은 시연값·연계 전 상태임을 표시하고, 연계가 열리면 구조를 바꾸지 않고 원천 어댑터와 데이터만 교체한다.
- 남은 미결은 **담양군이 확인해 주지 않으면 논리·근거가 성립하지 않는 항목(§5)** 뿐이다. 전부 미확인 상태의 표시·대체 동작이 확정돼 있어 **개발 착수 차단 조건이 아니다**.
- **2026-11-20 팀장 보고 회의가 연 결정과 입력 대기는 §5-1(도급관리 개편 보류)·§5-2(그 밖)에 모았다(2026-11-23).** 현행 화면은 그대로 돌고, 개편 부분만 결정을 기다린다. 요구 번호(R) 전체의 연결은 [`기획-1120회의-후속과제-연계맵-20261123-v1.md`](../planning/기획-1120회의-후속과제-연계맵-20261123-v1.md)이 본다.
- 프로토타입 미구현·시연값·실데이터 부족은 기획 미결로 세지 않는다. 본개발 계약과 현재 상태를 구분해 표시한다.

| 법령 근거 | 근거 없는 업무 저장·전달·관계 법령 목록 | 저장은 허용하고 미지정 건수를 표시한다. 부서 전달 전 경고하되 차단하지 않으며 적용 목록은 완결 여부를 표시한다. **담양군 적용 관계 법령 목록은 독립 미결이 아니라 관리대상 실태 확정(§5 EXT-09·10)의 파생물** — 법령 관리가 법리 기반 후보를 제시하고 실태가 확정되면 목록이 따라온다. 확정 전 동작(확인된 조문만 표시·미완결 안내)은 SCR-COM-008 §6 확정 그대로 |

## 4. 연계 구현 범위 — 미결이 아니다

외부 시스템이 정본인 축이다. RFP가 연계를 명시하며, 규격 수령·접속정보·신청은 본개발 사업 절차로 진행한다. **연계 수신 전 프로토타입 데이터는 전부 시연용 더미이며 각 화면이 그 사실을 표시한다.**

**연계 대상 시스템은 온나라·FMS·행정포털·법제처 네 곳이다.** 그중 **실제 자료에서 상태를 파생하는 것은 FMS와 법제처 둘**이고, 온나라·행정포털은 파생할 원본 이력이 없어 정상·지연·실패 어느 것으로도 표시하지 않고 「연계 이력 미구현」으로 밝힌다(SCR-ADMIN-004 §6 INT-03). **법제처 편입과 재정 시스템 제외는 별개의 결정이다** — 앞은 이미 수집 이력이 있는데 상태판에만 빠져 있던 것을 채운 것이고, 뒤는 대상 범위에서 뺀 것이라 하나가 다른 하나의 선례가 되지 않는다.

**개수를 세는 문장에는 이 네 곳만 쓴다.** 아래 표에는 파일 실물(파일관리)·알림 외부 채널(문자발송체계)처럼 원천이 따로 있는 축도 남아 있지만, 그것은 RFP가 요구한 축을 지우지 않기 위해 남긴 것이지 상태 모니터가 상태를 책임지는 대상이 아니다. 표의 원천 이름을 세어 다섯·여섯으로 말하면 화면·정의서와 개수가 어긋난다 — 실제로 「셋」과 「넷」이 저장소 안에서 동시에 주장된 적이 있다.

도급사업 목록·공사정보는 **e호조 계약대장 파일 반입으로 시작했다**(2026-10-15 — 범위는 2026-09-21 확정, 2026-08-24 「대상에서 제외」를 되돌린 축). API 인증이 오면 같은 원장으로 갈아탄다. 표에서 지우지 않고 **지금 동작과 남은 것**으로 남긴다 — 행을 지우면 RFP가 요구한 축이 검토조차 되지 않은 것처럼 보인다.

**동작 열의 시점은 축마다 다르므로 열 이름을 `확정 동작`으로 둔다.** 대부분은 `연계 전` 동작이고, 파일 반입으로 시작한 축(도급)과 이미 수집이 도는 축(법제처)에는 **지금 동작**을 적는다. 열 이름을 「연계 전」으로만 두면 이미 돌고 있는 연계를 아직 없는 것처럼 말하게 된다.

## 4-9. 「미결」과 「운영 설정」을 가른다 (2026-08-31 신설)

목록에 남아 있다고 전부 **개발 착수를 막는 것이 아니다.** 셋을 섞으면 착수 판정이 흐려지고, 담양군에는 「아직 못 쓴다」는 인상만 남는다.

| 갈래 | 뜻 | 착수 영향 | 자료가 없으면 |
|---|---|---|---|
| **A. 운영 설정** | 화면에서 담양군이 **직접 넣고 바꾸는 값** | **없음** — 기능은 이미 있다 | 그 값이 비어 있을 뿐이고, 화면이 비었음을 드러낸다 |
| **B. 착수 전 확정** | 값이 아니라 **화면 구조·판정 규칙**이 갈리는 것 | **있음** — 정해져야 만들 수 있다 | 만들 수 없다 |
| **C. 외부 연계 규격** | 상대 시스템이 답해야 하는 것 | 그 연계 부분만 | 대체 동작으로 진행 |
| **D. 선행 작업 이후 확정** | 지금 물어도 답이 없고, **문서 분류가 끝나야 실측으로 드러나는 것** | **없음** — 순서가 뒤일 뿐이다 | 그 축을 만들지 않고 «확인 전»으로 둔다 |

**가르는 기준은 하나다 — 「그 값을 넣을 화면이 이미 있는가」.** 있으면 A(자료 대기), 없고 만들 형태가 정해지지 않았으면 B, 밖에 있으면 C다.

## 5. 담양군 확인 필수 — 논리·근거로 만들 수 없는 항목

> **갈래는 §4-9 를 본다.** 아래 표의 대부분은 **A(운영 설정)** 로, 값이 없을 뿐 기능은 있어 개발 착수를 막지 않는다.
> **착수를 막는 항목은 현재 없다** — 공중교통수단·도급 선별 기준은 **문서 분류 이후 확정(D)**, e호조 계약 원장은 **파일 반입으로 시작했다**(2026-10-15 — API 인증은 전환에만 걸린다 · 2026-11-20 회의로 내부망 원인 확인·노선 결정이 더해졌다 — EXT-15). 11-20 회의가 연 개편 결정은 §5-1·§5-2 에 있다.

담양군의 사실 확인·지정 행위 없이는 어떤 법령·논리로도 값을 만들 수 없는 항목이다. 전부 확인 전 동작이 확정돼 있어 **비차단**이다. 종전에는 EXT-14 를 «계약 원본 반입의 선행 조건»으로 두었으나, 점검 대상을 사람이 판정하고 점검 항목을 의무 주체·법정 조건으로만 만들기로 확정해(SCR-SBM-004 §6) **선별 기준 없이도 반입할 수 있게 됐다**(2026-10-15) — 목록에 많이 들어오는 것과 점검표가 많이 생기는 것은 다른 문제다.

## 7. 개발 착수 판정

- 기능·UX 구현은 현재 정의서로 착수한다.
- 연계 축(§4)은 값이 없어도 `미등록 / 연계 전 / 판정 불가` 상태로 개발·시험한다. 연계 규격 협의·신청은 착수 후 병행하며, 프로토타입의 해당 데이터는 전부 시연용 더미다. **실제 자료에서 상태를 파생하는 FMS·법제처만은 그 값을 그대로 낸다** — 원본이 있는데 «연계 전»으로 뭉뚱그리면 이미 도는 연계를 없는 것처럼 말하게 되고, 반대로 원본이 없는 온나라·행정포털의 상태를 지어내면 상태판이 모니터로서 값을 잃는다.
- **도급사업 목록·공사정보에도 `연계 전` 상태를 두지 않는다 (2026-10-15 갱신).** e호조 계약대장 파일 반입으로 원장이 들어오고, 반입한 적이 없으면 직접 등록만으로 돈다. 「연계 전」으로 표시하면 곧 온다는 뜻이 되어 담당자가 등록을 미루고, 미룬 만큼 도급 현장이 목록에 없는 채로 남는다(SCR-SBM-004 §6). API 전환은 EXT-15, 재추출·정정은 EXT-23 으로 관리한다.
- 담양군 확인(§5)이 도착하면 구조를 바꾸지 않고 값·명단만 반영한다. **그중 A 갈래(§4-9)는 개발이 반영하는 것이 아니라
  담양군이 관리 화면에서 직접 넣는다** — 권한 관리(등급 구성원)·메뉴 관리(메뉴별 권한)·근로자 명단 관리(구분·지정일)가 그 자리다.
- **원료·제조물(EXT-10)의 «넣을 자리»는 화면으로 있고 메뉴에는 없다(2026-09-03).** 축소로 자리가 사라지자 선택지 ①(그 축만 남겨 되살린다)을
  택했다가, 제안요청서·법령 원문을 다시 대조해 **대시보드 흡수**로 확정했다 — 제안요청서에서 이 축이 나오는 곳은 SFR-020 의
  「원료·제조물 개소 표시」 한 문장뿐이고, 중처법 제9조제1항·시행령 제8조 어느 조문도 품목 대장을 명하지 않는다. 조치 의무는
  이행 관리(CIT-02·03)가 담는다. 그래서 **개소는 대시보드가 이행하고 대장은 주소로만 남긴다.**
  명단이 오면 그 화면에 넣고 그때 메뉴 노출을 다시 판단한다. ③(담양군이 «대상 없음»을 확인해 축을 닫는다)은 여전히 열려 있다.
