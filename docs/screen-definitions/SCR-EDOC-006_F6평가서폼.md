# 화면 정의서 — F6 평가서 폼(점수형)

> 판단이 필요했던 항목은 §6 정책에서 확정했습니다.

| 항목 | 내용 |

## 2. 권한 정보

- 메뉴 접근·보기·수정은 시스템 관리의 메뉴 관리(SCR-ADMIN-005)와 권한 관리(SCR-ADMIN-006)에서 설정한다.
- 이 화면 정의서에서는 역할별 권한과 열람 범위를 별도로 정하지 않는다.
- 이 폼을 여는 권한은 **호출한 화면의 권한을 그대로 따른다** — 폼 자체가 따로 권한을 갖지 않는다. 상태를 바꾸는 행위(등록·확정·개정)의 수행 주체는 §3~§6의 업무 흐름을 따른다.

## 3. 진입 / 이탈 경로 및 사용자 시나리오

| 구분 | 연결 화면 | 조건 / 트리거 |
|---|---|---|
| 진입 | 업무 목록·문서 상세 | 그 문서의 처리유형이 전자문서일 때 |
| 진입 | 각 업무 메뉴 | 해당 업무에서 이 서식이 필요할 때 |
| 이탈 | 온나라 결재 요청 안내 | 확정 실행 직후(SCR-EDOC-008) |
| 이탈 | 호출한 화면 | 저장·취소 후 되돌아간다 |

| 단계 | 사용자 행동 | 화면 반응 |
|:--:|---|---|
| 1 | 서식을 연다 | 저장된 값이 있으면 이어서 쓰고, 없으면 빈 서식으로 시작한다 |
| 2 | 항목을 채운다 | 입력 도중에는 저장되지 않는다 |
| 3 | [임시저장] 또는 [등록] | 임시저장은 상태를 유지하고, 등록은 등록완료로 넘긴다 |
| 4 | [확정 · 온나라 결재 상신] | 입력을 잠그고 결재 요청 안내를 띄운다 |

### 분기 로직

- **문서 상태가 화면의 버튼을 정한다** — **작성중**에는 [임시저장]·[등록], **등록완료**에는 [임시저장]·[확정 · 온나라 결재 상신], **확정**에는 [닫기]·[개정]만 나온다. 상태가 곧 다음 행동이라 별도 안내가 필요 없다.
- **확정은 되돌릴 수 없다** — 확정하면 입력이 잠기고 온나라 결재 요청 안내가 뜬다(SCR-EDOC-008). 고치려면 **개정**으로 새 버전을 만든다.
- **호출한 화면이 폼의 맥락을 넣는다** — 메뉴 라벨·연동 정보·점검 항목 세트를 호출처가 주입하며, 이 폼은 받은 것을 그대로 그린다. 같은 폼이 여러 메뉴에서 쓰이므로 폼이 맥락을 스스로 정하지 않는다.
- **모달과 인라인 두 형태로 열린다** — 목록에서 부르면 팝업으로, 문서 상세에서 부르면 화면 안 패널로 그려진다. 필드 구성·상태 전이·저장 결과는 같다.
- **읽기 전용 필드는 호출처가 채운 값이다** — 담당자가 고치지 않는다.
- **점검표(F5)와 성격이 다르다** — 점검표는 O·X로 이행 여부를 보고 X가 개선조치를 만든다. 평가서는 점수로 수준을 보며 **개선조치를 자동으로 만들지 않는다**. 낮은 점수가 곧 법 위반은 아니기 때문이다.

### 예외·경계 시나리오

| 상황 | 화면 반응 |
|---|---|
| 임시저장 | 상태를 바꾸지 않고 입력값만 보관한다 — 작성중이면 작성중, 등록완료면 등록완료 그대로다 |
| 확정된 문서를 다시 엶 | 입력을 잠그고 [개정]만 제공한다 — 확정본은 결재가 올라간 기록이다 |
| 처리 이력이 없는 새 문서 | 이력 영역 자체를 그리지 않는다 — 빈 상자를 두지 않는다 |
| 첨부 없이 등록·확정 | 막지 않는다 — 증빙이 나중에 오는 경우가 실제로 있다 |
| 전 항목을 미평가로 둔 채 확정 | 막지 않으나 §6 기준상 종합 의견이 필수다 — 근거 없는 평가서를 남기지 않는다 |
| 낮은 점수를 매김 | 개선조치가 자동으로 만들어지지 않는다 — 필요하면 사람이 조치보고(SCR-EDOC-007)로 잇는다 |

## 4. 화면 구성별 정리

### 4-1. 문서 머리 — 서식 이름과 상태

- 구성: 서식 이름 배지 · 현재 상태 배지(작성중 / 등록완료 / 확정) · 호출처 메뉴 라벨(주어진 경우).

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 폼 열기 | 저장된 상태를 배지로 표시한다 | 처음 여는 문서는 작성중 |
| 상태 전이 | 배지가 함께 바뀐다 | — |

- 상태: **작성중 → 등록완료 → 확정** 세 단계이며 되돌아가지 않는다. 호출처 라벨이 없으면 그 배지를 그리지 않는다.

### 4-2. 연동 정보

- 구성: 이 문서가 어느 업무·대상에서 왔는지 한 줄로 보여주는 카드.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 호출처가 연동 정보를 넘김 | 카드를 그린다 | — |
| 넘기지 않음 | 카드를 그리지 않는다 | 빈 카드를 두지 않는다 |

- 상태: **있음 / 없음** 둘이다. 이 폼이 스스로 만들어 내지 않는다.

### 4-3. 입력 영역

- 구성: **평가일** · **평가 대상** · **평가 항목**(항목마다 점수 선택 + 의견) · **종합 의견**(여러 줄).
- 점수는 **미평가 · 5(우수) · 4 · 3(보통) · 2 · 1(미흡)** 중에서 고른다. **미평가가 기본값**이다 — 안 본 항목을 보통으로 두면 평가하지 않은 것이 평균에 섞인다.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 항목 입력 | 화면에만 반영한다(저장 전) | — |
| 첨부 영역 클릭·끌어놓기 | 파일을 고른다 | 지원 형식·용량·개수 안내를 함께 낸다 |
| 확정된 문서에서 입력 시도 | 잠겨 있어 고칠 수 없다 | [개정]으로 새 버전을 만든다 |

- 상태: 항목별 **미입력 / 입력됨**이며, 확정 이후에는 전체가 **읽기 전용**이 된다. 빈 항목이 있어도 저장을 막지 않는다 — 무엇을 필수로 할지는 §5에 있다.

### 4-4. 처리 이력

- 구성: 시각과 무슨 일이 있었는지를 시간순으로 쌓는 목록.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 임시저장·등록·확정 | 그 사실을 이력에 남긴다 | — |
| 이력이 하나도 없음 | 이력 영역을 그리지 않는다 | — |

- 상태: **없음 / 있음** 둘이며 조회 전용이다. 고치거나 지울 수 없다.

### 4-5. 하단 버튼

- 구성: 상태에 따라 달라지는 버튼 묶음.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| [임시저장] | 상태를 유지한 채 입력값을 보관한다 | "임시저장되었습니다 — 작성중 상태로 유지" |
| [등록](작성중) | 등록완료로 넘긴다 | "등록되었습니다 — 확정 전까지 수정 가능" |
| [확정 · 온나라 결재 상신](등록완료) | 확정하고 결재 요청 안내를 띄운다 | SCR-EDOC-008 |
| [개정](확정) | 새 버전을 작성중으로 만든다 | 확정본은 그대로 남는다 |
| [취소]·[닫기] | 저장하지 않고 닫는다 | — |

- 상태: 상태마다 나오는 버튼이 다르며, 같은 자리에 모든 버튼을 두고 비활성으로 가리지 않는다 — 지금 할 수 있는 것만 보인다.

## 6. 정책

- **서식은 담당자가 고치지 않는다** — 항목 구성은 이 시스템이 제공하는 표준이며, 화면에서 항목을 더하거나 지우지 않는다. 서식을 바꿔야 하면 프리셋 양식 관리(SCR-ADMIN-003)에서 한다.
- **상태 전이는 한 방향이다** — 작성중 → 등록완료 → 확정으로만 가고 되돌아가지 않는다. 확정본을 고치는 유일한 길은 개정이며, 이전 버전은 지우지 않고 남긴다. 결재가 올라간 문서를 고칠 수 있으면 그것은 기록의 위조다.
- **확정과 결재 요청은 한 동작이다** — 확정하는 순간 결재 요청 안내가 뜬다. 두 단계로 나누면 확정만 하고 결재를 안 올린 문서가 생긴다.
- **문서번호는 온나라가 부여한다** — 이 폼이 자체 채번하지 않는다. 자체 번호를 붙이면 온나라 번호와 두 개가 돌아 담당자가 어느 것을 공문에 적어야 하는지 알 수 없다.
- **점수는 비교를 위한 값이다** — 항목 구성이 바뀌면 이전 평가와 비교할 수 없으므로, 항목 세트를 바꾼 시점을 함께 남긴다.
- **법령 근거를 이 폼이 정하지 않는다** — 서식 자체는 특정 조문의 이행 수단이 아니라 여러 업무가 공유하는 그릇이다. 근거는 **이 폼을 부른 화면**에 붙으며, 규칙은 공통 근거 연계(SCR-COM-008)를 따른다.
- **저장 경계(프로토타입)** — 입력값은 브라우저에 보관되어 화면을 옮겨도 유지되지만 실서비스 저장 방식은 본개발에서 정한다.

---

## 7. 미결사항

없음. 상태 전이 규칙·확정과 결재의 관계·필수 항목·서식 변경 경로·법령 근거의 소속은 모두 §6에서 확정했다.

실서비스 저장과 온나라 실연계는 미결이 아니라 **본개발 구현 범위**이며, 무엇을 저장하고 승인·반려가 무엇을 바꾸는지는 §6과 SCR-EDOC-008에 정해져 있다.
