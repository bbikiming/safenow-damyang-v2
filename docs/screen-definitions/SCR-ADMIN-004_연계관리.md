## 2. 권한 정보

- 메뉴 접근·보기·수정은 시스템 관리의 메뉴 관리(SCR-ADMIN-005)와 권한 관리(SCR-ADMIN-006)에서 설정한다.

## 3. 진입 / 이탈 경로 및 사용자 시나리오

**진입 / 이탈**

| 구분 | 연결 화면 | 조건 / 트리거 |
|---|---|---|
| 진입 | 시스템 관리 > 연계 관리 | 좌측 메뉴 |
| 이탈 | 같은 화면 유지 | [실패 재시도] — 결과 안내만 표시 |
| 이탈(설계상) | FMS 연계(SCR-FAC-004) | 시설물 연계의 실제 작업·이력으로 넘어가는 동선 — **현재 링크 없음**(§6 확정) |

**사용자 시나리오**

| 단계 | 사용자 행동 | 화면 반응 |
|:--:|---|---|
| 1 | 연계 관리 진입 | 시스템 네 곳의 상태 카드가 한 줄로 표시됨 |
| 2 | 카드의 상태 점 확인 | 정상은 초록, 지연·주의는 주황으로 구분됨 |
| 3 | FMS 카드 확인 | 마지막 수신 일시와 건수가 표시됨 — 시설물 대장의 실제 보유 건수와 같은 값 |
| 4 | 연계 로그 확인 | 시스템별 최근 작업이 일시·작업·건수·결과로 나열됨 |
| 5 | 실패 표시가 있는 행 확인 | 결과 칸에 실패 건수가 표시됨 |
| 6 | [실패 재시도] | 재시도 결과 안내가 표시됨(현재는 안내만) |

**분기 로직**

- **상태 점은 시스템별 상태에 따라 분기한다** — 정상 / 지연·주의 두 가지이며, 지연인 카드는 무엇이 밀렸는지(배치 건수·재시도 대기)를 함께 적는다.
- **FMS 카드와 로그의 건수는 고정값이 아니라 파생값이다** — 시설물 대장이 실제로 보유한 건수와 가장 최근 수신 이력에서 만들어진다. 대장을 다시 받으면 이 화면의 숫자도 함께 바뀐다.
- 나머지 세 시스템(온나라·e호조·행정포털)의 값은 아직 고정 표시값이다. 각 도메인에 이력을 남기는 구조가 생기면 FMS와 같은 방식으로 파생한다(§6 확정).

**엣지케이스**

- **수신 이력이 하나도 없으면 FMS 카드는 건수 대신 "수신 기록 없음"을 표시한다.** 0건과 기록 없음은 다른 상태이며, 섞으면 대장이 비었다는 뜻으로 오독된다.
- 시설물 대장 자료를 불러오지 못하면 FMS 카드의 건수·일시 자리는 채워지지 않는다. 이때 임의값을 넣지 않는다.
- [실패 재시도]는 실패 건이 없어도 눌린다. 재시도 대상이 없을 때의 처리는 §6에서 확정했다.
- 로그는 최근 몇 건만 보여주고 기간 조회·검색이 없다. 장애를 되짚으려면 기간이 필요하다(§6 확정).

## 4. 화면 구성별 정리

### 4-1. 시스템별 상태 카드

- 구성: 카드 4장 — 온나라(문서·결재) · FMS(시설물관리) · e호조(재정) · 행정포털(SSO·조직도). 각 카드는 상태 점 + 시스템명 + 연계 내용 한 줄 + 마지막 호출·수신 정보로 이루어진다.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 화면 진입 | 네 시스템의 현재 상태를 표시 | — |
| 화면 진입(FMS) | 시설물 대장의 실제 보유 건수와 최근 수신 일시를 계산해 채움 | 수신 기록이 없으면 "수신 기록 없음" |

- 상태: 카드마다 **정상 / 지연·주의** 두 상태를 가진다. FMS 카드는 여기에 더해 **자료 미확보**(대장을 불러오지 못한 경우) 상태를 갖는다. 단계상태로는 각 시스템이 **연결됨 → 지연 → 실패**로 진행하며, 지연·실패 카드는 그 사유를 한 줄로 함께 적는다. 카드에는 조작 수단을 두지 않는다 — 상태판이지 작업 화면이 아니다.

### 4-2. 연계 로그

- 구성: [실패 재시도] 버튼 + 5개 열 표(일시 · 시스템 · 작업 · 건수 · 결과). 최근 작업이 위에 온다.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 화면 진입 | 시스템별 최근 연계 작업을 나열 | — |
| 화면 진입(FMS 행) | 대장 수신 이력에서 일시·건수를 계산해 채움 | — |
| [실패 재시도] | 실패한 연계 작업을 다시 시도 | 현재는 결과 안내만 표시 |

- 상태: 각 행은 **성공 / 부분 실패**로 갈리며 부분 실패는 실패 건수를 함께 적는다. 로그가 비어 있는 경우는 없다(시스템별 최근 작업이 항상 한 건 이상 있다). 이 표는 조회 전용이라 여기서 로그를 지우거나 고칠 수 없다. **시설물 연계의 상세 내역**(무엇이 신규이고 무엇이 바뀌었는지, 필드 단위 변경, 전송 결과)은 이 표가 아니라 FMS 연계(SCR-FAC-004 §4-3)가 갖는다.

## 5. 유효성 검사

이 화면에는 입력 폼이 없다(상태 조회 + 재시도 실행). 저장하는 값이 없어 형식·필수 검증이 성립하지 않는다.

- 연계 파라미터(인증·수신 주기·실행 상한)의 입력과 검증은 시설물의 경우 연계 설정(SCR-FAC-005 §5)이 담당한다. 다른 시스템의 연계 설정 화면은 아직 없다(§6 확정).

## 6. 정책

- **이 화면은 상태만 본다** — 연계 작업의 실행·검토·감사는 각 도메인이 맡는다. 시설물은 FMS 연계(SCR-FAC-004)가 수신·차이 검토·반영·전송과 감사 이력을 갖고, 이 화면은 "지금 연결이 살아 있는가"만 답한다. 두 화면의 역할을 섞으면 같은 작업을 두 곳에서 하게 된다.
- **건수를 하드코딩하지 않는다** — 종전에는 FMS 동기화 건수가 고정값이었고, 그 값이 실제 대장 건수와 달라 두 화면이 서로 다른 현황을 주장했다. 상태 모니터가 틀린 숫자를 보이면 모니터로서 값을 잃는다. 실제 자료에서 파생하고, 파생할 수 없으면 비워 둔다.
- **없는 상태를 그럴듯하게 만들지 않는다** — 수신 기록이 없으면 "수신 기록 없음"이라고 쓴다. 임의 날짜나 0건으로 채우면 한 번도 받지 않은 상태와 받았는데 0건인 상태를 구분할 수 없다.
- **재시도는 외부로 나가는 행위다** — 상태를 읽는 것과 달리 외부 시스템에 요청을 다시 보낸다. 그래서 화면을 여는 것만으로 실행되지 않고 명시적으로 눌러야 나가며, 결과는 로그에 남는다. **재시도는 최대 3회까지, 자동이 아니라 사람이 누른다(INT-04 확정)** — 규격 오류·인증 만료·상대 시스템 점검처럼 몇 번을 보내도 같은 결과인 실패가 대부분이라, 자동 재시도는 로그를 같은 실패로 채워 진짜 원인을 덮는다. **재시도할 대상이 없으면 버튼을 비활성화**하고 "재시도할 실패 건이 없습니다"로 밝힌다 — 눌렀는데 아무 일도 안 일어나는 것이 가장 나쁘다. 3회 연속 실패하면 그 연계를 **"점검 필요"로 표시**하고 더 이상 재시도 버튼을 내지 않는다. 사람 손으로 원인을 없애야 하는 상태이기 때문이다.
- **각 카드에서 그 도메인의 연계 화면으로 간다(INT-02 확정)** — 상태만 보는 화면이라 "끊겼다"를 알고 나면 갈 곳이 있어야 한다. 시설물 카드는 FMS 연계(SCR-FAC-004)로 잇는다. **연계 작업 화면이 없는 시스템의 카드에는 링크를 만들지 않는다** — 없는 곳으로 보내는 것보다 없다는 사실이 보이는 편이 낫고, 그 빈자리가 다음에 만들 화면의 목록이 된다.
- **파생은 이력을 남기는 도메인부터 붙인다(INT-03 확정)** — 지금 실제 이력을 갖는 것은 시설물 연계 하나뿐이라 그 카드만 파생값이고 나머지 셋은 파생할 원본이 없다. **순서는 온나라 → 행정포털 → e호조**다. 온나라는 결재 상신·문서 발송이 이미 업무 흐름 안에 있어 이력을 남길 자리가 정해져 있고, 행정포털은 조직도·인증이라 끊기면 전 화면이 멈추므로 상태 표시의 값이 가장 크며, e호조는 예산 조회가 주기성 업무라 급하지 않다. **원본이 없는 카드는 파생하는 척하지 않고 "연계 이력 미구현"으로 밝힌다.**
- **로그는 기간·시스템·결과로 좁혀 보고, 지우지 않는다(INT-05 확정)** — 장애를 되짚으려면 최근 몇 건으로는 부족하고, 대개 "지난달 어느 날부터 이상했다"에서 시작하기 때문에 **기간**이 첫 조건이다. 여기에 시스템과 결과(성공·실패·대기)를 겹친다. 건수 상한이나 자동 삭제를 두지 않는다 — 연계 로그는 용량이 작고, 지우는 순간 되짚을 수 없는 것이 늘어난다.
- **시스템별 연계 파라미터는 도메인 화면이 관리한다(INT-06 확정)** — 이 화면에 통합하지 않는다. 파라미터는 그 연계의 규격에 매인 값이라(시설물의 기관코드·하루 상한처럼) 한곳에 모으면 서로 관계없는 설정이 뒤섞이고, 어느 값이 어느 연계에 영향을 주는지 알 수 없게 된다. 이 화면은 **어디서 설정하는지로 데려다주는 링크만** 갖는다 — 상태를 보다가 설정을 고쳐야 할 때 헤매지 않게 하는 것이 목적이다.
- **장애는 화면을 열지 않아도 알린다(INT-07 확정)** — 상태 모니터를 매일 여는 사람은 없다. **연계가 실패하면 시스템 관리자에게 알림을 보내고**, 시설물처럼 담당 도메인이 있는 연계는 그 담당자에게도 함께 보낸다. 채널은 시스템 내부 알림이다 — 문자·메일 같은 외부 채널은 발송 비용·개인정보 처리·수신 동의가 얽혀 별도 결정이 필요하므로, 내부 알림으로 시작하고 필요가 확인되면 확장한다. **매 실패마다 보내지 않고 상태가 바뀔 때만** 보낸다(정상→실패, 실패→정상) — 실패가 이어지는 동안 매번 보내면 알림이 소음이 되어 결국 꺼진다.
- **조직도 연계의 정식 명칭과 출처는 행정포털로 통일한다(INT-08 확정)** — 화면·정의서·연계 이력에서는 "행정포털(SSO·조직도)"만 사용한다. 온나라는 전자결재 연계 이름으로만 사용해 두 시스템이 같은 것처럼 보이지 않게 한다.
- **법령 근거를 붙이지 않는다** — 시스템 연계 상태 모니터링은 법령이 명한 의무 이행 행위가 아니다. 근거 없음을 명시하며 규칙은 공통 근거 연계(SCR-COM-008)를 따른다.
- **연계는 전부 시뮬레이션이다** — 프로토타입에서 외부 시스템을 실제로 호출하지 않는다. 실 개발에서는 배치 서버가 호출하고 화면은 그 결과를 읽는다. 화면이 외부를 직접 호출하는 구조를 만들지 않는다.

## 7. 미결사항

없음. 도메인 화면 연결·나머지 세 시스템의 파생 순서·재시도 정책·로그 조회와 보관·연계 파라미터의 관리 위치·장애 알림·조직도 연계 명칭은 모두 §6에서 확정했다.

조직도 연계 명칭과 단일 출처는 §6에서 확정했다. 실제 접속 규격은 외부 준비사항이며 미연계 동안 엑셀·직접 등록의 출처를 구분해 사용한다.
