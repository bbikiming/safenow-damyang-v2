업무에 필요한 **공지·참고자료·다른 부서의 사례**를 모아 두는 자리다. 안전보건 업무는 부서마다 따로 하다 보니 한 부서가 잘 만든 서식이나 대응 방법이 다른 부서로 넘어가지 않고, 법령이 바뀌어도 각자 알아서 알게 된다. 그래서 이 화면이 **알려야 할 것과 참고할 것**을 한곳에 둔다. 구성은 공지사항·자료실·우수사례 세 덩어리이며, 모두 조회와 등록만 있고 업무 상태를 바꾸지 않는다.

**탭은 시스템 관리 > 게시판 관리(SCR-ADMIN-011)가 정한 «사용» 게시판이 그 순서대로 된다**(2026-11-05). 기본 3개가 위 세 덩어리이고, 관리자가 게시판을 더 만들면 탭이 늘어난다. 각 게시판은 공지형·자료형·사례형 중 하나라 아래 세 영역의 구성을 그대로 따른다.

## 3. 진입 / 이탈 경로 및 사용자 시나리오

| 구분 | 연결 화면 | 조건 / 트리거 |
|---|---|---|
| 진입 | 통계·보고 > 정보센터 | 메뉴 선택 |
| 이탈 | 각 업무 화면 | 자료가 특정 업무를 가리킬 때 |
| 연계 | 시스템 관리 > 게시판 관리(SCR-ADMIN-011) | 탭(게시판)의 이름·순서·사용 여부를 정한다 |

| 단계 | 사용자 행동 | 화면 반응 |
|:--:|---|---|
| 1 | 화면에 들어온다 | 사용 중인 게시판을 탭으로 나눠 첫 탭을 보여 준다 |
| 1-1 | 검색칸에 낱말을 넣는다 | 입력하는 대로 지금 탭의 글을 거르고, 탭마다 걸린 글 수를 보인다 |
| 2 | 공지를 확인한다 | 제목·작성·등록일·조회수를 본다 |
| 3 | 자료를 찾는다 | 구분으로 좁혀 필요한 서식·지침을 받는다 |
| 4 | 사례를 올린다 | 부서와 함께 등록한다 |

### 분기 로직

- **세 영역의 성격이 다르다** — **공지**는 알려야 하는 것(읽었는지가 중요), **자료실**은 필요할 때 찾는 것(분류가 중요), **우수사례**는 퍼뜨릴 것(누가 했는지가 중요)이다. 그래서 표시하는 항목도 다르다 — 공지는 조회수, 자료실은 구분, 사례는 부서와 추천을 함께 낸다.
- **자료실은 기준문서함과 다르다** — 기준문서함(SCR-DOC-001)은 **업무 이행의 근거가 되는 문서**를 보관하고, 자료실은 **참고하면 좋은 자료**를 둔다. 이행 증빙이 되는 문서를 자료실에 두면 점검 때 근거를 못 찾는다.
- **법령 개정 안내는 공지로 나간다** — 조문 자체는 법령 관리(SCR-ADMIN-007)가 관리하고, 그 변화를 사람에게 알리는 것은 공지의 몫이다.

### 예외·경계 시나리오

| 상황 | 화면 반응 |
|---|---|
| 어느 영역이 0건 | 그 영역만 «등록된 글이 없습니다»로 표시하고 나머지는 정상 표시한다 |
| 검색 결과가 0건 | «조건에 맞는 글이 없습니다» — 글이 없는 것과 다른 문구로 말한다 |
| 사용 중인 게시판이 0개 | 탭과 검색칸 없이 «등록된 글이 없습니다» 한 줄만 보인다 |
| 글을 올릴 수 없는 게시판 | `[＋ 글 등록]`을 내지 않는다. 호출로 들어와도 누가 올리는지(주관부서 / 각 부서 담당자)를 밝히고 막는다 |
| 자료에 첨부가 없음 | 제목만 있는 항목도 허용한다 — 링크나 안내만 있는 경우가 있다 |
| 오래된 공지 | 지우지 않고 등록일로 정렬해 아래로 내린다 — 언제 무엇을 알렸는지가 남아야 한다 |
| 업무 이행 증빙을 자료실에 올리려 함 | 업무 관리 > 이행 관리(SCR-CMP-001)로 안내한다 — 두 곳에 나뉘면 점검 때 근거를 못 찾는다 |
| 우수사례에 부서가 비어 있음 | 등록을 막는다 — 누가 했는지 없는 사례는 물어볼 곳이 없어 퍼지지 않는다 |

## 4. 화면 구성별 정리

### 4-0. 검색·탭·글 등록

- 위 줄: 검색칸(제목·내용 검색) · `[＋ 글 등록]`(그 게시판에 올릴 수 있는 사람에게만).
- 검색은 사용 중인 게시판의 글을 제목·내용·구분·부서·작성으로 찾는다. 시스템 전체 색인 검색은 이 화면의 기능이 아니므로 그렇게 보이는 입력을 두지 않는다.
- 글을 누르면 같은 창에서 본문·첨부를 연다. 쓴 사람과 주관부서 담당자에게는 `[삭제]`가 있고, 삭제 확인도 같은 창 안에서 한다.
- 글 등록 창: 제목(자료형은 자료명·사례형은 사례) · 구분(자료형) · 부서(사례형 — 부서 담당자는 소속 부서로 고정, 주관부서 담당자는 조직도에서 고른다) · 내용 · 첨부(공통 첨부 기준).

### 4-1. 공지사항

- 구성: 제목 · 작성 · 등록일 · 조회 네 열.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 화면 진입 | 최근 공지를 최신 순으로 보여 준다 | — |
| 공지 선택 | 본문을 연다 | 조회수가 올라간다 |
| 공지가 0건 | 비어 있음을 표시한다 | — |

- 상태: **없음 / 있음** 둘이다. 조회수는 얼마나 전달됐는지를 가늠하는 값이며, 낮은 조회수는 다시 알려야 한다는 신호다.

### 4-2. 자료실

- 구성: 자료명 · 구분 · 등록일 세 열.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 구분으로 좁힘 | 그 구분의 자료만 남긴다 | 서식·지침·법령 안내 등 |
| 자료 선택 | 첨부를 받거나 안내를 연다 | 첨부가 없는 항목도 있다 |
| 업무 증빙을 올리려 함 | 이행 관리로 안내한다 | SCR-CMP-001 |

- 상태: **없음 / 있음**이며, 항목마다 **첨부 있음 / 없음**이 갈린다.

### 4-3. 우수사례

- 구성: 사례 · 부서 · 등록일 · 추천 네 열.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 사례 선택 | 내용을 연다 | 어느 부서가 했는지 함께 본다 |
| 추천 | 추천 수를 올린다 | 어떤 사례가 실제로 도움이 됐는지 드러난다 |
| 부서 없이 등록 | 막는다 | 물어볼 곳이 없는 사례는 퍼지지 않는다 |

- 상태: **없음 / 있음**이며, 추천 수로 정렬해 실제로 쓰인 사례가 위로 온다.

## 6. 정책

- **자료실과 업무문서를 섞지 않는다** — 이행의 근거가 되는 문서는 업무 관리(이행 관리·문서 목록)에, 자료실은 참고 자료를 둔다. 이행 증빙이 자료실에 있으면 점검 때 근거를 못 찾는다. (2026-09-03 이전에는 이 자리를 기준문서함이 맡았고, 그 화면은 메뉴에서 빠졌다.)
- **쓰는 권한을 영역마다 다르게 둔다** — 공지는 주관부서가 낸다(아무나 공지를 내면 무엇이 공식인지 알 수 없다). 자료실과 우수사례는 각 부서가 올린다 — 현장에서 만든 것이 가장 쓸모 있고, 막으면 아무도 올리지 않는다.
- **오래된 공지를 지우지 않는다** — 언제 무엇을 알렸는지가 나중에 근거가 된다.
- **우수사례에 부서를 필수로 받는다** — 누가 했는지 모르면 물어볼 곳이 없어 사례가 퍼지지 않는다. 사례의 값은 내용이 아니라 **따라 할 수 있다는 것**에 있다.
- **조회수·추천을 감추지 않는다** — 낮은 조회수는 전달이 안 됐다는 신호이고, 추천은 실제로 도움이 됐는지를 알려 준다.
- **법령 개정 자체를 여기서 관리하지 않는다** — 조문은 법령 관리가 관리하고, 이 화면은 그 변화를 사람에게 알리는 자리다.
- **탭의 정본은 게시판 관리다(2026-11-05)** — 화면이 탭을 따로 들고 있지 않는다. 관리 화면에서 만들거나 끈 게시판이 그대로 반영돼야 한다.
- **안내 문구는 이 화면에서 할 일만 말한다(운영 요청서 T18)** — 게시판이 어떻게 만들어지는지, 아직 없는 기능이 무엇인지 같은 시스템 설명을 쓰지 않는다. 비어 있으면 «등록된 글이 없습니다»만 보인다.
- **검색은 실제로 걸러지는 것만 약속한다** — 동작하지 않는 «통합검색» 입력을 두지 않는다. 검색칸은 보이는 게시판의 글을 거른다.
- **추천은 한 사람이 한 번이다** — 같은 사람이 여러 번 누르면 실제로 도움이 됐는지가 흐려진다.
- **법령 근거를 붙이지 않는다** — 자료·안내 허브는 법령이 명한 의무의 직접 이행 수단이 아니다. 근거 없음도 정보이며 규칙은 공통 근거 연계(SCR-COM-008)를 따른다.

## 7. 미결사항
