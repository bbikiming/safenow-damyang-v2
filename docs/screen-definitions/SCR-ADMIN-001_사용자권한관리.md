# 화면 정의서 — 사용자 관리

> 화면 ID: SCR-ADMIN-001 · 화면 유형: 목록 · 기획 관점(v6) · 구현 정합 2026-08-12
> 판단이 필요했던 항목은 §6 정책에서 확정했습니다.

---

## 1. 화면 정보

| 항목 | 내용 |
|---|---|
| 화면 ID | SCR-ADMIN-001 |
| 화면명 | 사용자 관리 |
| URL 경로 | admin-users.html |
| 상위 메뉴 | 시스템 관리 > 사용자 관리 |
| 화면 유형 | 목록 |

**누가 이 시스템을 쓰고 있고 무엇을 볼 수 있는지**를 사람 단위로 확인하는 화면이다. 권한은 등급과 메뉴 지정 두 곳에서 정해지는데, 그 결과 한 사람이 실제로 무엇에 접근하는지는 어느 한쪽만 봐서는 알 수 없다. 그래서 이 화면이 **합쳐진 결과를 사람 기준으로** 보여 준다. 구성은 사용자 목록·권한 등급 요약·접근 메뉴 역조회 세 덩어리이며, 등급 정의는 권한 관리(SCR-ADMIN-006), 메뉴 지정은 메뉴 관리(SCR-ADMIN-005)가 맡는다.

---

## 2. 권한 정보

- 메뉴 접근·보기·수정은 시스템 관리의 메뉴 관리(SCR-ADMIN-005)와 권한 관리(SCR-ADMIN-006)에서 설정한다.
- 이 화면 정의서에서는 역할별 권한과 열람 범위를 별도로 정하지 않는다.
- 이 화면은 **시스템 관리자만** 들어온다 — 다른 사람의 권한과 접속 기록을 다루기 때문이다.

---

## 3. 진입 / 이탈 경로 및 사용자 시나리오

| 구분 | 연결 화면 | 조건 / 트리거 |
|---|---|---|
| 진입 | 시스템 관리 > 사용자 관리 | 메뉴 선택 |
| 이탈 | 권한 관리 | 등급 구성원을 바꿀 때(SCR-ADMIN-006) |
| 이탈 | 메뉴 관리 | 메뉴별 접근을 바꿀 때(SCR-ADMIN-005) |

| 단계 | 사용자 행동 | 화면 반응 |
|:--:|---|---|
| 1 | 화면에 들어온다 | 사용자 목록과 각자의 권한·담당 대메뉴를 보여 준다 |
| 2 | 한 사람을 고른다 | 그 사람이 실제로 접근하는 메뉴를 역으로 보여 준다 |
| 3 | 권한이 잘못됐음을 발견한다 | 등급 또는 메뉴 지정 화면으로 보낸다 |

### 분기 로직

- **사람은 조직도에서 오고 권한은 이 시스템에서 정한다** — 성명·부서는 행정포털 조직도가 정본이고 이 화면이 명단을 만들지 않는다. 반대로 어느 등급인지·무엇에 접근하는지는 이 시스템의 설정이다. 두 축이 섞이면 인사이동 때 권한만 옛 상태로 남는다.
- **실효 권한은 합집합이다** — 한 사람이 여러 등급에 속하거나 개별 지정을 함께 받으면 **가장 넓은 권한**이 실효값이다. 이 화면은 그 합쳐진 결과를 보여 준다.
- **대표 등급은 가장 넓은 등급이다** — 여러 등급에 속한 사람은 넓은 쪽을 대표로 표시하며, 권한 관리 화면과 같은 규칙을 쓴다. 두 화면이 다른 대표 등급을 보이면 어느 쪽이 맞는지 알 수 없다.
- **이 화면에서 권한을 바꾸지 않는다** — 등급 구성원은 권한 관리, 메뉴별 접근은 메뉴 관리에서 바꾼다. 세 곳에서 바꿀 수 있으면 어디를 고쳐야 하는지 알 수 없고 변경 이력이 흩어진다.

### 예외·경계 시나리오

| 상황 | 화면 반응 |
|---|---|
| 어느 등급에도 속하지 않은 사람 | 목록에 남기고 등급 없음을 드러낸다 — 접근할 수 있는 메뉴가 없다는 뜻이라 확인이 필요하다 |
| 인사이동으로 부서가 바뀐 사람 | 부서는 조직도를 따라 바뀌고, **부서 기준으로 받은 권한도 함께 따라간다**. 개인 지정으로 받은 권한은 따라가지 않으므로 그 사실을 드러낸다 |
| 조직도에서 사라진 사람 | 목록에서 자동으로 지우지 않고 확인이 필요함을 표시한다 — 퇴직인지 부서 이동 반영 지연인지 이 화면은 알 수 없다 |
| 접속 기록이 없는 사람 | 한 번도 들어오지 않았음을 표시한다 — 빈칸으로 두면 기록이 없는 것인지 안 들어온 것인지 모른다 |
| 시스템 관리자가 한 명뿐 | 그 사실을 경고한다 — 한 명이 접근을 잃으면 아무도 설정을 못 바꾼다 |
| 전체 권한 등급 구성원이 0명 | 저장이 막힌다(SCR-ADMIN-006 §6) |

## 4. 화면 구성별 정리

### 4-1. 사용자 목록

- 구성: 성명 · 부서(조직도 연동) · 권한 · 담당 대메뉴 · 최근 접속 다섯 열.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 화면 진입 | 조직도 인원에 이 시스템의 권한을 붙여 보여 준다 | 명단을 따로 만들지 않는다 |
| 사용자 선택 | 그 사람의 접근 메뉴 역조회를 연다 | — |
| 등급이 없는 사람 | 등급 없음을 드러낸다 | 접근 가능한 메뉴가 없다는 뜻이다 |
| 접속 기록이 없는 사람 | 없음을 명시한다 | 빈칸으로 두지 않는다 |

- 상태: 사람마다 **등급 있음 / 없음**, **접속 이력 있음 / 없음**이 갈린다. 목록이 비는 경우는 없다 — 조직도에 사람이 있으면 여기에도 있다.

### 4-2. 권한 등급 요약

- 구성: 등급 · 구성원 수 · 적용 메뉴 수 · 설명.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 화면 진입 | 등급별 구성원과 적용 범위를 요약한다 | 정의는 권한 관리가 맡는다 |
| 등급 선택 | 권한 관리로 이동한다 | SCR-ADMIN-006 |
| 구성원이 0명인 등급 | 0을 그대로 표시한다 | 쓰지 않는 등급인지 알 수 있어야 한다 |

- 상태: 조회 전용이다. 등급을 만들거나 고치는 것은 이 화면이 하지 않는다.

### 4-3. 접근 메뉴 역조회

- 구성: 고른 사람이 실제로 접근하는 대메뉴 · 중메뉴 · 그 권한을 받은 **근거**(어느 등급 또는 개별 지정).

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 사용자 선택 | 등급과 개별 지정을 합친 결과를 보여 준다 | 합집합이 실효값이다 |
| 근거 표시 | 어느 등급에서 왔는지, 개별 지정인지 밝힌다 | 왜 이 메뉴가 보이는지 알 수 있어야 한다 |
| 접근 가능한 메뉴가 0건 | 그 사실을 드러낸다 | 등급이 없거나 지정이 안 된 상태다 |

- 상태: **접근 있음 / 없음** 둘이며, 항목마다 근거가 함께 붙는다. 근거를 안 보여 주면 권한이 잘못됐을 때 어디를 고쳐야 하는지 알 수 없다.

## 5. 유효성 검사

해당 없음 — 조회 전용 화면이라 저장형 입력이 없다. 등급 구성원 변경의 검증은 권한 관리(SCR-ADMIN-006 §5), 메뉴 지정의 검증은 메뉴 관리(SCR-ADMIN-005 §5)가 담당한다.

---

## 6. 정책

- **사람 명단을 이 시스템이 만들지 않는다** — 조직도가 정본이다. 명단을 따로 두면 인사이동 때 여기만 옛 상태로 남는다.
- **이 화면에서 권한을 바꾸지 않는다** — 등급은 권한 관리, 메뉴 접근은 메뉴 관리에서 바꾼다. 여러 곳에서 바꿀 수 있으면 변경 이력이 흩어져 "누가 언제 이 권한을 줬는가"를 답할 수 없다.
- **왜 그 메뉴가 보이는지 함께 보여 준다** — 접근 목록만 있고 근거가 없으면 권한이 잘못됐을 때 어느 등급을 고쳐야 하는지 알 수 없다.
- **부서 기준 권한과 개인 지정을 구분한다** — 앞은 인사이동을 따라가고 뒤는 따라가지 않는다. 이 차이를 드러내지 않으면 이동한 사람이 이전 부서 권한을 그대로 갖고 있게 된다.
- **조직도에서 사라진 사람을 자동으로 지우지 않는다** — 퇴직인지 반영 지연인지 이 화면은 알 수 없다. 확인 대상으로 남긴다.
- **관리자 1명 상태를 경고한다** — 그 한 명이 접근을 잃으면 아무도 설정을 못 바꾼다.
- **법령 근거를 붙이지 않는다** — 사용자·권한 관리는 법령이 명한 의무가 아니라 시스템 운영 기능이다. 근거 없음도 정보이며 규칙은 공통 근거 연계(SCR-COM-008)를 따른다.

---

## 7. 미결사항

없음. 명단의 출처·권한 변경의 소속·근거 표시·부서 권한과 개인 지정의 구분·퇴직자 처리·관리자 1명 경고는 모두 §6에서 확정했다.

조직도 연동과 접속 기록 수집은 미결이 아니라 **본개발 구현 범위**이며, 무엇을 표시할지는 §4에 정해져 있다.
