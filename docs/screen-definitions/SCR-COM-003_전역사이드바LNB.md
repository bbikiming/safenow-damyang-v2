# 화면 정의서 — 전역 사이드바(LNB)

> 화면 ID: SCR-COM-003 · 화면 유형: 공통 크롬 · 기획 관점(v6) · 구현 정합 2026-08-28
> 판단이 필요했던 항목은 §6 정책에서 확정했습니다.
> **2026-08-28 정보구조 재편 반영** — 대메뉴가 11개로 접히면서 하위가 늘어난 축에 **구분 머리글(2뎁스)** 을 두는 기준을 확정했다.

---

## 1. 화면 정보

| 항목 | 내용 |
|---|---|
| 화면 ID | SCR-COM-003 |
| 화면명 | 전역 사이드바(LNB) |
| URL 경로 | 전 화면 공통 — 특정 주소가 없다 |
| 상위 메뉴 | 공통/전역 |
| 화면 유형 | 공통 크롬 |

지금 있는 대메뉴 축의 **하위 화면 목록**을 왼쪽에 세로로 보여 준다. 구성은 중메뉴 목록 하나이며, 좁은 화면에서는 서랍으로 바뀐다. 어느 항목을 고를 수 있는지는 메뉴 관리(SCR-ADMIN-005)가 정한다.

이 화면은 메뉴 구조의 **2뎁스와 3뎁스를 함께 그린다.** 대메뉴(1뎁스)가 11개로 좁혀지면서 하위가 4개를 넘는 축이 생겼고, 그 축은 성격별 구분 머리글로 묶는다. 무엇을 머리글로 묶고 무엇을 그대로 두는지가 이 화면의 핵심 계약이다(§6).

## 2. 권한 정보

- 메뉴 접근·보기·수정은 시스템 관리의 메뉴 관리(SCR-ADMIN-005)와 권한 관리(SCR-ADMIN-006)에서 설정한다.
- 이 화면 정의서에서는 역할별 권한과 열람 범위를 별도로 정하지 않는다.
- **접근 권한이 없는 중메뉴는 목록에서 빠진다** — 보이되 막는 방식을 쓰지 않는다(§6).

## 3. 진입 / 이탈 경로 및 사용자 시나리오

| 구분 | 연결 화면 | 조건 / 트리거 |
|---|---|---|
| 진입 | 모든 화면 | 화면이 열릴 때 자동으로 붙는다 |
| 진입 | 헤더 메뉴 버튼 | 좁은 화면에서 서랍으로 연다(SCR-COM-001) |
| 이탈 | 각 중메뉴 화면 | 항목 선택 |

| 단계 | 사용자 행동 | 화면 반응 |
|:--:|---|---|
| 1 | 화면에 들어온다 | 그 축의 하위 목록을 보여 주고 지금 화면을 활성으로 표시한다 |
| 2 | 다른 중메뉴를 고른다 | 그 화면으로 이동하며 사이드바는 그대로 남는다 |
| 3 | 구분 머리글이 있는 축에 들어온다 | 성격별로 묶인 머리글 아래 항목이 들여쓰여 나온다 |
| 4 | 좁은 화면에서 메뉴를 연다 | 서랍이 덮으며 열리고, 항목을 고르면 닫힌다 |

### 분기 로직

- **대메뉴 축이 목록 내용을 정한다** — 사이드바는 지금 축의 하위만 보여 준다. 전 메뉴를 한 번에 늘어놓지 않는 이유는, 축을 넘나드는 일이 드물고 목록이 길어지면 지금 축 안에서 길을 잃기 때문이다.
- **구분 머리글이 있으면 3단이 된다** — 하위 항목이 성격별로 갈리는 축은 머리글을 두고 그 아래를 들여쓴다. 머리글은 이동 대상이 아니라 묶음 이름이다.
- **머리글 이름은 항목 이름에 합쳐 읽힌다** — 한 축 안에 같은 이름의 항목이 여러 벌 있을 수 있다(안전보건교육의 정기교육·채용시교육·기타 교육이 현업근로자와 관리감독자 두 벌). 눈으로는 머리글이 갈라 주지만 화면 낭독은 링크만 훑으므로, 항목이 읽히는 이름은 **머리글과 항목 이름을 합친 것**이어야 한다.
- **활성 표시는 화면에서 파생한다** — 주소로 직접 들어와도 맞는다. 상세 화면처럼 목록과 같은 축에 속하는 화면은 그 목록 항목을 활성으로 둔다. 활성 표시는 색만으로 하지 않고 보조기술에도 전달한다.
- **폭에 따라 형태가 바뀐다** — 넓으면 고정 기둥, 좁으면 서랍이다. 서랍일 때는 뒤 화면을 덮는 가림막이 함께 나오고, 항목을 고르면 닫힌다.

### 예외·경계 시나리오

| 상황 | 화면 반응 |
|---|---|
| 접근 가능한 중메뉴가 하나뿐 | 그 하나만 그린다 — 목록 자체를 감추지 않는다 |
| 접근 가능한 중메뉴가 0건 | 그 대메뉴가 애초에 보이지 않으므로 이 상태에 도달하지 않는다(SCR-COM-002) |
| 상세 화면에 있음 | 그 상세가 속한 목록 항목을 활성으로 둔다 — 아무것도 활성이 아닌 상태를 만들지 않는다 |
| 메뉴에서 제외된 화면에 링크로 들어옴 | 그 화면을 흡수한 축의 목록을 그리고, 목록에는 그 화면을 넣지 않는다 — 어디에 있는지는 알려주되 없는 메뉴를 만들지 않는다 |
| 머리글이 있는 축에 머리글 없는 항목이 섞임 | 머리글 묶음 뒤에 구분선을 두고 직속으로 그린다(§6) |
| 서랍이 열린 채 항목 선택 | 이동하며 서랍을 닫는다 |
| 서랍이 열린 채 가림막 선택 | 이동하지 않고 닫는다 |
| 메뉴 사용 여부를 끔 | 접근 권한과 무관하게 목록에서 빠진다(SCR-ADMIN-005 §6) |

## 4. 화면 구성별 정리

### 4-1. 중메뉴 목록

- 구성: 아이콘 + 중메뉴 이름의 세로 목록. 성격이 갈리는 축은 **구분 머리글 + 들여쓴 항목**의 3단 구조.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 항목 선택 | 그 화면으로 이동한다 | 사이드바는 그대로 남는다 |
| 화면 진입 | 지금 화면(또는 그 상세가 속한 목록)을 활성으로 표시한다 | 주소로 직접 들어와도 맞다 |
| 구분 머리글 | 이동하지 않는다 | 묶음 이름일 뿐이다 |
| 접근 권한이 없는 항목 | 목록에서 뺀다 | 보이되 막는 방식을 쓰지 않는다 |

- 상태: 항목별 **활성 / 비활성**이며, 목록 전체로는 **2단(머리글 없음) / 3단(머리글 있음)** 두 형태를 갖는다. 빈 목록 상태는 존재하지 않는다.

### 4-2. 축별 하위 구성

대메뉴 11축의 하위 구성이다. 굵은 줄은 구분 머리글(2뎁스)이고 그 아래가 중메뉴(3뎁스)다. 머리글이 없는 축은 중메뉴가 바로 온다.

| 대메뉴 | 구분 머리글 | 중메뉴 |
|---|---|---|
| 대시보드 | — | 통합 현황 · 내 할일 |
| 시설물·원료 | **시설물** | 시설물 대장 · 시설물 위험도 |
| | 직속 | 원료·제조물 대장 |
| 안전보건관리체계 | **중대산업·시민재해 계획** | 경영방침 · 조직 |
| | **중대산업·시민재해 의무 이행점검** | 이행점검 |
| | 직속 | 도급관리 |
| 위험성평가 | — | 정기 위험성평가 · 수시 위험성평가 |
| 안전보건교육 | **현업근로자** | 정기교육 · 채용시교육 · 기타 교육 |
| | **관리감독자** | 정기교육 · 채용시교육 · 기타 교육 |
| | **교육 현황·관리** | 이수현황 · 근로자 명단 관리 · 결재 이력 |
| 작업환경·건강 | — | 작업환경측정 · 건강검진(일반·특수) |
| 의견청취 | — | 의견청취·건의함 · 산업안전보건위원회 · 협의체·점검표 |
| 인력·예산 | **인력 평가** | 인력 평가 · 평가 현황 · 평가 설정 |
| | **예산 관리** | 예산 총괄표 · 예산 기준 설정 |
| 업무 관리 | — | 이행 관리 · 문서 목록 |
| 통계·보고 | — | 현황 통계 · 보고서·제증명 · 정보센터 |
| 시스템 관리 | **사용자·권한** | 사용자 관리 · 권한 관리 · 메뉴 관리 |
| | **기준정보** | 사업장 관리 · 프리셋 양식 관리 · 법령 관리 |
| | **연계·알림** | 연계 관리 · 알림 관리 |

- 안전보건관리체계의 **두 머리글은 발주처 확정 구조**다. 세 번째 머리글을 만들지 않는다(§6). 도급관리는 계약 자료 회신 대기 중이라 두 묶음 어느 쪽에도 넣지 않고 직속으로 둔다.
- 위험성평가의 개선조치 화면은 정기평가 상세 안에서 처리하므로 목록에 두지 않는다. 링크로는 열리며 소속 축은 위험성평가다.
- 업무 관리에는 메뉴에서 제외된 화면 4건(업무 목록·이행 목록·업무 발행 관리·부서 업무함)이 소속만 유지한 채 목록에 나오지 않는다.

### 4-3. 좁은 화면 서랍

- 구성: 헤더의 메뉴 버튼으로 여는 서랍 + 뒤를 덮는 가림막.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 메뉴 버튼 선택 | 서랍을 연다 | SCR-COM-001 |
| 항목 선택 | 이동하고 서랍을 닫는다 | — |
| 가림막 선택 | 이동하지 않고 닫는다 | — |
| 화면을 넓힘 | 서랍을 닫고 고정 기둥으로 돌아간다 | — |

- 상태: **닫힘 / 열림** 둘이며, 열려 있는 동안 뒤 화면은 가림막에 덮인다. 서랍 안에도 구분 머리글은 고정 기둥과 같은 형태로 나온다.

## 6. 정책

**뎁스 계약**

메뉴는 세 층이고 각 층의 역할이 다르다. "어디까지가 대메뉴인가"를 사람마다 다르게 판단한 결과가 대메뉴 16개였으므로, 층의 역할을 못 박는다.

| 층 | 무엇 | 규칙 |
|---|---|---|
| 1뎁스 | 대메뉴 띠 | 제안요청서 기능 모듈 7축 안에서만 선다(SCR-COM-002 §6) |
| 2뎁스 | 구분 머리글 | **누를 수 없다.** 묶음 이름일 뿐이다 |
| 3뎁스 | 중메뉴 | 실제 화면으로 가는 링크 |

- **하위가 4개 미만이고 성격이 하나면 머리글을 두지 않는다** — 항목 두 개짜리 목록에 머리글을 다는 것은 깊이만 늘고 정보는 늘지 않는다. 새 화면은 대메뉴가 아니라 여기(2뎁스)로 들어오므로, 항목이 늘어 성격이 갈리는 시점에 머리글을 신설한다.
- **머리글을 쓰면서 어느 묶음에도 안 들어가는 항목은 구분선 아래 직속으로 둔다(2026-09-03 · 시설물·원료 적용)** — 그 축은 항목 3개에 성격이 둘(시설물 / 원료·제조물)이라 위 조항의 발동 조건에 걸려 머리글 **시설물**(대장·위험도)을 세웠다. 남는 원료·제조물 대장을 1항목짜리 머리글로 감싸지 않는 이유는 **머리글 하나에 항목 하나면 깊이만 늘고 정보가 늘지 않기 때문**이다 — 안전보건관리체계의 도급관리가 같은 처리다. 렌더는 섹션에서 직속으로 넘어갈 때 구분선을 넣는다.
- **한 축에서 머리글을 쓰기 시작하면 남는 항목의 성격을 밝힌다** — 앞쪽 항목이 머리글을 갖는데 뒤쪽만 이름 없이 떠 있으면 그 항목들이 같은 층인지 아닌지 읽히지 않는다. 성격이 있으면 머리글을 주고, 어느 묶음에도 넣을 수 없는 것만 구분선 아래 직속으로 둔다.
- **머리글은 이동 대상이 아니다** — 누를 수 있게 하면 어디로 가는지 알 수 없는 항목이 생긴다. 묶음의 대표 화면이 필요하면 그 화면을 3뎁스 항목으로 만든다.
- **머리글 이름은 항목의 읽히는 이름에 합친다** — 같은 이름의 항목이 여러 머리글 아래 있을 수 있으므로, 항목만 훑는 사용자에게도 구분이 전달되어야 한다.
- **머리글을 3단보다 깊게 만들지 않는다** — 머리글 아래 머리글을 두지 않는다. 더 깊은 분류가 필요하면 그것은 메뉴가 아니라 화면 안의 탭·필터로 푼다.

**표시·활성**

- **지금 축의 하위만 보여 준다** — 전 메뉴를 늘어놓지 않는다. 축을 넘나드는 이동은 대메뉴 띠(SCR-COM-002)가 맡는다.
- **접근 권한이 없는 항목은 목록에서 뺀다** — 보이되 막으면 "왜 안 되는지"를 물으러 오게 되고, 목록만 길어진다.
- **활성 표시를 사용자 선택으로 기억하지 않는다** — 화면에서 파생해야 주소로 직접 들어와도 맞는다. 색에만 싣지 않고 보조기술에도 전달한다.
- **좁은 화면 전환 시점을 대메뉴 띠와 맞춘다** — 두 크롬이 다른 폭에서 접히면 중간 폭에서 어색한 조합이 생긴다.

**메뉴에서 뺀 화면**

- **소속은 유지하되 목록에는 넣지 않는다** — 링크로 들어온 사용자가 그 축의 사이드바를 달고 도착해야 지금 어디에 있는지 알 수 있다. 소속까지 없애면 기본 축의 목록이 붙어 "왜 대시보드 메뉴가 보이지" 상태가 된다. 반대로 목록에 넣으면 뺀 것이 아니다.

**소속·근거**

- **메뉴 구성은 이 화면이 갖지 않는다** — 구조·순서·이름은 메뉴 정의 한 곳에서 관리한다. 화면이 자체 목록을 들고 있으면 메뉴가 개편될 때 그 화면만 옛 이름으로 남는다.
- **법령 근거를 붙이지 않는다** — 이동 수단은 법령이 명한 의무의 직접 이행 수단이 아니다. 규칙은 공통 근거 연계(SCR-COM-008)를 따른다.

## 7. 미결사항

없음. 표시 범위·권한 없는 항목 처리·활성 판정·머리글 신설 기준과 성격·머리글 깊이 제한·메뉴에서 뺀 화면의 소속·좁은 화면 전환 시점·메뉴 구성의 소속은 모두 §6에서 확정했다.

접근 권한에 따른 실제 노출 차단은 미결이 아니라 **본개발 구현 범위**이며, 규칙은 메뉴 관리(SCR-ADMIN-005 §6)에 정해져 있다.
