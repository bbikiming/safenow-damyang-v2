# 화면 정의서 — 전역 사이드바(LNB)

> 화면 ID: SCR-COM-003 · 화면 유형: 공통 크롬 · 기획 관점(v6) · 구현 정합 2026-08-11
> 판단이 필요했던 항목은 §6 정책에서 확정했습니다.

---

## 1. 화면 정보

| 항목 | 내용 |
|---|---|
| 화면 ID | SCR-COM-003 |
| 화면명 | 전역 사이드바(LNB) |
| URL 경로 | 전 화면 공통 — 특정 주소가 없다 |
| 상위 메뉴 | 공통/전역 |
| 화면 유형 | 공통 크롬 |

지금 있는 대메뉴 축의 **하위 화면 목록**을 왼쪽에 세로로 보여 준다. 업무가 여러 단계로 나뉘는 축(안전보건교육처럼 대상별·유형별로 갈리는 경우)이 있어 구분 머리글을 둔 3단 구조까지 지원한다. 구성은 중메뉴 목록 하나이며, 좁은 화면에서는 서랍으로 바뀐다. 어느 항목을 고를 수 있는지는 메뉴 관리(SCR-ADMIN-005)가 정한다.

---

## 2. 권한 정보

- 메뉴 접근·보기·수정은 시스템 관리의 메뉴 관리(SCR-ADMIN-005)와 권한 관리(SCR-ADMIN-006)에서 설정한다.
- 이 화면 정의서에서는 역할별 권한과 열람 범위를 별도로 정하지 않는다.
- **접근 권한이 없는 중메뉴는 목록에서 빠진다** — 보이되 막는 방식을 쓰지 않는다(§6).

## 3. 진입 / 이탈 경로 및 사용자 시나리오

| 구분 | 연결 화면 | 조건 / 트리거 |
|---|---|---|
| 진입 | 모든 화면 | 화면이 열릴 때 자동으로 붙는다 |
| 진입 | 헤더 메뉴 버튼 | 좁은 화면에서 서랍으로 연다(SCR-COM-001) |
| 이탈 | 각 중메뉴 화면 | 항목 선택 |

| 단계 | 사용자 행동 | 화면 반응 |
|:--:|---|---|
| 1 | 화면에 들어온다 | 그 축의 하위 목록을 보여 주고 지금 화면을 활성으로 표시한다 |
| 2 | 다른 중메뉴를 고른다 | 그 화면으로 이동하며 사이드바는 그대로 남는다 |
| 3 | 좁은 화면에서 메뉴를 연다 | 서랍이 덮으며 열리고, 항목을 고르면 닫힌다 |

### 분기 로직

- **대메뉴 축이 목록 내용을 정한다** — 사이드바는 지금 축의 하위만 보여 준다. 전 메뉴를 한 번에 늘어놓지 않는 이유는, 축을 넘나드는 일이 드물고 목록이 길어지면 지금 축 안에서 길을 잃기 때문이다.
- **구분 머리글이 있으면 3단이 된다** — 하위 항목이 성격별로 갈리는 축은 머리글을 두고 그 아래를 들여쓴다. 머리글은 이동 대상이 아니라 묶음 이름이다.
- **활성 표시는 화면에서 파생한다** — 주소로 직접 들어와도 맞는다. 상세 화면처럼 목록과 같은 축에 속하는 화면은 그 목록 항목을 활성으로 둔다.
- **폭에 따라 형태가 바뀐다** — 넓으면 고정 기둥, 좁으면 서랍이다. 서랍일 때는 뒤 화면을 덮는 가림막이 함께 나오고, 항목을 고르면 닫힌다.

### 예외·경계 시나리오

| 상황 | 화면 반응 |
|---|---|
| 접근 가능한 중메뉴가 하나뿐 | 그 하나만 그린다 — 목록 자체를 감추지 않는다 |
| 접근 가능한 중메뉴가 0건 | 그 대메뉴가 애초에 보이지 않으므로 이 상태에 도달하지 않는다(SCR-COM-002) |
| 상세 화면에 있음 | 그 상세가 속한 목록 항목을 활성으로 둔다 — 아무것도 활성이 아닌 상태를 만들지 않는다 |
| 서랍이 열린 채 항목 선택 | 이동하며 서랍을 닫는다 |
| 서랍이 열린 채 가림막 선택 | 이동하지 않고 닫는다 |
| 메뉴 사용 여부를 끔 | 접근 권한과 무관하게 목록에서 빠진다(SCR-ADMIN-005 §6) |

## 4. 화면 구성별 정리

### 4-1. 중메뉴 목록

- 구성: 아이콘 + 중메뉴 이름의 세로 목록. 성격이 갈리는 축은 **구분 머리글 + 들여쓴 항목**의 3단 구조.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 항목 선택 | 그 화면으로 이동한다 | 사이드바는 그대로 남는다 |
| 화면 진입 | 지금 화면(또는 그 상세가 속한 목록)을 활성으로 표시한다 | 주소로 직접 들어와도 맞다 |
| 구분 머리글 | 이동하지 않는다 | 묶음 이름일 뿐이다 |
| 접근 권한이 없는 항목 | 목록에서 뺀다 | 보이되 막는 방식을 쓰지 않는다 |

- 상태: 항목별 **활성 / 비활성**이며, 목록 전체로는 **2단 / 3단(구분 머리글 있음)** 두 형태를 갖는다. 빈 목록 상태는 존재하지 않는다.

### 4-2. 좁은 화면 서랍

- 구성: 헤더의 메뉴 버튼으로 여는 서랍 + 뒤를 덮는 가림막.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 메뉴 버튼 선택 | 서랍을 연다 | SCR-COM-001 |
| 항목 선택 | 이동하고 서랍을 닫는다 | — |
| 가림막 선택 | 이동하지 않고 닫는다 | — |
| 화면을 넓힘 | 서랍을 닫고 고정 기둥으로 돌아간다 | — |

- 상태: **닫힘 / 열림** 둘이며, 열려 있는 동안 뒤 화면은 가림막에 덮인다.

## 6. 정책

- **지금 축의 하위만 보여 준다** — 전 메뉴를 늘어놓지 않는다. 축을 넘나드는 이동은 대메뉴 띠(SCR-COM-002)가 맡는다.
- **접근 권한이 없는 항목은 목록에서 뺀다** — 보이되 막으면 "왜 안 되는지"를 물으러 오게 되고, 목록만 길어진다.
- **활성 표시를 사용자 선택으로 기억하지 않는다** — 화면에서 파생해야 주소로 직접 들어와도 맞는다.
- **구분 머리글은 이동 대상이 아니다** — 묶음 이름이므로 누를 수 없다. 누를 수 있게 하면 어디로 가는지 알 수 없는 항목이 생긴다.
- **좁은 화면 전환 시점을 대메뉴 띠와 맞춘다** — 두 크롬이 다른 폭에서 접히면 중간 폭에서 어색한 조합이 생긴다.
- **메뉴 구성은 이 화면이 갖지 않는다** — 구조·순서·이름은 메뉴 정의 한 곳에서 관리한다.
- **법령 근거를 붙이지 않는다** — 이동 수단은 법령이 명한 의무의 직접 이행 수단이 아니다. 규칙은 공통 근거 연계(SCR-COM-008)를 따른다.

---

## 7. 미결사항

없음. 표시 범위·권한 없는 항목 처리·활성 판정·3단 구조의 머리글 성격·좁은 화면 전환 시점·메뉴 구성의 소속은 모두 §6에서 확정했다.

접근 권한에 따른 실제 노출 차단은 미결이 아니라 **본개발 구현 범위**이며, 규칙은 메뉴 관리(SCR-ADMIN-005 §6)에 정해져 있다.
