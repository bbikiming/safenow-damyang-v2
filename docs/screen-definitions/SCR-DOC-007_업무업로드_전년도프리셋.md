두 가지 등록 경로를 한 정의서에 담는다.

- **업무 업로드** — 증빙 파일을 올리고 그 문서가 증빙하는 **업무단계를 여러 개** 고른다. 문서 하나가 여러 업무단계에 걸칠 수 있고, 업무단계 하나에 여러 문서가 걸릴 수 있다.
- **전년도 프리셋** — 지난 연도에 낸 문서의 업무단계 선택값을 새 연도로 가져오고, 전년도 첨부를 그대로 쓰거나 새 파일로 바꾼다.

둘 다 이행 목록 위에서 단계형 입력창으로 열리며, 한 시점에 창은 하나만 뜬다.

## 3. 진입 / 이탈 경로 및 사용자 시나리오

| 구분 | 연결 화면 | 조건 / 트리거 |
|---|---|---|
| 진입 | 이행 목록 | [업무 업로드] 또는 [전년도 프리셋 불러오기] |
| 진입 | 업무 목록 | [업무 업로드] |
| 진입 | 업무 업로드 1단계 | [전년도 문서에서 가져오기] — 프리셋으로 갈아탄다 |
| 이탈 | 이행 목록 | 저장 후 창이 닫히고 카드·진행률·상태가 즉시 갱신된다 |
| 이탈 | 업무 목록 | 저장한 문서가 새 줄로 나타난다 |

### 3-1. 업무 업로드

| 단계 | 사용자 행동 | 화면 반응 |
|:--:|---|---|
| 1 | 파일을 올린다 | 파일 이름·크기를 목록으로 보여 주고, 문서명이 비어 있으면 첫 파일 이름에서 확장자를 뗀 값으로 채운다 |
| 2 | 문서 정보를 채운다 | 보고일자는 기준연도 안의 날짜만 받는다. 담당부서·담당자는 조직도에서 고른다 |
| 3 | 같은 문서가 있으면 | 기존 문서에 파일을 더할지 새 문서로 만들지 고르게 한다 — 막지 않는다 |
| 4 | 할 일을 고른다 | 왼쪽에서 법정 의무를 고르면 오른쪽에 그 의무의 할 일이 나온다. 칸마다 검색창이 있고 여러 개를 고를 수 있다 |
| 5 | 확인한다 | 문서 정보와 함께 **단계마다 바뀌기 전 상태와 저장 후 상태**를 나란히 보여 준다 |
| 6 | 등록한다 | 창이 닫히고 고른 단계가 모두 진행중이 된다 |

### 3-2. 전년도 프리셋

| 단계 | 사용자 행동 | 화면 반응 |
|:--:|---|---|
| 1 | 창을 연다 | 원본연도와 대상연도를 밝히고, 복제하지 않는 값이 무엇인지 먼저 알린다 |
| 2 | 전년도 문서를 찾는다 | 문서명·이행항목·주기·보고월로 좁힌다 |
| 3 | 한 건을 고른다 | 그 줄 아래에 빠른 설정(문서명 처리·첨부 처리)이 열리고 아래 단추가 [1건 가져오기]가 된다 |
| 4 | 여러 건을 고른다 | 일괄 설정 막대가 뜨고 단추가 [N건 가져오기]가 된다. 예외가 있는 문서만 줄을 펼쳐 따로 고친다 |
| 5 | 가져온다 | 이미 가져온 적이 있으면 알리고, 만든 뒤 결과를 건수로 알린다 |

### 분기 로직

- **순서를 뒤집지 않는다** — 문서·파일 → 업무단계 선택 → 확인 순이다. 업무단계를 고르기 전에 저장할 수 없다.
- **할 일 선택은 하나의 긴 목록이나 접었다 펴는 묶음으로 두지 않는다** — 78개를 펼쳤다 접으면 원하는 것을 만나기까지 계속 굴려야 한다. 왼쪽에서 의무를 고르면 오른쪽에 그 의무의 할 일만 나오는 2단 구조로 낸다.
- **고른 값은 어디서도 잃지 않는다** — 검색어를 바꿔도, 앞 단계로 갔다 돌아와도 유지한다.
- **선택 요약은 항상 보인다** — 고른 단계 수와 이행항목 수, 고른 단계 목록을 아래에 고정하고 개별 해제와 전체 해제를 둔다. 긴 이름은 줄을 바꿔 보여 주고 말풍선에만 숨기지 않는다.
- **한 건과 여러 건을 다른 화면으로 나누지 않는다** — 같은 선택 목록에서 고른 수에 따라 아래 영역만 바뀐다.
- **전년도 프리셋은 가져올 연도가 실제로 있을 때만 제공한다** — 없으면 진입 자체를 만들지 않는다.

### 예외·경계 시나리오

| 상황 | 화면 반응 |
|---|---|
| 필수값 누락 | 상단 요약과 **필드 아래 오류**를 함께 내고 첫 오류 칸으로 초점을 옮긴다 |
| 기준연도와 보고일자의 연도가 다름 | 저장하지 않고 어긋났음을 그 칸에서 알린다 |
| 지원하지 않는 형식·용량 초과 | 거절 사유를 알리고 이미 넣은 다른 입력은 그대로 둔다 |
| 같은 제목·수발신자·보고일자의 문서가 있음 | 기존에 더하기와 새로 만들기 중에 고르게 한다 |
| 기존에 더할 수 없는 문서였음 | 새 문서로 만들고 **왜 그렇게 됐는지 알린다** — 조용히 다른 일을 하지 않는다 |
| 소속이 아닌 부서를 담당으로 지정 | 조직도에 그 부서를 열지 않고, 다른 경로로 시도해도 사유와 함께 막는다 |
| 업무단계를 하나도 고르지 않음 | 다음으로 넘어가지 않고 무엇이 필요한지 알린다 |
| 이미 완료된 단계를 다시 증빙 | 확인 단계에서 **되돌아갈 단계 수를 미리 알리고** 저장하면 진행중으로 되돌린다 |
| 작성 중 창을 닫으려 함 | 닫기·바깥 영역·[취소]·키보드 닫기 **모두** 같은 확인을 받는다 |
| 전년도 첨부가 없는 문서를 그대로 사용 | 만들되 원본 파일 확인 필요로 남기고 건수를 알린다 |
| 같은 원본을 같은 연도로 다시 가져옴 | 중복임을 알리고 되묻는다 — 조용히 쌓지 않는다 |

## 4. 화면 구성별 정리

### 4-1. 업무 업로드 1단계 — 문서·파일

| 구성 요소 | 필수 | 설명 |
|---|:--:|---|
| 파일 첨부 | ● | 여러 개. 형식·용량·개수는 공통 계약을 따른다 |
| 문서명 | ● | 첫 파일 이름에서 자동으로 채우고 고칠 수 있다 |
| 보고일자 | ● | 기준연도 안의 날짜만. 기준연도가 올해가 아니면 비워 두고 고르게 한다 |
| 수발신자 | | 외부 기관 또는 직위 |
| 담당부서 · 담당자 | ● | 조직도에서 고른다. 고를 수 있는 범위는 §6이 정한다 |
| 문서 출처 | | 기본은 직접 첨부 |
| 비고 | | |
| 전년도 문서에서 가져오기 | | 가져올 연도가 있을 때만 |

### 4-2. 업무 업로드 2단계 — 할 일 선택 (2단 선택기)

이 서류가 **어떤 의무의 무슨 일**을 했다는 증거인지 고른다. 업무 목록의 상세 조건과 **같은 선택기**를 쓴다.

| 구성 요소 | 설명 |
|---|---|
| 왼쪽 칸 | 법정 의무 목록. 위에 인라인 검색창, 아래 따로 스크롤. 항목마다 할 일 수와 이미 고른 수 |
| 오른쪽 칸 | 고른 의무의 할 일 목록. 위에 인라인 검색창, 체크박스 다중 선택 |
| 이 의무의 N개 모두 | 오른쪽 칸 위의 묶음 전체 선택 |
| 아래 | 고른 할 일을 칩으로. 개별 해제와 모두 지우기 |

의무를 고르기 전에는 오른쪽 칸이 무엇을 해야 하는지 안내한다. 검색어를 바꿔도, 다른 의무로 옮겨도 이미 고른 것은 유지된다.

### 4-3. 업무 업로드 3단계 — 확인

문서명·파일·보고일자·담당자·출처·기준연도를 되짚고, 이행항목별로 묶어 **업무단계마다 바뀌기 전 상태와 저장 후 상태**를 보여 준다. 완료였던 단계가 있으면 몇 개가 되돌아가는지 먼저 알린다. 저장 후 상태는 예외 없이 진행중이며, 완료는 주관부서 확인 뒤에만 붙는다는 것을 함께 적는다.

### 4-4. 전년도 프리셋

| 구성 요소 | 설명 |
|---|---|
| 안내 | 원본연도·대상연도와 **복제하지 않는 값**(진행상태·결재상태·보고일자·문서번호) |
| 조회 조건 | 문서명·수발신자·업무단계 통합검색, 이행항목, 주기, 보고월, 고른 것만 보기 |
| 문서 목록 | 선택칸·문서명·보고일자·수발신자·업무단계 수. 쪽을 넘겨도 선택은 유지된다 |
| 빠른 설정(1건) | 문서명 처리(그대로·연도 치환·직접 수정), 첨부 처리(그대로 사용·교체) |
| 일괄 설정(2건 이상) | 같은 두 축을 한 번에 적용하고, 예외 문서만 줄을 펼쳐 고친다 |
| 가져오기 | 고른 건수를 단추에 적는다 |

## 5. 유효성 검사

| 대상 | 규칙 | 위반 시 |
|---|---|---|
| 첨부 파일 | 한 개 이상 | 다음으로 넘어가지 않고 첨부 영역으로 초점을 옮긴다 |
| 문서명 | 공백 제거 후 비어 있지 않아야 한다 | 칸 아래에 오류를 낸다 |
| 보고일자 | 기준연도 안의 날짜 | 어긋난 사유를 그 칸에서 알린다 |
| 담당부서·담당자 | 지정해야 하며, 지정할 수 있는 부서여야 한다 | 고를 수 없는 부서는 조직도에 열지 않고, 저장 시에도 다시 막는다 |
| 중복 문서 | 제목·수발신자·보고일자가 모두 같으면 알린다 | 처리 방법을 고르기 전에는 다음으로 넘어가지 않는다 |
| 업무단계 | 한 개 이상 | 다음으로 넘어가지 않는다 |
| 프리셋 선택 | 한 건 이상 | 가져오기를 제공하지 않는다 |
| 프리셋 재실행 | 같은 원본·같은 대상연도는 이미 만든 것으로 본다 | 알리고 되묻는다 |
| 창 닫기 | 작성 중이면 확인을 받는다 | 확인 전에는 닫지 않는다 |

오류는 상단 요약과 필드 아래 문구를 함께 내고 첫 오류로 초점을 옮긴다. 단계가 바뀌면 초점을 새 본문으로 옮겨 키보드 사용자가 바뀐 화면을 놓치지 않게 한다.

## 6. 정책

**P1. 순서를 뒤집지 않는다.**
문서·파일 → 업무단계 선택 → 확인이다. 업무단계 없이 저장되면 그 문서는 어떤 의무의 증빙인지 알 수 없어 이행 현황에 들어가지 못한다.

**P2. 저장 직후 상태는 예외 없이 진행중이다.**
이 화면에 완료 처리 수단을 두지 않는다. 올린 사람이 스스로 완료로 만들 수 있으면 확인 절차가 뜻을 잃는다.

**P3. 완료된 업무를 고치면 진행중으로 되돌린다.**
파일이나 업무단계 연결이 바뀌면 확인의 근거가 바뀐 것이다. 되돌리기 전에 **몇 개 단계가 영향을 받는지 먼저 알린다**.

**P4. 문서에 적히는 담당부서·담당자는 소속 범위 안에서만 고른다.**
조회 범위와 다른 축이다. 다른 부서 사람의 이름으로 문서를 남기면 기록이 사실과 달라진다. 조직도는 처음부터 고를 수 있는 범위만 열고, 저장할 때 같은 판정으로 다시 막는다 — 화면에서 감추는 것만으로는 부족하다. 주관부서 담당자는 전 부서를 지정할 수 있고 그 밖의 담당자는 소속 부서만 지정한다.

**P5. 중복 가능성은 막지 않고 알린다.**
같은 제목의 문서가 다른 날짜로 반복되는 것이 이 업무의 정상이다. 자동으로 합치지 않고 기존에 더할지 새로 만들지 사용자가 고른다.

**P6. 창을 닫는 네 가지 길이 모두 같은 확인을 받는다.**
[취소]에만 확인을 걸고 닫기·바깥 영역·키보드 닫기를 열어 두면 그건 확인이 아니다. 반대로 아무것도 입력하지 않았으면 묻지 않는다.

**P7. 보고일자 기본값은 기준연도를 따른다.**
기준연도가 올해가 아니면 오늘 날짜를 채우지 않고 비워 둔다. 채워 두면 연도와 날짜가 어긋난 문서가 그대로 저장된다.

**P8. 전년도 프리셋의 원본연도는 자료에서 파생한다.**
대상연도에서 무조건 1을 빼지 않는다. 그렇게 하면 자료가 없는 해를 가리켜 목록이 0건인 창이 열린다. 대상연도보다 이전이면서 문서가 있는 가장 최근 연도를 쓰고, 없으면 진입 자체를 만들지 않는다.

**P9. 프리셋은 업무단계 선택값과 그로부터 파생되는 이행항목만 항상 복제한다.**
문서명·담당자·첨부는 사용자가 고른다. 전년도 진행상태·결재상태·보고일자·문서번호는 **복제하지 않는다** — 지난 해의 결과를 새 해의 실적으로 만들면 안 된다.

**P10. 가져온 문서의 담당자는 가져온 사람 본인이다.**
전년도 담당자를 그대로 옮기면 남의 이름으로 새 연도 문서를 만드는 것이 된다. P4와 같은 근거다.

**P11. 첨부를 그대로 쓰면 새 파일로 복사한다.**
전년도 파일을 계속 참조하지 않는다. 대상연도 저장소로 복사해 **새 파일 식별값**을 부여하고, 어느 파일에서 어느 해로 복사했는지 이력을 남긴다. 전년도 원본 파일과 원본 문서는 바꾸지 않는다.

**P12. 여러 건을 가져올 때 일부만 실패하면 성공한 것은 살린다.**
파일 하나가 없다고 문서를 만들지 않으면 사용자가 다시 처음부터 해야 한다. 문서는 만들고 문제가 된 파일만 원본 파일 확인 필요로 남긴다. 결과에 성공·주의·차단 건수를 각각 알린다.

**P13. 할 일 선택기는 업무 목록과 같은 것을 쓴다.**
같은 것을 고르는데 화면마다 모양이 다르면 담당자가 두 번 배운다. 2단 선택기 하나를 두 화면이 공유한다. 선택기가 든 창은 칸이 눌리지 않도록 넓게 연다.

**P14. 창은 한 번에 하나만 뜬다.**
단계 전환도, 프리셋 선택도, 조직도 선택도 같은 창 안에서 처리한다. 창 위에 창을 겹치지 않는다.
