# 화면 정의서 — 메뉴 근거 매핑

> 화면 ID: SCR-ADMIN-008 · 화면 유형: 기타(관리) · 기획 관점(v6)
> 확정이 필요한 항목은 §7 미결사항에 모았습니다.

## 1. 화면 정보

| 항목 | 내용 |
|---|---|
| 화면 ID | SCR-ADMIN-008 |
| 화면명 | 메뉴 근거 매핑 |
| URL 경로 | admin-law-map.html · admin-law-map.html?page={화면 id} |
| 상위 메뉴 | 시스템 관리 > 법령 관리 |
| 화면 유형 | 기타 (관리) |

**목적·설명** — 각 화면에 어떤 조문을 근거로 붙일지 지정하는 화면이다. 근거를 붙이려면 **검증 항목을 통과해야 저장되도록** 막는 것이 이 화면의 존재 이유인데(왜: 근거를 잘못 붙이면 시스템이 틀린 법조문을 주장하게 되고, 실제 점검에서 그런 결함이 반복해서 나왔다), 그래서 붙이기와 떼기를 비대칭으로 다룬다. 구성은 ① 판정 현황 요약 ② 화면 목록·상태 필터 ③ 반영 안 되는 매핑 ④ 근거 편집(판정·조문 목록·순서·역할) ⑤ 근거 추가 3단계(선택 → 원문 확인 → 검증) ⑥ 미리보기 6영역이다. 핵심 연계는 조문을 확인하는 법령·조문(SCR-ADMIN-007)에서 넘어와 여기서 붙이고, 붙은 결과가 전 화면 상단 근거 표시(SCR-COM-008)로 나타나는 흐름이다.

## 3. 진입 / 이탈 경로 및 사용자 시나리오

**진입 / 이탈**

| 구분 | 연결 화면 | 조건 / 트리거 |
|---|---|---|
| 진입 | 시스템 관리 좌측 메뉴 | [메뉴 근거 매핑] 선택 |
| 진입(딥링크) | 법령·조문(SCR-ADMIN-007) | 재검증 대상에서 이동 — 해당 화면이 선택된 상태로 열림 |
| 이탈 | 법령·조문 | 상단 [법령·조문] 링크 |
| 이탈 차단 | 현재 화면 유지 | 저장하지 않은 변경이 있으면 다른 화면으로 이동 시 확인을 받는다 |

**사용자 시나리오**

| 단계 | 사용자 행동 | 화면 반응 |
|:--:|---|---|
| 1 | 화면 진입 | 상단에 판정 현황 4분할(근거 있음·근거 없음(확정)·미판단·반영 안 됨)과 **진척률을 표시하지 않는 이유** 안내 |
| 2 | 좌측에서 화면 선택 | 우측에 그 화면의 적용 범위·판정·근거 목록 표시 |
| 3 | 적용 범위 확인 | 이 근거가 적용되는 화면 파일 목록. 여러 화면이 공유하면 그 사실을 강조 |
| 4 | 판정을 근거 있음/없음 중 선택 | 선택에 따라 아래 입력 영역이 바뀐다 |
| 5 | [+ 근거 추가] | 패널 안에서 3단계 진행 — 조문 선택 → **원문 확인** → 검증 항목 |
| 6 | 조문 선택 | 조문 원문 전체가 표시된다. 번호만 보고 붙이지 못하게 하는 단계 |
| 7 | 검증 항목 응답 + 판단 근거 입력 | 전부 만족하기 전까지 [근거 추가]가 비활성 |
| 8 | 근거 추가 완료 | 목록에 추가되고 검증 기록이 남는다 |
| 9 | 순서 조정·역할 지정 | 순서가 화면 표시 순서. 역할은 의무 근거 / 주기 근거 |
| 10 | 미리보기 확인 후 [저장] | 저장 후 적용 대상 화면 목록과 "새로 열 때 반영" 안내 |
| 11 | (근거 없음 선택 시) 사유 입력 후 [저장] | 사유 없이 저장하면 안내가 나오고 저장되지 않는다 |

**분기 로직**

- **판정 선택이 입력 영역을 바꾼다** — 근거 있음이면 조문 목록과 추가 버튼이, 근거 없음이면 사유 입력이 나타난다. **판정을 바꾸면 직전 판정에 딸린 값은 비워진다** — 안 비우면 근거 없음 사유가 근거 있음 매핑에 붙어 저장된다.
- **붙이기와 떼기가 비대칭이다** — 떼기는 과잉 주장을 줄이는 방향이라 즉시 가능하고, 붙이기는 결함이 나온 방향이라 검증 단계를 통과해야 한다.
- **반영 안 되는 매핑은 편집 대상이 아니다** — 어떤 화면도 그 화면 식별자를 쓰지 않는 경우이며, 화면에서 고칠 수 없어 별도 구역에 잠금 상태로 표시한다.

**엣지케이스**

- **한 근거가 여러 화면에 적용된다** — 목록 화면과 상세 화면이 같은 식별자를 공유하는 경우가 실재한다. 저장 전에 적용 대상을 반드시 보여준다. 목록과 상세는 하는 일이 다르므로 판단 시 유의가 필요하다.
- **근거를 지정해도 표시되지 않는 화면** — 화면에 제목 영역이 없으면 근거 표시가 나타나지 않는다. 이 사실을 경고로 밝히지 않으면 관리 화면이 거짓을 말하게 된다.
- **중복 추가** — 이미 있는 조문을 다시 추가하려 하면 안내하고 추가하지 않는다.
- **저장 없이 이동** — 변경 중 다른 화면을 고르면 확인을 받는다.
- **빈 저장** — 근거 있음인데 조문이 없거나, 근거 없음인데 사유가 없으면 저장되지 않는다.
- **검색·필터 결과 0건** — 조건에 맞는 화면이 없음을 알린다.

## 4. 화면 구성별 정리

### 4-1. 상단 — 판정 현황

- 구성: 근거 있음 / 근거 없음(확정) / 미판단 / 반영 안 됨 4분할 건수 + **진척률을 두지 않는 이유** 안내 + [법령·조문] 링크.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| [법령·조문] | 조문 대장 화면으로 이동 | admin-law.html |

- 상태: 4분할 건수는 항상 표시된다. **완료율·진척률 지표는 만들지 않는다** — 근거는 채울수록 좋은 것이 아니라 맞아야 하는 것이고, 과잉으로 붙여서 생긴 결함이 실제로 있었다.

### 4-2. 좌측 — 화면 목록

- 구성: 검색 입력 + 상태 필터(전체·근거 있음·근거 없음(확정)·미판단) + 화면 행(식별자·상태 배지·표시 불가 표기).

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 검색어 입력 | 화면 식별자·파일명으로 목록을 좁힘 | 결과 건수 표시 |
| 상태 필터 선택 | 해당 상태만 표시 | — |
| 화면 행 선택 | 우측을 그 화면의 편집 패널로 전환. 저장 안 된 변경이 있으면 확인 | — |

- 상태: **근거 있음 / 근거 없음(확정) / 미판단** 3종을 배지로 구분하고, 근거 표시가 불가한 화면은 별도 표기를 덧붙인다.

### 4-3. 좌측 — 반영 안 되는 매핑

- 구성: 매핑은 있으나 어떤 화면도 쓰지 않는 식별자 목록. **편집 잠금**.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 행 표시 | 선택 불가. 사유 안내 | "어떤 화면도 이 식별자를 쓰지 않습니다 — 개발 수정 필요" |

- 상태: **없음**(구역 자체가 나타나지 않음) / **있음**(건수와 목록).

### 4-4. 우측 — 근거 편집

- 구성: 적용 범위(적용 화면 목록) · 표시 불가 경고(해당 시) · 판정 선택 · 근거 조문 목록(순서·역할·제거) · [+ 근거 추가] · 저장/되돌리기 · 검증 기록 건수.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 판정 변경 | 입력 영역 전환 + 직전 판정 값 비움 | — |
| 순서 위/아래 | 화면 표시 순서 변경 | — |
| 역할 변경 | 의무 근거 / 주기 근거 지정 | — |
| [제거] | 목록에서 제거(저장 전) | — |
| [되돌리기] | 변경 내용 폐기 | "변경 내용을 되돌렸습니다" |
| [저장] | 검증 통과 시 저장 + 이력 기록 | 적용 대상 화면 목록과 "근거 표시는 해당 화면을 새로 열 때 반영됩니다" |
| [저장] (조문 0건·근거 있음) | 저장하지 않음 | "근거 조문이 없습니다. 근거 없음으로 확정하거나 조문을 추가하세요" |
| [저장] (사유 없음·근거 없음) | 저장하지 않음 | "근거 없음 사유를 적어주세요" |

- 상태: **변경 없음** / **저장 필요**(배지). 업무 단계상으로는 미판단 → 판정 → (근거 있음이면) 근거 지정 → 저장 순이며, 저장 이후에도 언제든 재판정할 수 있다.

### 4-5. 우측 — 근거 추가 3단계

- 구성: 패널 안에서 진행하는 3단계. **팝업을 띄우지 않는다** — 원문을 펼쳐 읽어야 하는 단계라 팝업 안에서 다시 펼치면 화면이 겹친다.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 1단계 조문 선택 | 2단계로 이동 | "조문을 고르면 원문을 먼저 보여줍니다" |
| 2단계 [원문을 확인했습니다] | 3단계로 이동 | — |
| 3단계 검증 항목 응답 | 전부 만족 + 판단 근거 입력 시에만 추가 버튼 활성 | 미충족 시 사유 안내 |
| [근거 추가] | 목록에 추가 + 검증 기록 저장 | "근거를 추가했습니다 — 검증 기록이 남았습니다" |
| [취소] | 추가 중단 | — |

- 상태: **1단계 선택 / 2단계 원문 확인 / 3단계 검증**. 검증 미충족 상태에서는 추가 버튼이 비활성이고 그 이유가 함께 표시된다. 검증 기록에는 **판단 당시의 조문 제목**이 함께 저장되어, 조문이 바뀌면 재검증 대상으로 잡힌다.

### 4-6. 우측 — 미리보기

- 구성: 지정한 근거가 대상 화면 상단에 어떻게 보이는지 그대로 표시.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 근거 목록 변경 | 미리보기가 즉시 갱신 | — |

- 상태: **근거 있음일 때만 표시**. 저장 전에 실제 표시 모양을 보는 것 자체가 잘못 붙이는 것을 막는 수단이다.

## 5. 유효성 검사

| 입력 항목 | 필수 | 형식/규칙 | 오류 안내 |
|---|---|---|---|
| 판정 | 필수 | 근거 있음 / 근거 없음(확정) 중 하나 | 미선택 상태로 저장 불가 |
| 근거 조문 | 근거 있음일 때 1건 이상 | 제공 목록에서 선택. 직접 입력 불가 | "근거 조문이 없습니다. 근거 없음으로 확정하거나 조문을 추가하세요" |
| 검증 항목 | 근거 추가 시 전 항목 필수 | 모두 확인해야 진행 | 미충족 시 버튼 비활성 + 사유 표시 |
| 판단 근거 | 근거 추가 시 필수 | 빈 값 불가 | 동상 |
| 근거 없음 사유 | 근거 없음일 때 필수 | 빈 값 불가 | "근거 없음 사유를 적어주세요" |
| 조문 중복 | — | 같은 조문 중복 추가 불가 | "이미 추가된 조문입니다" |

- **조문 직접 입력을 막는 것이 기획 의도다.** 자유 문자열을 허용하면 같은 조문이 화면마다 다르게 적히고, 조문이 개정돼도 아무도 알아채지 못한다.
- **검증을 통과 못 하면 저장 자체가 안 된다.** 경고 후 진행 허용이 아니라 하드 블록이다 — 경고만으로는 같은 결함이 반복된다는 것이 확인되었다.

## 6. 정책

- **붙이기와 떼기는 비대칭이다** — 근거를 떼는 것은 과잉 주장을 줄이는 방향이라 절차를 가볍게 두고, 붙이는 것은 결함이 나온 방향이라 검증을 강제한다.
- **판단 근거를 데이터로 남긴다** — 누가 언제 무엇을 보고 그렇게 판단했는지가 기록되지 않으면, 나중에 그 근거가 맞는지 다시 판정할 수 없다. 검증 기록에는 판단 당시의 조문 제목을 함께 남겨 조문 변경 시 재검증 대상으로 잡는다.
- **근거 없음도 판정이다** — 법령이 정한 의무가 아닌 화면(시스템 운영 기능)은 근거를 비우는 것이 정상이며, **사유를 남겨야 다음 담당자가 같은 검토를 반복하지 않는다**(SCR-COM-008 연계).
- **진척률을 만들지 않는다** — 완료율 지표는 담당자를 "채우는" 방향으로 민다. 근거는 많이 붙일수록 좋은 것이 아니라 맞아야 하는 것이고, 과잉 부착으로 생긴 결함이 실제로 있었다. 4분할 건수만 표시하고 행동 대상은 미판단뿐이다.
- **적용 범위를 저장 전에 보여준다** — 한 근거가 여러 화면에 동시에 적용되는 경우가 실재하므로, 저장 버튼을 누르기 전에 대상을 확인시킨다.
- **표시되지 않는 것을 숨기지 않는다** — 화면 구조상 근거 표시가 불가한 경우 그 사실을 경고한다. 관리 화면이 "지정했다"고만 말하고 실제로 안 보이면 그것이 곧 거짓말이다.
- **저장이 즉시 다른 화면에 반영되지 않는다** — 이미 열려 있는 화면의 근거 표시는 갱신되지 않으며, 그 사실을 저장 안내에 명시한다. 미리보기가 그 공백을 메운다.
