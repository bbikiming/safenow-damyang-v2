# 화면 정의서 — 프리셋 양식 관리

> 화면 ID: SCR-ADMIN-003 · 화면 유형: 목록 + 편집 · 기획 관점(v6) · 구현 정합 2026-08-12
> 판단이 필요했던 항목은 §6 정책에서 확정했습니다.

## 1. 화면 정보

| 항목 | 내용 |
|---|---|
| 화면 ID | SCR-ADMIN-003 |
| 화면명 | 프리셋 양식 관리(양식 빌더) |
| URL 경로 | admin-presets.html |
| 상위 메뉴 | 시스템 관리 > 프리셋 양식 관리 |
| 화면 유형 | 목록 + 편집 |

전자문서가 쓰는 **서식의 항목 구성을 관리하는** 화면이다. 서식을 화면마다 고칠 수 있게 두면 같은 업무의 문서가 자리마다 달라지고, 반대로 아무도 못 고치게 두면 업무가 바뀔 때 개발을 기다려야 한다. 그래서 서식 변경은 **이 한 곳**으로 모은다. 구성은 양식 목록과 항목 편집 두 덩어리이며, 여기서 정한 서식을 전자문서 폼(SCR-EDOC-001~007)이 그대로 쓴다.

---

## 2. 권한 정보

- 메뉴 접근·보기·수정은 시스템 관리의 메뉴 관리(SCR-ADMIN-005)와 권한 관리(SCR-ADMIN-006)에서 설정한다.
- 이 화면 정의서에서는 역할별 권한과 열람 범위를 별도로 정하지 않는다.
- 서식을 바꾸면 그 서식을 쓰는 전 부서의 문서가 달라지므로 **시스템 관리자만** 들어온다.

## 3. 진입 / 이탈 경로 및 사용자 시나리오

| 구분 | 연결 화면 | 조건 / 트리거 |
|---|---|---|
| 진입 | 시스템 관리 > 프리셋 양식 관리 | 메뉴 선택 |
| 진입 | 업무 등록·수정 | 새 양식 만들기 선택(SCR-DOC-007) |
| 이탈 | 업무 등록·수정 | 양식을 만든 뒤 되돌아간다 |
| 연계 | 전자문서 폼 | 여기서 정한 항목 구성을 그대로 쓴다(SCR-EDOC-001~007) |

| 단계 | 사용자 행동 | 화면 반응 |
|:--:|---|---|
| 1 | 화면에 들어온다 | 양식 목록과 각 양식의 항목 수·사용 현황을 보여 준다 |
| 2 | 양식을 고른다 | 항목 구성을 보여 준다 |
| 3 | 항목을 더하거나 고친다 | 항목 이름과 입력 형식을 정한다 |
| 4 | 저장한다 | 이후 작성되는 문서부터 반영된다 |

### 분기 로직

- **표준 양식과 사용자 양식이 다르다** — 표준 7종은 이 시스템이 제공하는 것이고, 사용자 양식은 담양군이 만든 것이다. **표준 양식의 항목 구성은 고치지 않는다** — 여러 업무가 공유하므로 한 곳을 고치면 관계없는 업무까지 바뀐다. 필요하면 복제해 사용자 양식으로 만든 뒤 고친다.
- **입력 형식이 항목의 성격을 정한다** — 형식에 따라 검증과 집계 가능 여부가 갈린다. 숫자로 받아야 집계할 수 있고, 글로 받으면 서술만 남는다. **쓸 수 있는 형식은 §4-2의 표로 고정**하며 이 목록 밖의 형식은 만들지 않는다 — 목록이 열려 있으면 「지원하지 않는 형식」을 판정할 기준이 없어져 아래 사용 차단이 작동하지 않는다.
- **이미 쓰인 양식은 함부로 못 바꾼다** — 그 양식으로 작성된 문서가 있으면 항목을 지울 때 이전 문서의 값이 갈 곳을 잃는다. 그래서 **지우지 않고 사용 중지**로 두며, 이전 문서는 그대로 남는다.
- **바꾼 결과는 앞으로 작성될 문서부터다** — 이미 작성된 문서를 소급해 바꾸지 않는다.

### 예외·경계 시나리오

| 상황 | 화면 반응 |
|---|---|
| 표준 양식을 고치려 함 | 막고 복제해 쓰도록 안내한다 |
| 이미 쓰이고 있는 양식의 항목을 지우려 함 | 지우지 않고 사용 중지로 바꾼다. **몇 건의 문서가 그 항목을 쓰고 있는지** 함께 밝힌다 |
| 아무도 쓰지 않는 양식 | 지울 수 있다 — 사용 0건임을 확인시킨 뒤 진행한다 |
| 항목 이름을 비운 채 저장 | 저장을 막는다 — 이름 없는 항목은 채우는 사람이 무엇을 적어야 하는지 모른다 |
| 같은 이름의 항목이 둘 | 경고한다 — 문서를 읽을 때 어느 값인지 구분되지 않는다 |
| 항목이 하나도 없는 양식 | 저장은 되지만 사용할 수 없음을 알린다 |
| 양식을 바꾼 뒤 | 이미 작성된 문서는 그대로 두고, 바뀐 시점을 함께 남긴다 |

## 4. 화면 구성별 정리

### 4-1. 양식 목록

- 구성: 양식명 · 대메뉴 · 항목 수 · 사용 현황 네 열.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 화면 진입 | 표준 양식과 사용자 양식을 함께 보여 준다 | 어느 쪽인지 구분해 표시한다 |
| 양식 선택 | 항목 편집으로 넘어간다 | 표준 양식은 보기만 된다 |
| 사용 현황 | 그 양식으로 작성된 문서 수를 보여 준다 | 지울 수 있는지 판단의 근거다 |
| [+ 양식 추가] | 새 사용자 양식을 만든다 | 표준 양식을 복제해 시작할 수 있다 |

- 상태: 양식마다 **표준 / 사용자**가 갈리고, 사용 축으로 **사용 중 / 미사용**이 덧붙는다. 사용 중인 양식은 항목 삭제가 제한된다.

### 4-2. 항목 편집

- 구성: 항목 이름 · 입력 형식 · 필수 여부 · 순서 · 사용 여부.

**입력 형식 목록(확정)** — 아래 열 가지가 전부다. 표준 양식(SCR-EDOC-001~007)이 실제로 쓰는 형식에서 뽑았고, 여기 없는 형식은 항목을 만들 수 없다.

| 입력 형식 | 무엇을 받는가 | 집계 | 형식별 검증 |
|---|---|---|---|
| 한 줄 글 | 장소·강사처럼 짧은 값 | 불가 | 길이 |
| 여러 줄 글 | 목표·결과 요약처럼 서술하는 값 | 불가 | 길이 |
| 숫자 | 대상 인원·출석 인원·정량 실적 | 가능 | 최솟값·최댓값의 앞뒤 정합 |
| 날짜 | 실시일·점검일·조치 기한 | 가능(기간) | 시작·종료의 앞뒤 정합 |
| 단일 선택 | 정해진 값 하나 | 가능 | 선택지 1개 이상 |
| 복수 선택 | 정해진 값 여럿 | 가능 | 선택지 1개 이상 |
| 점검 항목 | 항목별 적합·부적합 판정 | 가능 | — |
| 점수 항목 | 평가 항목별 평가값 | 가능 | 최솟값·최댓값 |
| 조직도 선택 | 담당부서·담당자·점검자·확인자 | 불가 | 조직도의 활성 부서·구성원 |
| 파일 첨부 | 증빙·회의 자료 | 불가 | 공통 계약의 첨부 규칙 |

- **조직도 선택을 목록에서 빼면 표준 양식이 막힌다** — 계획서의 담당부서·담당자, 점검표의 점검자, 조치보고의 확인자가 모두 이 형식이다. 지원 목록에 없으면 아래 「지원하지 않는 형식이 있으면 양식 사용을 막는다」 규칙이 표준 양식 세 종을 사용 불가로 만든다.
- **집계 가능 여부는 형식이 정한다** — 같은 값을 글로 받으면 나중에 셀 수 없다. 나중에 세야 하는 값인지를 항목을 만들 때 정하는 것이지, 문서가 쌓인 뒤에 바꿀 수 있는 것이 아니다.
- **점검 항목·점수 항목을 글로 대신하지 않는다** — 부적합 판정은 개선조치로 이어지고 점수는 합산되므로, 글로 받으면 그 다음 단계가 성립하지 않는다.
- **형식 이름은 다른 정의서와 같은 말을 쓴다** — 점검표·평가서가 이미 「점검 항목」·「점수 항목」이라 부르는 것을 여기서 다른 이름으로 부르면, 같은 것을 두 이름으로 배우게 된다.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 항목 추가 | 이름과 입력 형식을 정한다 | 이름을 비우면 저장하지 않는다 |
| 입력 형식 선택 | 그 형식에 맞는 검증이 따라붙는다 | 숫자로 받아야 집계할 수 있다 |
| 순서 변경 | 문서에 나오는 차례를 바꾼다 | 이미 작성된 문서에는 영향이 없다 |
| 항목 사용 중지 | 이후 문서에서 빠지고 이전 문서는 남는다 | 지우지 않는다 |
| 사용 중인 항목 삭제 시도 | 막고 사용 건수를 밝힌다 | 사용 중지로 안내한다 |
| 표준 양식에서 편집 시도 | 막고 복제를 안내한다 | — |

- 상태: 항목마다 **사용 / 중지**이며, 양식 전체로는 **편집 가능(사용자 양식) / 보기 전용(표준 양식)**이 갈린다. 항목 0건인 양식은 저장은 되되 사용할 수 없다.

## 6. 정책

- **서식 변경을 이 한 곳으로 모은다** — 화면마다 고칠 수 있게 두면 같은 업무의 문서가 자리마다 달라진다.
- **표준 양식은 고치지 않는다** — 여러 업무가 공유하므로 한 곳을 고치면 관계없는 업무까지 바뀐다. 복제해 쓴다.
- **쓰이고 있는 항목을 지우지 않는다** — 사용 중지로 둔다. 지우면 이전 문서의 값이 갈 곳을 잃고, 그 문서를 다시 열었을 때 무엇을 적었는지 알 수 없다.
- **바꾼 결과를 소급하지 않는다** — 이미 작성된 문서는 그때의 서식으로 작성된 것이다. 바뀐 시점을 함께 남겨 왜 문서마다 항목이 다른지 설명할 수 있게 한다.
- **집계할 값은 숫자로 받는다** — 입력 형식이 곧 그 값을 나중에 셀 수 있는지를 정한다. 글로 받으면 서술만 남는다.
- **항목 이름 없는 항목을 만들지 않는다** — 채우는 사람이 무엇을 적어야 하는지 모른다.
- **양식은 식별값과 버전을 함께 가진다** — 양식 식별값은 바꾸거나 재사용하지 않고, 저장할 때 양식명·적용 메뉴·정렬된 항목·입력 형식·필수 여부·선택지·검증 규칙·사용 상태를 한 버전으로 묶는다. 편집을 열면 이름만이 아니라 그 버전의 항목 구성 전체를 불러온다.
- **작성 문서는 사용한 양식 버전을 보존한다** — 양식을 바꾼 뒤에도 기존 문서는 당시 항목·순서·선택지를 그대로 보여 준다. 현재 양식으로 다시 해석하지 않는다.
- **삭제와 사용중지를 구분한다** — 한 번도 사용하지 않은 사용자 양식만 확인 후 삭제할 수 있다. 사용 이력이 있는 양식·항목은 사용중지하고 새 문서 선택 목록에서만 제외한다. 표준 양식은 복제만 허용한다.
- **등록 폼 연결은 입력 형식으로 검증한다** — §4-2의 확정 목록에 있는 형식만 활성화할 수 있다. 선택형은 선택지 1개 이상, 숫자·날짜·점수 항목은 범위의 앞뒤 정합을 검사하며, 지원하지 않는 형식이 있으면 양식 사용을 막고 항목명을 알린다. **형식 목록은 §4-2 한 곳에만 둔다** — 정책과 화면 구성에 목록을 각각 적으면 둘이 갈라지고, 갈라진 순간 무엇을 막아야 하는지 알 수 없게 된다.
- **법령 근거를 붙이지 않는다** — 양식 관리는 법령이 명한 의무가 아니라 시스템 운영 기능이다. 서식이 담는 **내용**의 근거는 그 서식을 쓰는 업무 화면에 붙으며, 규칙은 공통 근거 연계(SCR-COM-008)를 따른다.

## 7. 미결사항

없음. 양식 저장 구조·편집 전체 로드·버전 보존·삭제와 사용중지·등록 폼 매핑·표준 양식의 편집 가능 여부·입력 형식과 집계의 관계·항목 이름 필수·근거의 소속은 모두 §6에서 확정했다.
