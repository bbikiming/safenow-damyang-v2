# 화면 정의서 — 의견청취

> 화면 ID: SCR-OPN-001(의견청취·건의함) · SCR-OPN-002(산업안전보건위원회) · SCR-OPN-003(협의체·점검표) · 화면 유형: 목록·등록·상세(건의함) / 목록·상세·등록(위원회) / 목록·상세·등록(협의체) · 기획 관점(v6)
> 판단이 필요했던 항목은 §6 정책에서 확정했습니다.
> 2026-10-07 온나라 공문 회신 반영 — 이 메뉴에서 상신하는 것은 **협의체 점검결과지** 하나이고 협의체 운영 결과는 상신하지 않는다 · 결재 상태는 연계 회신으로만 바뀌고 반송을 더했다(§4-C-2·§6). 상신 경로 분류의 정본은 공통 권한 정의 §7-4 다.
> 본 정의서는 의견청취가 **독립 대메뉴(GNB)로 승격**되고 처리 흐름이 **민원처리형(단일 흐름 CTA)** 으로 개편된 프로토타입 v2의 현재 구현 상태를 기준으로 하며, 하위 3개 화면(의견청취·건의함 / 산업안전보건위원회 / 협의체·점검표)을 한 문서로 정의한다.
> v1.4 (2026-11-18): **처리 단순화** — 재난안전과가 그 의견 안에서 혼자 닫는다. 처리 3택 = **조치 진행**(조치 부서·조치 계획) / **바로 완료** / **반려**, 조치중 건은 **[조치 완료] = 조치 결과 + 증빙 파일(필수)**. 부서와 주고받는 일은 공문·메신저로 하고 결과는 파일로 남긴다 — 부서 담당자는 등록·조회만 한다. 상태는 접수대기 → 조치중 → 완료(+반려), 현장점검(점검중)은 조치 계획에 적는다. 점검결과지 미흡 문항도 같은 방식(여러 문항 한 번에 완료). 운영 구현 요청: `docs/planning/전달-개발-의견청취-조치처리단순화-20261118-v1.md`.
> v1.3 (2026-11-17, v1.4로 대체): **개선조치를 만들지 않는다(A안)** — 개선조치는 위험성평가 소관이라, 의견 처리의 «개선조치 바로 생성»과 점검결과지 미흡 문항의 «개선조치 자동 연계»를 걷고 **담당 부서 조치 요청 → 조치 결과 → 재난안전과 확인**으로 그 건 안에서 끝낸다. 처리·관리 권한과 조회 범위를 화면과 진입 함수 양쪽에 걸었다(§6).
> v1.2: 프로토타입 대조 검수 반영 — 점검결과지 미흡 문항의 담당부서·기한 지정과 종합 결과 자동 산출, 재처리 시 연동 초기화, 사진 첨부 제한, 반려 확인 절차 등을 현행화하고 화면-고유 판단 항목을 §6에서 확정. §6 중 "(개발 반영)" 표기는 확정 기획이나 현재 프로토타입에 아직 반영되지 않은 항목이다.

**목적·설명** — 종사자 의견 청취 절차(중대재해처벌법 시행령 제4조제7호)와 산업안전보건위원회 운영(산업안전보건법 제24조), 도급 시 안전·보건 협의체 운영·점검(산업안전보건법 제64조)을 하나의 대메뉴(3개 화면)에서 통합 관리하며, 조치가 필요한 건은 재난안전과가 조치 부서·계획을 적고 조치 결과와 증빙 파일로 의견 건 안에서 끝낸다(안전점검·개선조치를 따로 만들지 않는다 — 개선조치는 위험성평가 소관이다).

- **의견청취·건의함**: 종사자 의견을 온라인·오프라인으로 접수하고, 접수대기 → 조치중 → 완료(+반려)의 민원처리형 흐름으로 처리·회신한다. 처리는 재난안전과 담당자가 하고, 부서와 주고받은 결과는 증빙 파일로 남긴다.
- **산업안전보건위원회**: 위원 구성, 의결 안건의 부서별 이행 현황, 회의록(작성·확정)을 관리한다.
- **협의체·점검표**: 협의체 위원 구성·운영 주기·운영 결과를 기록하고, 용역/구매설치/위탁사업/기타 구분의 점검결과지를 생성·결재한다.

메뉴 구조 변경 이력: 기존 "안전보건관리체계 > 의견청취(화면 내 3서브탭)" 구조에서 **GNB 대메뉴 + SNB 3화면**으로 승격되었다. 화면 내부 서브탭 바는 제거되었고 좌측 메뉴가 그 역할을 대신한다. 기존 주소(menu.html?m=opinion)로 진입하면 의견청취·건의함이 기본 표시된다(하위호환).

데이터는 세션 메모리에 보관되어 화면 이동 간 유지되며, 전체 새로고침 시 초기 예시 데이터로 리셋된다(프로토타입).

**분기 로직**

- **접수한 의견을 어떻게 처리할지 고르면 경로가 갈린다** — 조치 진행이면 `조치중`, 바로 완료면 `완료`, 조치가 필요 없다고 판단하면 `반려`가 된다. 다른 메뉴에 점검·개선조치를 만들지 않는다.
- **조치중 건은 재난안전과의 [조치 완료]로 끝난다** — 조치 결과와 증빙 파일이 있어야 완료된다. 부서가 시스템에서 결과를 올리거나 재난안전과가 확인하는 단계는 없다(부서와는 공문·메신저로 주고받고 그 결과를 파일로 남긴다).
- **접수 경로가 온라인과 오프라인으로 갈린다** — 오프라인 건은 담당자가 대신 등록하며, 접수 이력에 경로가 함께 기록된다. 처리 흐름 자체는 두 경로가 같다.
- **상태에 따라 처리 카드에 나오는 수단이 달라진다** — 접수대기에는 처리 방법 선택, 조치중에는 경과 추가·계획 수정·조치 완료, 완료·반려에는 결과 표시와 재처리가 나온다. 재난안전과 담당자가 아니면 버튼 대신 «처리는 재난안전과 담당자가 합니다»(조치 부서 담당자에게는 «조치 결과는 공문·메신저로 재난안전과에 회신해 주세요»)를 보인다.
- **이력은 사용자가 쓰는 것이 아니라 쌓이는 것이다** — 접수·조치 진행·계획 수정·완료·반려·재처리가 처리한 계정 이름으로 자동 기록되고, 사람이 직접 넣는 항목은 경과 추가(파일 선택) 하나뿐이다. 완료 이력에는 증빙 파일이 함께 남는다.

| E8 | 전체 새로고침 | 세션 메모리 데이터가 초기 예시로 리셋되는 것은 프로토타입 차이다. 본개발에서는 등록·수정·처리결과를 영속 저장하고 새로고침 뒤에도 동일 상태를 복원한다 |

## 4. 화면 구성별 정리

### 4-A. 의견청취·건의함 (SCR-OPN-001)

#### 4-A-1. 상태별 카운트 바
- 구성: [전체 N] [접수대기 N] [조치중 N] [완료 N] — 상태별 건수 버튼. **반려 건은 카운트 바에 별도 버튼이 없고**(전체 건수에는 포함) 목록의 상태 필터로 조회한다.

| 트리거 | 동작 결과 |
|---|---|
| 상태 버튼 클릭 | 목록이 해당 상태로 필터링(현재 선택 강조). [전체] 클릭 시 해제 |

- 상태: 건수는 현재 데이터 기준으로 실시간 집계된다.

#### 4-A-2. 의견 목록
- 구성: 검색 입력(제목·작성자, 입력 확정 또는 Enter 시 적용) + 분류/상태/부서 필터(부서에는 '미배정' 포함 — 처리 전 건) + 목록 표 + 페이지네이션(총 건수·현재 범위 표시) + [+ 의견 등록].
- 컬럼: 분류(칩) · 제목 · 작성자 · 조치 부서(처리 전 «-») · 등록일 · 상태(칩, 조치중 건은 «n일째» — 조치 진행을 저장한 날부터 · 알림 없음).

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 행 클릭 | 상세 진입 | 4-A-4 |
| [+ 의견 등록] | 등록 폼 전환 | 4-A-3 |
| 검색·필터 변경 | 즉시 목록 갱신, 1페이지로 이동 | 0건 시 빈 상태 문구(E7) |

- 상태: 목록 → 상세 → 목록 복귀 시 필터·페이지 유지. 각 행의 업무 단계상태는 접수대기 → 조치중 → 완료(+반려) 칩으로 표시.

#### 4-A-3. 의견 등록 폼 (온·오프라인 병행)
- 구성: 등록자 정보(로그인 계정·소속 부서 자동 표시) / 의견 정보(분류 필수, 접수경로 온라인·오프라인, 제출자, 발생장소(글자수 카운터), 제목 필수(카운터)) / 상세 내용 필수(카운터) / 사진 첨부(드래그 영역, **JPG·PNG·GIF만, 최대 10MB·최대 5장** 안내). 오프라인에서는 `등록 담당자`와 실제 `제출자`가 다르므로 두 값을 같은 작성자로 표시하지 않는다.
- 접수경로 표시는 `온라인(본인 등록) / 오프라인(담당자 대리)`다. 온라인은 SSO 로그인 사용자 성명·부서를 자동 입력하고 제출자 입력을 잠근다. 오프라인(서면·구두) 접수는 재난안전과 담당자가 접수경로를 바꾼 뒤 제출자명을 입력해 대리 등록한다 — 그 밖의 사람에게는 오프라인 선택지가 없다. 온라인·오프라인 모두 익명 접수는 제공하지 않는다.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| [등록하기] | 목록 최상단에 접수대기로 추가 + 담당자 접수 통지 알림(§6) + 이력에 "접수" 자동 기록 | "의견이 등록되었습니다" (오프라인이면 "담당자 대리 등록" 병기) |
| 접수경로 변경 | 온라인이면 SSO 사용자 자동 입력·잠금, 오프라인이면 제출자 직접 입력으로 전환 | 오프라인 제출자 미입력 시 저장 차단 |
| [취소] / [‹ 목록] | 저장 없이 목록 복귀 | |
| 사진 첨부 영역 | 프로토타입은 안내 표시로 대체 | |

- 상태: 신규 등록 건의 초기 상태는 접수대기, 조치 부서는 비어 있다(처리할 때 재난안전과가 정한다).

#### 4-A-4. 의견 상세 — 2:1 배치
좌측: ① 의견 정보 카드(분류·상태 칩, 제목, 작성자/경로, 작성일, 조치 부서, 발생장소, 상세내용, 첨부 사진) + ② 처리 카드. 우측: ③ 처리 이력 + ④ 조치 정보.

**② 처리 카드 — 상태별 4개 화면** (헤더에 "현재 상태" 칩 상시 표시)

| 상태 | 안내 배너 | 본문 구성 | 버튼 / 저장 동작 |
|---|---|---|---|
| 접수대기 | "접수 대기 중 — 의견을 검토하고 처리 방법을 선택하세요." (재난안전과 담당자가 아니면 "재난안전과 담당자가 검토해 처리합니다."만 보인다) | 처리 방법 3택 선택 카드: **조치 진행**(조치 부서 필수(공용 조직도·부서) · 조치 계획 필수(의견 제목 미리 채움) · 조치 예정일 선택(오늘 이후)) / **바로 완료**(조치 부서 선택 · 조치 결과 필수 · 완료일 필수(기본 오늘, 오늘 이전) · 증빙 파일 필수) / **반려**(사유 필수, "반려 사유가 기록되며, 되돌리려면 재처리해야 합니다" 경고). 선택 시 해당 폼만 펼침 | [저장] — 미선택 시 비활성. 조치 진행 → 조치중 + 조치 부서 안내 알림 / 바로 완료 → 완료 + 작성자 회신 / 반려 → 확인창 후 반려 + 작성자에게 사유 안내 |
| 조치중 | "조치 진행 중 — ○○과와 공문·메신저로 처리하고, 끝나면 결과와 증빙 파일을 올려 완료합니다." | 조치 부서 · 조치 계획 · 조치 예정일(지나면 «예정일 지남») · 진행(시작일 · n일째) | 재난안전과 담당자: [경과 추가](내용 + 파일 선택) · [계획 수정](조치 부서·계획·예정일 — 바꾸기 전 값은 이력에, 부서가 바뀌면 새 부서에 안내 알림) · **[조치 완료]**(조치 결과·완료일·증빙 파일 필수 → 완료 + 작성자 회신). 그 밖: 누가 하는지 한 줄 |
| 완료 | "처리 완료 — 조치 결과와 증빙이 기록되었습니다." | 완료일 · 처리자 · 조치 부서 · 조치 결과 · 증빙 파일(내려받기) | [재처리] — 재난안전과 담당자만. 확인 후 접수대기로 복귀(E4) |
| 반려 | "반려 처리됨 — 반려 사유가 기록되었습니다." | 반려 사유 박스 | [재처리] — 재난안전과 담당자만 |

- 증빙 파일 칸은 공용 업로드 칸, **일반 증빙 프로필**(12종 · 파일당 20MB · 최대 10개)이다. 부서 회신 공문 · 조치 전후 사진 · 점검 기록 등을 올린다.

**③ 처리 이력** — 세로 타임라인. 접수/조치 진행/계획 수정/경과/완료/반려/재처리가 단계 칩 + 내용 + 처리자 + 일시(연-월-일 시:분)로 자동 누적된다. 경과·완료에 붙은 파일은 그 줄에서 내려받는다. 사용자가 직접 입력하는 항목은 "경과 추가"뿐이다.

**④ 조치 정보** — 처리 전에는 "처리 방법을 정하면 표시됩니다" 빈 상태. 처리 후 조치 부서·조치 계획·예정일(완료면 조치 결과·증빙 건수). 다른 메뉴로 가는 버튼은 두지 않는다. 재처리 시 빈 상태로 복귀.

### 4-B. 산업안전보건위원회 (SCR-OPN-002)

- 상단 통계: [올해 회의 개최 N회] [안건 이행 N/N건] [이행 지연 N건]. "올해 회의 개최"는 현재 전체 회의록 수를 집계하고 있어 당해 연도 기준 집계로 정리한다(§6, 개발 반영).
- 화면 내 탭 3개: **[위원 구성] [안건 부서이행] [회의록]** — 탭 전환 시 해당 영역만 표시(탭 상태는 화면 내 유지).

#### 4-B-1. 위원 구성 탭
- 구성: 위원 표(구분·부서·직책·성명·관리) + "근로자·사용자 대표 동수 구성(산안법 §24)" 안내.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| [+ 위원 추가] / [수정] | 모달 — 구분 선택 + 조직도에서 위원 선택(부서·직책·성명 자동 입력) | "위원이 추가/수정되었습니다". 노사 위원 수가 다르면 동수 권고 안내 |
| [삭제] | 확인 후 삭제 | "위원이 삭제되었습니다" |

- 상태: 위원 목록에 별도 단계상태 없음. 노사 동수 여부는 저장 시점에 참고 안내로만 알린다(차단 아님).

#### 4-B-2. 안건 부서이행 탭
- 구성: 의결 안건 표(안건·담당부서·이행기한·이행상태 진행/완료/지연·관리).

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| [+ 안건 추가] / [수정] | 모달 — 의결 안건 필수, 담당부서(조직도 선택) 필수, 이행기한, 이행상태 | "안건 이행 현황이 추가/수정되었습니다" |
| [삭제] | 확인 후 삭제 | |

- 상태: 안건별 이행상태(진행/완료/지연)가 칩으로 표시되고 상단 통계에 집계된다.

#### 4-B-3. 회의록 탭
- 구성: 회의록 표(회차·유형·일시·참석 인원·주요 안건·상태 작성/확정) — 행 클릭 시 상세.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| [회의록 작성] / 상세 [편집] | 작성 폼 — 회차 필수(신규 시 기본값 제공), 유형(정기/수시), 일시, 장소, 주요 안건, 참석자(조직도에서 클릭 즉시 추가·재클릭/× 제외, 인원 수 실시간 표시), 의결사항(행 추가/삭제), "의결사항을 안건 부서이행 현황에 등록" 체크 | 저장 시 상세로 이동. 연계 체크 시 "의결사항 N건이 안건 부서이행 현황에 등록되었습니다" |
| 폼 [취소] | 저장 없이 회의록 목록 복귀(입력 소실) | |
| 상세 [확정 처리] | 확인창 후 상태 확정, 편집·확정 버튼 숨김 | "확정된 회의록입니다 — 편집할 수 없습니다" 안내 |

- 상태: 회의록 단계상태는 작성 → 확정(비가역). 편집 저장 시 기존 확정 상태는 유지된다(작성 상태에서만 편집 진입 가능).

### 4-C. 협의체·점검표 (SCR-OPN-003)

- 상단 통계: [점검결과지 N건] [미흡 N건] [결재 대기 N건].
- 화면 내 탭 2개: **[협의체 운영] [점검표]**(탭 상태는 화면 내 유지).

#### 4-C-1. 협의체 운영 탭

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| [+ 위원 추가]/[수정]/[삭제] | 4-B-1과 동일 패턴(동수 안내 없음) | |
| [주기 변경] | 모달 선택 → 저장 | "운영 주기가 변경되었습니다" |
| [+ 운영 결과 등록]/[수정] | 모달 — 회차 필수·일자·참석·논의 내용·결과 요약·상태 | "협의체 운영 결과가 등록/수정되었습니다" |

#### 4-C-2. 점검표 탭 (점검결과지 생성·조회·수정·삭제)
- 구성: 점검결과지 표(점검 구분·점검일·점검자·결과 적합/미흡(미흡 건수 병기)·온나라 결재 상태·조회/수정/삭제) + [+ 점검결과지 생성]. 수정·삭제 버튼은 미상신·반려 상태에서만 노출.
- 점검 구분 4종: **용역 / 구매설치 / 위탁사업 / 기타**.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| [+ 점검결과지 생성] / [수정] | 모달 — 점검 구분, 점검일, 표준 문항별 확인/미흡/해당없음 3택. **문항에서 "미흡" 선택 시 해당 문항 아래로 조치 부서(공용 조직도)·조치 계획 입력 행이 펼쳐진다** | 등록 시 "점검결과지가 등록되었습니다 — 미흡 N건 조치중". 미흡 문항마다 조치 부서·계획을 문항에 두고 그 부서에 안내 알림(할 일 아님). 개선조치를 만들지 않는다. 수정 저장 시 끝나지 않은 문항은 부서·계획이 그대로 따라가고, **조치를 완료한 문항은 미흡·조치 부서를 바꿀 수 없다**("N번 문항은 조치를 완료해…") |

## 6. 정책

- **등록과 처리는 주체가 다르다** — 의견 등록은 종사자 전원이 하는 것이 전제다(전원이 낼 수 없으면 의견청취가 성립하지 않는다). 접수 이후의 처리 일체는 재난안전과 담당자가 한다. 종사자·부서 담당자에게는 처리 수단을 노출하지 않는다.
- **상태 용어 표준(2026-11-18)**: 접수대기 → 조치중 → 완료 (+반려). 목록 필터·카운트 바·상태 칩·처리 카드가 동일 용어를 사용한다. 종전 `점검중`·`개선조치중`은 `조치중`으로 합쳤다 — «개선조치»는 위험성평가 메뉴 이름이라 같은 말을 쓰지 않는다. 반려는 카운트 바에 별도 표기하지 않고 상태 필터로 조회한다.
- **민원처리형 단일 흐름**: 처리 방법 선택은 접수대기 상태에서만 가능하다. 조치중에는 경과 추가·계획 수정·조치 완료만 제공하고, 완료/반려는 [재처리]로만 되돌린다. 재처리 시 처리 카드의 조치 정보는 비워지고 지난 내용은 이력에 남는다.
- **완료 신호(2026-11-18)**: 조치중 건은 재난안전과 담당자가 조치 결과와 **증빙 파일**을 올려 [조치 완료]할 때 완료된다. 증빙 파일 없이는 완료되지 않는다 — «완료라고 적고 빠져나가는» 일을 막고, 반기 점검(중처법 시행령 §4 7호) 때 이행 근거가 된다. 조치가 필요 없었던 건은 반려로 닫는다. 다른 메뉴의 상태로 자동 전이하지 않는다.
- **이력 자동 기록**: 접수·조치 선택·경과·완료·반려·재처리 등 모든 전이가 처리 이력에 자동 기록된다(일시·처리자 포함).
- **안전점검·개선조치를 만들지 않는다 — 재난안전과가 의견 안에서 닫는다(2026-11-18, A안 대체)**: 개선조치는 위험성평가(정기·수시) 소관이고 평가 진행률·완료 확인·결과 공문 판정이 그 개선조치를 센다. 의견·점검결과지 건을 거기 넣지 않는다. 2026-11-17 A안(부서 결과 등록 → 재난안전과 확인·보완 요청)은 한 건에 두 사람이 4~5번 시스템에 들어와야 해서 걷었다 — 의견청취는 건수가 적고 급하지 않아 부서와의 주고받기는 공문·메신저로 하고, 시스템에는 그 결과(회신 공문·사진)를 **파일로** 남긴다. 중처법 시행령 §4 7호가 요구하는 것은 의견 · 개선방안(조치 계획) · 이행 결과(증빙)가 한 건 안에 남는 것이다. 평가가 필요한 건(위험신고 등)을 수시 위험성평가로 넘기는 연결은 두지 않았다(필요하면 별도 결정).
- **권한 — 화면과 진입 함수가 같은 판정(2026-11-18)**: 의견 등록(온라인)은 전 직원. 처리 일체(처리 선택·조치 완료·계획 수정·경과·반려·재처리)·오프라인 대리 등록은 재난안전과 담당자. 위원회·협의체 기록·점검결과지 생성·수정·삭제·상신·미흡 문항 조치 완료는 재난안전과 담당자. 부서 담당자는 등록·조회만 한다(조치 결과는 공문·메신저로 회신). 관리·감독 계층(군수·과장·소장)은 조회만 한다. 할 수 없는 사람에게는 버튼을 내지 않고 누가 하는지를 밝힌다.
- **조회 범위(OPN-05 반영)**: 전 부서 범위(재난안전과·군수)가 아니면 의견 목록·상세에 **우리 부서가 조치 부서인 건과 내가 낸 건**만 보인다 — 신고자 실명이 다른 부서에 보이지 않게 한다. 카운트 바도 같은 범위로 센다.
- **점검결과지 종합 결과 자동 산출**: 미흡 문항이 1건이라도 있으면 「미흡」, 없으면 「적합」. 점검자가 임의로 종합 결과를 정할 수 없다.
- **결재 문서 보호**: 점검결과지는 결재중/승인완료 상태에서 수정·삭제가 잠긴다(편집 가능 상태는 미상신·반려·반송). 승인완료 문서는 반려 후 수정하고, 반려·반송 문서는 보완 후 재상신한다.
- **이 메뉴에서 상신하는 것은 협의체 점검결과지 하나다(2026-10-07)** — 도급관리의 «도급사업 점검표»(SCR-SBM-004)와 다른 화면이므로 이름을 섞지 않는다. **협의체 운영 결과는 상신하지 않는다** — 「산업안전보건법 시행규칙」 제79조제3항은 협의체가 매월 1회 이상 회의하고 «그 결과를 기록·보존»하도록만 정하며 결재를 요구하지 않는다.
- **점검결과지의 결재 결과는 사람이 옮겨 적지 않는다(공통 권한 정의 §7-4)** — 결재 결과가 후속 업무를 열지 않는 도메인이라 수동 기록 수단을 두지 않고, 온나라가 보낸 결재완료·반려·반송은 그대로 반영한다. 상신 직후에는 문서번호(생산등록번호)가 아직 없어 «연계 번호»로 보인다. 온나라로 보내는 것은 결과지 지면이고 **공문 붙임은 없다**. 공개구분은 연계 값으로 **공개**를 넘긴다(임시 기본값, `99_미결사항목록` §5 EXT-21).
- **조치 부서**: 접수 시 조치 부서는 비어 있고, 재난안전과 담당자가 조치 진행(필수)·바로 완료(선택) 때 공용 조직도에서 부서로 고른다. 사람(조치 담당자)·기한은 받지 않는다 — 부서 안에서 누가 하는지는 그 부서가 정하고, 재난안전과는 부서와 공문·메신저로 주고받는다. 조치 부서를 정하면 그 부서 담당자(없으면 부서장)에게 **안내 알림**을 보낸다(내 할일에 넣지 않는다).
- **온·오프라인 접수 규칙(확정)**: 온라인은 로그인된 종사자가 SSO 실명으로 직접 등록하며 작성자·부서는 자동 입력하고 수정할 수 없다. 오프라인 서면·구두 의견은 의견청취 주관 부서 담당자가 제출자 실명을 입력해 대리 등록하고 접수경로를 `오프라인`으로 남긴다. 익명 접수는 회신·처리 이력의 당사자를 확인할 수 없으므로 이번 범위에서 제공하지 않는다.
- **현장점검은 조치 계획에 적는다(2026-11-18)**: 별도 안전점검 건을 만들지 않는다(종전 «현장점검 실시 → 안전점검 자동 생성»은 걷었다). 점검 일정은 조치 계획에, 점검 결과는 조치 완료의 결과와 증빙 파일(사진·점검 기록)에 남긴다. 완료 신호가 두 곳에서 생기는 일이 없다.
- **알림 시점·대상(확정)**: ① 접수 시 재난안전과 담당자에게 접수 통지 ② 조치 진행·조치 부서 변경 시 그 부서 담당자에게 안내(할 일 아님) ③ 완료 시 작성자에게 결과 회신 ④ 반려 시 작성자에게 사유 안내 ⑤ 접수 후 7일 경과 미처리(접수대기 유지) 건은 재난안전과 담당자에게 재알림(개발 반영). 조치중 경과일은 목록 «n일째»로만 보이고 알림을 보내지 않는다. 발송 채널은 아래에서 확정했으며, 프로토타입은 발송 안내로 시뮬레이션된다.
- **위원회 통계 집계 기준(확정, 개발 반영)**: "올해 회의 개최"는 당해 연도 회의록만 집계한다(현재는 전체 회의록 수 집계).
- **회의록 의결사항 연계 기본값(확정)**: 연계 등록 시 안건의 담당부서는 주관 부서, 이행기한은 회의일 기준 1개월로 자동 부여하고, 부서·기한 조정은 안건 부서이행 탭의 [수정]으로 한다.
- **데이터 보존 계약(OPN-12 확정)**: 의견·위원회·협의체의 본개발 데이터는 서버에 영속 저장한다. 상태 전이·조치 부서 변경·결재·첨부 교체는 수정 전 값을 덮어쓰지 않고 행위자·시각·사유가 있는 추가 이력으로 남긴다. 삭제 UI는 두지 않고 잘못 등록한 건은 취소 상태와 취소 사유로 보존한다. 현재 프로토타입의 세션 메모리·새로고침 초기화는 시연 한계일 뿐 본개발 계약이 아니다.

- **처리 주체는 주관 부서 담당자이고, 확정·승인은 결재선이 한다(OPN-01 확정)** — 처리 선택·조치 완료·반려·재처리 같은 처리 일체는 그 의견을 받은 **주관 부서(재난안전과)의 담당자**가 한다. 관리·감독 계층은 조회만 하며, 이는 다른 도메인의 조작 권한 규칙과 같다 — 담당자 이름으로 대신 처리하면 그것은 기록의 위조다. 다만 **회의록 확정과 점검결과지 상신은 부서 결재선**을 탄다. 처리는 실무이고 확정은 책임이라 주체가 다르다.
- **온라인 접수를 구축한다(OPN-05 확정)** — 프로토타입처럼 종사자가 로그인 상태에서 직접 등록하며 SSO 실명·부서를 자동 기록한다. 별도 QR 공개 접수나 익명 접수는 만들지 않는다. 오프라인은 주관 부서 담당자가 실명으로 대리 등록해 같은 처리 흐름으로 합친다. 신고자 식별정보는 처리 담당자와 주관 부서만 열람하고, 통계·일반 목록에는 필요한 경우 마스킹해 실명 접수의 신고 위축을 줄인다.
- **점검결과지 문항은 4구분 공통을 유지한다(OPN-06 확정)** — 용역·구매설치·위탁사업·기타로 문항을 나누지 않는다. 공통 문항으로 두면 구분이 애매한 사업(용역이면서 설치를 포함하는 계약이 실제로 많다)에서 어느 문항지를 쓸지 다투지 않아도 되고, 구분별로 집계를 나눠 볼 수 있다. **구분별 특수 문항이 필요하면 공통 문항 뒤에 덧붙이는 방식**으로 확장한다 — 문항지를 통째로 갈라 놓으면 구분이 바뀔 때 앞서 받은 답을 옮길 수 없다.
- **결재선을 코드에 고정하지 않는다(OPN-07 확정)** — 회의록 확정·점검결과지 상신의 결재권자는 안전보건 법령이 아니라 **지자체 위임전결규칙** 소관이라 조직 개편·규칙 개정으로 바뀐다. 기본값(기안자 부서의 팀장 → 부서장)만 조직도에서 파생하고, 변경은 조직도 선택기로 받는다. 이는 다른 도메인의 결재선 규칙과 같다.
- **결재선은 기안 → 검토 → 결재 3단계이고 서로 다른 계정이어야 한다(2026-08-27 확정)** — 상신은 결재선 전체를 **한 번에** 온나라로 넘기므로(호출기안) 한 계정이 두 단계에 들어가면 결재선이 성립하지 않는다. 규칙과 판정은 공통 권한 정의 §7 이 정본이며 전 도메인이 같은 형태를 쓴다.
  - **결재선을 코드에 고정하지 않는다** — 결재권자는 지자체 위임전결규칙 소관이라 조직 개편·규칙 개정으로 바뀐다. 기본값만 조직도에서 직위명으로 파생하고 변경은 조직도 선택기로 받는다.
  - **위반은 고르는 단계에서 먼저 막는다** — 기안자와 이미 지정된 사람은 조직도에서 사유와 함께 고를 수 없게 표시하고, 상신 경로에서 다시 확인한다.
  - **결재선은 이름이 아니라 계정 식별자로 보관한다** — 온나라 결재선이 계정 식별자 배열이고, 동명이인·개명에 어긋나지 않아야 한다.

- **알림은 시스템 내부 알림으로 시작한다(OPN-08 확정)** — 발송 시점·대상은 이미 확정돼 있고 남은 것은 채널이다. **내부 알림을 기본으로 하고 외부 채널(문자·알림톡)은 붙이지 않는다** — 외부 발송은 비용·개인정보 처리·수신 동의가 얽혀 별개 결정이 필요하고, 의견청취는 마감이 촉박한 업무가 아니라 내부 알림으로 충분하다. 행정포털 알림 영역에 함께 띄우는 것은 연계가 열리면 검토한다.
- **부서별 별도 관리는 조회 조건으로 충족한다(OPN-09 확정)** — 도급사업의 의견을 부서별로 나눠 보라는 요구는 **데이터를 부서마다 따로 쌓으라는 뜻이 아니라 부서 단위로 확인할 수 있어야 한다는 뜻**이다. 부서를 조회 조건으로 두고 부서별 건수·처리 현황을 집계로 내면 충족된다. 부서마다 별도 목록을 만들면 부서를 넘나드는 의견(공동 도급 현장)을 어디에 둘지 정할 수 없고, 부서 개편 때 통째로 옮겨야 한다.
- **유해·위험요인 신고·개선제안은 이 화면의 기존 분류가 수용한다(SFR-019)** — `위험신고`는 유해·위험요인 신고, `안전제안`은 개선 제안이며 별도 중복 메뉴를 만들지 않는다. 접수 건수·추진결과 등록 기준 조치완료율은 현황 통계(SCR-RPT-001)에서 같은 원본을 집계한다.
- **재처리는 완료·반려 건에서만, 재난안전과 담당자가 한다(OPN-10 · 2026-11-18 개정)** — 다른 메뉴에 남는 조치가 없으므로 재처리하면 처리 카드의 조치 부서·계획·결과·파일이 비워지고 접수대기로 돌아간다. 지난 처리 내용과 파일은 처리 이력에 그대로 남는다. 조치중 건은 재처리 대상이 아니다 — 계획 수정으로 고친다.
- **점검결과지를 고치면 미흡 문항 조치도 다시 맞춘다(OPN-11 · 2026-11-18)** — 새 미흡 문항은 조치중으로 생기고, 끝나지 않은 문항은 조치 부서·계획을 고치거나 미흡을 풀면 조치가 사라진다. **조치를 완료한 문항은 미흡·조치 부서를 바꿀 수 없다** — 올린 결과·증빙이 소리 없이 사라지지 않게 한다.

## 7. 미결사항

없음. 처리 수행 주체·온라인 접수 채널·점검결과지 문항 구성·결재선 규칙·알림 채널·부서별 관리 범위·처리 단순화(재난안전과 단독 처리·증빙 파일 필수)·재처리·점검결과지 수정 시 재연계·영속 저장과 정정 이력은 모두 §6에서 확정했다.
