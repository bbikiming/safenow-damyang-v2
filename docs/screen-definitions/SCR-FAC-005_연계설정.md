# 화면 정의서 — 연계 설정

> 화면 ID: SCR-FAC-005 · 화면 유형: 설정 · 기획 관점(v6)
> 판단이 필요했던 항목은 §6 정책에서 확정했습니다.
>
> **메뉴 제외 화면 (2026-09-03)** — 이 화면은 대메뉴·좌측 메뉴에 나오지 않는다. 시설물 관리(구 기본정보) 대메뉴는 **시설물 대장·시설물 위험도 2화면만** 두기로 확정했다. **대체 화면은 없다** — 연계 조건(인증·수신주기·필드 소유권·공통코드 매핑)을 바꾸는 자리가 남아 있지 않다. 연계가 지금 어떤 상태인지는 시스템 관리 > 연계 관리(SCR-ADMIN-004)에서 본다.
> 정의서를 남기는 이유는 화면과 주소가 그대로 살아 있기 때문이다 — 아래 §3~§7은 그 화면에 도착한 사용자가 만나는 동작의 정의로 계속 유효하다. 메뉴 구조 규칙은 SCR-COM-002 §6·SCR-COM-003 §6이 정한다.

**목적·설명** — FMS와 주고받는 조건을 한곳에서 정하고, **어떤 정보를 누가 갖는지**와 **코드 값을 어떻게 읽을지**를 밝혀 두는 화면이다. 자동 현행화(제안요청서 SFR-002)는 "얼마나 자주 받을 것인가"와 "받은 값이 무엇을 덮어써도 되는가"가 정해져야 성립하는데, 이 두 규칙이 화면마다 흩어지면 대장이 조용히 어긋난다. 그래서 연계 조건을 이 화면 한 곳에 모으고, 실제 주고받는 작업은 FMS 연계(SCR-FAC-004)가 맡는다. 화면은 ① 인증·수신 조건 ② 필드 소유권 규칙 ③ 공통코드 매핑 ④ 초기화 4개 영역으로 구성한다. 여기서 정한 소유권 규칙이 시설물 상세(SCR-FAC-002)의 읽기 전용 구획과 편집 가능 구획을 가르는 근거가 된다.

- 연계 조건 저장과 초기화는 §3~§6의 업무 흐름과 상태 전이 조건을 따른다.

**사용자 시나리오**

| 단계 | 사용자 행동 | 화면 반응 |
|:--:|---|---|
| 1 | 연계 설정 진입 | 인증·수신 조건, 소유권 규칙, 공통코드 매핑, 초기화 4개 영역이 표시됨 |
| 2 | 기관코드·사용자 확인 | 현재 값이 입력칸에 채워져 있음. 인증키 입력칸은 없고 그 이유가 안내로 표시됨 |
| 3 | 일 배치 수신을 "사용"으로, 실행 상한을 조정 | 상한 옆에 허용 최대 횟수가 안내로 표시됨 |
| 4 | [설정 저장] | "연계 설정 저장됨" 안내. 값이 유지됨 |
| 5 | 필드 소유권 규칙 확인 | FMS가 갖는 정보와 우리가 갖는 정보가 좌우로 나뉘어 표시됨 |
| 6 | 공통코드 매핑 확인 | 개발자 가이드가 적어 둔 값과 실제 받은 값이 나란히 놓이고 판정이 붙어 있음 |
| 7 | [초기화] | 확인 팝업이 열리고 무엇이 사라지는지 안내됨 |
| 8 | 확인 팝업에서 [초기화] | "초기화되었습니다" 안내 후 화면이 처음 상태로 다시 표시됨 |
| 9 | 확인 팝업에서 [취소] | 아무것도 바뀌지 않고 팝업만 닫힘 |

**분기 로직**

- **일 배치 수신을 "미사용"으로 두면 자동 수신이 일어나지 않는다** — 이때 대장 갱신은 FMS 연계 화면에서 사람이 실행하는 경로만 남는다. 다만 현재 프로토타입은 "사용"으로 두어도 정해진 시각에 스스로 받아 오지 않는다(§4-1 상태).
- **자동 승인요청을 "사용"으로 두면 전송할 때 승인 요청이 함께 나간다** — 실제 전송 흐름과의 연결은 안내 수준이며 확정된 동작은 §6에 있다.
- **초기화는 두 단계로 분기한다** — 버튼을 눌렀다고 곧바로 지워지지 않고 확인 팝업을 한 번 거친다. 팝업에서 취소하면 아무 변화가 없다.
- 소유권 규칙과 공통코드 매핑에는 분기가 없다. 두 영역은 값을 고르는 곳이 아니라 **현재 적용 중인 규칙을 밝혀 두는 곳**이다.

**엣지케이스**

- 설정을 저장하지 않고 화면을 벗어나면 고치던 값은 반영되지 않는다. 저장 전 이탈에 대한 확인은 없다(§6 확정).
- **초기화는 되돌릴 수 없다.** 확인 팝업에서 사라지는 대상(대장·보완입력·연계 이력)을 명시하지만, 지운 뒤 복구하는 수단은 없다.
- 실행 상한에 허용 최대치를 넘는 숫자를 넣어도 현재는 막지 않는다(§6 확정).
- 소유권 규칙·공통코드 매핑은 화면에서 고칠 수 없으므로, 규칙이 바뀌면 화면 표시도 함께 갱신되어야 한다(§6 확정).

## 4. 화면 구성별 정리

### 4-1. FMS 인증 · 수신 조건

- 구성: 기관코드 · 사용자 ID · 일 배치 수신(사용/미사용, 사용 시 실행 시각 표시) · 1일 실행 상한(허용 최대 횟수 안내 병기) · 자동 승인요청(사용/미사용) · 자격증명 미입력 안내 · [설정 저장].

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 값 입력·선택 | 화면에만 반영(저장 전) | — |
| [설정 저장] | 입력한 조건을 저장 | "연계 설정 저장됨" |

- 상태: 저장 전(고치는 중) / 저장됨 두 상태를 가지며, 저장 후에도 화면은 그대로 머문다. **일 배치 수신을 "사용"으로 두어도 프로토타입에서는 정해진 시각에 스스로 받아 오지 않는다** — 조건을 보여 주는 단계이고 실제 자동 실행은 실서비스 몫이다. 이 사실을 화면에 밝혀야 "자동인 척"이 되지 않는다(§6 확정). 인증키·비밀번호는 입력칸 자체를 두지 않고 그 이유를 안내로 표시한다.

### 4-2. 필드 소유권 규칙

- 구성: 좌우 2단이되 오른쪽은 **두 부류로 갈라 적는다**(2026-08-13).

| 구분 | 항목 | 규칙 |
|---|---|---|
| **FMS 소유** (읽기 전용) | 대장 기본현황 항목 전부 + 반영키 | 받을 때 갱신, 정정은 수정 전송으로만 |
| **연계 전 임시 입력** (추가 연계 시 FMS 소유로 이관) | 안전등급(점검진단실적) · 점검일(점검진단계획·실적) · 중대결함(중대결함사후관리) · 규모(상세제원) | FMS 규격에는 있으나 이번 수신분(시설물관리대장 기본현황)에 0건이라 직접 받는다. 수신이 붙으면 입력란을 닫고 직접 입력값은 대조용으로 보관 |
| **담양군 관리** (FMS 규격 밖) | 소관부서 · 관리담당자 · 이용인원 · 좌표 · 중대재해대상 구분 | 계속 자체 관리. **추가 연계 요청 대상이 아니다** |

- **가운데 줄과 아래 줄을 한 덩어리로 묶지 않는다** — 종전에는 둘을 '자체 소유' 하나로 적어, 원래 FMS 소관인 네 축까지 담양군 데이터로 읽혔다. 2026-08-13 FMS 추가 연계 요청 검토에서 실제로 그렇게 읽혀 **요청 목록에서 네 축이 통째로 빠질 뻔했다.** 이 표가 곧 추가 연계 요청 목록의 출처이므로 구분이 틀리면 요청이 틀린다.
- **'자체 소유'라는 이름을 쓰지 않는다** — 그 말은 원래 소유권 선언이 아니라 *"수신 반영이 이 칸을 건드리지 않는다"*는 덮어쓰기 방지 규칙의 이름이었다. 두 개념이 한 단어를 쓰고 있어 생긴 오독이므로 규칙 이름과 소유권 표기를 분리한다.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 화면 진입 | 현재 적용 중인 소유권 구분을 표시 | — |

- 상태: 표시 전용이라 빈 상태·오류 상태가 없다. 이 규칙은 세 화면의 동작을 동시에 결정한다 — 시설물 상세(SCR-FAC-002)에서 어느 구획이 읽기 전용인지, FMS 연계(SCR-FAC-004)에서 무엇을 비교 대상으로 삼는지, 수신 반영이 어떤 항목을 건드리지 않는지가 모두 여기서 나온다. **추가 연계로 안전등급·점검이력을 FMS에서 받게 되면 그 항목은 자체 소유에서 FMS 소유로 옮겨진다** — 그때 이 표도 함께 바뀐다(§6 확정).

### 4-3. 공통코드 매핑

- 구성: "FMS 최신 공통코드 규격 미수신" 표시 + 4개 열 표(코드 · 보유 가이드 값 · 실제 받은 값 · 판정) 3행 — 시설물 구분/종류, 시설물 종별, 설계도서 보존 여부.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 화면 진입 | 보유 가이드 값과 실제 값의 차이를 나란히 표시 | 표 제목 옆에 최신 규격 미수신 표시 |

- 상태: 표시 전용이다. **보유 가이드가 오래되어 실제 받은 값과 어긋난 상태**를 숨기지 않으며, 최신 규격을 수신하면 판정 칸이 "확인 완료"로 바뀐다. 수신 전 검증은 보유 가이드와 실제 파일 값을 비교해 알 수 없는 코드를 격리하고, 자동으로 잘못 매핑하지 않는다. 확인 불가를 뜻하는 임시 문자열은 빈 값이 아니라 "코드 미매핑" 상태로 보존한다(§6 확정).

### 4-4. 초기화

- 구성: 안내 문구(대장·보완입력·이력을 처음 받은 상태로 되돌린다) + [초기화]. 실행 시 확인 팝업(사라지는 대상 명시 + [취소]·[초기화]).

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| [초기화] | 확인 팝업 열림 | 대장·보완입력·연계 이력이 사라진다는 안내 |
| 확인 팝업 [초기화] | 처음 받은 상태로 되돌리고 화면을 다시 표시 | "초기화되었습니다" |
| 확인 팝업 [취소] | 아무 변화 없이 팝업 닫힘 | — |

- 상태: 대기(버튼만 노출) → 확인 중(팝업) → 실행됨 세 단계다. 실행 후에는 대장이 처음 받은 상태로, 보완입력은 처음 들어 있던 시연용 값만 남은 상태로, 이력은 최초 수신 기록 한 건만 남은 상태로 되돌아간다. **되돌리기 수단은 없다.** 시연을 반복할 때 데이터가 쌓여 발표가 어긋나는 것을 막기 위한 기능이므로, 실서비스에서도 같은 형태로 둘지는 §6에서 확정했다.

## 6. 정책

- **자격증명은 화면에서 받지 않는다** — 인증키·비밀번호 입력칸을 아예 만들지 않고, 등록은 별도 보안 절차로 넘긴다. 권한으로 가리는 것과 기능을 두지 않는 것은 다르며, 여기서는 후자를 택했다.
- **소유권 규칙은 한 곳에서만 정한다** — 어떤 정보를 FMS가 갖고 어떤 정보를 우리가 갖는지는 이 화면이 단일 출처다. 화면마다 따로 판단하면 같은 항목이 어디서는 읽기 전용, 어디서는 편집 가능이 되어 수신 한 번에 값이 사라진다.
- **소유권은 옮겨질 수 있다** — 지금은 안전등급·점검이력·중대결함·규모를 우리가 직접 채우지만, 이는 해당 연계업무를 아직 받지 않았기 때문이다. 추가 연계가 붙으면 그 항목은 FMS 소유로 옮겨지고 직접 입력은 닫힌다.
- **그래서 '옮겨질 항목'과 '계속 우리 것'을 표에서부터 갈라 놓는다** — 옮겨질 항목을 계속 우리 것과 같은 칸에 적어 두면, 그 목록을 보고 추가 연계를 요청할 사람이 요청 대상을 빼먹는다. 소유권 이관 가능성은 각주가 아니라 **분류 축**이어야 한다.
- **소유권 목록은 화면에서 바꾸지 않는다(FST-02 확정)** — 이 목록은 담당자가 정하는 값이 아니라 **연계 규격이 정하는 사실**이다. 화면에서 바꿀 수 있게 하면 담당자가 "여기 값이 틀렸으니 우리가 고치자"며 FMS 소유 항목을 자체 소유로 돌려놓고, 다음 수신에서 그 값이 통째로 덮인다. 표시만 하고 변경은 규격 반영(코드 배포)으로만 한다.
- **소유권이 옮겨질 때 직접 입력값을 지우지 않는다(FST-02 확정)** — 항목이 FMS 소유로 넘어가면 입력란은 닫히되, 그때까지 담당자가 채운 값은 **"직접 입력값"으로 따로 보관**한다. 수신값과 다르면 상세 화면에 둘을 나란히 드러내 어느 쪽이 맞는지 확인하게 한다 — 조용히 덮으면 담당자가 현장에서 확인해 넣은 값이 오래된 FMS 값으로 되돌아가도 아무도 모른다. 확인이 끝나면 직접 입력값은 이력으로만 남는다.
- **코드 값을 가이드만 믿고 확정하지 않는다** — 개발자 가이드 판이 오래되어 실제 받은 값과 어긋나는 항목이 있다. 어긋남을 감추지 않고 표로 드러낸다. **확정 방법은 정해져 있다(FST-07 확정) — 가이드가 아니라 실제 수신 데이터에 나타난 값을 정본으로 삼는다.** 우리가 받는 것은 FMS가 실제로 보내는 값이지 문서에 적힌 값이 아니기 때문이다. 수신 데이터에 없는 코드는 목록에 두되 "미출현"으로 표시하고, 가이드에 없는데 수신에 나타난 코드는 **임시 이름을 지어 붙이지 않고 코드 값 그대로** 노출한다 — 지어 붙인 이름은 나중에 진짜 이름이 오면 두 이름이 도는 원인이 된다. 확인 불가를 뜻하는 임시 문자열도 정리하지 않고 그대로 드러낸다. 코드가 확정되기 전에는 코드에 기대는 조회 조건·검증 규칙을 고정하지 않는다.
- **수신 주기와 실행 상한은 연계 규격이 정한 범위 안에서 정한다** — 하루에 받을 수 있는 횟수에 상한이 있으므로 임의로 늘리지 않는다. 자동 현행화를 어느 범위까지 사람 확인 없이 진행할지는 FMS 연계(SCR-FAC-004 §6)에서 함께 정한다.
- **초기화는 시연·점검용 기능이다** — 담당자가 쌓은 보완입력을 한 번에 지우고 되돌릴 수단이 없다. 그래서 버튼 한 번으로 실행되지 않고 사라지는 대상을 명시한 확인 단계를 반드시 거친다. **실서비스에서는 이 기능을 두지 않는다(FST-08 확정)** — 확인 절차를 아무리 겹쳐도 되돌릴 수 없는 전체 삭제는 언젠가 실행된다. 시연·점검 환경에서만 노출하고 운영 환경에서는 화면 자체에 나타나지 않게 한다. 운영에서 데이터를 되돌려야 하는 상황은 초기화가 아니라 **백업 복원**으로 처리한다 — 전자는 전부 지우는 것이고 후자는 특정 시점으로 돌리는 것이라 필요한 일은 언제나 후자다.
- **막는 검증과 알리는 검증을 구분한다(FST-03 확정)** — 저장을 **막는 것**은 ① 기관코드·사용자 ID가 비어 있는 경우 ② 하루 실행 상한이 연계 규격의 허용 범위를 벗어난 경우 — 둘 다 그대로 저장하면 연계 자체가 실패하거나 상대 시스템에 부담을 준다. 그 밖(수신 주기가 이례적으로 잦거나 뜸한 경우 등)은 **경고만 하고 저장은 허용**한다. 설정 화면에서 지나치게 막으면 담당자가 값을 조정하지 못해 결국 연계를 꺼 버린다.
- **저장하지 않고 나가면 확인을 받는다(FST-05 확정)** — 설정은 항목 수가 적어 무엇을 고쳤는지 잊기 쉽고, 고친 줄 알았는데 안 고쳐진 상태가 다음 수신까지 이어진다. 자동 저장은 두지 않는다 — 연계 조건은 저장하는 순간부터 실제 동작이 달라지므로 사람이 의도를 확인한 시점에만 반영돼야 한다.
- **자동 승인요청은 전송의 승인 단계만 바꾼다(FST-04 확정)** — 이 설정이 켜져 있으면 우리 쪽에서 보낸 대장 수정·삭제가 FMS에서 **승인 대기 없이 즉시 반영**되도록 요청한다. 우리 시스템의 확인 단계(SCR-FAC-002 §6)는 그대로이며 이 설정이 그것을 건너뛰지 않는다. **승인 결과는 연계 이력(SCR-FAC-004 §4-3)에서 확인**한다 — 전송 건마다 성공·대기·거부 상태가 남는다. 기본값은 **꺼짐**이다 — 외부 정본이 우리 조작만으로 즉시 바뀌는 상태를 기본으로 두지 않는다.
- **자동 수신은 배치가 실행하고, 프로토타입은 조건만 저장한다(FST-06 확정)** — 화면이 정해진 시각에 스스로 도는 것이 아니라 **서버 배치가 이 설정을 읽어 실행**한다. 화면은 조건(주기·하루 상한·기관코드)을 저장하고 마지막 실행 결과를 보여줄 뿐이다. 이 구조는 법령 수집 배치와 같다 — 화면이 외부 시스템을 직접 호출하지 않는다. 실패 통지 대상은 시설물 담당자와 시스템 관리자 두 축이며, 통지 수단은 시스템 알림이다. **프로토타입에 자동 실행이 없다는 사실을 화면에 밝힌다** — 숨기면 "자동인 척"이 된다.
- **설정 변경 내역을 연계 이력에 남긴다(FST-09 확정)** — 수신 주기나 상한이 바뀌면 그 뒤의 수신 동작이 전부 달라지는데, 이력에 없으면 "왜 이때부터 안 받아졌지"를 되짚을 방법이 없다. 방향은 수신·전송과 구분해 **설정 변경**으로 남기고, 바뀐 항목의 이전 값과 이후 값을 함께 적는다.
- **법령 근거를 붙이지 않는다** — 연계 조건 설정은 법령이 명한 의무 이행 행위가 아니다. 근거 없음을 명시하며 규칙은 공통 근거 연계(SCR-COM-008)를 따른다.

---

## 7. 미결사항

없음. 소유권 규칙의 변경 경로와 이관 시 직접 입력값 처리·검증 채택 범위·자동 승인요청의 효력·이탈 보호·자동 수신 실행 주체·공통코드 확정 방법·초기화 존치 여부·설정 변경 이력은 모두 §6에서 확정했다.

공통코드의 **실제 값**은 수신 데이터가 쌓이면서 확정된다 — 미결이 아니라 확정 방법이 정해진 진행 항목이며, 그 사이에도 화면은 어긋남을 감추지 않는다.
