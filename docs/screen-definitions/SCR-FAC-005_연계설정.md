# 화면 정의서 — 연계 설정

> 화면 ID: SCR-FAC-005 · 화면 유형: 설정 · 기획 관점(v6)
> 확정이 필요한 항목은 §7 미결사항에 모았습니다.

---

## 1. 화면 정보

| 항목 | 내용 |
|---|---|
| 화면 ID | SCR-FAC-005 |
| 화면명 | 연계 설정 |
| URL 경로 | fac-settings.html |
| 상위 메뉴 | 시설물 안전관리 > 연계 설정 |
| 화면 유형 | 설정 |

**목적·설명** — FMS와 주고받는 조건을 한곳에서 정하고, **어떤 정보를 누가 갖는지**와 **코드 값을 어떻게 읽을지**를 밝혀 두는 화면이다. 자동 현행화(제안요청서 SFR-002)는 "얼마나 자주 받을 것인가"와 "받은 값이 무엇을 덮어써도 되는가"가 정해져야 성립하는데, 이 두 규칙이 화면마다 흩어지면 대장이 조용히 어긋난다. 그래서 연계 조건을 이 화면 한 곳에 모으고, 실제 주고받는 작업은 FMS 연계(SCR-FAC-004)가 맡는다. 화면은 ① 인증·수신 조건 ② 필드 소유권 규칙 ③ 공통코드 매핑 ④ 초기화 4개 영역으로 구성한다. 여기서 정한 소유권 규칙이 시설물 상세(SCR-FAC-002)의 읽기 전용 구획과 편집 가능 구획을 가르는 근거가 된다.

## 2. 권한 정보

- 메뉴 접근·보기·수정은 시스템 관리의 메뉴 관리(SCR-ADMIN-005)와 권한 관리(SCR-ADMIN-006)에서 설정한다.
- 이 화면 정의서에서는 역할별 권한과 열람 범위를 별도로 정하지 않는다.
- 연계 조건 저장과 초기화는 §3~§6의 업무 흐름과 상태 전이 조건을 따른다.

## 3. 진입 / 이탈 경로 및 사용자 시나리오

**진입 / 이탈**

| 구분 | 연결 화면 | 조건 / 트리거 |
|---|---|---|
| 진입 | 상단 메뉴 시설물 안전관리 > 연계 설정 | 좌측 메뉴 |
| 진입 | FMS 연계(SCR-FAC-004) | 연계 이력 영역의 [연계 설정] |
| 이탈 | 같은 화면 새로 표시 | [초기화] 실행 후 처음 상태로 다시 표시됨 |
| 이탈 | FMS 연계(SCR-FAC-004) | 좌측 메뉴로 이동해 수신 실행 |

**사용자 시나리오**

| 단계 | 사용자 행동 | 화면 반응 |
|:--:|---|---|
| 1 | 연계 설정 진입 | 인증·수신 조건, 소유권 규칙, 공통코드 매핑, 초기화 4개 영역이 표시됨 |
| 2 | 기관코드·사용자 확인 | 현재 값이 입력칸에 채워져 있음. 인증키 입력칸은 없고 그 이유가 안내로 표시됨 |
| 3 | 일 배치 수신을 "사용"으로, 실행 상한을 조정 | 상한 옆에 허용 최대 횟수가 안내로 표시됨 |
| 4 | [설정 저장] | "연계 설정 저장됨" 안내. 값이 유지됨 |
| 5 | 필드 소유권 규칙 확인 | FMS가 갖는 정보와 우리가 갖는 정보가 좌우로 나뉘어 표시됨 |
| 6 | 공통코드 매핑 확인 | 개발자 가이드가 적어 둔 값과 실제 받은 값이 나란히 놓이고 판정이 붙어 있음 |
| 7 | [초기화] | 확인 팝업이 열리고 무엇이 사라지는지 안내됨 |
| 8 | 확인 팝업에서 [초기화] | "초기화되었습니다" 안내 후 화면이 처음 상태로 다시 표시됨 |
| 9 | 확인 팝업에서 [취소] | 아무것도 바뀌지 않고 팝업만 닫힘 |

**분기 로직**

- **일 배치 수신을 "미사용"으로 두면 자동 수신이 일어나지 않는다** — 이때 대장 갱신은 FMS 연계 화면에서 사람이 실행하는 경로만 남는다. 다만 현재 프로토타입은 "사용"으로 두어도 정해진 시각에 스스로 받아 오지 않는다(§4-1 상태).
- **자동 승인요청을 "사용"으로 두면 전송할 때 승인 요청이 함께 나간다** — 실제 전송 흐름과의 연결은 안내 수준이며 확정은 §7 FST-04.
- **초기화는 두 단계로 분기한다** — 버튼을 눌렀다고 곧바로 지워지지 않고 확인 팝업을 한 번 거친다. 팝업에서 취소하면 아무 변화가 없다.
- 소유권 규칙과 공통코드 매핑에는 분기가 없다. 두 영역은 값을 고르는 곳이 아니라 **현재 적용 중인 규칙을 밝혀 두는 곳**이다.

**엣지케이스**

- 설정을 저장하지 않고 화면을 벗어나면 고치던 값은 반영되지 않는다. 저장 전 이탈에 대한 확인은 없다(§7 FST-05).
- **초기화는 되돌릴 수 없다.** 확인 팝업에서 사라지는 대상(대장·보완입력·연계 이력)을 명시하지만, 지운 뒤 복구하는 수단은 없다.
- 실행 상한에 허용 최대치를 넘는 숫자를 넣어도 현재는 막지 않는다(§7 FST-03).
- 소유권 규칙·공통코드 매핑은 화면에서 고칠 수 없으므로, 규칙이 바뀌면 화면 표시도 함께 갱신되어야 한다(§7 FST-02).

## 4. 화면 구성별 정리

### 4-1. FMS 인증 · 수신 조건

- 구성: 기관코드 · 사용자 ID · 일 배치 수신(사용/미사용, 사용 시 실행 시각 표시) · 1일 실행 상한(허용 최대 횟수 안내 병기) · 자동 승인요청(사용/미사용) · 자격증명 미입력 안내 · [설정 저장].

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 값 입력·선택 | 화면에만 반영(저장 전) | — |
| [설정 저장] | 입력한 조건을 저장 | "연계 설정 저장됨" |

- 상태: 저장 전(고치는 중) / 저장됨 두 상태를 가지며, 저장 후에도 화면은 그대로 머문다. **일 배치 수신을 "사용"으로 두어도 프로토타입에서는 정해진 시각에 스스로 받아 오지 않는다** — 조건을 보여 주는 단계이고 실제 자동 실행은 실서비스 몫이다. 이 사실을 화면에 밝혀야 "자동인 척"이 되지 않는다(§7 FST-06). 인증키·비밀번호는 입력칸 자체를 두지 않고 그 이유를 안내로 표시한다.

### 4-2. 필드 소유권 규칙

- 구성: 좌우 2단 — **FMS 소유(읽기 전용)**: 대장 기본현황 항목 전부와 반영키. 받을 때 갱신되고 정정은 수정 전송으로만 한다. **자체 소유(수신이 덮어쓰지 않음)**: 안전등급 · 점검일 · 중대결함 · 규모 · 이용인원 · 위험물 취급 · 좌표 · 소관부서 · 관리담당자 · 중대재해대상 구분.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 화면 진입 | 현재 적용 중인 소유권 구분을 표시 | — |

- 상태: 표시 전용이라 빈 상태·오류 상태가 없다. 이 규칙은 세 화면의 동작을 동시에 결정한다 — 시설물 상세(SCR-FAC-002)에서 어느 구획이 읽기 전용인지, FMS 연계(SCR-FAC-004)에서 무엇을 비교 대상으로 삼는지, 수신 반영이 어떤 항목을 건드리지 않는지가 모두 여기서 나온다. **추가 연계로 안전등급·점검이력을 FMS에서 받게 되면 그 항목은 자체 소유에서 FMS 소유로 옮겨진다** — 그때 이 표도 함께 바뀐다(§7 FST-02).

### 4-3. 공통코드 매핑

- 구성: "개발자 가이드 재확인 필요" 표시 + 4개 열 표(코드 · 개발자 가이드 값 · 실제 받은 값 · 판정) 3행 — 시설물 구분/종류(코드 체계가 개편됨), 시설물 종별(값 정의 재확인 필요), 설계도서 보존 여부(값 정의 재확인 필요).

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 화면 진입 | 가이드 값과 실제 값의 차이를 나란히 표시 | 표 제목 옆에 재확인 필요 표시 |

- 상태: 표시 전용이다. **가이드 판이 오래되어 실제 받은 값과 어긋나 있다는 사실 자체가 이 영역의 내용**이며, 해소되면 판정 칸이 "확인 완료"로 바뀐다. 코드 값을 확정하기 전에는 조회 조건의 구분·종별 선택지와 수신 파일 검증(SCR-FAC-004 §5)의 허용값을 확정할 수 없다. 확인 불가를 뜻하는 임시 문자열을 빈 값으로 정리하는 규칙도 이 영역이 관리 대상이나 현재는 표에 드러나 있지 않다(§7 FST-07).

### 4-4. 초기화

- 구성: 안내 문구(대장·보완입력·이력을 처음 받은 상태로 되돌린다) + [초기화]. 실행 시 확인 팝업(사라지는 대상 명시 + [취소]·[초기화]).

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| [초기화] | 확인 팝업 열림 | 대장·보완입력·연계 이력이 사라진다는 안내 |
| 확인 팝업 [초기화] | 처음 받은 상태로 되돌리고 화면을 다시 표시 | "초기화되었습니다" |
| 확인 팝업 [취소] | 아무 변화 없이 팝업 닫힘 | — |

- 상태: 대기(버튼만 노출) → 확인 중(팝업) → 실행됨 세 단계다. 실행 후에는 대장이 처음 받은 상태로, 보완입력은 처음 들어 있던 시연용 값만 남은 상태로, 이력은 최초 수신 기록 한 건만 남은 상태로 되돌아간다. **되돌리기 수단은 없다.** 시연을 반복할 때 데이터가 쌓여 발표가 어긋나는 것을 막기 위한 기능이므로, 실서비스에서도 같은 형태로 둘지는 §7 FST-08.

## 6. 정책

- **자격증명은 화면에서 받지 않는다** — 인증키·비밀번호 입력칸을 아예 만들지 않고, 등록은 별도 보안 절차로 넘긴다. 권한으로 가리는 것과 기능을 두지 않는 것은 다르며, 여기서는 후자를 택했다.
- **소유권 규칙은 한 곳에서만 정한다** — 어떤 정보를 FMS가 갖고 어떤 정보를 우리가 갖는지는 이 화면이 단일 출처다. 화면마다 따로 판단하면 같은 항목이 어디서는 읽기 전용, 어디서는 편집 가능이 되어 수신 한 번에 값이 사라진다.
- **소유권은 옮겨질 수 있다** — 지금은 안전등급·점검이력·중대결함·규모를 우리가 직접 채우지만, 이는 해당 연계업무를 아직 받지 않았기 때문이다. 추가 연계가 붙으면 그 항목은 FMS 소유로 옮겨지고 직접 입력은 닫힌다. 옮기는 시점과 그때까지 쌓인 직접 입력값의 처리는 §7 FST-02.
- **코드 값을 가이드만 믿고 확정하지 않는다** — 개발자 가이드 판이 오래되어 실제 받은 값과 어긋나는 항목이 있다. 어긋남을 감추지 않고 표로 드러내며, 국토안전관리원의 현행 공통코드를 다시 받아 확정한다(§7 FST-07). 확정 전에는 코드에 기대는 조회 조건·검증 규칙을 고정하지 않는다.
- **수신 주기와 실행 상한은 연계 규격이 정한 범위 안에서 정한다** — 하루에 받을 수 있는 횟수에 상한이 있으므로 임의로 늘리지 않는다. 자동 현행화를 어느 범위까지 사람 확인 없이 진행할지는 FMS 연계(SCR-FAC-004 §6)에서 함께 정한다.
- **초기화는 시연·점검용 기능이다** — 담당자가 쌓은 보완입력을 한 번에 지우고 되돌릴 수단이 없다. 그래서 버튼 한 번으로 실행되지 않고 사라지는 대상을 명시한 확인 단계를 반드시 거친다. 실서비스에서 같은 형태로 두면 사고가 나므로 없애거나 확인 절차를 더 두는 것을 전제로 한다(§7 FST-08).
- **법령 근거를 붙이지 않는다** — 연계 조건 설정은 법령이 명한 의무 이행 행위가 아니다. 근거 없음을 명시하며 규칙은 공통 근거 연계(SCR-COM-008)를 따른다.
