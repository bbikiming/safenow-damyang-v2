# 화면 정의서 — 경영방침

> 화면 ID: SCR-SBM-001 · 화면 유형: 목록·등록·상세 · 기획 관점(v7.1 — 유효성·경우의 수·정합성 보강)
> 본 정의서는 프로토타입 v2의 **현재 구현 상태**(버전 목록형 경영방침 관리 + 현행본 기준 이행점검)를 기준으로 작성되었다. v7.1에서 유효성 검사(§5)·예외·경계 시나리오(§3)·데이터 정합성(§6)을 기획 관점에서 보강했다. 판단이 필요했던 항목은 모두 §6 정책에서 확정했다.

| 관련 SFR | SFR-005 (안전·보건 목표와 경영방침) |

**목적·설명** — 담양군의 안전·보건 목표와 경영방침을 **버전 단위(제정/개정/최초)** 로 등록·관리하고, 각 버전을 온나라 결재에 상신하여 확정하며, 확정된 **현행본**에 대해 반기 1회 이행점검과 게시·주지(게시 전/후 증빙)를 수행하는 안전보건관리체계 최상위 업무 화면이다.

화면은 공통 셸(페이지 타이틀 + 요약 바) 위에 얹히며, 그 아래 **3개 서브탭**(경영방침 / 이행 점검 / 게시 현황)으로 골격을 이룬다. 각 서브탭은 **목록(list)** 을 기본으로 하고, 행을 클릭하면 **공유 상세(detail)** 로 진입한다(세 탭이 동일 상세를 공유). 경영방침 탭에서는 추가로 **등록 화면(form)** 으로 전환된다.

핵심 설계 원칙 두 가지:
1. **현행본 = 결재 승인완료된 확정 문서** — 버전 숫자가 아니라 *결재가 승인완료된 문서 중 시행일이 가장 최근인 버전*을 현행본으로 본다. 이행점검 작성·게시·증빙 등록은 **현행본에서만** 가능하다.
2. **이전 버전은 이력 열람 전용** — 현행본이 아닌 버전은 점검·게시·증빙의 신규 작성/수정/삭제가 불가하며, 점검표·게시·증빙을 **읽기만** 할 수 있다.

반기 이행점검에서 부적합(X) 판정된 항목은 개선조치(SCR-IMP 계열)로 자동 연계된다.

현재 프로토타입의 데이터는 `window.POLICY_STATE`(인메모리 SSOT)에 보관되어 **SPA 세션 동안 유지**되며(버전 추가·게시·증빙·점검 결과 반영), 전체 새로고침 시 초기 시드로 리셋된다. 단, 이행점검표 인스턴스는 e-Doc 엔진에 별도 보관된다(세션 종료 후에도 유지). 실제 영구 저장·발송·온나라 연계 규칙은 §6에서 확정했다.

연관 화면: 이행관리(SCR-CMP 계열, 점검 상태 표시·역진입), 개선조치(SCR-IMP 계열, 부적합 항목 유입), 업무 목록(docs-preset.html?menu=policy).

## 4. 화면 구성별 정리

### 4-1. 공통 셸 — 페이지 타이틀 / 요약 바 (경영방침 고유 아님)
- 구성: 페이지 타이틀("경영방침") + 서브타이틀("안전보건관리체계 > 경영방침 · SFR-005 · 문서 N건"). 그 아래 **요약 바**(전 메뉴 공통) — "이행률 N%" 진행바(완료 문서 비율, 70↑ 양호·40↑ 주의·그 외 위험 색)·"시기도래 N건/없음"·"담당부서 재난안전과 중대재해팀".
- 상태: 요약 바 수치는 문서 데이터 기반 동적 표시. 별도 로딩 없이 즉시 표시. 모든 메뉴가 공유하는 공통 셸로 경영방침 고유 영역이 아니다.
- **변경 이력**: 이전 버전 정의서의 상단 [업무 기능]/[문서] 2탭은 **제거**되었다. 경영방침 화면은 곧바로 업무 기능(3 서브탭)으로 진입하며, 문서 분류 보기는 업무문서 > 업무 목록(docs-preset.html)에서 제공한다.

### 4-2. 서브탭 바 (경영방침 / 이행 점검 / 게시 현황)
- 구성: 3개 서브탭 버튼(`.psub-tabs`). 현재 활성 탭이 강조된다. 클릭 시 해당 목록으로 전환되며, 상세 화면은 세 탭이 공유한다(상세에서 [‹ 목록]을 누르면 직전 활성 탭의 목록으로 복귀).

| 트리거 | 동작 결과 |
|---|---|
| [경영방침] | 버전 목록(4-3) 표시 |
| [이행 점검] | 이행점검 목록(4-6) 표시 |
| [게시 현황] | 게시 현황 목록(4-9) 표시 |

- 상태: 라우팅은 인메모리 SSOT(`POLICY_STATE.tab/view/ver`)로 관리된다. 서브탭 전환 시 view는 목록(list)으로 초기화된다.

### 4-3. 경영방침 목록 (서브탭: 경영방침)
- 구성: 카드 제목 "경영방침 (N건)" + [+ 등록] 버튼. 표 컬럼 — 버전(`vX.X` + 제정/개정/최초 칩) · 방침명 · 반기 점검(최근 점검 완료일 또는 '미점검') · 온나라 결재 상태(미상신/결재중/승인완료/반려 칩). 행 클릭 시 상세로 진입.
- 등록된 방침이 하나도 없으면 빈 안내 + [최초 등록] 버튼만 표시된다.
- 시드 데이터: v2.0(제정·승인완료·현행), v1.1(개정·승인완료), v1.0(최초·승인완료).

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 행 클릭 | 상세(4-5)로 진입 | — |
| [+ 등록] | 등록 구분 선택 팝업(4-4) | 버전이 없으면 곧바로 '최초'(v1.0) 등록 화면으로 |

### 4-4. 경영방침 등록 (구분 선택 팝업 → 등록 화면)
- **구분 선택 팝업**: 현재 최신본 기준으로 [개정](+0.1)/[제정](+1.0)을 선택. 각 버튼에 다음 버전 번호와 성격(개정=소폭 보완·갱신, 제정=전면 재수립)이 표기된다. 버전 번호 규칙 — 최초=1.0, 개정=직전 +0.1, 제정=정수부 +1.0.
- **등록 화면(form)**: 상단 취소 바("경영방침 {구분} 등록 · v{번호}") + 입력 그리드.
  - 목표(슬로건, 텍스트, 필수 — 미입력 시 "목표를 입력하세요" 토스트로 저장 차단)
  - 세부 방침(줄 단위 GUI — 행별 입력 + ×삭제, [+ 세부 방침 추가]로 빈 줄 추가·포커스. 저장 시 빈 줄은 자동 제외)
  - 점검자(읽기전용 표시 + [조직도] 버튼 → 조직도 트리 오버레이)
- 방침 제호는 "담양군 안전·보건 경영방침"으로 고정. 시행일은 등록일로 채워지고 결재 상태는 '미상신'으로 시작.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 팝업 [개정]/[제정] | 구분·버전 확정 후 등록 화면으로 | — |
| [+ 세부 방침 추가] | 세부 방침 입력 줄 1개 추가 + 포커스 | — |
| 세부 방침 줄 [×] | 해당 줄 제거 | — |
| [조직도] | 조직도 트리 오버레이(부서·이름) → 선택 시 점검자 칸 채움 | — |
| [저장] | 목표 미입력 시 차단 / 정상 시 새 버전을 목록 최상단(unshift)에 추가하고 상세로 이동 | "경영방침 vX (구분) 등록 완료" |
| [취소]/[‹ 취소] | 목록으로 복귀 | — |

- 상태: 저장된 버전은 인메모리 SSOT에 즉시 반영되어 목록·상세에서 보인다(세션 유지, 전체 새로고침 시 초기화 — §6). 입력 검증은 프로토타입에 목표 필수만 있고, 필수 항목은 §6에서 확정했다.

### 4-5. 경영방침 상세 (3개 탭 공유)
- 구성: 상단 헤더([‹ 목록] + 우측 [개정]/[제정] + 미상신·반려 상태일 때만 [온나라 결재 상신]) → "경영방침 vX 상세" 카드(좌: 정보 그리드, 우: PDF 미리보기 패널) → 반기 이행 점검 이력 섹션(4-6 내 상세) → 게시 현황 섹션(4-9 내 상세).
- **정보 그리드**: 버전(번호 + 제정/개정/최초 칩 + **현행/이력 칩**) · 방침 제호 · 시행일 · 목표 · 세부 방침(번호 목록) · 점검자 · 반기 점검(완료일/미점검) · 온나라 결재(상태 칩 + [이력]). 하단 [ⓘ 작성 가이드] 배지.
- **PDF 미리보기 패널**: "PDF 미리보기" 라벨 + [전체화면]/[PDF 다운로드]. 그 아래 문서 용지(pdf-paper) — 서명자·문서번호·제호·버전·목표 슬로건·세부 방침 목록·시행일·직인 표시.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| [‹ 목록] | 직전 활성 서브탭 목록으로 복귀 | — |
| [개정] / [제정] | 해당 구분 등록 화면으로(4-4) | — |
| [온나라 결재 상신] (미상신·반려 시) | 결재 상태 '결재중' 전환 + 온나라 결재요청 안내(4-7) | — |
| [이력] (온나라 결재) | 결재 처리 이력 모달(4-7) | — |
| [ⓘ 작성 가이드] | 작성 가이드 모달(4-8) | — |
| [전체화면] | 문서 미리보기 **전체화면 팝업**(4-10) | — |
| [PDF 다운로드] | 안내만 표시 | "PDF 다운로드 (프로토타입)" |

- 상태: **현행/이력 칩**으로 편집 가능 여부가 결정된다. 현행본이면 점검·게시·증빙 편집 버튼이 노출되고, 이전 버전이면 잠금(아래 4-6·4-9). 표시 데이터는 해당 버전의 SSOT 값을 반영한다.

### 4-6. 이행 점검 목록 + 상세 점검 이력 (서브탭: 이행 점검)
- **목록(renderListCheck)**: 상단 안내 배너 — "결재 승인완료된 **현행본만** 이행 점검을 작성할 수 있습니다. 이전 버전은 **점검 이력 열람만** 가능합니다. 현행본: vX". 표 컬럼 — 버전 · **상태(현행/이력 칩)** · 방침명 · 점검 여부(완료/미점검) · 점검일 · 점검 결과(적합/부적합/보완 필요 칩) · 점검표(액션). 푸터에 [현행본 이행점검 작성].
- **점검표 컬럼 액션 분기**:
  - 점검 이력이 있으면 → [점검표 보기](읽기 뷰어 4-11)
  - 이력 없음 + 현행본 → [점검 작성](F5 폼 4-12)
  - 이력 없음 + 이전 버전 → "이력 없음"(텍스트, 버튼 없음)
- **상세 내 '반기 이행 점검 이력' 섹션**: 회차·점검일·점검자·결과 표 + 회차별 [점검표 보기]. 현행본이면 [이행점검 작성] 버튼, 이전 버전이면 버튼 없이 🔒 "이전 버전입니다. 점검 이력 열람만 가능하며 신규 점검 작성·수정은 현행본에서만 할 수 있습니다." 안내.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 행 클릭 | 상세(4-5)로 진입 | — |
| [점검 작성]/[현행본 이행점검 작성] (현행본) | F5 이행점검 점검표 폼(4-12) | — |
| 이전 버전에서 점검 작성 시도(직접 호출) | 작성 차단 | "현행(결재 승인완료) 방침만 이행 점검을 작성할 수 있습니다" |
| [점검표 보기] | 읽기 전용 점검표 뷰어(4-11) | — |

- 상태: 현행본 판정은 **결재 승인완료** 버전 중 **시행일이 가장 최근**인 버전을 현행으로 본다(버전 숫자 기준 아님). 현행본이 없으면(결재 미승인) 배너에 "현행본 없음 — 결재 승인 후 점검 가능"이 표시되고 작성 푸터 버튼이 숨겨진다.

### 4-7. 온나라 결재 (경영방침 상세에 통합)
- 구성: 별도 결재 박스 없이 상세 정보 그리드의 '온나라 결재' 칩 + [이력], 헤더의 [온나라 결재 상신](미상신·반려 시)으로 구성된다. 결재 상태: 미상신 / 결재중 / 승인완료 / 반려.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| [온나라 결재 상신] | 상태 '결재중' 전환 + 화면 재구성 + 온나라 결재요청 안내(e-Doc 공통 팝업) | — |
| [이력] | 결재 처리 이력 모달(고정 이력 3행: 상신·팀장 승인·부군수 승인) | — |

- 상태: 현재 결재 상태 전환은 시뮬레이션이다(실제 온나라 연동은 본개발 범위이며, 승인·반려가 무엇을 바꾸는지는 §6에서 확정했다). 이전 정의서의 '데모 상태' 버튼군(미상신/결재중/승인완료/반려 임의 전환)과 진행 상태 스트립은 재개편으로 **제거**되었다.

### 4-8. 작성 가이드 모달
- 구성: [ⓘ 작성 가이드]로 열리는 4단계 안내 — ① 경영방침 작성 원칙 ② 목표(KPI) 설정 ③ 게시·주지 의무 ④ 점검·환류. 각 단계에 근거 법령 표기.
- [확인]으로 닫기. 표시 전용(입력·저장 없음).

### 4-9. 게시 현황 목록 + 상세 게시 섹션 (서브탭: 게시 현황)
- **목록(renderListBoard)**: 카드 제목 "게시 현황 [산안법 §14 칩]". 표 컬럼 — 버전 · 방침명 · 게시 건수 · 최근 게시일 · 시행일. 행 클릭 시 상세로.
- **상세 내 '게시 현황(비포/애프터)' 섹션**: 안내 + 게시 전/후 카드 목록(위치·BEFORE→AFTER 슬롯·게시일·상태 칩). 그 아래 '관련 증빙' 표(파일명/구분). 현행본이면 카드 ×삭제·[+ 게시 위치 추가]·증빙 [삭제]·[+ 증빙 추가]가 노출되고, 이전 버전이면 모두 잠금(읽기 전용).
- 게시 위치 추가 팝업 입력: 게시 위치(필수 라벨)·게시일(필수 라벨)·게시 전(Before) 사진 드롭존·게시 후(After) 사진 드롭존·게시 내용(선택 메모). 사진은 **이미지 파일만 허용**("이미지 파일만 업로드할 수 있습니다" 토스트).

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 행 클릭 | 상세(4-5)로 진입 | — |
| [+ 게시 위치 추가] (현행본) | 게시 위치 추가 팝업 → [등록] 시 카드 추가 | "게시 항목이 등록되었습니다" |
| 게시 카드 [×] (현행본) | 해당 카드 제거 | "게시 항목이 삭제되었습니다" (확인 절차는 §6에서 확정 — 프로토타입 미반영) |
| [+ 증빙 추가] (현행본) | 증빙 추가 팝업(구분·파일·파일명) → [등록] 시 행 추가 | "증빙이 추가되었습니다" |
| 증빙 [삭제] (현행본) | 해당 행 제거 | "증빙이 삭제되었습니다" |

- 상태: 게시 위치를 입력하지 않아도 "새 게시 위치"로, 증빙 파일명을 입력하지 않아도 "증빙_N"으로 **자동 대체**되어 빈 값이 차단되지 않는다(필수 라벨↔실제 미강제 — §6에서 빈 값 차단으로 확정, 프로토타입 미반영). 게시/증빙 편집은 인메모리 SSOT에 반영(세션 유지).

### 4-10. 문서 미리보기 전체화면 팝업
- 구성: 상세 PDF 패널의 [전체화면]으로 열리는 **전체화면 오버레이**(화면 대부분을 채우는 큰 크기). 헤더("경영방침 vX 문서 미리보기" + [PDF 다운로드] + ×닫기) + 본문(문서 용지를 크게 렌더 — 760px·14px). 배경 클릭 또는 ×로 닫기.

### 4-11. 이행 점검표 읽기 뷰어 (점검표 보기 모달)
- 구성: [점검표 보기]로 열리는 **읽기 전용** 점검표(넓은 모달). 상단 메타(점검일·점검자·종합 결과 칩) + 요약(적합·부적합·텍스트 건수) + 영역별 섹션. 각 항목은 질문 + 관련 근거 태그(**호버 시 법령 상세 툴팁**) + 결과(O·적합 / X·부적합 칩 또는 텍스트 서술). 부적합이 있으면 "부적합 N건은 개선조치(IMP)로 자동 등록되었습니다" 안내. 푸터 [닫기]/[인쇄]/[PDF 다운로드].

### 4-12. 반기 이행점검 점검표 폼 (F5 e-Doc 폼)
- 구성: e-Doc 표준 폼(F5)로 열리는 작성 모달 "경영방침 수립·이행 점검표 (vX)". 필드 — 점검자(기본 해당 버전 점검자), 점검 항목 체크리스트(경영방침 점검표 프리셋, 7개), 증빙 첨부(파일 목록). 각 항목에 영역·결과유형·관련 근거(호버 툴팁)가 붙는다.

| [등록] | 상태 '등록완료'(확정 전 수정 가능) | "등록되었습니다" |

- 상태: 작성중 → 등록완료 → 확정. 점검표 인스턴스는 e-Doc 엔진에 보관되며 변경 시 화면이 즉시 갱신된다. 전 항목 판정 강제와 X·해당없음 사유 필수는 §6에서 확정했다(프로토타입 미반영). X 판정 자동 개선조치의 기한·담당 산정 규칙은 §6에서 확정했다.

### 4-13. 마스터 관리 모달군 (코드상 정의·현재 상세에서 직접 노출은 [작성 가이드]만)
- 구성: 근거법령·고려사항 관리(법령/조항/세부내용 표 + 구분/고려사항 표, 행 추가/삭제), 점검표 관리(영역/항목/결과유형/근거 표, 행 추가/삭제), 점검표 관련 근거(조문 상세) 설정 모달이 코드(PG.policyBasis/policyChecklist 등)로 정의되어 있다. 각 [+ 추가]는 단일 오버레이 규칙으로 입력 팝업을 띄운다.
- 입력 검증: 대부분 미입력값을 기본값(`'설정 시'`, `'O / X'` 등)으로 대체해 검증 없이 행이 추가된다. 단 **조문 상세의 '근거 표기'는 필수**("근거 표기를 입력하세요" 토스트로 차단)이며, **점검표 관련 근거 설정은 현행본에서만** 가능하다("현행(결재 승인완료) 방침에서만 …" 차단).
- 상태: 재개편된 상세 화면에서는 **[작성 가이드] 배지만 노출**되며, 근거법령·고려사항·점검표 관리 진입 배지는 제거되었다(코드 핸들러는 유지). 각 모달의 [저장]은 현재 안내만 표시하고 실제 데이터(점검표 F5 프리셋 등)에 반영되지 않는다 — 점검항목 마스터 단일화는 §6에서 확정했다. 점검표 관리 모달의 항목 수(6)와 실제 F5 점검표(7) 불일치도 같은 단일화로 해소한다.

## 6. 정책 (업무 규칙 · 데이터 정합성)

- **작성·상신·게시는 되돌리기 어려운 순서를 이룬다** — 방침은 결재를 거쳐 공표되는 문서라, 상신 이후에는 내용을 고치는 것이 아니라 새 버전을 만들어 다시 결재를 받는다. 게시·공표는 대외로 나가는 행위이므로 결재 승인완료를 선행 조건으로 삼는다. **결재 주체는 결재선이 정하고, 결재선은 코드에 고정하지 않는다(SBM-01 확정)** — 경영방침은 군수 명의로 나가는 문서라 최종 결재권자는 군수이고, 그 앞단(팀장 → 부서장 → 부군수)은 **지자체 위임전결규칙** 소관이라 조직 개편·규칙 개정으로 바뀐다. 기본값만 조직도에서 직위로 파생하고 변경은 조직도 선택기로 받는다. **게시·공표는 결재 승인완료를 선행 조건**으로 삼는다(SBM-06 확정) — 승인 전에 게시하면 결재 절차가 사후 추인이 된다. 상신은 **본문(목표·세부방침)이 채워진 상태**에서만 가능하며, 이행점검은 상신의 선행 조건이 아니다 — 점검은 방침을 정한 뒤에 하는 일이다.
- **현행본 판정 기준(단일성)** — 현행본은 `결재 승인완료` 버전 중 **시행일 최신본**으로 산출한다(버전 숫자 아님). 시스템 관점에서 현행본은 항상 0건 또는 1건이어야 한다. 결재 승인된 버전이 둘 이상이면 시행일이 가장 최근인 것을 현행으로 보며, **현행 전환은 시행일 도래 시점**이다(SBM-04 확정) — 승인 즉시로 하면 아직 시행되지 않은 방침이 현행으로 게시된다. 시행일이 오기 전까지는 이전 본이 현행이고 새 본은 "시행 예정"으로 표시한다. **시행일이 같은 승인본이 둘 이상이면 나중에 승인된 것을 현행**으로 보고, 그런 상태가 생기면 목록에 경고를 띄운다 — 정상적인 상황이 아니라 담당자가 확인해야 할 신호다.
- **버전 번호 정합성** — 최초=1.0, 개정=+0.1, 제정=정수부 +1.0의 자동 채번이다. 버전 번호는 중복되지 않아야 하며(자동 채번이라 충돌 가능성은 낮으나), **자동 채번을 유지한다**(SBM-11 확정) — 수동 지정이나 연도 기반으로 바꾸지 않는다. 수동 지정은 중복과 건너뜀을 만들고, 연도 기반은 한 해에 두 번 개정하면 곧바로 무너진다. 자동 채번은 중복이 구조적으로 생기지 않고, 개정(+0.1)과 제정(+1.0)의 차이가 번호만 보고도 읽힌다.
- **편집 잠금 경계** — 현행본만 이행점검 작성·게시 추가/삭제·증빙 추가/삭제가 가능하고, 이전 버전은 점검표·게시·증빙을 읽기만 한다(목록 액션·상세 버튼·직접 호출 모두 동일 가드). **이전 버전은 본문도 고칠 수 없다**(SBM-05 확정) — 결재를 거쳐 공표된 문서라 고치는 순간 "그때 무엇을 공표했는가"를 잃는다. 잠금 대상은 본문·점검·게시·증빙 **전부**이며, 고쳐야 하면 개정으로 새 버전을 만든다. 오탈자 하나도 예외로 두지 않는다 — 예외를 두면 어디까지가 오탈자인지 다투게 된다.
- **점검 결과 ↔ 개선조치 일관성** — 이행점검 확정 시 X(부적합) 항목마다 개선조치가 자동 생성된다. 점검표의 X 건수와 자동 생성 개선조치 건수가 일치해야 하며, **기한은 점검 확정일부터 30일, 담당자는 그 부서의 책임자**를 기본으로 지목하고 부서가 실제 담당자로 바꾼다(SBM-08 확정) — 주관부서가 남의 부서 담당자를 정하지 않는다는 원칙과 같다. 항목의 법령 근거는 개선조치로 그대로 전이한다.
- **점검항목 마스터 단일화** — 점검표 관리 모달(6항목)과 실제 F5 점검표(7항목)가 다르며 관리 모달 편집이 F5에 반영되지 않는다. 점검항목을 단일 마스터로 통합하고, 관리 모달의 F5 반영·노출 여부를 정해야 한다(개발 시 반영).
- **필수 라벨 ↔ 실제 강제 정합** — 게시 위치·게시일에 '필수' 라벨이 있으나 실제로는 빈 값이 자동 대체되어 강제되지 않는다. 라벨과 검증 동작을 일치시켜야 한다(개발 시 반영).
- **필수는 본문과 게시 정보다(SBM-02 확정)** — 저장을 막는 것은 **목표 · 세부방침(1건 이상) · 시행일** 셋이고, 게시 등록에서는 **게시 위치 · 게시일**이다. 필수 라벨을 붙여 놓고 빈 값을 자동 대체하는 지금 동작은 **라벨과 실제가 어긋나 담당자를 속인다** — 자동 대체를 없애고 실제로 막는다. 점검자·증빙은 이행점검 단계의 값이라 방침 저장의 필수가 아니다.
- **전 항목 판정을 강제하고 X에는 사유를 받는다(SBM-09 확정)** — 미판정 항목이 있으면 점검을 확정할 수 없고, 무엇이 비었는지 밝힌다. **X(부적합)에는 사유가 필수**이고 **"해당없음"에도 사유를 받는다** — 사유 없는 해당없음이 종이 서식의 가장 흔한 회피 경로이고, 그대로 두면 그 문제를 시스템으로 옮기는 것이 된다. 텍스트 서술 항목은 판정 항목과 달라 빈 값을 허용한다.
- **삭제는 무엇이 지워지는지 밝히고 확인을 받는다(SBM-12 확정)** — 게시 카드·증빙·세부방침 줄 모두 확인 단계를 거친다. 세부방침 줄은 이행점검 항목과 이어져 있을 수 있으므로 **연결된 점검 항목이 있으면 그 사실과 건수를 함께** 밝힌다. 되돌리기는 두지 않는다 — 되돌리기가 있으면 확인을 대충 하게 되고, 삭제 전 확인이 이미 그 역할을 한다.
- **마스터 모달도 같은 검증을 받는다(SBM-17 확정)** — 근거법령·고려사항·점검 항목을 추가할 때 **빈 값으로 행이 생기지 않게** 막는다. 지금은 기본값이 자동으로 들어가 "제목 없는 항목"이 목록에 쌓이는데, 그렇게 생긴 행은 아무도 지우지 않고 남아 점검표를 어지럽힌다. 항목명은 필수이고 나머지는 선택이다.
- **저장 경계(영구화)** — 버전 추가·게시·증빙·점검 결과는 인메모리 SSOT(`POLICY_STATE`)에 반영되어 세션 동안 유지되나 전체 새로고침 시 초기 시드로 리셋된다. 이행점검표 인스턴스만 e-Doc 엔진에 별도 보관되어 세션 종료 후에도 유지된다. 실서비스 영구 저장 대상·시점·연동 범위는 개발 시 반영한다(개발 진행 중 자연 해소 — 미결 제외).
- **상신·게시 선행조건** — 미상신·미점검 상태에서도 상신·게시가 가능하다. 선행 조건은 위 결재 정책에서 확정했다 — **상신은 본문이 채워진 상태에서, 게시·공표는 승인완료 이후**다.
- **온나라 결재 전환·채번** — 결재 상태 전환은 시뮬레이션이며 권한·결재선·선행조건이 적용되지 않는다. [확정] 정식 문서번호는 **온나라 채번을 정본**으로 하며(실연계 시 자동 수신, 미연계 시 결재 완료 후 담당자 수동 입력, 결재 전 '미채번'), 실제 온나라 연동은 본개발 구현 범위이며, **승인되면 그 버전이 잠기고 시행일에 현행으로 전환되며, 반려되면 미상신으로 풀리고 반려 사유가 함께 표시**된다(SBM-07 확정).

---

## 7. 미결사항

없음. 결재 주체와 결재선·입력 유효성·현행본 판정과 전환 시점·편집 잠금 범위·상신과 게시의 선행 조건·문서번호 채번·개선조치 자동 연계 기준·이행점검 판정 규칙·버전 번호 규칙·삭제 확인 절차·표시값 산정·상태 처리·마스터 모달 검증은 모두 §6에서 확정했다.

온나라 **실연계**와 실서비스 영구 저장은 미결이 아니라 본개발 구현 범위이며, 승인·반려가 무엇을 바꾸는지는 §6에 정해져 있다.
