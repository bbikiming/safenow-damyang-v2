# 화면 정의서 — FMS 연계

> 화면 ID: SCR-FAC-004 · 화면 유형: 기타(연계 작업·이력) · 기획 관점(v6)
> 확정이 필요한 항목은 §7 미결사항에 모았습니다.

| 항목 | 내용 |

**목적·설명** — 국토안전관리원 시설물통합정보관리시스템(FMS)에서 시설물관리대장을 **받아들이고**, 우리 쪽에서 고친 내용을 **되돌려 보내며**, 그 오간 내역을 **남기는** 화면이다. 제안요청서가 요구하는 "FMS 시설물 현황과 시설물안전법상 종별 분류의 자동 연계 및 자동 현행화"(SFR-002)와 "FMS 시설물 정보의 저장"(SFR-016)이 실제로 일어나는 곳이며, 받은 것을 그대로 덮어쓰지 않고 **무엇이 달라졌는지 사람이 보고 반영**하게 하는 것이 설계의 핵심이다. 화면은 ① 수신 ② 전송 ③ 연계·변경 이력 3개 영역으로 구성한다. 반영 결과는 시설물 대장(SCR-FAC-001)·시설물 위험도(SCR-FAC-003)에 곧바로 나타나고, 연계 조건은 연계 설정(SCR-FAC-005)에서 정하며, 시스템 전반의 외부 연계 상태 모니터링은 연계 관리(SCR-ADMIN-004)가 따로 맡는다.

- 메뉴 접근·보기·수정은 시스템 관리의 메뉴 관리(SCR-ADMIN-005)와 권한 관리(SCR-ADMIN-006)에서 설정한다.

- 수신·차이 반영, 전송, 실패 재처리는 §3~§6의 업무 흐름과 상태 전이 조건을 따른다.

| 이탈 | 연계 설정(SCR-FAC-005) | 이력 영역의 [연계 설정] |
| 이탈 | 시설물 대장(SCR-FAC-001) | 반영 후 좌측 메뉴로 이동해 결과 확인 |

**사용자 시나리오**

| 단계 | 사용자 행동 | 화면 반응 |
|:--:|---|---|
| 1 | FMS 연계 진입 | 수신·전송 두 영역과 그 아래 연계 이력이 표시됨 |
| 2 | 수신 영역의 업로드 자리를 클릭(또는 키보드로 실행) | 파일 선택 창이 열림. 지원 형식·용량·개수 안내가 함께 표시됨 |
| 3 | 대장 파일 선택 | 차이 미리보기가 나타남 — 신규·변경·동일 건수와 변경 건 목록 |
| 4 | 변경 내역 확인 | 어느 시설물의 몇 개 항목이 달라지는지 목록으로 표시(일정 건수까지) |
| 5 | [선택 반영] | 대장에 반영되고 "반영 완료 — 신규 N건 · 변경 N건" 안내. 이력에 수신 기록이 남음 |
| 6 | (되돌리기) [취소] | 미리보기가 닫히고 대장은 그대로 |
| 7 | 전송 영역 확인 | 신규 등록은 상세 정보가 없어 막혀 있고, 수정·삭제는 가능하다는 상태가 표시됨 |
| 8 | 개별 시설물 전송 | 이 화면이 아니라 시설물 상세(SCR-FAC-002)에서 실행 — 결과가 이력에 기록됨 |
| 9 | 이력 확인 | 수신·전송·보완입력이 시간순으로 한 표에 쌓여 있음 |
| 10 | [연계 설정] | 연계 설정 화면으로 이동 |

**분기 로직**

- **수신은 두 단계로 분기한다** — 파일을 고르는 것만으로 대장이 바뀌지 않고, 반드시 차이 미리보기를 거친다. 미리보기에서 [선택 반영]을 눌러야 대장에 들어가고, [취소]를 누르면 아무것도 바뀌지 않는다.
- **차이는 세 갈래로 나뉜다** — 대장에 없는 시설물번호면 신규, 있으면서 값이 달라졌으면 변경, 값이 같으면 동일이다. **동일 건은 반영해도 대장이 바뀌지 않는다.**
- **전송은 종류에 따라 가능 여부가 갈린다** — 수정·삭제는 보낼 수 있지만 **신규 등록은 막혀 있다.** 신규 등록을 받아 주려면 FMS가 규모·구조 상세 정보를 함께 요구하는데 그 정보를 아직 확보하지 못했기 때문이다. 화면은 이 사실을 상태로 표시하고 실행을 막는다.
- **비교 대상은 FMS에서 받는 항목뿐이다** — 담당자가 채운 보완입력은 비교에도 반영에도 들어가지 않는다. 수신이 보완입력을 지우지 않게 하는 분기다(소유권 규칙은 SCR-FAC-005 §4-2).

**엣지케이스**

- **어떤 파일을 골라도 현재는 이번에 받은 대장 내용이 그대로 미리보기에 올라온다.** 프로토타입은 파일 내용을 읽어 들이지 않고 수신 상황을 재현만 하기 때문이다. 그래서 현재 미리보기는 대개 "동일" 건수만 나오고 신규·변경이 잡히지 않는다. 실제 파일 해석 규칙은 §7 FSY-02.
- 미리보기를 띄운 채 화면을 벗어나면 대기 중이던 내용은 사라지고 대장은 그대로다.
- 이력이 한 건도 없으면 "연계 이력이 없습니다" 안내를 표시한다. 다만 대장을 처음 받은 기록이 항상 남아 있어 실제로는 비어 있지 않다.
- **FMS에서 사라진 시설물은 현재 감지하지 않는다.** 받은 목록에 없는 기존 시설물을 어떻게 처리할지(그대로 두기 / 폐지 표시 / 삭제)는 §7 FSY-04.
- 반영 중 오류가 나거나 일부만 반영되는 경우의 처리는 정하지 않았다(§7 FSY-05).

## 4. 화면 구성별 정리

### 4-1. 수신 (FMS → 시스템)

- 구성: 설명 문단(차이 미리보기 후 선택 반영, 보완입력은 덮어쓰지 않음) · 파일 업로드 자리(클릭 또는 키보드로 실행) · 지원 형식·용량·개수 안내 · [시드 재적재(시뮬레이션)] · 차이 미리보기 자리.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 업로드 자리 클릭·키보드 실행 | 파일 선택 창 열림 | — |
| 파일 선택 | 차이 미리보기 생성(신규·변경·동일 건수 + 변경 목록) | 파일명이 미리보기 제목에 표시 |
| [시드 재적재(시뮬레이션)] | 파일 없이 같은 미리보기를 생성 | 시연·점검용 경로임을 화면에 밝힘 |
| [선택 반영] | 미리보기 내용을 대장에 반영 | "반영 완료 — 신규 N건 · 변경 N건" + 이력 기록 |
| [취소] | 미리보기를 버림 | 대장 변화 없음 |

- 상태: **대기 없음(미리보기 전) → 검토 중(미리보기 표시) → 반영됨** 세 단계를 가진다. 미리보기 전에는 차이 영역이 비어 있고, 검토 중에는 대장이 아직 바뀌지 않은 상태이며, 반영 후 미리보기는 사라진다. 변경 건 목록은 일정 건수까지만 보여주고 나머지는 건수로만 표시한다. **[선택 반영]이라는 이름과 달리 지금은 항목을 골라 반영하는 수단이 없고 미리보기 전체가 함께 반영된다**(§7 FSY-03).

### 4-2. 전송 (시스템 → FMS)

- 구성: 설명 문단 · 전송 종류 표(3행 — 신규 등록 / 수정 / 삭제. 각 행에 대조 키와 가능 여부) · 개별 전송 안내 · 현재 인증 기관·사용자 표시.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 표 확인 | 전송 종류별 가능 여부를 확인 | 신규 등록은 "상세제원 필요"로 표시되어 실행 불가 |
| 개별 시설물 전송 | 이 화면이 아닌 시설물 상세에서 실행 | SCR-FAC-002 하단 [FMS 전송(수정)] |

- 상태: 이 영역은 **실행 화면이 아니라 조건 안내 영역**이다. 신규 등록은 상시 막힘(불가), 수정·삭제는 상시 가능으로 표시된다. 대장 전체를 한 번에 보내는 일괄 전송 수단은 두지 않았다(§7 FSY-06). 시설물 대조 키는 시설물번호이며, 이는 수신·전송 양쪽에서 같은 값을 쓴다.

### 4-3. 연계 · 변경 이력 (감사 추적)

- 구성: 헤더에 [연계 설정] 버튼 · 표 7개 열 — 일시 · 방향(수신/전송/보완입력) · 인터페이스 · 시설물 · 반영키 · 결과 · 내용.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 수신 반영 | 신규·변경 건수를 담은 수신 기록이 맨 위에 추가됨 | — |
| 시설물 상세에서 전송 | 전송 기록(대상 시설물·반영키·결과)이 추가됨 | — |
| 보완입력 저장 | 어떤 항목이 바뀌었는지 담은 기록이 추가됨 | 방향은 "보완입력" |
| [연계 설정] | 연계 설정 화면으로 이동 | fac-settings.html |

- 상태: 최근 기록이 위에 오고 일정 건수까지만 보관한다 — 보관 기간·건수 기준은 §7 FSY-07. 비어 있으면 "연계 이력이 없습니다" 안내를 두지만, 대장 최초 수신 기록이 항상 남아 실제로 비는 경우는 없다. 기록에는 **성공·실패 결과를 함께 남기며**, 실패 기록에서 재처리로 이어지는 동선은 아직 없다(§7 FSY-05). 이력은 조회 전용이라 이 화면에서 수정·삭제할 수 없다.

## 5. 유효성 검사

> 현재 프로토타입은 올린 파일의 내용을 검사하지 않는다. 아래는 제안요청서가 요구하는 "일괄 등록 시 유효성 체크와 오류 로그 제공"(SFR-016)을 이 화면에 적용하기 위한 검증 기준(제안)이며, 채택 범위는 §7 FSY-02·FSY-08.

| 입력 항목 | 필수 | 형식/길이 규칙 | 오류 안내 |
|---|---|---|---|
| 수신 파일 | 예 | 지원 형식·용량·개수는 공통 첨부 기준을 따름 | 형식이 다르면 "지원하지 않는 형식입니다"(제안) |
| 파일 구조 | 예(제안) | FMS 대장 전송 형식(정해진 항목 수와 순서)을 만족해야 함 | "대장 형식이 아닙니다 — 항목 수 불일치"(제안) |
| 시설물번호 | 예(제안) | 모든 행에 있어야 하며 파일 안에서 중복 불가 | 빠진 행·중복 행의 줄 번호를 오류 목록으로 제시(제안) |
| 시설물종별 | 예(제안) | 정해진 종별 값 중 하나 | 허용값이 아니면 해당 행을 오류로 분류(제안) |
| 구분·종류 코드 | 예(제안) | 공통코드 매핑표(SCR-FAC-005 §4-3)에 있는 값 | 매핑에 없는 코드는 "코드 확인 필요"로 표시(제안) |
| 준공일자 | 예(제안) | 날짜 형식. 미래 날짜 불가 | 형식 오류·미래 날짜는 오류 행으로 분류(제안) |
| 값이 비정상인 항목 | — | 확인 불가를 뜻하는 임시 문자열은 빈 값으로 정리 | 정리 규칙은 연계 설정에서 관리(SCR-FAC-005 §4-3) |
| 상위 시설물 참조 | 아니오(제안) | 참조 대상이 대장에 없으면 경고 | 반영을 막지 않고 "참조 확인 필요"로 표시(제안) |

- **오류 처리 원칙(제안)**: 오류가 있는 행은 반영하지 않고 나머지는 반영한다. 오류 행은 줄 번호·시설물번호·사유를 담은 목록으로 화면에 보여 주고, 같은 내용을 연계 이력에 남겨 나중에 확인할 수 있게 한다. 데이터 일괄등록(SCR-BASE-004)의 유효성 결과 화면과 같은 방식을 쓴다.

## 6. 정책

- **반영은 되돌릴 수 없는 단계다** — [선택 반영]은 대장 전체를 한 번에 바꾸고, 되돌리는 수단은 연계 설정의 초기화(전체를 처음 상태로) 하나뿐이다. 그래서 파일을 고르는 것과 반영하는 것을 반드시 나누고, 그 사이에 차이 미리보기를 둔다. 조회하러 들어온 사람이 실수로 반영까지 진행하지 않도록 하는 것이 이 두 단계의 목적이다.
- **받은 것을 그대로 덮어쓰지 않는다** — 수신은 반드시 차이 미리보기를 거친다. 자동 연계라 해도 무엇이 어떻게 바뀌는지 모른 채 대장이 갈리면, 잘못된 수신 한 번으로 현황·위험도·예산 근거가 한꺼번에 틀어진다.
- **보완입력은 수신이 건드리지 않는다** — 담당자가 채운 안전등급·점검일·규모 등은 FMS가 보내는 값이 아니므로 비교 대상에서 빼고, 반영할 때도 손대지 않는다. 이 규칙이 무너지면 대장을 받을 때마다 담당자가 쌓은 정보가 사라진다.
- **정정 방향은 한 쪽이다** — FMS에서 받은 항목이 틀렸으면 우리 화면에서 고치는 것이 아니라 수정을 전송하고 다시 받아 확인한다. 양쪽에서 같은 항목을 고치면 어느 값이 맞는지 판단할 근거가 없어진다.
- **자동 현행화는 신규만 자동, 변경은 확인 후다(FSY-08 확정)** — ① **신규 시설물은 사람 확인 없이 반영한다.** 새로 생긴 시설물이 목록에 없으면 아무도 관리하지 않게 되고, 신규 반영은 기존 값을 덮지 않아 잃을 것이 없다. ② **기존 값의 변경은 확인 후 반영한다.** 이미 그 값 위에 위험도·관리대상 판정·예산 근거가 얹혀 있어, 소리 없이 바뀌면 무엇 때문에 숫자가 달라졌는지 추적할 수 없다. ③ **자동 실행 실패는 이력에 남기고 시설물 담당자에게 알린다.** 실패가 조용하면 며칠째 옛 대장을 보고 있어도 모른다. 수신 주기와 하루 실행 상한은 연계 설정(SCR-FAC-005 §4-1)에서 관리한다.
- **없어진 시설물은 지우지 않고 폐지로 표시한다(FSY-04 확정)** — 지금은 신규·변경·동일 세 갈래만 보므로 **삭제를 네 번째 갈래로 넣는다**. 바로 지우면 그 시설물에 달린 보완입력·위험도·개선조치 이력이 함께 끊기는데, 그 이력은 "그때 그렇게 판단했다"는 기록이라 시설물이 없어져도 남아 있어야 한다. 그래서 **폐지 표시 후 보관**한다 — 기본 목록에서는 빠지고 조회 조건으로만 볼 수 있으며, 딸린 이력은 그대로 유지된다. 폐지 처리는 **자동으로 하지 않는다** — 수신 파일이 일부만 담고 있었을 때 멀쩡한 시설물이 통째로 폐지된다. 차이 미리보기에 "받은 목록에 없음 N건"으로 올리고 사람이 확인한다.
- **오간 내역은 전부 남긴다** — 수신·전송뿐 아니라 담당자의 보완입력까지 한 표에 남긴다. 시설물 정보는 예산·위험성평가의 근거가 되므로 "언제 누가 무엇을 바꿨는가"를 되짚을 수 있어야 한다. 이력은 고칠 수 없다.
- **이 화면과 연계 관리(SCR-ADMIN-004)의 역할이 다르다** — 연계 관리는 온나라·FMS·재정·행정포털의 연결 상태를 한눈에 보는 모니터이고, 시설물 연계의 실제 작업·차이 검토·이력은 이 화면이 맡는다. 두 화면이 서로 다른 시설물 건수를 보이면 안 된다. **기준은 하나다 — 연계 관리가 보여 주는 시설물 건수는 이 대장에서 파생한다**(FSY-09 확정). 세는 대상은 **폐지되지 않은 대장 전건**이고, 마지막 동기화 시각은 연계 이력의 가장 최근 수신 시각이다. 연계 관리가 자체 수치를 갖지 않으므로 두 화면이 어긋날 여지 자체가 없다.
- **차이 미리보기 확인이 곧 승인이다(FSY-01 확정)** — 별도 결재를 두지 않는다. 미리보기는 이미 "무엇이 어떻게 바뀌는지"를 항목 단위로 보여주므로, 그 위에 승인 단계를 하나 더 얹으면 확인하는 사람과 승인하는 사람이 갈려 **아무도 실제 내용을 읽지 않는 결재**가 된다. 대신 ① 미리보기를 거치지 않은 반영 경로를 만들지 않고 ② 실행자·시각·반영 건수를 이력에 남기며 ③ **폐지 처리가 포함된 반영에는 확인 문구를 한 단계 더** 둔다 — 되돌리기 가장 어려운 동작이기 때문이다.
- **건별로 골라 반영한다(FSY-03 확정)** — 전체 반영만 두면 열 건 중 한 건이 이상해도 나머지 아홉 건을 못 받는다. 그러면 담당자는 결국 통째로 받고 나중에 고치거나, 아예 안 받는다. 다만 **항목별(한 시설물 안에서 주소만 받고 이름은 안 받기) 선택은 두지 않는다** — 한 시설물의 정보가 반쪽만 갱신되면 FMS 정본과도 우리 대장과도 다른 제3의 상태가 생긴다. 선택 단위는 **시설물 한 건**이다.
- **수신 파일 해석 규칙은 표준연계 규격을 그대로 따른다(FSY-02 확정)** — 시설물관리대장 기본현황(BASTB_MASTER)은 **42개 항목**을 구분 문자로 이어 붙인 레코드로 오며, 식별 키는 **시설물번호**다. 프로토타입은 파일 내용을 읽지 않고 수신 상황만 재현하지만, 항목 수·순서·구분 문자·키는 이미 정해진 값이라 개발이 정할 여지가 없다. 규격과 다른 파일이 들어오면 **반영하지 않고 거부**한다 — 항목 수가 어긋난 채 밀어 넣으면 값이 한 칸씩 밀려 전 건이 오염된다.
- **실패는 그 건만 멈추고 나머지는 진행한다(FSY-05 확정)** — 한 건이 실패했다고 전체를 되돌리면 정상 처리된 79건까지 다시 받아야 한다. 대신 **실패한 건과 사유를 이력에 남기고 미리보기 화면에 그대로 되돌려** 담당자가 그 건만 다시 처리하게 한다. 자동 재시도는 두지 않는다 — 규격 오류나 키 충돌은 몇 번을 다시 보내도 같은 결과이고, 재시도가 이력을 같은 실패로 채워 진짜 원인을 덮는다. 알림 대상은 시설물 담당자이며, 자동 수신 실패는 여기에 더해 시스템 관리자에게도 알린다.
- **일괄 전송은 두지 않는다(FSY-06 확정)** — 대장 전체를 한 번에 FMS로 보내는 수단은 만들지 않는다. 전송은 **외부 정본을 바꾸는 행위**이고(SCR-FAC-002 §6), 일괄 전송은 한 번의 실수가 80건을 한꺼번에 망가뜨린다. 우리가 바꾸는 것은 어차피 담당자가 확인한 개별 건이므로 개별 전송으로 충분하다.
- **연계 이력은 지우지 않는다(FSY-07 확정)** — 시설물 정보는 위험도·관리대상 판정·예산의 근거이므로 "언제 누가 무엇을 바꿨는가"가 사후에 문제가 됐을 때 유일한 증거다. 건수 상한이나 자동 삭제를 두지 않고 전건을 보관하며, 조회는 **기간 · 방향(수신·전송·보완입력) · 시설물** 세 조건으로 좁힌다. 보존 연한을 특정 숫자로 못 박지 않는 이유는, 담양군 기록물 보존 기준이 정해지면 그것을 따라야 하고 그 전에 임의 연한으로 지우면 되돌릴 수 없기 때문이다.
- **추가 연계는 요청 항목을 확정해 신청한다(FSY-10 확정)** — 받아야 할 것은 네 묶음이다. ① **안전등급**(점검진단실적) — 위험도의 핵심 변수이자 관리대상 판정의 입력 ② **점검 이력**(최근·차기 점검일) — 법정 주기 초과 판정의 입력 ③ **중대결함** 유무·유형·통보일 — 조치 기한 계산의 입력 ④ **규모**(교량 연장·최대 경간장 / 터널 연장·차로수 / 건축물 연면적·층수·용도 / 상하수도 구분·1일 처리용량 / 옹벽·절토사면 높이·연장) — 공중이용시설 판정의 유일한 근거다. **받게 되면 해당 항목의 소유권이 보완입력에서 FMS로 넘어가고**, 넘어가는 시점에 이미 직접 입력해 둔 값은 지우지 않고 "직접 입력값"으로 따로 보관해 수신값과 다르면 드러낸다(SCR-FAC-005 §6). 신청 시기는 이 시스템 개통 전이어야 한다 — 개통 후에 붙이면 그 사이 담당자가 채운 값과 수신값을 대조하는 일이 통째로 생긴다.
- **법령 근거를 붙이지 않는다** — 시스템 간 데이터 주고받기는 의무를 이행하는 형식이지 법령이 직접 명한 행위가 아니다. 근거 없음을 명시하는 것도 정보이며, 근거 연계 규칙은 공통 근거 연계(SCR-COM-008)를 따른다.

## 7. 미결사항

없음. 반영 승인 단계·파일 해석 규칙·선택 반영 단위·삭제 감지·실패 처리·일괄 전송·이력 보관·자동 현행화 규칙·연계 관리와의 표시 정합·추가 연계 대상은 모두 §6에서 확정했다.

추가 연계 **신청 자체**는 담양군이 FMS 운영기관에 하는 행정 절차라 이 문서가 대신할 수 없다. 다만 **무엇을 요청할지**는 §6에 항목까지 확정해 두었으므로, 신청서에 그대로 옮기면 된다.
