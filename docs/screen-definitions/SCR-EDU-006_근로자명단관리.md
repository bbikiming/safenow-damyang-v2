- 인사연동 자료는 읽기 전용으로 표시하고 직접·엑셀 등록 자료는 수정·삭제한다.

- 이 화면 정의서에서는 역할별 권한과 열람 범위를 별도로 정하지 않는다.

## 3. 진입 / 이탈 경로 및 사용자 시나리오

| 구분 | 연결 화면 | 조건 / 트리거 |
|---|---|---|
| 진입 | 근로자 명단 관리 | 메뉴 선택 |
| 연계 | 정기·채용시·기타 교육 | 교육 대상자 모집단 제공 |
| 연계 | 이수현황 | 대상 구분·고용형태·채용일·관리감독자 지정일 제공 |

| 단계 | 사용자 행동 | 화면 반응 |
|:--:|---|---|
| 1 | 이름·부서·구분·고용형태·출처·채용연도로 조회한다 | 활성 근로자 목록 표시 |
| 2 | 직접 등록으로 근로자 정보를 입력한다 | 직접 등록 출처의 대상자 생성 |
| 3 | 직접·엑셀 등록자를 수정 또는 삭제한다 | 교육 판정용 기본정보 갱신 또는 비활성화 |
| 4 | 부서와 엑셀 파일을 선택해 업로드한다 | 시연용 예시 근로자 추가 |

### 분기 로직

- **출처가 조작 가능 여부를 정한다** — 인사연동 자료는 **읽기 전용**이고 직접 등록·엑셀 업로드분만 수정·삭제할 수 있다. 정본이 인사시스템에 있는 값을 여기서 고치면 다음 연동에서 덮이기 때문이다. 목록에 출처를 배지로 함께 보인다.
- **고용형태가 입력 칸을 늘린다** — **기간제 또는 일용**을 고르면 계약기간 입력이 나타나고, 다른 형태로 바꾸면 그 값은 저장되지 않는다. 계약기간은 채용시교육의 필요시간을 가르는 값이라 그 두 형태에서만 뜻이 있다.
- **구분이 교육 대상을 정한다** — 관리감독자·사무직·판매업무·비사무직 하나를 고르며, 이 값이 정기교육의 법정 시간과 이수현황의 모집단을 가른다. 비워 둘 수 없다.
- **등록과 수정이 같은 폼을 쓴다** — 다만 수정에서는 출처를 바꾸지 않는다.

### 예외·경계 시나리오

| 상황 | 화면 반응 |
|---|---|
| 인사연동 근로자를 수정·삭제하려 함 | 막고 "인사연동 근로자는 수정할 수 없습니다" |
| 이름 또는 채용일을 비운 채 저장 | 저장을 막고 무엇이 비었는지 알린다 |
| 근로자 삭제 | 활성 목록에서만 빠지고 **이미 쌓인 이수기록은 남는다** — 그 사람이 그때 교육을 받은 사실 자체가 사라지면 안 된다 |
| 엑셀 업로드 | 프로토타입은 파일 내용을 해석하지 않고 예시 자료를 넣으며 **그 사실을 화면에 밝힌다** |
| 엑셀에 형식 오류가 섞임(실서비스) | 오류 건을 따로 모아 보이고 정상 건만 반영한다 |
| 조회 결과가 0건 | 조건을 풀 수 있음을 함께 안내한다 |

## 4. 화면 구성별 정리

### 4-1. 필터와 목록
- 이름·부서 검색어와 **부서 · 구분 · 고용형태 · 출처 · 채용연도** 다섯 조건으로 조회한다.
- 이름, 부서, 구분, 고용형태, 채용일, 관리감독자 지정일과 관리 액션을 표시한다.
- 인사연동 자료에는 읽기 전용을, 직접·엑셀 자료에는 수정·삭제를 표시한다.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 검색어 입력 | 이름·부서를 함께 찾아 즉시 좁힌다 | — |
| 구분·고용형태·출처·채용연도 선택 | 선택 즉시 목록과 건수를 갱신한다 | — |
| 인사연동 자료 행 | 수정·삭제 수단을 내지 않는다 | 원천이 인사 자료라 이 화면에서 고치지 않는다 |

- 상태: 한 사람의 출처 축은 **인사연동 / 직접 등록 / 엑셀 업로드** 셋이고, 출처가 곧 조작 가능 여부를 정한다 — 인사연동 자료는 읽기 전용이라 수정·삭제 수단이 나타나지 않는다. 정본이 인사시스템에 있는 값을 여기서 고치면 다음 연동에서 덮이기 때문이다. 조건 결과가 0건이면 목록 자리에 빈 상태를 낸다.

### 4-2. 직접 등록·수정
- 이름, 부서, 구분, 고용형태와 채용일을 입력한다. 관리감독자이면 지정일을 함께 입력한다.
- 구분은 관리감독자, 사무직, 판매업무, 비사무직을 하나의 선택값으로 관리한다.
- 기간제 또는 일용 고용형태에는 계약기간을 추가 입력한다.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| [근로자 등록] | 이름·부서·구분·고용형태·채용일 입력을 연다 | — |
| 인사연동 관리감독자의 [지정일 등록] | 인사 기본정보는 잠근 채 지정일만 받는다 | 재난안전과 확인값으로 저장 |
| 고용형태를 기간제·일용으로 선택 | 계약기간 입력이 함께 나타난다 | 그 밖의 형태에서는 나타나지 않는다 |
| [저장](신규) | 명단에 더한다 | “(이름) 근로자 등록 완료” |
| [저장](수정) | 정보를 고친다 | “근로자 정보 저장” |
| 이름·채용일 누락 | 저장을 막고 무엇이 비었는지 알린다 | “이름을 입력하세요” · “채용일을 입력하세요” |
| 관리감독자 지정일 누락 | 관리감독자 직접 등록은 막고, 인사연동 대상은 "미등록"으로 남긴다 | “관리감독자 지정일을 입력하세요” |
| 인사연동 자료 수정 시도 | 막고 사유를 알린다 | “인사연동 근로자는 수정할 수 없습니다” |

- 상태: 입력 단계는 **작성 중 → 저장됨**이며 임시 보관이 없다. 관리감독자는 **지정일 미등록 / 등록**이 추가되고, 미등록은 0이나 미이수로 세지 않는다. 고용형태가 **기간제 또는 일용**일 때만 계약기간을 저장한다.

### 4-3. 엑셀 업로드
- 대상 부서와 파일을 선택해 업로드한다.
- 현재 프로토타입은 실제 파일 내용을 해석하지 않고 예시 데이터를 추가한다.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| [엑셀 업로드] | 대상 부서와 파일을 받는 입력을 연다 | — |
| 파일 선택 | 첨부된 것으로 표시한다 | 파일 내용을 해석하지 않음을 밝힌다 |
| [업로드] | 그 부서에 예시 인원을 더한다 | “(부서) 부서에 N명 엑셀 업로드 완료” |

- 상태: **파일 미선택 / 선택됨 / 반영됨** 세 단계다. 프로토타입은 파일 내용을 해석하지 않고 예시 자료를 넣으며, **그 사실을 화면에 밝힌다** — 숨기면 실제로 읽은 것으로 오해한다. 실서비스에서는 형식 오류 건을 따로 모아 보여주고 정상 건만 반영한다.

### 4-4. 삭제
- 직접·엑셀 등록자를 활성 목록에서 제외한다. 버튼 라벨은 [삭제]이고 실제 동작은 **명단에서 제외**다 — 이수기록은 남는다.
- 인사연동 자료는 이 화면에서 수정하거나 삭제하지 않는다.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| [삭제] | 활성 명단에서 제외한다 | “근로자를 명단에서 제외했습니다” |

- 상태: 삭제 수단은 **직접·엑셀 출처**에만 나타난다. 지우면 활성 목록에서 빠지지만 이미 쌓인 이수기록은 남는다 — 그 사람이 그때 교육을 받은 사실 자체가 사라지면 안 되기 때문이다. 인사연동 자료는 어느 상태에서도 이 화면에서 지울 수 없다.

## 6. 정책

- 인사연동 출처는 읽기 전용이며 직접 등록과 엑셀 업로드 출처만 화면에서 편집한다.
- 관리감독자 지정일은 재난안전과 확인값으로 저장하며 인사연동의 직위·채용일로 추정하지 않는다.
- 인사연동 기본정보는 계속 읽기 전용이지만 관리감독자 지정일은 별도 보완값으로 등록할 수 있다. 지정일 변경은 이전 값·변경일·처리자를 이력에 남긴다.
- 삭제는 활성 목록에서 제외하는 방식으로 처리한다.
- 엑셀 업로드는 현재 시연 동작이며 실파일 파싱 결과를 보장하지 않는다.
- 관리감독자 구분과 지정일은 정기교육(SCR-EDU-001)·이수현황(SCR-EDU-005)·조직(SCR-SBM-002)이 같은 값을 사용한다. 화면마다 별도 날짜를 갖지 않는다.
