# 화면 정의서 — 전역 GNB(대메뉴 바)

> 화면 ID: SCR-COM-002 · 화면 유형: 공통 크롬 · 기획 관점(v6) · 구현 정합 2026-08-11
> 판단이 필요했던 항목은 §6 정책에서 확정했습니다.

---

## 1. 화면 정보

| 항목 | 내용 |
|---|---|
| 화면 ID | SCR-COM-002 |
| 화면명 | 전역 GNB(대메뉴 바) |
| URL 경로 | 전 화면 공통 — 특정 주소가 없다 |
| 상위 메뉴 | 공통/전역 |
| 화면 유형 | 공통 크롬 |

헤더 아래에 붙는 **대메뉴 가로 띠**다. 이 시스템이 다루는 업무 축이 무엇무엇인지를 한 줄로 보여 주고, 지금 어느 축에 있는지를 표시한다. 업무가 늘면서 대메뉴가 14개가 되어 화면 폭을 넘기므로 가로 스크롤과 좌우 흐림 처리를 함께 둔다. 구성은 대메뉴 목록 하나이며, 대메뉴를 고르면 그 축의 사이드바(SCR-COM-003)가 함께 바뀐다.

---

## 2. 권한 정보

- 메뉴 접근·보기·수정은 시스템 관리의 메뉴 관리(SCR-ADMIN-005)와 권한 관리(SCR-ADMIN-006)에서 설정한다.
- 이 화면 정의서에서는 역할별 권한과 열람 범위를 별도로 정하지 않는다.
- **접근 권한이 없는 대메뉴는 보이지 않는다** — 하위 중메뉴가 하나라도 접근 가능할 때만 그 대메뉴를 낸다(SCR-ADMIN-005 §6).

---

## 3. 진입 / 이탈 경로 및 사용자 시나리오

| 구분 | 연결 화면 | 조건 / 트리거 |
|---|---|---|
| 진입 | 모든 화면 | 화면이 열릴 때 자동으로 붙는다 |
| 이탈 | 각 업무 첫 화면 | 대메뉴 선택 시 그 축의 첫 중메뉴로 이동 |

| 단계 | 사용자 행동 | 화면 반응 |
|:--:|---|---|
| 1 | 화면에 들어온다 | 지금 화면이 속한 대메뉴를 활성으로 표시한다 |
| 2 | 다른 대메뉴를 고른다 | 그 축의 첫 화면으로 이동하고 사이드바가 함께 바뀐다 |
| 3 | 폭이 좁아 메뉴가 잘린다 | 가로로 밀어 볼 수 있고 잘린 쪽에 흐림 표시가 나온다 |

### 분기 로직

- **활성 대메뉴는 지금 화면이 속한 축이다** — 사용자가 고른 값을 따로 기억하지 않는다. 주소로 직접 들어와도 그 화면의 축이 활성으로 잡히므로, 표시와 실제가 어긋나지 않는다.
- **접근 가능한 하위가 하나도 없으면 그 대메뉴를 그리지 않는다** — 눌러도 아무것도 없는 대메뉴는 없는 것보다 나쁘다.
- **폭이 모자라면 스크롤로 전환한다** — 대메뉴를 접거나 더보기로 묶지 않는다. 접으면 어느 축이 있는지 자체를 알 수 없게 되고, 이 띠의 목적이 바로 "무슨 축이 있는가"를 보여 주는 것이다.
- **활성 항목은 화면 밖에 있으면 자동으로 끌어온다** — 스크롤 상태와 무관하게 지금 위치가 보여야 한다.

### 예외·경계 시나리오

| 상황 | 화면 반응 |
|---|---|
| 대메뉴가 화면 폭을 넘김 | 가로 스크롤 · 잘린 쪽에 흐림 표시 · 활성 항목 자동 노출 |
| 어느 축에도 속하지 않는 화면 | 기본 축(대시보드)을 활성으로 둔다 — 아무것도 활성이 아닌 상태를 만들지 않는다 |
| 접근 가능한 대메뉴가 하나뿐 | 그 하나만 그린다 — 띠 자체를 감추지 않는다 |
| 좁은 화면 | 띠는 그대로 두고 사이드바만 서랍으로 바뀐다 — 축 이동은 좁은 화면에서도 자주 쓴다 |
| 메뉴 사용 여부를 끔 | 그 메뉴는 접근 권한과 무관하게 보이지 않는다(SCR-ADMIN-005 §6) |

## 4. 화면 구성별 정리

### 4-1. 대메뉴 목록

- 구성: 아이콘 + 대메뉴 이름이 가로로 나열된 띠. 지금 축은 활성 표시.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 대메뉴 선택 | 그 축의 첫 화면으로 이동한다 | 사이드바가 함께 바뀐다(SCR-COM-003) |
| 화면 진입 | 지금 화면이 속한 축을 활성으로 표시한다 | 주소로 직접 들어와도 맞다 |
| 활성 항목이 스크롤 밖에 있음 | 보이도록 끌어온다 | — |
| 폭이 모자람 | 가로 스크롤과 좌우 흐림 표시 | 접거나 더보기로 묶지 않는다 |

- 상태: 항목별 **활성 / 비활성** 둘이고, 띠 전체로는 **전부 보임 / 잘림(스크롤)** 두 상태를 갖는다. 접근 가능한 대메뉴가 0건이면 시스템에 들어올 수 없는 상태라 이 화면의 문제가 아니다.

## 6. 정책

- **대메뉴를 접거나 더보기로 묶지 않는다** — 이 띠의 목적이 "무슨 축이 있는가"를 보여 주는 것이라 감추면 목적이 사라진다. 폭이 모자라면 스크롤로 푼다.
- **활성 표시는 화면에서 파생한다** — 사용자가 고른 값을 기억하지 않는다. 기억하면 주소로 직접 들어왔을 때 표시와 실제가 어긋난다.
- **빈 대메뉴를 두지 않는다** — 하위가 하나라도 접근 가능할 때만 그린다.
- **아무것도 활성이 아닌 상태를 만들지 않는다** — 축에 속하지 않는 화면은 기본 축을 활성으로 둔다.
- **메뉴 구성은 이 화면이 갖지 않는다** — 대메뉴·중메뉴 구조와 순서는 메뉴 정의 한 곳에서 관리하고 이 띠는 그것을 그린다. 화면이 자체 목록을 들고 있으면 메뉴가 개편될 때 여기만 옛 이름으로 남는다.
- **법령 근거를 붙이지 않는다** — 이동 수단은 법령이 명한 의무의 직접 이행 수단이 아니다. 근거 없음도 정보이며 규칙은 공통 근거 연계(SCR-COM-008)를 따른다.

---

## 7. 미결사항

없음. 폭 초과 처리·활성 판정 기준·빈 대메뉴 처리·메뉴 구성의 소속은 모두 §6에서 확정했다.

접근 권한에 따른 실제 노출 차단은 미결이 아니라 **본개발 구현 범위**이며, 규칙은 메뉴 관리(SCR-ADMIN-005 §6)에 정해져 있다.
