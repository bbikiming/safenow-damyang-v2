## 1. 화면 정보

| 상위 메뉴 | 업무문서 > 업무 목록 |
| 화면 유형 | 목록 |

온나라로 상신한 문서, 시스템 전자문서, 담당자가 직접 올린 첨부, 전용 화면에서 처리하는 업무를 **한곳에서 찾는** 자리다. 목록 한 줄이 문서 한 건이며, 한 문서가 여러 업무단계에 걸쳐 있어도 한 줄로 본다.

이행 목록(SCR-DOC-003)이 의무가 채워졌는지 보는 자리라면 이곳은 **문서 자체를 찾는** 자리다. 채용 사이트의 상세 검색처럼 조건을 세밀하게 조합해 좁혀 간다.

> URL 경로의 이름은 예전 것을 그대로 쓴다. 다른 화면과 통계에서 걸어 둔 링크를 살리기 위해서이며, 전년도 프리셋 기능은 이 화면이 아니라 이행 목록에 있다.

| 5 | 조건을 하나만 푼다 | 조건 표시에서 개별로 뗄 수 있다 |
| 6 | 문서를 고른다 | 문서 상세로 가고, 돌아오면 조건·정렬·쪽이 그대로다 |
| 7 | 주관부서 담당자가 미분류를 고친다 | 그 문서가 증빙하는 업무단계를 지정하면 이행 현황에 반영된다 |

### 분기 로직

- **문서 출처에 따라 다음 행동이 다르다** — 온나라는 지면 확인, 전자문서는 양식 입력, 직접 첨부는 미리보기, 전용 화면 업무는 해당 화면 이동이다. 단추 이름을 모두 '확인'으로 뭉뚱그리지 않는다.
- **상태 선택지는 고른 출처에 따라 바뀐다** — 출처마다 업무 흐름이 다르므로 하나의 공통 단계로 환산하지 않는다. 출처를 고르지 않으면 전체 상태를 보여 주되 그렇다는 것을 문구로 알린다.
- **업무단계 선택지는 이행항목에 종속된다** — 이행항목을 먼저 고르지 않으면 업무단계를 고를 수 없다.
- **한 문서가 여러 업무단계에 걸치면 대표 하나와 나머지 수를 보여 준다** — 펼치면 그 줄 안에서 전부 보이고 각 단계에서 이행 목록으로 갈 수 있다.
- **미분류와 이행항목 축 없음을 구분한다** — 원장에서 분류가 빠진 문서와, 애초에 이행항목 축을 갖지 않는 기존 업무문서는 다른 것이다. 합치면 교정 대상이 무엇인지 알 수 없어진다.
- **예전 조회 조건 링크는 살릴 수 있는 것만 살린다** — 대메뉴 조건은 기존 업무문서가 그 값을 갖고 있으므로 그대로 동작한다. 분류 버전 조건은 그 기능이 폐지돼 뜻이 없으므로 조용히 무시하고 오류를 내지 않는다.

### 예외·경계 시나리오

| 담당 정보가 없는 원장 문서 | 원장 미보유로 표시한다 — 빈칸으로 두면 누락으로 읽힌다 |

| 제목이 거의 같은 문서 | 중복 의심으로 표시하고, 주관부서 담당자에게 정리 수단을 제공한다 |
| 온나라 문서인데 지면이 없는 경우 | 단추를 비활성으로 두고 사유를 밝힌다 — 가짜 링크를 만들지 않는다 |

| 링크로 들어왔는데 없는 업무단계 값 | 그 조건만 무시하고 나머지로 조회한다 |

## 4. 화면 구성별 정리

### 4-1. 안내

접을 수 있게 하고 접어도 한 줄은 남긴다. 남는 한 줄은 전체 문서 수와 출처별 구성이다. 펼치면 다음을 밝힌다.

- 네 갈래 문서를 한곳에서 조회한다는 것과, 한 문서가 여러 업무단계에 걸쳐도 한 줄이라는 것
- 이행 현황은 이행 목록에서 본다는 것
- 지난 연도 원장에는 담당 정보가 없고, 수발신자 상위 값이 외부 발신기관이라 담당자가 아니라는 것
- 문서 출처와 상태가 시연값이며 실제 운영에서는 각 원천 시스템의 상태로 대체된다는 것

### 4-2. 통합검색과 빠른 조건

| 조건 | 형태 | 대상 |
|---|---|---|
| 통합검색 | 입력 | 문서명·수발신자·담당자·담당부서·이행항목명·업무단계명·문서 식별값 |
| 기준연도 | 선택 | 자료에 실재하는 연도만 |
| 문서 출처 | 선택 | 온나라·전자문서·직접 첨부·전용 화면 업무 |
| 상세 조건 | 단추 | 펼치고 접는다 |

검색어와 조건은 주소에 함께 담아 새로고침·뒤로가기·링크 공유가 되게 한다.

### 4-3. 상세 조건

이행항목 · 업무단계 · 상태 · 법령근거 · 운영주기 · 취합상태 · 적용대상 · 이행주체 · 담당부서 · 담당자 · 수발신자 · 매핑 상태 · 첨부 유무 · 지면 유무 · 보고일자 기간.

- 화면 안에서 펼친다. 별도 창으로 띄우지 않는다.
- 선택지가 많은 축(이행항목·법령근거·수발신자)은 타이핑으로 좁히는 입력으로 둔다. 수십에서 수백 개를 스크롤로 찾게 하지 않는다. 선택지 수를 이름 옆에 적는다.
- 담당부서·담당자는 새로 등록한 문서에만 값이 있다는 것을 조건 아래에 밝힌다.

### 4-4. 적용 조건 표시

적용 중인 조건을 이름과 값으로 나열하고 개별로 뗄 수 있게 한다. 상세 조건을 접어도 보인다. 전체 초기화를 함께 둔다.

### 4-5. 결과 도구 줄

결과 건수와 쪽 수, 정렬(보고일자 최신·오래된순, 문서명 가나다·역순), 쪽 크기(20·50·100건).

### 4-6. 문서 표

| 열 | 내용 |
|---|---|
| 문서명 / 수발신자 | 문서명 아래 줄에 수발신자. 중복 의심·미분류 표시를 함께 단다 |
| 출처 | 네 갈래 |
| 상태 | 출처별 업무 흐름 상태 |
| 이행항목 · 업무단계 | 대표 이행항목과 업무단계. 여러 개면 나머지 수를 함께 적고 펼칠 수 있다 |
| 담당부서 / 담당자 | 값이 없으면 원장 미보유 |
| 보고일자 | |
| 첨부 / 지면 | 있을 때만 표시한다 |
| 관리 | 출처별 다음 행동. 주관부서 담당자에게는 교정 수단을 함께 둔다 |

열을 열 개로 늘리면 넓은 화면에서도 오른쪽 끝이 잘려 정작 행동 단추가 보이지 않는다. 수발신자는 문서명 아래로, 이행항목과 업무단계는 한 칸으로 합쳐 정보를 버리지 않고 폭을 줄인다.

### 4-7. 미분류 교정 · 중복 정리 (주관부서 담당자)

- **단계 지정** — 그 문서가 증빙하는 업무단계를 검색해 고른다. 저장하면 해당 단계가 진행중이 되고 이행 목록에 반영된다.
- **중복 정리** — 제목이 거의 같은 문서를 나란히 보여 주고 같은 문서로 합칠지 다른 문서로 둘지 고르게 한다. 합치면 업무단계 연결이 한쪽으로 모이고 나머지는 중복으로 표시된다. 원자료는 지우지 않는다.

## 5. 유효성 검사

| 대상 | 규칙 | 위반 시 |
|---|---|---|
| 통합검색 | 앞뒤 공백을 제거하고 부분 일치로 찾는다 | 입력 중 초점과 커서를 잃지 않는다 |
| 좁히는 입력 | 목록에 있는 값만 조건으로 받는다 | 없는 값이면 조건을 걸지 않고 후보를 좁히라고 알린다 |
| 업무단계 조건 | 이행항목을 먼저 골라야 한다 | 고르기 전에는 선택할 수 없게 한다 |
| 상태 조건 | 고른 출처의 상태만 제시한다 | 출처를 바꾸면 상태 조건을 함께 푼다 |
| 보고일자 기간 | 시작이 끝보다 늦을 수 없다 | 어긋나면 알리고 조회하지 않는다 |
| 단계 지정 | 업무단계를 하나 이상 골라야 한다 | 저장하지 않고 알린다 |
| 단계 지정·중복 정리 | 주관부서 담당자만 수행한다 | 수단을 노출하지 않고, 다른 경로로 시도해도 사유와 함께 막는다 |

전 화면 공통 계약(조회·필터, 쪽 나눔·정렬, 비동기 상태, 입력 검증)은 작성 규칙 §5를 따른다.

## 6. 정책

**P1. 목록의 기본 단위는 문서 한 건이다.**
카드형·세트형·단계 묶음형을 쓰지 않는다. 한 문서가 여러 업무단계에 걸쳐도 줄을 나누지 않는다 — 나누면 문서 수가 부풀어 "몇 건이 있는가"에 답할 수 없다.

**P2. 문서 출처는 네 갈래다.**
온나라·전자문서·직접 첨부에 더해 **전용 화면에서 처리하는 업무**를 넷째로 둔다. 셋으로 두면 기존 업무문서의 상당수가 어디에도 들어가지 않아 목록에서 사라지고, 내 할일과 통계에서 걸어 둔 진입점이 끊긴다.

**P3. 서로 다른 출처의 상태를 하나의 공통 단계로 환산하지 않는다.**
온나라는 결재 흐름, 전자문서는 작성 흐름, 직접 첨부는 검토 흐름, 전용 화면 업무는 시행 흐름이다. 억지로 맞추면 어느 쪽도 사실이 아닌 상태가 생긴다. 상태 조건은 고른 출처를 따라 바뀐다.

**P4. 상태는 상세 조건에만 둔다.**
같은 축을 빠른 조건과 상세 조건 양쪽에서 물으면 어느 쪽이 적용된 건지 알 수 없다. 상태는 출처에 종속되므로 출처와 함께 상세 조건에 둔다.

**P5. 미분류는 원장에서 분류가 빠진 문서만을 뜻한다.**
이행항목 축을 애초에 갖지 않는 기존 업무문서는 미분류가 아니다. 둘을 합치면 이행 목록의 미분류 건수 링크가 열 배로 열려 교정 대상이 무엇인지 알 수 없다. 매핑 상태는 분류완료·미분류·이행항목 축 없음 셋으로 나눈다.

**P6. 표시하고 끝내지 않는다 — 교정 수단을 함께 둔다.**
미분류와 중복 의심을 보여 주면서 고칠 방법이 없으면 화면이 도달할 수 없는 행동을 약속한 것이다. 주관부서 담당자에게 단계 지정과 중복 정리를 제공한다.

**P7. 교정은 원자료를 고치지 않고 덧씌운다.**
원자료는 생성물이라 손대지 않는다. 사람이 내린 판단은 따로 쌓아 원장 위에 얹는다. 무엇을 언제 누가 고쳤는지 추적할 수 있어야 하고, 되돌릴 수 있어야 한다.

**P8. 지면은 실제로 열 수 있을 때만 단추를 켠다.**
출처가 온나라라는 이유만으로 링크를 만들지 않는다. 없으면 비활성으로 두고 사유를 밝힌다. 실제 운영에서는 연계가 돌려준 값만 쓴다.

**P9. 문서 출처와 상태는 시연값이며 실제 운영값과 섞지 않는다.**
시연값은 문서 식별값에서 고정 배정해 새로고침해도 바뀌지 않게 한다. 무작위로 만들지 않는다. 각 문서에 시연값임을 남겨 실제 운영 전환 때 이 계층만 걷어낼 수 있게 한다. 실제 운영에서는 온나라·전자문서·파일관리 연계가 출처·상태·갱신시각·지면·첨부를 제공한다.

**P10. 예전 조회 조건 링크는 뜻이 남아 있는 것만 살린다.**
대메뉴 조건은 기존 업무문서가 그 값을 그대로 갖고 있으므로 살린다 — 무시하면 통계의 대메뉴별 링크 아홉 개가 전부 같은 전체 목록으로 떨어져 정보를 잃는다. 분류 버전 조건은 그 기능이 폐지돼 뜻이 없으므로 무시하되 오류를 내지 않는다.

**P11. 조회는 부서로 좁히지 않고 등록·수정만 부서로 막는다.**
지난 연도 자료가 주관부서의 문서 원장이라 부서로 조회를 좁히면 다른 부서 담당자에게 아무것도 보이지 않는다. 담당 정보가 없다는 사실은 원장 미보유로 드러낸다.

**P12. 많은 선택지는 스크롤이 아니라 타이핑으로 좁힌다.**
이행항목·법령근거·수발신자는 선택지가 수십에서 수백 개다. 목록을 굴려 찾게 하면 조건을 걸지 않게 된다.
