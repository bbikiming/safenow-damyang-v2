# 화면 정의서 — 시설물 상세 · 보완입력

> 화면 ID: SCR-FAC-002 · 화면 유형: 상세·등록·수정(팝업) · 기획 관점(v6)
> 확정이 필요한 항목은 §7 미결사항에 모았습니다.

---

## 1. 화면 정보

| 항목 | 내용 |
|---|---|
| 화면 ID | SCR-FAC-002 |
| 화면명 | 시설물 상세 · 보완입력 |
| URL 경로 | fac-list.html · fac-risk.html (행 클릭 또는 [상세]·[보완입력] → 팝업) |
| 상위 메뉴 | 시설물 안전관리 > 시설물 대장 · 시설물 위험도 |
| 화면 유형 | 상세 + 등록·수정 (팝업) |

**목적·설명** — 시설물 한 건에 대해 FMS에서 받은 정보를 그대로 보여주고, **받지 못했지만 위험성평가에 반드시 필요한 정보를 담당자가 직접 채우며**, 그 시설물에 대해 **실제로 어떤 개선조치를 했는지 되짚는** 화면이다. 받은 대장에는 안전등급·점검이력·중대결함·규모가 들어 있지 않아 그대로는 위험성평가를 시작할 수 없기 때문에, 이 화면이 그 공백을 메우는 유일한 입구가 된다(중대재해처벌법 시행령 제10조가 요구하는 안전점검·유해위험요인 확인의 선행 자료). 팝업은 ① FMS 기본현황(읽기 전용) ② 보완입력(직접 채우는 값) ③ 위험도 요약 ④ 개선조치 내역 4개 구획과 하단 버튼 줄로 구성한다. 시설물 대장(SCR-FAC-001)과 시설물 위험도(SCR-FAC-003)에서 열리고, 저장 결과는 두 화면에 즉시 반영되며, 개선조치 내역은 정기 위험성평가(SCR-RISK-001) 검수 표에서 이 시설물을 지정한 항목이 개선조치(SCR-IMP-001)까지 이어져 쌓인 결과다.

## 2. 권한 정보

- 메뉴 접근·보기·수정은 시스템 관리의 메뉴 관리(SCR-ADMIN-005)와 권한 관리(SCR-ADMIN-006)에서 설정한다.

- 보완입력 저장, FMS 전송, 위험성평가 착수는 §3~§6의 업무 흐름과 상태 전이 조건을 따른다.

| 이탈 | 원래 화면 유지 | [FMS 전송(수정)] — 팝업은 열린 채 결과 안내만 표시 |

**사용자 시나리오**

| 단계 | 사용자 행동 | 화면 반응 |
|:--:|---|---|
| 1 | 대장에서 행 클릭 | 팝업이 열리고 제목에 시설명이 표시됨. FMS 기본현황이 읽기 전용으로 표시 |
| 2 | FMS 기본현황 확인 | 받지 못한 항목은 "FMS 미제공"으로 표시되어 빈칸과 구분됨 |
| 3 | 안전등급 선택 | 등급별 상태 설명이 선택지에 함께 표시됨(우수·양호·보통·미흡·불량) |
| 4 | 최근 점검일 입력 | 다시 열었을 때 차기 점검예정일 옆에 법정주기 기준 제안값이 표시됨 |
| 5 | 중대결함 "있음" 선택 후 유형 선택 | 유형은 시설물 안전 관계 법령이 정한 결함 종류 중에서 고름 |
| 6 | 규모·이용인원·좌표 등 입력 | 입력한 값에 따라 위험도 요약의 "확보 변수"가 늘어남 |
| 7 | [보완입력 저장] | 팝업이 닫히고 "보완입력 저장됨" 안내. 목록·위험도의 등급·위험도 칸이 즉시 갱신 |
| 8 | 다시 열어 위험도 요약 확인 | 핵심 변수가 채워졌으면 "산정불가"가 풀리고 [위험성평가 착수]가 나타남 |
| 9 | [위험성평가 착수] | 정기 위험성평가 화면으로 이동 |
| 10 | [FMS 전송(수정)] | 전송 결과 안내가 표시되고 연계 이력(SCR-FAC-004)에 기록됨 |

**분기 로직**

- **위험도 산정 가능 여부가 하단 버튼을 가른다** — 안전등급과 최근 점검일이 **둘 다 비어 있으면** 위험도가 "산정불가"가 되고, 이때는 [위험성평가 착수]를 내지 않는다. 둘 중 하나라도 채워지면 [위험성평가 착수]가 나타난다. 값이 부족한 채로 평가에 들어가는 것을 막기 위한 분기다.
- **중대결함 "있음"이면 기한 안내가 따라붙는다** — 결함을 통보받은 날이 기록되어 있으면 **착수기한(통보일부터 2년 이내)**을 계산해 보여주고, **완료기한은 착수일부터 3년 이내**라는 기준을 함께 밝힌다(시설물안전법 제24조제1항제3호·시행령 제19조). 완료기한을 날짜로 단정하지 않는 이유는 기산점이 통보일이 아니라 **착수일**이고 착수일은 담당자만 아는 값이기 때문이다. 통보일이 없으면 안내는 나타나지 않는다.
- **차기 정기안전점검 제안값은 안전등급에 따라 갈린다** — A·B·C 등급과 등급 미지정은 **반기 1회 이상**, D·E 등급은 **연 3회 이상**이다(시설물안전법 시행령 별표3). 제안값은 채워 넣는 값이 아니라 옆에 표시되는 참고값이며 담당자가 직접 입력한 날짜를 덮지 않는다.
- **D·E 등급은 법이 간격이 아니라 시기를 정한다** — 해빙기(2·3월)·우기(5·6월)·동절기(11·12월) 전 각 1회다(별표3 비고 3). 그래서 제안값 옆에 그 세 시기를 문구로 함께 낸다 — 날짜만 제안하면 담당자가 균등 간격으로 잡아 법정 시기를 벗어난다.

**엣지케이스**

- **저장하지 않고 닫으면 입력값은 사라진다.** 확인 없이 닫히므로 입력 도중 이탈에 대한 보호가 없다(§7 FDT-06).
- **안전등급이나 최근 점검일을 바꿔도 차기 점검예정일 제안값은 그 자리에서 다시 계산되지 않는다.** 저장하고 팝업을 다시 열어야 갱신된 제안값이 보인다.
- 중대결함을 "있음"에서 "없음"으로 되돌려도 이미 고른 결함 유형·보수보강 진행 값은 지워지지 않는다. 정합성 처리 규칙은 §7 FDT-03.
- FMS 기본현황 값이 모두 비어 있는 항목이라도 항목 자체는 숨기지 않고 "FMS 미제공"으로 남긴다 — 무엇을 못 받았는지가 곧 추가 연계 요청 목록이기 때문이다.
- 신규 등록 전송은 이 화면에서 제공하지 않는다. 대장에 없는 시설물을 FMS에 새로 올리려면 규모·구조 상세 정보가 함께 있어야 하는데 아직 확보되지 않아 막혀 있다(SCR-FAC-004 §4-2).

## 4. 화면 구성별 정리

### 4-1. FMS 기본현황 (읽기 전용)

- 구성: "읽기 전용" 표시와 함께 12개 항목 — 시설물번호 · 시설물명 · 구분/종류 · 시설물종별 · 관리주체코드 · 소유자 · 소재지 · 준공일자(경과 연수 병기) · 설계자 · 시공자 · 공사명 · 내진설계 적용 여부.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 팝업 열림 | 해당 시설물의 수신 값을 그대로 표시 | 값이 없으면 "FMS 미제공" |

- 상태: 이 구획에는 입력 수단을 두지 않는다. 값을 고쳐야 하면 우리 시스템에서 바꾸는 것이 아니라 FMS로 수정을 전송하고 다시 받아 확인한다(소유권 규칙은 SCR-FAC-005 §4-2). 단계상태로는 **수신 전(표시할 값 없음) → 수신됨 → 수정 전송 후 재수신 확인**의 세 국면을 가진다. 준공일자가 없으면 경과 연수도 표시하지 않는다.

### 4-2. 보완입력 (직접 채우는 값)

- 구성: "자체 소유 · FMS 수신이 덮어쓰지 않음" 표시와 함께 13개 입력 항목 — 안전등급(A~E, 등급별 상태 설명 병기) · 소관부서 · 최근 점검일 · 차기 정기안전점검 예정일(제안값 + 법정주기 문구 병기) · 중대결함 유무 · 중대결함 유형 · 보수보강 진행(계획/착수/완료) · 규모(값 + 단위) · 이용인원(일평균) · 위험물 취급 여부 · 좌표(위도 · 경도) · 인접 위험요소.
- **중대결함 유형은 두 묶음으로 나눠 고른다** — **구조안전**(시행령 제18조제1항 11호)과 **공중이 이용하는 부위**(같은 조 제2항 4호)는 통보 근거 조항이 다르므로 한 목록으로 섞지 않는다. 담양군은 공중이용시설 관리자라 난간·포장·환기구 덮개 파손을 다루는 제2항이 실무상 더 자주 걸린다.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 항목 입력·선택 | 화면에만 반영(저장 전) | — |
| [보완입력 저장] | 입력한 값을 저장하고 팝업 닫음 | "보완입력 저장됨" + 목록·위험도 갱신 |
| 저장 시 값이 바뀐 항목이 있음 | 어떤 항목이 바뀌었는지 연계 이력에 기록 | SCR-FAC-004 이력에 "보완입력"으로 표시 |

- 상태: 빈 항목은 오류가 아니라 **아직 확보하지 못한 정보**로 다룬다(빈 상태 = 미확보). 단계상태는 **미확보 → 핵심 변수 확보(안전등급 또는 최근 점검일) → 위험도 산정 가능 → 전 항목 확보** 순이며, 위험도 요약의 "확보 변수" 수가 그 진척을 나타낸다. 중대결함을 통보받은 날짜는 현재 입력란이 없어, 이미 기록이 있는 시설물에서만 기한 안내가 표시된다(§7 FDT-03).

### 4-3. 위험도 · 위험성평가 요약

- 구성: 위험도 배지(높음/보통/낮음/산정불가와 점수), 확보한 변수 목록, 산정불가일 때의 안내 문구.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 팝업 열림 | 현재 값 기준으로 위험도를 다시 계산해 표시 | 산정불가면 "핵심변수(안전등급·점검일) 부족 — 보완입력 후 착수" 안내 |

- 상태: 산정불가(핵심 변수 없음) / 산정됨(높음·보통·낮음) 두 상태로 갈린다. 산정불가일 때는 점수를 숫자로 내지 않는다 — 부족한 값을 0으로 처리해 낮은 점수를 보이면 안전한 시설물로 오해되기 때문이다(산정 규칙은 SCR-FAC-003 §6).

### 4-4. 개선조치 내역

- 구성: 건수 요약(전체 · 완료) + 표 — 유해위험요인/조치 · 부서 · 기한 · 상태 · 증빙 · [보기]. 이 시설물로 지정된 개선조치가 없으면 0건 표시와 함께 어디서 지정하는지 안내한다.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 팝업 열림 | 이 시설물로 지정된 개선조치를 모아 표시 | 0건이면 "위험성평가 보고서 검수에서 유해위험요인 행에 이 시설물을 지정하면 여기에 쌓입니다" |
| [보기] | 해당 개선조치의 상세로 이동 | SCR-IMP-002 |

- 상태: **0건(아직 지정된 조치 없음) / N건**으로 갈리며, 각 행의 단계상태는 **진행 → 기한 초과 → 완료**이고 완료 건에는 확인 상태(확인 대기 · 확인 완료 · 반려)를 함께 표시한다. 위험성평가 자료를 불러오지 못한 경우에는 건수를 0으로 보이지 않고 불러오지 못했다는 사실을 표시한다 — 0건과 조회 실패는 다른 상태이며, 섞으면 조치가 없는 시설물로 오독된다. 이 구획은 조회 전용이라 여기서 조치를 만들거나 고치지 않는다.

| 트리거 | 동작 결과 | 이동 / 메시지 |

## 6. 정책

- **보완입력 저장과 FMS 전송은 같은 조건으로 다루지 않는다** — 보완입력은 우리 시스템 안의 값이라 틀리면 다시 고치면 되지만, **FMS 전송은 외부 정본을 바꾸는 행위**여서 되돌리려면 다시 전송해야 한다. 두 동작을 한 번의 판단으로 묶지 않고, 전송은 무엇이 바뀌는지 확인한 뒤 실행하는 별도 단계로 둔다. 전송 결과는 연계 이력(SCR-FAC-004 §4-3)에 남아 누가 언제 외부를 바꿨는지 되짚을 수 있다.
- **받은 값과 채운 값을 섞지 않는다** — FMS 기본현황은 고칠 수 없고 보완입력만 고칠 수 있다. 이 경계를 흐리면 대장을 다시 받았을 때 담당자가 채운 값이 지워지거나, 반대로 우리 쪽 임의 수정이 FMS 정본으로 올라간다. 소유권 목록은 연계 설정(SCR-FAC-005 §4-2)이 관리한다.
- **위험성평가를 시작할 수 있는 최소 정보는 네 축이다** — 안전등급 / 최근·차기 점검일 / 중대결함 유무 / 규모 대표값과 이용인원. FMS에서 이미 받은 경과연수·종별·내진 적용 여부와 합치면 위험도 산정이 성립한다. 네 축이 다 차야 하는 것은 아니고, 안전등급이나 최근 점검일 중 하나만 있어도 산정을 시작한다(SCR-FAC-003 §6).
- **점검 주기는 우리가 정하는 값이 아니다** — 관리주체는 소관 시설물의 안전점검을 정기적으로 실시할 의무가 있고(시설물안전법 제11조제1항), 실시시기는 시행령 별표3이 정한다. **정기안전점검은 A·B·C 등급과 등급 미지정이 반기 1회 이상, D·E 등급이 연 3회 이상**이며, D·E는 해빙기·우기·동절기 전 각 1회라는 **시기**까지 정해져 있다(별표3 비고 2·3). 화면은 제안 날짜와 이 주기 문구를 함께 낸다.
- **중대결함의 조치기한은 두 단계이고 기산점이 다르다** — 통보를 받은 날부터 **2년 이내에 착수**하고, 특별한 사유가 없으면 **착수한 날부터 3년 이내에 완료**해야 한다(시설물안전법 제24조제1항·시행령 제19조). 즉 완료기한은 통보일 기준이 아니라 착수일 기준이며, 최대 통보일로부터 5년까지 벌어질 수 있다. 화면은 착수기한만 날짜로 계산하고 완료기한은 기준을 문구로 밝힌다 — 착수일을 모른 채 완료기한을 날짜로 단정하면 지연 판정이 틀린다. 조치를 마치면 결과를 통보해야 한다(제24조제3항). 기한 관리를 개선조치(SCR-IMP-001)로 넘길지는 §7 FDT-08.
- **안전등급은 판단 결과이지 입력값이 아니다** — 안전점검등의 실시결과에 따라 지정하며 구간은 시행령 별표8이 정한다(A 우수 / B 양호 / C 보통 / D 미흡 / E 불량). 원래 점검·진단 실적에서 나오는 값이라 장기적으로는 FMS 점검진단실적 연계로 받아야 하고 직접 입력은 연계 전까지의 임시 경로다. 연계가 붙으면 이 항목의 소유권이 자체에서 FMS로 넘어간다(SCR-FAC-005 §7).
- **시설물과 위험성평가는 평가 단위가 아니라 항목 단위로 잇는다** — 정기 위험성평가는 부서 단위로 한 해 한 건이고, 용역 보고서 한 건에 여러 시설물의 지적사항이 섞여 나온다. 그래서 "시설물 하나 = 평가 하나"로 잇지 않고, **검수 표의 유해위험요인 행에 시설물을 지정하는 방식**(SCR-RISK-001 §4-5)으로 잇는다. 이 화면의 [위험성평가 착수]는 그 화면으로 데려다주는 역할이고, 실제 연결은 행에서 이루어진다.
- **잇는 키는 이름이 아니라 시설물번호다** — 같은 이름의 시설물이 실제로 있고 시설물은 개명·통폐합된다. 이름으로 이으면 대장을 다시 받는 순간 연결이 조용히 끊긴다.
- **지정은 선택이지 필수가 아니다** — 작업 행동·화학물질·보건처럼 특정 시설물에 붙지 않는 유해위험요인이 많다. 필수로 걸면 담당자가 아무 시설물이나 지정하게 되고, 그 순간 이 화면의 개선조치 내역이 거짓 기록이 된다.
- **이 연결이 FMS로 되돌려 보낼 내용을 만든다** — 지금 전송할 수 있는 것이 대장 수정·삭제뿐인 이유는 우리 시스템이 시설물에 대해 만들어낸 정보가 없기 때문이다. 조치 실적이 시설물에 쌓이면 FMS 표준연계가 받도록 정해 둔 보수·보강 실적·중대결함 사후관리로 보낼 근거가 생긴다(SCR-FAC-004 §7 FSY-10과 함께 판단).
