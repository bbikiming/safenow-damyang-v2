# 화면 정의서 — 시설물 상세 · 보완입력

> 화면 ID: SCR-FAC-002 · 화면 유형: 상세 + 등록·수정 (팝업) · 기획 관점(v6)
> 판단이 필요했던 항목은 §6 정책에서 확정했습니다.

---

## 1. 화면 정보

| 항목 | 내용 |
|---|---|
| 화면 ID | SCR-FAC-002 |
| 화면명 | 시설물 상세 · 보완입력 |
| URL 경로 | fac-list.html · fac-risk.html (행 클릭 또는 [상세]·[보완입력] → 팝업) |
| 상위 메뉴 | 시설물 안전관리 > 시설물 대장 · 시설물 위험도 |
| 화면 유형 | 상세 + 등록·수정 (팝업) |

**목적·설명** — 시설물 한 건에 대해 FMS에서 받은 정보를 그대로 보여주고, **받지 못했지만 시설물 위험도와 안전점검 계획에 필요한 정보를 담당자가 직접 채우며**, 그 시설물에 연결된 종사자 작업 개선조치가 있는지 되짚는 화면이다. 받은 대장에는 안전등급·점검이력·중대결함·규모가 들어 있지 않아 그대로는 안전점검 우선순위를 산정할 수 없기 때문에, 이 화면이 그 공백을 메우는 유일한 입구가 된다(중대재해처벌법 시행령 제10조와 시설물안전법상 점검·등급 관리의 선행 자료). 팝업은 ① FMS 기본현황(읽기 전용) ② 보완입력(**6항목** — 연계 전 임시 4 + 담양군 관리 2) ③ 위험도 요약 ④ 근로자 위험성평가 연결 개선조치 내역 4개 구획과 하단 버튼 줄로 구성한다.

**제안요청서와의 관계** — 제안요청서에 '보완입력'이라는 기능은 없다. 시설물 관련 요구는 SFR-002·SFR-016 두 건이고, 그중 **「1·2·3종 분류 자동 연계」·「자동 현행화」·「저장」은 받은 대장만으로 충족된다**(종별이 100% 채워져 왔다). 충족되지 않는 것은 뒤의 두 문장 — *"연계된 시설물 정보를 구축시스템에서 관리하고 **점검**할 수 있도록"*(SFR-002), *"저장된 시설물 정보를 기반으로 **관리대상 분류** 및 점검이 가능하도록"*(SFR-016) — 이다. 안전등급·점검일 없이는 무엇을 먼저 점검할지 정할 수 없고, 규모 없이는 그 시설이 중대재해법상 관리대상인지조차 판정할 수 없다. **이 구획은 그 두 문장을 성립시키기 위한 최소 우회로이지 독립 기능이 아니다.** 그래서 항목을 요구사항에 직접 대응하는 것만 남기고(§6 축소), 추가 연계가 붙으면 닫히는 임시 경로임을 화면에 명시한다. 시설물 대장(SCR-FAC-001)과 시설물 위험도(SCR-FAC-003)에서 열리고, 저장 결과는 두 화면에 즉시 반영된다. 개선조치 내역은 정기 위험성평가(SCR-RISK-001) 검수 표에서 청소·정비 등 종사자 작업의 유해위험요인에 이 시설물을 지정한 경우에만 쌓이며, 시설물 안전점검 완료를 뜻하지 않는다.

## 2. 권한 정보

- 메뉴 접근·보기·수정은 시스템 관리의 메뉴 관리(SCR-ADMIN-005)와 권한 관리(SCR-ADMIN-006)에서 설정한다.

**사용자 시나리오**

| 단계 | 사용자 행동 | 화면 반응 |
|:--:|---|---|
| 1 | 대장에서 행 클릭 | 팝업이 열리고 제목에 시설명이 표시됨. FMS 기본현황이 읽기 전용으로 표시 |
| 2 | FMS 기본현황 확인 | 받지 못한 항목은 "FMS 미제공"으로 표시되어 빈칸과 구분됨 |
| 3 | 안전등급 선택 | 등급별 상태 설명이 선택지에 함께 표시됨(우수·양호·보통·미흡·불량) |
| 4 | 최근 점검일 입력 | 다시 열었을 때 **차기 정기안전점검 예정일이 법정주기로 자동 산출되어** 표시됨(입력란이 아니다) |
| 5 | 중대결함 유무 선택 | 있음 / 없음만 고른다. 결함 유형·통보일은 FMS 중대결함사후관리가 원천이라 이 화면에서 받지 않는다 |
| 6 | 규모·이용인원 입력 | 입력한 값에 따라 위험도 요약의 "확보 변수"가 늘어남 |
| 7 | [보완입력 저장] | 팝업이 닫히고 "보완입력 저장됨" 안내. 목록·위험도의 등급·위험도 칸이 즉시 갱신 |
| 8 | 다시 열어 위험도 요약 확인 | 핵심 변수가 채워졌으면 "산정불가"가 풀리고 [근로자 위험성평가 연계]가 나타남 |
| 9 | 종사자 작업 위험도 함께 다뤄야 하는 경우 [근로자 위험성평가 연계] | 정기 위험성평가 화면으로 이동 |
| 10 | [FMS 전송(수정)] | 전송 결과 안내가 표시되고 연계 이력(SCR-FAC-004)에 기록됨 |

**분기 로직**

- **위험도 산정 가능 여부가 하단 버튼을 가른다** — 안전등급과 최근 점검일이 **둘 다 비어 있으면** 위험도가 "산정불가"가 되고, 이때는 [근로자 위험성평가 연계]를 내지 않는다. 둘 중 하나라도 채워지면 선택 연계 버튼이 나타난다. 이 버튼은 시설물 위험도 검토의 완료 신호가 아니라 청소·정비 등 종사자 작업 위험을 별도로 다룰 때 쓰는 연결이다.
- **중대결함 "있음"이면 기한 안내가 따라붙는다** — 결함을 통보받은 날이 **수신되어 있으면** **착수기한(통보일부터 2년 이내)**을 계산해 보여주고, **완료기한은 착수일부터 3년 이내**라는 기준을 함께 밝힌다(시설물안전법 제24조제1항제3호·시행령 제19조). 완료기한을 날짜로 단정하지 않는 이유는 기산점이 통보일이 아니라 **착수일**이고 착수일은 담당자만 아는 값이기 때문이다. 통보일이 없으면 안내는 나타나지 않는다 — 그리고 통보일은 **직접 입력받지 않으므로**, 중대결함사후관리 연계가 붙기 전까지 이 안내는 이미 통보일이 있는 건에서만 나타난다(§6 확정).
- **차기 정기안전점검 예정일은 입력이 아니라 산출값이다** — A·B·C 등급과 등급 미지정은 **반기 1회 이상**, D·E 등급은 **연 3회 이상**이다(시설물안전법 시행령 별표3). 최근 점검일에 등급별 주기를 더해 자동으로 내고 **입력란을 두지 않는다** — 법이 정한 값이라 담당자가 달리 적을 자리가 아니고, 입력란을 두면 법정 주기와 다른 날짜가 들어와 주기 초과 판정이 틀린다. 최근 점검일이 비어 있으면 "최근 점검일 입력 후 산출"로 표시한다.
- **D·E 등급은 법이 간격이 아니라 시기를 정한다** — 해빙기(2·3월)·우기(5·6월)·동절기(11·12월) 전 각 1회다(별표3 비고 3). 그래서 제안값 옆에 그 세 시기를 문구로 함께 낸다 — 날짜만 제안하면 담당자가 균등 간격으로 잡아 법정 시기를 벗어난다.

**엣지케이스**

- **저장하지 않고 닫으면 입력값은 사라진다.** 확인 없이 닫히므로 입력 도중 이탈에 대한 보호가 없다(§6 확정).
- **안전등급이나 최근 점검일을 바꿔도 차기 점검예정일 산출값은 그 자리에서 다시 계산되지 않는다.** 저장하고 팝업을 다시 열어야 갱신된 값이 보인다.
- **항목 축소(§6)로 사라진 입력란의 기존 값은 지워지지 않는다.** 저장은 화면에 있는 6항목만 덮어쓰고 나머지는 그대로 둔다 — 입력란이 없어졌다는 이유로 이미 확보한 값을 없애면 연계 이관 때 대조할 근거가 사라진다. 다만 그 값들은 이 화면에 더 이상 표시되지 않는다.
- FMS 기본현황 값이 모두 비어 있는 항목이라도 항목 자체는 숨기지 않고 "FMS 미제공"으로 남긴다 — 무엇을 못 받았는지가 곧 추가 연계 요청 목록이기 때문이다.
- 신규 등록 전송은 이 화면에서 제공하지 않는다. 대장에 없는 시설물을 FMS에 새로 올리려면 규모·구조 상세 정보가 함께 있어야 하는데 아직 확보되지 않아 막혀 있다(SCR-FAC-004 §4-2).

## 4. 화면 구성별 정리

### 4-1. FMS 기본현황 (읽기 전용)

- 구성: "읽기 전용" 표시와 함께 12개 항목 — 시설물번호 · 시설물명 · 구분/종류 · 시설물종별 · 관리주체코드 · 소유자 · 소재지 · 준공일자(경과 연수 병기) · 설계자 · 시공자 · 공사명 · 내진설계 적용 여부.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 팝업 열림 | 해당 시설물의 수신 값을 그대로 표시 | 값이 없으면 "FMS 미제공" |

- 상태: 이 구획에는 입력 수단을 두지 않는다. 값을 고쳐야 하면 우리 시스템에서 바꾸는 것이 아니라 FMS로 수정을 전송하고 다시 받아 확인한다(소유권 규칙은 SCR-FAC-005 §4-2). 단계상태로는 **수신 전(표시할 값 없음) → 수신됨 → 수정 전송 후 재수신 확인**의 세 국면을 가진다. 준공일자가 없으면 경과 연수도 표시하지 않는다.

### 4-2. 보완입력 (직접 채우는 값 — 6항목)

- 구성: "FMS 수신이 덮어쓰지 않음" 표시와 **두 부류를 가르는 안내 문구**, 그리고 6개 입력 항목.

| 부류 | 항목 | 왜 받는가 | 연계되면 |
|---|---|---|---|
| **연계 전 임시 입력**<br>(원래 FMS 소관) | 안전등급(A~E, 등급별 상태 설명 병기) | 위험도 1차 결정변수 | 점검진단실적 수신 → 입력란 닫힘 |
| | 최근 점검일 | 법정 주기 초과 판정 | 점검진단계획·실적 수신 → 닫힘 |
| | 중대결함 유무(있음/없음) | 즉시위험 · 위험도 가산 | 중대결함사후관리 수신 → 닫힘 |
| | 규모(값 + 단위) | 중대재해법 별표3 공중이용시설 판정 | 상세제원 수신 → 닫힘 |
| **담양군 관리**<br>(FMS 규격 밖) | 소관부서 | 점검 주체 — 없으면 누가 점검하는지 안 정해짐 | 계속 자체 관리 |
| | 이용인원(일평균) | 노출도 · 피해심도 | 계속 자체 관리 |

- **두 부류를 화면에서 갈라 밝힌다** — 라벨 하나로 묶어 두면 원래 FMS 소관인 항목까지 담양군 자체 데이터로 읽힌다. 실제로 2026-08-13 FMS 추가 연계 요청 검토에서 이 구획 전체가 "담양군이 별도 관리하는 데이터"로 읽혀 **요청 목록에서 FMS 소관 4축이 통째로 빠질 뻔했다.** 각 항목에도 `연계 전 임시 입력` / `담양군 관리 항목` 을 붙인다.
- **차기 정기안전점검 예정일은 입력 항목이 아니다** — 최근 점검일 + 등급별 법정주기(시행령 별표3) 산출값을 읽기 전용으로 낸다. `자동 산출` 표시와 주기 문구를 함께 붙인다.
- **중대결함은 유무만 받는다** — 유형·통보일은 받지 않는다. 중대결함은 FMS가 원천이고(표준연계에 등록·삭제 인터페이스가 없으며 조치 회신 인터페이스만 있다) 유형 목록은 시행령 제18조가 정한 값이라, 담당자가 고를 값이 아니라 **수신할 값**이다. 유형 기준표(구조안전 제1항 11호 / 공중 이용 부위 제2항 4호 — 통보 근거 조항이 달라 섞지 않는다)는 수신값을 읽기 위해 그대로 보존한다.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 항목 입력·선택 | 화면에만 반영(저장 전) | — |
| [보완입력 저장] | 입력한 값을 저장하고 팝업 닫음 | "보완입력 저장됨" + 목록·위험도 갱신 |
| 저장 시 값이 바뀐 항목이 있음 | 어떤 항목이 바뀌었는지 연계 이력에 기록 | SCR-FAC-004 이력에 "보완입력"으로 표시 |

- 상태: 빈 항목은 오류가 아니라 **아직 확보하지 못한 정보**로 다룬다(빈 상태 = 미확보). 단계상태는 **미확보 → 핵심 변수 확보(안전등급 또는 최근 점검일) → 위험도 산정 가능 → 전 항목 확보** 순이며, 위험도 요약의 "확보 변수" 수가 그 진척을 나타낸다. 중대결함을 통보받은 날짜는 현재 입력란이 없어, 이미 기록이 있는 시설물에서만 기한 안내가 표시된다(§6 확정).

### 4-3. 위험도 · 위험성평가 요약

- 구성: 위험도 배지(높음/보통/낮음/산정불가와 점수), 확보한 변수 목록, 산정불가일 때의 안내 문구.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 팝업 열림 | 현재 값 기준으로 위험도를 다시 계산해 표시 | 산정불가면 "핵심변수(안전등급·점검일) 부족 — 보완입력 후 착수" 안내 |

- 상태: 산정불가(핵심 변수 없음) / 산정됨(높음·보통·낮음) 두 상태로 갈린다. 산정불가일 때는 점수를 숫자로 내지 않는다 — 부족한 값을 0으로 처리해 낮은 점수를 보이면 안전한 시설물로 오해되기 때문이다(산정 규칙은 SCR-FAC-003 §6).

### 4-4. 개선조치 내역

- 구성: 건수 요약(전체 · 완료) + 표 — 유해위험요인/조치 · 부서 · 기한 · 상태 · 증빙 · [보기]. 이 시설물로 지정된 개선조치가 없으면 0건 표시와 함께 어디서 지정하는지 안내한다.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 팝업 열림 | 이 시설물로 지정된 개선조치를 모아 표시 | 0건이면 "위험성평가 보고서 검수에서 유해위험요인 행에 이 시설물을 지정하면 여기에 쌓입니다" |
| [보기] | 해당 개선조치의 상세로 이동 | SCR-IMP-002 |

- 상태: **0건(아직 지정된 조치 없음) / N건**으로 갈리며, 각 행의 단계상태는 **진행 → 기한 초과 → 완료**이고 완료 건에는 확인 상태(확인 대기 · 확인 완료 · 반려)를 함께 표시한다. 위험성평가 자료를 불러오지 못한 경우에는 건수를 0으로 보이지 않고 불러오지 못했다는 사실을 표시한다 — 0건과 조회 실패는 다른 상태이며, 섞으면 조치가 없는 시설물로 오독된다. 이 구획은 조회 전용이라 여기서 조치를 만들거나 고치지 않는다.

## 5. 유효성 검사

> 현재 프로토타입은 일부 검증을 아직 수행하지 않는다. 아래 표는 본개발에서 적용할 확정 검증 계약이며, 현재 차이는 구현 대상이다.

| 입력 항목 | 필수 | 형식/길이 규칙 | 오류 안내 |
|---|---|---|---|
| 안전등급 | 아니오. 근로자 위험성평가 연계 시 필수 | A~E 중 하나 | 평소 미선택은 "미평가". 연계 시 "안전등급 또는 최근 점검일을 입력하세요" |
| 최근 점검일 | 아니오 | 유효한 날짜, 오늘 이후 불가 | "점검일은 미래일 수 없습니다" |
| 중대결함 유무 | 아니오 | 있음 / 없음 | — |
| 규모(값·단위) | 관리대상 판정 시 조건부 필수 | 0 이상 숫자와 시설 종류에 맞는 단위 | "규모 값과 단위를 올바르게 입력하세요" |
| 소관부서 | 예 | 조직도에서 선택. 담양군 외 관리주체는 기관명 직접 입력 | "소관부서를 선택하거나 외부 소관 기관을 입력하세요" |
| 이용인원(일평균) | 아니오 | 0 이상 숫자. **0과 미입력을 구분해 저장** | "0 이상 숫자를 입력하세요" |

- **차기 점검예정일에는 검증이 없다** — 입력 항목이 아니라 산출값이라 사람이 틀리게 넣을 자리가 없다.
- **중대결함 유형·통보일, 보수·보강 착수일의 검증 계약은 여기서 뺐다** — 입력받지 않기로 확정했기 때문이다(§4-2·§6). 해당 값이 중대결함사후관리 연계로 들어오면 **수신 검증**으로 다시 정의한다(SCR-FAC-004).

## 6. 정책

- **보완입력은 6항목이다 — 소비처 없는 입력란을 두지 않는다(FDT-13 확정, 2026-08-13)** — 종전 13항목 중 **7개(차기 점검예정일·중대결함 유형·보수보강 진행·위험물 취급·인접 위험요소·좌표 위·경도)는 어느 화면도 읽지 않는 입력란**이었다. 저장했다가 다시 보여주는 것 외에 소비처가 없었다. 채워도 아무 일이 일어나지 않는 칸을 담당자에게 요구하면 곧 아무도 채우지 않고, 그때부터 **채워진 칸까지 신뢰를 잃는다.** 남긴 6개는 각각 쓰이는 곳이 있다 — 안전등급·최근 점검일·중대결함 유무·이용인원은 위험도 산정 변수이고, 규모는 중대재해법 별표3 공중이용시설 판정의 유일한 근거이며, 소관부서는 점검 주체다. **판단 기준은 "있으면 좋은 정보인가"가 아니라 "이 값이 바뀌면 화면의 무엇이 달라지는가"다.**
  - 뺀 항목이 불필요하다는 뜻이 아니다. 좌표는 지오코딩 일괄 확보 대상이고, 중대결함 유형·보수보강은 FMS 수신 대상이며, 위험물·인접 위험요소는 소비처(현장조사 축)가 생기면 그때 되살린다. **지금 손으로 받을 이유가 없을 뿐이다.**
  - **뺀 항목의 기존 저장값은 지우지 않는다** — 저장은 화면에 있는 6항목만 덮어쓴다. 연계 이관 때 수신값과 대조할 근거를 없애지 않기 위해서다.
- **'자체 소유'라는 한 덩어리 표기를 쓰지 않는다(FDT-13 확정)** — 이 구획에는 성격이 다른 두 부류가 섞여 있다. **안전등급·점검일·중대결함·규모는 원래 FMS 소관**(점검진단실적·중대결함사후관리·상세제원)인데 이번 수신분(시설물관리대장 기본현황)에 0건이라 임시로 받는 값이고, **소관부서·이용인원은 FMS 표준연계 규격 자체에 없어** 담양군이 계속 관리하는 값이다. 한 라벨로 묶으면 앞의 넷까지 담양군 데이터로 읽힌다 — 실제로 2026-08-13 FMS 추가 연계 요청 검토에서 이 구획 전체가 "담양군이 별도 관리하는 데이터"로 읽혀 **요청 목록에서 FMS 소관 4축이 통째로 빠질 뻔했다.** 화면은 두 부류를 갈라 적고 항목마다 `연계 전 임시 입력` / `담양군 관리 항목` 을 붙인다. 같은 구분을 연계 설정(SCR-FAC-005 §4-2)의 소유권 표도 쓴다.
  - **'자체 소유'는 원래 소유권 선언이 아니라 덮어쓰기 방지 규칙의 이름이었다** — 수신 반영이 이 칸을 건드리지 않는다는 뜻이다. 두 개념이 한 단어를 쓰고 있어 생긴 오독이므로 규칙 이름과 소유권 표기를 분리한다.
- **보완입력 저장과 FMS 전송은 같은 조건으로 다루지 않는다** — 보완입력은 우리 시스템 안의 값이라 틀리면 다시 고치면 되지만, **FMS 전송은 외부 정본을 바꾸는 행위**여서 되돌리려면 다시 전송해야 한다. 두 동작을 한 번의 판단으로 묶지 않고, 전송은 무엇이 바뀌는지 확인한 뒤 실행하는 별도 단계로 둔다. 전송 결과는 연계 이력(SCR-FAC-004 §4-3)에 남아 누가 언제 외부를 바꿨는지 되짚을 수 있다.
- **FMS 전송은 확인 단계를 반드시 거친다(FDT-01 확정)** — 누르면 바로 나가지 않고, **무엇이 어떻게 바뀌는지(항목·이전 값·이후 값)를 보여준 뒤 실행**한다. 별도 결재를 태우지는 않는다 — 결재를 붙이면 대장 오타 하나 고치는 데 며칠이 걸려 아무도 안 고치게 되고, 그때부터 대장이 현실과 어긋난다. 대신 실행자·시각·전송 내용을 연계 이력에 남겨 사후 추적으로 책임을 담보한다. **삭제 전송만 예외로 사유 입력을 필수**로 한다 — 되돌릴 수 없는 유일한 동작이다.
- **막는 검증과 알리는 검증을 구분한다(FDT-05 확정)** — 저장 자체를 **막는 것**은 ① 값의 형식이 틀린 경우(날짜가 아닌 날짜, 음수 면적) ② 시간 순서가 뒤집힌 경우(차기 점검일이 최근 점검일보다 이전) ③ 중대결함 "있음"인데 결함 유형이 비어 있는 경우 — 셋 다 그대로 저장하면 이후 계산이 틀리는 값이다. 그 밖은 **경고만 하고 저장은 허용**한다(법정 주기를 넘긴 차기 점검일, 준공일 대비 이례적인 값 등) — 현실에는 예외가 있고, 막아 버리면 담당자가 아무 값이나 넣어 통과시킨다. 경고는 저장 후에도 행에 남아 사라지지 않는다.
- **저장하지 않고 닫으면 확인을 받는다(FDT-06 확정)** — 값을 고친 뒤 닫으려 하면 "저장하지 않은 변경이 있습니다"로 되묻는다. 임시 보관(자동 저장)은 두지 않는다 — 저장한 값과 저장 안 한 값이 뒤섞이면 지금 화면의 숫자가 어느 쪽인지 알 수 없고, 이 화면의 값은 위험도 산정과 FMS 전송의 입력이라 그 모호함을 감당할 수 없다.
- **받은 값과 채운 값을 섞지 않는다** — FMS 기본현황은 고칠 수 없고 보완입력만 고칠 수 있다. 이 경계를 흐리면 대장을 다시 받았을 때 담당자가 채운 값이 지워지거나, 반대로 우리 쪽 임의 수정이 FMS 정본으로 올라간다. 소유권 목록은 연계 설정(SCR-FAC-005 §4-2)이 관리한다.
- **위험성평가를 시작할 수 있는 최소 정보는 네 축이다** — 안전등급 / 최근·차기 점검일 / 중대결함 유무 / 규모 대표값과 이용인원. FMS에서 이미 받은 경과연수·종별·내진 적용 여부와 합치면 위험도 산정이 성립한다. 네 축이 다 차야 하는 것은 아니고, 안전등급이나 최근 점검일 중 하나만 있어도 산정을 시작한다(SCR-FAC-003 §6).
- **점검 주기는 우리가 정하는 값이 아니다** — 관리주체는 소관 시설물의 안전점검을 정기적으로 실시할 의무가 있고(시설물안전법 제11조제1항), 실시시기는 시행령 별표3이 정한다. **정기안전점검은 A·B·C 등급과 등급 미지정이 반기 1회 이상, D·E 등급이 연 3회 이상**이며, D·E는 해빙기·우기·동절기 전 각 1회라는 **시기**까지 정해져 있다(별표3 비고 2·3). 화면은 제안 날짜와 이 주기 문구를 함께 낸다.
- **중대결함의 조치기한은 두 단계이고 기산점이 다르다** — 통보를 받은 날부터 **2년 이내에 착수**하고, 특별한 사유가 없으면 **착수한 날부터 3년 이내에 완료**해야 한다(시설물안전법 제24조제1항·시행령 제19조). 즉 완료기한은 통보일 기준이 아니라 착수일 기준이며, 최대 통보일로부터 5년까지 벌어질 수 있다. 화면은 착수기한만 날짜로 계산하고 완료기한은 기준을 문구로 밝힌다 — 착수일을 모른 채 완료기한을 날짜로 단정하면 지연 판정이 틀린다. 조치를 마치면 결과를 통보해야 한다(제24조제3항). **통보일은 입력이 아니라 수신으로 받는다(FDT-03 → FDT-13으로 정정, 2026-08-13)** — 통보일이 없으면 착수기한을 계산할 수 없다는 판단은 그대로다. 바뀐 것은 **조달 경로**다. 중대결함은 FMS가 원천이라(표준연계에 등록·삭제 인터페이스가 없고 조치 회신만 있다) 유무를 넘어선 세부값을 담당자가 손으로 적을 자리가 아니고, 손으로 받으면 FMS 수신값과 어느 쪽이 맞는지 대조할 일이 생긴다. 중대결함사후관리 연계가 붙기 전까지 **착수기한 안내는 이미 통보일이 있는 건에서만** 나타나고, 그 사실을 화면에 드러낸다. 위험도 산정에 필요한 것은 유무뿐이라 이 축소로 산정이 막히지 않는다.
- **중대결함의 조치는 개선조치 대장으로 넘겨 관리한다(FDT-08 확정)** — 이 화면에만 두면 시설물 상세를 열어 본 사람만 기한을 알고, 담당자 배정·독촉·완료 확인 같은 수단이 하나도 없다. 개선조치 대장에는 이미 담당자·기한·완료 확인·독촉이 갖춰져 있으므로 그것을 다시 만들지 않는다. 다만 **출처를 "시설물 중대결함"으로 구분**해 위험성평가에서 나온 건과 섞이지 않게 하고, 기한은 법정 기한(착수 2년)을 기본값으로 채우되 담당자가 앞당길 수 있게 한다 — 법정 기한은 상한이지 목표가 아니다. 이 화면에는 연결된 개선조치의 상태만 표시한다.
- **법령 근거는 법률·시행령까지 확보됐다(2026-08-11 해소)** — 시설물안전법 법률 4개 조문(§7 종류·§11 안전점검·§16 안전등급·§24 보수보강)과 시행령 5건(§12·§18·§19·별표3·별표8)을 수록해 **안전등급 구간·정기안전점검 주기·중대결함 종류·보수보강 기한이 모두 확정값**이 됐다. 남은 위임은 국토교통부령뿐이며(중대결함의 "그 밖에 국토교통부령으로 정하는 결함", 안전등급 지정·변경 절차) 그 두 항목은 목록 말미의 포괄 선택지로만 두고 세부를 지어내지 않는다.
- **안전등급은 판단 결과이지 입력값이 아니다** — 안전점검등의 실시결과에 따라 지정하며 구간은 시행령 별표8이 정한다(A 우수 / B 양호 / C 보통 / D 미흡 / E 불량). 원래 점검·진단 실적에서 나오는 값이라 장기적으로는 FMS 점검진단실적 연계로 받아야 하고 직접 입력은 연계 전까지의 임시 경로다. 연계가 붙으면 이 항목의 소유권이 자체에서 FMS로 넘어간다(SCR-FAC-005 §6).
- **안전등급의 출처 확인은 연계로 해결한다(FDT-02 → FDT-13으로 정정, 2026-08-13)** — 등급만 받으면 "담당자가 보기에 그쯤"인지 "정밀안전점검 결과"인지 구분되지 않는다는 문제 인식은 그대로다. 다만 그 해법으로 **점검 종류·근거 문서 첨부를 덧붙이지 않는다** — 안전등급 자체가 점검진단실적 연계로 넘어갈 임시 입력인데, 그 위에 부속 입력을 쌓으면 **연계가 붙는 순간 함께 버려질 항목을 지금 담당자에게 요구하는 것**이 된다. 대신 등급과 최근 점검일을 함께 받아 최소한 "언제의 판정인가"는 남기고, 등급이 임시 입력이라는 사실을 화면에 상시 표시한다. 출처 신뢰성은 점검진단실적 수신이 붙는 시점에 확보한다.
- **시설물과 근로자 위험성평가는 평가 단위가 아니라 항목 단위로 선택 연계한다** — 정기 위험성평가는 부서 단위로 한 해 한 건이고, 용역 보고서 한 건에 여러 시설물의 종사자 작업 지적사항이 섞여 나올 수 있다. 그래서 "시설물 하나 = 평가 하나"로 잇지 않고, **검수 표의 유해위험요인 행에 시설물을 지정하는 방식**(SCR-RISK-001 §4-5)으로 잇는다. 이 화면의 [근로자 위험성평가 연계]는 그 화면으로 데려다주는 역할이고, 실제 연결은 행에서 이루어진다. 이 연결은 시설물안전법상 점검·등급 판정과 별개다.
- **검수 표에서 고를 수 있는 시설물은 좁히지 않는다(FDT-04 확정)** — 소관부서가 대부분 비어 있어 부서로 좁히면 고를 수 있는 시설물이 사라진다. 대신 목록을 **소관부서가 자기 부서인 것 → 소관 미상 → 그 밖**의 순서로 정렬해 자기 것이 먼저 보이게 하고, 소관이 다른 시설물을 고르면 "소관부서가 다릅니다"로 알리되 막지는 않는다(도로·하천처럼 실제로 여러 부서가 함께 다루는 시설이 있다). 소관 미상 시설물을 고르면 **그 자리에서 소관부서를 채울 수 있게** 하고, 채운 값은 대장에 반영된다 — 결측을 발견한 사람이 그 자리에서 메우는 것이 가장 값싸다.
- **소관부서는 직접 입력이 아니라 조직도에서 고른다(FDT-09 확정)** — 직접 입력은 "환경과"와 "환경 과"와 "환경과(수질)"를 다른 부서로 만들고, 그러면 부서별 집계가 조용히 어긋난다. 조직도 선택기를 쓴다. 다만 **담양군 조직도에 없는 관리주체**(국가·도·민간)가 실제로 있으므로, 선택기 아래에 "담양군 외 관리주체" 항목을 따로 두고 기관명을 자유 입력으로 받는다 — 이 경우 부서별 집계에서는 빠지고 소관구분만 바뀐다. **현재 프로토타입은 이 확정을 따르지 않는다** — 소관부서가 자유 입력 한 칸이라 위에 적은 표기 흔들림을 그대로 허용한다. 항목 축소(FDT-13)와 별개인 **구현 차이**이며, 본개발은 이 확정대로 구현한다(기획 미결이 아니다).
- **잇는 키는 이름이 아니라 시설물번호다** — 같은 이름의 시설물이 실제로 있고 시설물은 개명·통폐합된다. 이름으로 이으면 대장을 다시 받는 순간 연결이 조용히 끊긴다.
- **보여 주는 이름은 대장에서 매번 찾는다** — 다른 화면(개선조치 등)이 들고 있는 시설물 이름은 그 건을 만들 때 복사해 둔 사본이라, 시설물이 개명되면 대장은 새 이름인데 그 화면만 옛 이름으로 남는다. **잇는 키가 멀쩡해 연결은 유지되므로 오류로 드러나지 않고 보이는 이름만 조용히 갈린다** — 담당자가 현장에서 그 이름의 시설물을 못 찾게 된다. 그래서 표시 순서는 **대장의 현재 이름 → 저장된 사본 → 시설물번호**다. 사본을 버리지 않는 이유는, 폐지된 시설물이 대장에서 빠졌을 때 이름조차 없으면 지난 이력이 번호만 남은 줄이 되기 때문이다.
- **지정은 선택이지 필수가 아니다** — 작업 행동·화학물질·보건처럼 특정 시설물에 붙지 않는 유해위험요인이 많다. 필수로 걸면 담당자가 아무 시설물이나 지정하게 되고, 그 순간 이 화면의 개선조치 내역이 거짓 기록이 된다.
- **점검주기표는 확정값으로 적용한다(FDT-07 확정)** — 간이 제안값을 쓰던 자리를 시행령 별표3으로 대체했다. 차기 점검일 제안은 최근 점검일에 등급별 주기를 더해 계산하고, 등급이 없으면 반기 1회를 적용한다(별표3 비고 2 — 등급 지정 전에도 반기 1회). **주기를 넘긴 건은 막지 않고 경고로 드러낸다** — 이미 지난 일을 입력 단계에서 막으면 기록 자체가 안 남는다. 경고는 목록의 행 태그와 위험도 산정(SCR-FAC-003)에 함께 반영된다. 정밀안전점검·정밀안전진단 주기는 종별에 따라 대상이 갈리므로 1·2종 시설물이 들어올 때 함께 적용한다.
- **자체 촬영 사진 업로드는 구축 범위에서 제외한다(FDT-10 → 2026-08-14 확정)** — 전경·정측면 사진이 없어 시설물을 눈으로 확인할 방법이 없다는 문제 인식은 그대로다. 다만 사진을 소비할 화면(위험성평가·개선조치의 "개선 전" 자료)이 이 시설물 축과 이어져 있지 않고, RFP에도 시설물 사진 요구가 없다. 소비처 없는 입력란을 두지 않는다는 위 원칙을 사진에도 똑같이 적용해 **자체 촬영 업로드는 만들지 않는다** — 소비 화면(현장조사 축)을 신설하는 것은 별도 변경 요청 사안이다. 사진의 확보 경로는 **FMS 추가 연계 수신**으로 확정한다(사진 파일명 필드는 FMS 규격에 있으나 수신 채움률 0% — 추가 연계 신청 항목, SCR-FAC-004 §6).
- **조치 실적은 위험도를 낮추지 않는다(FDT-11 확정)** — 개선조치를 완료했다고 점수를 깎으면, 실제 상태가 그대로인데 **서류만으로 위험도가 내려간다**. 위험도는 시설의 상태(안전등급·점검 경과·중대결함)로만 계산하고, 상태가 바뀌었다면 그것은 다음 점검에서 등급으로 나타나야 한다. 대신 조치 실적은 **점수가 아니라 이력으로** 이 화면과 위험도 화면에 함께 보여준다 — "위험도는 높은데 조치가 여러 건 완료됐다"는 상태 자체가 판단에 필요한 정보다.
- **조치 실적을 FMS로 되돌려 보내는 것은 이번 범위가 아니다(FDT-12 확정)** — 보낼 대상(보수·보강 실적·중대결함 사후관리)은 표준연계에 있지만, 우리 쪽 개선조치는 위험성평가에서 나온 것이라 **시설물안전법이 말하는 보수·보강과 범위가 같지 않다**. 범위가 다른 것을 같은 칸에 넣으면 FMS 정본이 오염된다. 이번 구축은 대장 수정·삭제 전송까지만 구현하고 조치 실적 역전송은 구축하지 않는다. 향후 별도 변경 요청이 승인될 때에만 중대결함 출처·대상·시점·항목 계약을 새로 확정한다(SCR-FAC-004).
- **이 연결이 FMS로 되돌려 보낼 내용을 만든다** — 지금 전송할 수 있는 것이 대장 수정·삭제뿐인 이유는 우리 시스템이 시설물에 대해 만들어낸 정보가 없기 때문이다. 조치 실적이 시설물에 쌓이면 FMS 표준연계가 받도록 정해 둔 보수·보강 실적·중대결함 사후관리로 보낼 근거가 생긴다(SCR-FAC-004 §6).

---

## 7. 미결사항

없음. 기획 판단은 모두 §6에서 확정했다 — 전송 승인 단계·안전등급 입력 근거·중대결함 통보일과 후속 관리·시설물 지정 범위·검증 채택 범위·이탈 보호·점검주기표·소관부서 입력 방식·자체 촬영 사진 제외·조치 실적의 위험도 반영과 FMS 회신, 그리고 **항목 축소(FDT-13)**.

법령 근거는 2026-08-11 시설물안전법 법률·시행령 수집으로 확보됐다. 남은 위임(국토교통부령)은 조문 자체가 포괄 위임이라 목록 말미의 포괄 선택지로 두고 세부를 지어내지 않는다.

### 참고 — 연계 구현 범위

- **FMS 추가 연계 5축**(안전등급 · 최근 점검일 · 중대결함 유형·통보일 · 상세제원(규모) · 전경·정측면 사진)은 미결이 아니라 **연계 구현 범위**다 — 같은 신청 **한 건**(국토안전관리원, 담양군 신청)이고, 요청 항목의 정본은 SCR-FAC-004 §6, 연계 전 확정 동작은 [미결사항 목록 §4](99_미결사항목록.md)다. 연계 전 임시 입력 4종의 동작(등급 없으면 `산정불가`, 점검일 없으면 주기 초과 미판정, 통보일 없으면 착수기한 미계산, 규모 없으면 공중이용시설 미판정)은 §5·§6에 확정돼 있다. **시스템 개통 전에 신청해야 한다** — 개통 후에 붙이면 그 사이 담당자가 채운 값과 수신값을 대조하는 일이 통째로 생긴다(SCR-FAC-004 §6 FSY-10).
- **소관부서의 조직도 갭**(부서 명단 일부 등록)은 행정포털 조직도 연계 축이다 — 같은 목록 §4. 입력 방식 자체는 §6 FDT-09에서 확정했다.
- **이 화면의 프로토타입 데이터(FMS 80건·보완입력 값)는 시연용 더미다.** 연계가 열리면 구조를 바꾸지 않고 수신값으로 교체하며, 화면은 그때까지 시연 자료임을 표시한다.
