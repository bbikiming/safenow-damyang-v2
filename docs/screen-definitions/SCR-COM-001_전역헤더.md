# 화면 정의서 — 전역 헤더(상단바)

> 화면 ID: SCR-COM-001 · 화면 유형: 공통 크롬 · 기획 관점(v6) · 구현 정합 2026-08-11
> 판단이 필요했던 항목은 §6 정책에서 확정했습니다.

## 1. 화면 정보

| 항목 | 내용 |
|---|---|
| 화면 ID | SCR-COM-001 |
| 화면명 | 전역 헤더(상단바) |
| URL 경로 | 전 화면 공통 — 특정 주소가 없다 |
| 상위 메뉴 | 공통/전역 |
| 화면 유형 | 공통 크롬 |

모든 화면 맨 위에 자동으로 붙는 띠다. **지금 누구로 보고 있는지**, **처리할 알림이 몇 건인지**, **이 화면이 무엇을 하는 곳인지**를 한 자리에서 알려 준다. 화면마다 다시 만들지 않고 한 곳에서 그리므로 어느 화면에서도 같은 자리에 같은 것이 있다. 구성은 좌측 정체성(기관명·시연본 표시)·우측 도구(자료 준비·알림·권한 전환) 두 덩어리이며, 알림은 전역 알림 드롭다운(SCR-COM-004)으로, 자료 준비는 외부 자료·연계 준비 목록으로 이어진다.

## 2. 권한 정보

- 메뉴 접근·보기·수정은 시스템 관리의 메뉴 관리(SCR-ADMIN-005)와 권한 관리(SCR-ADMIN-006)에서 설정한다.
- 이 화면 정의서에서는 역할별 권한과 열람 범위를 별도로 정하지 않는다.
- 헤더 자체는 전 사용자에게 보인다. 다만 **권한 전환은 시연용 수단**이며 실서비스에서는 로그인한 사람의 정보만 표시한다(§6).

### 분기 로직

- **접속자 계층이 표시 문구를 가른다** — 이름 아래에 직위와 소속을 함께 적는다. 같은 이름이라도 어느 자리에서 보고 있는지에 따라 화면이 달라지므로, 그 사실을 항상 눈에 두는 것이 이 자리의 목적이다.
- **도움말은 등록된 화면에만 버튼이 나온다** — 열어 봐야 «준비 중»이라고 말하는 버튼은 도달할 수 없는 수단이다. 어느 화면에서나 같은 세기로 강조하면 곧 무시된다.
- **화면 폭이 좁아지면 좌측이 먼저 접힌다** — 기관명 대신 햄버거 버튼이 나오고, 사이드바는 서랍으로 바뀐다. 우측 도구(알림·권한)는 폭과 무관하게 남는다 — 좁은 화면에서도 알림은 놓치면 안 된다.
- **드롭다운은 한 번에 하나만 열린다** — 알림과 권한 전환을 동시에 펼치지 않는다.

### 예외·경계 시나리오

| 상황 | 화면 반응 |
|---|---|
| 읽지 않은 알림이 0건 | 숫자 배지를 그리지 않는다 — 0을 표시하면 눈이 그 자리를 계속 확인하게 된다 |
| 외부 자료가 모두 수신됨 | 칩을 그대로 두되 강조하지 않고 수신 완료 상태를 보여 준다 |
| 권한 전환 직후 | 바뀐 관점을 알리는 짧은 안내를 한 번 띄운다 — 화면이 갑자기 달라진 이유를 알 수 있어야 한다 |
| 드롭다운이 열린 채 다른 곳을 누름 | 드롭다운을 닫는다 |
| 드롭다운이 열림 | 화면 우하단의 떠 있는 안내 패널을 함께 접는다 — 겹쳐서 목록을 가리면 안 된다 |

## 4. 화면 구성별 정리

### 4-1. 좌측 — 기관 정체성

- 구성: 기관명·시스템명 · (좁은 화면에서) 메뉴 열기 버튼.
- **«검토 전 시연본» 표시는 두지 않는다(2026-08-19 확정)** — 화면은 완성된 시스템의 말로만 한다. 미구현·예시 자료를 밝히는 일은 그 자리에서 하고(예시 자료 칩·「연계 후 제공」 안내), 헤더에 상시 딱지를 붙이지 않는다. **되살리지 말 것.**

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 기관명 선택 | 대시보드로 이동한다 | index.html |
| 좁은 화면에서 메뉴 버튼 선택 | 사이드바를 서랍으로 연다 | SCR-COM-003 |

- 상태: 넓은 화면에서는 기관명이, 좁은 화면에서는 메뉴 버튼이 나온다. (구 «검토 전» 표시 서술은 위 확정으로 삭제됐다.) 감추지 않는다.

### 4-2. 우측 — 도움말 [?]

- 구성: 물음표 버튼 하나. 누르면 **이 화면에서 하는 일 · 자주 하는 일(바로가기) · 관련 법령 · 단계별 안내 시작**을 담은 시트가 열린다.
- **도움말이 등록되지 않은 화면에는 버튼을 내지 않는다** — 열어 봐야 «준비 중»이라고 답하는 버튼은 도달할 수 없는 수단이다.
- 바로가기는 **이미 있는 진입점만** 가리킨다. 도움말 때문에 새 동작을 만들지 않는다.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| [?] 선택 | 이 화면의 도움말 시트를 연다 | 화면을 떠나지 않는다 |
| 자주 하는 일 선택 | 그 진입점으로 이동하거나 그 동작을 연다 | 실재하는 수단만 나열한다 |
| 단계별 안내 시작 | 그 화면의 안내를 시작한다 | 안내가 있는 화면에만 나온다 |
| 첫 방문 | 그 화면에서 한 번만 안내 배너를 띄운다 | 닫으면 기억한다 |

- 상태: **있음 / 없음(버튼 미노출)** 두 가지다.
- **외부 자료·연계 준비 목록은 2026-08-19에 헤더에서 뺐다.** 그 축은 «사용자가 쓰는 자리»가 아니라 «외부에서 무엇이 들어오는가»라 시스템 관리 &gt; 연계 관리(SCR-ADMIN-004)가 단일 창구다. **헤더로 되돌리지 말 것.**

### 4-3. 우측 — 알림 벨

- 구성: 벨 모양 버튼 + 읽지 않은 건수 배지.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 벨 선택 | 알림 드롭다운을 연다 | SCR-COM-004 |
| 읽지 않은 알림이 생김 | 배지 숫자가 올라간다 | — |
| 읽지 않은 알림이 0건 | 배지를 그리지 않는다 | — |

- 상태: **읽지 않음 있음 / 없음** 둘이다. 드롭다운의 열림·닫힘은 SCR-COM-004가 다룬다.

### 4-4. 우측 — 접속자와 권한 전환

- 구성: 접속자 이름·직위·소속 · 계층 배지 · (시연) 다른 직위로 보기.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 접속자 영역 선택 | 전환 가능한 직위 목록을 펼친다 | 시연용 수단임을 함께 밝힌다 |
| 직위 선택 | 그 관점으로 화면 전체를 다시 그린다 | 바뀐 관점을 알리는 안내를 한 번 띄운다 |
| 이미 선택된 직위 | 표시만 하고 다시 그리지 않는다 | — |

- 상태: **닫힘 / 열림**이며, 선택된 직위가 현재 관점이다. 계층은 총괄·관리감독자·업무담당자 세 가지로 구분해 보여 준다 — 무엇을 할 수 있는지가 계층에서 갈리기 때문이다.

## 6. 정책

- **헤더를 화면마다 다시 만들지 않는다** — 한 곳에서 그려 전 화면에 붙인다. 화면별로 따로 만들면 같은 기능이 자리마다 달라지고, 고칠 때 화면 수만큼 손대야 한다.
- **권한 전환은 시연용이다** — 실서비스에서는 로그인한 사람의 정보만 표시하고 전환 수단을 두지 않는다. 지금 남겨 둔 이유는 계층별로 화면이 어떻게 달라지는지 한 자리에서 보여 주기 위해서다.
- **헤더에 «검토 전» 딱지를 붙이지 않는다(2026-08-19 확정)** — 화면은 완성된 시스템의 말로만 한다. 확정본으로 오해하는 것은 상시 딱지가 아니라 **그 자리에서 사실을 밝혀** 막는다 — 예시 자료에는 「예시 자료」 칩을, 아직 안 되는 기능에는 「무엇 이후 제공」을 적는다.
- **알림 0건에 0을 그리지 않는다** — 배지는 처리할 것이 있을 때만 나타난다.
- **드롭다운과 떠 있는 안내 패널이 겹치지 않는다** — 드롭다운이 열리면 패널을 접는다. 레이어 순서를 뒤집지 않고 접는 쪽을 택한 이유는, 패널이 뜨는 자리가 원래 그 자리이기 때문이다.
- **좁은 화면에서 우측 도구를 버리지 않는다** — 접히는 것은 좌측이다. 알림과 접속자 정보는 좁은 화면에서 더 필요하다.
- **법령 근거를 붙이지 않는다** — 공통 크롬은 법령이 명한 의무의 직접 이행 수단이 아니다. 근거 없음도 정보이며 규칙은 공통 근거 연계(SCR-COM-008)를 따른다.

## 7. 미결사항

없음. 표시 항목·도움말 버튼의 노출 조건·알림 배지 규칙·권한 전환의 성격과 실서비스 처리·좁은 화면 우선순위·겹침 처리는 모두 §6에서 확정했다.

실제 로그인 연동은 미결이 아니라 **본개발 구현 범위**이며, 무엇을 표시할지는 §4에 정해져 있다.
