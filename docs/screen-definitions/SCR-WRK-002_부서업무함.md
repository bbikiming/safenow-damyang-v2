- **배정 대기는 담당자가 없고 일이 남은 건만 센다** — 원본에서 완료된 업무는 배정 대상으로 되살리지 않는다.
- **반려되면 같은 담당자에게 돌아간다** — 담당자를 자동 해제하지 않고 사유와 재제출 요구를 표시한다.
- **완료 후 담당자 변경을 막는다** — 완료 당시 책임자 이력을 보존한다.
- **부서장 미등록은 자동 대체하지 않는다** — `부서장 미등록`으로 표시하고 지정 권한자를 지어내지 않는다.

## 4. 화면 구성별 정리

### 4-1. 부서·요약·탭

- 구성: 부서 선택, 배정 대기·미배정 지연·진행·완료 요약, 배정·구성원별 현황 탭.
- 부서 선택지는 현재 사용자의 데이터 범위 안에서만 만든다.

### 4-2. 배정 목록

- 열: 업무·회차·기한·상태·담당자·관리.
- 상태: 미배정·미배정 지연·배정됨·제출·확인·반려·완료를 서로 겹치지 않게 표시한다.
- 담당자 선택 시 같은 부서 활성 구성원만 제공하고, 변경 시 사유를 기록한다.

### 4-3. 구성원별 현황

- 활성 구성원별 담당 업무 수·진행·지연·완료와 담당 업무 목록을 표시한다.
- 담당 업무가 없는 구성원도 0건으로 표시한다.
- 팀 이름은 표시 정보이고 실제 배정 범위는 부서 기준이다.

## 6. 정책

- **개인 배정은 부서가 한다** — 재난안전과는 부서까지만 정하고 부서장·지정 담당자가 실제 수행자를 고른다.
- **행정포털 조직도가 단일 출처다** — 전입자는 활성화 뒤 선택하고 전출자는 신규 배정에서 제외한다. 기존 이력의 이름은 보존한다.
- **담당자 변경은 진행 전 또는 반려 상태에서만 허용한다** — 제출·확인·완료 뒤에는 당시 책임자를 보존한다.
- **배정과 내 할일은 같은 기록을 쓴다** — 한쪽에서 바꾸면 다른 쪽이 즉시 따라오고 중복 배정 레코드를 만들지 않는다.
- **팀 정보 미수신은 개발 차단이 아니다** — 부서 단위로 배정하고 실제 팀 편제가 들어오면 표시·조건만 확장한다.

## 7. 미결사항

없음. 개인 배정 주체·조직도 출처·상태·담당자 변경·반려 복귀·내 할일 연계를 모두 §3~§6에서 확정했다. 전체 조직 명단은 외부 준비사항이며 부서 단위 대체 동작으로 개발한다.
