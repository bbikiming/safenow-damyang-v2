# 화면 정의서 — 알림 관리

> 화면 ID: SCR-ADMIN-002 · 화면 유형: 설정 + 이력 · 기획 관점(v6) · 구현 정합 2026-08-12
> 판단이 필요했던 항목은 §6 정책에서 확정했습니다.

## 1. 화면 정보

| 항목 | 내용 |
|---|---|
| 화면 ID | SCR-ADMIN-002 |
| 화면명 | 알림 관리(규칙 설정·발송 이력) |
| URL 경로 | admin-notify.html |
| 상위 메뉴 | 시스템 관리 > 알림 관리 |
| 화면 유형 | 설정 + 이력 |

**어떤 일이 생겼을 때 누구에게 알릴지**를 정하고, 실제로 무엇이 나갔는지 되짚는 화면이다. 안전보건 업무는 기한이 있는 일이 많아 알림이 없으면 놓치고, 반대로 아무에게나 자주 보내면 곧 무시된다. 그래서 규칙을 한 곳에서 정하고 발송 결과를 남긴다. 구성은 알림 규칙 설정과 발송 이력 두 덩어리이며, 실제 발송은 각 업무 화면이 하고(SCR-EDOC-009) 받는 사람은 전역 알림 드롭다운(SCR-COM-004)에서 확인한다.

---

## 2. 권한 정보

- 메뉴 접근·보기·수정은 시스템 관리의 메뉴 관리(SCR-ADMIN-005)와 권한 관리(SCR-ADMIN-006)에서 설정한다.
- 이 화면 정의서에서는 역할별 권한과 열람 범위를 별도로 정하지 않는다.
- 규칙을 바꾸면 전 사용자의 알림이 달라지므로 **시스템 관리자만** 들어온다.

## 3. 진입 / 이탈 경로 및 사용자 시나리오

| 구분 | 연결 화면 | 조건 / 트리거 |
|---|---|---|
| 진입 | 시스템 관리 > 알림 관리 | 메뉴 선택 |
| 진입 | 전역 알림 드롭다운 | 전체 보기 선택(SCR-COM-004) |
| 이탈 | 각 업무 화면 | 이력 항목이 가리키는 건으로 이동 |

| 단계 | 사용자 행동 | 화면 반응 |
|:--:|---|---|
| 1 | 화면에 들어온다 | 어떤 이벤트에 언제 누구에게 보내는지 표로 보여 준다 |
| 2 | 규칙을 바꾼다 | 채널과 수신 대상을 고른다 |
| 3 | 발송 이력을 확인한다 | 일시·채널·내용·수신자·결과를 조회한다 |
| 4 | 실패 건을 찾는다 | 결과로 좁혀 무엇이 안 갔는지 본다 |

### 분기 로직

- **이벤트마다 시점이 다르다** — 기한 임박처럼 **시간이 지나면** 나가는 것과, 배정·반려처럼 **누가 무언가를 하면** 나가는 것이 있다. 앞은 주기적으로 확인해야 하고 뒤는 그 행위에 붙는다.
- **수신 대상은 역할로 정한다** — 사람 이름으로 지정하지 않는다. 이름으로 두면 그 사람이 옮기거나 퇴직할 때 알림이 끊기고, 누가 고쳐야 하는지도 모른다. **담당자·부서장·주관부서·시스템 관리자** 같은 역할로 정하면 사람이 바뀌어도 이어진다.
- **채널을 이벤트마다 고른다** — 현재 프로토타입 표에서는 문자·메일 선택 UX를 시연한다. 체크 상태와 성공·실패 이력은 모두 `시연용`이며 실제 발송 결과가 아니다. **외부 채널(SMS·메일·Push)은 본개발 연계 구현 범위**(RFP SFR-017)이고, 연계 전에는 시스템 내부 알림만 실제 기록한다.
- **이력은 고칠 수 없다** — 규칙은 바꿀 수 있지만 이미 나간 기록은 바꾸지 않는다. 이력이 바뀌면 "보냈다"를 증명할 수 없다.

### 예외·경계 시나리오

| 상황 | 화면 반응 |
|---|---|
| 모든 채널을 끈 이벤트 | 저장은 되지만 **알림이 나가지 않는다**는 사실을 경고한다 — 조용히 꺼진 규칙이 가장 찾기 어렵다 |
| 수신 대상이 비어 있는 규칙 | 저장을 막는다 — 보낼 곳 없는 규칙은 규칙이 아니다 |
| 수신 대상 역할에 사람이 없음 | 규칙은 유효하되 그 사실을 드러낸다 — 예를 들어 선임 공백인 자리로는 알림이 갈 곳이 없다 |
| 외부 발송 실패 | 일시 장애는 공통 연계 계약대로 최대 3회 자동 재시도하고, 모두 실패하면 최종 실패 사유와 시도 횟수를 남겨 담당자 재처리로 전환한다 |
| 같은 이벤트가 연달아 발생 | 이력에 각각 남긴다 — 몇 번 나갔는지가 재촉 이력의 핵심이다 |
| 이력이 0건 | 아직 발송이 없음을 표시한다 — 규칙이 잘못된 것인지 일이 없었던 것인지 구분해 안내한다 |
| 규칙을 바꿈 | 이미 나간 알림에 소급 적용하지 않는다 |

## 4. 화면 구성별 정리

### 4-1. 알림 규칙 설정

- 구성: 이벤트 · 시점 · 문자 · 메일 · 수신 대상 다섯 열의 표.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 채널 켜고 끄기 | 그 이벤트의 발송 경로를 바꾼다 | 저장해야 반영된다 |
| 수신 대상 지정 | 역할로 고른다 | 사람 이름으로 지정하지 않는다 |
| 모든 채널을 끔 | 저장하되 알림이 나가지 않음을 경고한다 | — |
| 수신 대상을 비움 | 저장을 막는다 | 보낼 곳 없는 규칙은 만들 수 없다 |
| 문자·메일 선택 | 프로토타입에서는 설정 UX만 바꾼다 | 화면 상단에 실제 발송되지 않는 시연용 값임을 상시 표시한다 |

- 상태: 이벤트마다 문자·메일 **선택 / 미선택**이 갈린다. 현재 체크값은 시연 초기값이며 저장 버튼도 프로토타입 토스트만 낸다. 본개발에서는 내부 알림·SMS·메일·Push의 사용 가능 상태와 선택값을 분리한다.

### 4-2. 발송 이력

- 구성: 일시 · 채널 · 내용 · 수신자 · 결과 다섯 열의 표와 조회 조건.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 화면 진입 | 최근 발송을 최신 순으로 보여 준다 | — |
| 결과로 좁힘 | 성공·실패만 남긴다 | 실패를 먼저 찾을 수 있어야 한다 |
| 기간으로 좁힘 | 그 기간의 발송만 남긴다 | 장애는 대개 "언제부터"에서 시작한다 |
| 이력 항목 선택 | 그 알림이 가리키던 건으로 이동한다 | 가리키는 건이 없어졌으면 그 화면이 알린다 |
| 실패 건 | 사유·시도 횟수를 함께 표시한다 | 최대 3회 기술 재시도 후 최종 실패면 담당자 재처리 |

- 상태: 프로토타입 표의 성공·실패 행은 레이아웃 확인용 **시연 이력**이다. 본개발 건별 상태는 **대기 / 성공 / 실패**이며, 목록 전체로는 **비어 있음 / 있음 / 조건 결과 없음** 세 상태를 갖는다. **전체 이력을 보관**하며 전역 드롭다운처럼 상한으로 밀어내지 않는다.

### 4-3. 외부 발송 관리(본개발 연계 구현 범위)

- SMS는 분류·수신번호·내용 검색, 전체/개인/기관 총괄/기관 담당자 수신 구분, 엑셀 업로드, 예약/즉시 발송을 제공한다. 예약 건은 발송 전까지만 취소할 수 있다.
- 수신번호는 조직도 연계값을 기본으로 하고 목록에는 마스킹해 표시한다. 수기 번호는 엑셀 업로드 발송에서만 허용하며 출처를 `수기 업로드`로 남긴다. 엑셀 오류 행은 정상 행과 분리해 오류 사유 파일로 제공하고 정상 행만 발송한다.
- 메일·Push는 채널 사용 가능 여부와 연계 상태를 표시하고, Push는 URL response 방식으로 처리한다.
- 외부 모듈 응답을 발송 건별 `대기 / 성공 / 실패`로 저장하며 실패 사유를 함께 보관한다. 일시 장애는 최대 3회 자동 재시도하고 최종 실패 후에는 사용자가 원인을 확인한 뒤 새 발송으로 실행한다.
- 앱·exe 설치 없이 만들 수 있는 바탕화면 바로가기 생성 안내를 제공한다.
- 프로토타입은 이 연계 구획을 실제로 호출하지 않으며 화면 상단과 카드 제목에 `시연용`을 표시한다.

## 6. 정책

- **수신 대상을 역할로 정한다** — 사람 이름으로 두면 인사이동·퇴직 때 알림이 조용히 끊기고, 누가 고쳐야 하는지도 모른다.
- **조용히 꺼진 규칙을 만들지 않는다** — 모든 채널을 끄면 경고한다. 알림이 안 오는 이유를 나중에 찾는 일이 가장 오래 걸린다.
- **기술 재시도와 업무 재발송을 구분한다** — 일시적 연계 오류는 공통 계약대로 최대 3회 자동 재시도하되 같은 발송 건의 시도 이력으로 묶는다. 3회 실패 뒤에는 자동 업무 재발송을 멈추고 담당자가 원인을 확인해 새 발송을 만든다.
- **이력을 고치거나 지우지 않는다** — 이력이 바뀌면 "보냈다"를 증명할 수 없다. 전역 드롭다운은 조회 보조 수단이라 상한이 있지만, **이곳은 이력 대장**이라 상한을 두지 않는다.
- **규칙 변경을 소급하지 않는다** — 이미 나간 알림은 그때의 규칙으로 나간 것이다.
- **외부 채널(SMS·메일·Push)은 본개발 구현 범위다** — RFP SFR-017이 요구하고 원천은 문자발송체계·통신사 모듈 연계다(미결사항 목록 §4). 프로토타입의 체크값과 성공·실패 표본은 실제 발송으로 간주하지 않으며, 세부 기능·상태 계약은 §4-3을 따른다.
- **법령 근거를 붙이지 않는다** — 알림 설정은 법령이 명한 의무가 아니라 시스템 운영 기능이다. 근거 없음도 정보이며 규칙은 공통 근거 연계(SCR-COM-008)를 따른다.

## 7. 미결사항

없음. 수신 대상 지정 방식·채널 전부 해제 시 처리·재발송 여부·이력 보관과 변경 불가·규칙 변경의 소급 여부·외부 발송 관리의 스펙은 모두 §4·§6에서 확정했다.

외부 채널(SMS·메일·Push)은 **본개발 연계 구현 범위**이며(미결사항 목록 §4), 연계 전에는 내부 알림 기록으로 동작한다. 프로토타입에 보이는 문자·메일 체크와 발송 이력은 화면에 명시한 시연용 데이터다.
