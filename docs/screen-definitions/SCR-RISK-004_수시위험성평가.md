## 3. 진입 / 이탈 경로 및 사용자 시나리오

| 구분 | 연결 화면 | 조건 / 트리거 |
|---|---|---|
| 진입 | 수시 위험성평가 | 메뉴 선택 |

| 단계 | 사용자 행동 | 화면 반응 |
|:--:|---|---|
| 1 | 6개 실시 사유 중 하나를 선택한다 | 선택 사유가 입력된 등록 폼 표시 |
| 2 | 부서·발생일·내용과 요인·감소대책을 등록한다 | 수시평가와 감소대책 수만큼 개선조치 생성 |
| 3 | 담당 부서가 개선조치를 완료한다 | 목록의 조치 완료율 갱신 |
| 4 | 재난안전과가 안전관리자 서명 검토파일을 등록한다 | 상태를 검토완료로 변경하고 이력 기록 |

**분기 로직**

- **정기와 흐름의 방향이 반대다** — 정기는 주관부서가 열어 부서로 내려보내지만, 수시는 **부서에 사유가 생겨 올리고** 주관부서가 안전관리자 검토를 붙인다. 그래서 첫 단계의 주체가 부서 담당자다.
- **등록 전에 실시 사유를 반드시 먼저 고른다** — 사유를 고르지 않고 입력으로 들어가는 경로를 두지 않는다. 사유가 곧 그 평가를 해야 하는 법적 근거이기 때문이다.
- **고른 사유가 입력 항목을 바꾼다** — 재해 발생을 고르면 재해 개요와 작업 재개 예정일이 추가된다. 재해 발생 작업은 작업을 다시 시작하기 전에 평가를 마쳐야 하므로, 언제 재개하는지가 기한의 근거가 된다.
- **등록과 검토의 주체가 다르다** — 등록은 그 부서 담당자가, 안전관리자 검토파일 등록은 주관부서 담당자가 한다. 서로의 단계를 대신 수행하지 않는다.
- **검토파일의 유무가 곧 상태다** — 파일을 붙이면 검토완료, 떼면 다시 등록됨으로 돌아간다. 외부 용역이 수행하는 검토라 전자결재를 태우지 않고 파일로 갈음한다.
- **행마다 시설물을 붙일지 갈린다** — 실시 사유 6종 중 건설물 설치·이전·변경·해체와 정비·보수는 시설물이 원인이라 지정이 자연스럽고, 작업방법 변경 같은 사유는 지정하지 않는 것이 정상이다.
- **등록과 동시에 개선조치가 만들어진다** — 요인과 감소대책이 모두 채워진 행마다 1건씩 생기며, 담당 부서 화면에서 완료까지 이어진다. 정기와 달리 조치기한 설정이라는 별도 단계를 두지 않는다.
- **담당자를 비워 두면 비운 채로 내려간다** — 정기와 같은 규칙이다. '○○과 담당자' 같은 총칭을 대신 채우지 않는다. 총칭을 넣으면 그 부서가 정한 것처럼 보여 정작 누가 할지 정하는 단계가 사라진다(발주처 2026-08-06).

**엣지케이스**

- **조치기한을 비운 채 등록할 수 있다** — 기한 없는 개선조치가 만들어지고, 목록·카드·내 할일에 **"기한 미지정"** 으로 표시된다. 다만 기한 초과 집계에는 잡히지 않으므로 확인이 필요한 상태로 드러낸다.
- **요인과 감소대책이 모두 채워진 행만 개선조치가 된다** — 한 쪽만 적힌 행은 **평가 원본에는 적은 그대로 남고** 조치로만 넘어가지 않는다. 저장 단계에서 지워 버리면 담당자가 적어 둔 내용이 소리 없이 사라진다. 최소 1건이 없으면 등록 자체를 막는다.
- **행은 최소 1개를 유지하고 최대 10개까지 늘린다** — 마지막 한 행은 지우지 않고 내용을 비우도록 안내한다.
- **재해 발생 사유인데 재해 개요나 작업 재개 예정일이 비면** 저장을 막고 그 입력으로 커서를 옮긴다.
- **작성 양식 다운로드는 파일명만 안내한다** — 실제 파일이 아직 연결되지 않았음을 밝힌다.
- **안전관리자 서명의 진위는 시스템이 확인하지 않는다** — 외부 용역이 작성한 파일을 그대로 보관하며, 이 사실을 화면에 밝힌다.
- **조회 범위 밖 부서의 건은 목록에서 보이지 않고 주소로도 열리지 않는다** — 목록에서만 지우면 주소로 뚫린다.
- **시연 초기화는 주관부서 담당자만 실행한다** — 그 해의 등록분을 되돌리는 파괴적 동작이라 확인 단계를 거친다.

## 4. 화면 구성별 정리

### 4-1. 실시 사유와 조회
- 연도와 6개 실시 사유로 목록을 조회한다.
- 건설물 설치·이전·변경·해체, 기계·설비·원재료 도입·변경, 정비·보수, 작업방법·절차 변경, 중대산업사고·산업재해, 그 밖에 필요하다고 판단한 경우를 표시한다.
- 등록 전에 실시 사유 선택 화면을 반드시 거친다.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 연도 선택 | 그 해의 수시평가만 표시한다 | — |
| 실시 사유 선택 | 그 사유의 건만 남긴다 | 6개 사유는 고시가 정한 것을 그대로 쓴다 |
| [수시평가 등록] | 실시 사유를 먼저 고르는 단계를 연다 | 사유 없이 곧바로 입력으로 들어가지 않는다 |
| 등록 권한이 없는 사용자로 시도 | 막고 수행 주체를 알린다 | “수시평가 등록은 부서 담당자 본인이 수행합니다” |

### 4-2. 양식과 등록
- HWPX 작성 양식 다운로드를 제공하되 현재 실제 파일은 연결하지 않는다.
- 부서, 실시 사유, 발생일, 내용, 첨부파일을 입력한다.
- 재해 발생 사유에는 재해 개요와 작업 재개 예정일을 추가한다.
- 각 행에 **시설물(선택)**, 유해위험요인, 원인, 감소대책, 담당자(선택)와 개선 전 사진을 최대 10행 등록하고 공통 조치기한을 선택적으로 입력한다.
- 시설물은 FMS 시설물 대장(SCR-FAC-001)에서 고르며 지정하지 않으면 “해당 없음”이다. 실시 사유 6종 중 건설물 설치·이전·변경·해체와 정비·보수는 시설물이 원인이므로 정기평가보다 결합도가 높다.
- 지정한 시설물은 개선조치까지 따라가 그 시설물의 상세(SCR-FAC-002 §4-4)에 조치 내역으로 쌓인다. 잇는 키는 이름이 아니라 시설물번호다.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| [작성 양식 다운로드] | 양식 파일명을 안내한다 | 실제 파일이 아직 연결되지 않았음을 밝힌다 |
| 실시 사유를 재해 발생으로 선택 | 재해 개요와 작업 재개 예정일 입력이 추가된다 | 그 밖의 사유에서는 나타나지 않는다 |
| 시설물 칸의 [시설물 대장] | 대장을 인라인으로 펼쳐 고른다 | 새 창을 겹치지 않는다 |
| 시설물 선택 | 그 행에 시설물을 지정한다 | “시설물 지정: (시설명)” |
| 시설물 [해제] | “해당 없음”으로 되돌린다 | “시설물 지정 해제” — 오류가 아니다 |
| [＋ 행 추가] | 유해위험요인 행을 하나 더 만든다 | 상한을 넘으면 “한 번에 최대 10건까지 등록합니다” |
| 행 [×] | 그 행을 지운다 | 마지막 한 행은 지우지 않고 내용을 비우게 안내한다 |
| 개선 전 사진 첨부 | 그 행의 증빙으로 담는다 | “개선 전 사진 N건 첨부” |
| [등록] | 입력을 검사한 뒤 저장하고 개선조치를 만든다 | “수시평가 등록 · 개선조치 N건 생성 — [내 할일]에서 조치를 마무리하세요” |
| 필수 항목 누락 | 저장을 막고 빈 항목으로 커서를 옮긴다 | 부서·사유·발생일·내용 / 재해 개요 / 작업 재개 예정일 / 요인 최소 1건 |

### 4-3. 목록
- 발생일, 실시 사유, 부서, 내용·첨부, 개선조치 진행률, 안전관리자 검토, 상태와 이력을 표시한다.
- 개선조치가 있으면 조치 상세와 미완료 시 내 할일 이동을 제공한다.
- 상태는 등록됨과 검토완료로 표시한다.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| [부서별 조치] | 그 건의 개선조치 상세 카드를 연다 | 개선조치가 있는 건에만 나타난다 |
| 미완료 조치에서 [내 할일] | 담당자 화면으로 이동한다 | my-work.html |
| [이력] | 등록·검토·알림·상태 변경을 시간순으로 연다 | — |

### 4-4. 안전관리자 검토
- 검토파일, 검토한 안전관리자 이름과 검토일을 등록한다. **검토일은 업로드일과 다르다** — 외부 용역이 검토를 마친 날이며, 비워 두면 등록일로 기록되고 그 사실을 입력란 아래에 밝힌다.
- 파일 등록을 검토완료로 처리하며 서명의 진위는 시스템에서 확인하지 않는다.
- 검토파일 해제 시 검토완료 상태도 해제한다.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| [＋ 검토파일 등록] | 검토파일·안전관리자 이름·검토일 입력을 연다 | 주관부서 담당자에게만 나타난다 |
| 검토파일 등록 | 그 건을 검토완료로 바꾼다 | 서명의 진위는 시스템이 확인하지 않는다 |
| [해제] | 검토파일을 떼고 검토완료도 함께 푼다 | 파일과 상태가 어긋나지 않게 한다 |
| 권한 없는 사용자로 시도 | 막고 수행 주체를 알린다 | “안전관리자 검토 서명은 주관부서(재난안전과) 담당자가 첨부합니다” |

### 4-5. 이력과 빈 상태
- 등록, 검토, 알림과 상태 변경 이력을 표시한다.
- 해당 연도 또는 사유에 결과가 없으면 수시평가가 없음을 안내한다.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 조회 결과 0건 | 목록 자리에 빈 상태 안내를 표시한다 | — |
| 조치기한을 비운 채 등록 | 기한 없는 개선조치가 만들어진다 | 목록·카드·내 할일에 **“기한 미지정”** 으로 드러낸다 |
| [시연 초기화] | 확인 뒤 그 해를 미등록 상태로 되돌린다 | 주관부서 담당자만 실행할 수 있다 |

## 6. 정책

- 수시평가 등록은 실시 사유 선택에서 시작한다.
- 유해위험요인과 감소대책이 모두 입력된 행마다 개선조치 1건을 즉시 생성한다.
- 위험성 수준, 허용 여부, 참여 근로자와 결과 공유 정보는 입력하지 않는다.
- 조치 담당자와 조치기한은 선택 사항이며 비워 둔 상태로 등록할 수 있다.
- 개선조치 완료율은 조치 상태를 기준으로 표시하고 안전관리자 검토 상태와 별도로 관리한다.
- 검토파일을 삭제할 수 있으며 별도 교체 사유나 파일 버전을 요구하지 않는다.
- 본 문서는 현재 프로토타입의 기능·UX를 기록하며 법령상 추가 기록 기준은 별도 문서에서 관리한다.
