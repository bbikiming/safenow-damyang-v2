| 단계 | 사용자 행동 | 화면 반응 |
|:--:|---|---|

| 2 | 공통 또는 부서별 설문조사표와 부서 제출본을 등록한다 | 부서별 파일 현황 갱신 |
| 3 | 통합 보고서를 등록하고 부서별 개선조치 행을 직접 작성한다 | 요인·원인·조치·담당·증빙 저장 |
| 4 | 부서별 조치기한을 정해 전달한다 | 유효 행마다 개선조치 생성 및 알림 기록 |
| 5 | 부서가 조치 결과를 완료하고 재난안전과가 확인한다 | 완료율·확인 상태·공문 기안 가능 여부 갱신 |
| 6 | 공문을 기안하고 결재 회신 상태를 확인한다 | 온나라 이관 문서와 상태 표시 |

**분기 로직**

- **연도에 평가가 있는지로 화면 전체가 갈린다** — 없으면 생성 안내와 2단계 마법사만 나오고, 있으면 그 평가의 진행 상태를 그린다. 같은 연도에 두 번째 평가를 만들지 않는다.
- **보고서 단계(등록 전 / 작성 중 / 전달됨)가 본문을 결정한다** — 등록 전에는 통합 보고서 첨부 버튼, 작성 중에는 부서별 검수 입력표, 전달 후에는 부서별 조치 표로 바뀐다. 세 국면이 같은 자리를 번갈아 차지한다.
- **평가가 완료되면 편집 수단이 사라진다** — 보고서 영역이 첨부 파일과 승인 완료일만 보여주는 형태로 바뀌고 제출·재촉 버튼은 나오지 않는다. 끝난 평가에 도달할 수 없는 행동을 약속하지 않기 위해서다.
- **조작 권한과 조회 범위는 서로 다른 축이다** — 조회 범위는 총괄 책임자와 주관부서가 전 부서, 그 밖은 자기 부서다. 반면 생성·검수·전달·완료확인·공문은 주관부서 **담당자**만 수행하며 같은 부서 과장도 조회만 한다. 조회를 막지 않으므로 막다른 길이 생기지 않는다.
- **검수 행은 요인명과 개선조치가 모두 있어야 전달 대상이다** — 둘 중 하나라도 비면 그 행은 세지 않는다. 유효 행이 하나도 없는 부서는 "지적사항 없음"으로 조치 대상에서 빠지고 그 사실이 이력에 남는다.
- **완료 확인은 조치 상태를 건드리지 않는다** — 확인·반려는 별도 축이며 반려해도 조치는 완료 상태로 남는다. 실질 제재는 두 가지다: 공문 기안이 막히고, 담당자 화면에 반려 사유와 회차가 계속 뜬다.
- **공문 기안은 전 건 확인 완료라야 열린다** — 조치가 하나라도 확인 전이면 기안 단계로 갈 수 없다. 기안 이후에도 상신은 문서 미리보기에서만 하며 기안 폼에서 곧바로 상신하는 경로는 두지 않는다.
- **내 부서 진행 상황은 로그인한 사람의 부서로 갈린다** — 대상 부서면 그 부서의 4단계 위치를, 대상이 아니면 대상이 아니라는 사실을 문장으로 밝힌다.

**엣지케이스**

- **보고서를 등록하면 설문조사표와 부서 제출본이 잠긴다** — 검수가 시작된 뒤 근거 자료를 바꾸면 무엇을 보고 적었는지 알 수 없어진다.
- **보고서를 취소·재업로드하면 작성한 검수 행이 사라진다** — 지워질 범위를 먼저 밝히고 확인을 받는다.
- **개선 후 사진이 없으면 작성 단계의 완료 체크를 할 수 없다** — 증빙 없는 완료는 기록으로서 소명되지 않는다.
- **반려는 사유 없이 저장되지 않는다** — 담당자가 무엇을 다시 해야 하는지 모르면 반려가 작동하지 않는다.
- **재제출하면 확인 상태가 대기로 돌아가고 제출 회차가 올라간다** — 이전 반려 기록은 지우지 않고 함께 남긴다.
- **평가 전체가 완료여도 그 부서에 반려 건이 남아 있을 수 있다** — 이때 담당자 화면에는 재제출 수단이 계속 보여야 한다. 완료 탭에 묻히면 되돌릴 방법이 사라진다.
- **시설물 축은 세 상태다** — 지정 / **해당 없음**(확인 결과 붙지 않음) / **미지정**(아직 판단 안 함). 어느 상태도 다음 단계를 막지 않는다. 작업 행동·화학물질처럼 시설물에 붙지 않는 요인이 정상적으로 존재하므로 지정을 필수로 걸지 않는다. 다만 **미지정과 해당 없음을 한 상태로 합치지 않는다** — 합치면 "아직 안 봤다"와 "봤는데 없다"가 구분되지 않아 검수가 끝났는지 알 수 없다(SCR-BASE-003 의 "0건을 해당 없음으로 단정하지 않는다"·SCR-DASH-001 의 "0이 아니라 미등록"과 같은 원칙).
- **담당자를 비운 채 전달할 수 있다** — 담당자는 그 부서가 정하는 것이 원칙이라 비워 두면 부서가 개선조치 목록에서 지정한다.
- **조회 전용 사용자에게는 검수 입력표 자체가 나오지 않는다** — 버튼만 감추고 표를 남기면 무엇을 보는 화면인지 알 수 없다.

## 4. 화면 구성별 정리

### 4-1. 연도와 생성
- 연도별 정기평가는 1건만 등록한다.
- 미등록 연도에는 정기평가 생성을 표시하고 대상 부서 선정, 부서별 점검일 지정의 2단계 마법사를 제공한다.
- 이미 등록된 연도에는 추가 생성하지 못하며 다른 연도를 선택하도록 안내한다.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 연도 선택 | 그 해의 정기평가를 표시한다 | 미등록 연도면 생성 안내로 바뀐다 |
| [정기평가 생성] | 대상 부서 선정(1단계) 입력을 연다 | 부서를 한 곳도 고르지 않으면 다음으로 못 간다 |
| 부서 선정 후 [다음] | 부서별 점검일 지정(2단계)으로 넘어간다 | 빈 점검일이 있으면 몇 곳인지 알린다 |
| [생성] | 그 해의 정기평가를 만들고 대상 부서에 통보 이력을 남긴다 | 목록이 즉시 갱신된다 |
| 조작 권한이 없는 사용자로 시도 | 막고 수행 주체를 알린다 | 조회는 막지 않는다 |

- 상태: 연도 단위 상태는 **미생성**(생성 안내와 마법사 진입만 노출)과 **생성됨**(그 해 평가 표시) 둘이다. 조작 권한이 없는 접속자에게는 두 상태 모두 조회만 가능하고 생성 수단이 나타나지 않으며, 왜 없는지와 누가 하는지를 문장으로 밝힌다. 목록·이력이 비는 경우는 없다.

### 4-2. 내 부서 진행 상황
- 설문조사표 작성·제출, 보고서 검수·개선조치 전달, 개선조치 완료, 완료 확인의 4단계를 표시한다.
- 현재 역할·소속 부서에 따라 조회 범위와 다음 행동 안내를 바꾼다.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 화면 진입 | 4단계 중 내 부서가 지금 어디에 있는지 표시한다 | — |
| 다음 행동이 있는 단계 | 그 단계로 가는 수단을 함께 낸다 | 도달할 수 없는 행동은 약속하지 않는다 |
| 3단계에서 [개선조치에서 마무리] | 개선조치 목록으로 이동한다 | 조회 범위가 걸려 자기 부서 건만 보인다(SCR-IMP-001) |
| 1단계에서 [지금 제출하기] | **이 화면 안에서** 설문조사표 제출 단계를 연다(§4-3) | 다른 화면으로 보내지 않는다 |
| 이미 제출한 뒤 | 버튼이 [제출본 교체]로 바뀐다 | 제출일과 제출자를 함께 표시한다 |
| 관리·감독 계층으로 진입 | 제출 수단을 내지 않는다 | 조회는 막지 않는다 |
| 대상 부서가 아닌 부서로 진입 | 그 사실을 문장으로 밝힌다 | 빈 화면으로 두지 않는다 |

- 상태: 단계상태는 **설문조사표 제출 → 보고서 검수 → 개선조치 전달 → 조치 완료 → 완료 확인** 순이며, 각 부서는 이 중 한 지점에 있다. 그 해 정기평가가 아직 없으면 **미생성**(생성 안내로 대체), 접속자의 부서가 대상 부서가 아니면 **대상 아님**을 문장으로 밝힌다 — 빈 화면으로 두지 않는다. 조회 범위 밖 부서는 애초에 표시하지 않으므로 여기서 빈 상태가 되는 일은 없다.

### 4-3. 설문조사표와 부서 제출본
- 공통 설문조사표 **양식**을 등록해 전 대상 부서에 적용하거나 부서별 양식으로 교체한다.
- **부서 담당자 본인이 자기 부서 제출본을 낸다** — 양식을 내려받아 작성한 뒤 이 화면에서 바로 올린다. 제출자·제출일이 실제 접속자로 기록된다.
- 주관부서는 부서가 종이·메일로 낸 경우에 한해 **대리 등록**할 수 있고, 이때는 대리 등록임이 이력에 남는다.
- 통합 보고서 등록 또는 검수 시작 이후에는 양식과 제출본을 모두 잠근다.
- **양식과 제출본은 다른 것이다** — 양식은 주관부서가 배포하는 빈 서식이고, 제출본은 부서가 작성해 낸 결과물이다. 한 칸에 섞으면 배포와 회수를 구분할 수 없다.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 공통 설문조사표 양식 등록 | 전 대상 부서에 같은 양식을 적용한다 | — |
| 부서별 양식 등록·삭제 | 그 부서만 공통본 대신 쓸 양식을 지정한다 | 삭제하면 공통본으로 되돌아간다 |
| 부서 담당자가 [지금 제출하기] | 배포된 양식을 함께 보여주고 작성본을 받는다 | 양식이 없으면 "재난안전과에 문의하세요" |
| 부서 담당자가 제출 | 제출본을 저장하고 제출자를 실제 접속자로 남긴다 | "설문조사표 제출 · 재난안전과로 전달되었습니다" |
| 파일을 고르지 않고 제출 | 저장하지 않는다 | "작성한 설문조사표 파일을 선택하세요" |
| 주관부서가 [제출본 대리 등록] | 그 부서 제출본을 대신 올린다 | 이력에 대리 등록임을 남긴다 |
| 다른 부서 담당자가 남의 부서 제출 시도 | 막는다 | 자기 부서 몫만 낼 수 있다 |
| 보고서 등록 이후 제출·교체 시도 | 수단을 내지 않고 잠긴 사유를 표시한다 | 검수가 시작된 뒤에는 근거 자료를 바꾸지 않는다 |

- 상태: 빈 상태는 **공통 설문조사표 양식 미등록**(등록 안내)과 **제출본 0건**(부서명만 나열되고 파일명 자리가 비어 있음) 두 가지다. 부서 단위 상태는 **미제출 / 본인 제출 / 대리 등록**이며, 제출자 표기로 셋이 구분된다 — 대리 등록을 본인 제출과 같게 보이면 나중에 "우리는 안 냈는데 냈다고 돼 있다"가 된다. 단계상태는 **미등록 → 공통 등록 → 부서별 제출 진행 → 전 부서 제출 완료 → 잠김**이며, 잠김은 통합 보고서가 등록되거나 검수가 시작된 이후를 뜻한다. 잠긴 뒤에는 첨부 수단 자체를 내지 않고 잠긴 사유를 대신 표시한다 — 버튼만 비활성으로 두면 왜 안 되는지 알 수 없다.

### 4-4. 보고서 검수·직접 작성
- 통합 보고서 파일을 등록한 뒤 부서별로 행을 추가한다.
- 각 행에 시설물(선택), 유해위험요인, 분류, 원인, 개선조치, 담당자(선택), 개선 전·후 사진과 완료 체크를 둔다.
- 시설물 축은 **세 상태**다 — **지정 / 해당 없음(확인 결과 붙지 않음) / 미지정(아직 판단 안 함)**. 기본값은 미지정이고, '해당 없음'은 [해당 없음]을 눌러 **적극적으로 표시**한다.
- 개선 후 사진이 있어야 작성 단계의 완료 체크를 선택할 수 있다.
- 보고서 취소·재업로드 시 작성한 검수 행의 삭제 범위를 확인한다.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 통합 보고서 등록 | 부서별 빈 입력표를 연다 | 파일 내용에서 행을 자동으로 만들지 않는다 |
| [＋ 행 추가] | 그 부서에 빈 행을 하나 더 만든다 | — |
| 시설물 칸 선택 | 시설물 대장을 인라인으로 펼쳐 고른다 | 새 창을 겹치지 않는다(SCR-FAC-001) |
| 시설물 [해당 없음] | 확인 결과 시설물에 붙지 않는 요인임을 표시한다 | 미지정과 구분된다 — 앞은 아직 안 본 것이다 |
| 시설물 [미지정으로 되돌리기] | 지정·해당 없음을 모두 풀어 기본 상태로 되돌린다 | 오류가 아니라 정상 상태다 |
| 담당자 칸 선택 | 조직도에서 한 명을 고른다 | 비워 두면 그 부서가 정한다 |
| 개선 후 사진 첨부 | 완료 체크의 선행 조건을 채운다 | 사진이 없으면 완료를 체크할 수 없다 |
| [보고서 취소·재업로드] | 지워질 검수 행의 범위를 밝힌 확인 단계를 연다 | 확인 전에는 지우지 않는다 |

- 상태: 단계상태는 **보고서 미등록 → 등록됨(빈 입력표) → 행 작성 중 → 작성 완료**다. 보고서를 등록하기 전에는 입력표 자체가 없고, 등록 직후에는 **행 0건**으로 시작한다 — 파일 내용에서 행을 자동으로 만들지 않기 때문이며, 이 빈 표가 정상이라는 사실을 함께 밝힌다. 행 단위로는 **시설물 미지정**·**시설물 해당 없음**·**담당자 미지정**·**개선 후 사진 없음**이 각각 정상 상태이고 오류가 아니다. **미지정과 해당 없음은 다른 상태다** — 앞은 아직 판단하지 않은 것이고 뒤는 확인해서 붙지 않는 것이라, 검수가 어디까지 진행됐는지를 이 둘이 갈라 준다 — 다만 개선 후 사진이 없으면 완료 체크가 잠긴다.

### 4-5. 조치기한 설정과 전달
- 유해위험요인과 개선조치가 모두 입력된 행만 전달 대상으로 본다.
- 일괄 기한 또는 부서별 기한을 지정한다.
- 유효 행이 있는 부서에는 행마다 개선조치 1건을 만들고, 유효 행이 없는 부서는 지적사항 없음으로 조치 대상에서 제외한다.
- 담당자를 비워 전달하면 해당 부서가 개선조치 목록에서 지정한다.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| [작성완료 · 조치기한 설정] | 일괄 기한과 부서별 기한을 받는 입력을 연다 | 유효 행이 하나도 없으면 진행할 수 없다 |
| 기한 지정 후 [전달] | 유효 행마다 개선조치 1건을 만들어 부서로 내려보낸다 | 부서별 기한이 비면 몇 곳인지 알린다 |
| 유효 행이 없는 부서 | 지적사항 없음으로 조치 대상에서 제외한다 | 그 사실을 이력에 남긴다 |

- 상태: 단계상태는 **전달 전 → 기한 지정 중 → 전달 완료**다. 유효 행(유해위험요인과 개선조치가 모두 채워진 행)이 **한 건도 없으면 전달 자체가 불가**하며 그 사실을 알린다. 부서 단위로는 **유효 행 있음**(개선조치 생성 대상)과 **유효 행 없음**(지적사항 없음으로 제외) 두 상태가 공존하고, 후자도 이력에 남겨 빠뜨린 것과 구분한다. 전달이 끝나면 이 영역은 조회 전용이 된다.

### 4-6. 개선조치·확인
- 부서별 개선조치를 카드로 열어 담당자, 기한, 조치 전·후 사진, 완료일과 전자서명을 확인한다.
- 개선조치 상태가 전부 완료가 되면 정기평가를 자동 완료한다.
- 재난안전과는 완료 건의 증빙을 열람 확인한 뒤 확인 또는 반려하며 반려 사유와 제출 회차를 표시한다.
- 완료 확인 전에도 평가 완료율에는 완료 상태가 반영되지만 전 건 확인 전에는 공문 기안을 막는다.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| [부서별 조치] | 그 부서 개선조치를 카드로 연다 | 담당자·기한·전후 사진·완료일·서명을 함께 본다 |
| [확인] | 그 건을 확인 완료로 표시한다 | 조치 상태는 건드리지 않는다 |
| [반려] | 사유를 받아 담당자에게 되돌린다 | 사유 없이는 저장하지 않는다 |
| 반려 후 담당자가 재제출 | 확인 대기로 되돌리고 제출 회차를 올린다 | 담당자 화면에 사유가 상시 표시된다 |
| [재촉] | 미제출 부서에 재촉 이력을 남긴다 | 보낸 사람은 실제 접속자로 기록된다 |

- 상태: 개선조치 1건의 단계상태는 **예정 → 진행중 → 완료**이고, 여기에 **확인 축**(확인 대기 → 확인 완료 / 반려)이 별도로 얹힌다. 두 축은 독립이라 **완료이면서 확인 대기**, **완료이면서 반려됨**이 정상적으로 존재한다 — 반려해도 조치 상태를 되돌리지 않기 때문이다. 반려 건에는 사유와 제출 회차가 함께 표시된다. 부서 단위로는 조치 0건인 부서(지적사항 없음)가 있고 이 부서는 확인 대상이 아니다. 평가 전체는 조치가 전부 완료되면 **자동 완료**되지만, 전 건 확인이 끝나기 전에는 공문 기안이 잠긴다.

### 4-7. 공문·이력
- 확인이 끝난 평가에 공문 기안을 제공하고 상신 후 문서 보기와 결재 상태를 표시한다.
- 평가 생성, 파일, 전달, 완료, 확인, 재촉과 공문 처리 이력을 시간순으로 표시한다.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| [공문 기안] | 공문 작성 화면을 연다 | 전 건 확인이 끝나야 열린다 |
| 공문 작성 후 [문서 보기] | 미리보기 지면을 연다 | 상신 버튼은 미리보기에만 둔다 |
| 미리보기에서 [상신] | 온나라로 이관 처리하고 상태를 표시한다 | 기안 폼에서 곧바로 상신하지 않는다 |
| 이력 탭 선택 | 생성·파일·전달·완료·확인·재촉·공문을 시간순으로 표시한다 | — |

- 상태: 공문의 단계상태는 **기안 전 → 기안됨 → 상신됨 → 결재 완료 / 반려**다. 확인이 끝나지 않은 평가에서는 기안 전에서 더 나아가지 못하고 그 사유를 표시한다. 상신 전에는 문서번호가 **온나라에서 부여**로 표시된다 — 자체 채번하지 않는다. 이력은 비는 경우가 없다(평가를 만든 순간 생성 이력이 남는다). 이력은 조회 전용이며 이 화면에서 고치거나 지울 수 없다.

|---|---|---|---|

| 시설물 | 아니오 | 대장에서 고르거나 [해당 없음]으로 표시하거나 미지정으로 둔다 | **셋 다 오류가 아니며 어떤 단계도 막지 않는다** |

## 6. 정책

- 같은 연도에는 정기평가를 1건만 생성한다.
- 보고서는 파일로 보관하고 화면 항목을 자동 생성하지 않는다.
- 부서별 검수 행의 시설물 연결과 담당자 사전 지정은 선택 사항이다.
- 유효한 검수 행은 허용 여부나 위험성 수준 판정 없이 모두 개선조치로 생성한다.
- 개선조치 완료율과 평가 자동 완료는 개선조치의 완료 상태를 기준으로 한다.
- 완료 확인은 별도 상태로 관리하며 전 건 확인완료가 공문 기안 조건이다.
- 평가가 완료된 뒤에도 공문 기안과 결재 회신을 후속 단계로 처리한다.
- 본 문서는 현재 프로토타입의 기능·UX를 기록하며 근로자 참여, 위험성 수준·허용 여부와 결과 공유는 현 화면 기능에 포함하지 않는다.
