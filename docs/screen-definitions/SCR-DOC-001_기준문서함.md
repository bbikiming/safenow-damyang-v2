# 화면 정의서 — 기준문서함

> 화면 ID: SCR-DOC-001 · 화면 유형: 조회 목록 · 기획 관점(v7) · 구현 정합 2026-08-12
> 판단이 필요했던 항목은 §6 정책에서 확정했습니다.
>
> **메뉴 제외 화면 (2026-09-03)** — 이 화면은 대메뉴·좌측 메뉴에 나오지 않는다. 업무 관리의 흐름을 **이행 관리 · 문서 목록 · 내 할일 셋 안에서** 끝내기로 확정했다. **문서를 찾는 자리는 업무 관리 > 문서 목록(SCR-CMP-002)이 잇는다.** 다만 이 화면에만 있던 **문서별 버전 이력과 다중 첨부 보관은 대체 화면이 없다** — 없어진 기능을 있는 것처럼 적지 않는다.
> 정의서를 남기는 이유는 화면과 주소가 그대로 살아 있기 때문이다 — 아래 §3~§7은 그 화면에 도착한 사용자가 만나는 동작의 정의로 계속 유효하다. 메뉴 구조 규칙은 SCR-COM-002 §6·SCR-COM-003 §6이 정한다.

법적의무 재분류 V2 정본 중 **처리유형이 첨부파일인 문서**를 모아 조회한다. 문서 목록(SCR-CMP-002)이 어떤 할 일의 증빙인지와 함께 문서 1건을 찾는 자리라면, 기준문서함은 파일형 기준·계획·실적·참고자료의 버전과 보관 상태를 빠르게 찾는 자리다. 기존 V1의 `확인필요`를 분류 미결로 다시 노출하지 않으며, V2의 모든 기본 문서는 대메뉴·세트·PDCA가 확정되어 있다.

## 2. 권한 정보

- 메뉴 접근·보기·수정은 시스템 관리의 메뉴 관리(SCR-ADMIN-005)와 권한 관리(SCR-ADMIN-006)에서 설정한다.
- 이 화면 정의서에서는 역할별 권한과 열람 범위를 별도로 정하지 않는다.
- 목록은 조회 전용이며 새 버전 업로드는 문서 상세(SCR-DOC-004)에서 수행한다.

## 3. 진입 / 이탈 경로 및 사용자 시나리오

| 구분 | 연결 화면 | 조건 / 트리거 |
|---|---|---|
| 진입 | 주소·즐겨찾기 | `docs-archive.html` — 메뉴로는 들어올 수 없다 |
| 이탈 | 문서 상세 | [미리보기] 선택(SCR-DOC-004) |
| 이탈 | 문서 목록(SCR-CMP-002) | 분야 칩 선택 — 그 분야로 좁힌 문서 목록으로 |

| 단계 | 사용자 행동 | 화면 반응 |
|:--:|---|---|
| 1 | 화면에 들어온다 | 보관 문서 전체·참고/보관·안전점검 계열·매뉴얼/업무처리절차·V2 분류 완료 건수를 표시한다 |
| 2 | 대메뉴·근거 구분·문서 성격으로 좁힌다 | 같은 V2 원본에서 조건에 맞는 행만 다시 계산한다 |
| 3 | 문서명을 검색한다 | 이름이 포함된 문서만 즉시 표시한다 |
| 4 | [미리보기]를 선택한다 | V2 문서 상세로 이동한다 |
| 5 | [더 보기]를 선택한다 | 다음 20건을 같은 조건으로 추가 표시한다 |

### 분기 로직

- **대상은 V2의 첨부파일 문서다** — V1의 `workType=첨부`나 `확인필요`를 섞지 않는다.
- **참고·보관과 안전점검은 문서 성격 태그다** — 대메뉴·세트·PDCA 분류 상태와 다른 축이며 서로 겹칠 수 있다.
- **근거 구분은 배타적인 네 그룹이다** — 중처법만 포함, 산안법만 포함, 둘 다 포함한 복합근거, 어느 쪽 문자열도 없는 기타근거로 나눠 합계가 전체와 같게 한다.
- **안전점검 계열은 문서명·주제·세부유형에 `점검`이 포함된 첨부문서다** — 별도 메뉴를 만들지 않는다.
- **매뉴얼·업무처리절차는 문서 성격 필터다** — 문서명·주제·세부유형에 `매뉴얼`, `업무처리절차`, `업무 절차`가 포함된 첨부문서를 찾는다. 제정·개정 원문은 이 화면의 문서 상세에서 관리하고 이행 여부는 이행 목록(SCR-DOC-003/SCR-SBM-006)에서 확인한다.

### 예외·경계 시나리오

| 상황 | 화면 반응 |
|---|---|
| 조회 결과 0건 | 조건에 맞는 문서가 없음을 표시하고 조건을 풀 수 있게 한다 |
| 법적근거가 비어 있음 | 기타근거로 분류하고 툴팁에는 `근거 없음`을 표시한다 |
| 태그가 없는 문서 | 표시 열을 `-`로 표시한다 |
| 20건 초과 | 20건만 먼저 표시하고 [더 보기]를 제공한다 |
| V2 세트·PDCA가 없는 기본 문서 | 정합성 오류로 기록하고 V2 분류 완료 수에서 제외한다 |

## 4. 화면 구성별 정리

### 4-1. 요약 카드

- 구성: 보관 문서 전체 · 참고/보관 · 안전점검 계열 · **매뉴얼/업무처리절차** · V2 분류 완료.
- 전체·성격 태그·분류 완료는 같은 모집단에서 계산한다. 참고/보관과 안전점검은 겹칠 수 있으므로 서로 더하지 않는다.

### 4-2. 조회 조건

| 항목 | 값 | 동작 |
|---|---|---|
| 대메뉴 | V2 데이터에 실제 존재하는 대메뉴 | 해당 대메뉴만 표시 |
| 근거 구분 | 중처법·산안법·복합근거·기타근거 | 배타 그룹 하나만 표시 |
| 표시 | 참고/보관·안전점검 계열·매뉴얼/업무처리절차 | 선택한 성격 문서만 표시 |
| 검색 | 문서명 포함 검색 | 입력 즉시 반영 |

조건이 바뀌면 더 보기 누적 수를 20건으로 초기화한다.

### 4-3. 문서 표

- 열: 문서명 · 대메뉴 · 근거 구분 · 표시 · 버전 · 최종 수정 · 관리.
- 대메뉴 칩은 `docs-preset.html?ver=v2&menu={menuKey}`로 이동한다.
- [미리보기]는 `doc-detail.html?id={문서ID}&v=2`로 이동한다.
- 근거 구분 칩의 툴팁에 문서의 전체 `legalBasis`를 표시한다.

## 5. 유효성 검사

조회 전용이므로 저장형 입력은 없다. 문서 상세에서 새 버전을 업로드할 때의 확장자·크기·개수·중복·실패 처리는 SCR-DOC-004와 공통 첨부 규칙을 따른다.

## 6. 정책

- **V2를 단일 정본으로 쓴다** — 기본 429행 중 완전 동일한 3쌍은 원본 추적용으로 보존하고 화면·통계에서는 426문서로 합친다.
- **과거 `확인필요`는 현재 분류 상태가 아니다** — V2에서 대메뉴·세트·PDCA·처리유형이 지정됐으므로 다시 미결로 노출하지 않는다.
- **조건부 적용과 기획 미결을 분리한다** — `해당 시`·`조건부` 문서는 관련 사업·작업이 있을 때만 이행 대상으로 활성화하며, 분류 자체는 확정 상태다.
- **안전점검은 별도 대메뉴로 승격하지 않는다** — 점검 문서는 위험성평가·관계법령·도급관리 등 실제 의무 대메뉴에 속하고 성격 태그로만 교차 조회한다.
- **매뉴얼·업무처리절차의 원문과 이행을 분리한다** — 제정·개정된 문서 원본과 버전은 기준문서함/문서 상세가 맡고, 제정·조치 여부 점검과 증빙은 이행 목록이 맡는다. 같은 원문을 두 곳에 업로드하지 않는다.
- **이 화면에서 분류를 바꾸지 않는다** — 신규·사용자 문서 분류는 업무 등록·수정(SCR-DOC-007) 한 곳에서만 변경한다.

## 7. 미결사항

없음. V2 정본·중복 통합·첨부파일 대상·근거 그룹·참고/보관·안전점검·매뉴얼/업무처리절차 태그·상세 이동·조건부 적용을 모두 §3~§6에서 확정했다.
