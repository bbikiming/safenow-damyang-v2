업무 세트에 배정되지 않았거나 **아직 어느 업무에 속하는지 정해지지 않은 문서**를 모아 두는 자리다. 실제 문서대장에는 대메뉴가 확정되지 않은 문서가 다수 섞여 있어, 이들을 업무 목록에 그냥 두면 세트 구조가 어지러워지고 빼 버리면 존재 자체가 사라진다. 그래서 별도 함에 모아 **분류가 정해질 때까지 눈에 보이게** 둔다. 구성은 요약 카드·조회 조건·문서 표 세 덩어리이며, 분류가 정해진 문서는 업무 목록(SCR-DOC-002)으로 넘어간다.

## 2. 권한 정보

- 메뉴 접근·보기·수정은 시스템 관리의 메뉴 관리(SCR-ADMIN-005)와 권한 관리(SCR-ADMIN-006)에서 설정한다.
- 이 화면 정의서에서는 역할별 권한과 열람 범위를 별도로 정하지 않는다.
- 문서 열기·업로드의 수행 주체는 §3~§6의 업무 흐름을 따른다.

## 3. 진입 / 이탈 경로 및 사용자 시나리오

| 구분 | 연결 화면 | 조건 / 트리거 |
|---|---|---|
| 진입 | 업무문서 > 기준문서함 | 메뉴 선택 |
| 진입 | 문서 상세 | 기준 문서 항목에서 되돌아올 때(SCR-DOC-004~006) |
| 이탈 | 기준문서 업로드 모달 | 문서 선택(SCR-EDOC-010) |
| 이탈 | 업무 목록 | 분류가 확정된 문서를 확인할 때(SCR-DOC-002) |

| 단계 | 사용자 행동 | 화면 반응 |
|:--:|---|---|
| 1 | 화면에 들어온다 | 보관 전체·분류 미확정·2차 검토 대상·확정 건수를 먼저 보여 준다 |
| 2 | 표시 조건으로 좁힌다 | 분류 미확정만, 또는 2차 검토 대상만 남긴다 |
| 3 | 문서명을 검색한다 | 이름으로 즉시 좁힌다 |
| 4 | 문서를 연다 | 처리유형에 따라 업로드 모달이 열린다 |
| 5 | 더 본다 | 정해진 개수만큼 더 불러온다 |

### 분기 로직

- **분류 확정 여부가 문서의 성격을 가른다** — 대메뉴가 정해진 문서와 **분류 미확정** 문서가 한 표에 섞여 있고, 미확정 건에는 눈에 띄는 표시를 붙인다. 섞어 두는 이유는 분리하면 미확정 함을 아무도 열어 보지 않기 때문이다.
- **2차 검토 대상은 따로 표시한다** — 안전점검 계열처럼 **메뉴로 승격할지 아직 정하지 않은** 문서다. 분류 미확정과 다른 축이라 별도 표시를 쓴다 — 앞은 "어디에 속하는지 모른다"이고 뒤는 "구조를 바꿀지 정하지 않았다"다.
- **대메뉴 조건은 실제 데이터에서 만든다** — 목록에 없는 대메뉴는 선택지에도 없다. 고정 목록을 두면 문서가 없는 메뉴가 선택지에 남아 0건만 보게 된다.
- **문서를 여는 결과는 처리유형이 정한다** — 첨부파일이면 업로드 모달, 전자문서면 입력 폼, 프로그램이면 그 화면으로 간다(SCR-EDOC-010 §3).

### 예외·경계 시나리오

| 상황 | 화면 반응 |
|---|---|
| 조회 결과가 0건 | 조건에 맞는 문서가 없음을 표시하고 조건을 풀 수 있게 한다 |
| 분류 미확정이 0건 | 요약 카드에 0을 그대로 표시한다 — 감추면 해소됐는지 원래 없었는지 알 수 없다 |
| 문서가 많아 한 번에 못 보여줌 | 정해진 개수씩 끊어 보여 주고 더 볼 수 있게 한다 |
| 법령이 지정되지 않은 문서 | 법령 칸을 비우지 않고 없음을 표시한다 |
| 2차 검토 결정이 보류된 상태 | 그 사실을 화면에 문장으로 남긴다 — 결정이 미뤄졌다는 것도 정보다 |

## 4. 화면 구성별 정리

### 4-1. 요약 카드

- 구성: 보관 문서 전체 · 분류 미확정 · 2차 검토 대상 · 대메뉴 확정 네 개.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 화면 진입 | 네 수치를 목록 데이터에서 계산해 표시한다 | 고정값을 쓰지 않는다 |
| 문서 분류가 확정됨 | 미확정이 줄고 확정이 는다 | — |

- 상태: 네 수치는 항상 표시하며 0도 그대로 낸다. 전체 = 미확정 + 확정이고, 2차 검토 대상은 그와 다른 축이라 합에 포함되지 않는다.

### 4-2. 조회 조건

- 구성: 대메뉴 선택 · 표시 선택(분류 미확정 / 2차 검토 대상) · 문서명 검색.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 대메뉴 선택 | 그 메뉴 문서만 남긴다 | 선택지는 실제 데이터에서 만든다 |
| 표시 선택 | 미확정 또는 2차 검토 대상만 남긴다 | 두 축은 성격이 달라 함께 걸 수 있다 |
| 문서명 검색 | 이름으로 좁힌다 | 입력 도중 포커스가 유지된다 |
| 결과 0건 | 빈 상태를 표시한다 | 조건을 풀 수 있게 한다 |

- 상태: **조건 없음 / 조건 적용 중**이며, 적용 중일 때 결과 건수를 함께 보여 준다.

### 4-3. 문서 표

- 구성: 문서명 · 대메뉴 · 법령 · 표시 · 버전 · 최종 수정 · 관리 일곱 열.

| 트리거 | 동작 결과 | 이동 / 메시지 |
|---|---|---|
| 문서 선택 | 처리유형에 맞는 화면·모달을 연다 | SCR-EDOC-010 |
| 분류 미확정 문서 | 그 사실을 표시 열에 드러낸다 | 표에서 빼지 않는다 |
| 2차 검토 대상 문서 | 별도 표시를 붙인다 | 분류 미확정과 다른 축이다 |
| 더 보기 | 정해진 개수만큼 더 불러온다 | — |

- 상태: 행 단위로 **분류 확정 / 미확정**이 갈리고 **2차 검토 대상** 표시가 덧붙는다. 표 전체는 **비어 있음 / 일부 표시(더 있음) / 전부 표시** 세 상태를 갖는다.

해당 없음 — 조회 목록이라 저장형 입력이 없다. 문서에 파일을 올릴 때의 검증은 기준문서 업로드 모달(SCR-EDOC-010 §5)이 담당한다.

## 6. 정책

- **분류가 정해지지 않은 문서를 감추지 않는다** — 별도 함에 모으되 눈에 보이게 두고 건수를 요약에 올린다. 감추면 아무도 분류하지 않는다.
- **미확정과 2차 검토를 같은 표시로 묶지 않는다** — 해소 방법이 다르다. 앞은 그 문서가 어느 업무인지 정하면 되고, 뒤는 메뉴 구조를 바꿀지 정해야 한다.
- **조회 선택지는 실제 데이터에서 만든다** — 문서가 없는 대메뉴를 선택지에 남기면 0건만 보게 된다.
- **보류된 결정을 화면에 남긴다** — 2차 검토가 보류 상태라는 사실을 문장으로 표시한다. 결정이 미뤄졌다는 것도 다음에 할 일의 정보다.
- **이 화면은 분류를 바꾸지 않는다** — 문서가 어느 업무에 속하는지는 업무 등록·수정(SCR-DOC-007)에서 정한다. 두 곳에서 분류를 바꾸면 어느 쪽이 맞는지 알 수 없다.
- **법령 근거를 화면에 붙이지 않는다** — 이 함은 분류 대기 문서의 보관소이지 특정 조문의 직접 이행 수단이 아니다. 근거는 **문서마다** 갖고 표에 함께 보여 주며, 규칙은 공통 근거 연계(SCR-COM-008)를 따른다.

## 7. 미결사항

없음. 미확정 문서의 표시 방식·두 표시 축의 구분·조회 선택지의 출처·보류 결정의 노출·분류 변경의 소속·법령 근거의 위치는 모두 §6에서 확정했다.

안전점검 계열의 메뉴 승격 여부는 이 화면의 미결이 아니라 **메뉴 구조 결정**이며, 결정될 때까지 2차 검토 대상 표시로 드러낸다.
