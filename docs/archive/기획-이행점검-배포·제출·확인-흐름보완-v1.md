## 0. 결론

**«재난안전과가 점검표를 배포하고, 부서가 내려받아 작성해 올린다»가 맞다.** 세 근거가 같은 흐름을 가리킨다.

| 근거 | 무엇을 말하나 |
|---|---|
| 담양군 5개년 공문 실측 ([분석-업무문서-5개년-실측-v1](분석-업무문서-5개년-실측-v1.md) F01 · 378건) | 재난안전과가 **5월 중순·11월 하순**에 «이행사항 자체점검 실시 통보»를 보내고(점검표 붙임), 부서가 **반기 말까지** «자체점검표 제출»로 회신하며, 12월에 **2차 촉구**가 나간다. 회신 중에는 «결과제출(수정)»도 있다 — 보완 요구가 실제 업무다 |
| 담양군 업무 분류기준(94단계) **IND-10** | ① 반기 의무이행 점검계획 **수립·시달** → ② 부서별 의무이행 점검 **결과 제출** → ③ 점검 결과 **경영책임자 보고** 세 단계로 나눠 두었다 |
| 중대재해처벌법 시행령 **§5②1·2호 · §11②1·2호** | 경영책임자는 «직접 점검하지 않은 경우 점검 결과를 **보고받고**», 의무 미이행이 확인되면 «인력 배치·예산 추가 편성 등 **필요한 조치**»를 한다 |

지금 화면에는 이 가운데 **②(부서 등록)와 ③(마감 보고 상신)만** 있다. 그래서 네 가지가 빠진다.

1. 부서는 **무엇을 점검하라는지·언제까지인지**를 시스템에서 알 수 없다 — 양식은 공문으로 따로 온다.
2. **점검을 안 한 부서와 점검했더니 지켜지지 않은 부서가 같은 «미이행»** 으로 보인다. 게다가 내 할일은 «이행»일 때만 끝나서, **미이행을 정직하게 적은 부서의 할 일이 영영 남는다** — 부서가 «이행»으로 찍게 만드는 구조다.
3. 부서가 올린 값을 **아무도 확인하지 않고** 그대로 군수에게 보고한다. 보고한 뒤에도 부서 값이 바뀐다.
4. 미이행이 나와도 **그 다음(조치계획·조치 결과)으로 가는 길이 없다** — 법이 요구하는 것은 점검 그 자체보다 이 후속 조치다.

이 문서는 같은 화면 안에 **회차 배포 패널 하나**를 더하고, 부서 줄의 상태를 **제출 여부 × 점검 결과** 두 축으로 나누고, 재난안전과의 **확인·보완 요청**과 부서의 **미이행 조치계획**을 붙이고, 마감 보고를 그 값으로 채운 뒤 **잠그는** 것으로 네 가지를 메운다.

### 1-3. 내 할일

- 정의서(SCR-MYW-001 §4-3-1 카드 전수표)는 이행점검을 **«넣지 않는 것(후속)»** 으로 두었다. 운영에서는 부서가 **시스템 안에서 점검이 시작됐다는 것을 알 길이 없다** — 신호는 공문뿐이다.
- 프로토타입에는 옛 자동발행(`W-CMP-IND`·`W-CMP-CIV`, 05-14·11-21)이 카드를 내지만, 완료 판정이 **«이행(DONE)»뿐**이다. 미이행·해당없음을 정직하게 등록해도 카드가 끝나지 않는다(§2-2 G2).

## 2. 진단

### 2-1. 맞는 것 — 그대로 둔다

1. **부서 × 회차** 단위 저장 — 상반기 값이 하반기를 완료로 만들던 결함을 막는다.
2. **두 법률 축** 분리(중대산업재해 · 중대시민재해).
3. «이행»은 **증빙**이, «해당없음»은 **사유**가 있어야 저장된다 — 종이 서식의 «해당 없음으로 빠져나가기»를 막는다.
4. 부서는 자기 줄만, 관리·감독 계층은 조회, **독촉 권한**(11-10 확정 — 부서 담당자 계정에는 자기 부서 줄 독촉이 없다).
5. **마감 보고 = 경영책임자 보고 공문** — 결재선 3단계 · 결재 결과 수기 기록 없음 · 반려·반송이면 다시 상신(10-07).
6. 부서 표를 경영방침 게시 현황과 **같은 엔진**으로 그린다.

| B. 시스템 안에서 항목별로 입력하는 온라인 점검표(F5형) | 후속 | 항목 마스터(관계 법령별 의무 목록)가 확정돼야 성립한다 — 지금은 «목록 미등록»이다. 확정되면 §4-2 의 «결과 요약»을 항목 입력으로 바꿀 수 있고, 양식 내려받기는 남긴다 |
| C. 지금처럼 상태 + 사진 | 불채택 | G1~G5 |

## 4. 기능 상세

### 4-1. 점검 배포 패널 (재난안전과)

**위치** — «부서별 이행 현황» 카드 맨 위, 축 탭·회차 선택 바로 아래. 편집 수단은 재난안전과 담당자에게만 있고, 그 밖의 사람에게는 배포 내용 요약(배포일·기한·양식)만 보인다.

| 항목 | 필수 | 기본값 | 설명 |
|---|:--:|---|---|
| 점검 양식 | 예 (1개 이상) | **지난 회차 양식을 이어받기로 제안** | 점검표(HWP·XLSX 등)와 작성 안내. 공통 업로드 칸 `general` 프로필(12종 · 20MB · 10개) |
| 안내 문구 | 아니오 | 없음 | 부서 화면의 회차 머리에 그대로 보인다(예: «부서장 서명 후 스캔본을 올려 주세요») |
| 제출 기한 | 예 | 반기 말일(06-30 · 12-31) | 실측 기한이 반기 말일이다 |
| 대상 부서 | 예 (1개 이상) | 산업 = **전 부서** · 시민 = **공중이용시설 보유 부서**(조직도 속성) | 공용 조직도 다중 선택(`ORGPICK.deptsPanel`)으로 더하고 뺀다. 대상이 아닌 부서는 표에 «대상 아님» — 분모에서 빠진다 |

- `[점검 배포]` → 확인 창: «대상 N개 부서 담당자(없으면 부서장)에게 할 일과 알림이 갑니다 · 기한 YYYY-MM-DD». **새 정보만** 낸다(공문 골격 확인 단계와 같은 원칙).
- **배포 뒤 고칠 수 있는 것**

  | 무엇 | 허용 | 따라오는 것 |
  |---|---|---|
  | 기한 | **늘리기만** — 이미 받은 부서의 기한을 앞당기지 않는다 | 미제출 부서에 알림 |
  | 대상 추가 | 가능 | 그 부서에 할 일·알림 |
  | 대상 제외 | **제출하지 않은 부서만** — 제출 기록이 사라지면 이력 변조다(CLAUDE.md §14-7) | 그 부서 할 일 회수 |
  | 양식 교체 | 가능 — **판 번호를 올리고 이전 판을 남긴다** | 이미 제출한 부서는 그대로(어느 판으로 냈는지 제출 기록에 남는다) · 미제출 부서 회차 머리에 «양식이 바뀌었습니다(제2판 · 날짜)» |

- **배포 취소** — 제출한 부서가 0일 때만. 확인 창이 회수되는 할 일 수를 밝힌다.
- **회차 선택지에 상태를 붙인다** — «배포 전» · «진행 중 · D-n» · «기한 경과» · «마감 보고됨».
- **시기 알림** — 재난안전과 담당자 내 할일에 «하반기 의무이행 점검 배포 준비»가 실측 시기(5월 중순 · 11월 하순) 2주 전에 뜬다. 배포는 사람이 하되 시기는 시스템이 알린다(§4-7 · D-3).

### 4-2. 부서 — 내려받기 · 작성 · 제출

**회차 머리(부서 화면)**

```
2026 하반기 중대산업재해 의무이행 점검      배포 11-21 · 기한 12-31 (D-40)
[점검표 내려받기 (제1판)]   안내: 부서장 서명 후 스캔본을 올려 주세요.
```

- **배포 전 회차** — 머리에 «재난안전과가 점검을 배포하면 이 줄에서 제출합니다». 우리 줄에 제출 버튼이 없다.
- **버튼 이름 `[확인 등록]` → `[결과 제출]`** — 재난안전과의 `[확인]`과 이름이 겹치지 않게 한다. 경영방침 게시 현황은 `[확인 등록]` 그대로다.

**결과 제출 창**

| 항목 | 필수 | 규칙 |
|---|:--:|---|
| 점검 결과 | 예 | **전 항목 이행 / 일부 미이행 / 해당없음** 중 하나 |
| 작성한 점검표 | 전 항목 이행 · 일부 미이행이면 예 | 내려받은 양식으로 작성한 파일(서명본 스캔 포함). 공통 업로드 칸 |
| 점검일 | 예 | 기본값 = 시연 기준일(`DYV2.today()`) |
| 비고 | 아니오 | 한 줄 |
| 미이행 내용 | 일부 미이행이면 예 | 어느 항목이 왜 지켜지지 않았는지(점검표 항목 번호를 적도록 안내) |
| 조치계획 | 일부 미이행이면 예 | 무엇을 하겠다 |
| 조치 예정일 | 일부 미이행이면 예 | 제출 기한 뒤 날짜도 된다 |
| 필요한 지원 | 일부 미이행이면 예 | 인력 · 예산 · 기타 · 부서 자체 처리 (여럿 고름) — 군수 보고 «필요한 조치» 절의 원료다 |
| 해당없음 사유 | 해당없음이면 예 | 사유 없는 저장 불가(현행 그대로) |

- **«위치» 칸은 이 화면에서 뺀다** — 증빙이 «작성한 점검표 파일»이 되면서 «어디에 비치했나»가 뜻을 잃는다. 경영방침 게시는 위치가 핵심이라 그쪽은 그대로 둔다.
- **제출하면 결과가 무엇이든 줄이 «확인 대기»가 되고 내 할일 카드가 내려간다** — G2 의 역유인을 없애는 핵심 규칙이다.
- 확인 전에는 `[제출 고치기]` · `[제출 취소]`(확인 창 필수 — G13). 확인 뒤에는 잠기고, 고치려면 재난안전과가 `[확인 취소]`(사유 필수)를 해야 한다.
- **기한 뒤 제출은 막지 않는다** — «지연 제출(D+n)»으로 표시한다. 마감 보고 상신 뒤에는 막는다.

### 4-3. 재난안전과 — 확인 · 보완 요청

- 확인 대기 줄마다 `[확인]` · `[보완 요청]`. 대기가 2건 이상이면 카드 머리 `[확인 대기 N건만 보기]`가 그 줄만 거른다.
- `[확인]` — 제출 내용(결과 · 파일 · 미이행 내용 · 조치계획)을 펼쳐 보이고 확인한다. 확인자 · 확인일을 남긴다.
- `[보완 요청]` — **사유 필수**(무엇을 다시 할지 모르면 보완 요청이 작동하지 않는다). 부서 줄에 «보완 요청 — 사유»가 상시 보이고 부서 내 할일에 다시 뜬다. 재제출하면 차수(1차 · 2차 …)가 올라가고 **이전 제출 파일은 이력으로 남는다**.
- **같은 사람이 제출하고 확인하지 않는다** — 재난안전과 줄(자기 부서)은 재난안전과의 다른 담당자가 확인한다. 다른 담당자가 없으면 «확인자 없음 — 다른 담당자 지정 필요»를 드러낸다(D-6).
- **확인은 결과 값을 바꾸지 않는다** — 결과가 틀렸으면 보완 요청으로 부서가 고친다. 재난안전과가 부서 값을 대신 고치면 대리 작성이다.
- 일괄 확인은 첫 판에 두지 않는다 — 부서마다 파일을 열어 봐야 확인이 의미가 있다(위험성평가식 «열람 체크 후 일괄 확인»은 후속 검토).
- 이름을 «반려»가 아니라 **«보완 요청»** 으로 둔다 — 이 시스템에서 «반려»는 온나라 결재 반려와 위험성평가 확인 반려를 가리켜, 같은 화면의 마감 보고 반려와 섞인다.

### 4-4. 미이행 — 조치계획과 조치 결과

- 조치계획은 제출 때 받는다(§4-2).
- **조치 결과** — 부서가 우리 줄 `[조치 결과 등록]`: 조치 완료일 · 조치 내용 · 증빙 1개 이상. 상태는 **조치 예정 → 조치 완료**(예정일이 지나면 «조치 지연»).
- **마감 보고 뒤에도 조치 결과는 등록할 수 있다** — 보고된 점검 결과는 잠기지만 조치 결과는 **덧붙이는 기록**이라 보고 내용을 바꾸지 않는다.
- **다음 회차로 이어 보인다** — 다음 회차를 배포하면 그 부서 회차 머리에 «지난 상반기 미이행 조치 1건 — 예정일 지남», 재난안전과 화면 머리에 «지난 회차 조치 미완료 N건»이 뜬다.
- **위험성평가 개선조치로 보내지 않는다** — 그쪽은 유해·위험요인 감소대책이고 확인 주체와 흐름이 다르다(CLAUDE.md §4-3). 점검 미이행 조치는 이 화면 안에서 끝낸다.

### 4-5. 독촉

- 대상은 **미제출**(대상 부서인데 제출 없음) · **보완 요청 후 미재제출** · (선택) **조치 지연**. 확인 대기 · 확인 완료 줄에는 `[독촉]`을 내지 않는다.
- 권한은 현행 그대로다 — 주관부서 · 그 부서장이 보내고, 부서 담당자 계정에는 자기 부서 줄 독촉이 없고, 군수는 보내지 않는다(11-10).
- 문구를 나눈다 — «결과 제출 독촉» · «보완 제출 독촉» · «조치 결과 독촉».
- 카드 머리 일괄 버튼(운영 화면 «미이행 N개 부서 독촉»)은 **«미제출 N개 부서 독촉»** 으로 바꾸고 미제출만 센다.

### 4-6. 반기 마감 보고(경영책임자 보고)와 잠금

- **상신 조건은 «배포된 회차» 하나다.** 미제출 · 확인 대기가 남아 있어도 막지 않는다 — 5개년 실측상 전 부서 제출이 성립한 해가 없어 100% 게이트를 걸면 보고가 영원히 갇힌다(CLAUDE.md §14-9). 대신 상신 확인 창이 «미제출 N · 확인 대기 N · 보완 요청 N»과 «확인되지 않은 줄은 ‘부서 제출값(미확인)’으로 올라갑니다»를 밝힌다.
- **지면** — 10-07 정의를 보강한다. 새 항목을 지어 넣지 않고 화면 값을 옮긴다.
  1. 회차 · 배포일 · 기한 · 양식 판
  2. 두 축 각각의 요약 — 대상 · 제출 · 확인 완료 · 전 항목 이행 · 일부 미이행 · 해당없음 · 미제출
  3. 부서별 표(**대상 부서만**) — 부서 · 진행(확인 완료 / 미확인 / 미제출) · 결과 · 해당없음 사유 · 제출일(지연 표시)
  4. **미이행 사항과 조치계획** — 부서 · 미이행 내용 · 조치계획 · 예정일 · 필요한 지원. **§5②2 «필요한 조치»를 군수가 판단하는 자리다**
  5. **미제출 부서 목록** — 미이행과 분리한다(G2)
  6. 지난 회차 조치 미완료(있을 때만)
- 붙임은 지금처럼 없다(10-07 — 부서 점검표는 시스템에서 조회).
- **상신하면 그 회차를 잠근다** — 결과 제출 · 고치기 · 취소 · 확인 · 보완 요청 · 대상 · 기한 · 양식 변경 전부. 반려 · 반송 회신이 오면 풀린다. 잠긴 회차 머리: «2026 하반기 마감 보고 상신됨(결재중) — 이 회차 값은 보고된 그대로입니다». **예외는 조치 결과 등록(§4-4) 하나다.**
- 상신 기록 · 결재선은 회차별로 **저장소에 남긴다**(G8).
- 체계 점검(F5) 결과를 같은 보고에 담을지는 D-5.

### 4-7. 내 할일 · 알림

**SCR-MYW-001 §4-3-1 카드 전수표에 더할 행** (받는 사람 · 생기는 때 · 내려가는 때를 모두 채운다 — 한 칸이라도 비면 끝나지 않는 카드가 된다)

- 8 은 기한이 있어 «지연 · 이번주» KPI에 들어간다.
- 정의서 «넣지 않는 것(후속)»에서 «이행점검 반기 부서 확인 등록과 독촉»을 지운다.
- **알림(SCR-ADMIN-002)** — 배포 · 기한 변경 · 보완 요청 · 대상 추가 4개를 «받는 사람이 할 일이 있을 때만» 기준으로 더한다. **확인 완료는 알리지 않는다** — 받는 사람이 할 일이 없다(결재완료를 알리지 않는 것과 같은 기준).
- **옛 자동발행(`W-CMP-IND`·`W-CMP-CIV`)의 완료 판정을 «이행(DONE)»에서 «제출됨»으로 바꾼다.** 단 **경영방침 게시(`policy-post`)는 «게시(DONE)» 그대로**다 — 게시는 게시해야 끝나는 일이다. 판정은 키마다 다르다. 업무 관리 이행 관리의 IND-10-02 · CIT-01-02(같은 표를 판정 원본으로 쓴다)도 «제출됨»을 따른다.

### 4-8. «관계 법령 의무이행 점검» 절 정리 (G11)

- **§5-1(종사자 · 반기)** 행의 현황 칸을 «관계 법령 목록 미등록» 대신 **위 산업 축 부서 점검의 그 회차 현황**으로 바꾼다 — 예: «2026 상반기 · 제출 9/11 · 확인 7 · 일부 미이행 2 — 점검 항목은 배포한 점검표에 있습니다». 분류기준 IND-10 이 이 점검의 근거에 §5② 를 넣어 두었다.
- **§11-1(공중이용시설 · 연 1회)** 행은 **시민 축 양식에 관계 법령 의무 항목이 들어 있을 때만** 같은 방식으로 잇는다. 분류기준은 시민 축 점검(CIT-01-02)의 근거를 시행령 §10제3·5호(체계 · 반기)로, §11 연 1회 점검(CIT-04-01)은 별도 «확인 필요»로 두었다 — 겸하는지는 받을 양식(§10)을 보고 정한다. 겸하면 주기 칸에 «반기 점검으로 연 1회 의무 충족»을 밝히고, 겸하지 않으면 «목록 미등록» 그대로 둔다.
- **관계 법령 목록을 시스템이 지어내지 않는다는 원칙은 그대로다.** 다만 «목록이 없어서 점검을 못 한다»가 아니라 **«목록은 배포 양식 안에 있다»** 는 사실을 말한다. `[관계 법령 목록이란]` 안내도 그 한 줄을 맞춘다.
- §5-3 · §11-3(교육 점검) 행은 현행 그대로.

## 5. 상태 정의

### 5-1. 회차 상태 (축 × 반기)

| 상태 | 조건 | 부서 | 재난안전과 |
|---|---|---|---|
| 배포 전 | 배포 기록 없음 | 제출 불가 | 준비 · 배포 |
| 진행 중 | 배포됨 · 기한 전 | 제출 | 확인 · 보완 요청 · 독촉 · 기한/대상/양식 조정 |
| 기한 경과 | 배포됨 · 기한 지남 · 상신 전 | 제출(지연 제출) | 위와 같음 + 마감 보고 |
| 마감 보고됨 | 상신(결재중 · 결재완료) | 조치 결과만 | 조회 |
| (반려 · 반송) | 온나라 회신 | 진행 중 / 기한 경과로 돌아간다 | 고쳐 다시 상신 |

- **시스템 도입 전 회차**(배포 기록 없이 결과만 있는 회차)는 «배포 기록 없음»으로 표시하고 조회만 한다 — 배포 기록을 지어 만들지 않는다.

### 5-2. 부서 줄 — 두 축

**진행 축**

| 진행 | 뜻 |
|---|---|
| 대상 아님 | 이 회차 대상 부서가 아니다 — 분모에서 빠지고 흐리게 보인다 |
| 미제출 | 대상인데 제출이 없다 · 기한이 지나면 «미제출 · 기한 경과» |
| 확인 대기 | 제출했다 |
| 보완 요청 | 재난안전과가 사유와 함께 돌려보냈다 |
| 확인 완료 | 재난안전과가 확인했다 |

**결과 축** (제출한 줄만)

| 결과 | 저장 코드 |
|---|---|
| 전 항목 이행 | `DONE` (현행 재사용) |
| 일부 미이행 | `TODO` (현행 재사용) |
| 해당없음 | `NA` (현행 재사용) |

- **저장 코드는 그대로 셋이다.** «미제출»은 새 코드가 아니라 **기록이 없음**으로 판정한다 — 손대지 않은 줄을 «미이행»으로 만들어 보여 주던 것만 멈춘다. 그래서 같은 표를 쓰는 경영방침 게시 현황도 «미등록 / 게시 / 미게시 / 해당없음»으로 자연히 갈린다(정의서 SCR-SBM-006 §4-1 이 이미 약속한 4상태와도 맞는다).
- **확인은 별도 축**(`확인 상태: 대기 / 완료 / 보완 요청` · 확인자 · 확인일 · 사유 · 차수)이고 결과 값을 건드리지 않는다 — 위험성평가 개선조치 완료 확인과 같은 구조다(CLAUDE.md §4-3).
- **배포 · 확인 축은 이행점검에서만 켠다.** 경영방침 게시는 배포물이 방침 자체이고 확인 단계를 정한 적이 없다 — 미등록 분리만 함께 받는다.

### 5-3. 카드 머리 요약

`대상 N · 제출 N (제출률) · 확인 완료 N · 전 항목 이행 N · 일부 미이행 N · 해당없음 N (사유 없음 N) · 미제출 N (기한 경과 N)`

- **«이행률»을 «제출률»로 바꾼다** — 이행 여부는 부서 자기 신고라, 확인 전 값을 비율로 내면 측정값처럼 읽힌다. 이행은 결과 칸이 개수로 말한다.

| **D-1** | 부서의 **결과 회신 공문**을 계속 받나, 시스템 제출로 갈음하나 | **갈음** — 결과는 재난안전과 마감 보고 공문 1건으로 군수에게 올라간다. 부서 회신 공문은 같은 결과의 사본이다(G10) | 유지로 두고 가이드에 «공문도 보내되 판정은 화면 제출»(현행) |
| D-2 | 재난안전과 **시달 공문**을 계속 보내나 | 시스템 배포 + 알림으로 갈음. 필요하면 «시스템에서 내려받으라»는 짧은 공문만 | 공문 시달과 별개로 배포 — 시스템은 배포일만 기록 |
| **D-3** | 부서 할 일이 **배포하는 순간** 생기나, 정해진 날짜에 자동으로 생기나 | **배포하는 순간** — 양식 · 기한 · 대상 없이 빈 할 일을 먼저 내지 않는다. 시기는 재난안전과에 미리 알린다(§4-7 #11). ⚠ CLAUDE.md §14-3(«주기 업무는 사람이 발행을 누르지 않는다», 발주처 확정 2026-08-11)과 관계 — 자동으로 나가는 것을 재난안전과의 «배포 준비» 할 일로 옮기는 해석이라 확인이 필요하다 | 재난안전과 배포 순간 생성(프로토타입 시연) |
| D-4 | 점검표에 **부서장 서명**을 요구하나 | 요구 — 안내 문구로 받고 시스템은 파일 내용을 판정하지 않는다 | 안내 문구 비움 |
| D-5 | 반기 마감 보고에 **체계 점검(F5) 결과**를 함께 담나 | 담는다 — §4 반기 점검도 경영책임자가 보고받아야 하는 의무다. 절 1개(확정 여부 · 미흡 항목 수) | 담지 않음(현행) |
| D-6 | 재난안전과 자기 부서 제출의 **확인자** | 재난안전과의 다른 담당자(예: 팀장) | «확인자 없음» 표시 |
| D-7 | 시민 축 **대상 부서** 기본값 | 공중이용시설 보유 부서(조직도 속성) — 실측 11곳 명단과 대조 | 조직도 속성 기본값 |

**받을 자료** — 2026 상반기(또는 2025 하반기) **자체점검 실시 통보 공문의 붙임 양식**(산업 · 시민 각각). 첫 배포에서 이어받을 양식이자 시드이고, 시민 축 양식에 관계 법령 의무 항목이 있는지(§4-8 · §11-1 행을 이을지)도 이것으로 판단한다. 11-04 자료 요청 ①은 결과와 부서 제출 원본이었고 양식 자체는 받지 않았다.
