## 0. 검토 결론 요약

- §7에 실제 미결 표가 남은 정의서는 4건 — SCR-DOC-002(5행)·SCR-DOC-003(3행)·SCR-DOC-007(3행)·SCR-FAC-002(6행), 그 밖에 열린 꼬리 서술 3건(EVL-001·FAC-002 사진·EDU-006 이력). 나머지 72건은 "없음"으로 닫혀 있고 재론할 것이 없다.
- **자체 기획으로 소거·확정 가능: 7건**(§1). 판단이 아니라 위치가 문제인 것(외부 연계 항목의 화면 분산·3중 중복): **10행 → 대장 통합**(§2). 문서가 구현 현실과 어긋난 사실 정정: **2건**(§3).
- 이 편집을 마치면 99 대장의 "자체 기획 미결 0건" 선언이 다시 참이 된다.

### 판단 원칙 (모든 지시의 근거 틀)

1. **기능은 RFP(SFR-001~021) 범위 안에서 최소로 확정한다.** RFP가 요구하지 않는 기능은 "구축하지 않는다"로 닫는 것이 기본값이고, 닫는 근거를 §6에 남긴다. 발주처가 회의로 직접 확정한 사항(교육 공문 순서·채용시 탭 구성·첨부 슬롯 등)은 재론 금지.
2. **프로토타입 미구현은 기획 미결이 아니다**(99 §1 현행 원칙 유지). 미구현은 §5·§6에 구현 차이로 명시한다.
3. **외부 준비사항의 인덱스는 99 대장 하나다.** 여러 화면에 걸치는 항목은 대장이 상세를 갖고 화면 §7은 포인터만 둔다(SCR-EDU-007 §7이 선례). 한 화면 고유 항목은 그 화면이 상세를 갖되 대장에 인덱스 행을 둔다.
4. **`python3 docs/screen-definitions/_lint.py` 전체 통과가 완료 조건이다.** §7 포인터 스타일은 본문 앞부분이 `없음.`으로 시작해야 하고, 항목 표를 유지하는 정의서는 `기한` 컬럼이 있어야 한다.

## 1. 소거·확정 지시 — 7건

### A-1. SCR-DOC-003 §7 `EXEC-01`(업무단계별 법정 마감일) — 행 삭제, §6 P8 보강

- §6 P8이 같은 내용을 이미 확정했다("기한 초과 상태를 만들지 않는다 · 마감일이 들어오면 그때 정한다"). §7 행은 중복.
- P8 보강(취지): 업무단계별 마감일 축은 **구축 범위에서 제외**로 확정한다. 근거 — RFP에 요구 없음(SFR-014는 점검·기록·변동이력을 요구하고 기한 축은 요구하지 않는다), 기한 관리는 업무 발행 축(SCR-WRK-001)의 소관이라 역할이 갈린다. 마감일 자료가 담양군에서 확정되면 미결 부활이 아니라 **변경 요청**으로 반영한다.

### A-2. SCR-DOC-003 §7 `EXEC-03`(조건부 이행항목 적용 여부 판단 기준) — 행 삭제, §6 P7 보강

- §6 P7이 동작을 확정(해당없음 사유 필수·자동 판정 없음).
- P7 보강(취지): **적용 여부 자동 판정 기능은 구축하지 않는다**로 확정. 판단 기준 문서는 시스템 입력이 아니라 재난안전과 운영 지침 소관이며, 시스템 몫은 사유를 강제·보존·노출하는 데까지다(RFP에 자동 판정 요구 없음).

### A-3. SCR-DOC-002 §7 `LIST-04`·`LIST-05` — 행 삭제, 대장 EXT-07로 흡수

- 화면 기능은 완결이다(§4-7 중복 정리 · P6 교정 수단 · P7 덧씌움 · "원본 확인 필요" 표시). 남은 것은 담양군의 **원장 데이터 확인 작업** = 외부 준비. §2 B-4에 따라 EXT-07에 흡수한다.

### A-4. SCR-FAC-002 `TBD-005` — 자체 촬영 업로드 꼬리 닫기

- §6 현장 사진 문단과 §7 TBD-005의 "자체 촬영분 업로드는 소비 화면이 정해질 때 붙인다" 꼬리를 닫는다: **자체 촬영 업로드는 구축 범위에서 제외**로 확정. 근거 — RFP에 시설물 사진 요구 없음(SFR-002는 현황 연계·관리·점검), FDT-13 원칙(소비처 없는 입력란 금지)의 동일 적용. 소비 화면(현장조사 축) 신설은 별도 변경 요청 사안.
- 사진 **수신**은 FMS 추가 연계 신청에 합류: §7 말미 "네 건(TBD-001~004)은 같은 신청 한 건" → **다섯 건(TBD-001~005)**. TBD-005의 기한 `미정` → `시스템 개통 전`.

### A-5. SCR-FAC-002 §7 `TBD-006`(조직도 소관부서 매핑) — 행 삭제

- 입력 방식은 §6 FDT-09가 이미 확정(조직도 선택 + 담양군 외 관리주체만 기관명 직접 입력). 외부 의존(전체 부서 명단)은 **EXT-02와 같은 항목**이라 별도 행이 중복이다. 행을 지우고 EXT-02 참조 한 줄로 대체. 프로토타입이 자유 입력인 사실은 §6 FDT-09에 이미 명시돼 있으므로 유지(원칙 2).

### A-6. SCR-EVL-001 §7 둘째 문단 — 낡은 꼬리 정정

- "도급사 수준평가 **화면 신설 자체**는 … 도급 관리 쪽의 후속 과제다"는 사실과 다르다. **SCR-SBM-004 §4-2가 수급인 안전보건 수준 평가를 이미 정의**하고 있다(평가 축 3·주기 계약 전 1회+반기 1회·유효기간 1년·상태 4단계 — EVL-14 확정값과 일치). "후속 과제" 표현을 지우고 SCR-SBM-004 §4-2·§6 상호 참조로 교체한다. 신규 화면·신규 화면 ID를 만들지 않는다.

### A-7. SCR-EDU-006 §6 지정일 변경 이력 — '잔여 후속' → 확정

- 현행 서술 "지정일 변경 이력은 현재 남기지 않는다 — 최신값만 보관한다(**잔여 후속**)"를 확정으로 전환: **본개발에서 변경 이력(이전 값·변경일·처리자·사유)을 남긴다.**
- 근거 — ① 지정일은 법정 교육 의무 판정의 기산점이라 값이 바뀌면 과거 판정이 통째로 달라진다(정의서 자체 서술) ② SFR-014 "기록 및 변동이력" ③ 99 §2 공통 정책(식별값·버전 — 개정 이력). 프로토타입은 최신값만 보관한다는 구현 차이 명시는 유지. '잔여 후속' 라벨 제거.
- `CLAUDE.md` §4 잔여 후속 ②에 "본개발 확정 — SCR-EDU-006 §6" 부기(§3 C-2와 함께 처리).

## 4. 건드리지 말 것

- 각 정의서 §6의 기확정 정책 재론 금지. 특히 발주처 회의 확정 사항(교육 공문 순서, 채용시 탭 3개, 첨부 슬롯, 공문 대메뉴 금지 등).
- EXT-01~13의 기존 대체 동작 문구 변경 금지 — B-3·B-4는 **서술 추가만**.
- **EXT-13(교육시간 면제·감면)은 발주처 확인으로 유지** — 재량 조항 + 판정 입력 부재라 자체 확정 불가.
