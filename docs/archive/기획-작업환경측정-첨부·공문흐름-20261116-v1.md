## 0. 한 줄 요약

작업환경측정은 **재난안전과가 반기마다 측정기관에 맡기고, 결과를 받아 해당 부서에 공문으로 알리는 업무**다(온나라 원장 실측). 그런데 지금 화면은 이 업무를 **부서가 사업장별 계획을 등록하고 결과를 첨부하는 업무**로 그리고 있고, 공문 기능이 없다.
→ 회차(연도·반기) 하나를 단위로 바꾼다. 재난안전과가 **결과보고서를 첨부 → 결과 안내 공문 기안 → 온나라 보내기**까지 하고, 부서에는 **개선이 필요한 사업장의 조치**만 남긴다.

여기서 읽히는 것:
1. **측정 주체는 재난안전과다.** 계획 내부결재 → 측정기관 위탁 → 결과 통보 수신 → 비용 지급 → 해당 부서에 결과 안내 공문. 이 순서가 2년 연속 반기마다 같다.
2. **부서는 공문을 받는 쪽이다.** 물순환사업소 원장에는 받은 «실시 안내»·«결과 안내»만 있고, 부서가 무엇을 제출한 기록은 없다.
3. **예외가 있다** — 농업기술센터기술보급과는 자체적으로 측정하고 내부결재로 끝낸다(재난안전과 공문이 없다).
4. 이 흐름과 별개로 연 1회 «작업환경측정 및 특수건강진단 대상조사를 위한 MSDS 자료요청»(2월 전 부서 발송)이 있다(`분석-업무문서-5개년-실측-v1` F08). 이것만 부서에서 자료를 받는 업무다.

## 2. 현행 화면과 어긋나는 점

| | 실제 업무 | 현행 화면 |
|---|---|---|
| 단위 | 반기 회차 1건(재난안전과 계획 1건) | 사업장 × 유해인자 계획 행 |
| 계획 등록 | 재난안전과 | 부서 담당자(소속 부서 고정) · 재난안전과 |
| 결과보고서 | 측정기관 → 재난안전과(한 부) | 행마다 부서가 첨부 |
| 부서 통보 | 재난안전과 «결과 안내» 공문 | **없음** |
| 부서가 할 일 | 개선이 필요한 곳의 조치 | 계획 등록 · 첨부 · 완료 처리 · 개선조치 |

현행 구조는 `SCR-WEM-001`·`002` 와 2026-10-06 기획확인 4차 3-3(«계획 등록 부서 소속 고정»)에서 왔다. 그 결정은 «남의 부서 명의로 등록되는 구멍»을 막은 것이고, 누가 측정 업무의 주체인지를 정한 결정은 아니다.

## 3. 제안 흐름

### 3-1. 단계

| # | 누가 | 무엇을 | 화면 |
|:--:|---|---|---|
| ① | 재난안전과 | **회차 등록** — 연도·반기, 측정기관, 측정 예정 기간, **대상 사업장**(사업장 관리의 «대상»·«검토 중» 사업장에서 고른다. 기본값 = 직전 회차 대상) | 목록 상단 `[＋ 측정 회차 등록]` |
| ② | 재난안전과 | (선택) **실시 안내 공문** — 수신 = 대상 사업장 소관 부서 | 회차 카드 `[실시 안내 공문]` |
| ③ | 재난안전과 | **결과보고서 첨부** — 측정기관이 보낸 보고서(회차 1부, 여러 파일 가능) + 사업장별 결과(적정 / 개선 필요 · 개선 요구 · 조치기한) | 회차 카드 `[결과 등록]` |
| ④ | 재난안전과 | **결과 안내 공문 기안 → 미리보기 → 온나라로 보내기** — 붙임 = ③의 보고서(이미 올린 파일에서 고른다) + 별지 «사업장별 측정 결과» | 회차 카드 `[결과 안내 공문]` |
| ⑤ | 시스템 | 보내는 순간 회차를 잠그고, **개선 필요 사업장의 부서에 할 일·알림**을 만든다 | — |
| ⑥ | 부서 담당자 | 개선조치 완료 — 개선 증빙·완료일·결과 | 현행 상세 `[개선 증빙 등록]`·`[개선조치 완료]` 그대로 |

**모든 사업장이 «적정»이면 부서 할 일은 없고, ④에서 업무가 끝난다.** 공문은 결과를 알리는 용도로 그대로 보낸다(§7 — 근로자에게 알릴 의무).

### 3-2. 지향(«첨부 → 공문 → 업로드»)과 맞추기

재난안전과의 반기 업무가 ① → ③ → ④ 세 번의 클릭 덩어리로 끝난다. 입력은 **파일 1개 이상 + 사업장별 결과 고르기**뿐이다. 측정 실시일·유해인자 같은 값은 보고서에 있으므로 필수로 받지 않는다(§9 D-4).

### 3-3. 화면 구성 변경

- **목록(`work-env.html`)**: 맨 위에 **회차 카드**(올해 상·하반기 2장)를 두고, 그 아래 현행 사업장 행 표를 둔다. 카드 한 장에는 상태 칩(«측정 전 → 결과 등록 → 공문 보냄 → 조치 중 → 완료»), 주 버튼 하나(지금 할 일), 개선 필요 n곳·조치 완료 m곳을 싣는다.
  - 행 표는 회차에 속한 사업장 행이다. `[＋ 측정 계획 등록]`과 행별 `[＋ 첨부]`는 **걷는다**(③으로 옮긴다).
  - 요약 타일 5개(전체·측정 완료·미실시·개선 필요·기한 초과)는 그대로 둔다.
- **상세(`work-env-detail.html`)**: 사업장 한 줄의 결과·개선조치 화면으로 남긴다. `[결과보고서 등록]`·`[측정 완료 처리]`는 걷고 회차에서 받는다. `[개선 증빙 등록]`·`[개선조치 완료]`·`[기한 재설정]`·이력은 그대로다.
  - 검수 §4-2의 «개선 전 사진 칸은 있는데 올릴 길이 없다»는 «개선 증빙 등록» 창에 «개선 전 / 개선 후»를 고르는 칸으로 메운다.
  - `[알림 발송]`은 걷는다. 부서 통보는 공문과 ⑤의 알림이 한다. 검수 §4-2의 «발송했습니다» 문구 문제도 함께 사라진다.
- **자체 측정 부서(농업기술센터 등)**: 그 부서 담당자가 자기 부서 회차를 등록하고 ③까지 한다. **공문은 내지 않는다** — 원장대로 내부결재로 끝나고, 결과보고서 첨부가 곧 완료다. 회차에 `selfRun: true` 를 남긴다(§9 D-2).

## 4. 공문 2종 — `DYDOC.define({ simple: true })`

이행점검 시달 공문·위험성평가 요청 공문(`RSKREQ`, `js/rsk-list.js` `setupReqDoc`)과 같은 단순 기안이다. 결재선이 없고, 온나라 기안함까지만 보낸다(2026-11-06 운영 결정). **새 공문 골격을 만들지 않는다**(CLAUDE.md §7-1).

| cfg | 실시 안내(`kind: 'N'`) | 결과 안내(`kind: 'R'`) |
|---|---|---|
| `ns` | `WENVDOC` (한 정의에 두 종) | 〃 |
| `titleOf` | `YYYY년 상/하반기 작업환경측정 실시 안내` | `YYYY년 상/하반기 작업환경측정 결과 안내` — 원장 제목과 같게 |
| `initOf` | `{ docType: '외부발송', to: '수신자 참조' }` | 〃 |
| 수신처 | 대상 사업장 소관 부서 전부(`recipientsDefault`), 조직도에서 고친다 | 〃 |
| `ready` | 회차가 있고 대상 사업장이 1곳 이상 | 결과보고서 1개 이상 · **모든 대상 사업장에 결과**(적정/개선 필요) · 개선 필요는 요구사항과 오늘 이후 기한 |
| `chips` | 실시 개요(기간·측정기관·대상 n곳) · 협조 사항(근로자대표 참석 요구 시 알림 — 법 §125④) | 결과 요약(대상 n곳 · 적정 a · 개선 필요 b) · 개선 요청(조치기한 · 시스템 › 작업환경측정에서 완료 처리) · 결과 게시(해당 작업장 근로자에게 알려 주시기 바랍니다) |
| 붙임(`simplePick`) | 없음 | 회차 결과보고서(이미 올린 파일) — 고른다 |
| 별지 | 대상 사업장 목록 | **사업장별 측정 결과**(사업장 · 유해인자 · 결과 · 개선 요구 · 조치기한) |
| `canDraft` | 재난안전과 담당자(`DYROLE.canAct(OWNER_DEPT)`) | 〃 |
| 보낸 뒤 | 상태 «기안함 전송» · 회차 정보 잠금 없음(안내일 뿐) | «기안함 전송» → **회차 잠금** + ⑤ 부서 할 일 |

- 본문은 자동으로 만들지 않는다. 삽입 칩만 건넨다(§7-1).
- 근거 절은 고른 것만 찍는다. 후보는 `DYLAW` 의 `osh-125` 이고 조문 문자열은 화면에 쓰지 않는다(§10 — 교육 공문 칩의 하드코딩 결함을 되풀이하지 않는다).
- 반려·반송이면 잠금을 풀고 같은 회차 공문을 다시 보낸다. 이미 만든 부서 할 일은 유지한다(이행점검 시달 공문과 같은 규칙).

## 5. 데이터

```text
DYSH.weRounds[]  — 새 컬렉션(회차)
  { id, year, half, vendor, period:{from,to}, siteIds:[…], selfRun:false, deptId(자체 측정일 때),
    files:[{name,size,at,by}], results:{ siteId: { result:'적정'|'개선 필요', improveReq, improveDue } },
    docs:{ N:{sid,status,at,by}, R:{sid,status,at,by} }, history:[…] }

DYSH.workEnv[]   — 현행 행은 «회차 × 사업장» 파생/저장 행으로 남긴다(roundId 추가)
  · result·improveReq·improveDue 는 회차 results 에서 내려받는다(결과 공문을 보낼 때 확정)
  · 개선 증빙·완료 필드(afterPhoto·beforePhoto·improveDone…)는 현행 그대로
```

- **잠금 판정은 한 곳**이다: `DYSH.weRoundLock(roundId)` — 결과 공문이 «기안함 전송·결재중·결재완료»면 잠근다. 잠기면 파일·결과를 고칠 수 없다(*"이건 문서 위조예요"*). 판정 인자만 보고 모듈 상태를 읽지 않는다(§4-3 `DYRSKDOC.lockOf` 교훈).
- 회차 중복: 같은 연도·반기의 회차는 재난안전과 1건 + 자체 측정 부서마다 1건.
- 옛 행(roundId 없음)은 «회차 미지정»으로 표에 그대로 보인다. 시드는 2026 상·하반기 회차 2건으로 다시 짜고 `SKEY` 를 올린다. 하반기는 «결과 등록 전»으로 남겨 실습 자리를 둔다(§11 운영 예시 원칙).
- 내 할일·대시보드: 부서 할 일은 «개선조치 n곳» 하나로, `DYSH.weTodos(deptId)` 한 곳에서 센다. 재난안전과 할 일은 «결과 등록 대기 · 공문 기안 대기 회차»다 — 교육 검수의 «기안 차례가 알려지지 않는다»(높음)를 이 메뉴에서는 처음부터 만들지 않는다. `W-ENV-MEA` 자동발행 완료 판정(`SH:workenv`)은 «그 회차 결과 공문 보냄»으로 바꾼다.

검수 §4-2의 «목록 첨부 함수가 부서 없이 판정»은 함수 자체를 걷으면서 사라진다.

## 7. 법령 근거 — 검증 6문

## 10. 범위 밖 · 후속

- **건강검진(`health-exam`)**: 원장에 «특수건강검진 실시 안내·결과 안내»가 같은 형태로 있다(F07). 이 기획이 확정되면 같은 회차 + 결과 안내 공문 구조를 옮긴다. 단, 개인 결과는 비공개(법 §132②)라 별지에 사람별 결과를 싣지 않는다.
- **안전보건교육**: 검수 §5-4의 «확인 없이 할 수 있는 단순화» 3건은 이 기획과 별개로 진행할 수 있다.
- 측정비 지급(내부결재)은 예산 관리 소관이라 넣지 않는다.

## 11. 수용 기준

1. 재난안전과 계정으로 ① 회차 등록 → ③ 결과 등록(파일 1개, 사업장 4곳: 적정 2·개선 필요 2) → ④ 결과 안내 공문 기안·미리보기·보내기까지, 다른 화면으로 가지 않고 끝난다.
2. 보낸 뒤 회차 파일·결과를 고치는 경로(화면 버튼과 전역 호출) 전부가 거절된다. 반려 회신이면 다시 열린다.
3. 개선 필요 2곳의 부서 담당자 내 할일에 «작업환경측정 개선조치»가 생기고, 적정 사업장 부서에는 생기지 않는다.
4. 부서 담당자 계정에는 회차 등록·결과 등록·공문 버튼이 없고, 전역 호출도 거절된다(자체 측정 부서는 자기 회차만 허용).
5. 결과 공문 별지의 사업장 수·결과 수가 회차 카드와 목록 타일 숫자와 같다.
6. 모든 사업장이 적정이면 공문을 보낸 뒤 회차가 «완료»가 되고 부서 할 일은 0건이다.
7. 공문 근거 칩에 조문 문자열 하드코딩이 없다(`DYLAW` 파생).
