## 1. 요구 요지

주무관이 짚은 원칙은 하나다 — **편리함보다 문서대장 기록.**

> «결과 공문만 끝났다 이것만 하는 게 아니라 그 과정들도 다 내부적으로 문서 대장에 등록이 다 돼야 돼요» (02:17)

지금은 집합교육 1건당 공문이 **끝에 한 번**(실시 결과 공문, 종료 처리 뒤 재난안전과 기안) 나간다. 바뀐 뒤에는 **과정마다 한 번씩, 교육 1건당 세 종류**가 온나라 연계기안함으로 나간다. 통화 끝에 주무관이 직접 셋을 확인했다(05:18).

| # | 언제 | 누가 | 공문 | 지금 |
|---|---|---|---|---|
| ① | 집합교육 등록 | 재난안전과 담당자 | **교육 안내 공문** (수신 각 부서) | 없음 — 화면 알림만(«집합교육 예정 안내») |
| ② | 교육 뒤 참석자 등록부 등록 | 각 부서 담당자 | **참석자 등록부 제출 공문** (수신 재난안전과) | 없음 — 시스템 등록만 |
| ③ | 교육 뒤 | 재난안전과 담당자 | **출장 결과 보고서** | 실시 결과 공문(종료 처리 뒤)이 이 자리 → **③으로 바뀐다** |

공문 세 종 모두 **결재선 없이 «온나라로 보내기»**(`DYDOC.define({ simple: true })`, 운영 결정 2026-11-06 «온나라로 기안까지만»)다. 검토·결재는 담당자가 온나라에서 지정해 상신한다.

- **업무 담당자는 둘로 나뉜다** — 재난안전과 담당자(1·2·5·6)와 각 부서 담당자(4). 주무관이 «업무 담당자가 둘로 나눠져야 되는 거 알죠»(04:43)로 다시 확인했다. 화면은 접속한 사람이 어느 쪽인지에 따라 그 사람의 버튼만 낸다.

### 2-1. 교육 상태와 공문 상태

교육 상태(카드 칩)는 넷이고, 공문 상태는 공문마다 따로 붙는다.

| 교육 상태 | 판정 | 저장 |
|---|---|---|
| 안내 공문 전 | 집합교육이 있고 ① 을 보낸 적이 없다(또는 마지막 ① 이 반려·반송) | 파생 — `DYEDU.noticeSent(c)` |
| 교육 전 | ① 보냄 · 마지막 회차 날 전 | 파생 |
| 등록부 받는 중 | ① 보냄 · 마지막 회차 날부터 · 종료 처리 전 | 파생(`enrollOpen`) |
| 완료 | 종료 처리 | `status: DONE` (지금 그대로) |

| 공문 상태 | 뜻 | 화면 |
|---|---|---|
| 미기안 | 보낼 차례인데 아직 안 보냄 | 담당자에게 [○○ 공문 기안] |
| 기안함 전송 · 결재중 · 결재완료 | 보냄 | 상태 칩 + [문서 보기], 해당 대상 잠금 |
| 반려 · 반송 | 온나라에서 돌아옴 | 사유 + [다시 기안](앞 제목·본문 이어 쓰기), 잠금 풀림, 기안자에게 알림 |

① 이 반려·반송되면 교육은 다시 «안내 공문 전»으로 보인다 — 부서는 받은 적 없는 안내를 근거로 움직이지 않는다. 다만 ① 이 한 번이라도 «기안함 전송» 이상이었다가 돌아온 경우 부서 화면의 카드는 남기고 «안내 공문 다시 보내는 중» 한 줄을 단다(이미 알림을 받은 부서에서 카드가 갑자기 사라지면 더 헷갈린다).

## 3. 화면별 변경

### 3-1. 교육 등록 폼 (`js/edu-reg.js` `renderCreate`)

- **«내용» → «제목»** (00:30 «이 내용을 제목으로 바꿔주세요» · 00:37 «내용을 적다 보면 헷갈릴 거 같거든요»). 지금 이 칸 값(`desc`)이 이미 카드·상세·공문의 교육 제목으로 쓰이고 있어 **이름과 모양만** 바꾼다.
  - 라벨 «제목 *» · 여러 줄 입력(`textarea`) → 한 줄 입력(`input.form-input`) · 검증 문구 «교육 제목을 입력하세요.»
  - 목록 검색 안내 «교육명·강사·장소 검색» → «제목·강사·장소 검색».
  - 저장 키는 **`desc` 그대로**(스키마·시드·공문·이수현황이 같은 키를 읽는다).
  - 자체교육 등록 폼(같은 `renderCreate`)도 같은 칸이라 함께 바뀐다 — 화면마다 같은 칸 이름이 달라지지 않게.
- 집합교육 저장 버튼: [등록] → **[등록하고 안내 공문 기안 →]**. 저장이 끝나면 같은 모달 안에서 ① 기안 화면으로 본문을 교체한다(§1 단일 모달 — 새 모달을 띄우지 않는다).
- ① 기안 화면: 수신 = **그 교육의 대상 부서 전부**(`courseTargetDepts`)가 기본값이고 공용 조직도(`ORGPICK.deptsPanel`)로 빼거나 더한다(이행점검 시달 공문과 같은 방식). 제목 기본값 «{연도} {교육 제목} 집합교육 실시 안내» · 본문 직접 작성(삽입 칩: 교육 개요 — 일시·장소·강사 · 참석 대상 · 등록부 기한) · 붙임 = 등록 때 올린 교육 자료·참석자 명단(고름).
- 수신 부서와 «부서 할 일을 받는 부서»는 같은 값이다 — 수신에서 뺀 부서에는 예정 안내·등록부 할 일을 내지 않는다(공문을 받지 않은 부서에 할 일만 가면 근거가 없다).
- 수정 모달은 지금 그대로 [저장]. 다만 ① 공문을 보낸 뒤에는 수정이 잠긴다(§5).

### 3-2. 정기교육 목록 카드 (`js/edu-reg.js`)

- 상태 칩에 **«안내 공문 전»**을 더한다(집합교육만): «안내 공문 전 → 교육 전 → 등록부 받는 중 → 완료». `DYV2.STATUS_TONE` 에 어휘 추가.
- 상단 필터 «상태»도 넷으로 바꾼다 — 지금은 저장값(진행중·완료) 둘이라 «안내 공문 전»·«등록부 받는 중»으로 거를 수 없다. 부서 담당자에게는 «안내 공문 전» 선택지를 내지 않는다(고르면 늘 0건).
- 목록에 지금은 **조회 범위 판정이 없다**(전원이 전 집합교육 카드를 본다). «안내 공문 전» 카드를 부서에 감추는 판정을 `DYEDU.visibleCourse(c)` 한 곳에 두고 목록·상세 진입·내 할일이 같이 쓴다 — 목록에서만 지우면 상세 주소로 열린다.
- «안내 공문 전» 카드: 재난안전과 담당자에게 [교육 안내 공문 기안] · [수정] · [삭제]. 부서에는 카드가 **보이지 않는다**(공문이 나가기 전에는 부서에 알리지 않는다 — 위험성평가 요청 공문 «보내는 순간 부서 할 일»과 같은 원칙).
- «등록부 받는 중» 카드: 부서 담당자에게 [＋ 참석자 등록부 등록], 재난안전과 담당자에게 **[출장 결과 보고서 작성]**(작성 뒤에는 [출장 결과 보고서 보기]).
- 카드의 종전 [공문 기안](실시 결과 공문)은 **집합교육에서 걷는다** — ③이 그 자리다. 자체교육 카드는 지금 그대로(범위 밖).

### 3-3. 교육 상세 (`js/edu-reg-detail.js`)

- 제목 줄 공문 칩: 종전 실시 결과 공문 한 칩 → **공문 세 줄 요약**(«안내 공문 기안함 전송 11-16 · 등록부 공문 3 / 8개 부서 · 출장 결과 보고서 미작성»). 줄을 누르면 그 공문 문서 보기.
- 액션:
  - 재난안전과 담당자: [교육 안내 공문 기안](① 전) · **[출장 결과 보고서 작성]**(교육 뒤) · [교육 종료 처리]. **[＋ 일괄 등록 (여러 부서)] 은 걷는다**(§7 D — 부서마다 자기 공문을 기안해야 해서 재난안전과가 여러 부서 몫을 한 번에 올릴 수 없다).
  - 부서 담당자: [＋ 참석자 등록부 등록](우리 부서 등록부가 없을 때) · 등록부를 저장했는데 공문을 안 보냈으면 **[등록부 공문 기안]**.
- 부서별 등록 현황 표에 **«공문» 열**을 더한다 — 미기안 / 기안함 전송 / 결재중 / 결재완료 / 반려 / 반송.
- 표는 지금 **등록한 부서 줄만** 그린다. 재난안전과 담당자가 누가 안 냈는지 보려면 **대상 부서 전부**를 줄로 그려야 한다 — 미등록 부서는 «미등록», 등록만 한 부서는 «등록 · 공문 미기안». 부서 담당자에게는 종전대로 등록한 줄만 보인다(다른 부서 미제출 명단은 그 부서가 볼 이유가 없다).
- **[독촉]은 지금 없는 수단이다** — 등록부 미등록 독촉은 현재 어느 화면에도 없다(이수현황의 독촉은 미이수자 대상). 미등록·미기안 줄에 [독촉]을 새로 두고, 판정은 `DYROLE.canRemind(deptId)`, 받는 사람은 `DYADM.deptContacts(deptId)`, 기록은 교육 이력에 남긴다. 위에 [미제출 부서 일괄 독촉] 하나(대상 2곳 이상일 때).
- 이력 카드에 공문 보내기·반려·반송·독촉을 남긴다(누가 · 언제 · 어느 공문).

### 3-4. 참석자 등록부 등록 창 (부서 담당자)

- 지금 입력(참석자 · 실제 참석시간 · 서명부 스캔)은 그대로.
- **부서 칸의 [조직도]를 걷는다** — 지금은 재난안전과 담당자가 조직도로 다른 부서를 골라 «대리 등록»할 수 있다(`canPickDept`). 대리 등록한 부서 몫의 ② 는 그 부서가 기안해야 하는데 재난안전과는 남의 부서 공문을 기안하지 않으므로(§4), 대리 등록을 남기면 그 부서 ② 가 영영 미기안이 된다. 누구든 **소속 부서로 고정**한다. 옛 «대리 등록»·«일괄 등록» 줄 표시는 남긴다.
- 하단 버튼 [등록] → **[다음: 공문 기안 →]**. 등록부를 저장하고 같은 모달에서 ② 기안으로 넘어간다.
- ② 공문 지면: 수신 **재난안전과**(고정 표시 — 01:47 «재난 안전과에») · 제목 기본값 «{교육 제목} 참석자 등록부 제출({부서명})» · 본문 직접 작성(삽입 칩: 교육 개요 · 참석 n명 · 실제 참석시간) · 붙임 = **그 부서 서명부 스캔**(이미 올린 파일) + **참석자 명단 별지**(그 부서 줄만).
- 창을 닫아도 등록부는 저장돼 있고, 상세·내 할일에 [등록부 공문 기안]이 남는다.
- 등록부만 저장하고 ② 를 안 보낸 동안에는 [등록 취소]로 고칠 수 있다. ② 를 보낸 뒤에는 잠긴다(§5).

### 3-4-1. 교육 종료 처리 (재난안전과 담당자)

- 종료 처리는 지금처럼 교육이 끝난 뒤 언제든 한다 — ② · ③ 이 다 나가기를 기다리지 않는다(등록부 기한을 넘긴 부서 때문에 종료가 막히면 이수현황이 영영 비는 것과 같은 이유).
- 확인 창에 **아직 안 끝난 것을 수로** 보인다: «등록부 미등록 n개 부서 · 등록부 공문 미기안 n개 부서 · 출장 결과 보고서 미작성». 막지는 않는다.
- 이수 기록은 **등록부 기준**이다 — ② 를 안 보낸 부서의 등록부도 이수로 센다(등록부가 참석의 증빙이고 공문은 그 기록을 문서대장에 남기는 일이다). 그 부서의 «등록부 공문 보내기» 할 일은 종료 뒤에도 남는다(§7 J).

### 3-5. 출장 결과 보고서 창 (재난안전과 담당자 · 신설)

주무관 요구 그대로(04:14 «교육 자료, 교육 사진, 참석자 몇 명 들었는지 숫자 기입할 수 있게끔» · 04:30 «숫자만, 대략적으로만»).

| 칸 | 필수 | 입력 | 비고 |
|---|---|---|---|
| 교육 자료 | ○ | 업로드 칸(`DYV2.uploadDrop`, 프로필 `general`) | 등록 때 올린 교육 자료를 기본으로 불러오고 바꿀 수 있다 |
| 교육 사진 | ○ | 업로드 칸(프로필 `image`) | |
| 참석 인원 | ○ | 숫자(1 이상) | **대략적인 수**. 옆에 참고로 «등록부 기준 n명(현재)»을 보인다 — 값을 대신 채우지 않는다 |
| 비고 | | 한 줄 | |

- 창을 닫으면 작성 내용은 저장되고(«작성 중») ③ 은 미기안으로 남는다. ③ 을 보내기 전에는 [출장 결과 보고서 수정]으로 고친다.
- 저장 버튼 **[다음: 공문 기안 →]** → ③ 지면: 제목 기본값 «{교육 제목} 출장 결과 보고» · 본문 직접 작성(삽입 칩: 교육 개요 · 참석 인원) · 붙임 = 교육 자료 · 교육 사진(방금 올린 파일에서 고름). 수신은 **내부결재**(재난안전과 내부 보고).
- 작성 시점: **교육이 끝난 날(마지막 회차 날)부터**. 부서 등록부를 다 받기 전에도 쓸 수 있고, 종료 처리 앞뒤와 상관없다(§7 C).
- 이수 판정은 **지금처럼 부서 등록부**로 한다. 보고서의 참석 인원은 보고용 숫자이고 이수현황·완료율에 쓰지 않는다(§7 B).

### 3-6. 내 할일 · 알림

| 받는 사람 | 할 일 카드 | 생기는 때 | 끝나는 때 |
|---|---|---|---|
| 재난안전과 담당자 | 교육 안내 공문 보내기 | 교육을 등록하고 ①을 안 보냈을 때 | ① 보냄 |
| 재난안전과 담당자 | 출장 결과 보고서 작성 | 교육이 끝난 날 | ③ 보냄 |
| 부서 담당자 | 참석자 등록부 등록 (지금 있음) → 저장 뒤 **등록부 공문 보내기**로 바뀜 | 교육이 끝난 날 | **② 보냄** (종전: 등록부 저장) |
| 기안한 담당자 | ○○ 공문 다시 보내기 | 그 공문이 반려·반송 | 다시 보냄 |

- 판정은 지금처럼 `DYEDU.deptTodos(deptId)` 한 곳에서 낸다 — 내 할일과 대시보드가 같은 함수를 센다. 재난안전과 담당자 몫(①·③)도 `deptTodos('safety')` 안에 넣는다(재난안전과 부서 할 일 수와 대시보드가 갈리지 않게). 재난안전과 과장·팀장은 같은 카드를 보되 처리 버튼은 막힌다(지금 내 할일 규칙).
- 카드의 주 버튼은 그 처리 창을 곧바로 연다(교육 상세로 가서 다시 찾게 하지 않는다) — «지금 할 일» 강조(`markNow`)도 같은 카드에 붙는다.
- «집합교육 예정 안내» 알림(`notifyUpcoming`)은 **① 보낸 순간**에 낸다(종전: 등록 저장 순간).
- 부서가 ②를 보내면 재난안전과 담당자에게 «참석자 등록부 제출» 알림(받는 사람이 할 일이 있을 때만 — 확인할 것이 생긴다).

## 5. 잠금

공문이 나간 뒤 그 공문에 실린 것을 고치면 이미 나간 문서와 시스템이 어긋난다(«이건 문서 위조예요»). 잠금은 공문 종류마다 따로 판정하고, **기안함 전송 · 결재중 · 결재완료는 잠금, 반려 · 반송은 풀림**이 셋 다 같다.

| 공문 | 보낸 뒤 잠기는 것 | 판정 |
|---|---|---|
| ① 안내 | 교육 제목 · 회차(일시) · 강사 · 장소 수정, 교육 삭제 | `EDUDOC.lockOf(courseId, 'NOTICE')` |
| ② 등록부 | **그 부서** 등록부 취소 · 정정 | `EDUDOC.lockOf(courseId, 'ENROLL', deptId)` |
| ③ 출장 결과 | 출장 결과 보고서 수정 | `EDUDOC.lockOf(courseId, 'TRIP')` |

- 종전 «실시 결과 공문을 보내면 교육 전체 잠금»은 집합교육에서 위 표로 바뀐다. 자체교육은 종전 그대로.
- 반려·반송되면 같은 공문을 다시 기안한다(앞 기안 제목·본문 이어 쓰기 — 지금 `initOf` 와 같다).
- 잠긴 버튼은 잠금 표시로 바꾸고 사유를 보인다 — 누르면 거절하는 버튼을 남기지 않는다.

## 6. 데이터

- 공문 저장(`EDUDOC` 스토어 `docs[courseId][]`)에 **`kind`** 를 더한다: `NOTICE` · `ENROLL`(+`deptId`) · `TRIP` · `RESULT`(옛 실시 결과 · 자체교육). `kind` 가 없는 옛 기록은 `RESULT` 로 읽는다.
- 출장 결과 보고서: `course.trip = { headcount, files:[{slot:'자료'|'사진', …}], memo, by, at }`. 교육 데이터라 `DYEDU` 에 둔다.
- 교육 상태: 집합교육에 «안내 공문 전»을 파생한다 — **저장 필드를 늘리지 않고** `NOTICE` 공문이 보내진 적이 있는지로 판정한다(`DYEDU.noticeSent(c)` 한 곳). 옛 시드 교육은 안내 공문이 이미 나간 것으로 본다(옛 데이터가 갑자기 «안내 공문 전»으로 돌아가지 않게 — `c.imported`·시드 표시 기준).
- 시드: 11월 운영 예시(§11)에 맞춰 지난 집합교육에는 ①·②·③ 공문 기록을 «결재완료»로 채우고, 진행 중 교육 1건은 일부 부서 ② 미기안으로 둔다. `DYEDU` `SKEY`·`EDUDOC` `SKEY` 범프.

## 8. 기존 규칙에서 바뀌는 것 (CLAUDE.md §4 개정 대상)

구현과 함께 아래 문장을 고친다. 고치지 않으면 다음 작업자가 새 흐름을 규칙 위반으로 읽고 되돌린다.

| 지금 규칙 | 바뀐 뒤 |
|---|---|
| 공문 **단위는 교육 1건뿐**, 3종을 되살리지 말 것 | 집합교육은 **과정 3종**(안내·등록부·출장 결과). 되살리지 말라는 옛 3종(총괄·교육별·개인별)과는 다른 축임을 적는다 |
| **진입점은 한 자리** — 종료 처리된 교육의 [공문 기안] | 집합교육은 등록 직후 · 등록부 저장 직후 · 교육 뒤 세 자리. 자체·채용시·기타는 종전 |
| **기안 조건은 종료 처리 하나** | ①은 등록, ②는 등록부 저장, ③은 교육이 끝난 날 |

| **재난안전과 일괄 등록**(`EDURD.openBulk`, 11-11 발표안 27장) | 걷는다(§7 D) — 함수는 옛 데이터(`bulk` 표시 줄) 표시를 위해 남기고 진입 버튼만 뺀다 |
| 재난안전과가 다른 부서 몫을 올리면 `proxy`(«대리 등록») | 대리 등록도 걷는다 — 등록부 창 부서 칸은 누구든 소속 부서 고정(§3-4) |
| 등록 현황 표는 등록한 부서 줄만 | 재난안전과 담당자·조회 계층에는 대상 부서 전부 줄(미등록 포함) |
| 집합교육 목록은 전원에게 전부 보임 | «안내 공문 전»은 재난안전과만(`DYEDU.visibleCourse`) |
| 잠금 판정 `EDUDOC.lockOf(courseId)` 한 곳 | `lockOf(courseId, kind, deptId)` 한 곳 — 공문 종류별 |
| 등록부 등록이 부서 할 일의 끝 | **② 공문을 보내야** 끝 |
| 시연 투어 5단계 | 6단계 |

화면 정의서 SCR-EDU-001(정기교육) · SCR-EDU-004(교육 상세 · 공문) · SCR-EDU-005(결재 이력) 와 `_공통_권한정의.md` §7-4(상신 경로 표 — 교육 경로 1개 → 3개)도 함께 고친다.

## 10. 수용 기준

| ID | 기준 |
|---|---|
| EC-01 | 교육 등록 폼의 칸 이름이 «제목»이고 한 줄 입력이다. 비우면 «교육 제목을 입력하세요.»로 저장되지 않는다 |
| EC-02 | 집합교육을 저장하면 같은 모달이 교육 안내 공문 기안으로 넘어가고, 수신은 대상 부서 전부가 기본값이다 |
| EC-03 | ① 을 보내기 전 교육은 «안내 공문 전»이고 부서 담당자 목록·내 할일에 보이지 않는다. 보낸 순간 «교육 전»이 되고 부서에 예정 안내 알림이 간다 |
| EC-04 | ① 을 보낸 뒤 교육 제목·회차·강사·장소 수정과 삭제가 잠기고, 반려·반송되면 풀린다 |
| EC-05 | 부서 담당자가 등록부를 저장하면 같은 모달이 ② 기안으로 넘어가고, 수신은 재난안전과, 붙임 후보는 그 부서 서명부와 명단 별지다 |
| EC-06 | 다른 부서 담당자 · 재난안전과 담당자 · 군수는 남의 부서 ② 를 기안할 수 없다(버튼 없음 · 전역 호출도 거절) |
| EC-07 | 부서 할 일 «참석자 등록부 등록»은 ② 를 보내야 끝난다. 등록부만 저장한 부서에는 [등록부 공문 기안]이 남는다 |
| EC-08 | ② 를 보낸 부서의 등록부 취소·정정이 잠긴다. 다른 부서 등록부는 영향이 없다 |
| EC-09 | 재난안전과 담당자의 교육 상세·카드에 [출장 결과 보고서 작성]이 있고 [＋ 일괄 등록]이 없다. 교육이 끝나기 전에는 작성 버튼이 없다 |
| EC-10 | 출장 결과 보고서는 교육 자료·교육 사진·참석 인원(1 이상)이 있어야 저장되고, 참석 인원은 이수현황에 쓰이지 않는다 |
| EC-11 | 집합교육 카드·상세에 종전 실시 결과 [공문 기안]이 없다. 자체교육은 종전 그대로다 |
| EC-12 | 결재 이력에 공문 종류가 보이고, 옛 실시 결과 공문 기록도 «실시 결과»로 보인다 |
| EC-13 | 관리감독자 정기교육(`edu-sup`)도 EC-01~12 가 같다 |
| EC-14 | 시연 투어 6단계가 데이터 파생으로 진행된다(손으로 처리해도 단계가 넘어간다) |
| EC-15 | «안내 공문 전» 교육은 부서 담당자·부서장의 목록·상세 주소·내 할일 어디에서도 열리지 않는다 |
| EC-16 | 재난안전과 담당자의 등록 현황 표에는 대상 부서 전부가 줄로 있고 미등록·미기안 줄에 [독촉]이 있다. 부서 담당자 표에는 다른 부서 미제출 줄이 없다 |
| EC-17 | 등록부 창의 부서 칸에 [조직도]가 누구에게도 없다(재난안전과 담당자 포함) |
| EC-18 | 부서 담당자 화면의 «공문» 요약에는 우리 부서 ② 만 있고 ①·③ 이 없다. 출장 결과 보고서는 부서 계정으로 열리지 않는다(전역 호출 포함) |
