## ⚠ 이 전달분의 범위 — 먼저 읽어 주세요

**이 문서와 화면 정의서는 「현행 프로토타입의 기능·UX를 재현하기 위한 범위」입니다. 법령이 요구하는 위험성평가 전체 기능의 완결본이 아닙니다.**

담양군은 위험성평가를 **외부 용역**으로 수행하고 시스템은 그 결과를 접수·전달·이행관리합니다. 그래서 아래 항목은 **의도적으로 현 화면 기능에 넣지 않았습니다.** 2026-08-11에 법령을 마저 수집해 **무엇이 빠졌는지는 확정**했으므로, 이제 "미확정"이 아니라 **범위 밖**입니다.

| 법령이 요구하는 것 | 근거 | 현재 화면 | 개발 범위 |
|---|---|---|---|
| 위험성 수준 결정 · 허용 가능 여부 판단 | 산안법 §36① · 시행규칙 §37①2호 | **없음** — 용역 보고서가 담당 | 편입하지 않음(용역 소관) |
| 근로자 참여 기록 | 산안법 §36② · 시행규칙 §37의2 | **없음** — 부서 설문조사표 제출로 갈음 | **편입 필요** — 순회 점검이 원칙, 설문·면담 병행 가능 |
| 실시 전·후 결과 공유 기록 | 산안법 §36④ · 시행규칙 §37의3 | **없음** | **편입 필요** — 실시 전 일정, 실시 후 결과와 이행 결과 |
| 기록·보존 | 산안법 §36⑤ · 시행규칙 §37의4 | 부분 | **편입 필요** — 기록 항목 3가지 + **보존 3년** (항목은 변경방향 문서 §5-3) |

법령 근거 칩도 이 세 축에는 붙이지 않았습니다 — 화면이 하지 않는 일을 한다고 쓰지 않기 위해서입니다. 편입하면 그때 붙습니다.

**따라서 개발 범위를 두 가지로 나눠 계약·인수 기준을 잡아 주세요.**

1. **현행 기능·UX 재현** — 이 문서와 화면 정의서로 착수 가능합니다.
2. **법령상 위험성평가 전체 관리** — 위 표의 "편입 필요" 3건이며, **요구사항은 이미 확정**돼 있습니다(변경방향 문서 §5-3). 화면 설계만 추가하면 됩니다.

이 구분 없이 "완성본"으로 인수하면 법정 필수 기록이 빠진 채 검수될 수 있습니다.

### 이번 전달에 **들어가지 않는 화면** — 내 할일(my-work)

**`내 할일`은 다음 차수입니다.** 화면 정의서를 쓰지 않았고 70화면 목록에도 없습니다.

그런데 이 화면은 원래 위험성평가 흐름의 **부서 담당자 쪽 절반**을 맡고 있었습니다. 그대로 두면 정의서를 아무리 채워도 흐름 한가운데가 범위 밖 화면에 걸려 **이 축만 떼어 개발할 수 없습니다.** 그래서 2026-08-11에 의존을 끊었습니다.

| 부서 담당자가 하는 일 | 종전 | 이번 전달 |
|---|---|---|
| 설문조사표 작성·제출 | `내 할일`에만 있었음 | **정기 위험성평가 화면 안에서 제출**(내 부서 진행 상황 1단계 → [지금 제출하기]) |
| 개선조치 완료 처리 | `내 할일`로 보냄 | **개선조치 목록 → 상세**에서 처리(이미 자족 경로였음) |
| 반려 건 재제출 | 〃 | 〃 |

`내 할일`은 여러 도메인의 할 일을 **모아 보는 편의 화면**으로 남습니다 — 유일한 수행 경로가 아닙니다. 다음 차수에 정의서를 쓸 때도 이 관계를 유지해 주세요. **한 도메인의 수행 경로를 내 할일에만 두지 마세요.**

> 같은 작업에서 **문구 오류 하나**를 찾아 고쳤습니다 — 정기평가 부서 행의 `[부서 보고서 첨부]`가 "용역업체가 작성한 보고서를 첨부합니다"라고 설명하고 있었는데, 그 자리에 실제로 담기는 것은 **부서가 낸 설문조사표 작성본**입니다(용역 통합 보고서는 별도 항목입니다). 같은 값을 두 화면이 다르게 부르고 있었습니다. 이제 **제출본 대리 등록**으로 바로잡았고, 부서가 직접 낸 것과 주관부서가 대신 올린 것이 이력에서 구분됩니다.

## 2. 정기 위험성평가 — 가장 많이 바뀐 화면

### 2-1. 🔴 보고서 자동 파싱 폐지

```
기존   통합보고서 업로드 → 시스템이 항목 추출 → 검수 화면에서 확인
변경   보고서 업로드 → 빈 작성표 → 담당자가 [＋행 추가]로 직접 입력
```

**왜** — 회의 중 뒤집혔습니다. 통합본 자동 분배안이 나왔다가 반론을 받고 *"차라리 그게 나을 것 같죠? 그냥 그렇게 할게요"* 로 **부서별 분할 업로드**로 결정. 부서별 한글 파일이 용역업체에서 이미 쪼개져 옵니다.

> ⚠️ 실 개발에서 "파싱하면 편한데?" 유혹이 다시 옵니다. 이건 기술이 아니라 **책임** 문제입니다 — 시스템이 옮긴 항목이 틀리면 책임 소재가 안 정해집니다.

### 2-2. 🔵 부서별 조치 작성표 — 열 구성이 바뀜

```
기존   요인 · 분류 · 원인 · 법령근거 · 개선조치                        (5열)
변경   요인 · 분류 · 원인 · 개선조치 · 담당자 · 증빙(전/후) · 완료 · 삭제  (8열)
```

| 변경 | 내용 |
|---|---|
| 🟢 담당자 | 행마다 조직도(인라인 트리)로 지정 |
| 🟢 증빙(전/후) | 행마다 개선 전·후 **사진 업로드**, 셀에 썸네일 표시 |
| 🟢 완료 | 행 단위 체크 — **개선 후 사진 없으면 체크 불가** |
| 🔴 법령 근거 열 | **제거** — 법정 기록 항목이 아니고, 미지정이 주황 `대기` 칩으로 떠서 *하지 않아도 되는 일이 남은 일처럼* 보였음 |

### 2-3. 🔵 설문조사표 — 부서가 직접 제출

```
기존   [내 할일] 양식 다운로드만 (제출 경로는 주관부서 화면에만)
변경   [내 할일] 양식 받기 → 작성본 제출 까지 한 자리에서
```

**왜** — 부서가 정기평가에서 지는 몫은 '점검일 참여'가 아니라 **설문조사표 작성·제출**입니다. 담당자가 자기 화면에서 끝낼 수 없는 구조였습니다.
**추가** — 이력에 *누가 올렸는지*가 남습니다(종전엔 무조건 '재난안전과'로 기록).

### 2-4. 🔵 개선조치 완료 — 증빙 필수

```
기존   조치 내용 입력 → 완료
변경   조치 내용 + 완료일 + 개선 후 사진(실제 파일) + 전자서명 → 완료
       ↑ 하나라도 없으면 완료 처리 차단
```

> *"이 개선 후를 사진을 올리기만 하면 돼요 … 사진 첨부해서 이렇게 하면은 이게 법적으로 한 거예요"*

### 2-5. 🟢 완료 확인 — **이번 변경의 핵심**

```
기존   부서가 완료 누름 → 그대로 평가까지 종료 (아무도 안 봄)
변경   부서 완료 → [재난안전과] 증빙 열람 → 확인 / 반려(사유 필수)
                                              └→ 담당자 화면에 사유·회차 → 재제출
```

**왜** — 기존엔 **부서의 자기 선언이 곧 확정**이었습니다. 주관부서에 남은 수단은 재촉뿐인데 재촉 버튼은 완료되는 순간 사라집니다.

**UX**
- 새 모달 안 띄우고 **개선조치 카드 안에서 펼침**
- `열람했습니다` 체크 전에는 **[확인] 비활성** — 오확인 방지
- 반려는 **사유 없으면 저장 안 됨**
- 상단에 `확인 대기 N건` 배너 + `[대기 건만 보기]` — 부서를 건너다니지 않고 한 화면에서 처리

> ⚙️ **개발 주의** — 확인은 기존 `status`(DONE/IN_PROGRESS)를 **건드리지 않고 별도 축**으로 둡니다. `status==='DONE'`으로 세는 곳이 8군데라 값을 하나 더 넣으면 전부 어긋납니다.
> 반려해도 `status`는 DONE 유지 — 대신 **공문 기안이 막히고**, 담당자 화면은 `needsAction(m)`(= `status!=='DONE' || 반려`)로 판정해 **반려 건을 '할 일'로 되돌리고 [재제출] 버튼을 냅니다.** 집계는 이 판정을 쓰지 않습니다(완료율 유지).

### 2-6. 🟢 공문 기안 → 미리보기 → 온나라

```
[공문 기안] ──▶ [문서 미리보기] ──▶ [온나라로 결재 상신] ──▶ 잠금
   작성 폼         표준 공문 지면        여기에만 상신 버튼
   상신 버튼 없음
```

**왜 이 순서인가** — 발주처가 교육의 `[결재 상신]`을 **두 번** 지우라고 했습니다. 기능이 아니라 순서가 틀렸습니다.
> *"왜 갑자기 뜬금없이 결재 상신이 있지"*
> *"결재 상신을 눌러요. 그럼 공문 내용이 있을 거 아니에요? **작성을 하고** … 붙임 파일에 넣어놨었잖아요"*

**기안 폼**

| 항목 | 처리 |
|---|---|
| 제목·수신·본문 | **직접 타이핑** — *"이게 다 직접 타이핑 하셔야 돼"* |
| 붙임 | **자동 연결** — 회의에서 합의된 유일한 자동화 |
| 수치 | `＋ 개선조치 3건` 칩 클릭 → 커서 위치에 삽입 (문장은 사람이) |
| 항목 번호 | `1.` `가.` `1)` 삽입 버튼 |
| 결재선 | 조직도에서 선택 (기본값 팀장→과장, **코드 고정 금지**) |
| 관련 근거 | 고른 조문만 찍힘, 안 고르면 절 자체가 사라짐 |

**문서 미리보기 — 표준 공문 서식**

전 행정기관 공통 서식(기안문·시행문)입니다. 담양군 고유 양식이 따로 없습니다.

```
              담 양 군                    ← 행정기관명(중앙·자간)
─────────────────────────
수 신   수신자 참조  (경유)               ← 내부결재면 "내부결재"
제 목   …
─────────────────────────
1. 관련: …                                ← 1. → 가. → 1) 항목 체계
2. …
   가. …
붙 임   1. … 1부.
        2. … 1부.   끝.                   ← "끝." 위치 규칙

          담 양 군 수   (관인)            ← 외부발송만
─────────────────────────
기안자 … 검토자 … 결재권자 …              ← 서명란은 하단 (상단 아님)
시 행  재난안전과-101(2026-08-03)  접 수   ← 접수는 외부발송만
우 (미등록) … / 전화 (미등록)             ← 기관정보는 외부발송만
```

**내부결재 / 외부발송은 지면이 실제로 다릅니다** — 합치지 마십시오.

| | 내부결재 | 외부발송 |
|---|---|---|
| 수신 | `내부결재` | 수신자 + `(경유)` |
| 발신명의·관인 | 없음 | `담 양 군 수` + 관인 |
| 접수란·기관정보 | 없음 | 있음 |

> ⚠️ **보고서 서식으로 그리지 마십시오** — 절 구분(Ⅰ/Ⅱ/Ⅲ)·KPI 카드는 공문에 없습니다. 큰 표는 본문이 아니라 **붙임 별지**로 뺍니다.
> ⚠️ **상신 후 잠금** — 확인 결과·증빙 수정 불가. *"공문을 첨부하면 기록이 남잖아요. 더 이상 수정이 안 돼요. 이건 문서 위조예요"*
> ⚠️ **결재 반려 = 새 문서로 재기안** — 온나라에는 **요청을 보내고 결재 결과를 받아오는 것만** 가능합니다. 반려된 문서를 고쳐 다시 올리는 게 아니라, `[재기안]`으로 **새 문서번호의 문서를 새로 상신**합니다. 이전 건은 덮어쓰지 않고 이력으로 남습니다.

## 7. 권한 (3계층)

기존 프로토타입은 **계층이 거꾸로**였습니다 — 가장 낮은 권한(주무관)이 시스템 관리를 볼 수 있었습니다.

| 계층 | 조회 | 처리 |
|---|---|---|
| 총괄(군수) | 전 부서 | **조회만** |
| 관리감독자(과장·소장) | 소속 부서 | 조회 + **재촉** |
| 업무담당자(주무관) | 자기 부서 | 완료 처리·제출·**전자서명** |
| ┗ 주관부서(재난안전과) | 전 부서 | 위 + 평가 운영·**완료 확인**·**공문 기안** |

**판정 규칙 2개로 전부 갈립니다**
```
canAct()     = 업무담당자 && 내 소속 == 보고 있는 부서   → 완료·제출·서명
canManage()  = 소속 == 재난안전과                       → 운영·확인·기안
```

**원칙**
- 조회는 막지 않습니다 (진행 상황 보는 건 총괄·감독의 정당한 권한)
- **대리 서명은 막습니다** — 군수·과장이 담당자 이름으로 서명하면 문서 위조
- 권한 없으면 버튼을 **비활성이 아니라 다른 것으로 교체**하고 **왜 없는지 밝힘**
- 화면에서 숨기는 것으로 끝내지 말고 **함수 진입부에도 가드** (콘솔·딥링크 우회)
