## 1. 흐름과 상태 (화면 명세의 뼈대)

```
① 생성 → ② 대상 · 일정 → ③ 설문 요청 공문 → ④ 부서 제출 → ⑤ 보고서 + 조치기한
→ ⑥ 조치 요청 공문 → ⑦ 부서 작성 · [입력 완료] → 완료 처리 → ⑧ 완료 확인 → 결과 공문
   (⑥-1 조치 대상 없음 종결 · ⑥-2 추가 조치 요청 · 작성 중 [입력 재촉])
```

### 1-1. 평가 · 부서 · 개선조치에 더할 저장 항목

| 대상 | 항목 |
|---|---|
| 평가 | 설문 제출 기한 · 설문 요청 공문{보낸 일시 · 보낸 사람 · 연계 번호 · 상태} · 조치 요청 공문{같은 항목 · 요청 부서 목록} · 추가 조치 요청{일시 · 한 사람 · 부서 · 공문} · 조치 대상 없음 종결{일시 · 한 사람 · 사유} |
| 부서 줄 | 점검일 · 요청 받음 여부{일시 · 한 사람 · 공문 번호} · 조치기한 · 지적사항 없음 여부 · 입력 완료{일시 · 한 사람 · 0건 사유 · 건수} · 입력 완료 취소 이력 · 입력 재촉 이력{일시 · 보낸 사람 · 받는 사람} |
| 개선조치 | 확인 축{상태(확인 대기 · 확인 완료 · 반려) · 확인자 · 확인일 · 반려 사유 · 회차} — **완료 상태와 별개** · 기한 변경 이력{전 · 후 · 사유 · 한 사람} |

참여 근로자 · 근로자 공유 · 작성표 행 사진 · 행 완료 체크는 **저장 항목이 아니다.**

### 1-2. 상태 판정 — 저장하지 않고 파생

| 대상 | 판정 |
|---|---|
| 평가 카드 | 저장 상태가 «완료»여도 **확인 대기 건이 남았으면 «확인 대기»**(완료일 없음) · 반려 건이 남았으면 «진행중» · 확인할 건이 없으면(종결 · 전 부서 0건) «완료». 저장값은 바꾸지 않는다 |
| 저장 상태 «완료» 조건 | 요청 부서 전부 입력 완료 + 개선조치 전부 완료 · 또는 조치 대상 없음 종결. 입력 중인 부서가 하나라도 있으면 완료되지 않는다 |
| 부서 줄 | 조치 요청 전(회색 · 보고서 전후) → 조치전(요청 받음 · 입력 완료 전) → 조치중(입력 완료 · 미완료 건 있음) → 완료(전부 완료 · 확인) / 반려(반려 건 있음) / 지적사항 없음(요청 안 받음 · 또는 0건 입력 완료). **부서 표 · 조회 표 · 요약 · 상세가 같은 판정 하나** |
| 부서 줄 버튼 | 확인 전 `[관리]` · 확인까지 끝나면 `[보기]` |
| 개선조치 | 완료 축(진행중 · 완료)과 확인 축은 따로 간다. «완료 + 반려»가 정상. 반려해도 완료를 되돌리지 않는다. 확인 축이 없는 옛 건은 «확인 대기» |
| 반려 건의 할 일 | 완료 상태여도 반려면 담당자의 **할 일**로 다시 올라온다(완료 탭에 묻히면 재제출 수단이 사라진다) |

## 2. 정기평가 화면 — 단계별 구현

### 2-1. ① 생성 · ② 대상 · 일정 (마법사)

| 화면 | 규칙 · 문구 |
|---|---|
| 빈 화면 `[＋ 정기평가 생성]` | 재난안전과 담당자만. 그 해 평가가 없을 때 |
| STEP — 대상 부서 | 공용 조직도 다중 선택(기본 전체) |
| STEP — 부서별 점검일 | 필수 · 일괄 적용 가능 · 지난 날짜도 받는다 |
| STEP — 설문 제출 기한 | 필수 · 오늘 이후. 비면 «설문조사표 제출 기한을 정하세요.» · 지나면 «설문조사표 제출 기한은 오늘(YYYY-MM-DD) 이후로 정합니다» |
| 점검일 < 설문 기한인 부서 | **막지 않고 알리기만**(점검 전에 작성본이 들어와야 하므로) |
| 저장 | 토스트 «정기평가 생성 · N개 부서 — 설문조사표 양식을 붙이고 요청 공문을 보내세요». **부서에는 아무것도 가지 않는다** |
| 도구 줄 `[평가 정보 수정]` · `[평가 삭제]` | 설문 요청 공문 **전**에만. 수정은 같은 마법사(«YYYY년 정기평가 정보 수정» → `[저장]`) · 검사는 생성과 같고 **바꾼 설문 기한만** 오늘 이후 검사 · 이력 «평가 정보 수정 · 대상 부서 N개(추가 x · 제외 y) · …». 정보 수정에서 뺀 부서의 양식은 지운다. 삭제 확인 «…를 지웁니다. 되돌릴 수 없습니다.» · «아직 설문조사표 요청 공문을 보내지 않아 부서에 간 것은 없습니다. 지운 뒤 같은 해 평가를 다시 생성할 수 있습니다.» |
| 공문 뒤 | 두 버튼 없음 · 직접 호출 거절 «설문조사표 요청 공문을 보낸 뒤에는 평가 정보를 고치거나 지울 수 없습니다.» · 시스템 관리자 삭제는 지금대로 |

### 2-2. ③ 설문조사표 양식 · 요청 공문

| 화면 | 규칙 · 문구 |
|---|---|
| 양식 `[＋ 첨부]` | 공통본 1개 또는 부서별본. 업로드 칸 안내 «최대 1개». 첨부 직후 «양식을 붙였습니다 — 요청 공문을 보내야 부서에 갑니다»(«발송»이라고 하지 않는다) |
| `[요청 공문 보내기 →]` | 대상 부서 전부에 양식이 있어야 열린다. 없으면 «설문조사표 양식이 없는 부서가 있습니다 — 공통 양식을 먼저 붙이세요.» · 설문 기한 없으면 «설문 제출 기한이 없습니다.» |
| 공문 | §4 공통 골격 · 수신 = 대상 부서장 전부 · 붙임 = 양식 + 별지 «설문조사표 제출 대상 부서»(연번 · 부서 · 점검일 · 받는 사람) |
| 보낸 순간 | 대상 부서 할 일 «유해위험요인 설문조사표 작성·제출(기한)» + 알림(§5) · **양식 잠김** «설문조사표 요청 공문을 보낸 뒤에는 양식을 바꿀 수 없습니다.» |

### 2-3. ④ 부서 제출

| 화면 | 규칙 · 문구 |
|---|---|
| 창 하나 | 내 할일 `[작성본 제출]`과 정기평가 화면 우리 줄 `[지금 제출하기]`가 **같은 창** — «1 양식 받기 · 2 작성본 제출 · [제출]». 양식은 실제로 내려받아진다 |
| 제출 | 파일 1개 · 완료 «설문조사표를 제출했습니다 — 재난안전과에 전달됩니다» |
| 거절 | 요청 공문 전 «아직 설문조사표 요청 공문이 오지 않았습니다.» · 보고서 등록 뒤 «보고서가 등록되어 제출본을 더 이상 바꿀 수 없습니다.» · 다른 부서 «설문조사표 제출은 그 부서 담당자 본인이 합니다.» |
| 기한 지남 | 보고서 등록 전이면 **받는다** · «기한 지남» 표시만 · 새 알림 없음 |
| 재난안전과 | 대리 등록 · 교체(보고서 등록 전만 — 그 뒤에는 버튼을 내지 않는다) |

### 2-4. ⑤ 용역 보고서 + 부서별 조치기한

| 화면 | 규칙 · 문구 |
|---|---|
| `[＋ 통합 보고서 첨부]` | 설문 요청 공문 **뒤**에만(부서 제출 전원은 기다리지 않는다). 전에는 잠김 · «설문조사표 요청 공문을 보낸 뒤에 보고서를 첨부합니다.» |
| 업로드 | 1개 · 보고서 프로필(일반 증빙 12종 · **30MB**) |
| 조치기한 | 같은 창에서 일괄 또는 부서별 · **전 부서 필수 · 오늘 이후**. 비면 «조치기한이 비어 있는 부서가 있습니다 (N개) — 일괄 적용하거나 부서별로 넣으세요.» · 지나면 «조치기한은 오늘(YYYY-MM-DD) 이후로 정합니다 — 지난 날짜인 부서 N개» |
| 저장 | «보고서·조치기한 등록 · 이제 조치를 요청할 부서를 고르세요» · 부서별 조치 표에 «요청» 체크 열(기본 전부) · **설문 제출 마감**(못 낸 부서 «미제출 · 마감» 회색, 제출 카드 · 버튼 사라짐) |
| 보고서 취소 | 조치 요청 공문 전만 |

### 2-5. ⑥ 조치 요청 공문 · ⑥-1 종결 · ⑥-2 추가 요청

| 화면 | 규칙 · 문구 |
|---|---|
| «요청» 체크 → `[조치 요청 공문 (N곳) →]` | 1곳 이상 · 고른 부서 조치기한 **오늘 이후**(화면 · 기안 조건 · 저장 세 곳). 기한이 지난 부서 «조치기한이 지난 부서가 있습니다 (N개) — 기한을 오늘 이후로 고친 뒤 보냅니다.» · 저장 거절 «조치기한이 없거나 지난 부서가 있어 보내지 않았습니다.» |
| 공문 | 수신 = 고른 부서장 · 붙임 = 별지 «조치 요청 부서와 조치기한»(연번 · 부서 · 조치기한 · 받는 사람). **용역 보고서는 붙이지 않고** 별지 끝 «용역 보고서는 중대재해 통합관리시스템 › 위험성평가 › 정기 위험성평가 화면에서 내려받습니다.» |
| 보낸 순간 | 고른 부서 «조치전» + 할 일 «부서별 개선조치 작성(기한)» + 알림 · 고르지 않은 부서 «지적사항 없음»(완료, 할 일 · 알림 없음) · 이력 «조치 요청»(옛 이름 «전달» 쓰지 않음) |
| ⑥-1 `[평가 종결 — 조치 대상 없음]` | 보고서 등록 뒤 · 조치 요청 공문 전. 고른 부서가 0곳이면 «지금 할 일»이 이 버튼. 창 «용역 보고서상 개선이 필요한 부서가 없으면 조치 요청 공문을 보내지 않고 평가를 끝냅니다.» · «종결 사유 *» · «종결하면 되돌릴 수 없습니다.» · `[취소]` `[평가 종결]`. 사유 없으면 «종결 사유를 적으세요.» · 완료 «평가를 종결했습니다 — 조치 대상 없음 · 결과 공문을 기안할 수 있습니다». 대상 부서 전부 «지적사항 없음» · 부서에 할 일 · 알림 없음 · 평가 바로 «완료» |
| ⑥-2 `[추가 조치 요청 →]` | «지적사항 없는 부서 N개 제외» 줄. 조치 요청 공문 뒤 · **평가당 한 번** · 결과 공문 전 · 종결한 평가엔 없음. 창 안 패널(부서 체크 · 조치기한 오늘 이후) → `[추가 조치 요청 공문 (N곳) →]` → 같은 공문 단계(제목 «YYYY년 정기 위험성평가 결과 개선조치 이행 요청(추가)»). 보낸 순간 ⑥과 같은 할 일 · 알림 · 완료로 보이던 평가는 다시 «진행중» |

### 2-6. ⑦ 작성표 · 입력 완료

**보이는 범위** — 재난안전과 · 군수는 전 부서 칸, 그 밖은 **본인 부서 칸만**. 쓸 수 없는 칸은 감추지 않고 읽기 전용(같은 부서 과장 · 팀장).

**쓸 수 있는 때** — 그 부서가 요청을 받았고 입력 완료 전 · 그 부서 담당자 또는 재난안전과 담당자(대신 적은 기록 남김). 다른 부서 «다른 부서의 개선조치는 그 부서 담당자가 적습니다.»

| 화면 | 규칙 · 문구 |
|---|---|
| 열 | **시설물 · 유해위험요인 · 분류 · 원인 · 개선조치 · 담당자**(+ 삭제). 사진 · 완료 칸 없음. 1280px 에서 옆으로 밀지 않는다(표 최소 폭 760px) |
| 표 아래 안내 | «개선 전·후 사진과 완료일은 여기서 받지 않습니다 — [입력 완료] 뒤 생기는 개선조치마다 [완료 처리]에서 올립니다» |
| 유효 행 | 유해위험요인 + 개선조치 둘 다. 부서 머리 «n건 작성»은 유효 행만 · **행을 채우는 순간 다시 그리지 않아도** 수와 «지금 할 일»이 바뀐다 |
| 시설물 | 지정 / 해당 없음 / 미지정 — 셋 다 오류 아님 |
| 담당자 | 그 부서 사람만(조직도가 그 부서만 보인다 · 저장 때 다시 본다) · 비워 두면 «비워 두면 입력 완료 뒤 그 부서가 개선조치 카드에서 지정합니다» · 총칭으로 채우지 않는다 · 작성 중에는 알리지 않는다 |
| `[입력 완료]` | 펼쳐지는 확인 줄이 **화면 안으로 오고** «지금 할 일»이 줄 안 버튼으로. 줄 문구 «적은 N건이 개선조치가 됩니다 · 그 뒤로 작성표는 닫힙니다» · «다음 차례 — 조치를 마치면 [개선조치 완료 처리](또는 내 할일)에서 건마다 개선 후 사진 · 완료일을 올립니다». 0건이면 사유 필수 |
| 입력 완료 순간 | 유효 행 → 개선조치(**모두 진행중**) · 행의 담당자와 부서 조치기한을 이어받음 · 부서 줄 «조치중»(0건이면 «지적사항 없음») · 재난안전과 «조치 입력 완료» 알림 · 행 담당자에게 «개선조치 담당자 지정»(본인 제외) · 토스트 «입력 완료 · 개선조치 N건이 만들어졌습니다 — 조치를 마치면 [개선조치 완료 처리]에서 사진 · 완료일을 올립니다» · 화면이 «내 부서 진행 상황»의 `[개선조치 완료 처리]`(«지금 할 일»)로 옮겨 감 |
| `[입력 완료 취소]` | 그 부서 개선조치 중 완료 처리한 건이 없음 · 결과 공문 전 · 평가 진행 중. 개선조치를 거두고 작성표로(행 남음) · «입력 완료 취소 · 작성표로 돌아갑니다» · 이력 «입력 완료 취소». 다시 완료하면 담당자 지정 알림을 다시 |
| `[입력 재촉]`(부서별 조치 표 줄) | 조치 요청 받음 · 입력 완료 전. 창 «(부서) — 조치 입력 재촉»(받는 사람 · 조치기한 · 조치 요청 · 지난 재촉) → `[재촉 보내기]`. 대상이 아니면 «입력 중인 부서가 아닙니다 — 입력 완료 전 부서만 재촉합니다.» · 줄 «재촉 n회»(과장 · 팀장 조회 표에도) · 내 할일 카드에 재촉 표시 |

### 2-7. 개선조치 카드 (정기 · 수시 공용)

| 버튼 | 누가 · 언제 | 규칙 · 문구 |
|---|---|---|
| `[개선조치 완료 처리]`(내 부서 진행 상황) | 그 부서 담당자 · 미완료 건 있음 | 그 부서 카드 목록을 연다 · 입력 완료 직후 «지금 할 일» |
| `[완료 처리]` | 그 부서 담당자 · 미완료 | 조치 내용 · 완료일 · **개선 후 사진 필수** · 개선 전 사진 선택 · 전자서명. 사진 칸은 **이미지 프로필**(JPG · JPEG · PNG · GIF · 10MB · 5개 — PDF 받지 않음). 정기면 재난안전과에 «완료 확인 요청» |
| `[재제출]` | 그 부서 담당자 · 반려 건 | 같은 완료 창 · 회차 +1 · 확인 축 «확인 대기»로 |
| `[담당자 지정 · 기한 연장]`(수시 `[담당자 지정]`) | 그 부서 담당자 · **미완료 건만**(완료한 건에는 내지 않는다 — 내 할일 카드도 같다) | **처음 담당자를 정할 때 사유 없음**(이력 «담당자 지정») · 담당자를 바꾸거나 기한을 늦출 때만 사유 필수 «변경 사유를 입력하세요» · 기한은 그 건의 현재 기한보다 늦게만 · 앞당기기는 재난안전과 · 늦추면 재난안전과에 «조치기한 연장» 알림 · 담당자를 정하거나 바꾸면 그 사람에게 «담당자 지정»(본인 제외) |
| `[재촉]` | §3 재촉 판정 | 기한 지난 건 · 본인이 담당자인 건은 «본인이 담당자인 건은 재촉하지 않습니다.» · 완료 «재촉 · 받는 사람 ○○» |

- 완료 전 건 표시: 회색 «개선 후 사진은 완료 처리 때 올립니다» · «완료 처리 전 — 기한 …». 종전 «증빙 사진 없음 · 완료 소명 불가»는 쓰지 않는다(오류처럼 읽힌다).
- 카드 번호는 작성 순서 그대로 — 완료해서 정렬이 바뀌어도 번호는 안 바뀐다.

### 2-8. ⑧ 완료 확인 · 결과 공문

| 화면 | 규칙 · 문구 |
|---|---|
| 진입 | 부서 줄 `[관리]` 또는 `[확인 대기 건만 보기 →]` · 재난안전과 내 할일 «완료 확인 대기 — (평가)» → 확인 대기 목록을 바로 연다(확인할 사람이 아니거나 대기가 없으면 열지 않음) |
| 묶음 | 건 단위 기록 · 화면은 **부서별 묶음 제목**. `[관리]`(한 부서 전체)와 `[확인 대기 건만 보기]`(전 부서 대기)를 합치지 않는다 |
| `[확인]` / `[반려]` | 재난안전과 담당자(지금 운영대로 — 완료한 사람이 확인해도 된다). 증빙 열람 체크가 있어야 확인. 반려는 사유 필수 → 담당자 «확인 반려» 알림 · 담당자 할 일에 `[재제출]` |
| 한 번에 확인 | 확인 대기 2건 이상이면 `[확인 대기 N건 한 번에 확인]` — 같은 창이 일괄 화면으로 바뀌어 건마다 조치 내용 · 사진 수 · 완료일 · 서명 · 회차를 펼치고 열람 체크가 있어야 `[N건 확인]`. 대상은 확인 대기만 · **반려는 일괄로 하지 않는다** |
| 결과 공문 기안 | 요청 부서 전부 입력 완료 + 전 건 완료 · 확인(또는 조치 대상 없음). 아니면 기안 막힘(사유) |
| 결과 공문 | §4 공통 골격 · 수신 내부결재 · 붙임 확인 결과표 · 전후 사진철(별지 → PDF) · 그 밖 파일 · 근거는 고른 것만. «조치 대상 없음» 평가는 §4-3 |
| 보낸 순간 | 온나라 기안함까지 · **확인 · 반려 · 확인 취소 잠김** · 평가는 여기서 끝난다(뒤에 근로자 공유 같은 단계 없음) |

### 2-9. «지금 할 일» 강조

접속한 **담당자 계정**에게 지금 단계에서 눌러야 할 **버튼 하나**를 강조한다. 판정 한 곳에서 버튼 하나를 고른다.

- 모양 — 그 버튼에 바깥 고리(브랜드 색 토큰) + 채운 모양 + «지금 할 일» 꼬리표. 맥동은 **강조 대상이 바뀔 때 2회만**(같은 단계에서 다시 그릴 때 반복 없음) · 움직임 줄이기 설정이면 없음 · 화면 가림 · 오버레이 없음.
- 도구 줄 바로 아래 한 줄 — «지금 할 일 — (문장)» + `[바로 가기 ↓]` / «기다리는 중 — (무엇을)» / «완료 — 이 평가는 끝났습니다 · 우리 부서 몫은 모두 끝났습니다 · 지적사항 없음».
- 내지 않는 때 — 조회 계층(과장 · 팀장 · 군수) · 단계별 안내가 켜져 있을 때.

| 단계 | 재난안전과 담당자 | 부서 담당자 |
|---|---|---|
| 평가 없음 | `[＋ 정기평가 생성]` | — |
| 설문 요청 전 | 양식 `[＋ 첨부]` → (전부 붙으면) `[요청 공문 보내기 →]` | 기다리는 중 — 요청 공문 |
| 설문 요청 뒤 · 보고서 전 | 제출이 덜 들어왔고 기한 전이면 «기다리는 중 — 설문 제출 n / m (기한 MM-DD)»(보고서 버튼은 눌린다) · 다 들어왔거나 기한이 지나면 `[＋ 통합 보고서 첨부]` | 미제출이면 `[지금 제출하기]` / 기다리는 중 — 보고서 |
| 조치 요청 전 | `[조치 요청 공문 (N곳) →]` · 고른 부서 0곳이면 `[평가 종결 — 조치 대상 없음]` | 기다리는 중 — 요청 부서 고르는 중 |
| 작성 중 | 기다리는 중 — 입력 완료 n / m곳 · 아직 쓰는 부서 · [입력 재촉] 안내 | 유효 행 0 → `[＋ 행 추가]` · 1 이상 → `[입력 완료]` · 확인 줄이 열리면 줄 안 `[입력 완료]` |
| 조치 중 | 확인 대기가 있으면 `[확인 대기 건만 보기 →]` / 없으면 기다리는 중 | 미완료 건이 있으면 `[개선조치 완료 처리]` · 다 했으면 기다리는 중 — 재난안전과 확인 |
| 전 건 확인 | `[공문 기안]` | 완료 — 우리 부서 몫은 모두 끝났습니다 |
| 결과 공문 뒤 | 결재중이면 기다리는 중 · 결재완료면 완료 — 이 평가는 끝났습니다 | 완료 |
| 요청 안 받은 부서 | — | 완료 — 우리 부서는 조치 요청 대상이 아닙니다(지적사항 없음) |

### 2-10. 화면의 다른 표시

| 표시 | 규칙 |
|---|---|
| 평가 카드 | «대상 부서 N개 (조치 완료 n개 · 지적사항 없음 n개)» · «확인 대기»일 때 완료일 없음 |
| 연도 목록 | 올해를 늘 포함 |
| 이력 | 처리자는 사람 이름 + 시각 · «조치 요청» · «변경» · «입력 완료 취소» |
| 부서장 화면 `[기한초과 재촉]` | 기한 초과 건이 있을 때만 |
| 내 부서 진행 | 설문 제출 → 보고서 · 조치 요청 → 개선조치 작성 · 완료 → 완료 확인. 마감된 설문 «미제출 · 마감» · 요청 안 받음 «할 일 없음» · 확인 전 «평가 완료» 없음 |
| 그 해 대상이 아닌 부서 | 단계 · 표를 그리지 않고 «우리 부서는 YYYY년 정기 위험성평가 대상이 아닙니다.» 한 줄 |

### 4-1. 공통 골격 — 결재선 없이 «온나라로 보내기» (11-06 운영 결정)

`[공문 기안]`(또는 `[요청 공문 보내기 →]` · `[조치 요청 공문 (N곳) →]`) → 본문 직접 작성(삽입 조각) → `[문서 미리보기 →]` → `[온나라로 보내기]` → 확인 → `[보내기]` → 온나라 연계기안함. 검토 · 결재는 담당자가 온나라에서 지정해 상신한다.

- 기안 폼에 보내기 수단이 없다 · 본문을 자동 생성하지 않는다 · 결재선 칸 없음 · 미리보기 서명란은 기안자만.
- 붙임은 이미 올린 파일에서 고른다 · 한도 파일당 10MB · 5개 · 합계 30MB(고르는 단계에서 검사).
- 상태 «기안함 전송 → 결재중 → 결재완료 / 반려 / 반송». 상신 직후 값은 «연계 번호»(«문서번호»는 결재 뒤 생산등록번호).

## 5. 알림

기준 «받는 사람이 할 일이 있을 때만» · 보낸 사람 본인 · 본인 지정은 언제나 뺀다. «부서 안전보건 담당자 → 부서장»은 그 부서에 지정된 부서 안전보건 담당자(재난안전과는 전담부서 등급)가 받고, 없으면 부서장이 받고, 둘 다 없으면 받는 사람 없음(지금 운영 순서).

| 알림 | 신규 | 언제 | 받는 사람 |
|---|:--:|---|---|
| 정기평가 설문조사표 제출 요청 | 시점 변경 | 설문 요청 공문을 보낸 즉시 | 대상 부서 안전보건 담당자 → 부서장 |
| 위험성평가 조치 요청 | ● | 조치 · 추가 조치 요청 공문을 보낸 즉시 | 고른 부서 안전보건 담당자 → 부서장 |
| 위험성평가 조치 입력 완료 | ● | 입력 완료 즉시 | 주관부서 담당자 |
| 위험성평가 조치기한 연장 | ● | 부서가 기한을 늦춘 즉시 | 주관부서 담당자 |
| 위험성평가 조치 입력 재촉 | ● | [입력 재촉] | 그 부서 안전보건 담당자 → 부서장 |
| 개선조치 담당자 지정 | 시점 변경 | 작성표 행 = 입력 완료 순간 한 번(재완료 때 다시) · 카드 지정 · 변경 · 수시 등록 | 지정된 담당자 |
| 개선조치 완료 확인 요청 | | 정기 조치 완료 · 재제출(건마다 · 회차) | 주관부서 담당자 |
| 개선조치 확인 반려 | | 반려 즉시(사유 포함) | 조치 담당자 → 부서 안전보건 담당자 → 부서장 |
| 위험성평가 조치기한 재촉 | | [재촉] · [기한초과 재촉] | 조치 담당자 → 부서 안전보건 담당자 → 부서장 |
| 개선조치 기한 임박 · 초과 | | D-7 · D-1 · D+1 뒤 7일마다(지금 운영대로) | 조치 담당자 · 초과 시 부서장 추가 |
| 수시평가 개선조치 도착 | | 주관부서가 그 부서 건으로 대신 등록 | 그 부서 안전보건 담당자 → 부서장 |

**만들지 않는 알림** — 평가 생성 · 양식 첨부 · 보고서 등록 때 부서 알림 · 설문 제출 기한 임박 · 지남 · 수시 조치 완료의 «완료 확인 요청» · 작성 중 행 담당자 알림.

알림 관리 규칙 표(정본 SCR-ADMIN-002 §4-1)에 신규 4종을 더한다.

### 9-2. 결과 공문 화면 — 프로토타입 동결본

발주처 지시로 동결돼 아래가 남아 있다. **운영은 §4 대로**(결재선 없이 보내기 · 결재 결과 수동 기록은 지금 운영대로).

- 결재선 지정 칸 · «임시 채번» · 결재완료 회신에 생산등록번호 필수값 없음
- «조직도(DYV2.ORG) 한 곳만 갱신하면 됩니다» · «결재권자는 … 코드에 고정하지 않습니다»(개발 용어)
- 상신 확인 창의 회의 발언 인용문
- «온나라 연동은 미구현입니다 — 결재 결과는 … 회신 버튼으로 시연합니다»
- «시행규칙 제37조의4에 따라 … 참여자 … 기록»(참여 근로자 입력을 거뒀으므로 사실과 다름)

### 9-3. 프로토타입 한계

온나라 보내기는 항상 성공으로 재현(실패 · 반송 화면 없음 · «기안함 전송»에서 멈춤 · 연계 번호 임시) · 파일은 브라우저 세션에만 · 알림은 헤더 알림함까지 · 날짜 기준일 2026-11-13 하한(운영은 서버 날짜) · 단계별 안내(투어)는 시연 기능이라 운영에 없으면 해당 없음.
