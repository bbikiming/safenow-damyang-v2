# 구현 요청 — 의견청취 조치 처리 단순화 (2026-11-18)

- 2026-11-18 · 기획 → 개발
- 범위: 의견청취 › **의견청취·건의함**의 처리 흐름, 협의체·점검표 › **점검결과지 미흡 문항** 조치. 산업안전보건위원회 화면은 바꾸지 않습니다.
- 기준 자료: 「담양군 중대재해 2차 교육 1회차 — 재난안전과」(2026-11-18) 23~25쪽. 운영 흐름은 «접수 → 처리 선택(현장점검·개선조치·반려) → 완료»입니다.
- 화면 정의서: SCR-OPN-001 **v1.4** 가 이 문서와 같은 내용입니다. 프로토타입(의견청취 3화면)도 이 흐름대로 맞춰 두었습니다 — 화면을 직접 눌러 보며 확인할 수 있습니다.

**한 줄로** — 의견 처리에서 **안전점검·개선조치를 따로 만들지 않습니다.** 재난안전과 담당자가 그 의견 안에서 «조치 부서·조치 계획»을 적고, 끝나면 «조치 결과 + 증빙 파일»을 올려 닫습니다. 부서와 주고받는 일은 지금처럼 공문·메신저로 하고, 시스템에는 그 결과(회신 공문·사진)를 **파일로** 남깁니다. 부서 담당자는 의견을 **등록하고 조회만** 합니다.

## 1. 왜 바꾸나요

지금 운영 흐름(교육자료 23·25쪽)은 처리 방법을 고르면 **다른 업무가 새로 생깁니다.**

| 지금 | 생기는 문제 |
|---|---|
| [현장점검 실시] → 안전점검 자동 생성 | 의견과 점검이 두 곳에 남고, 완료를 어디서 찍는지가 둘이 됩니다 |
| [개선조치 바로 생성] → 담당자에게 개선조치 생성(5단계 «담당자가 조치 입력») | 개선조치는 **위험성평가 소관**입니다. 평가 진행률·완료 확인·결과 공문이 개선조치 건수를 세는데, 의견에서 만든 건이 섞이면 평가 판정이 흔들립니다. 부서는 «위험성평가 개선조치»와 «의견에서 온 조치»를 같은 목록에서 구분해야 합니다 |
| [저장] = 되돌릴 수 없음(25쪽) | 잘못 고르면 다른 메뉴에 남은 건을 따로 지워야 합니다 |
| 부서 입력 → 재난안전과 확인 | 한 건이 끝나려면 두 사람이 시스템에 들어와야 합니다. 의견청취는 건수가 적고 급하지 않은 업무라 이 왕복이 일만 늘립니다 |

**법이 요구하는 것은 «기록»입니다.** 중대재해처벌법 시행령 제4조제7호는 종사자 의견을 듣고, 재해 예방에 필요하면 **개선방안을 마련해 이행하는지 반기 1회 이상 점검**하라고 정합니다. 필요한 것은 ① 들은 의견 ② 마련한 조치(계획) ③ 이행한 결과와 그 증빙, 셋이 한 건 안에 남는 것입니다. 부서가 시스템에서 직접 입력해야 한다는 요구는 없습니다.

## 2. 바뀐 흐름

```
부서·직원        재난안전과 담당자
[의견 등록] ──▶ [처리]
                 ├ 조치 진행 ── 조치 부서·조치 계획 기록 ──▶ (공문·메신저로 부서와 처리) ──▶ [조치 완료] 결과 + 증빙 파일 ──▶ 완료
                 ├ 바로 완료 ── 이미 조치했거나 답변으로 끝나는 건: 결과 + 증빙 파일 ─────────────────────────────▶ 완료
                 └ 반려 ────── 조치가 필요 없다고 본 이유 ──────────────────────────────────────────────────────▶ 반려
```

| | 지금(운영) | 바꾸면 |
|---|---|---|
| 처리 선택 | 현장점검 실시 / 개선조치 바로 생성 / 반려 | **조치 진행 / 바로 완료 / 반려** |
| 다른 메뉴에 생기는 것 | 안전점검 1건 또는 개선조치 1건 | **없음** |
| 부서가 할 일 | 개선조치에서 조치 입력 | **없음**(등록·조회만) |
| 완료 | 개선조치 완료 → 재난안전과 확인 | 재난안전과가 **[조치 완료]** 한 번(결과 + 증빙 파일 필수) |
| 현장점검 | 점검 종류·예정일·담당자로 안전점검 생성 | 조치 계획에 적습니다(예: «11/25 현장 합동점검 후 미끄럼방지 패드 교체 요청»). 점검 결과는 완료 때 사진·점검 기록 파일로 남깁니다 |
| 사람·클릭 | 2명 · 4~5번 | 1명 · 2번(바로 완료는 1번) |

## 3. 상태

**접수대기 → 조치중 → 완료** (+ 반려)

- `점검중`은 없앱니다. 현장점검도 조치 방법 가운데 하나라서 `조치중`에 들어갑니다.
- `개선조치중`은 `조치중`으로 이름을 바꿉니다. «개선조치»는 위험성평가 메뉴 이름이라, 같은 말을 쓰면 «개선조치 메뉴에 가면 있나»로 읽힙니다.
- 상태별 숫자 바(24쪽 ①): **전체 / 접수대기 / 조치중 / 완료**. 반려는 상태 필터로 봅니다(지금과 같음).
- 목록 상태 칩·필터·숫자 바·처리 카드는 같은 말을 씁니다.

| 조치중 경과 | 조치중 건은 상태 칩 옆에 «n일째»를 보입니다(조치 진행을 저장한 날부터). 알림은 보내지 않습니다 |
| 제목 옆 연동 칩 | «안전점검»·«개선조치» 칩을 걷습니다 |

### 4-2. 의견 등록

**바꾸지 않습니다.** 분류 4종(아차사고·안전제안·위험신고·청취조사) · 온라인 본인 등록 / 오프라인 재난안전과 대리 등록 · 사진 첨부(이미지 프로필) 그대로입니다.

### 4-3. 의견 상세 — 처리 카드 (25쪽 화면)

**접수대기 — 처리 방법 세 가지 중 하나를 고르고 [저장]**

| 선택 | 받는 것 | 저장하면 |
|---|---|---|
| **조치 진행** | 조치 부서 *(공용 조직도 · 부서 선택 · 재난안전과도 고를 수 있음)* · 조치 계획 *(글, 의견 제목을 미리 채움)* · 조치 예정일(선택, 오늘 이후) | `조치중` · 조치 부서를 목록 «조치 부서»에 표시 · 그 부서 담당자에게 **안내 알림**(6장) · 이력 «조치 진행» |
| **바로 완료** | 조치 결과 * · 증빙 파일 * · 완료일 *(기본 오늘, 오늘 이전만)* · 조치 부서(선택) | `완료` · 작성자에게 결과 회신 알림 · 이력 «완료» |
| **반려** | 사유 *(«조치가 필요 없다고 본 이유»)* · 확인창 | `반려` · 작성자에게 사유 알림 · 이력 «반려» |

- 선택 전에는 [저장]을 막습니다(지금과 같음).
- **«되돌릴 수 없음» 경고(25쪽)는 반려에만 둡니다.** 조치 진행은 다른 메뉴에 아무것도 만들지 않으므로 계획 수정으로 고칠 수 있습니다.
- 조치 담당자(사람)·조치 기한은 받지 않습니다. 부서 안에서 누가 하는지는 그 부서가 정하고, 재난안전과는 부서와 공문·메신저로 주고받습니다.

**조치중**

| 버튼 | 받는 것 | 저장하면 |
|---|---|---|
| **[조치 완료]** | 조치 결과 * · 증빙 파일 *(부서 회신 공문·조치 전후 사진·점검 기록 등)* · 완료일 *(기본 오늘, 오늘 이전만)* | `완료` · 작성자에게 결과 회신 알림 · 이력 «완료» |
| [계획 수정] | 조치 부서 · 조치 계획 · 조치 예정일 | 이력 «계획 수정»(바꾸기 전 값 함께) · 부서가 바뀌면 새 부서에 안내 알림 |
| [경과 추가] | 경과 내용(선택: 파일) | 이력 «경과» — 중간에 받은 회신·사진을 남기는 자리 |

- 증빙 파일 칸은 **공용 업로드 칸, 일반 증빙 프로필**(HWP·HWPX·PDF·DOC(X)·XLS(X)·PPT(X)·JPG·PNG 12종 · 파일당 20MB · 10개)입니다. 업로드 칸을 따로 만들지 않습니다.
- **증빙 파일 없이는 완료되지 않습니다.** «완료라고 적고 빠져나가는» 일을 막고, 반기 점검 때 이행 근거가 됩니다. 조치가 필요 없었던 건은 반려로 닫습니다.

**완료 / 반려**

| 상태 | 보이는 것 | 버튼 |
|---|---|---|
| 완료 | 완료일 · 처리자(완료를 누른 계정) · 조치 부서 · 조치 계획 · 조치 결과 · 증빙 파일(내려받기) | [재처리] |
| 반려 | 반려 사유 · 처리자 · 일시 | [재처리] |

- [재처리]는 확인 후 `접수대기`로 돌립니다. 조치 계획·결과·파일은 처리 카드에서 비우되 **처리 이력에는 그대로 남깁니다**(파일 포함).

### 4-4. 처리 이력 · 연동 정보 (25쪽 ④)

- 이력은 자동으로 쌓입니다: 접수 · 조치 진행 · 계획 수정 · 경과 · 완료 · 반려 · 재처리. 각 줄에 처리한 계정·일시를 남깁니다. 사람이 직접 쓰는 것은 경과 추가뿐입니다.
- **«연동 정보» 영역은 «조치 정보»로 바꿉니다** — 조치 부서 · 조치 계획 · 예정일 · 조치 결과 · 증빙 파일. 다른 메뉴로 가는 링크는 두지 않습니다.

### 4-5. 협의체·점검표 › 점검결과지 미흡 문항

의견과 같은 방식입니다.

| 단계 | 요청 |
|---|---|
| 점검결과지 작성 | 문항을 «미흡»으로 고르면 아래에 **조치 부서*(조직도) · 조치 계획***을 받습니다. 개선조치를 만들지 않습니다 |
| 상세 «미흡 문항 조치» | 문항마다 조치 부서 · 계획 · 상태(조치중/완료) · 결과 · 파일 |
| **[미흡 문항 조치 완료]** | 아직 끝나지 않은 미흡 문항을 **체크로 여러 개 고르고** 조치 결과 * · 증빙 파일 * · 완료일 *을 한 번에 받습니다. 한 회신 공문으로 여러 문항이 끝나는 경우가 많아서입니다 |
| 결재와의 관계 | 미흡 문항 조치는 점검결과지 결재 상태와 별개로 진행합니다(결재중·승인완료여도 조치 완료 가능) |
| 점검결과지 수정 | 조치를 완료한 문항은 미흡·조치 부서를 바꿀 수 없습니다. 끝나지 않은 문항은 바꾸면 그대로 따라갑니다 |

- 버튼만 숨기지 말고 **서버 저장에서도 같은 판정**을 해 주세요.
- 할 수 없는 사람에게는 버튼 대신 «처리는 재난안전과 담당자가 합니다» 한 줄을 보입니다.
- 부서 담당자에게 처리 버튼이 없는 것이 정상입니다. 조치 결과는 공문·메신저로 재난안전과에 회신합니다.

- 처리 선택의 **[현장점검 실시]**(안전점검 자동 생성)와 **[개선조치 바로 생성]**
- 상태 `점검중` · 이름 `개선조치중`
- 의견에서 **안전점검·개선조치를 만드는 저장 경로** — 화면에서만 숨기지 말고 서버 경로도 막아 주세요
- 점검결과지 미흡 문항의 **개선조치 자동 연계**
- 개선조치 목록·내 할일에서 «의견청취 출처» 건이 생기는 경로
- 처리 카드·연동 정보의 «이어진 점검·개선조치» 링크

## 9. 이미 있는 자료

- 의견에서 만들어진 **안전점검·개선조치가 몇 건 있는지 먼저 알려 주세요**(교육용 «[실습]» 자료 제외).
- 실습 자료뿐이면 정리해 주세요(의견·안전점검·개선조치 모두).
- 실제 건이 있으면:
  - `점검중`·`개선조치중` 의견 → `조치중`. 조치 부서 = 연결된 점검·개선조치의 담당자 부서, 조치 계획 = 그 점검·개선 내용.
  - 연결된 개선조치는 **지우지 않고** 개선조치 메뉴에 그대로 둡니다. 의견 쪽 이력에 «이전 방식 — 개선조치 ○○에서 처리» 한 줄을 남깁니다. 그 건의 완료는 재난안전과가 [조치 완료]로 의견에서 닫습니다.
  - 이미 `완료`인 의견은 그대로 둡니다.

## 10. 수용 기준

| # | 확인 | 기대 |
|---|---|---|
| OP-01 | 접수대기 의견 처리 카드 | 선택지가 조치 진행 / 바로 완료 / 반려 셋. 현장점검·개선조치 생성이 없다 |
| OP-02 | 조치 진행 저장 | 상태 `조치중`, 목록 «조치 부서» 표시, 조치 부서 담당자에게 안내 알림. 안전점검·개선조치 메뉴에 새 건이 **0건** |
| OP-03 | 조치 완료 — 파일 없이 | 저장되지 않는다(«증빙 파일을 1개 이상 올리세요») |
| OP-04 | 조치 완료 — 결과·파일·완료일 입력 | 상태 `완료`, 작성자에게 결과 회신 알림, 상세에서 파일 내려받기 가능 |
| OP-05 | 바로 완료 | 접수대기에서 한 번에 `완료`. 조건은 OP-03·04 와 같다 |
| OP-06 | 반려 | 사유 없이 저장 안 됨, 확인창 뒤 `반려`, 작성자에게 사유 알림 |
| OP-07 | 재처리 | 재난안전과 담당자만. `접수대기`로 돌아가고 지난 계획·결과·파일은 이력에 남는다 |
| OP-08 | 부서 담당자 계정 | 처리 버튼이 없고 «처리는 재난안전과 담당자가 합니다» 표시. 서버로 직접 요청해도 거절 |
| OP-09 | 부서 담당자 조회 범위 | 우리 부서가 조치 부서인 건 + 내가 낸 건만 보인다 |
| OP-10 | 상태 숫자 바 | 전체 / 접수대기 / 조치중 / 완료. `점검중`·`개선조치중` 문구가 화면 어디에도 없다 |
| OP-11 | 점검결과지 미흡 문항 | 미흡 선택 시 조치 부서·계획을 받고, 개선조치가 생기지 않는다 |
| OP-12 | 미흡 문항 조치 완료 | 여러 문항을 골라 파일 하나로 한 번에 완료된다. 완료한 문항은 점검결과지 수정에서 미흡·부서를 못 바꾼다 |
| OP-13 | 개선조치 메뉴·위험성평가 | 의견청취 출처 건이 새로 생기지 않고, 평가 진행률·확인 대기 수가 의견 처리로 바뀌지 않는다 |
