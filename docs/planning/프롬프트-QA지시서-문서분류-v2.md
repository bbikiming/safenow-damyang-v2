# §A 프롬프트 본문 (여기부터 복사)

```
담양군 중대재해 통합관리 시스템의 **문서 분류 QA 지시서**를 아티팩트로 만들어 줘.

═══════════════════════════════════════
1. 누가 읽나
═══════════════════════════════════════
담양군 재난안전과 담당자. 시스템 개발자가 아니라 **업무 담당 공무원**이다.
전문 용어를 모르고, 이 화면을 처음 열어 본다. 바빠서 오래 붙잡고 있을 수 없다.
짧게, 쉽게, 친절하게 써야 한다.

═══════════════════════════════════════
2. 무엇을 확인하는 QA 인가
═══════════════════════════════════════
「담양군_2025_문서분류_대시보드」에서 정리한 문서 분류가 시스템에 제대로 들어갔고,
담당자가 그것을 **원활하게 찾고 확인할 수 있는가**를 본다.

기능 전체를 훑는 QA 가 아니다. **분류 축 하나**에 집중한다:
  · 문서가 어느 「할 일」의 증거인지 붙어 있나
  · 그것이 화면에서 구분돼 보이나
  · 담당자가 원하는 문서를 찾아갈 수 있나
  · 그 분류가 이행 판정으로 이어지나

═══════════════════════════════════════
3. 확인할 화면
═══════════════════════════════════════
- 업무 관리 > **문서 목록** — 문서를 찾고 분류 상태를 본다
- 업무 관리 > **이행 관리** — 그 분류가 이행 판정으로 이어진다

두 화면은 같은 자료를 **반대 방향에서** 본다. 문서 목록은 「이 서류가 어느 할 일의
증거인가」를, 이행 관리는 「이 할 일의 증거가 갖춰졌나」를 묻는다. 지시서가 이 관계를
한 줄로 설명해 주면 담당자가 두 화면을 오가는 이유를 안다.

═══════════════════════════════════════
4. 지금 시스템에 들어간 자료 (사실로 적어도 되는 값)
═══════════════════════════════════════
【문서】
- 2025년 문서 원장 **57,765건** · **20개 부서**
- 할 일이 붙은 문서 **33,433건**
- 아직 안 붙은 문서(미분류) **22,651건**
- 분류에서 뺀 문서(타 기관 소관·자치사무) **1,681건**
- 할 일은 붙었으나 원장이 「애매」로 표시한 문서(분류 확인) **7,384건**

【할 일】
- 법정 의무 **95가지**, 그 아래 할 일 **213개**
- 2025년에 서류가 있는 할 일 **179개**
- 계층별 — 군 단위 103 · 부서 단위 68 · 관리대상 단위 42

【판정 — 2025년】
- 이행 179 · 미이행 18 · 사유 미발생 8 · 대상 미발생 8
- 법정 이행률 전체 **59/72 (82%)**
- 계층별 이행률 — 군 32/33(97%) · 부서 15/24(63%) · 관리대상 12/15(80%)
- 누락 점검 **34개** = 확인 필요 18 + 조건 확인 16

═══════════════════════════════════════
5. 확인 항목 — 7개로 만들어 줘
═══════════════════════════════════════
많으면 안 한다. 한 항목은 **한 가지만** 묻는다.
아래 7개를 뼈대로 쓰되, 문장은 네가 담당자 말로 다시 써 줘.

각 항목에 이 네 가지를 적는다:
  ① 무엇을 확인하는지 (한 문장)
  ② 어떻게 하는지 (2~4단계, 누를 것·입력할 것을 순서대로)
  ③ 이렇게 나오면 정상 (구체적인 수치나 화면 상태)
  ④ 결과 적는 칸

---
[1] 문서를 이름으로 찾을 수 있나
  · 문서 목록에서 「2025년」 칩을 고르고 검색칸에 "점검" 입력
  · 정상: 5,900건 안팎이 나온다. 칸에 친 낱말이 제목에 들어간 문서만 남는다
  · 다른 낱말 참고 — 교육 약 2,700 · 계획 약 4,400 · 훈련 약 1,400

[2] 어떤 할 일의 서류인지 보이나
  · 검색 결과에서 아무 문서나 한 줄 본다. 「업무단계」 칸을 확인
  · 정상: 할 일 이름이 초록 칩으로 붙어 있다. 두 개까지 보이고 더 있으면 「+N」
  · 「+N」을 누르면 그 자리에서 나머지가 펼쳐진다

[3] 아직 분류가 안 된 문서가 구분돼 보이나
  · 같은 목록을 훑으며 「업무단계」 칸에 회색·주황 표시가 있는 줄을 찾는다
  · 정상: 세 가지가 서로 다르게 보인다
      「미분류」   — 아직 어느 할 일인지 안 붙음 (22,651건)
      「분류 제외」 — 타 기관 소관이라 뺐음 (1,681건)
      「분류 확인」 — 붙었으나 확인이 필요 (7,384건)
  · 셋이 같아 보이거나 뜻을 알 수 없으면 그것을 적어 준다

[4] 문서 하나를 열어 어디서 온 것인지 알 수 있나
  · 아무 문서나 이름을 누른다
  · 정상: 「문서 정보」에 문서번호·보고일자·수발신·담당부서·기준연도·
    데이터 구분이 나온다. 데이터 구분이 「문서 원장 실측」이면 실제 기록이다
  · 「담당자 기록 없음」과 「결재 완료 문서 없음」은 **정상**이다 (§6 표 참고)

[5] 반대로, 할 일에서 그 서류를 볼 수 있나
  · 이행 관리 > 「군 단위」 → 아무 할 일 이름을 누른다
  · 정상: 오른쪽에 그 해 문서가 목록으로 나온다. 열 건씩 쪽이 나뉜다
  · 문서가 많은 할 일 예시 — 「위험기상 대비 안전관리 지시 접수·시달」 3,730건
    (쪽 번호 칸에 숫자를 쳐 넣으면 그 쪽으로 바로 간다)

[6] 부서로 좁힐 수 있나
  · 문서 목록 > 「상세 조건」을 펼치고 「부서」에서 하나 고른다
  · 정상: 그 부서 문서만 남고 건수가 바뀐다
  · 부서별 문서 수 참고 — 재난안전과 10,673 · 재무과 7,537 · 건설과 5,057 ·
    산림정원과 4,058 · 문화체육과 3,759

[7] 화면의 수치가 정리한 자료와 맞나
  · 이행 관리 첫 화면에서 위쪽 숫자판 4개를 본다
  · 정상: 군 단위 기준 법정 이행률 97%, 이행 32 / 산정 대상 33개
  · 계층을 「부서 단위」로 바꾸면 63%, 「관리대상 단위」로 바꾸면 80%
  · 상태 칩 합 — 이행 99 + 미이행 2 + 사유 미발생 2 + 대상 미발생 0 = 103

═══════════════════════════════════════
6. 「이건 결함이 아닙니다」 표를 반드시 넣어 줘
═══════════════════════════════════════
아직 자료가 안 와서 비어 있는 자리가 있다. 미리 알려 주지 않으면 담당자가 전부
문제로 적게 되고, 그러면 **진짜 문제가 묻힌다.** 이 표를 확인 항목보다 **앞에** 둬.

| 화면에 이렇게 보이면 | 뜻 | 언제 채워지나 |
|---|---|---|
| 담당자 「기록 없음」 | 문서 원장이 부서까지만 갖고 있다 | 담당자 연계 |
| 「결재 완료 문서가 없습니다」 | 원본을 아직 보관하지 않는다 | 온나라 연계 |
| 첨부 파일이 안 열림 | 파일 이름만 기록했다 | 본개발 |
| 부서 이행률 「분모 확인 필요」 | 어느 할 일을 어느 과가 맡는지 미확정 | 소관표 수신 |
| 부서 이행률 「원장에 문서 없음」 | 그 부서 이름의 문서가 원장에 없다 | 자료 보완 |
| 「미분류 22,651건」 | 분류 정리가 진행 중이다 | 분류 완료 |
| 2026년 자료에 「예시 자료」 표시 | 올해 실적이 아직 없어 작년 것으로 만든 예시 | 운영 개시 |
| 2024년 이전 문서가 없음 | 받은 원장이 2025년분뿐이다 | 지난 자료 수신 |
| 「판정 보류」 | 판단에 필요한 값(시설 등급 등)이 아직 없다 | 자료 수신 |
| 「미등록」·「미입력」 | 연계로 받지 못한 항목이다 | 연계·자료 |

**반대로 이런 것은 꼭 적어 달라고 해 줘:**
- 눌렀는데 아무 일도 안 일어난다
- 숫자가 위에 적힌 값과 다르다
- 같은 것을 두 화면에서 다르게 말한다
- 무슨 뜻인지 모르겠는 말이 있다
- 찾으려는 것을 못 찾겠다

═══════════════════════════════════════
7. 결과 적는 자리
═══════════════════════════════════════
각 항목마다 「됨 / 안 됨 / 잘 모르겠음」 셋과 자유 메모 한 줄.

**「잘 모르겠음」을 꼭 넣어 줘.** 애매한 것을 억지로 «됨»으로 적게 하면 QA 가 뜻을
잃는다. 「잘 모르겠음」이 많이 나오면 그건 화면 설명이 부족하다는 뜻이라 그 자체가
값진 결과다.

맨 끝에 자유 의견칸을 하나 더 둬 — 「쓰면서 불편했던 것」.

═══════════════════════════════════════
8. 글쓰기 규칙
═══════════════════════════════════════
【용어 — 왼쪽을 쓰지 말고 오른쪽으로】
  이행항목      → 법으로 해야 하는 일
  업무단계      → 할 일
  매핑·분류     → 어느 할 일의 서류인지 붙이는 것
  원장          → 시스템에 들어온 문서 목록
  필터·조건     → 좁혀 보기
  딥링크·URL    → 주소
  판정          → 시스템이 매긴 상태

【문장】
- 명령조 대신 안내조. "확인하시오"(X) → "이렇게 해 보세요"(O)
- 한 문장은 짧게. 두 줄 넘으면 자른다
- 숫자는 정확히. 「많다」 대신 「57,765건」
- 못 하는 것을 사과하지 마. 사실만 담담하게
- 「~하시면 됩니다」보다 「~하세요」. 군더더기를 뺀다

9. 만들 때 주의
═══════════════════════════════════════
- 맨 앞에 **오늘 무엇을 볼 건지 3줄 요약**과 예상 소요 시간
- 「이건 결함이 아닙니다」 표를 **확인 항목보다 앞에**
- 인쇄해서 손으로 적을 수 있게 — 체크칸을 넉넉히, 표가 잘리지 않게
- 항목 사이를 충분히 띄워 어디까지 했는지 알 수 있게
- 밝은 화면·어두운 화면 둘 다에서 읽히게
- 표가 화면 밖으로 나가지 않게

═══════════════════════════════════════
붙임 1. 화면에 실제로 보이는 이름 (이 이름 그대로 써 줘)
═══════════════════════════════════════
지시서가 「○○를 누르세요」라고 쓰려면 화면의 글자와 같아야 한다. 다르면 담당자가
그 버튼을 찾다 멈춘다. **바꿔 부르지 마.**

【찾아가는 길】
맨 위 가로 메뉴 **「업무 관리」** → 왼쪽에 **「이행 관리」**와 **「문서 목록」**

【문서 목록 화면】
- 화면 이름: 문서 목록
- 화면 설명: 「어떤 할 일의 증빙인지와 함께 문서를 찾습니다」
- 검색칸 안내문: 「문서명으로 찾기」
- 버튼: 「＋ 문서 등록」 · 「업무단계 고르기」 · 「상세 조건 ▾」 · 「필터 초기화」
- 연도 칩: 「전체 58,296」 · 「2026년 531」 · 「2025년 57,765」
- 표의 열: 문서명 / 업무단계 / 부서 / 수발신자 / 보고일자 / 결재상태
- 분류 표시: 「미분류」 · 「분류 제외」 · 「분류 확인」
- 「상세 조건」을 펼치면: 부서 · 결재상태 · 수발신처
- 문서 상세의 항목: 문서번호 / 보고일자 / 수발신 / 담당부서 · 담당자 /
  기준연도 / 데이터 구분 / 가져온 원본 / 비고

【이행 관리 화면】
- 화면 이름: 이행 관리
- 화면 설명: 「법으로 해야 하는 일을 군·부서·관리대상 세 계층으로 나눠 봅니다」
- 탭: 「단계별 이행현황」 · 「누락 점검」
- 계층: 「군 단위 103」 · 「부서 단위 68」 · 「관리대상 단위 42」
- 위쪽 숫자판 4개: 「법정 이행률」 · 「서류 확인」 · 「미이행」 · 「조건 미발생」
- 상태 칩: 「전체」 · 「✓ 이행」 · 「□ 미이행」 · 「· 사유 미발생」 ·
  「· 대상 미발생」 · 「− 비해당」
- 검색칸 안내문: 「할 일·법령·수행 주체로 찾기」
- 표의 열: 할 일(업무단계) / 이행주기 / 회차 / 이행상태 / 수행 위치 /
  수행 주체 / 문서
- 부서별 보기의 열: 부서 / 서류가 붙은 할 일 / 보유 업무문서 /
  적용(추정) / 추정 밖 / 이행률

【공통】
- 화면 제목 왼쪽의 **작은 초록 점**을 누르면 그 화면의 설계서가 새 탭으로 열린다
```

# §B 받은 지시서 검수 항목

만들어진 아티팩트를 이 기준으로 본다. 하나라도 어긋나면 고쳐 달라고 한다.

| 확인 | 왜 |
|---|---|
| 확인 항목이 **7개 이하**인가 | 많으면 담당자가 중간에 그만둔다 |
| 「이건 결함이 아닙니다」 표가 **확인 항목보다 앞에** 있나 | 뒤에 있으면 이미 다 적은 뒤에 읽는다 |
| 각 항목에 **기대값이 숫자로** 적혀 있나 | 「정상적으로 나온다」로는 판정할 수 없다 |
| **「잘 모르겠음」** 칸이 있나 | 없으면 애매한 것이 «됨»으로 적힌다 |
| 화면 라벨이 **붙임 1과 글자까지 같은가** | 다르면 그 버튼을 찾다 멈춘다 |
| 시스템 용어가 남아 있지 않나 | 「이행항목」·「매핑」·「원장」이 보이면 고친다 |
| 회신 방법이 적혀 있나 | 다 적고 어디로 보낼지 모르면 그대로 묻힌다 |
| 가정한 것을 밝혔나 | 질문에 답을 안 줬다면 그 가정이 맨 앞에 있어야 한다 |
