# 개발 전달 — 반기 이행점검 «배포 → 제출 → 검토 → 보고» · 교육 참석자 등록부 «교육 끝난 뒤» (2026-11-11)

> **2026-11-12 점검을 마친 뒤** — ① 지난 반기 미이행의 **조치 결과**를 다음 회차 제출 때 필수로 받는다(§1-6-1) ② 전 부서 확인 완료·기한 경과면 재난안전과에 **«마감 보고 차례»** 를 알린다(§1-9 · 내 할일 카드 10).
> **2026-11-12 마감 보고도 결재선 없이** — 반기 마감 보고를 시달 공문과 같이 «온나라로 보내기»(연계기안함 · 결재선 없음)로 맞췄다(§1-9).
> **2026-11-12 화면 단순화** — 이행점검 화면은 **반기 이행점검표 카드 하나**만 남긴다. 체계 점검(F5) · 매뉴얼·업무처리절차 점검 · 관계 법령 의무이행 점검 · 예산 편성·집행 네 영역을 **걷었고**, `[반기 마감 · 군수 보고]`는 이행점검표 카드 머리로 옮겼다(§1-13).
> **2026-11-12 보완** — ① **점검 배포 = 온나라로 시달 공문 보내기**(보내는 순간 배포 · 결재선 없음 · 공문 1건 / 수신처 = 대상 부서 전부 · §1-5-1) ② 이행점검 표는 **조회 범위**(재난안전과·군수 전 부서, 그 밖 우리 부서 줄만 · §1-4) ③ 상신 경로가 14개가 됐다(공통 §7-4 14번).
> **무엇을 바꾸나** — ① 반기 이행점검에 **점검표 배포(시달 공문)**와 **재난안전과 검토(승인·반려)** 를 넣고, «안 낸 것»과 «미이행»을 나누고, 마감 보고 전에 **보고서 미리보기**·상신 뒤 **회차 잠금**을 둔다. ② 집합교육 참석자 등록부를 **교육이 끝난 뒤에만** 받고 **등록 기한**을 둔다.
> **메뉴·화면은 그대로다** — 새 메뉴·새 화면 없음. 이행점검(`menu.html?m=comply`) · 정기교육 목록·상세 · 내 할일 · 알림 관리 · 헤더 알림이 바뀐다.
> **정본** — 화면 정의서 SCR-SBM-006(이행관리) · SCR-EDU-001(정기교육) · SCR-EDU-004(정기교육 상세) · SCR-MYW-001(내 할일) · SCR-ADMIN-002(알림관리) · SCR-SBM-001(경영방침). 이 문서와 정의서가 다르면 정의서가 맞다.
> **프로토타입** — 동작을 그대로 확인할 수 있다(§6). 배경·진단은 `docs/archive/기획-이행점검-배포·제출·확인-흐름보완-v1.md`.
> **화면 모양** — 새 창·칸은 기존 디자인시스템 컴포넌트만 쓴다. 온나라 전송 결과 창은 라벨–값 2열 하나로(§1-14).
> **담양군 확인 대기** — §5. 답이 늦어도 개발은 막히지 않는다(답 전 동작을 함께 적었다).

## 1. 반기 이행점검

### 1-1. 흐름 — 4단계

| 단계 | 누가 | 화면에서 | 결과 |
|:--:|---|---|---|
| 1. 배포 | 재난안전과 담당자 | 축·회차를 고르고 `[점검 배포]` — 점검표 양식 · 안내 · 제출 기한 · 대상 부서 → `[공문 기안 →]` → 시달 공문 제목·본문 → 미리보기 → **`[온나라로 보내기]`** | **보내는 순간 배포** — 대상 부서 내 할일 «결과 제출» 카드 · 헤더 알림. 공문은 온나라 기안함 → 담당자 상신 → 결재 후 각 부서로 시행 |
| 2. 제출 | 그 부서 담당자 | 점검표 내려받기 → 작성(부서장 확인) → 우리 줄 `[결과 제출]` | 줄 «확인 대기» · 부서 할 일 끝(결과 무관) · 재난안전과에 «검토 요청» 알림 |
| 3. 검토 | 재난안전과 담당자 · 팀장 | 줄 `[검토]` → 점검표 내려받아 보고 `[승인]` / `[반려]`(사유) | 승인 = 확인 완료 · 반려 = 그 부서에 알림 + 할 일 다시 생김 |
| 4. 보고 | 재난안전과 담당자 | `[반기 마감 · 군수 보고]` → **보고서 미리보기** → `[온나라로 보내기]` → `[보내기]`(결재선 없음) | 보고 공문 1건이 온나라 연계기안함으로 · 그 회차(두 축) 잠금 · 담당자가 온나라에서 검토·결재 지정해 상신 |

- 미이행은 제출할 때 **조치계획**을 함께 받고, 조치했는지는 **다음 반기 점검**에서 받는다 — 바로 앞 회차에 «일부 미이행»으로 낸 부서는 다음 회차 결과 제출 때 **«지난 반기 미이행 조치 결과»를 필수로** 낸다(§1-6-1). 조치 결과만 따로 올리는 단계는 두지 않는다.
- 대상 부서 전부가 확인 완료되거나 기한이 지나면 재난안전과에 **«마감 보고 차례»** 를 알린다(§1-9).
- 축은 둘(중대산업재해 / 중대시민재해)이고 축마다 배포·제출·검토가 따로다. 마감 보고는 회차 단위(두 축 함께)다.

### 1-2. 업무 수행 주체 (권한) — 정본 SCR-SBM-006 §6

| 하는 일 | 누가 | 범위 |
|---|---|---|
| 결과 제출 · 제출 고치기 · 제출 취소 · 다시 제출 | 그 부서 **담당자** | **자기 부서 줄만** — 재난안전과 담당자도 재난안전과 줄만 낸다. **대리 제출 없음** |
| 검토(승인 · 반려 · 확인 취소) | 재난안전과 **담당자 · 팀장** | 전 부서 — **본인이 제출한 줄은 본인이 검토하지 않는다** |
| 독촉 | 재난안전과(담당자 · 팀장 · 과장) · 그 부서장 | 미제출 · 반려 후 미재제출 줄. 부서 담당자는 자기 부서 줄을 독촉하지 않는다. 군수는 독촉하지 않는다 |
| 점검 배포(시달 공문) · 배포 수정 · 마감 상신 | 재난안전과 **담당자** | 회차 전체 |
| 조회 | 모두 | 전 부서 |

- **화면과 서버 모두** 같은 판정을 건다. 버튼만 숨기면 직접 호출로 뚫린다.
- «재난안전과 팀장»은 재난안전과 소속 + 직위 «팀장»이다. 팀장은 제출·배포·마감을 하지 않는다. 재난안전과장은 조회 + 독촉만 한다.
- 표 위에 «이 화면에서 내가 하는 일»을 계정마다 한 줄로 보인다(위 표와 같은 말).
- ⚠ 운영 재검수 2-1(부서 계정에 `[반기 마감]`·`[점검표 작성]` 활성)과 같은 구멍을 만들지 말 것 — 판정은 «부서 미지정 담당자»가 아니라 **재난안전과 담당자**다.

### 1-3. 상태

**회차(축 × 반기)**

| 상태 | 조건 | 부서 제출 | 회차 선택지 표시 |
|---|---|---|---|
| 배포 전 | 배포 기록 없음 | 불가 | «2026년 하반기 · 배포 전» |
| 진행 중 | 배포됨 · 기한 전 | 가능 | «… · 진행 중» |
| 기한 경과 | 배포됨 · 기한 지남 · 상신 전 | 가능(지연 제출) | «… · 기한 경과» |
| 마감 보고됨 | 상신(결재중 · 결재완료) | 불가 | «… · 마감 보고됨» |

- 반려·반송 회신이 오면 «진행 중 / 기한 경과»로 돌아간다(잠금 해제). 수동 기록 수단은 두지 않는다(공통 §7-4).
- 배포 기록 없이 결과만 있는 지난 회차(시스템 도입 전)는 «배포 기록 없음»으로 조회만 한다 — 배포 기록을 지어 만들지 않는다.

**부서 줄 — 진행과 결과 두 축**

| 진행 | 뜻 | 결과(제출한 줄만) |
|---|---|---|
| 대상 아님 | 이 회차 대상 부서가 아님 — 흐리게, 분모 제외 | — |
| 미제출 | 대상인데 제출 없음(기한 지나면 «기한 경과» 표시) | — |
| 확인 대기 | 제출함 | 전 항목 이행 / 일부 미이행 / 해당없음 |
| 반려 | 재난안전과가 사유와 함께 돌려보냄 | 〃 |
| 확인 완료 | 재난안전과 승인 | 〃 |

- **«미제출»은 저장 값이 아니라 «제출 기록 없음»이다.** 결과 코드는 셋(이행·미이행·해당없음)이고, 손대지 않은 줄을 «미이행»으로 보이지 않는다. 섞으면 미이행을 정직하게 적은 부서에 독촉이 가고 군수 보고의 미이행 목록에 안 낸 부서가 섞인다.
- **검토(확인)는 결과와 별도 축이다** — 상태 `대기 / 완료 / 반려` · 검토자 · 일시 · 반려 사유 · 제출 차수. 승인·반려가 결과 값을 바꾸지 않는다(결과가 틀렸으면 반려해서 부서가 고친다).

**전이**

| 지금 | 행동(누가) | 다음 |
|---|---|---|
| 미제출 | 결과 제출(그 부서 담당자) | 확인 대기(차수 1) |
| 확인 대기 | 제출 고치기(그 부서) | 확인 대기 |
| 확인 대기 | 제출 취소(그 부서, 확인 창) | 미제출(제출 기록 삭제) |
| 확인 대기 | 승인(재난안전과 담당자·팀장) | 확인 완료 |
| 확인 대기 | 반려(재난안전과 담당자·팀장, 사유 필수) | 반려 |
| 반려 | 다시 제출(그 부서) | 확인 대기(차수 +1, 이전 기록 보존) |
| 확인 완료 | 확인 취소(재난안전과 담당자·팀장, 사유 필수) | 확인 대기 |
| 아무 상태 | 마감 상신 | 잠금(전이 없음) |

### 1-4. 화면 구성 (부서별 이행 현황 카드)

- **조회 범위** — 재난안전과(담당자·팀장·과장)와 총괄 책임자(군수)는 전 부서 줄, 그 밖의 부서 담당자·부서장은 **우리 부서 줄만** 본다. 범위가 좁으면 아래 4(명단 갭)·6(요약 칸)을 내지 않는다. 판정은 공통 조회 범위(scope) 한 곳 — 서버 목록 조회도 같은 범위로 거른다.


1. 축 탭 · 점검 회차 선택(상태 표시)
2. 안내 한 줄 + «서류 판정은 업무 관리 › 이행 관리가 따로 합니다» 링크
3. **회차 머리** — 배포 전: 재난안전과 담당자에게 `[점검 배포]`, 그 밖에는 «재난안전과가 배포하면 제출합니다». 기안 중(공문을 보내기 전): «시달 공문 기안 중 · 기한 · 대상 N개 부서 — 아직 배포되지 않았습니다» + `[공문 기안 이어 하기]` `[기안 버리기]`. 배포 후: «시달 공문 기안함 전송 · 보낸 날 · 연계 번호 · [공문 보기]»(재난안전과 담당자에게 «온나라 기안함에서 검토·결재를 지정해 상신하세요») + 상태 칩 · 배포일 · 기한(D-day) · 대상 부서 수 · 안내 · 양식 `[⬇ 파일명]` · 판 번호 · (재난안전과 담당자) `[배포 내용 고치기]`
4. 부서 명단 갭 안내(등록 N / 39)
5. 내가 하는 일 한 줄(§1-2)
6. 요약 칸 — 대상 · 제출(제출률) · 확인 완료 · 확인 대기 · 반려 · 일부 미이행 · 미제출(기한 경과). **이행률은 내지 않는다**(자기 신고라 개수로만).
7. 부서 표 — 부서 · 진행(칩 + 반려 사유 · 검토자/일시 · 차수 · «독촉 N회 · 최근») · 점검 결과(칩 + 미이행 내용 · 조치계획(예정일) · 해당없음 사유 · 비고) · 제출일(지연 제출 · 제출자) · 작성한 점검표(`[⬇ 파일명]`) · 관리(버튼). 대상 부서를 위에, 대상 아님을 아래에.
8. 잠긴 회차는 표 위에 «군수께 보고되었습니다 — 반려·반송되면 다시 열립니다», 버튼 자리에 «잠김».

**관리 칸 버튼 (조건이 맞을 때만 낸다)**

| 버튼 | 보이는 줄 | 보이는 사람 |
|---|---|---|
| `[결과 제출]` | 미제출 | 그 부서 담당자 |
| `[다시 제출]` | 반려 | 그 부서 담당자 |
| `[제출 고치기]` `[제출 취소]` | 확인 대기 | 그 부서 담당자 |
| `[검토]` | 확인 대기 | 재난안전과 담당자·팀장(본인 제출 줄은 «다른 담당자·팀장이 검토») |
| `[확인 취소]` | 확인 완료 | 재난안전과 담당자·팀장 |
| `[독촉]` | 미제출 · 반려 | §1-2 독촉 주체 |

### 1-5. 배포

| 항목 | 필수 | 기본값 | 규칙 |
|---|:--:|---|---|
| 점검 양식 | 예(1개 이상) | 지난 회차 양식 `[이어받기]` 제안 | 공통 첨부 기준(일반 12종 · 20MB · 10개) |
| 안내 | 아니오 | 지난 회차 안내 | 부서 회차 머리에 그대로 |
| 제출 기한 | 예 | 반기 말일(06-30 · 12-31) | 처음 배포는 오늘 이후 |
| 대상 부서 | 예(1개 이상) | 산업 = 전 부서 · 시민 = 공중이용시설 관리 부서 | 공용 조직도 다중 선택 |

- `[점검 배포]` 창의 버튼은 **`[공문 기안 →]`** 이다(«다음 단계에서 각 부서에 보낼 시달 공문(제목·본문)을 작성해 온나라로 보냅니다. 보내는 순간 배포됩니다»). 이 시점의 배포 내용은 **«기안 중»** 으로만 저장되고 부서에는 아무것도 가지 않는다.
- **배포 뒤 고치기** — 기한은 **늘리기만** · 대상 추가 가능(그 부서에 할 일·알림) · 대상 제외는 **제출하지 않은 부서만** · 양식 교체는 **판 번호 +1**, 이전 판 보존, 이미 제출한 부서는 그대로(제출 기록에 어느 판으로 냈는지 남김). 변경 공문을 다시 보낼지는 §5 D-9.
- **배포 취소** — 시달 공문을 보내기 전(«기안 중»)에만 `[기안 버리기]`로 지운다(아무 데도 가지 않았다). **보낸 뒤에는 취소하지 않는다.**

#### 1-5-1. 시달 공문 — 언제 온나라로 가고, 모든 부서에 어떻게 가나 ⚠ 핵심

> 운영 결정(2026-11-06, `_공통_권한정의.md` §7 머리) **«이 시스템은 온나라로 기안까지만 보낸다 — 검토·결재는 담당자가 온나라 기안함에서 지정해 상신한다»** 를 그대로 따른다. 그래서 이 공문 기안에는 **결재선이 없다.**

**(1) 타이밍 — 다섯 시점**

| 시점 | 누가 · 어디서 | 시스템에서 일어나는 일 | 온나라에서 일어나는 일 | 부서가 받는 것 |
|---|---|---|---|---|
| **T0 배포 입력** | 재난안전과 담당자 · 이행점검 `[점검 배포]` | 양식·안내·기한·대상을 «기안 중»으로 저장 | 없음 | 없음 |
| **T1 공문 작성** | 같은 사람 · `[공문 기안 →]` → 제목·본문 작성 → 미리보기 | 지면 미리보기만 | 없음 | 없음 |
| **T2 온나라로 보내기** ★ | 같은 사람 · `[온나라로 보내기]` → `[보내기]` | 온나라 연계(호출기안)로 기안문 **1건**을 보낸다. **연계가 성공 응답(연계 번호)을 주는 순간 배포가 확정된다** — 배포일 = 보낸 날, 판 1, 회차 «진행 중», 대상 부서 할 일(카드 8)·시스템 알림 생성, 시달 공문 «기안함 전송» | 재난안전과 담당자의 **연계기안함**에 기안문이 생긴다(아직 상신 전) | **시스템 알림 · 내 할일** — 점검표를 바로 내려받아 작업을 시작할 수 있다 |
| **T3 온나라 상신** | 재난안전과 담당자 · 온나라 연계기안함 | 문서조회로 읽어 «결재중»으로 바꾼다 | 담당자가 검토·결재자를 지정해 상신 | 없음 |
| **T4 결재 완료 → 시행** | 결재권자 · 온나라 | «결재완료» · 생산등록번호(조회로 오지 않으면 «문서번호 미기재») | 온나라가 **수신 부서 전부에 시행(발송)** — 각 부서 문서함으로 접수 | **온나라 공문 접수** |

- **T2 실패(연계 오류·응답 없음)** — 배포하지 않는다. «기안 중» 그대로 두고 «온나라로 보내지 못했습니다 — 다시 보내기»를 보인다. **반쯤 배포된 상태(부서 할 일은 생겼는데 공문은 안 간 상태)를 만들지 않는다.**
- **반송**(연계기안함에서 상신하지 않고 지우거나 닫음) · **반려**(결재 반려) — 배포는 **유지**한다(부서는 이미 작업 중이다). 회차 머리에 «시달 공문 반송/반려 — 사유»를 보이고 `[시달 공문 다시 보내기]`로 같은 회차 공문을 고쳐 다시 보낸다(이전 기록은 남긴다). 사람이 결재 결과를 옮겨 적는 수단은 없다(공통 §7-4).
- **부서가 시스템 알림(T2)과 온나라 공문(T4)을 따로 받는다** — 둘 사이에 결재 기간만큼 시차가 있다. 시스템 알림을 먼저 내는 이유는 점검 기간(반기 말까지)이 짧고 시스템 안에서 할 일이 이미 완결되기 때문이다. 결재 뒤에 열어야 한다면 T2 대신 T4에서 확정하도록 바꾼다(§5 D-8 — 답 전 동작은 T2 확정).

**(2) 모든 부서에 보내는 방법 — 공문 1건 · 수신처 여러 곳**

| 항목 | 값 |
|---|---|
| 건수 | **회차 × 축마다 1건.** 부서마다 따로 기안하지 않는다(N건이면 결재도 N번이다) |
| 문서 종류 | 시행문 — 기관 내 부서에 보내는 공문(지면 «외부발송» 서식: 수신 · 발신명의 담양군수 · 수신자 행). 화면에서 바꾸지 않는다 |
| 수신 | «수신자 참조» |
| 수신자 | **기본값 = 배포에서 고른 대상 부서 전부.** 기안 창에서 **공용 조직도(부서 다중 선택 트리 · 검색)** 로 더하거나 뺄 수 있고 `[기본값으로]`로 되돌린다. 1곳 이상 필수. 지면 표기 «○○과장 · ○○사업소장 · ○○읍장»(부서장 직위), 연계로는 **부서(처리과) 단위 수신처 목록**을 넘긴다. 재난안전과도 대상이면 수신자에 든다 |
| 수신자 ≠ 배포 대상일 때 | **수신처는 «공문이 가는 곳», 배포 대상은 «시스템 할 일이 가는 곳»이라 서로 바꾸지 않는다.** 갈리면 기안 창에 바로 알린다 — «공문을 받지 않는 점검 대상 N곳(…) — 시스템 할 일·알림만 받습니다» / «점검 대상이 아닌 수신처 N곳(…) — 공문만 받고 결과 제출 대상은 아닙니다». 보내기는 막지 않는다. 대상을 바꾸려면 `[배포 내용 고치기]`(배포 전이면 배포 창)에서 한다 |
| 수신처 코드 | 조직도 부서 ↔ 온나라 수신처(부서 코드) 대응은 조직도 연계 값으로 만든다. **대응 코드가 없는 부서가 있으면 미리보기에 «온나라 수신처 미확인 N곳 — 이 부서는 시스템 알림·할 일로만 받습니다»를 보이고 보내기는 막지 않는다**(점검 자체는 시스템으로 돌아간다). 코드 확보는 §5 D-10 |
| 부서 안에서 누가 받나 | 온나라 공문은 그 부서 문서 접수 담당이 받는다(온나라 몫). 시스템 할 일·알림은 그 부서 **안전보건 담당자(없으면 부서장)** 에게 간다(받는 사람 규칙은 독촉과 같다) |
| 제목 | 기본값 «YYYY년 상/하반기 중대(산업·시민)재해 이행사항 자체점검 실시 통보» — 고칠 수 있다 |
| 본문 | **직접 작성**(자동 생성하지 않는다). 삽입 조각 — 실시 안내 · 점검 개요(대상 부서 수 · 제출 기한 · 제출 방법: 시스템 이행점검에서 내려받아 작성 후 [결과 제출]) · 미이행 작성 안내 · 배포 안내 문구 |
| 붙임(고정) | ① 배포한 점검표 양식(배포 칸에 올린 파일 그대로 — 같은 파일을 두 번 받지 않는다) ② 별지 «점검 대상 부서»(연번 · 부서 · 시스템 알림 받는 사람) PDF. 한도 5개 · 파일당 10MB · 합계 30MB(넘으면 보내기 전 차단) |
| 결재선 | **받지 않는다** — 온나라 기안함에서 지정. 지면 서명란은 기안자만 |
| 공개구분 | 연계 기본값 «공개»(임시, EXT-21) |
| 권한 | 보내기는 **재난안전과 담당자**만(작성·미리보기·확인·보내기 네 경로 모두) |
| 상신 경로 분류 | 공통 §7-4 **14번** — 축·반기 단위, 수동 기록 없음, 반려·반송이면 배포 유지·다시 보내기 |

**(3) 화면 — 단순 기안**

- 공문 기안 창은 **수신(«수신자 참조 — N곳» + 부서장 목록 · `[조직도에서 수신처 고르기]` · `[기본값으로]`) · 제목 · 본문(삽입 조각) · 붙임(고정 목록 + 한도 표시)** 넷뿐이다. 조직도는 창 안에 펼쳐지는 공용 부서 트리(검색 · 다중 선택)이고 새 창을 띄우지 않는다. 체크를 바꾸면 수신 요약과 대상 불일치 안내가 그 자리에서 바뀐다. 문서 종류 선택·결재선 편집·관련 근거 선택은 두지 않는다. 버튼 `[닫기]` `[문서 미리보기 →]`, 하단 «검토·결재는 온나라 기안함에서 지정합니다».
- 미리보기 = 표준 공문 지면(수신자 참조 · 제목 · 본문 · 붙임 · 발신명의 · **수신자** 행 · 서명란 «기안자 — 검토·결재는 온나라 기안함에서 지정») + 별지. 버튼 `[← 수정]` `[온나라로 보내기]`.
- 확인 창 «온나라로 보내면 되돌릴 수 없습니다 — 보내는 순간 대상 부서에 점검이 배포됩니다(할 일·알림). 배포를 취소할 수 없습니다» → `[보내기]`.
- 결과 창 «온나라 기안함에 보냈습니다 · 연계 번호 · 붙임 · **온나라 기안함에서 검토·결재를 지정해 상신하세요** — 결재가 끝나면 온나라가 수신 부서로 시행합니다».
- 회차 머리 «시달 공문 [기안함 전송 → 결재중 → 결재완료 / 반려 / 반송] · 보낸 날 · 연계 번호 · [공문 보기]». «기안함 전송»이면 재난안전과 담당자에게 «온나라 기안함에서 검토·결재를 지정해 상신하세요»를 상시 보인다(보내 놓고 상신을 잊는 것을 막는다).

### 1-6. 결과 제출 (부서)

| 항목 | 필수 | 규칙 / 오류 문구 |
|---|:--:|---|
| 점검 결과 | 예 | 전 항목 이행 / 일부 미이행 / 해당없음 — «점검 결과를 고르세요» |
| 작성한 점검표 | 전 항목 이행 · 일부 미이행 | 공통 첨부 — «작성한 점검표를 올려 주세요» |
| 점검일 | 예 | 기본 오늘 |
| 비고 | 아니오 | 한 줄 |
| 미이행 내용 · 조치계획 · 조치 예정일 | 일부 미이행 | 공백 불가 · 날짜 — «미이행 내용과 조치계획, 조치 예정일을 적어 주세요» |
| 해당없음 사유 | 해당없음 | 공백 불가 — «해당없음 사유를 적으세요 — 사유 없이 빠질 수 없습니다» |

- 창 머리에 배포 내용(회차 · 기한 · 양식 · 판 · 안내)을 보인다. 반려 뒤 다시 낼 때는 «반려된 결과를 고쳐 다시 제출합니다» + 반려 사유.
- 저장 시 제출일 · 제출자(실제 접속자) · 양식 판 · 확인 상태 «대기» · 차수를 남긴다.
- 기한 뒤 제출은 받고 «지연 제출»을 표시한다. 마감 상신 뒤에는 막는다.
- 확인 완료된 줄을 부서가 고치려 하면 막고 «재난안전과에 확인 취소를 요청하세요».

#### 1-6-1. 지난 반기 미이행 조치 결과 (2026-11-12 — 시행령 §5②2 «필요한 조치»)

| 항목 | 값 |
|---|---|
| 누가 내나 | 같은 축의 **바로 앞 회차**(상반기 ← 전년 하반기, 하반기 ← 같은 해 상반기)에 결과를 **«일부 미이행»** 으로 낸 대상 부서 |
| 어디서 | 이번 회차 `[결과 제출]` 창 맨 위 — 지난 반기 «미이행 내용 · 조치계획(예정일)»을 보여 주고 바로 아래에서 받는다 |
| 받는 값 | **조치 결과**(조치 완료 / 조치 중 / 미조치 — 필수) + **내용**(무엇을 했는지, 조치 중·미조치면 사유와 새 예정일 — 필수). 제출 기록에 «지난 반기 조치 결과»로 함께 저장 |
| 오류 문구 | «지난 반기 미이행 조치 결과(조치 완료·조치 중·미조치)와 내용을 적어 주세요» |
| 보이는 곳 | ① 부서 줄 «점검 결과» 칸 아래 «지난 반기 미이행 · 조치계획 «…»(예정) → 조치 완료 …» / «→ 조치 결과 미보고» ② 재난안전과(전 부서 범위) 표 위 «지난 반기(2026 상반기) 미이행 N곳 — 이번 점검에서 조치 결과를 함께 받습니다. 보고 n곳 · 조치 완료 m곳 · 아직 안 낸 곳 k» ③ 검토 창 «지난 반기 미이행 조치 결과» ④ 마감 보고 지면 «지난 반기 미이행 조치 결과 (m / N곳 조치 완료)» 표 ⑤ 부서 내 할일 카드 설명 «지난 반기 미이행 조치 결과도 함께 적습니다» |
| 미조치 · 조치 중 | 막지 않는다 — 그대로 마감 보고에 실려 군수가 «필요한 조치»(인력 배치 · 예산 추가 편성 등)를 판단하는 원료가 된다 |

### 1-7. 검토 (재난안전과 담당자 · 팀장)

- `[검토]` 창: 점검 결과 · (일부 미이행) 미이행 내용·조치계획·예정일 · (해당없음) 사유 · **작성한 점검표 `[⬇ 내려받기]`** · 배포한 양식명·판 · 제출일·제출자 · 반려 사유 입력칸.
- `[승인]` → 확인 완료, 검토자·일시를 줄에 표시. 알림 없음.
- `[반려]` → **사유 필수**(«반려 사유를 적어 주세요 — 부서가 무엇을 고칠지 알아야 합니다»). 그 부서 담당자(없으면 부서장)에게 «반려 — 사유» 알림. 부서 내 할일 카드 다시 생김.
- `[확인 취소]` → 사유 필수, 확인 대기로.
- 본인이 제출한 줄은 본인이 검토하지 않는다(창을 열어도 막는다).
- 화면 문구는 «반려», 정의서에는 «반려(보완 요청)»로 적었다 — 온나라 결재 «반려»와 같은 화면에 함께 나오므로 문맥으로 구분된다.

### 1-8. 독촉

- 미제출 · 반려 후 미재제출 줄에만 낸다(확인 대기 · 확인 완료 · 대상 아님에는 없음). 카드 머리 일괄 버튼은 «미제출 N개 부서 독촉»(미제출만 셈).
- 문구: «결과 제출 독촉» / «반려 재제출 독촉». 받는 사람(부서 안전보건 담당자 → 없으면 부서장)을 누르기 전에 밝힌다.
- **보낸 기록을 남긴다** — 회차 × 부서마다 일시 · 보낸 사람(실제 접속자) · 받는 사람 · 종류. 줄에 «독촉 N회 · 최근 날짜», 마감 보고 미제출 목록에 «(독촉 N회)».

### 1-9. 마감 보고 — 미리보기 · 상신 · 잠금

- **마감 보고 차례 알림** — 그 회차에 배포한 축 전부가 «대상 부서 모두 확인 완료» 또는 «기한 경과»면 카드 머리 버튼 옆에 사유 칩(«전 부서 확인 완료 — 마감 보고 차례» / «기한 경과 — 마감 보고 차례»)을 붙이고 버튼을 주 버튼으로 바꾼다. 재난안전과 담당자 내 할일 카드 10. 판정은 한 곳(화면·내 할일 공용).
- 상신 조건은 **배포된 회차** 하나다. 미제출·확인 대기가 있어도 막지 않는다(전 부서 제출을 게이트로 걸면 보고가 갇힌다 — 실측상 전 부서 제출이 성립한 해가 없다).
- `[반기 마감 · 군수 보고]` → **문서 미리보기**(아래 지면) → `[온나라로 보내기]` → 확인 «보내는 순간 이 회차(두 축)가 잠깁니다 — 제출·검토·배포 수정이 모두 막힙니다» → `[보내기]` → «온나라 기안함에 보냈습니다 · 연계 번호 · 온나라 기안함에서 검토·결재를 지정해 상신하세요». **결재선을 받지 않는다**(운영 결정 «온나라로 기안까지만» — 시달 공문과 같은 방식).
- 미리보기 위 안내: «확인되지 않은 줄 N건은 «미확인»·«반려»로 그대로 올라갑니다».
- **지면**(축마다 반복, 배포 안 한 축은 «배포하지 않았습니다»):
  1. 제목 «YYYY 상/하반기 중대재해 예방을 위한 안전·보건 확보의무 이행점검 결과 보고»
  2. 배포일 · 기한 · 양식 판 · 대상 · 제출 · 확인 완료 · 전 항목 이행 · 일부 미이행 · 해당없음 · 미제출
  3. 부서별 표(대상 부서만): 부서 · 진행(확인 완료 / 미확인 / 반려 / 미제출) · 결과 · 해당없음 사유 · 제출일(지연)
  4. 일부 미이행 사항과 조치계획: 부서 · 미이행 내용 · 조치계획 · 예정일
  5. **지난 반기 미이행 조치 결과**(부서 · 지난 반기 미이행 · 조치계획(예정일) · 조치 결과 — 해당 부서가 있을 때만, «m / N곳 조치 완료»)
  6. 미제출 부서(독촉 횟수)
- 붙임 없음(부서 점검표는 시스템에서 조회 — 10-07 결정). 공개구분 «공개»(임시, EXT-21). 지면을 본문/붙임 1 중 어디에 실을지는 온나라 본문 형식(EXT-22).
- **보내는 순간 그 회차(두 축)를 잠근다**(상태 «기안함 전송»부터 잠금) — 제출 · 고치기 · 취소 · 검토 · 확인 취소 · 배포 수정 · 독촉 모두 막힌다. 보낸 기록(일시 · 기안자 · 연계 번호 · 상태)은 회차별로 저장(다시 들어와도 «마감 보고됨»). 같은 회차는 기안함 전송·결재중·결재완료면 다시 보내지 않고, 반려·반송이면 다시 보낸다(새 기록, 이전 기록 보존).

### 1-13. 다른 화면과의 관계

- **업무 관리 › 이행 관리와 판정을 잇지 않는다** — «이행»을 말하는 축이 셋(서류 · 부서 점검 · 발행)이고 서로의 판정을 읽지 않는 것이 규칙이다. 이 화면의 제출은 부서 점검 축, 이행 관리의 «부서별 의무이행 점검 결과 제출»(IND-10-02)은 온나라 서류로 판정한다. 두 화면 안내에 서로의 역할만 밝힌다. 부서 회신 공문을 시스템 제출로 갈음하기로 정하면(§5 D-1) 그때 서류 축 판정을 다시 정한다.
- 이행 관리에서 이행점검으로 가는 링크는 축까지 맞춰 연다(산업 → `axis=industrial`, 시민 → `axis=citizen`).
- **경영방침 게시 현황**(같은 부서 표를 쓴다)도 «미등록 / 게시 / 미게시 / 해당없음» 넷으로 보인다(미등록 = 기록 없음). 배포·검토는 이행점검에만 있다.
- **이 화면에서 걷은 네 영역(2026-11-12)** — 이행점검 화면은 반기 이행점검표만 다룬다. 운영 화면에서도 아래를 **삭제**한다(정본 SCR-SBM-006 §6 «걷은 영역»).

| 걷은 영역 | 그 일을 하는 곳 |
|---|---|
| 안전보건관리체계 점검(반기) — F5 점검표 `[점검표 작성]` · §4 항목별 근거 현황 표 | 각 정본 화면(경영방침 반기 점검 · 정기 위험성평가 · 인력 평가 · 의견청취). 이 화면의 F5 호출은 없앤다(이미 상신된 문서의 회신 반영은 남긴다 — 상신 경로 5번은 «걷음» 표시) |
| 중대재해 예방 매뉴얼·업무처리절차 점검 | 업무 관리 › 문서 목록 · 이행 관리 |
| 관계 법령 의무이행 점검(목록 미등록 안내 · `[관계 법령 목록이란]`) | 점검 항목은 배포하는 이행점검표 양식 안에 있다 |
| 안전보건 예산 편성·집행 | 인력·예산 › 예산 총괄표 |

- `[반기 마감 · 군수 보고]`(종전 «반기 마감 · 온나라 상신»)는 이행점검표 카드 머리 오른쪽에 둔다. 재난안전과 담당자에게만 보이고, 상신한 회차는 그 자리에 «마감 보고 상신됨 · 연계 번호 · 이 회차는 잠겼습니다».

### 1-14. 화면 모양 — 기존 디자인시스템 그대로 (MUST, 2026-11-12)

이번에 생기는 창·칸은 전부 **이미 있는 컴포넌트**로 그린다. 새 모양을 만들지 않는다. 운영 화면은 운영 디자인시스템의 같은 컴포넌트를 쓴다(괄호는 프로토타입 대응).

| 요소 | 쓰는 것 |
|---|---|
| 창 | 공용 모달 **1개**(적층 금지 — 조직도·추가 입력은 창 안에 펼친다) (`DYV2.openModal` · `.org-inline`) |
| 표 · 상태 · 빈 상태 · 안내 | 공용 표 · 상태 칩(색은 상태 어휘 표에서, 새 어휘는 표에 추가) · 빈 상태 · 안내 상자 (`.table-figma` · `chip-status` + `DYV2.toneOf` · `.v2-empty` · `.check-notice`) |
| 버튼 · 업로드 · 조직도 | 공용 버튼(높이 3단) · 공용 업로드 칸과 그 아래 안내 · 공용 부서 트리 (`.btn` · `DYV2.uploadDrop` + `fileHint` · `ORGPICK`) |
| 공문 지면 | 표준 공문 서식 (`.pdf-gm`) |
| **온나라로 보낸 뒤 결과 창** | **«온나라 결재 상태» 라벨–값 2열 하나** — 맨 위 한 문장(무엇이 일어났는지) + 상태(칩 · 예시 자료) · 문서 · 연계 번호 · 붙임 · 다음 할 일. 보조 문구(«문서번호는 결재가 끝나면 온나라가 부여합니다» 등)는 **값 아래 작은 회색 글씨**. 시달 공문 · 반기 마감 보고 · 교육 공문이 **같은 모양**이고 업무마다 따로 짜지 않는다 (`DYDOC.sentHtml` · `.approval-box` / `.approval-kv`) |

**하지 말 것**
- **문장 중간에 상자형 안내(배경·테두리·안쪽 여백이 있는 칸)를 끼우지 않는다** — 2026-11-12 시달 공문 결과 창이 가운데 정렬 문단 안에 상자 조각을 섞어, 글이 조각으로 갈라지고 줄이 합쳐져 깨져 보였다. 상자형 안내는 업로드 칸 아래처럼 **블록 하나**로만 쓰고, 문장 안의 보조 설명은 회색 작은 글씨다.
- 긴 문단을 가운데 정렬하지 않는다(결과 창의 정보는 라벨–값 표로).
- 색·글자 크기·간격·겹침 순서에 원시값을 쓰지 않는다(디자인 토큰만). 화면 전용 새 클래스 계열을 만들지 않는다.
- **375px 폭에서 확인한다** — 가로 스크롤 없음, 라벨–값 2열은 라벨 폭만 줄여 유지, 버튼·칩이 겹치지 않는다.

## 2. 집합교육 참석자 등록부 — 교육이 끝난 뒤에

### 2-1. 무엇이 바뀌나

- 07-16 «신청 = 참석 증빙 한 단계»(사전 신청 · 불참자 처리 없음)는 **그대로**다. 바뀌는 것은 **언제 받는가**다 — 서명은 참석 사실의 증빙이고 실제 참석시간은 교육이 끝나야 정해지므로, 등록부는 **마지막 회차가 끝난 날부터 등록 기한까지** 받는다.
- 화면 어휘에서 «신청»을 걷는다(사전 신청이 없으므로).

### 2-2. 상태

| 상태 | 조건 | 등록부 | 종료 처리 |
|---|---|---|---|
| 교육 전 | 마지막 회차 날 전 | 받지 않음 — «교육이 끝난 뒤(MM-DD부터) 각 부서 담당자가 참석자 등록부를 올립니다 · 등록 기한 MM-DD» | 불가 |
| 등록부 받는 중 | 마지막 회차 날 이후 · 종료 전 | 받음 · 등록 기한(D-day) 표시 | 가능 |
| 완료 | 종료 처리됨 | 정정 등록부만(현행) | — |

### 2-3. 등록 기한

- 집합교육 등록 폼에 **«참석자 등록부 기한 — 마지막 회차가 끝난 뒤 N일 안에»**(필수 · 1~30일 · 기본 7). 수정에서도 고친다.
- 등록 기한 = 마지막 회차 날 + N일. 목록 카드 · 상세 머리에 표시.
- 기한이 지나면 재난안전과가 종료한다. 기한 전에 종료하면 확인창에 «아직 등록 기한(MM-DD) 전입니다 — 지금 종료하면 그 뒤에 올리려던 부서는 이 교육 이수가 0 이 됩니다».
- 교육이 끝나기 전에는 종료 처리를 막는다(«교육이 끝난 뒤 종료 처리합니다»).

### 2-4. 등록 시점 가드 — 세 곳 같은 판정

- 목록 카드의 `[＋ 참석자 등록부 등록]` · 상세의 `[＋ 참석자 등록부 등록]` · **저장(서버)** 모두 «마지막 회차 날 이후 · 종료 전»을 본다. 교육 전에는 버튼을 내지 않고, 직접 호출해도 «교육이 끝난 뒤(MM-DD부터) 참석자 등록부를 올립니다»로 거절.

### 2-5. 화면 이름 바꾸기

| 전 | 후 |
|---|---|
| 상태 «진행중 · 신청 접수» | «교육 전» / «등록부 받는 중» |
| 목록 상태 필터 «신청 접수 중» | «진행 중» |

### 2-6. 내 할일 (SCR-MYW-001 카드 5)

- 생기는 때: **교육이 끝난 날**(마지막 회차) — 종료 전 · 우리 부서 등록부 없음. 기한 = 등록 기한.
- 제목 «(교육명) — 참석자 등록부 등록», 설명 «교육 MM-DD 종료 · 참석자 · 실제 참석시간 · 서명부 스캔을 올립니다», 버튼 `[등록부 올리러 가기]` → 교육 상세.
- 대시보드의 교육 할 일 수도 같은 판정을 센다.

## 4. 기존 데이터 이관 (운영)

- **이행점검** — 이미 등록된 부서 줄은 그대로 «제출»로 본다(이행 → 전 항목 이행, 미이행 → 일부 미이행 — 미이행 내용·조치계획이 비어 있으면 «확인 필요» 표시, 해당없음 그대로). 검토 상태는 «대기»로 시작한다. 손대지 않은 줄은 «미제출». 이미 지난 회차(배포 기록 없음)는 «배포 기록 없음»으로 조회만. 진행 중인 회차를 바뀐 흐름으로 돌리려면 재난안전과가 그 회차를 배포한다(이미 제출한 부서는 유지).
- **교육** — 접수 중인 교육에 교육 전 등록된 등록부는 지우지 않는다(조회·종료 처리 그대로). 등록 기한이 없는 기존 교육은 기본 7일로 본다.
