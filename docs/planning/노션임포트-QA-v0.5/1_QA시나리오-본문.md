# 1. QA 목적

본 문서는 담양군청 중대재해예방 통합관리시스템의 **실제 화면 흐름**을 기준으로 기능 및 UX 결함을 확인하기 위한 통합 QA 시나리오다.

기존 SafeNow QA 문서의 회원가입·구독·사업장 페르소나·계정별 역할 수행 구조는 사용하지 않는다.
담양군 시스템은 **현재 IA의 기능 모듈 단위**로 테스트하며, 테스트 중 필요한 업무 권한은 화면 우측 상단의 권한 전환 기능을 이용한다.

이번 1차 QA에서 가장 우선적으로 검증하는 범위는 다음과 같다.

1. **위험성평가 전체 업무 흐름** (정기: 생성 → 설문조사표 → 보고서·개선조치 → 완료 확인 → 공문 / 수시)
2. **안전보건교육 전체 업무 흐름** (명단 → 교육 등록 → 참석자 등록부 → **종료 처리** → 이수현황 → 공문)
3. 공통 등록/조회/수정/첨부/상태/권한 UX
4. 나머지 기능 모듈의 기본 진입 및 주요 흐름 Smoke Test

# 4. 테스트 운영 기준

## 4.1 결과 표기

- `PASS`: 기대 결과와 동일하게 동작
- `FAIL`: 기능 오류, 데이터 불일치, UX 진행 불가 또는 명확한 오동작
- `N/A`: 프로토타입 범위상 **의도적으로 미구현**이며 화면이 그 사실을 안내하는 경우 (아래 4.4 ④)
- `SKIP`: 사전조건 미충족·상위 TC 실패로 수행하지 않음
- `N/T`: 아직 수행하지 않음 (초기값)
- `BLOCK`: 이후 시나리오 진행을 막는 치명적 오류
- 실제 결과와 테스터 이름은 테스트하면서 직접 입력한다.

## 4.2 권한 테스트

별도 테스트 계정 정보는 작성하지 않는다. 우측 상단 사용자 칩을 눌러 **페르소나를 전환**한다.

권한은 3계층이고, **조회 범위와 조작 권한이 서로 다른 축**이다.

| 계층 | 페르소나 (TC에서 이 이름으로 지칭) | 조회 범위 | 조작 |
| --- | --- | --- | --- |
| 총괄 책임자 | **김담양** (군수) | 전 부서 | 불가 (조회 전용) |
| 관리감독자 | **홍길동** (재난안전과장) | 전 부서 | 불가 (조회 전용) |
| 관리감독자 | **임시설** (공공시설사업소장) / **오순환** (물순환사업소장) | 소속 부서만 | 불가 (배정만 가능) |
| 업무담당자 | **박안전** (재난안전과 주무관 · 주관부서) | 전 부서 | 전 부서 |
| 업무담당자 | **하정수** (물순환사업소) / **정환경** (환경과) | 소속 부서만 | 소속 부서만 |
| 결재 검토 | **김중대** (중대재해팀장) | 소속 부서만 | 불가 (배정만 가능) |

1. 테스트가 필요한 화면으로 이동한다.
2. 우측 상단 사용자 칩 → 필요한 페르소나를 선택한다.
3. 같은 화면을 권한별로 비교해야 하는 TC에서만 전환한다.
4. **주의** — 「관리감독자(과장·소장)에게 등록/수정 버튼이 보이지 않는 것」은 **정상 동작**이다. 조회 범위가 '전 부서'여도 조작은 담당자만 한다.

**상신은 담당자만 한다 (2026-08-28 적용).** 상신은 기안 행위여서, 관리·감독 계층이 누르면 그 사람이 기안자로 온나라 결재선에 올라간다. 그래서 상신 경로만 권한을 좁혔다.

- 적용 범위 6곳 — **예산 총괄표 · 경영방침 · 의견청취 점검결과지 · 인력 평가 · 이행점검 반기 마감 · 전자문서 폼 확정(=상신)**
- 관리·감독 계층(김담양·홍길동·임시설·오순환·노읍장·김중대·문정수)에게는 **상신 버튼이 나오지 않고** 「상신은 담당자가 합니다 — 관리·감독 계층은 조회만 합니다」가 대신 뜬다. 이는 **정상**이다.
- ⚠ **화면 전체가 조회 전용이 된 것은 아니다.** 좁힌 것은 상신 경로뿐이므로, 같은 화면의 다른 등록·수정 버튼이 보이는 것은 결함이 아니다.

**이 시스템에는 결재함이 없다.** 승인·반려의 판단은 온나라에서 일어난다. **김중대·홍길동으로 접속해도 결재할 것이 없는 것이 정상**이며, 「결재 대기 목록이 없다」는 결함이 아니다.

## 4.3 테스트 데이터 표기

실제 운영 데이터와 혼동되지 않도록 아래 QA 식별값을 권장한다. **입력란이 실제로 있는 값만 적었다.**

- 집합교육명(내용란): `QA_정기교육_집합`
- 자체교육명(내용란): `QA_정기교육_자체`
- 기타교육명(내용란): `QA_기타교육`
- 테스트 근로자: `QA_근로자01`
- 수시평가 내용란: `QA_설비변경작업`
- 테스트 부서: **물순환사업소 / 환경과** (담당자 페르소나가 있는 부서)
- 정기평가는 **평가명 입력란이 없다** — 제목은 「YYYY년 정기 위험성평가」로 자동 생성된다. 연도 셀렉트로 구분한다.

## 4.4 공통 확인 원칙 · 프로토타입 전제

**① 시연 기준일이 `2026-07-16`으로 고정돼 있다.**
전 화면의 D-day·기한초과·이수 판정이 이 날짜 파생이다. 오늘 날짜와 다르다고 FAIL 처리하지 않는다.

**② 데이터는 브라우저 로컬 저장소에 있다.**
탭·브라우저·PC마다 데이터가 다르다. 테스터 간 수치를 비교하지 않는다. 초기화는 헤더 `[?]` 도움말 시트 안 **[예시 데이터 되돌리기]**.

**③ 파일 업로드는 메타(파일명·크기)만 저장한다.**
실제 파일 저장·열람·재다운로드는 없다. 「파일명이 목록에 남는가」까지만 확인한다.

**④ 미구현은 화면이 스스로 밝힌다.**
`○○는 △△ 연계 후 제공됩니다` 형태의 안내가 뜨면 **정상이며 `N/A`로 기록**한다. 반대로 아무것도 저장되지 않았는데 「저장했습니다」가 뜨면 그것은 `FAIL`이다.

**⑤ 결재 결과 회신은 도메인마다 다르다. 「전 시스템이 결재중 하나」가 아니다.**
가르는 기준은 하나 — **결재 결과가 후속 업무를 여는가.**

| 구분 | 도메인 | 결재 결과가 여는 것 |
| --- | --- | --- |
| **회신을 받는다** | 위험성평가 공문 | 평가 종결 · 단계별 안내 완료 판정 |
| | 예산 총괄표 | **집행액·비고 입력** (결재중에는 전면 잠금) |
| | 경영방침 | **현행본 판정** → 이행점검·게시 |
| | 인력 평가 | 문서등록번호·결재일을 평가 이력에 연결 |
| **안 받는다** | 안전보건교육 공문 · 의견청취 점검결과지 · 도급 점검표 | 없음 — 상신 사실까지만 (`결재중` 하나) |

회신을 받는 곳에는 **「결재 결과 회신 등록 — 연계 전 수동 기록」** 수단이 있다. **자체 결재가 아니라 온나라가 보낸 결과를 옮겨 적는 자리**이며, 버튼 라벨과 처리자가 그 문서 결재선에서 파생된다(예: `[검토 승인 회신 (김중대)]` → `[결재 완료 회신]`). 반려는 사유 없이 등록되지 않는다.

**⑥ 정상 동작인데 결함으로 보이기 쉬운 것 — 결함으로 올리지 않는다.**

| 현상 | 왜 정상인가 |
| --- | --- |
| 검토 조직도를 열고 결재 조직도를 열면 **앞엣것이 닫힌다** | 결재선 조직도는 한 번에 한 패널만 연다. 두 패널이 열려 있으면 고른 사람이 어느 단계로 들어갈지 잃는다. |
| 박안전이 상신한 문서를 홍길동으로 전환해 열어도 **기안자가 「박안전」** | 저장된 문서의 기안자는 **상신 당시 사람**이다. 보는 사람에 따라 바뀌면 이력이 위조된다. |
| 김중대로 로그인하면 기본 결재선이 「기안 김중대 → **검토 (미지정)** → 결재 홍길동」 | 기본 결재선은 **기안자 본인을 건너뛴다**. 안 그러면 「기안 김중대 → 검토 김중대」라는 상신 불가 결재선이 뜬다. 조직도에서 검토자를 고르면 된다. |
| 김중대·홍길동으로 접속해도 **결재할 것이 없다** | 결재함을 만들지 않는다(§4.2). 결재는 온나라에서 한다. |
| 결재선 조직도에 **군수·부군수**가 나온다 | 위임전결규칙상 지휘부가 결재권자로 서는 문서가 있다. 표기는 「군수 김담양」이다. |

**⑦ 아직 확인할 수 없는 것 — TC로 만들지 않는다.**
「결재선에 지명된 사람은 소속 부서와 무관하게 그 문서를 열람한다」는 정본이 규정하고 판정 함수도 있지만 **그것을 부르는 화면이 아직 없다.** 지금은 결재문서 목록에 부서 필터가 없어 열람이 우연히 성립할 뿐이다. **연계 후 검증 대상**이며, 김중대에게 타 부서 문서가 보이지 않아도 결함이 아니다.

**⑧ 예산 저장 키가 `dybgt-v3` → `dybgt-v4`로 바뀌었다.**
QA 시작 시 예산 화면의 브라우저 데이터가 **한 번 초기화된다**(옛 키는 삭제된다). 이전에 입력해 둔 예산 값이 사라지는 것은 정상이다.

**⑨ 메뉴에 없는데 열리는 화면이 4개 있다 — 결함이 아니다.**
대메뉴 재편으로 **은퇴한 화면**이며, 사이드바에 없고 **주소·즐겨찾기로만** 열린다. 열면 「이전 버전 화면 — 지금은 …에서 같은 일을 합니다」 부제가 뜨고, **소속 대메뉴(업무 관리)의 사이드바를 달고** 나온다.

| 은퇴 화면 | 지금 그 일을 하는 곳 |
| --- | --- |
| 업무 목록 (`docs-preset.html`) | ⑨ 업무 관리 > 문서 목록 |
| 이행 목록 (`docs-exec.html`) | ⑨ 업무 관리 > 이행 관리 |
| 업무 발행 관리 (`work-admin.html`) | ⑨ 업무 관리 |
| 부서 업무함 (`work-dept.html`) | ① 대시보드 > 내 할일 |

「메뉴에서 찾을 수 없다」·「이전 버전이라고 뜬다」는 **정상**이다. 반대로 **살아 있는 화면이 이 넷으로 링크를 보내면 결함**이다(SMK-011).

**⑩ 메뉴 권한 설정은 실제 메뉴 노출을 바꾸지 않는다.**
시스템 관리 > 메뉴 관리·권한 관리에 등급별 보기·수정 설정이 있지만, 프로토타입의 GNB·사이드바는 **그 설정을 읽지 않는다.** 실제 노출을 정하는 것은 **로그인 계층** 하나다 — 시스템 관리는 박안전만 보이고, 나머지 10개 대메뉴는 전 계층에 보인다. 「권한 관리에서 잠갔는데 메뉴가 그대로 보인다」는 **현재 설계대로**이며 연계·본개발 대상이다.

**⑪ 그 밖의 원칙**
- 목록에서 보이는 값과 상세 화면 값이 일치해야 한다.
- 등록/수정 후 새로고침하거나 재진입해도 저장값이 유지되어야 한다.
- 완료/미완료/기한초과/보완필요 등 상태는 화면마다 같은 의미로 표현되어야 한다.
- 필수값 오류는 사용자가 **어떤 항목을 수정해야 하는지 즉시 알 수 있어야 한다.**
- 화면에서 제공되는 기능만 테스트하며, 화면에 없는 정책이나 기능을 추정하여 FAIL 처리하지 않는다.

# 7. P0 안전보건교육 QA 시나리오

교육은 **근로자 명단 → 교육 등록 → 참석자 등록부 → 교육 종료 처리 → 이수현황 → 공문·결재**까지 데이터가 연결되는지를 핵심으로 본다.

> **가장 중요한 전제 — 이수시간은 참석자 등록 시점이 아니라 [교육 종료 처리] 시점에 생성된다.** 종료 처리를 건너뛰면 이수현황 TC가 전부 재현되지 않는다.
> **두 번째 전제 — 관리감독자의 채용시교육 기준일은 채용일이 아니라 '지정일'이다.** 지정일이 없으면 이수·미이수 어느 쪽도 아닌 **판정 불가**로 남는다. 현재 담양군 관리감독자는 전원 지정일 미등록이므로 `관리감독자 > 채용시교육`이 전건 판정 불가인 것은 **정상**이다.

> **이 절의 테스트 케이스 41건은 별도 데이터베이스에 있다** — 「QA 테스트 케이스」 데이터베이스에서 `구분 = 안전보건교육` 로 거른다. (원본: `2_QA-테스트케이스.csv`)

- [ ] (박안전) 부서별 개선조치 직접 작성 · 조치기한 설정
- [ ] (박안전) 부서 전달
- [ ] (하정수) 조치내용 + 개선 후 사진 입력 후 완료 제출

하나의 평가가 생성부터 공문 상신까지 중간 데이터 손실 없이 연결되고, 요약/부서별 표/이력의 상태가 서로 일치한다.

- [ ] (박안전) 근로자 명단에서 대상 근로자 확인 또는 `QA_근로자01` 등록
- [ ] (박안전) 집합교육 등록 — 회차(일자·시작·종료)로 교육시간 자동 산출 확인
- [ ] (박안전) 상세 진입 → 참석자 등록부 등록 (부서 · 근로자 다중 선택 · 실제 참석시간 · 서명파일)
- [ ] 같은 부서 재등록이 차단되는지 확인
- [ ] (박안전) **[교육 종료 처리]** → 이수기록 생성 확인
- [ ] (하정수) 자체교육 1건 추가 등록
- [ ] 이수현황 > 대상자별 상세에서 필요 · 인정 · 미달 확인 (집합 + 자체 합산)
- [ ] 이수현황 > 부서별 요약의 완료 인원·완료율이 상세와 일치하는지 확인

**E2E 기대 결과**
교육 원천 실적이 종료 처리를 거쳐 개인별·부서별 이수현황으로 정확히 집계되고, 중복 또는 누락이 없다.

## E2E-04 채용 시 교육 · 공문

- [ ] (박안전) 신규 근로자 등록 (채용일 · 고용형태 지정)
- [ ] 채용시교육 미이수 탭에 자동 노출 확인
- [ ] 고용형태별 필요시간(1·4·8h)이 맞는지 확인
- [ ] 이수 등록 → 정상 이수 / 지연 이수 구분 확인
- [ ] [이수 수정]에서 값 변경 후 회수까지 확인 (회수되는 시간·건수 명시 확인)
- [ ] 관리감독자 채용시교육에서 지정일 미등록자가 **판정 불가**로 분리되는지 확인
- [ ] 종료 처리된 교육 1건에서 [공문 기안] → 미리보기 → 상신
- [ ] 상신 후 교육 수정·삭제·등록부 취소가 모두 잠기는지 확인
- [ ] 결재 이력 화면에서 상신 건을 **저장된 문서번호와 함께** 조회
- [ ] **교육은 회신을 받지 않는다** — 상태가 「결재중」 하나로 남고 승인/반려 버튼이 없는 것을 확인

**E2E 기대 결과**
채용 시 교육의 필요시간과 실제 이수시간이 일관되게 관리되고, 공문이 상신된 뒤에는 원본이 잠긴다.

# 11. 결함 기록

> **결함은 별도 데이터베이스에 기록한다** — `3_QA-결함기록.csv` 를 임포트해 만든 「QA 결함 기록」 데이터베이스에 쓴다. 테스트 케이스의 `이슈번호` 속성을 이 데이터베이스에 대한 관계(Relation)로 바꾸면 TC ↔ 결함이 양방향으로 연결된다.

## 심각도 기준

| 등급 | 기준 |
| --- | --- |
| Blocker | 화면진입/저장 등 핵심 흐름이 막혀 이후 테스트 자체가 불가능 |
| High | 주요 업무 완료 불가, 데이터 손실·오집계, 권한·잠금 우회, 다른 업무에 영향을 주는 오류 |
| Medium | 우회 가능하지만 기능 오동작 또는 중요한 UX 오류 |
| Low | 문구, 정렬, 간격, 경미한 표시 오류 등 업무 수행에는 직접 영향이 적음 |

> **결함으로 올리기 전에 4.4의 전제 ①~④를 먼저 확인한다.** 기준일 차이·로컬 저장소·파일 목업·의도된 미구현 안내는 결함이 아니다.
