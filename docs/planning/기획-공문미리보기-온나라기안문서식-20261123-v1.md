## 1. 한 줄 요약

공문 [문서 미리보기]는 **온나라 기안함에서 완성될 기안문과 같은 모양**으로 보여 준다. 이 시스템이 온나라로 보내는 것은 **수신 · 제목 · 본문(글자) · 붙임 파일** 넷뿐이다. 나머지 자리는 값을 지어내지 않고 «온나라가 채움»으로 표시한다. **붙임은 본문 지면에 이어 그리지 않고** 지면 아래 «붙임 파일» 묶음으로 따로 보인다. 온나라에도 붙임은 기안문과 별개의 첨부 파일로 간다.

## 2. 왜 바꾸나 — 회의에서 나온 것

11-20 회의(녹취 27:27~28:45, 자동 받아쓰기라 말이 일부 뭉개져 있다)의 흐름:

| 시각 | 누가 | 요지 |
|---|---|---|
| 27:27 | 팀장(참석자 1) | 연계 기안문 아래에 «추가되는 부분»까지 연계기안함에 문서 하나로 보인다고 들었다. 필요 없으면 아예 안 넘기거나, 그 부분을 **붙임 파일로** 넘기는 방법이 있다 |
| 27:54~28:06 | 팀장 | 그 아래 부분은 붙임이다. **붙임은 따로, 첨부 파일로 들어간다** |

| 28:13 | 팀장 | 본문과 붙임이 전부 **문서 하나로, 미리보기 그대로** 간다고 알아들었다 — 미리보기가 오해를 만들었다 |

문제는 **종전 미리보기의 생김새**였다. 본문 지면 아래에 별지 표가 이어 그려져 있어서, 온나라에도 «본문 + 표»가 한 장으로 가는 것처럼 보였다. 실제로 연계는 본문을 글자로만 보내고 별지는 파일로 붙인다(10-07 회신 «붙임으로 적은 것은 실제 파일로 나간다»). 화면이 실제 동작과 다른 말을 하고 있었다.

## 4. 원칙

1. **보내는 것은 넷이다** — 수신 · 제목 · 본문(글자만, 줄바꿈과 들여쓰기는 그대로) · 붙임 파일. 결재선은 보내지 않는다(운영 결정 11-06 — 검토·결재는 담당자가 온나라 기안함에서 지정한다).
2. **나머지는 온나라가 채운다 — 값을 지어내지 않는다** — 그 자리는 «온나라가 채움»으로 표시한다(기울임 회색). **«미등록»이라고 쓰지 않는다** — 담양군이 줘야 할 자료가 빠진 것처럼 읽힌다. 기관정보는 담양군에 요청하지 않는다(10-07 회신 · EXT-01).
3. **붙임은 본문 지면에 이어 그리지 않는다** — 지면 아래 별도 묶음으로 보인다. 온나라에도 파일 단위로 간다.
4. **표본의 배치를 그대로 쓴다** — 자리 이름뿐 아니라 위치와 간격도 맞춘다(§6).
5. **보낸 뒤 다시 열어도 같은 지면이다** — 저장된 문서는 저장값(기안자 · 수신 · 연계 번호 · 결재완료 시 생산등록번호)으로 그린다. 지금 접속한 사람으로 바뀌지 않는다.

## 6. 배치 — 표본과 같게

- **본문 → 붙임**: 본문이 끝나면 한 줄(약 24px)만 띄우고 바로 붙임 줄이 온다. 본문 칸에 최소 높이를 두지 않는다. 종전에는 120px 최소 높이로 큰 빈칸이 생겼다.
- **발신명의 · 서명란은 쪽 아래**: 화면에서는 지면을 A4 비율(210:297)로 그리고, 발신명의부터 끝까지를 아래로 붙인다. 붙임과 발신명의 사이의 빈 공간은 표본과 같다. 내용이 한 쪽을 넘으면 지면이 늘어난다(내용이 잘리지 않는다).
- **인쇄**에서는 A4 비율을 걸지 않는다. 종이와 여백이 쪽을 정하므로, 비율을 걸면 2쪽으로 넘칠 수 있다.
- **결재일**은 마지막 결재자 이름 위에 작게 놓는다.
- **시행 · 접수**는 한 줄이다. 공개구분은 전화·팩스·전자우편 줄 끝에 붙는다.
- **좁은 화면(375px)**: 지면은 미리보기 창 안에서만 스크롤되고, 페이지가 옆으로 넘치지 않는다.

## 7. 붙임 파일 묶음

지면 아래 «붙임 파일 n개 — 기안문과 따로, 온나라에 개별 파일로 함께 갑니다» 제목의 묶음이다.

| 종류 | 줄 모양 | 내용 |
|---|---|---|
| 올린 파일 | `붙임 n · 파일 이름 · 용량` (용량을 모르면 «올린 파일») | 담당자가 이미 올려 둔 파일 중 기안 창에서 고른 것. 공문 화면에서 새로 받지 않는다(같은 증빙이 두 벌 생긴다) |
| 별지(표) | `붙임 n · 제목.pdf · PDF로 만들어 붙임 · 펼쳐 보기` (접힘) | 펼치면 표 내용이 보인다. 보낼 때 PDF로 만들어 붙인다 |

- 번호는 지면 «붙임» 줄의 순번과 같다. 올린 파일이 먼저 오고, 별지가 뒤에 온다.
- **한도**: 5개 · 파일당 10MB · 합계 30MB(별지도 1개로 센다). 온나라 확인 전 설정값이다(`DYDOC` `ATTACH_LIMIT` 한 줄). 고르는 단계에서 막고, 넘는 파일을 조용히 빼고 보내지 않는다.

**대상 아님**

- **위험성평가 결과 공문**(`DYRSKDOC`) — 동결(2026-08-12)이라 옛 지면 그대로다. 같은 `.pdf-gm` 클래스를 쓰므로 새 규칙은 `.pdf-gm-onnara` 아래에만 두었다. 바꾸려면 발주처 확인이 먼저다.
- **예산 총괄표 · 인력 평가 결과 보고** — 지면 자체를 PDF 붙임 1건으로 보내고 본문은 한 줄이다(2026-11-17). 이 미리보기를 쓰지 않는다.
- **안전보건교육** — 공문이 없다(2026-11-23 제거).

|---|---|---|---|
| 9-1 | «붙임 … 1부. 끝.» 줄을 **연계가 본문 끝에 실어 보내는가, 온나라가 붙임 파일 목록으로 만드는가** | 둘 다 하면 지면에 두 번 찍힌다. 어느 쪽도 안 하면 빠진다 | 지면에 그려 둔다(표본에 있는 자리) |
| 9-2 | 발신명의(«○○과장»)와 기관정보(주소·전화·전자우편)를 **온나라가 다 채우는가** (10-07 O-7) | 연계가 보내야 하면 값 출처를 정해야 한다 | 발신명의는 기안자 부서에서 만들어 보이고, 기관정보는 «온나라가 채움» |
| 9-3 | 별지 PDF를 **어디서 만드는가**(서버 생성 / 화면 인쇄) · 파일 이름 규칙 | 미리보기는 «제목.pdf»로 약속한다 | «제목.pdf» |
| 9-4 | 본문의 **줄바꿈 · 들여쓰기(번호 1. 가. 1))가 연계 후에도 유지되는가** | 온나라 본문은 글자만 받는다. 들여쓰기가 무너지면 번호 체계가 읽히지 않는다 | 사람이 친 그대로 보인다 |
| 9-5 | 공개구분을 연계로 넘길 수 있는가 · 넘기지 못하면 온나라 기본값이 무엇인가 | 업무별 기본값(시스템 «공개»)과 다를 수 있다 | 업무별 기본값 표시 |
| 9-6 | 수신이 여럿일 때 결문 «수신자» 목록을 온나라가 만드는가 | 연계로 수신처 목록만 보내면 충분한지 | 수신 «수신자 참조» + 결문 목록 |

R39(본문 아래 필요 없는 부분은 아예 넘기지 않기)는 9-1·9-3 답과 실제 연계 결과를 본 뒤 정한다.

## 10. 표본과 알고 둔 차이

| 자리 | 표본 | 미리보기 | 두는 이유 |
|---|---|---|---|
| 서명란 칸 이름 | 실제 직위(중대재해팀장 · 재난안전과장) | «검토 · 결재 — 온나라 기안함에서 지정» | 검토·결재자는 온나라에서 지정한다. 직위를 추정해 넣으면 지어낸 값이 된다 |
| 기관정보 · 시행번호 · 표어 · 로고 · 하단 문구 | 실제 값 · 이미지 | «온나라가 채움» | 이 시스템이 보내지 않는 값이다 |
| 붙임 번호 | 1개라 번호 없음 | 1개면 같음, 2개 이상이면 `1. 2.` | 우리 공문은 대개 붙임이 둘 이상이다 |
| 지면 높이 | A4 고정 | 화면은 A4 비율(넘치면 늘어남), 인쇄는 종이에 맞춤 | 내용이 잘리지 않게 한다 |
