## 이번에 바뀐 것 — QA 문서가 모르는 내용
아래는 v0.2 작성 **이후** 바뀐 것이다. 각 항목이 기존 TC를 무효로 만들거나 새 TC를 요구한다.

### A. 결재 결과를 받을지는 도메인마다 다르다 (2026-08-28 확정)
가르는 기준: **결재 결과가 후속 업무를 여는가.**
- **받는다** — 위험성평가 공문 / 예산 총괄표 / 경영방침 / 인력 평가
  · 「결재 결과 회신 등록 — 연계 전 수동 기록」 수단이 있다. 자체 결재가 아니라 온나라가 보낸 결과를 옮겨 적는 자리다.
  · 버튼 라벨·처리자가 그 문서 결재선에서 파생된다(예: `[검토 승인 회신 (김중대)]` → `[결재 완료 회신]`).
  · 반려는 사유 없이 등록되지 않는다.
- **안 받는다** — 안전보건교육 공문 / 의견청취 점검결과지 / 도급 점검표 → 상태는 `결재중` 하나.
- ⚠ 「전 시스템이 결재중 하나」로 적힌 TC가 있으면 **도메인별로 갈라 다시 써야 한다.**

### B. 상신 경로가 새로 생기거나 바뀐 곳
- **예산**: 상신 전 결재선 지정 모달 → 상신 → 결재중. 회신 등록으로 승인완료 → **집행액 입력이 열린다.**
- **경영방침**: 상신 전 결재선 지정 → 결재중. 회신 등록으로 승인완료 → **현행본이 되어 이행점검·게시가 열린다.**
- **이행점검 `[반기 마감 · 온나라 상신]`**: 종전에는 결재선을 묻지 않고 곧바로 팝업이 떴다. 지금은 결재선 지정 → 검증 → 상신이고, 상신된 회차는 버튼 대신 결재선과 상태를 표시한다. 회차 표기가 화면에서 고른 반기를 따른다.
- **인력평가**: 상신하면 부서 단위로 결재선·기안자가 저장된다(종전에는 아무것도 저장되지 않았다). 이미 상신된 부서는 문서번호·결재일·결재선을 상단에 밝힌다.

### C. 상신 권한이 담당자로 좁혀졌다
- 상신은 **기안 행위**이므로 담당자만 한다. 관리·감독 계층(군수·과장·소장)에게는 **상신 버튼이 나오지 않고** 「상신은 담당자가 합니다 — 관리·감독 계층은 조회만 합니다」가 대신 뜬다.
- 적용 범위: 예산 · 경영방침 · 의견청취 점검결과지 · 인력평가 · 이행점검 마감 · 전자문서 폼 확정(=상신).
- ⚠ **화면 전체가 조회 전용이 된 것은 아니다.** 좁힌 것은 상신 경로뿐이다.

### D. 결재선 동작이 바뀐 곳 (QA가 결함으로 오인하기 쉬움)
- **조직도는 한 번에 한 패널만 열린다.** 검토 조직도를 열고 결재 조직도를 열면 앞엣것이 닫힌다 → **정상**.
- **저장된 문서의 기안자는 상신 당시 사람이다.** 박안전이 상신한 문서를 홍길동으로 전환해 열어도 기안자는 「박안전」 → **정상**.
- **관리감독자로 로그인하면 기본 결재선에서 자기가 빠진다.** 김중대로 보면 「기안 김중대 → **검토 (미지정)** → 결재 홍길동」이 뜬다 → **정상**(막다른 길을 없앤 것이다).
- 지휘부(군수·부군수)가 결재선 조직도에 나오고, 표시가 「군수 김담양」이다(종전 「군수 군수 김담양」).

### E. 그 밖에 화면 문구·동작이 바뀐 곳
- 상신 팝업의 **문서번호가 저장된다** — 결재 이력·상태 표시에 나온다. 「온나라에서 문서번호로 확인」이 실제로 가능해졌다.
- 내 할일의 「**결재하러 가기**」 → 「**상신 상태 보기**」, 대시보드의 「**결재 대기 (온나라)**」 → 「**온나라 상신 중**」.
  (이 시스템에는 결재함이 없다 — 결재는 온나라에서 한다.)
- 예산 저장 키가 `dybgt-v3` → `dybgt-v4` 로 바뀌었다. **QA 시작 전 브라우저 데이터가 초기화된다**는 안내가 필요하다.
- 내 할일 화면의 조직도 버튼(개선조치·업무 배정)이 종전에는 오류로 죽어 있었고 지금은 동작한다.

### F. 문서가 약속했지만 아직 구현되지 않은 것 — TC 로 만들면 안 된다
- **`결재선에 지명된 사람은 부서와 무관하게 그 문서를 열람한다`** — 판정 함수만 있고 그것을 부르는 화면이 없다. 지금은 결재문서 목록에 부서 필터가 없어 열람이 우연히 성립할 뿐이다.
  ⚠ QA 문서 §4.2 표의 「결재 검토 · 김중대 · 소속 부서 **+ 결재선에 지명된 문서**」 는 **현재 검증할 수 없다.** 사실대로 고쳐라.
- **결재함(승인·반려 처리 화면)은 없고 앞으로도 만들지 않는다.** 김중대·홍길동으로 접속해도 결재할 것이 없는 것이 정상이며, 그 사실을 QA 문서가 밝혀야 헛된 결함 보고를 막는다.

## 특히 의심스러운 기존 TC (전수로 확인하되 여기부터 봐라)
- **SMK-014**(예산) 기대값 「자체 승인/반려 버튼이 없다」 → **지금은 「결재 결과 회신 등록」 수단이 있다.** 자체 결재가 아니라는 점을 구분해 다시 써라.
- **EDU-040**(교육 결재 이력) 「상태는 결재중 하나」 → 교육은 맞다. 다만 **전 도메인 공통처럼 읽히면 안 된다.**
- **RISK-030 / EDU-037**(기안 → 미리보기 → 상신 순서) → 순서는 그대로다. 다만 위험성평가는 **결재 결과 회신** 단계가 뒤에 붙는다.
- **RISK-031**(결재선 3계정 정합) → 유효하다. 다만 **조직도에서 선택 불가 표시가 실제로 회색으로 보이는지**가 이번에 고쳐진 부분이라 확인 문구를 보강하라.
- **§4.2 권한 테스트 표** → 「상신은 담당자만」이 추가돼야 하고, 김중대 행의 조회 범위를 사실대로 고쳐야 한다.
- **§5 권장 진행 순서 11번**(교육 공문 → 상신 → 결재 이력) → 회신을 받는 도메인의 순서도 필요한지 검토하라.
- **E2E-01 / E2E-04** 체크리스트 → 상신 이후 단계(회신 등록 · 잠금)가 도메인별로 다르다.

## 지켜야 할 것
1. **코드를 실제로 열고, 로컬 서버에서 눌러 보고 쓴다.** 문서나 주석이 「그렇게 했다」고 말하는 것을 근거로 삼지 마라. 서버는 `.claude/launch.json` 의 `demo2`(포트 8786) 를 쓴다.
2. **없는 기능을 TC 로 만들지 마라.** 위 F 항목이 대표적이다. 확인할 수 없는 것은 TC 에서 빼고 「연계 후 검증」으로 옮겨라.
3. **TC 번호 체계와 문서 구조를 유지하라.** 기존 번호를 재사용하지 말고, 삭제한 TC 는 삭제 사유를 변경 요약에 남겨라.
4. **정상 동작을 결함으로 오인할 여지가 있는 것**(위 D 항목)은 §4.4 「공통 확인 원칙」이나 각 TC 기대값에 **명시적으로** 적어라. 이게 이번 개정의 핵심 목적 중 하나다.
5. 프로토타입 한계(온나라 미연계 등)는 감추지 말고 그대로 적되, **바뀐 사실은 정확히** 반영하라.
6. 작업이 끝나면 **버전을 v0.3 으로 올리고** 문서 머리에 「v0.2 대비 변경」을 삭제·재작성·신규 건수와 함께 적어라. `docs/README.md` 표의 해당 줄도 갱신하라.
