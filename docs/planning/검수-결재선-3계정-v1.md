## 2. A. 결재 상태 축이 도메인마다 다르다 — **가장 먼저 정할 것**

발주처가 교육에서 *"공문을 첨부하면 기록이 남잖아요. 더 이상 수정이 안 돼요. 이건 문서 위조예요"* 라고 한 것과 같은 축이다. 지금 **세 가지 처리가 공존**한다.

| 도메인 | 지금 | 근거 |
|---|---|---|
| **위험성평가** | 결재 상태 모달에 `[결재 완료 회신]`·`[반려 회신]` — 누르면 실제로 `결재완료`/`반려`로 저장 | `js/rsk-doc.js:633-641` · `SCR-RISK-001 §4-7`이 「기안됨 → 상신됨 → **결재 완료 / 반려**」를 규정 · **시연 투어 9단계의 마지막이 이 버튼**이고 완료 판정이 `status==='결재완료'`(`js/rsk-tour.js:306-323`) |
| **인력평가** | 상신 직후 「온나라 결재결과 회신 등록」 모달이 **기안자에게** 문서등록번호·결재일을 수기 입력받는다 | `evl-eval.html:1131-1150` · `SCR-EVL-001 §3` 시나리오 6에도 「결과 회신 등록 안내」로 남아 있다 |
| **예산** | 같은 UI(모의 수신 3버튼)를 **2026-08-27에 제거**했다 | `기획-결재선-3계정-정합-v1.md` F-11 |
| 교육·경영방침·의견청취·도급 | 결재중 하나 | 규칙대로 |

**이것은 단순 코드 결함이 아니라 규칙 충돌이다.**
- 「결재 완료·반려를 수기로 받지 않는다」는 **2026-08-13 교육 도메인 확정**이다.
- 위험성평가는 **2026-08-12 동결**이고 그 정의서·투어가 회신을 규정한다.
- **두 확정을 「전 시스템 규칙」으로 일반화한 것은 이번 작업(C순위)에서 `CLAUDE.md §7-1`에 적은 문장이다.** 문서가 코드보다 넓게 말하고 있다.

### ✅ 2026-08-28 확정 — 도메인별로 다름을 확정한다

가르는 기준은 하나다: **결재 결과가 후속 업무를 여는가.**

| | 도메인 | 결재 결과가 여는 것 |
|---|---|---|
| **회신을 받는다** | 위험성평가 공문 | 평가 종결 · 단계별 안내 완료 판정 |
| | 예산 총괄표 | **집행액·비고 입력**(결재중은 전면 잠금) |
| | 경영방침 | **현행본 판정** → 이행점검·게시 |
| | 인력 평가 | 문서등록번호·결재일을 평가 이력에 연결 |
| **안 받는다** | 안전보건교육 공문 · 의견청취 점검결과지 · 도급 점검표 | 없음 — 상신 사실까지만 |

- **받는 것은 「자체 결재」가 아니다** — 온나라가 보낸 결과를 **옮겨 적는 자리**다. ① 화면에 「연계 전 수동 기록」임을 밝히고 ② 승인 단계·처리자를 **그 문서 결재선에서 파생**하며 ③ 회신 등록은 결재가 아니므로 결재선과 무관하게 주관부서 담당자가 한다.
- 2026-08-13 「결재 완료·반려를 수기로 받지 않는다」는 **교육 도메인 확정**이고, 그 근거는 결재 결과가 아무것도 열지 않는 도메인에서만 성립한다. **전 시스템 규칙으로 일반화한 것이 잘못이었다**(`CLAUDE.md §7-1` · 2026-08-28 정정).

### ⚠ 확정에 따라 코드가 못 미치는 곳 2건 — 후속 과제

| 도메인 | 상태 |
