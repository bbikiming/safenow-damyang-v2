## 3. 연계 규격

### 3-1. 엔드포인트

```
http://{별도공지 URL}:{포트}/{영역}/openAPI/{테이블명}
```

| 테이블 | 영역 | 인터페이스ID | 주기 |
|---|---|---|---|
| `TFC1250M` 계약관리대장 | **`FE`** | `LR_FE_LAF_SA_00067` | **일** |
| `TCM3030C` 공통상세코드 | `CM` | `LR_CM_LAF_SA_00005` | 월 |
| `TCM2060C` 부서코드 | `CM` | `LR_CM_LAF_SA_00011` | 월 |

> ⚠ **`TFC1250M` 은 FC 테이블인데 영역이 `FE` 다.** `/FC/openAPI/...` 로 부르면 404. 인터페이스ID도 `LR_FC_` 가 아니라 `LR_FE_` 다.

### 3-2. 요청

**헤더(필수)** — `ifId`(18) · `tranId`(42) · `trnmtInstCd`·`rcptnInstCd`(기관코드 3) · `trnmtInstSysCd`·`rcptnInstSysCd`(시스템코드 3). 선택: `transfGramNo` · `userDeptCode` · `userName`

**바디** — `TFC1250M` 기준

| 파라미터 | 필수 | 값 |
|---|:--:|---|
| `fyr` 회계연도 | **Y** | `2026` — **연도별로 나눠 호출** |
| `lastMdfcnBgngYmd` | N | 증분 시작(YYYYMMDD) |
| `lastMdfcnEndYmd` | N | 증분 종료 |
| `curPage` | **Y** | 1부터 |
| `pageSize` | **Y** | **최대 3,000** |

### 3-3. 페이징 — 루프 필수 (MUST)

응답의 `totalCnt` 를 보고 **마지막 페이지까지 돌린다.** 첫 페이지만 받고 끝내면 **조용히 잘린다** — 오류가 나지 않아 눈치채지 못한다.

### 3-4. 응답 코드

| 코드 | 뜻 | 처리 |
|---|---|---|
| `00000` | 정상 | — |
| `40101` | 유효하지 않은 API 키 | 중단 · 담당자 알림 |
| `40102` | 사용 권한 없음 | 중단 |
| `42901` | **정보제공 요청한도 초과** | **백오프 후 재시도** |
| `50003` | 처리시간 초과 | 재시도 |

**실패를 성공으로 기록하지 않는다** — 연계 관리 카드(§5-3)가 이 결과에서 파생된다.

### 3-5. 받는 필드 8개

| # | 우리 값 | e호조 필드 | 타입 | 필수 | 주의 |
|---|---|---|---|:--:|---|
| 1 | 계약 식별자 | `ctrtLdgrMngNo` 계약대장관리번호 | STRING(12) | Y | **PK·불변.** 멱등키 |
| 2 | 사업명 | `ctrtTrgtNm` 계약대상명 | STRING(300) | Y | |
| 3 | 구분 | `ctrtKndCd` 계약종류코드 | STRING(1) | Y | **코드 — §3-6** |
| 4 | 담당부서 | `deptCd` 부서코드 | STRING(7) | **N** | 비어 올 수 있다 |
| 5 | 기간 시작 | `bgcsYmd` 착공일자 | STRING(8) | **N** | **§3-7 폴백** |
| 6 | 기간 종료 | `cmcnScdYmd` 준공예정일자 | STRING(8) | **N** | **이 열이 연계의 목적** |
| 7 | 계약금액 | `smzCtrtTottAmt` 총괄계약총금액 | NUMBER(20) | Y | **원 단위** |
| 8 | 계약일 | `smzCtrtYmd` 총괄계약일자 | STRING(8) | Y | |

**저장만 하고 화면에 내지 않는 2개** — `ctrtCnltYn` 계약해지여부(1) · `lctnNm` 위치명(300). 같은 응답에 딸려 오므로 버리지 않는다. **해지 계약을 점검 대상에서 거르는 필터로만** 쓴다.

**발주처는 필드로 받지 않는다** — `lafCd` 로 담양군 계약만 받으므로 **고정값 `'담양군'`**.

### 3-6. ⚠ 구분 코드 매핑 — 미확정, 검증 시 확정한다

`ctrtKndCd` 는 **STRING(1) 코드**이고 실제 코드값은 **아직 모른다.** 우리 화면의 5분류(**공사 / 용역 / 구매설치 / 위탁 / 기타**)와 **1:1이 아닐 수 있다.**

- 코드 → 라벨 해석은 `TCM3030C 공통상세코드` 에서 가져온다.
- **매핑표를 코드에 박지 말 것.** `TCM3030C` 의 해석값을 우리 5분류로 옮기는 **변환표를 설정값으로** 둔다.
- **매핑에 없는 코드는 `기타`로 떨어뜨리고 원본 코드를 함께 남긴다.** 조용히 버리면 그 계약이 목록에서 사라진다.
- 보조 필드 `cstcDvCd` 공사구분코드(2) · `ctrtOpslDvCd` 계약목적물구분코드(1) 가 함께 오므로, 1:1이 아니면 이 둘을 조합해 가른다.

### 3-7. 착공일자 폴백 (MUST)

용역·구매설치·위탁은 **착공 개념이 없어** `bgcsYmd` 가 빈다.

```
기간 시작 = bgcsYmd 있으면 그 값
           없으면 smzCtrtYmd (계약일) + 화면에 「계약일 기준」 표시
```

**지어내지 않는다.** 폴백을 썼다는 사실이 화면에 보여야 한다.

### 3-8. 배치 순서

```
① 월 1회  TCM2060C(부서) → TCM3030C(공통상세코드)
② 일 1회  TFC1250M  fyr=당해연도, lastMdfcnBgngYmd=전일
          → 페이지 루프 → upsert(ctrtLdgrMngNo 기준)
```

**upsert 다.** 같은 계약이 변경되면 같은 `ctrtLdgrMngNo` 로 다시 온다. insert 만 하면 중복이 쌓인다.

## 4. 부서코드 매핑 (MUST)

e호조 `deptCd` 는 **7자리**, 우리 `DYV2.ORG` id 는 `safety`·`water` 같은 문자열이다.

- **`DYV2.ORG` 노드에 `ehojoDeptCd` 를 추가한다** — 조직도가 단일 출처다(CLAUDE.md §3). 변환표를 연계 모듈에 따로 두면 조직도와 갈린다.
- ⚠ **`DYV2.ORG` 등록 부서는 11개, 담양군 과·사업소는 39개다.** 계약은 39개 전부에서 나온다.
- **매핑 없는 부서의 계약을 버리지 말 것** — 「조직도 미등록」으로 드러낸다. 버리면 그 부서 도급사업이 화면에서 통째로 사라진다.

## 5. 구현본 수정 지점

### 5-1. 도급관리 — `js/menu.js` `contract()` (≈2000행~)

**① `CONTRACT_BIZ_STATE` 를 연계 수신분과 합친다** (`js/menu.js:2008`)

현재 필드 `{ id, name, cat, dept, co, signed, period, amount, src }`

| 필드 | 지금 | 바꿀 것 |
|---|---|---|
| `id` | gyeyak 공개목록 「번호」(`'4173'`) | **`ctrtLdgrMngNo`** 로 교체 — 체계가 다르다 |
| `name` | 수기 | `ctrtTrgtNm` |
| `cat` | 수기 | `ctrtKndCd` 변환(§3-6) |
| `dept` | 수기 | `deptCd` → `TCM2060C` 해석 |
| **`co`** | 수기 | **그대로 수기** — 연계 안 함(§6) |
| `signed` | 수기 | `smzCtrtYmd` |
| `period` | **10건 중 1건만 채워짐** | `bgcsYmd ~ cmcnScdYmd` (§3-7 폴백) |
| `amount` | 수기(원 단위 문자열) | `smzCtrtTottAmt` |
| **`src`** | `'gyeyak'` 고정 | **`'ehojo'` / `'manual'`** 로 갈라 쓴다 |
| **(신규)** | — | `ctrtCnltYn` · `lctnNm` 저장 |

> 현재 시드 주석이 *"⚠ period 는 10건 중 1건만 채워져 있다 … 빈 채로 두어야 «기간을 모르면 반기 점검 대상을 판정할 수 없다»는 사실이 드러난다"* 라고 적어 둔 바로 그 결손이 메워진다. **주석도 함께 고친다** — 안 고치면 다음 사람이 해소된 제약을 살아 있는 제약으로 읽는다.

**② 출처 표기 — 열을 추가하지 않는다 (정정)**

`srcLine()`(`js/menu.js:2157`)이 **이미 사업명 아래에 `부서 · 계약정보시스템 4173` 형태로 출처를 그리고 있다.** 열을 새로 만들면 같은 정보가 두 곳에 생긴다. **`'gyeyak'` 분기를 `'ehojo'` 로 바꾸는 것으로 끝난다.**

**②-1 ⚠ 검색·페이징을 새로 만든다 (MUST)**

현재 `biz.map(...)`(`js/menu.js:2181`)이 **전건을 한 번에 그린다.** 검색도 페이징도 없다. 수천 건이 들어오면 화면이 무너진다.
- `DYV2.pager()`(`js/common.js:857`)가 이미 있다 — **새로 짜지 말 것**(CLAUDE.md §5). 다만 현재 소비처가 없어 `cmp-docs.js`·`doc-list.js` 는 각자 로컬 페이저를 갖고 있다. **그쪽을 복제하지 말고 공용을 쓴다.**
- 조건이 바뀌면 1쪽으로 돌아간다 · 한 쪽뿐이면 건수만 남긴다(§5 규칙).

**②-2 ⚠ 「점검 대상」 축을 새로 만든다 (MUST)**

지금은 **등록 = 점검 대상**이라 성립했으나, 연계로 전건이 들어오면 **그 전부가 점검 대상은 아니다**(EXT-14 미확정).
- **자동으로 거르지 않는다.** 담당자가 목록에서 **고른다.**
- 고른 것만 점검표·서약서·평가 대상이 된다.
- **요약 지표 4개를 「고른 것」 기준으로 다시 센다**(`js/menu.js:2169`~). 지금은 `biz.length` 전건 기반이라 **「점검표 미작성 3,842」** 같은 읽을 수 없는 숫자가 뜬다. `등록 사업` 라벨도 함께 고친다.

**②-3 안내·빈 상태 문구 교체** (`js/menu.js:2176`·`2192`)

*"공개 목록에서 옮겨 적은 계약… 자동으로 받아오는 연계는 없으므로"* 와 *"계약기간은 목록 화면에 없어 N건 미확인"*(`noPeriod`) **둘 다 사실이 아니게 된다.** `noPeriod` 계산 자체가 불필요해진다.

**③ 수신분의 8필드를 읽기 전용으로**

[수정]에서 `src === 'ehojo'` 면 **사업명·구분·부서·기간·금액·계약일을 잠그고** 수급업체만 받는다. 잠근 이유를 밝힌다(「e호조 원장 값입니다」). **버튼만 잠그면 전역 호출로 뚫리므로 저장 경로에도 가드**(CLAUDE.md 반복 지침).

**④ 등록 창 안내 문구 교체**

```
현재: "계약 시스템에서 사업 정보를 받아오는 경로가 없습니다"
변경: "e호조에서 받은 계약은 목록에 이미 있습니다. 여기는 e호조에 없는 사업을 담는 자리입니다."
```

**⑤ 수급업체가 빈 수신분 처리** — `vendorList()` 가 업체에서 평가 대상을 파생하므로(`js/menu.js:2025`~), **업체가 빈 수신분은 평가 대상에 오르지 않는다.** 그 사실을 목록이 드러내고 「업체를 입력하면 평가 대상이 됩니다」로 안내한다. **요약의 '수급인 미평가'가 이것 때문에 실제보다 작게 보이므로** 그 사실도 함께 밝힌다.

**⑥ 해지 계약 필터** — `ctrtCnltYn === 'Y'` 는 **점검 대상에서 제외**한다. 열로 보여주지는 않는다(§6).

### 5-2. 조직 공사별 선임 현황 — `js/menu.js` `org()` (≈948행)

**① `ORG_CONSTRUCTION_STATE` 를 연계 수신분과 합친다**

현재 `{ id, owner, name, from, to, amount, manager, status, source }`

| 필드 | 바꿀 것 |
|---|---|
| `id` | `ctrtLdgrMngNo` |
| `owner` | **고정 `'담양군'`** (필드로 안 받음) |
| `name` | `ctrtTrgtNm` |
| `from`·`to` | `bgcsYmd` ~ `cmcnScdYmd` (§3-7) |
| `amount` | `smzCtrtTottAmt` |
| **`manager`** | **그대로 수기** — e호조에 없다 |
| `status` | 그대로 — **우리 점검 상태**이지 계약 상태가 아니다 |
| **`source`** | `'ehojo'` / `'manual'` — **주석이 «나중에 연계가 붙으면 이 자리에서 축을 되살린다» 고 적어 둔 바로 그 자리**(`js/menu.js:933`) |

**② 표에 출처 열 추가** (`js/menu.js:1139`) — 현재 7열(발주처·공사명·공사기간·공사금액·안전관리자·점검·관리)에 **출처 표기가 전혀 없다.** 도급관리와 달리 여기는 진짜로 새로 만들어야 한다.

**②-1 안내 문구 교체** (`js/menu.js:1138`) — *"계약 시스템에서 자동으로 들어오는 경로가 없으므로"* 가 사실이 아니게 된다.

**②-2 e호조 행은 안전관리자가 빈 채로 들어온다** — 결함이 아니라 **이 연계의 효과**다. 지금은 등록하지 않은 공사의 선임 공백이 아예 보이지 않는다. 미선임 배지가 한꺼번에 늘어나는 것을 「오류」로 읽지 않도록 안내가 밝힌다.

**③ 수신분은 안전관리자만 수정 가능** — 나머지는 읽기 전용 + 가드.

**④ ⚠ 안전관리자를 현장대리인·계약감독자로 채우지 말 것 (MUST)**

e호조에 `TFC1910L 현장대리인`·`TFC1190L 계약감독자`가 있지만 **둘 다 산안법 안전관리자와 다른 지위**다. 채우면 **선임 공백이 선임된 것으로 표시**되어 법정 의무 미이행이 이행으로 둔갑한다. **이 두 API 를 호출하지 않는다.**

**⑤ 중복 처리** — 같은 공사가 수신분·등록분으로 둘 다 있을 수 있다. `ctrtLdgrMngNo` 유무로 구분하되 **자동 병합하지 않는다**(담당자가 정리 — 정의서 §4-5).

### 5-3. 연계 관리 — `admin-integration.html`

- **카드 4장 → 5장.** e호조+(계약) 카드 추가 (`admin-integration.html:40`~ 패턴 따름)
- `data-page-subtitle` 갱신 — 현재 `"온나라 · FMS · 법제처 · 행정포털 상태 모니터링"`
- 상단 안내(15~18행)의 *"상태를 만들어 내는 연계는 둘"* 문구 갱신
- **인증 정보 미수령 상태는 「미설정」** — 정상·지연·실패 어느 것으로도 표시하지 않는다(온나라·행정포털의 「연계 이력 미구현」과 같은 규칙)
- 이동 링크는 **도급관리**로
