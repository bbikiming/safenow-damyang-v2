## 0. 한눈에 · 우선순위 · 용어

**한 줄** — «부서가 이행/미이행을 찍는 표 + 다섯 영역」을 **«재난안전과가 점검표를 배포(온나라 시달 공문)하고 → 부서가 작성해 제출하고 → 재난안전과가 검토(승인·반려)하고 → 반기 마감으로 군수에게 보고(온나라)하는 반기 이행점검표 화면 하나」** 로 바꾼다. 법령 근거는 중처법 시행령 §5②1·2(시민 축 §11②1·2) — 반기 1회 이상 점검 → 보고 → 미이행이면 필요한 조치.

**우선순위**
- **P1** — 2026 하반기 점검(통상 11월 하순 실시 통보) 전에 필요하다: R-01~R-09 · R-11 · R-13 · R-17 · R-18 · §5 연계
- **P2** — 그다음: R-10 · R-12 · R-14 · R-15 · R-16

**용어**

| 말 | 뜻 |
|---|---|
| 축 | 중대산업재해(산업) / 중대시민재해(시민). 축마다 배포·제출·검토가 따로다 |
| 회차 | 반기 — `2026-H1`(상반기) · `2026-H2`(하반기). 마감 보고는 회차 단위(두 축 함께) |
| 배포 | 재난안전과가 점검표 양식 · 안내 · 기한 · 대상 부서를 정해 내려보내는 것. **시달 공문을 온나라로 보내는 순간 확정된다** |

| 마감 보고 | 회차의 점검 결과를 군수에게 보고하는 공문 — 온나라로 보내는 순간 회차가 잠긴다 |
| 진행 | 부서 줄의 처리 상태 — 대상 아님 · 미제출 · 확인 대기 · 반려 · 확인 완료 |
| 결과 | 부서가 낸 점검 결과 — 전 항목 이행 · 일부 미이행 · 해당없음(제출한 줄만) |
| 연계 번호 | 온나라로 보낸 직후 온나라가 돌려주는 값. **문서번호(생산등록번호)는 결재가 끝나야 생긴다** — 둘을 섞지 않는다 |
| 재난안전과 담당자 / 팀장 | 재난안전과 소속 + 등급 «담당자» / 재난안전과 소속 + 직위 «팀장» |
| 부서 실무자 | 그 부서 소속 **담당자 계층**(과장·소장·실장·국장·읍면장·팀장·군수가 아닌 사람). 지정 담당자로 좁히지 않는다 |

## 2. 바뀐 뒤 흐름 — 4단계

| 단계 | 누가 | 화면에서 | 결과 |
|:--:|---|---|---|
| 1. 배포 | 재난안전과 담당자 | 축·회차 → `[점검 배포]`(양식·안내·기한·대상) → `[공문 기안 →]` → 시달 공문 제목·본문 → 미리보기 → **`[온나라로 보내기]`** | **보내는 순간 배포** — 대상 부서 내 할일 «결과 제출» · 헤더 알림. 공문은 온나라 기안함 → 담당자 상신 → 결재 후 각 부서로 시행 |
| 2. 제출 | 그 부서 실무자 | 점검표 내려받기 → 작성(부서장 확인은 부서 안 절차 — 시스템은 묻지 않는다) → 우리 줄 `[결과 제출]` | «확인 대기» · 부서 할 일 끝(결과 무관) · 재난안전과에 «검토 요청» |
| 3. 검토 | 재난안전과 담당자 · 팀장 | `[검토]` → 점검표 내려받아 보고 `[승인]` / `[반려]`(사유) | 승인 = 확인 완료 · 반려 = 그 부서 알림 + 할 일 다시 |
| 4. 보고 | 재난안전과 담당자 | `[반기 마감 · 군수 보고]` → 보고서 미리보기 → `[온나라로 보내기]` → `[보내기]` | 보고 공문 1건이 온나라 연계기안함으로 · 회차(두 축) 잠금 |

- 미이행은 제출 때 **조치계획**을 받고, 조치했는지는 **다음 반기 제출 때** 받는다(R-10). 조치 결과만 올리는 단계는 두지 않는다.
- 대상 전부 확인 완료 또는 기한 경과면 재난안전과에 **«마감 보고 차례»** 를 알린다(R-13).
- **이 시스템에서 결재선을 받지 않는다** — 시달 공문 · 마감 보고 모두 «온나라 기안함까지»만 보내고, 검토·결재는 담당자가 온나라에서 지정해 상신한다(운영 결정 2026-11-06).

## 4. 수정 요청

### R-01 · 네 영역 삭제 · 카드 하나로 (P1)

- **삭제** — 카드 2 «안전보건관리체계 점검 (반기)»(`[점검표 작성]` · §4 근거 현황 표 · «현행 경영방침이 없어…» 안내) · 카드 3 «중대재해 예방 매뉴얼·업무처리절차 점검» · 카드 4 «관계 법령 의무이행 점검»(`[관계 법령 목록이란]` 포함) · 카드 5 «안전보건 예산 편성·집행».
- 카드 1 제목 «부서별 이행 현황 (전수 점검)» → **«반기 이행점검표»**.
- 카드 머리 오른쪽에 **`[반기 마감 · 군수 보고]`**(재난안전과 담당자만 — R-02). 종전 머리의 `[미이행 39개 부서 독촉]`은 없앤다(R-12의 일괄 독촉으로 바뀐다).
- 이 화면의 F5(«의무이행 점검표») 호출을 없앤다. 이미 상신된 F5 문서가 있으면 회신 반영만 남긴다(공통 §7-4 경로 5번 «걷음»).
- 걷은 일이 가는 곳(화면 안내에 쓰지 않아도 된다 — 정본 SCR-SBM-006 §6 «걷은 영역»):

| 걷은 영역 | 그 일을 하는 곳 |
|---|---|
| 안전보건관리체계 점검(반기) | 경영방침 반기 점검 · 정기 위험성평가 · 인력 평가 · 의견청취 |
| 매뉴얼·업무처리절차 점검 | 업무 관리 › 문서 목록 · 이행 관리 |
| 관계 법령 의무이행 점검 | 배포하는 이행점검표 양식 안의 점검 항목 |
| 안전보건 예산 편성·집행 | 인력·예산 › 예산 총괄표 |

- 카드 안 순서(위 → 아래): ① 축 탭 · 회차 선택 ② 안내 한 줄 ③ 회차 머리(R-07·R-08) ④ 부서 명단 갭 안내(전 부서 범위만) ⑤ 내가 하는 일 한 줄(R-02) ⑥ 지난 반기 미이행 요약(R-10, 전 부서 범위만) ⑦ 요약 칸(전 부서 범위만) ⑧ 일괄 독촉 버튼(R-12) ⑨ 부서 표.
- 안내 한 줄: «종사자 안전·보건 확보의무(중처법 §4·§5) 이행 여부를 부서·사업장 단위로 점검합니다. 재난안전과가 점검표를 배포하면 부서가 내려받아 작성해 결과를 제출하고, 재난안전과가 검토합니다.»(시민 축은 «§9·§11 공중이용시설 관리 부서»로 바꿔 쓴다)

### R-02 · 권한 — 화면과 서버 모두 (P1)

| 하는 일 | 누가 | 범위 |
|---|---|---|
| 결과 제출 · 제출 고치기 · 제출 취소 · 다시 제출 | 그 부서 **실무자 누구나**(지정 담당자로 좁히지 않는다) · 실무자 계정이 한 명도 없는 부서만 부서장 | **자기 부서 줄만.** 재난안전과 실무자도 재난안전과 줄만. **대리 제출 없음** |
| 검토(승인 · 반려 · 확인 취소) | 재난안전과 **담당자 · 팀장** | 전 부서. **본인이 제출한 줄은 본인이 검토하지 않는다** |
| 독촉 | 재난안전과(담당자 · 팀장 · 과장) · 그 부서장 | 미제출 · 반려 줄. **부서 담당자는 자기 부서 줄을 독촉하지 않는다**(자기 자신 — 부서 단위, 11-10 확정). 군수 없음 |
| 점검 배포 · 배포 수정 · 시달 공문 · 마감 보고 | 재난안전과 **담당자** | 회차 전체 |
| 조회 | 모두 | R-03 범위 |

- **서버에도 같은 판정을 건다** — 버튼을 숨기는 것만으로는 직접 호출로 뚫린다. 배포·검토·마감의 판정은 «부서 미지정 담당자 → 통과»가 아니라 **«재난안전과 소속 + 담당자 계층»** 이다(11-09 N2의 원인).
- **결과 제출을 지정 담당자로 좁히지 않는 이유** — 담당자는 부서마다 지정해야 하는데 39개 부서 명단이 담양군 확정 전이다. 좁히면 지정 전 부서는 아무도 결과를 낼 수 없어 점검이 멈춘다. 온나라 원본 잇기의 «담당자»를 실무자 계층으로 둔 것과 같은 근거다(10-30 개발 확인).
- **메뉴 권한** — 이행점검 메뉴는 **«전 직원 등록» 프로필**(의견청취와 같다 — 모든 직원 보기·수정)로 둔다. 일반 공무원 등급이 조회 전용이면 화면 판정을 넓혀도 실무자가 제출하지 못한다. 메뉴 수정이 열려도 배포·검토·독촉·마감은 위 표의 화면 판정이 막으므로 더 열리는 기능은 없다.
- 같은 부서 실무자끼리는 서로의 제출을 고치고 취소할 수 있다(줄이 부서당 하나다). 그래서 **고친 사람 · 취소한 사람**을 기록한다(R-09).
- 재난안전과 팀장은 제출·배포·마감을 하지 않는다. 재난안전과장은 조회 + 독촉만 한다. 군수는 조회만 한다.
- **표 위 «이 화면에서 내가 하는 일» 한 줄**(계정마다):

| 계정 | 문구 |
|---|---|
| 재난안전과 담당자 | «**우리 부서(재난안전과) 결과 제출**과 **전 부서 검토(승인·반려)·독촉**을 합니다. 점검 배포·마감 보고도 재난안전과 담당자 몫입니다.» |
| 재난안전과 팀장 | «**전 부서 검토(승인·반려)·독촉**을 합니다. 결과 제출·배포·마감은 담당자가 합니다.» |
| 재난안전과장 | «**조회**와 **전 부서 독촉**을 합니다. 결과 제출은 부서 실무자, 검토는 재난안전과 담당자·팀장이 합니다.» |
| 그 밖의 부서 실무자 | «**우리 부서 줄의 결과 제출**만 합니다(우리 부서 실무자 누구나). 검토는 재난안전과가 합니다.» |
| 실무자 계정이 없는 부서의 부서장 | «**우리 부서 결과 제출**과 **독촉**을 합니다 — 우리 부서에 실무자 계정이 없어 부서장이 냅니다.» |
| 그 밖의 부서장 | «**조회**와 **우리 부서 독촉**을 합니다. 결과 제출은 부서 실무자가 합니다.» |
| 군수 | «**조회 전용입니다.** 결과 제출은 각 부서 실무자, 검토는 재난안전과가 합니다.» |

- 권한 밖 직접 호출의 거절 문구는 §7.

### R-03 · 목록 조회 범위 (P1)

- 재난안전과(담당자 · 팀장 · 과장) · 군수 = **전 부서 줄**. 그 밖의 부서 담당자 · 부서장 = **우리 부서 줄만**.
- 범위가 좁으면 **요약 칸 · 부서 명단 갭 안내 · 지난 반기 미이행 요약 · 일괄 독촉 버튼을 내지 않는다**(한 줄을 보면서 «대상 11개 부서»를 읽게 하지 않는다).
- **서버 목록 조회도 같은 범위로 거른다.** 범위 밖 부서의 제출 파일 내려받기도 막는다.

| 상태 | 조건 | 부서 제출 | 회차 선택지 표시 |
|---|---|---|---|
| 배포 전 | 배포 기록 없음(«기안 중» 포함) | 불가 | «2026년 하반기 · 배포 전» |
| 진행 중 | 배포됨 · 기한 전 | 가능 | «… · 진행 중» |

- 마감 보고가 **반려·반송** 회신을 받으면 «진행 중 / 기한 경과»로 돌아간다(잠금 해제).
- 배포 기록 없이 결과만 있는 지난 회차(시스템 도입 전)는 «배포 기록 없음»으로 조회만 한다 — 배포 기록을 지어 만들지 않는다.
- 회차 선택지는 올해 하반기 · 상반기 · 전년 하반기 · 상반기 넷(지금과 같다). 딥링크 `?axis=industrial|citizen&period=YYYY-H1|H2` 를 받는다.

### R-05 · 부서 줄 상태 — 진행 × 결과 (P1)

| 진행 | 뜻 | 결과(제출한 줄만) |
|---|---|---|
| 대상 아님 | 이 회차 대상 부서가 아님 — **흐리게, 표 아래쪽, 분모 제외**, 칸에 «이 회차 점검 대상이 아닙니다» | — |
| 미제출 | 대상인데 제출 기록 없음(기한 지나면 칩 아래 «기한 경과») | — |
| 확인 대기 | 제출함 | 전 항목 이행 / 일부 미이행 / 해당없음 |
| 반려 | 재난안전과가 사유와 함께 돌려보냄(칩 아래 사유) | 〃 |
| 확인 완료 | 재난안전과 승인(칩 아래 «검토자 · 일시») | 〃 |

- **«미제출»은 저장 값이 아니라 «제출 기록 없음»이다.** 결과 코드는 셋(DONE 이행 · TODO 미이행 · NA 해당없음)이고, 손대지 않은 줄을 «미이행»으로 보이지 않는다.
- **검토는 결과와 별도 축이다** — 상태 `WAIT 대기 / OK 완료 / RETURNED 반려` · 검토자 · 일시 · 반려 사유 · 차수. 승인·반려가 결과 값을 바꾸지 않는다(결과가 틀렸으면 반려해서 부서가 고친다).
- 2차 이상 제출이면 진행 칩 아래 «N차 제출». 독촉 기록이 있으면 «독촉 N회 · 최근 YYYY-MM-DD»(미제출·반려 줄만).

**전이**

| 지금 | 행동(누가) | 다음 |
|---|---|---|
| 미제출 | 결과 제출(그 부서 실무자) | 확인 대기(차수 1) |
| 확인 대기 | 제출 고치기(그 부서 실무자) | 확인 대기 |
| 확인 대기 | 제출 취소(그 부서 실무자, 확인 창) | 미제출(제출 값은 지우고 «제출 취소 · 이름 · 날짜» 기록은 남긴다 — R-09) |
| 확인 대기 | 승인(재난안전과 담당자·팀장) | 확인 완료 |
| 확인 대기 | 반려(재난안전과 담당자·팀장, 사유 필수) | 반려 |
| 반려 | 다시 제출(그 부서 실무자) | 확인 대기(차수 +1, 이전 기록 보존) |
| 확인 완료 | 확인 취소(재난안전과 담당자·팀장, 사유 필수) | 확인 대기 |
| 아무 상태 | 마감 보고 보내기 | 잠금(전이 없음) |

### R-06 · 요약 칸 · 부서 표 · 관리 버튼 (P1)

**요약 칸**(전 부서 범위만) — 대상 N개 부서 · 제출 N개(제출률 %) · 확인 완료 · 확인 대기 · 반려 · 일부 미이행 · 미제출(기한 지나면 «· 기한 경과»). **이행률은 내지 않는다**(자기 신고라 개수로만). 분모 = 대상 부서(대상 아님 제외).

**부서 표 열**

| 열 | 내용 |
|---|---|
| 부서·사업장 | 부서명 + 인원 |
| 진행 | 진행 칩 + (반려) 사유 · (확인 완료) 검토자·일시 · N차 제출 · 독촉 N회 · 기한 경과 |
| 점검 결과 | 결과 칩 + (일부 미이행) «미이행: …» «조치계획: …(예정 YYYY-MM-DD)» · (해당없음) «사유: …» · 비고 · (지난 반기 미이행 부서) R-10 줄 |
| 제출일 | 제출일 + «지연 제출»(기한 뒤 제출) + 제출자 |
| 작성한 점검표 | `[⬇ 파일명]`(여러 개면 각각) |
| 관리 | 아래 버튼 — 없으면 «조회», 잠긴 회차는 «잠김» |

- 정렬: 대상 부서를 위에, 대상 아님을 아래에.

**관리 칸 버튼 — 조건이 맞을 때만 낸다**

| 버튼 | 보이는 줄 | 보이는 사람 |
|---|---|---|
| `[결과 제출]` | 미제출 | 그 부서 실무자 |

### R-07 · 점검 배포 (P1)

**회차 머리 — 상태별**

| 회차 상태 | 재난안전과 담당자 | 그 밖 |
|---|---|---|
| 배포 전 | 칩 «배포 전» · «YYYY 상/하반기 ○○재해 이행점검» · `[점검 배포]` · «점검표 양식 · 안내 · 기한 · 대상 부서를 정하고 시달 공문을 온나라로 보내면 배포됩니다.» · 표 자리 «이 회차는 아직 배포하지 않았습니다. 위 [점검 배포]에서 점검표·기한·대상을 정하고 시달 공문을 온나라로 보내면 대상 부서에 할 일이 갑니다.» | 칩 «배포 전» · 표 자리 «재난안전과가 점검표를 배포하면 이 표에서 우리 부서 결과를 제출합니다.» · 제출 버튼 없음 |
| 기안 중(공문 보내기 전) | 칩 «시달 공문 기안 중» · «기한 · 대상 N개 부서» · «아직 배포되지 않았습니다 — 시달 공문을 온나라로 보내는 순간 대상 부서에 할 일·알림이 가고, 공문은 온나라 결재 후 각 부서로 시행됩니다.» · `[공문 기안 이어 하기]` `[기안 버리기]` | «배포 전»과 같다 |
| 진행 중 · 기한 경과 · 마감 보고됨 | 상태 칩 · «배포 YYYY-MM-DD · 기한 YYYY-MM-DD (D-n/D+n) · 대상 N개 부서» · 안내 · 시달 공문 줄(R-08) · 양식 `[⬇ 파일명]` · «제N판» · `[배포 내용 고치기]`(마감 보고됨이면 없음) | 같은 정보 · `[배포 내용 고치기]` 없음 · 시달 공문 줄은 «결재 진행은 온나라에서 확인합니다» |

**`[점검 배포]` 창**

| 항목 | 필수 | 기본값 | 규칙 · 오류 |
|---|:--:|---|---|
| 점검 양식 | 예(1개 이상) | — · `[지난 회차 양식 이어받기 (파일명)]` 버튼 제공 | 공용 업로드 칸(일반 12종 · 20MB · 10개). 없으면 «부서가 내려받을 점검표를 올려 주세요.» |
| 안내 | 아니오 | 지난 회차 안내 | 부서 회차 머리·제출 창 머리에 그대로 |
| 제출 기한 | 예 | 반기 말일(06-30 · 12-31) | 없으면 «제출 기한을 정하세요.» · 처음 배포는 오늘 이후 — «기한은 오늘 이후로 정하세요.» |

- **시민 축 기본값의 이름 불일치** — 시설물 대장의 관리부서 이름이 조직도와 다르면 그 부서는 기본값에서 빠진다. 배포 창 대상 부서 아래에 «시설물 대장 관리부서 중 조직도에서 찾지 못한 이름 N개(…) — 대상에 넣을 부서를 직접 고르세요»를 보여 담당자가 빠진 부서를 알아채게 한다.
- 버튼 `[취소]` · **`[공문 기안 →]`**, 버튼 옆 안내 «다음 단계에서 각 부서에 보낼 시달 공문(제목·본문)을 작성해 온나라로 보냅니다. 보내는 순간 배포됩니다.»
- `[공문 기안 →]`을 누르면 배포 내용은 **«기안 중»으로만 저장**되고 부서에는 아무것도 가지 않는다 → 시달 공문 기안 창(R-08)이 열린다.
- `[기안 버리기]` → «기안 중이던 배포를 버렸습니다 — 아무 데도 보내지 않았습니다» · 회차 «배포 전».
- `[공문 기안 이어 하기]` → 같은 배포 내용으로 기안 창을 다시 연다.

**`[배포 내용 고치기]`**(시달 공문을 보낸 뒤, 마감 보고 전)

| 항목 | 규칙 |
|---|---|
| 양식 | 교체하면 **판 번호 +1**, 이전 판 보존. 이미 제출한 부서는 그대로(제출 기록에 낸 판 번호). 창 안내 «양식을 바꾸면 판 번호가 올라갑니다. 이미 제출한 부서의 제출은 그대로 둡니다.» · 저장 토스트 «배포 내용을 고쳤습니다 — 양식 제N판» |
| 기한 | **늘리기만** — 앞당기면 «기한은 늘릴 수만 있습니다.» · 늘리면 미제출 대상에 «기한 변경» 알림(R-14) |
| 대상 추가 | 가능 — 그 부서에 할 일·«배포» 알림 |
| 대상 제외 | **제출하지 않은 부서만** — 제출한 부서를 빼면 «이미 제출한 부서는 대상에서 뺄 수 없습니다.» 창 안내 «이미 제출한 부서는 뺄 수 없습니다.» |

- 배포 내용을 고쳐도 변경 공문은 다시 보내지 않는다 — 바뀐 내용은 알림(기한 변경 · 대상 추가 배포)으로 알린다.

### R-08 · 시달 공문 — 언제 온나라로 가고 모든 부서에 어떻게 가나 (P1 · ⚠ 핵심)

> 운영 결정(2026-11-06) **«이 시스템은 온나라로 기안까지만 보낸다 — 검토·결재는 담당자가 온나라 기안함에서 지정해 상신한다»** 를 그대로 따른다. **결재선이 없다.** 공통 §7-4 상신 경로 **14번**(축·반기 단위 · 수동 기록 없음 · 반려·반송이면 배포 유지·다시 보내기).

**(1) 타이밍**

| 시점 | 누가 · 어디서 | 시스템 | 온나라 | 부서가 받는 것 |
|---|---|---|---|---|
| T0 배포 입력 | 재난안전과 담당자 · `[점검 배포]` | «기안 중» 저장 | — | — |
| T1 공문 작성 | 같은 사람 · `[공문 기안 →]` → 작성 → 미리보기 | 미리보기만 | — | — |
| **T2 `[온나라로 보내기]`** ★ | 같은 사람 · 확인 `[보내기]` | 호출기안 1건 전송 → **성공 응답(연계 번호) 순간 배포 확정**: 배포일 = 보낸 날 · 판 1 · 회차 «진행 중» · 대상 부서 할 일(카드 8)·알림 · 시달 공문 «기안함 전송» | 담당자 **연계기안함**에 기안문(상신 전) | **시스템 알림 · 내 할일** — 바로 점검표를 내려받아 시작 |
| T3 온나라 상신 | 재난안전과 담당자 · 온나라 | 문서조회로 «결재중» | 검토·결재 지정 · 상신 | — |
| T4 결재 완료 | 결재권자 · 온나라 | «결재완료» · 생산등록번호(조회로 안 오면 «문서번호 미기재») | **수신 부서 전부로 시행** | 온나라 공문 접수 |

- **T2 실패**(연계 오류 · 응답 없음) — **배포하지 않는다.** «기안 중» 그대로, 회차 머리에 «온나라로 보내지 못했습니다 — 다시 보내기». 반쯤 배포된 상태(할 일은 생겼는데 공문은 안 간 상태)를 만들지 않는다.
- **반송**(연계기안함에서 상신하지 않고 지움 · 닫음) · **반려**(결재 반려) — **배포는 유지**(부서는 이미 작업 중). 회차 머리에 «시달 공문 반송/반려 — 사유» + `[시달 공문 다시 보내기]`(같은 회차, 같은 기안 창, 이전 기록 보존). 사람이 결재 결과를 옮겨 적는 수단은 두지 않는다.
- 부서는 시스템 알림(T2)과 온나라 공문(T4)을 따로 받는다 — 결재 기간만큼 시차가 있다.

**(2) 공문 1건 · 수신처 여러 곳**

| 항목 | 값 |
|---|---|
| 건수 | **회차 × 축마다 1건.** 부서마다 따로 기안하지 않는다 |
| 문서 종류 | 시행문(외부발송 서식 — 수신 · 발신명의 담양군수 · 수신자 행). 화면에서 바꾸지 않는다 |
| 수신 | «수신자 참조» |
| 수신처 | **기본값 = 배포 대상 부서 전부.** 기안 창 `[조직도에서 수신처 고르기]`(공용 부서 트리 · 검색 · 다중 선택, 창 안에 펼침 · `[조직도 접기]`) · `[기본값으로]`. 1곳 이상 필수(«수신처를 1곳 이상 고르세요.» — 미리보기·보내기 둘 다 막음). 지면 표기는 부서장 직위(«○○과장 · ○○사업소장 · ○○읍장»), 연계로는 **부서(처리과) 단위 수신처 목록**. 재난안전과도 대상이면 수신처에 든다 |
| 수신처 ≠ 배포 대상 | 서로 바꾸지 않는다(수신처 = 공문, 배포 대상 = 시스템 할 일). 갈리면 수신 요약 아래 바로 «공문을 받지 않는 점검 대상 N곳(부서…) — 시스템 할 일·알림만 받습니다» / «점검 대상이 아닌 수신처 N곳(부서…) — 공문만 받고 결과 제출 대상은 아닙니다». 보내기는 막지 않는다. 저장: 공문의 수신처 목록은 배포 대상과 따로 |
| 수신처 코드 | 조직도 부서 ↔ 온나라 부서 코드. 코드 없는 부서가 있으면 미리보기 «온나라 수신처 미확인 N곳 — 이 부서는 시스템 알림·할 일로만 받습니다»(보내기는 막지 않음) |
| 제목 | 기본 «YYYY년 상/하반기 중대(산업·시민)재해 이행사항 자체점검 실시 통보» — 고칠 수 있음(필수) |
| 본문 | **직접 작성**(필수, 자동 생성 없음). 삽입 조각 4개 — `＋ 실시 안내` · `＋ 점검 개요`(대상 수 · 기한 · 제출 방법) · `＋ 미이행 작성 안내` · `＋ 배포 안내 문구`(배포 창 안내) |
| 붙임(고정) | ① 배포한 점검표 양식(같은 파일 — 두 번 받지 않는다) ② 별지 «점검 대상 부서»(연번 · 부서 · 시스템 알림 받는 사람) PDF. 표시 «붙임 n / 5개 · 합계 n / 30MB» · 한도 5개 · 파일당 10MB · 합계 30MB — 넘으면 보내기 전 차단 |
| 결재선 · 문서 종류 · 관련 근거 | **받지 않는다** |
| 공개구분 | 연계 기본값 «공개» |
| 권한 | 재난안전과 담당자 — 작성 · 미리보기 · 확인 · 보내기 네 경로 모두(서버 포함) |

**(3) 화면**

1. **기안 창**(제목 «공문 기안 — {제목}») — 수신(«기본값은 이 회차 점검 대상 부서 전부입니다» · «수신자 참조 — N곳 부서장…» · 조직도 · 기본값으로 · 불일치 안내) · 제목 · 본문(«직접 작성합니다 — 아래 조각을 눌러 넣을 수 있습니다» + 조각) · 붙임(고정 목록 + 한도). 하단 «검토·결재는 온나라 기안함에서 지정합니다.» 버튼 `[닫기]` `[문서 미리보기 →]`.
2. **미리보기**(제목 «문서 미리보기 — {제목}», 넓은 창) — 표준 공문 지면: 기관명 · 수신 «수신자 참조» · 제목 · 본문 · 붙임 + «끝.» · 발신명의 · **수신자** 행(부서장 목록) · 서명란 «기안자 {직위 이름}» + «검토·결재 — 온나라 기안함에서 지정» · 시행 «(온나라에서 부여)» + 별지 «[붙임 n] 점검 대상 부서». 버튼 `[PDF 저장 / 인쇄]`(머리) · `[← 수정]` `[온나라로 보내기]`.
3. **확인 창**(제목 «온나라로 보내면 되돌릴 수 없습니다») — «보내는 순간 대상 부서에 점검이 배포됩니다(할 일·알림). 배포를 취소할 수 없습니다.» · «공문은 온나라 연계기안함에 들어갑니다. 검토·결재를 지정해 상신하는 것은 온나라에서 합니다.» 버튼 `[← 미리보기]` `[보내기]`.
4. **결과 창**(제목 «온나라 기안함에 보냈습니다») — R-17의 **라벨–값 한 모양**: 맨 위 «시달 공문을 온나라 연계기안함에 보냈고, 대상 부서에 점검이 배포되었습니다.» · 상태 [기안함 전송] · 문서 {제목} · 연계 번호 {값}(아래 회색 «문서번호는 결재가 끝나면 온나라가 부여합니다.») · 붙임 {파일 · 점검 대상 부서} · 다음 할 일 «온나라 기안함에서 검토·결재를 지정해 상신하세요.»(아래 회색 «결재가 끝나면 온나라가 수신 부서로 시행합니다.»). 버튼 `[확인]`.
5. **회차 머리 시달 공문 줄** — «시달 공문 [기안함 전송 / 결재중 / 결재완료 / 반려 / 반송] YYYY-MM-DD 보냄 · 연계 번호 {값} · [공문 보기]». «기안함 전송»이면 재난안전과 담당자에게 «온나라 기안함에서 검토·결재를 지정해 상신하세요 — 결재가 끝나면 각 부서로 시행됩니다»를 **상시** 보인다(보내 놓고 상신을 잊는 것을 막는다). 결재완료면 생산등록번호를 함께. 반려·반송이면 사유 + `[시달 공문 다시 보내기]`.
6. 배포 기록이 있는데 시달 공문이 없는 지난 회차 — «시달 공문 기록 없음(시스템 도입 전 배포)».

- 저장: 제출일 · 제출자(실제 접속자) · 양식 판 · 검토 상태 «대기» · 차수. 다시 제출이면 차수 +1, **이전 차수 제출을 보존**.
- **고친 사람 · 취소한 사람을 남긴다** — `[제출 고치기]`는 처음 제출자·제출일을 그대로 두고 «고침 · 이름 · 날짜»를 따로 남겨 제출일 칸에 보인다. `[제출 취소]`는 «제출 취소 · 이름 · 날짜»를 회차 × 부서 기록에 남겨 미제출 줄 제출일 칸에 보인다. 같은 부서 다른 실무자가 한 일도 누가 했는지 알 수 있어야 한다.
- 제출하면 → 줄 «확인 대기» · 그 부서 카드 8 완료(결과 무관) · 재난안전과 «검토 요청» 알림(R-14).
- 기한 뒤 제출 — 받고 «지연 제출».
- 확인 대기 중 — 그 부서 실무자만 `[제출 고치기]`(같은 창, 값 채워진 채) · `[제출 취소]`(확인 창 → «제출을 취소했습니다.», 미제출로).
- 확인 완료 줄 고치기 — «재난안전과가 확인한 결과입니다 — 고치려면 재난안전과에 확인 취소를 요청하세요.»
- 배포 전 · 대상 아님 · 잠김 — «아직 배포되지 않은 회차입니다 — 재난안전과가 점검표를 배포하면 제출합니다.» / «이 회차 점검 대상 부서가 아닙니다.» / «이 회차는 마감 보고를 보내 잠겼습니다.»

### R-10 · 지난 반기 미이행 조치 결과 (P2 — 운영 첫 회차에는 대상 없음)

### R-11 · 검토 (P1)

- 확인 대기 줄 `[검토]` → 창(제목 «제출 검토 — {부서}»): 점검 결과 · (일부 미이행) 미이행 내용·조치계획·예정일 · (해당없음) 사유 · (지난 반기) 조치 결과 · **작성한 점검표 `[⬇ 파일명]`** · «배포한 양식: {파일} (제N판) — 위 회차 머리에서 내려받습니다» · 제출 «YYYY-MM-DD · 제출자» · 반려 사유 입력칸(«반려할 때 필수 — 부서 담당자에게 알림으로 갑니다»). 버튼 `[닫기]` `[반려]` `[승인]`.
- `[승인]` → 확인 완료(검토자 · 일시) · «{부서} 승인 — 확인 완료» · **알림 없음**.
- `[반려]` → 사유 필수 «반려 사유를 적어 주세요 — 부서가 무엇을 고칠지 알아야 합니다.» → 줄 «반려 + 사유» · 제출한 사람(+ 지정 담당자)에게 알림(R-14) · 카드 8 «다시 제출하러 가기» · «{부서} 반려 — 제출한 사람에게 알림을 보냈습니다».
- 확인 완료 줄 `[확인 취소]` → 창 «확인을 풀면 확인 대기로 돌아가고 부서가 제출을 고칠 수 있습니다.» · 사유 필수 «확인을 취소하는 이유를 적어 주세요.» → 확인 대기 · 확인 취소 기록(누가 · 언제 · 사유).
- 본인이 제출했거나 고친 줄은 창을 열어도 막는다 — «본인이 제출한 결과는 재난안전과의 다른 담당자나 팀장이 검토합니다.»
- 표 «작성한 점검표» 칸에서도 내려받는다(범위 안 계정).

### R-12 · 독촉 (P2)

- **줄 `[독촉]`** — 미제출 · 반려 후 미재제출 줄에만(확인 대기 · 확인 완료 · 대상 아님에는 없음). 버튼에 **받는 사람**을 밝힌다(마우스를 올리면 «받는 사람 {이름}»). 종류: 미제출 «결과 제출 독촉» · 반려 «반려 재제출 독촉». 토스트 «{부서} 결과 제출 독촉 · 받는 사람 {…}».
- **일괄 `[미제출 N개 부서 독촉]`**(표 위 오른쪽) — 미제출 부서가 **2곳 이상**이고 독촉할 수 있는 계정·전 부서 범위일 때. **반려 줄은 세지 않는다**(사유가 달라 줄에서 따로). 누르면 확인 창(제목 «미제출 N개 부서 결과 제출 독촉»): «아래 부서에 «결과 제출 독촉» 알림을 보내고 회차 기록에 남깁니다.» + 표(부서 · 받는 사람 · 이전 독촉 횟수) → `[취소]` `[N개 부서 독촉]` → «N개 부서에 결과 제출 독촉을 보냈습니다».
- **받는 사람** — 그 부서 지정 담당자(조직 관리 › 부서 상세) → 없으면 부서장(«부서장 ○○○(담당자 미지정 — 대신 받음)») → 없으면 «받는 사람 없음(담당자·부서장 미등록)»(그래도 기록은 남긴다).
- **보낸 기록** — 회차 × 축 × 부서: 일시 · 보낸 사람(실제 접속자 — 고정 문자열 금지) · 받는 사람 · 종류. 줄에 «독촉 N회 · 최근 YYYY-MM-DD», 마감 보고 미제출 목록에 «(독촉 N회)».
- 독촉마다 그 부서에 **헤더 알림**(R-14).
- 거절 — 배포 전 «아직 배포되지 않은 회차입니다.» · 잠김 «이 회차는 마감 보고를 보내 잠겼습니다.» · 확인 대기/완료 «미제출·반려된 부서에만 독촉합니다.» · 부서 담당자가 자기 부서 «우리 부서 독촉은 부서장과 재난안전과가 합니다 — 담당자 자신에게는 보내지 않습니다.» · 군수 «독촉은 주관부서(재난안전과)와 그 부서가 합니다 — 총괄 책임자는 진행 상황을 조회합니다.»

### R-13 · 반기 마감 · 군수 보고 (P1)

**마감 보고 차례**(P2 — 판정 한 곳, 화면·내 할일 공용)
- 조건: 그 회차에 배포한 축이 있고, **배포한 축 전부가 «대상 전부 확인 완료» 또는 «기한 경과»**, 아직 보내지 않았다.
- 표시: 카드 머리 `[반기 마감 · 군수 보고]` 옆 칩 «전 부서 확인 완료 — 마감 보고 차례» / «기한 경과 — 마감 보고 차례» + 버튼을 주 버튼(채운 색)으로. 재난안전과 담당자 내 할일 카드 10.

**보내기**
- 조건은 **배포한 축이 있는 회차** 하나 — 없으면 «배포한 점검이 없는 회차입니다 — 점검표를 먼저 배포하세요.» 미제출·확인 대기가 남아도 막지 않는다(전 부서 제출을 걸면 보고가 갇힌다 — 실측상 전 부서 제출이 성립한 해가 없다).
- `[반기 마감 · 군수 보고]` → **문서 미리보기**(제목 «YYYY 상/하반기 의무이행 점검 마감 보고 — 문서 미리보기», 넓은 창). 위 안내 «군수께 올라갈 보고 내용입니다. [온나라로 보내기]를 누르면 온나라 기안함으로 가고 이 회차는 잠깁니다. 검토·결재는 온나라에서 지정합니다.» + «확인되지 않은 줄 N건은 «미확인»·«반려»로 그대로 올라갑니다.» 버튼 `[취소]` `[온나라로 보내기]`.
- **지면**(축마다 반복 — 배포 안 한 축은 «배포하지 않았습니다»):
  1. 제목 «YYYY 상/하반기 중대재해 예방을 위한 안전·보건 확보의무 이행점검 결과 보고»
  2. 축 이름 + «배포 · 기한 · 양식 제N판 · 대상 · 제출 · 확인 완료 · 전 항목 이행 · 일부 미이행 · 해당없음 · 미제출»
  3. 부서별 표(대상만): 부서 · 진행(확인 완료 / 미확인 / 반려 / 미제출) · 결과 · 해당없음 사유 · 제출일(«(지연)»)
  4. «일부 미이행 사항과 조치계획»: 부서 · 미이행 내용 · 조치계획 · 예정일
  5. «지난 반기 미이행 조치 결과 (m / N곳 조치 완료)»: 부서 · 지난 반기 미이행 · 조치계획(예정일) · 조치 결과 — 해당 부서가 있을 때만
  6. «미제출 부서»: «회계과 (독촉 2회) · 재무과 · …»
- **지면은 PDF로 만들어 붙임 1로 보내고, 본문은 «붙임 문서를 결재 요청합니다.» 한 줄이다** — 온나라 연계 본문은 글자만 받아(규격 «텍스트 형태의 본문 정보») 부서별 표를 본문에 실을 수 없다(10-07 회신 2-2 · O-5, 2026-11-12 개발 회신). 지면 내용은 위 1~6 그대로. 반려·반송 뒤 다시 보낼 때는 PDF를 새로 만든다. 부서별 점검표 파일은 붙이지 않는다(시스템에서 조회). 공개구분 «공개».
- `[온나라로 보내기]` → 확인 «보내는 순간 YYYY 상/하반기 이행점검(두 축)이 잠깁니다 — 제출·검토·배포 수정이 모두 막힙니다» → `[← 미리보기]` `[보내기]` → 결과 창(R-17 한 모양: «마감 보고 공문을 온나라 연계기안함에 보냈고, YYYY 상/하반기 이행점검을 잠갔습니다.» · 상태 [기안함 전송] · 문서 · 연계 번호(+회색 «문서번호는 결재가 끝나면 온나라가 부여합니다.») · 다음 할 일 «온나라 기안함에서 검토·결재를 지정해 상신하세요.»(+회색 «온나라에서 반려·반송되면 이 회차가 다시 열립니다.»)).
- **결재선 없음** · 수동 기록 없음(공통 §7-4 10번).

**잠금**
- 보내는 순간 회차(두 축) 잠금 — **상태 «기안함 전송»부터** 잠금으로 본다(결재중 · 결재완료도). 잠금 판정은 **한 곳**에서 하고 이행점검 화면 · 회차 선택지 · 내 할일이 같은 판정을 쓴다.
- 잠기면: 제출 · 고치기 · 취소 · 검토 · 확인 취소 · 배포 수정 · 독촉 · 다시 보내기 모두 막힌다(서버 포함). 버튼 자리 «잠김». 표 위 «**이 회차는 마감 보고를 온나라로 보냈습니다(기안함 전송).** 보낸 그대로 잠겨 제출·검토·독촉을 바꿀 수 없습니다. 온나라에서 반려·반송되면 다시 열립니다.» 카드 머리 «마감 보고 기안함 전송 · 연계 번호 · 이 회차는 잠겼습니다 · 온나라 기안함에서 상신하세요».
- 거절 문구 — 다시 보내기 «YYYY 상/하반기 마감 보고는 이미 온나라로 보냈습니다.» · 배포 수정 «마감 보고된 회차는 바꿀 수 없습니다.»
- 반려 · 반송 회신 → 잠금 해제 · 새 기록으로 다시 보낸다(이전 기록 보존).
- 보낸 기록은 **회차별로 서버에 저장**한다(화면 메모리에 두면 새로고침 뒤 같은 회차를 또 올린다).

| 이행점검 제출 검토 요청 | 제출 · 다시 제출 즉시 | 재난안전과 담당자 · 팀장 | «{부서} YYYY 상/하반기 ○○재해 의무이행 점검 결과 제출 — 검토 요청» |
| 이행점검 결과 반려 | 반려 즉시 | **실제로 제출한 사람**(고친 사람이 있으면 그 사람도) + 지정 담당자 | «YYYY 상/하반기 ○○재해 의무이행 점검 결과 반려 — {사유}» |
| 이행점검 결과 제출 독촉 | 보낼 때 | 그 부서 지정 담당자(없으면 부서장 — 공통 규칙) | «… 의무이행 자체점검 결과 제출 독촉 — 결과를 제출해 주세요(기한 …)» / «… 반려 재제출 독촉 — 반려된 결과를 고쳐 다시 제출해 주세요» |

- **받는 사람 = 할 수 있는 사람** — 결과를 낼 수 있는 사람은 그 부서 실무자 누구나다(R-02). 배포·기한 변경 알림을 «지정 담당자, 없으면 부서장»에게 보내면 지정 전 부서에서는 **제출할 수 없는 부서장에게만** 가고 실제로 낼 실무자는 모른다. 그래서 지정 담당자가 없으면 실무자 전원에게 보낸다. 반려 알림은 무엇을 고칠지 아는 **제출한 사람**에게 간다.
- **독촉은 공통 규칙 그대로** — 독촉 받는 사람(지정 담당자 → 없으면 부서장)은 위험성평가·교육·경영방침 독촉과 같은 공통 규칙이다. 독촉은 «누가 좀 내라»는 지휘 신호라 부서장에게 가도 말이 된다(부서장이 실무자에게 맡긴다). 이것만 이행점검에서 바꾸면 업무마다 독촉 받는 사람이 갈린다.
- 승인은 알리지 않는다. 종전 «이행점검 미이행 재촉»은 «결과 제출 독촉»으로 바꾼다.
- 알림을 누르면 내 할일, «해당 화면 바로 열기»는 이행점검(그 축·회차 딥링크). 근거 칩 중처법 시행령 §5.
- 반려 사유는 사람이 쓴 글이라 **이스케이프해서** 넣는다(HTML 그대로 넣지 않는다).
- «검토 요청»은 재난안전과 **담당자·팀장**에게만 — 과장은 받지 않는다(사람 단위로 정한다).
- 시스템 관리 › 알림 관리 규칙 표에 5행(이벤트 · 시점 · 받는 사람 · 채널). 문자·메일 실발송은 알림 연계 몫.

- 카드 8 기한 = 배포 기한(D-day). 카드 9·10은 기한 없음.
- 날짜로 자동 생기는 이행점검 카드(종전 발행 업무)는 쓰지 않는다 — 카드는 **배포 기록에서** 만든다(양식·기한·대상 없이 빈 할 일을 내지 않는다).
- 옛 고정 예시 «의무이행 점검표 반기 마감 — 점검표 작성»류 카드·알림이 운영에 있다면 걷는다(걷은 F5 영역으로 보낸다).

### R-16 · 경영방침 게시 현황 «미등록» 분리 (P2)

- 같은 부서 표를 쓰는 경영방침 › 게시 현황도 **«미등록(기록 없음) / 게시 / 미게시 / 해당없음»** 넷으로 보인다. «미등록»은 저장 값이 아니라 기록 없음이다. 배포·검토 흐름은 이행점검에만 있다(게시 현황은 전수 표 그대로).

### R-18 · 기존 데이터 (P1)

- 운영은 네 회차 모두 등록 0건이다(11-12 관찰) — **옮길 데이터가 없다.** 이미 지난 회차는 «배포 기록 없음»으로 조회만 한다.

## 5. 온나라 연계 요구

두 가지 호출기안이 생긴다. 둘 다 **결재선 없이 연계기안함까지**다(운영 결정 2026-11-06).

| | 시달 공문(R-08) | 마감 보고(R-13) |
|---|---|---|
| 상신 경로(공통 §7-4) | 14번 | 10번 |
| 단위 | 축 × 회차 1건 | 회차 1건(두 축) |
| 보낼 값 | 기안자 계정 · 제목 · 본문 · **수신처 목록(부서 코드)** · 붙임(양식 + 별지 PDF) · 공개구분 «공개» · 문서 종류 시행문 | 기안자 계정 · 제목 · 본문 한 줄(«붙임 문서를 결재 요청합니다.») · 수신 내부결재 · 공개구분 «공개» · **붙임 1 = 마감 보고 지면 PDF** |
| 성공 응답 | 연계 번호 → **배포 확정**(배포일 · 할 일 · 알림) | 연계 번호 → **회차 잠금** |
| 실패 | 배포하지 않음 · «기안 중» 유지 · 다시 보내기 | 잠그지 않음 · «온나라로 보내지 못했습니다 — 다시 보내기» |
| 문서조회 상태 | 기안함 전송 → 결재중 → 결재완료(생산등록번호) / 반려(사유) / 반송(사유) | 같다 |
| 반려 · 반송이면 | 배포 유지 · `[시달 공문 다시 보내기]` | 잠금 해제 · 다시 보내기 |
| 수동 기록 | 없음 | 없음 |

- **연계 번호 ≠ 문서번호** — 화면에 «연계 번호»로 보이고, 결재완료 뒤 온 생산등록번호를 «문서번호»로 따로 보인다.
- **수신처 코드** — 조직도 부서 ↔ 온나라 부서 코드 대응을 조직도 연계 값으로 만든다. 코드 없는 부서는 공문 수신처에서 빠지고 시스템 알림·할 일만 받는다(미리보기에 밝힘).
- **붙임 한도** — 5개 · 파일당 10MB · 합계 30MB(온나라 확인 전 설정값). 고르는 단계·보내기 전 검사, 넘는 파일을 조용히 빼고 보내지 않는다.
- 별지는 **PDF로 만들어** 붙인다(시행규칙 §4④ — 붙임으로 적은 것은 실제 파일로 나간다).
- **결재선은 기안자 한 줄이다**(11-06 운영 결정 · 개발 합의). 온나라가 기안자 한 줄을 거절하면 **보내는 방식은 그 결과를 보고 함께 정한다**(2026-11-12 개발 2차 회신 — 대체 방식을 미리 박지 않는다). 그 사이에도 «보내기 실패 → 배포하지 않음 · 잠그지 않음 · 다시 보내기» 규칙은 그대로다.
- **운영 전 시험 (MUST)** — 교육 연습 공문으로 다음을 확인하고 결과를 기획에 알린다. **하반기 시달 공문을 보내기 전에** 끝낸다(시달 날에 처음 거절이 드러나면 배포가 그 자리에서 멈춘다).
  1. 기안자 한 줄로 연계기안함에 들어가는가
  2. 기안함에서 상신 → 결재완료 회신(생산등록번호 · 결재일)이 돌아오는가
  3. **반려 · 반송 회신이 돌아와 수신 모듈이 상태를 바꾸는가**
- **3이 안 되면 마감 보고 회차가 영구히 잠긴다** — 이행점검은 수동 기록이 없는 축이라 잠금은 반려·반송 회신으로만 풀린다. 시달 공문도 «기안함 전송» 안내가 계속 남고 `[시달 공문 다시 보내기]`가 뜨지 않는다. 그 경우 복구 방식(예: 문서조회로 상태를 다시 읽기)을 기획과 함께 정한다. 사람이 상태를 옮겨 적는 수단은 두지 않는다.
