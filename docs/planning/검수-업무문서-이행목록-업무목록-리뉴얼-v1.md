**변환 중 보고된 차이 2건 (§9-3이 요구한 보고)**

1. **미분류 원본 35행 → 엔터티 34건.** 1행이 미분류이면서 동시에 완전중복이라 제거됐다. 두 수치는 서로 다른 것을 세며 둘 다 참이다.
2. **근사 중복 4건(2쌍).** 제목 안 이중 공백만 다른 별개 엔터티(`2025년 찾아가는 안전체험교실␣␣현장근무자…`). §9-2 3의 "공백 정규화"를 제목 내부까지 적용하면 문서가 3,828건이 되어 검증값이 깨진다. **동일성 판정은 strip 만** 하고 근사 중복은 `DOCS[].nearDup` 플래그로 남겨 **FT-09 중복 교정의 실제 재료**로 썼다 — 중복을 지어낼 필요가 없어졌다.

**2025 진행상태 파생의 정합성** — `취합상태` 투영이 임의값이 아님이 데이터로 확인된다.

| | 건수 | 대조 |
|---|--:|---|
| 확인됨 → 완료 | 119 | +보완필요 16 = **135** = 2025 문서 확인 단계 |
| 보완필요 → 진행중 | 16 | 〃 |
| 취합대상 → 미이행 | 26 | +조건부 7 = **33** = 2025 문서 없는 단계 |
| 조건부 → 해당없음 | 7 | 〃 |

**런타임 재확인** — 브라우저에서 `DYDOCT`/`DYDOCH` 로드 후 78 / 168 / 3,830 / 210 / 11 / 34(엔터티) / 33 / 주기보유 47 / 미보유 31 / `stageIds` 합계 168 전부 일치.

## 8. 사용성 개선 (3차 — 간소화·직관화)

기획(정의서 §6 정책)은 그대로 두고 **표현과 조작 방식만** 고쳤다. 기준은 Data-Dense Dashboard 원칙(최소 패딩·공간 효율·스캔 가능, 장식 금지)이고, 색·폰트는 담양군 기존 토큰을 그대로 쓴다.

### 8-1. 많은 선택지 → 2단 트리 (채용 사이트 패턴)

법정 의무 78가지·할 일 168개를 드롭다운과 78개 아코디언으로 고르게 하고 있었다. 사람인·잡코리아의 직무 선택 구조로 바꿨다 — **좌 대분류 / 우 소분류, 칸마다 따로 스크롤, 칸 위에 인라인 검색창, 아래에 고른 것 칩.**

| | 전 | 후 |
|---|---|---|
| 업무 목록 상세 조건 | 78개 드롭다운 + 종속 드롭다운 | 2단 트리 (칸별 검색) |
| 업무 업로드 2단계 | 78개 아코디언 + 조건 3개 | 같은 2단 트리 |
| 학습 비용 | 화면마다 다른 모양 | **하나만 배우면 된다** |

두 화면이 **같은 선택기**를 공유한다. 선택값은 각 화면이 들고 있고 선택기는 그리기만 한다.

### 8-2. 조건 벽 허물기

상세 조건 15개를 한 번에 늘어놓던 것을 **세 겹**으로 나눴다 — ① 2단 트리(의무·할 일) ② 자주 쓰는 6개 상시 노출 ③ 그 밖의 8개는 접음. 접힌 조건에 값이 걸리면 **자동으로 펼치고** 걸린 개수를 단추에 적는다(숨은 조건 때문에 결과가 이상해 보이는 일을 막는다).

### 8-3. 설계 용어 → 담당자 말

| 전 | 후 |
|---|---|
| 증빙 문서 축 / 원자료 취합상태에서 파생 | (삭제 — 정의서에만) |
| 업무단계 · 연결 문서 0건 | **할 일** · **서류 없음** |

### 8-4. 군더더기 제거

| 항목 | 전 | 후 |
|---|--:|--:|
| 이행 목록 안내 | 333자 · 124px | **157자 · 48px** |
| 이행 목록 첫 카드까지 | 548px | **472px** |
| 업무 목록 표 | 10열(220px 가림) | **8열(가림 0)** |

### 8-5. 그 과정에서 발견한 것

- **마법사 CSS가 통째로 빠져 있었다** — `du-*` 규칙이 하나도 없어 단계 표시·입력 격자·파일 목록·중복 경고·프리셋 일괄 막대가 전부 브라우저 기본 스타일로 렌더되고 있었다. 채워 넣었다.
- **트리가 든 창이 500px 라 칸이 205px 로 눌렸다** — 긴 할 일 이름이 네 줄로 접혔다. 내용으로 폭을 정하는 기존 관례를 따라 860px 로 넓혔다.
- 좁은 화면에서 본문 텍스트 링크형 단추가 18px 이었다 — 36px 로 올렸다.

### 8-6. 재확인

카드 78 · 진행률 막대 47 · 주기 없음 31 · 2025 요약(완료 119·진행중 16·미이행 26·해당없음 7) 그대로. 권한 4계층 전수 동일. 업로드 전 과정(파일→트리 선택→전체선택→확인→저장→진행중) 통과. 375px 가로 스크롤 없음, 트리 1열 스택·행 44px. 콘솔 오류 0 · 원시값 0 · 정의서 76건 규칙 통과.

## 10. 검증 한계 · 발주처 확인 대상

- **온나라 연동 미구현** — 상신 사실과 지면만 보여주고 결재 회신은 만들지 않았다. `PDF 보기`는 실제 산출물이 있을 때만 활성이고, 없으면 비활성 + 사유다. **지시서 §8-8이 요구한 "로컬 PDF fixture"는 만들지 않았다** — 실제 담양군 공문명을 붙인 가짜 PDF 를 저장소에 넣는 것이 "지어내지 말 것" 원칙과 충돌한다(UX설계 §11-6).
- **첨부 파일 실물 없음** — 프로토타입에 바이너리가 없어 복사는 메타데이터 이력(`copiedFromFileId`·`sourceYear`·`targetYear`)만 재현하고 화면에 명시한다.
- **2025 원장의 담당부서·담당자 없음** — `원장 미보유`로 표시. 신규 등록분부터 값이 쌓인다.
- **원자료 오염** — `수발신자 = '노, 로, 도'` 100건(문서 상세에 `원본 확인 필요` 배지), 공란 460건, `현재주기` 공란 2,141행(52%). 지어내 채우지 않았다.
- **근사 중복 2쌍의 병합 여부** — 같은 문서인지 발주처 확인 대상.
- **문서 출처·상태는 시연값** — `dataMode:'demo'`·`statusSource:'demo-seed'`, 문서 ID FNV-1a 해시 기반이라 새로고침해도 불변(`Math.random()` 미사용).
