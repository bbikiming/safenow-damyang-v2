## 1. 왜 따로 두나

부서 교육(1차)과 주무관 확인 작업에 쓰는 자료 두 건을 시스템 안에서 언제든 받을 수 있어야 한다. 처음에는 도움말 시트 안에 두는 안을 검토했으나 따로 버튼을 두기로 했다(2026-10-16 확정).

1. **도움말은 «이 화면» 사용법이다.** 도움말 내용이 등록되지 않은 화면에는 [?] 버튼 자체가 없다. 그 안에 넣으면 일부 화면에서는 자료를 받을 길이 없다.
2. **이 자료는 화면과 무관하다.** 교재는 시스템 전체를, 가이드는 업무 관리 메뉴를 다룬다. 어느 화면에 있든 같은 자리에서 받아야 한다.
3. **교육 때 «오른쪽 위 가이드 다운로드»라고 한 번에 안내할 수 있어야 한다.** 도움말을 열고 아래로 내려 찾게 하면 안내가 길어진다.

## 5. 서버 — 파일 제공

| 항목 | 값 |
|---|---|
| 접근 | **로그인한 사용자만** 받는다. 비로그인 상태로 파일 주소에 직접 들어오면 로그인 화면으로 보낸다 |
| 응답 헤더 | `Content-Type: application/pdf` · `Content-Disposition: attachment; filename="{ASCII 대체 이름}"; filename*=UTF-8''{퍼센트 인코딩한 저장 이름}` |
| 캐시 | 파일 이름에 연월이 들어가므로 같은 이름은 같은 판이다. 같은 이름으로 파일을 덮어쓸 때는 캐시가 남지 않게 `ETag`/`Last-Modified` 로 재검증되게 한다 |
| 없는 파일 | 목록에 있는데 파일이 없으면 그 건을 **모달에서 내지 않는다**(누르면 오류가 나는 버튼을 두지 않는다). 운영 로그에는 남긴다 |

- **로그인을 요구하는 이유** — 교재 04장에 **부서별 2025년 이행 현황**이 실려 있다. 내부 자료이므로 공개 주소로 두지 않는다.
- 프로토타입은 HTML `download` 속성으로 저장 이름을 정한다. 이 속성은 **파일이 다른 도메인(파일 서버·CDN)에 있으면 무시**되므로, 운영에서는 반드시 응답 헤더(`Content-Disposition`)로 저장 이름을 정한다. 한글 이름이므로 `filename*` 형식이 필요하다.
- 다운로드 횟수 집계는 요청 사항이 아니다. 넣지 않아도 된다.
