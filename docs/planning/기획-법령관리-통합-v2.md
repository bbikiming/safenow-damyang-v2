## 2. 구조 결정 — 2화면 → 단일 화면 3탭 (v1 §2.3 대체)

v1 은 "조문(사실)과 매핑(판단)은 파괴 성격이 달라 화면을 나눈다"로 2화면을 확정했다.
**2026-07-30 사용자 지시로 단일 메뉴 + 탭으로 통합한다.** v1 이 지키려던 것은 화면 분리 자체가 아니라 **저장 단위의 분리**이므로, 탭 구조에서도 다음으로 유지된다.

- 탭마다 draft/저장이 독립이고, **매핑 탭의 미저장 변경은 탭 전환에도 confirm 가드**가 걸린다(`LAWTABS` ↔ `DYADMLAWMAP.isDirty()`).
- 조문 탭에는 여전히 편집 입력란이 없다 — 편집 경계(v1 §1.2)는 전부 승계.
- 변경 이력은 두 탭의 조작이 쌓이는 **단일 타임라인**이므로 탭 3으로 승격했다(열 때마다 재렌더).

| 탭1 법령·조문 | `DYADMLAW` — 대장·원문(읽기 전용)·영향 범위·무결성·수집 검토 |

### 2.1 매핑 탭 편집 제거 — 검토 대장 + 재검토 요청 모델 (2026-07-30 추가 결정)

사용자 문제 제기: *"어차피 법령이 정해져 있는 거라면 저장 버튼이 있어야 할까."*

**판단 — 맞다. 저장을 포함한 편집 조작 전부를 제거한다.**

- 근거 조문은 법령이 정한 사실이고, "어느 화면의 근거인가"는 기관 판단이지만 그 판단은
  전수 검토(검증 6문 74건)로 확정된 **초기 DB** 다. 판단의 변경은 검토 절차 → 데이터
  재생성으로 가야지, 화면 즉석 수정은 감사 결함 5종("그럴듯한 오답")의 재발 경로다.
- 근거 **추가** UI 가 이미 같은 논리로 제거됐다(af303ba). 남아 있던 제거·순서·역할·저장은
  논리적 잔재였다 — 즉석 판단으로 떼는 것도 즉석 판단으로 붙이는 것과 같은 사고 유형이다.
- 부수 효과: 브라우저 로컬 override 가 재생성된 base 를 가리는 사고 원천이 사라진다
  (`LAWADM.effective()` 가 base 만 읽는다). "이 시스템은 법령 데이터를 손대지 않는다"는
  약속이 조문·매핑 모두에 일관된다.

| 제거 | 대체 |
|---|---|
| [저장]·[되돌리기]·draft/dirty 가드 | — (편집 없음) |
| 근거 판정 라디오·조문 [제거]·[▲▼] 순서 | 읽기 전용 표시 |
| 역할(의무/주기) select — **주기 조문이 전부 "의무 근거"로 오표시되던 결함의 원인** | 조문 속성(`ARTICLES[].cycle`) 파생 배지 — §37·§190·§197·별표4·고시 §15 는 「주기·기준 근거」 |
| 근거 없음 사유 textarea | 시드 사유의 읽기 전용 표시 |
| `LAWADM.saveMapping/clearMapping`·`mapOverride` 병합 | 제거 — base(law-map.js) 단일 진실 |
| (신설) | **[매핑 재검토 요청]** — 사유 필수, 비파괴 기록. 정비 큐·변경 이력에 표출, 철회 가능. 실제 변경은 law-map.js 재생성으로만 |

추가 개선 — 각 근거 조문 아래 **전수 검토 논거**(시드 검증 기록의 사유)를 함께 표시해,
"왜 이 조문이 이 화면에 붙는지"를 대장에서 바로 읽을 수 있다. 진척률 금지 문구 등
편집 화면을 전제로 한 설명도 함께 정리했다.

### 2.2 조문 탭 같은 기준 점검 (2026-07-30 후속)

같은 기준("생성물은 화면에서 고치지 않는다 · 소비자 없는 저장값은 두지 않는다")으로 조문 탭을 점검했다.

| 기능 | 판정 | 사유 |
|---|---|---|
| **적용 축 지정 select** | 제거 → **파생 배지** | 저장값(articleAdmin.axis)을 읽는 소비자가 없었다(검증 게이트용이었는데 게이트는 이미 없음). 축은 화면별 판단이 아니라 조문의 객관적 성격 — `ARTICLES[].civil`(중처법 §9·시행령 §8~11) 파생으로 「시민재해 축 / 산업재해 축」 배지 표시 |
| **[보관] 버튼·생애주기** | 제거 | '보관' 상태를 읽는 곳이 자기 표시뿐이었다. 수록 목록도 생성물이므로 수록 제외는 재수집(재생성)으로만 — 미참조 조문도 항목·주기 근거로 쓰이므로 수록 유지를 안내 문구로 명시 |

| 미연계 표기 분류 select | 유지 | 매핑과 달리 '사람 기록' 층이고 분류 주체(재난안전과) 재검토가 열려 있는 실일감(LWM-04) |
| 내보내기·데모 초기화·무결성·정비 큐 | 유지 | 판단 기록 반출·파생 검사 |

## 6. 이번 회차가 새로 드러낸 갭·확인 사항

### 6.1 이행관리에 원료·제조물 축 점검 항목이 없다 (신규 발견)

중처법 시민재해 축은 시행령이 둘로 갈린다 — 공중이용시설(§10·§11, 점검 **연 1회**)과 **원료·제조물(§8·§9, 점검 반기 1회)**. 담양군 관리대상에 원료·제조물 6건이 실재하는데, 이행관리 화면의 점검 영역은 §5(종사자)·§11(공중이용시설)뿐이고 **§9 축 항목이 없다.** §11 신설 때(연계 v1 §4.5)와 같은 유형의 절반 누락이다.

- 조치: `cse-9` 조문은 수록 완료. **화면 매핑은 보류** — 점검 항목이 실제로 생기기 전에 붙이면 검증 6문 #6(하지 않는 일을 한다고 쓰기) 위반이다.
- 필요 결정: 이행관리 화면에 §9 점검 영역(반기 1회) 신설 여부 — 기획/발주처.

### 6.2 담양군 중대재해 조례 — 법제처 등록 기준 미보유 확인

연계 v1 후속 3("조례 보유 여부부터 확인")의 답: **2026-07-30 법제처 국가법령정보 검색 "담양군 중대재해" 0건 — 등록된 조례 없음.** 전국 지자체 중대재해 조례 70건 흐름에 비추어 제정 여부는 발주처 정책 판단 사항이다. 조례 정비 레이더(배치 월 1회)는 제정 후 대상이 생긴다.

### 6.3 시민재해 축 점검 주기 3원화

주기 이원화(반기/연 1회, v1 후속 2-2)로 알고 있었으나 실제로는 **3원**이다 — 종사자 반기(§5) · 원료·제조물 반기(§9) · 공중이용시설 연 1회(§11). 이행관리 주기 설계에 반영 필요.
