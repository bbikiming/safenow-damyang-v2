## 0. 왜 이 문서가 필요한가

회의 직후 작성된 요약 문서(`담양군_중대재해_프로토타입_수정사항_상세정리.md`)를 녹취와 1:1 대조한 결과, 주장 349건 중 **정확 206건(59%) · 무근거 56건 · 왜곡 12건 · 과단정 9건**이었고, 녹취에는 있으나 요약에서 빠진 요구가 **74건**이었다. 요약 문서를 그대로 구현 지시로 쓰면 회의에서 부정된 것을 만들게 되므로, 이 문서를 반영 기준으로 삼는다.

특히 요약 문서 §11 "최종 메뉴 구조안"은 **회의 산출물이 아니라 작성자 창작**이다. 아래 항목들은 반영하지 않았다.

## 3. 착수 전 확정이 필요한 사항

1. **부서 명단 39개** — 현재 `DYV2.ORG` 11개. 경영방침·이행점검 전수 화면의 전제이며 화면에 갭이 노출되어 있다.
2. **공문 작성 화면** — 선행 조건이 두 가지다. ① 발주처가 공문 양식 3~4건을 **출력물로 지참해 대면 전달**(731~732, 1465) ② 수행사가 담양군을 방문해 **온나라 문서대장 작성 화면을 실물로 확인**(985~987). 벤치마크는 온나라 민원처리 결재 화면의 **표 형식 칸 나눔**(925~932). 내부결재/외부발송 통합 여부는 **미결**(991·1009·1033).
3. **연간 업무 자동 발행** — 참석자4가 *"이거보다 더 중요한 게"*(1380)로 우선순위를 못박은 기능. 건설과·환경과·물순환사업소 3개 과의 **문서대장 제목 5년치 엑셀**(8월 둘째 주 제출)을 받아 AI 로 표준 업무목록을 도출하고 전 부서에 일괄 발행 → 각 부서가 쳐내기(1414~1423). **미착수** — 입력 자료 대기.
   - 설계 주의: 부서가 쳐낸 건을 그냥 지우면 §1-5 에서 막은 '해당없음 회피' 경로를 시스템이 만들어주게 된다. **사유가 남는 비파괴 기록**이어야 한다.
4. **특별교육 별표5 수집** — DYLAW 재수집 필요(수기 작성 금지).
5. **다음 주 금요일 팀장 보고**(1529) — 신임 팀장이 방향을 틀면 이번 회의 결과는 잠정안이 된다. 되돌리기 어려운 대규모 작업은 그 이후로.

**근거**
- 시스템이 이미 필수로 다루지 않았다 — `deliverFromReview` 의 전달 대상 필터 조건은 `name`·`action` 두 개뿐이고 `basis` 는 빈 값이 기본이었다.
- 법정 기록 항목이 아니다 — 기록·보존 의무는 산안법 §36⑤이고 조문 자체는 고용노동부령에 **위임만** 한다. 스냅샷에 있는 §36①이 정한 실체는 *유해·위험요인 발굴 → 위험성 결정 → 개선대책 수립·이행*이며 항목별 조문 인용을 요구하지 않는다.
- CLAUDE.md §10 검증 6문 3번(화면 근거 vs 항목 근거) 기준으로도 행별 근거는 **있으면 좋은 항목 근거**이지 성립 요건이 아니다.

**문제였던 점** — 미지정 상태가 주황(warning) `법령 매핑 대기` 칩이라 **하지 않아도 되는 일이 남은 일처럼** 보였다. 부서 수가 39개로 늘면 이 가짜 미완료 표시가 화면을 뒤덮는다.

**남긴 것**
- 저장 스키마의 `r.basis` · `hazard.basis` 는 **그대로 유지**한다. 다른 경로(수시평가 등)가 채우면 개선조치 상세·내 할일에서 그대로 표시된다.
- 화면 단위 근거 칩(`DYLAW.MAP` → `layout.js` 주입)은 유지. 이건 화면 근거라 성격이 다르다.
- 미지정 표기는 `근거 미지정`(중립 톤, 대비 5.33:1)으로 바꿨다 — 사실만 알리고 조치를 요구하지 않는다.

**미확인 사항** — 위임받은 **산안법 시행규칙 §37(위험성평가 기록·보존 항목)이 DYLAW 스냅샷에 미수록**이다. 발주처에 "법정 필수 기록 항목"을 확답해야 하면 이 조문을 먼저 수집해야 한다(수기 작성 금지, §10).

**후속(같은 날)** — 상세 화면의 `근거 미지정` 자리 표시도 없앴다. 채울 수단(작성표 선택기)을 지운 뒤에도 자리를 남기면 **아무도 처리할 수 없는 미완료 표시**가 된다. 근거가 있으면 칩을 그리고, 없으면 아무것도 그리지 않는다(`.law-basis-none` 클래스 삭제).

## 6. 부서별 개선조치 상세 — 표 → 카드 재설계 (2026-07-31)

`RSKLIST.openDept()` 를 6열 표에서 **건별 카드**로 바꿨다. 사용자 지시: *"상세답게 이미지도 볼 수 있게 하고 여러 행이 있었을 경우 어떻게 보여줄지도 디자인해서 구현"*.

**왜 표를 버렸나** — 행마다 개선 전·후 사진이 붙으면서 (a) 이미지 칸이 글자 칸을 짓눌러 375px 에서 가로 스크롤 없이는 못 읽고, (b) 전·후 **대조**라는 이 화면의 존재 이유가 표의 한 칸으로 묻혔다. 카드는 `요인 → 조치 → 증빙(전·후) → 완료 확인`이 위에서 아래로 읽힌다.

**여러 건일 때의 설계**
- **요약 헤더** — 총 건수 · 완료율 게이지 · 점검일자/설문조사표/전달일/조치기한.
- **상태 필터** `전체 / 기한초과 / 미완료 / 완료` — **4건 이상일 때만** 낸다(적을 땐 필터가 소음이다). 0건인 상태 칩은 아예 안 그린다.
- **정렬이 곧 우선순위** — 기한초과 → 미완료 → 완료. 건수가 많을수록 정렬이 훑기의 전부다.
- **번호 배지(①②③)** — 카드가 길어져도 "몇 번째 건"으로 대화할 수 있다.
- 기한초과는 색만이 아니라 **좌측 굵은 선 + 상태 배지 글자**로도 구분한다(색만으로 정보 전달 금지).

**증빙 표시 규칙**
- 개선 전 | 개선 후를 **나란히** 둔다(560px 이하에서는 세로로 쌓되 순서로 대조 유지).
- 썸네일은 `flex:1 1 120px` — 1장이면 칸을 채우고 여러 장이면 나눠 갖는다. 높이는 200px 로 묶어 카드 하나가 화면을 다 먹지 않게 한다.
- 썸네일 클릭 → **그 카드 안에서** 확대(모달 적층 금지, §1). 원본 objectURL 이 죽었으면 썸네일로 폴백.
- **빈 상태를 감추지 않는다** — 개선 후가 없으면 점선 테두리 + `미제출`, 둘 다 없으면 `증빙 사진 없음 — 개선 전·후 모두 미제출` 한 줄. 카드 하단에도 `개선 후 사진 미제출 — 완료 소명 불가`를 남긴다.

**데이터 변경 (SKEY `damyangRskV2r11`)** — 개선조치에 `before_photos[]` · `after_photos[]`(썸네일 보유 객체)를 추가했다. 종전에는 `deliverFromReview` 가 **파일명 문자열만** 넘겨서 전달과 동시에 사진을 다시 볼 수 없었다. 옛 데이터(`before_photo` 문자열/불리언)는 `photoItems()` 가 흡수해 "미리보기 없음"으로 표시한다.

## 7. 배정 부서 담당자 관점 — 권한 전환 페르소나 + 담당자 주도 프로세스 (2026-07-31)

사용자 지시: *"권한 전환에서 업무 배정받은 일반 공무원 입장에서 보는 경우도 추가 / 위험성평가를 직접 진행해서 개선조치 마무리까지 부서의 담당자가 마치는 프로세스를 해볼 수 있게"*.

**페르소나 2인 추가**(`js/layout.js` `ROLE_PERSONAS`, tier `staff`) — 하정수(`u_wat3` · 물순환사업소) · 정환경(`u_env2` · 환경과). uid·deptId 는 `DYV2.ORG` 값 그대로다(§3).
기존 `staff`(박안전)와 계층은 같지만 성격이 다르다 — 박안전은 **주관부서(재난안전과) 실무**로 전 부서를 취합·점검하고, 신규 2인은 **업무를 배정받는 쪽**이라 자기 부서 일만 본다. 법적 3계층(§4·§16)을 늘리지 않고 설명으로 구분했다.

**로그인한 사람의 부서가 화면 기본값**(`DYROLE.deptId()` 신설) — 내 할일·위험성평가 내 할일의 부서 기본값이 '목록 첫 번째'에서 '내 소속'으로 바뀌었다. `?dept=` 가 있으면 그게 우선.

**끊겨 있던 고리를 이었다 — 수시평가는 '등록하고 끝'이었다.**
수시평가는 고시 §15② 트리거로 실시하지만, 실시했다고 끝나는 게 아니라 **위험성 감소대책을 수립·실행**해야 완결된다(산안법 §36①). 종전 등록 폼은 사유·발생일·내용만 받고 개선조치를 만들지 않아, 담당자가 자기 화면에서 마무리할 방법이 없었다.

등록 폼에 **실시 결과 행**(유해위험요인 · 원인 · 감소대책 · 조치 담당자(ORGPICK) · 개선 전 사진)을 넣고, 등록 시 그 행이 그대로 개선조치가 된다(`source_type: 'occasional'`, `occ_id` 로 역참조). 요인만 적고 대책이 비면 등록을 막는다 — *평가는 했는데 조치는 없는* 기록을 남기지 않기 위해서다.

**담당자가 끝까지 가는 경로**
1. 권한 전환 → 하정수(물순환사업소)
2. 수시 위험성평가 → `[＋ 수시평가 등록]` → 법정 사유 6종 중 선택
3. 실시 결과 행 작성 + 개선 전 사진(실제 파일) → 등록 → **개선조치 자동 생성**
4. 목록의 `개선조치` 칸에 진행률(`0 / 1`) + `[내 할일에서 마무리 →]`
5. 내 할일 → `완료 처리` → 조치 내용 · 완료일 · **개선 후 사진(실제 파일)** · 전자서명(본인 이름 자동)
6. 수시평가 목록이 `조치완료 1 / 1` 로 바뀜

**부수 수정** — 내 할일의 개선 후 사진이 파일명을 지어내는 목업이었다(`pickPhoto`). 이 사진 한 장이 조치 완료의 증빙이라 실제 파일 선택(`uploadDrop(pick)`)으로 바꾸고 `after_photos[]` 에 썸네일까지 저장한다. 개선조치 상세도 수시평가 출처의 유해위험요인·근거를 표시한다(종전에는 정기평가 출처만 보였다).

## 8. 정기 위험성평가 — 담당자 관점 완주 경로 (2026-07-31)

수시평가에 이어 **정기평가도 부서 담당자가 처음부터 끝까지** 해볼 수 있게 했다.

**끊겨 있던 곳** — 부서가 정기평가에서 지는 몫은 '점검일에 참여'가 아니라 **유해위험요인 설문조사표를 작성해 제출**하는 것이다. 그런데 내 할일에는 *양식 다운로드*만 있었고 제출 경로는 주관부서 화면(`rsk-list` 부서별 보고서)에만 있었다. 담당자가 자기 화면에서 끝낼 수 없는 구조였다.

**추가**
- 내 할일의 정기평가 카드를 `점검일 참여` → **`설문조사표 작성·제출`** 로 바꾸고, 모달 안에서 ① 양식 받기 ② 작성본 제출(실제 파일)을 한 자리에서 끝낸다. 제출하면 카드가 `제출 완료`로 바뀌고 `[교체]`만 남는다.
- `setDeptReport(aid, deptId, fileName, by)` 에 **`by` 추가** — 담당자가 올린 건을 '재난안전과'로 기록하면 이력이 사실과 달라진다. `dp.reportAt`·`dp.reportBy` 도 함께 남긴다.
- `rsk-list` 상단에 **내 부서 진행 상황 패널**(`myDeptPanel`) — 이 화면은 주관부서용 관리 화면이라 담당자가 들어오면 자기 부서가 어느 단계인지 표에 묻힌다. 3단계(① 설문조사표 제출·**내 부서** → ② 검수·전달·**재난안전과** → ③ 개선조치 완료·**내 부서**)를 뽑아 현재 차례와 다음 행동만 보여준다. 끝난 평가는 조회 전용(액션 버튼 없음, `평가 완료` 배지).

**완주 검증 (역할을 오가며 실제로 끝까지 실행)**

| 역할 | 행동 | 결과 |
|---|---|---|
| 박안전(주관) | 마법사로 2026년 평가 생성 | 대상 11개 부서 · 점검일 2026-09-10 |
| 박안전 | 공통 설문조사표 첨부 | `2026_유해위험요인_설문조사표.hwpx` |
| **하정수(부서)** | 진행 패널 `지금 제출하기` → 작성본 제출 | 이력 `by: 물순환사업소 · 하정수` · 진행률 1/11 |
| 박안전 | 통합보고서 등록 → 작성표 작성 → 조치기한 설정 → 전달 | `IMP-501` 생성(담당자 하정수, 기한 2026-10-31) |
| **하정수** | 진행 패널 `내 할일에서 마무리` → 완료 처리 | 개선 후 사진(실물)·전자서명 `하정수` |
| — | 평가 자동 완결 | 부서 `DONE` · 평가 `COMPLETED` · 개선 1/1 (100%) |

**발견해서 고친 결함** — `deliverFromReview` 가 개선 전 사진이 없을 때 `before_photo: true` 를 기본값으로 넣고 있었다. 올린 적 없는 사진을 '있음'으로 기록해 개선조치 상세에서 `미리보기 없음`으로 둔갑했다(구 파싱 목업의 잔재). `false` 로 바로잡아 `없음`으로 정직하게 표시된다.

## 9. 개선조치 상세 카드 공용화 — 정기·수시 동일 화면 (2026-07-31)

수시평가도 조치가 끝난 뒤 **무엇을 어떻게 고쳤는지 사진까지** 볼 수 있어야 한다는 지시에 따라, 정기평가 부서 상세와 **같은 화면**을 쓰도록 카드 렌더러를 공용 모듈로 뺐다.

**`js/rsk-imp-cards.js`(전역 `IMPCARD`) 신설** — 화면마다 카드를 다시 짜면 한쪽만 고쳐지고 다른 쪽이 조용히 뒤처진다(CLAUDE.md §7). 요약 헤더·상태 필터·정렬·카드·전후 사진·인라인 확대가 전부 여기 한 곳에 있다.
- `IMPCARD.open({ key, title, metaHtml, noteHtml, emptyHtml, items, canRemind, onRemind })`
- `items` 는 **함수로 넘긴다** — 재렌더마다 다시 읽어 완료 처리 결과가 즉시 반영된다.
- `metaHtml`·`noteHtml` 만 화면별로 다르다(정기: 점검일자·설문조사표·부서 제출본·전달일·조치기한 / 수시: 발생일·실시 사유·첨부·안전관리자 검토).

**소비처**
- `RSKLIST.openDept(deptId)` — 정기평가 부서 상세(기존 동작 유지, 재촉 버튼 포함).
- `RSKOCC.openImp(occId)` — 수시평가 목록 `개선조치` 칸의 **`[조치 상세]`** 버튼(신규). 재촉은 없다(부서가 스스로 등록한 조치라 재촉 주체가 없다).

**함께 개선** — 완료 카드에 `action_content`(실제 조치 내용)를 서명 줄 아래 함께 표시한다. 사진만 있고 무엇을 했는지 글이 없으면 소명 자료로 부족하다.

**검증** — 수시평가 1건을 담당자(하정수) 관점에서 등록→완료까지 실행한 뒤 `[조치 상세]` 확인: 전·후 썸네일 2장·확대(1500×1125px·22KB)·`완료 2026-07-31 · 전자서명 하정수` + 조치 내용. 정기평가 쪽도 동일 렌더러로 회귀 없음(대비 31개 노드 전부 통과, 375px 가로 스크롤 없음, 콘솔 에러 0).

## 10. 내 할일 — 완료한 업무 탭 재설계 (2026-07-31)

**문제** — 완료한 업무 탭이 '완료했다'는 사실만 남기고 있었다. 카드가 미완료 카드와 같은 모양이고, 무엇보다 **날짜가 기한이었다** — `완료 2026-10-31` 로 찍혀 완료일처럼 보였지만 실제 완료일은 2026-07-31 이었다. 이 탭을 여는 이유가 (a) 내가 뭘 끝냈는지 되짚기 (b) 감사·소명 자료 찾기인데, 둘 다 안 되던 상태다.

**설계**
- **날짜는 완료일** — 아이템에 `doneDate`·`doneBy`·`doneText`·`shots` 를 실어 `완료 2026-07-31 · 확인 하정수 · 기한 2026-10-31` 로 나눠 표기한다.
- **증빙을 카드에서 바로** — 개선조치는 개선 후 사진 썸네일(최대 3장 + `+N`)을 카드에 붙이고, `[조치 상세]` 로 **정기·수시와 같은 IMPCARD 화면**(전·후 대조·확대·서명)을 연다.
- **완료일 기준 시간 그룹** — `최근 7일 / 최근 30일 / 그 이전`. 회고는 시간순이 자연스럽고, 최근 것이 위로 온다.
- **분류 칩 필터** — 마감 할일 탭과 같은 `state.fCat` 을 쓴다(탭을 옮겨도 관점 유지). 분류가 1종뿐이면 칩을 내지 않는다.
- **요약 스트립** — `3건 완료 · 증빙 사진 2건 · 기한 후 완료 1건`. **지연 완료를 감추지 않는다** — 기한을 넘겨 끝낸 것도 사실이고, 카드에도 `기한 후 완료` 배지를 단다.
- **완료 체크는 아이콘 + 색** — 색만으로 완료를 표시하지 않는다.
- **되돌리기는 제공하지 않는다** — 증빙이 붙은 기록을 지우면 소명 자료가 사라진다. 파일 교체(`제출본 교체`·`첨부 재등록`)만 남긴다.
- **발행 업무는 10건까지만 펼친다** — 환경과는 완료 발행 업무가 55건이라 한 번에 펼치면 마감 할일 완료분이 스크롤 아래로 밀린다. `나머지 45건 더 보기`로 접는다.

**함께 고친 것** — 끝난 평가(`COMPLETED`)의 부서 항목을 통째로 건너뛰고 있어서 **제출한 설문조사표 기록까지 사라졌다**. 미제출 건만 건너뛰고 제출본이 있으면 완료 기록으로 남긴다.

**검증** — 완료 3건(설문조사표 제출 1 · 개선조치 2)에서 완료일 `2026-07-31 / 07-05 / 04-10` 이 각각 `최근 7일 / 최근 30일 / 그 이전` 으로 분류, 지연 1건 배지·요약 반영, 분류 칩 `전체 3 · 위험 1 · 개선 2` 필터 동작, `[조치 상세]` → IMPCARD 정상. 대비 42개 노드 전부 통과, 12px 미만 0, 375px 가로 스크롤 없음(썸네일·버튼이 본문 아래로 리플로우), 콘솔 에러 0.

## 11. 권한별 사용자 플로우 감사 (2026-07-31)

7개 페르소나 × 주요 화면을 기계적으로 훑어 **권한 경계가 실제로 지켜지는지** 확인했다. 구조 결함 4건을 찾아 고쳤다.

### 11-1. 권한 계층이 거꾸로였다 (CRITICAL)
`ROLE_TIERS.staff.hideNav` 가 **빈 배열**이라, 물순환사업소 주무관이 **사용자·권한·메뉴 관리(시스템 관리)** 를 볼 수 있었다. 가장 낮은 권한이 가장 많이 보던 상태다.
→ `staff.hideNav: ['admin']`. 시스템 관리는 페르소나의 **`sysAdmin: true`** 플래그로만 열린다(주관부서 실무자 박안전 1인). 계층 기본값 + 페르소나 예외를 합치는 `DYROLE.hidden(p)` 를 단일 판정 지점으로 뒀다.
**검증** — 김담양 12 / 홍길동·임시설·노읍장 13 / 박안전 14 / 하정수·정환경 13개 GNB.

### 11-2. 총괄·감독이 담당자 대신 '완료 서명'을 할 수 있었다 (CRITICAL)
군수·실과장이 [내 할일]에서 **완료 처리·전자서명·제출**을 그대로 눌렀다. 담당자 이름으로 남의 서명을 만드는 건 문서 위조다. 담당자끼리도 **다른 부서**를 골라 보면 같은 문제가 생겼다.
→ `MYWORK.canAct()` 단일 판정: `tier === 'staff' && 내 소속 === 보고 있는 부서`. 아니면 액션 버튼을 **[상세 보기]** 로 바꾸고 카드 클릭도 끈다. 조회는 막지 않는다 — 진행 상황을 보는 것은 총괄·감독의 정당한 권한이다. 콘솔·딥링크 우회를 막으려 `complete()`·`openReport()` 안쪽에도 같은 가드를 뒀다.
계층별 안내 문구를 다르게 낸다(총괄 / 관리감독자 / 타 부서 조회 중).

### 11-3. 실무자 대시보드가 하드코딩이라 [내 할일]과 어긋났다 (HIGH)
`staffView()` 가 페르소나를 받지도 않고 `4 / 2 / 7 / 12` 를 고정 출력했다. 하정수의 실제 마감은 1건인데 대시보드는 4건 지연이라 말했고, 그 숫자를 눌러 들어가면 다른 화면이 나왔다. **한 번 어긋난 대시보드는 그 뒤로 아무도 믿지 않는다.**
→ `staffCounts(deptId)` 로 `DYRSK` 실집계. 라벨을 `내 부서 개선조치` 로 좁혀 모수를 명시하고, 딥링크에 `cat=improve&dept=` 를 실어 **누르면 같은 숫자가 나오게** 했다. 관리감독자 대시보드의 `개선조치 지연` 도 시드 → 실집계로 교체(임시설 3건 → 실제 0건).
0건일 때 빈 막대 대신 **다음 행동**(완료한 업무 보기 / 수시평가 등록)을 준다 — 할 일이 없는 담당자에게 빈 화면은 막다른 길이다.

### 11-4. 대상 부서가 주관부서의 관리 화면을 편집할 수 있었다 (HIGH)
정기 위험성평가(`rsk-list`)는 **주관부서(재난안전과) 운영 화면**인데, 공공시설사업소장이 남의 부서 보고서 첨부·검수·조치기한 설정을 다 할 수 있었다.
→ `canManage()` = 소속이 재난안전과. 아니면 **조회 전용 표**(부서·점검일·설문조사표 제출·개선조치·기한·상태·[상세])로 대체하고, 왜 조작이 없는지 밝힌다. 내 부서 진행 패널은 유지 — 자기 몫은 거기서 처리한다.
`openWizard`·`openSurveyAll`·`uploadReport`·`openReportAttach`·`openDueSet`·`clearSurveyAll`·`clearReport` 함수 안쪽에도 가드를 넣어 우회를 막았다.

### 11-5. 감독자에게는 '대신 처리'가 아니라 '재촉'을 준다
내 부서 진행 패널이 관리감독자에게도 `지금 제출하기`(→ 조회 전용 화면)를 띄워 막다른 길이었다.
→ 계층별로 액션을 바꾼다: 담당자 `지금 제출하기 / 내 할일에서 마무리`, 감독자 `진행 확인 → / 기한초과 재촉`(산안법 §16 지휘·감독). 헤더도 `내 부서` ↔ `소속 부서 진행 상황 (관리감독)`.

**최종 검증** — 7개 페르소나 전수: GNB 노출·관리 버튼 수(주관부서 4, 그 외 0)·조회 전용 배너·진행 패널 표기가 전부 의도대로. 콘솔 에러 0, `css/v2.css` 원시값 0.

**남은 갭(의도적으로 드러냄)** — 관리감독자 대시보드의 `평가 완료 12/14` 등은 아직 `SUPER_SEED` 시드다. 부서별 평가 이력을 실데이터로 채우려면 시드 확장이 필요해 이번 범위에서 제외했고, **딥링크가 걸린 지표(개선조치 지연)만 실집계로 바꿨다** — 눌러서 확인 가능한 숫자부터 진실이어야 한다.
