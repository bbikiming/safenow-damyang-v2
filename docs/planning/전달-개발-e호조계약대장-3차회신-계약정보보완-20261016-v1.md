## 1. 문의 회신

### 1-1. 자료 정정 17건 (+ 준공예정 2062년 2건)

- 담양군에 정정을 요청하지 않는다. 1·2차 회신의 «e호조에서 정정 → 다시 받는다»를 이 문서로 대체한다.
- 해당 계약은 지금처럼 «계약 정보 확인 필요»로 드러낸다 — 기간 역전은 회차 «판정 불가», 금액 0원은 «금액 확인 필요».
- 감독부서 담당자가 **보완값(종료일·계약금액)**을 사유와 함께 넣으면 그 값으로 판정한다(§2).
- 2062년 2건은 형식상 정상이라 자동 표시에는 걸리지 않는다. 그래서 보완 입력을 **모든 계약에** 연다(§2-1).

### 1-2. 사업소·읍면·과년도 계약

- 받은 파일은 관서가 전부 «본청»이라 사업소·읍면 계약이 빠져 있고, 작년 이전 계약 중 진행 중인 공사도 빠져 있다. 계약대장은 e호조에서만 나오므로 **추출은 담양군에 요청할 수밖에 없다.**
- 조건 — **관서 전체 · 준공예정일자 2026-01-01 이후(계약 연도 무관) · 지금과 같은 양식.** 요청 메일은 기획이 보낸다.
- 파일이 오면 지금의 반입 기능으로 올린다. 같은 관리번호는 갱신되고 새 관리번호만 더해진다 — **추가 구현은 없다.**
- 오기 전에는 지금 866건으로 진행한다. 급한 사업소·읍면 계약은 직접 등록으로 넣을 수 있다.

### 1-3. 계약 변경 반영

- 재난안전과 담당자가 계약대장 엑셀을 다시 올린다(반입·판정 권한과 같은 사람).
- 기본 주기 — **반기 회차 시작 전(1월·7월 첫 주) 1회 + 매월 1회.** 회차 대상은 «기간이 반기와 겹치는가»로 정하므로 회차 시작 시점의 원장이 맞아야 하고, 월 1회는 새 계약이 그 회차 점검에서 빠지지 않게 하는 간격이다. 시스템이 주기를 강제하지는 않는다 — 운영 기준이다.
- 다시 올려도 **판정·점검 유형·도급인 의무 적용·착공일(보완)·보완값·안전관리자**는 지워지지 않는다.
- API 연계(EXT-15)가 붙으면 일 배치로 바뀌고 수동 반입이 필요 없어진다.

## 2. 기능 — 계약 정보 보완값

### 2-1. 보완할 수 있는 칸

| 칸 | 원장(파일) 값 | 보완값 | 비고 |
|---|---|---|---|
| 계약 시작 | 계약일자 | **착공일(보완)** — 이미 있음 | 기간 역전 중 시작이 틀린 경우도 이것으로 고친다 |
| 계약 종료 | 준공예정일자 | **종료일(보완)** — 신설 | |
| 계약금액 | 총계약금액 | **계약금액(보완)** — 신설 | 원 단위 정수 |

- **모든 계약에서** 보완할 수 있다(자동 표시된 17건만이 아니다). 2062년처럼 형식은 정상인 오기를 감독부서만 알아볼 수 있기 때문이다.
- 계약명·업체명·사업자등록번호·감독부서·계약종류는 보완 대상이 아니다. 판정에 쓰는 값이 아니거나(이름), 판정자가 따로 정하는 값(점검 유형)이 이미 있다.
- **원장 값은 그대로 둔다.** 보완은 원장을 고치는 것이 아니라 그 위에 얹는 값이다.

### 2-2. 누가

| | 보완 입력·수정·해제 |
|---|---|
| 그 계약의 감독부서 담당자 | ○ |
| 재난안전과 담당자 | ○ (전 계약) |
| 다른 부서 담당자 | — |
| 관리·감독 계층(군수·과장·소장) | — (조회만) |

- 판정은 착공일(보완)과 **같은 함수**를 쓴다 — 프로토타입 `DYCON.canActRow(r)` = `DYROLE.canAct(감독부서 id)`. 감독부서가 조직도에 없으면 담당자 누구나(종전 규칙 그대로).
- 버튼과 저장 양쪽에 같은 판정을 건다 — 버튼만 숨기면 직접 호출로 뚫린다.

### 2-3. 입력 규칙

| 항목 | 규칙 | 거절 문구 |
|---|---|---|
| 종료일(보완) | 날짜. **유효 시작일(착공일 보완 → 계약일자) 이후** | 종료일이 시작일보다 앞섭니다 |
| 계약금액(보완) | 1 이상의 원 단위 정수 | 계약금액을 원 단위 숫자로 입력하세요 |
| 보완 사유 | **필수**(1자 이상, 200자 이내) — 예: «계약서 확인», «착공계 기준», «변경계약 반영» | 보완 사유를 적어 주세요 |
| 해제(값 지우기) | 원장 값으로 돌아간다. 사유 불필요, 확인 한 번 | — |

- 착공일(보완)도 같은 창에서 함께 고친다 — 시작·종료가 한 쌍이라 따로 고치면 역전을 검사할 수 없다.
- 입력할 때마다 **이력**을 남긴다 — 칸 · 이전 값 · 새 값 · 사유 · 입력자 · 일시.

### 2-4. 판정 순서 — «유효 값»

모든 판정은 아래 **유효 값**으로 한다. 칸마다 보완값이 있으면 보완값, 없으면 원장 값이다.

| 유효 값 | 순서 |
|---|---|
| 유효 시작일 | 착공일(보완) → 원장 계약일자 |
| 유효 종료일 | 종료일(보완) → 원장 준공예정일자 |
| 유효 금액 | 계약금액(보완) → 원장 총계약금액 |

**유효 값을 쓰는 곳 (빠짐없이)**

| 판정 | 화면 |
|---|---|
| 회차 대상(기간이 반기와 겹치나) · 기간 역전 여부 | 도급관리 점검표·요약 «점검표 미작성» |
| 진행 중/종료 | 도급관리 기본 보기 · 조직 공사별 목록 포함 여부 |
| 법정 적용(산업안전보건관리비 2천만원 · 기술지도 1억~120억·1개월 · 안전보건대장 50억) | 도급관리 «법정 적용» 칸·조건 |
| 안전관리자 선임 의무(50억) | 조직 공사별 안전관리자 칸·완료 차단 |
| 정렬(시작일 순) | 두 목록 |

> 한 곳이라도 원장 값을 직접 읽으면 «보완했는데 그 화면만 그대로»가 생긴다. 판정 함수를 한 곳(원장 계층의 유효 값 함수)에 두고 화면은 그것만 부르게 하라.

### 2-5. 상태

| 상태 | 조건 | 표시 |
|---|---|---|
| **계약 정보 확인 필요** | 유효 값 기준으로 기간 역전(유효 종료일 < 유효 시작일) · 또는 반입분인데 유효 금액이 0원·빈 값 | 빨강 «기간 확인 필요» / «금액 확인 필요» |
| **보완됨** | 보완값이 하나 이상 있고 확인 필요 조건에 걸리지 않음 | 회색 «보완» 표시 + 칸 옆 «보완값 기준» |
| **원장 변경됨 — 보완값 확인** | §2-7 | 주황 |

- 요약의 «자료 확인 필요»는 **유효 값 기준**으로 센다 — 보완하면 그 수가 준다.
- 반입 결과 창의 «자료 확인 필요»는 **파일(원장) 기준**으로 센다 — 그 파일의 품질을 말하는 숫자다. 두 숫자가 다를 수 있다는 것을 반입 결과 창에 한 줄로 밝힌다(«목록의 수는 보완한 값을 반영합니다»).

### 2-6. 화면

**목록(도급관리·조직 공사별)**
- 계약기간·계약금액 칸에는 **유효 값**을 보이고, 보완값이면 칸 아래에 «보완값 기준»을 단다. 마우스를 올리면 원장 값과 보완 사유가 보인다.
- 확인 필요 계약은 사업명 옆에 «기간 확인 필요»/«금액 확인 필요» 칩. 조건 «확인 필요만»에 걸린다(지금과 같음).
- 감독부서 담당자에게는 계약기간 칸의 [착공일] 버튼을 **[계약 정보 보완]**으로 바꾼다 — 한 창에서 시작·종료·금액을 다룬다. 공사에만 있던 버튼을 **모든 유형**으로 넓힌다(종료일·금액은 유형과 무관하다).

**[계약 정보 보완] 창**

```
계약 정보 보완 — {계약명}
──────────────────────────────────────
             원장(e호조)        보완값
계약 시작    2026-02-02         [ 날짜 ]   ← 착공일(보완)
계약 종료    2026-01-16         [ 날짜 ]
계약금액     0원                [ 숫자 ]
보완 사유 *  [ 계약서 확인                  ]

ⓘ 원장 값은 그대로 남고, 판정은 보완값으로 합니다.
  엑셀을 다시 올려도 보완값은 지워지지 않습니다.
──────────────────────────────────────
[취소]  [보완 해제]  [저장]
```

- 비운 칸은 «보완 없음»(원장 값 사용)이다.
- 창 아래에 그 계약의 **보완 이력**(최근 5건)을 보인다.
- [보완 해제] — 세 칸을 모두 비운다. 확인 한 번만 받는다.

**판정 창(재난안전과)**
- 원장 요약에 원장 값과 보완값을 함께 보인다(«계약기간 2026-02-02 ~ 2026-01-16 → 보완 2026-02-02 ~ 2026-07-16»).

### 2-7. 엑셀을 다시 올릴 때

| 경우 | 처리 |
|---|---|
| 원장 값이 그대로 | 아무것도 바꾸지 않는다 |
| 원장 값이 바뀌었고 **새 원장 값 = 보완값** | 원장이 정정된 것이다 — 그 칸의 보완값을 **자동으로 정리**하고 이력에 «원장 정정으로 해제»를 남긴다 |
| 원장 값이 바뀌었고 **새 원장 값 ≠ 보완값** | 보완값은 **그대로 우선**한다. «원장 변경됨 — 보완값 확인»을 달고 감독부서가 [보완값 유지] 또는 [원장 값 사용]을 고르면 표시가 지워진다 |
| 보완값이 없는 칸의 원장 값이 바뀜 | 지금 규칙 그대로(판정한 계약이면 «판정 후 변경됨») |

- **보완값을 덮어쓰지 않는다**(착공일 보완과 같은 규칙).
- 반입 되돌리기의 차단 조건에 «보완값이 있는 신규 계약»을 더한다(지금: 판정·착공일).

### 2-8. 판정한 계약의 값이 바뀔 때

- 판정(대상/제외)을 한 계약의 **유효 값**이 바뀌면 — 원장이 바뀌었든 보완값을 넣었든 — «판정 후 변경됨»을 단다. 금액이 법정 기준선을 넘나들면 판정 근거가 달라지기 때문이다. 판정을 자동으로 되돌리지는 않는다(종전 규칙).

### 2-9. 저장할 값

| 값 | 형식 | 비고 |
|---|---|---|
| 종료일(보완) | 날짜 · 비어 있을 수 있음 | 신설 |
| 계약금액(보완) | 정수 · 비어 있을 수 있음 | 신설 |
| 착공일(보완) | 날짜 · 비어 있을 수 있음 | 이미 있음 |
| 보완 사유 · 입력자 · 입력 일시 | 마지막 입력 기준 | 신설 |
| 보완 이력 | 칸 · 이전 값 · 새 값 · 사유 · 입력자 · 일시 의 목록 | 신설 — 지우지 않는다 |
| 원장 변경 확인 필요 | 예/아니오 | 신설 — §2-7 |

- 원장 칸과 **같은 열 묶음에 두지 않는다** — 반입이 덮는 범위를 스키마가 지키게(1차 회신 §8-6과 같은 원칙).

### 2-10. 하지 말 것

| | 왜 |
|---|---|
| 원장 값을 화면에서 직접 고치게 하기 | 다음 반입에 덮이고, 무엇이 원래 값이었는지 사라진다 |
| 보완값을 반입이 덮어쓰기 | 감독부서가 확인한 사실이 사라진다 |
| 판정을 화면마다 따로 짜기 | 보완했는데 한 화면만 그대로인 상태가 생긴다(§2-4) |
| 사유 없는 보완 | 왜 원장과 다른지 아무도 모른다 |
| 2062년 같은 값을 «몇 년 이상이면 이상» 규칙으로 자동 표시 | 우리가 정한 상한이 기준이 된다(1차 회신 §2-3) — 감독부서가 보고 보완한다 |
| 담양군 계약부서에 정정 요청 | 재난안전과·계약부서는 그 값이 왜 틀렸는지 모른다 |

### 2-11. 범위

- **이번에 만든다** — §2 전부(보완 3칸 · 유효 값 판정 · 상태 · 보완 창 · 재반입 규칙 · 이력).
- **선택(뒤로 미뤄도 된다)** — «계약 정보 확인 필요» 계약을 감독부서 **내 할일**에 «계약 정보 보완»으로 띄우기. 없어도 목록의 «확인 필요만» 조건으로 찾을 수 있다.
