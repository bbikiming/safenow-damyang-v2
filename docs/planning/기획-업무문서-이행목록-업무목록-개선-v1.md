## 1. 점검 결론

**골격은 실무에 맞다.** 두 화면의 축 분리(의무의 증빙이 갖춰졌나 / 문서가 어디 있나), 판정 단일 출처(`DYDOCS`), 업로드 3단계 마법사, 전년도 프리셋, 소유권 검증(`assertOwn`), URL 상태 동기화, 미확정 갭 노출(원장 미보유·시연값)은 담양군청의 "증빙을 모아 재난안전과가 확인한다"는 실제 업무 구조와 일치하고, 검색 성능(4,256건 13ms)·첫 데이터 거리(§14-12)도 충족한다.

**그러나 실무 루프가 한 곳에서 끊긴다.** 관리자의 `[확인 반려]`가 사유를 필수로 받고서 **어디에도 저장·표시하지 않아**, 반려당한 담당자는 반려 사실조차 알 수 없다(IMP-01). 그 밖에 부서 담당자가 "내가 채울 일"을 찾을 수단이 없는 것(IMP-02), 같은 선택 UI가 두 벌인 것(IMP-03), 항상 실패하는 삭제 버튼(IMP-04)이 실사용 효용을 깎는다.

| 우선순위 | 항목 | 성격 |
|---|---|---|
| **P1** | IMP-01 반려 축 신설 — 사유가 담당자에게 보이게 | 기능 결함 (루프 단절) |
| **P1** | IMP-04 원장·시드 문서의 [문서 삭제] 게이트 | 결함 (도달 불가 약속) |
| **P2** | IMP-02 '내 부서 관련만 보기' 파생 필터 + 안내 문구 교정 | 효용성 (핵심 동선 미지원) |
| **P2** | IMP-03 미분류 교정 모달 DYPICK 전환 | 규칙 위반 (§5·§7 MUST) |
| **P3** | IMP-05 확인 모달 증빙 링크 새 탭 | 사용성 (확인 루프 마찰) |
| **P3** | IMP-06 진행상태 이중 컨트롤 정리 | 규칙 위반 (§14-12) |
| **P4** | IMP-07 DYPICK 좌측 검색 — 할 일 이름까지 | 사용성 |
| **P4** | IMP-08 '취합상태' 필터 라벨에 연도 명시 | 문구 |

## 2. 개선 항목

### IMP-01 반려가 작동하지 않는다 — 반려 축 신설 (MUST)

**증거.**
- `js/doc-exec.js` `rejectStage()` 는 사유 없으면 저장을 거부하면서(*"담당자가 무엇을 다시 해야 하는지 알 수 없습니다"*), 정작 그 사유를 `transition(…, ST.WIP, {reason})` 으로 넘긴다.
- `js/doc-progress.js` `transition()` 은 `opt.reason` 을 **`ST.NA` 일 때만** `naReason` 으로 저장한다. 반려(WIP)의 사유는 `store().log` 로만 가는데, **`log` 를 읽는 화면이 0개다**(전 코드베이스 grep 확인).
- 반려해도 상태가 `진행중` → `진행중` 이라 담당자 화면에는 **아무 변화가 없다.** `stageRecord()` 가 노출하는 것은 `needsRecheck`(완료→환원 전용)·`naReason` 뿐이다.
- 관리자도 "확인할 것 16건" 안에서 **반려해 둔 건과 새로 올라온 건을 구분하지 못한다.**

**왜 문제인가.** CLAUDE.md §4-3 이 같은 구조의 결함을 이미 명문화했다 — *"사유 없는 반려는 저장되지 않는다 — 담당자가 무엇을 다시 해야 하는지 모르면 반려가 작동하지 않는다"*, *"반려 사유·회차가 담당자 화면에 상시 뜬다"*. 현행은 사유를 **받기만 하고 버린다.** 실무에서는 반려당한 부서가 전화로 물어봐야 하는 시스템이 된다.

**기획.** 위험성평가 `improvement.confirm` 선례(§4-3)를 그대로 따른다.
- `status` 는 건드리지 않는다 — `진행중` 이분법을 소비하는 화면(요약 칩·진행률·필터)이 있으므로 **별도 축**으로 둔다.
- `StageProgress` 에 `returned: { reason, at, by }` + 누적 `returnRound`(반려 회차, 초기화하지 않음) 를 추가한다. `undefined` = 반려 없음으로 파생되므로 **SKEY 범프 불필요**(§4-3 과 같은 근거).
- 저장은 `transition()` 한 곳에서만: `opt.kind === 'reject'` 일 때 `returned` 를 기록하고 `returnRound` 를 +1 한다. 사유 없으면 저장 거부(현행 화면 검사를 데이터 계층으로 내린다 — 전역 호출로 뚫리지 않게).
- **재제출이 반려 표시를 지운다** — `applyDocument()`(새 문서/파일이 그 단계에 붙는 순간) 가 `returned` 를 삭제한다. `returnRound` 는 남는다.
- `stageRecord()` 에 `returned`·`returnRound` 노출.

**화면.**
- 이행 목록 단계 행: `returned` 가 있으면 `반려됨` 칩(warning tone) + **사유 한 줄 상시 노출**(단계명 아래 줄, `rec.returned.reason`). 숨기지 않는다 — 반려의 존재 이유가 이 한 줄이다.
- 요약 바: `진행중` 칩 옆에 반려 건수가 있을 때만 `반려 N` 보조 칩(클릭 시 반려 건만 필터, URL `?returned=1`, `stageMatch` 에 조건 추가).
- 담당자 `nextStep()`: 반려 건이 있으면 **최우선**으로 "반려된 서류 N건 — 사유를 확인하고 다시 올리면 됩니다" + 이동 버튼.
- 확인 모달(관리자): 현재 상태 옆에 `반려 N회 · 마지막 사유` 표시(자기가 반려해 둔 건임을 알게).
- `apply()` 토스트 문구 분기: 반려 시 "진행중 처리했습니다"(현행 — 오해 유발)가 아니라 **"확인 반려했습니다 — 사유가 담당자 화면에 표시됩니다."**

**수용 기준.**
1. 박안전이 사유와 함께 반려 → 하정수 화면에서 그 단계 행에 `반려됨` 칩과 사유가 보인다.
2. 하정수가 그 단계로 새 문서를 올리면 칩·사유가 사라지고 관리자에게 다시 확인 대기로 잡힌다. `returnRound` 는 유지.
3. `DYDOCS.transition(id, y, ST.WIP, {kind:'reject'})` 를 사유 없이 전역 호출하면 거부된다.
4. 새로고침 후 유지(localStorage). 기존 저장 데이터(반려 축 없음)가 오류 없이 로드된다.

### IMP-02 '내가 채울 일'을 찾을 수단이 없다 — 내 부서 관련 파생 필터

**증거.**
- 시연 가이드가 부서 담당자에게 *"① 내가 채울 일 찾기"* 를 약속하지만, 화면에는 어느 단계가 자기 부서 것인지 알 축이 없다. `적용대상` 셀렉트는 원자료 문구 28종(`"물순환사업소 · 건설과 · 읍면"`, `"밀폐공간 작업 부서(물순환·환경 등)"` …)을 그대로 나열해 사실상 못 쓴다.
- `nextStep()` 이 물순환사업소 주무관에게 *"아직 서류가 없는 일이 26건 있습니다. 여기부터 채우면 됩니다"* 라고 말한다 — 26건 대부분은 재난안전과·다른 부서 소관이다. **화면이 남의 일을 내 일이라고 말한다.**

**왜 문제인가.** 이행 목록의 부서 담당자 동선은 "내 몫의 증빙을 올린다" 하나다. 그 진입이 막혀 있으면 이 화면은 재난안전과 전용이 되고, 부서 담당자에게는 78개 카드 스크롤이 된다.

**기획.**
- 실측: 168개 단계 전부 `target` 문구가 있고, '물순환' 부분일치 + 전부서형 문구만으로 168 → **44건**으로 좁혀진다. 파생이 성립한다.
- `DYDOCS` 에 단일 판정 `stageDeptHit(stage, deptName)` 신설: ① `target` 이 부서명(전체·접미어 제거형 — "물순환사업소"→"물순환", 2자 이상)을 포함 ② 또는 전부서형 문구(`전 부서`·`각 부서`·`전체 부서`) 포함. **화면이 각자 매칭을 복제하지 않는다.**
- 이행 목록 필터 바에 `[내 부서 관련만]` 토글(체크박스, URL `?mine=1`): 접속자에게 `deptId` 가 있고 주관부서(재난안전과)가 아닐 때만 노출. `stageMatch()` 에 조건 추가.
- 토글이 켜지면 결과 옆에 **추정임을 밝히는 안내**를 함께 낸다: "적용대상 문구에서 부서명을 찾아 고른 추정 목록입니다 — 확정 담당부서 연계(새올·온나라, `doc-dept-src`) 수신 전까지의 대체 동작입니다." **지어낸 확정 매핑처럼 보이게 하지 않는다**(CLAUDE.md §14-12 갭 노출 원칙). DYPOLICY 신규 항목은 만들지 않는다 — 기존 `doc-dept-src` 가 이 갭의 실제 항목이다.
- 비주관부서 담당자의 `nextStep()` 문구 교정: "내 부서 관련(추정) 미이행 N건 · 전체 26건" — 버튼은 `미이행 + 내 부서` 를 함께 건다. 파생 결과가 0건이면 전체 건수로 안내하되 "내 부서 관련으로 추린 결과 0건"을 밝힌다.
- **조회 범위(§12)와 무관하다** — 이 화면은 scope 를 걸지 않는 화면(CLAUDE.md §5)이고, 이 토글은 제한이 아니라 편의 필터다. 기본값은 꺼짐(전체 노출 유지).

**수용 기준.**
1. 하정수(물순환) 로그인 → 토글 노출, 켜면 카드·건수가 부서 관련 단계로 좁혀지고 추정 안내가 보인다.
2. 박안전(재난안전과)·군수 로그인 → 토글이 보이지 않는다(재난안전과는 전 항목이 제 일이고, 조회 계층에는 '채울 일' 동선이 없다 — 단, head/super 중 부서 소속(과장·소장·읍면장)에게는 노출해 자기 부서 조회를 돕는다).
3. `?mine=1` 딥링크 재진입 시 상태 복원.
4. 하정수의 nextStep 이 전체 26건을 "여기부터 채우면 됩니다"라고 말하지 않는다.

### IMP-03 미분류 교정 모달이 DYPICK 을 쓰지 않는다 (§5·§7 MUST 위반)

**증거.** `js/doc-list.js` `renderRemap()` 이 78개 이행항목 그룹 × 168개 체크박스를 **자체 마크업**(`.dl-rm-grp`)으로 한 스크롤에 쌓는다. CLAUDE.md §5: *"이행항목·업무단계를 고르는 UI 는 DYPICK 으로만 (MUST) … 78개 아코디언은 원하는 것을 만나기까지 계속 굴려야 한다"* — DYPICK 이 대체하려던 바로 그 패턴이다. 업로드 STEP2·상세조건과 **같은 과업을 다른 UI 로 두 번 배우게** 한다.

**기획.**
- `renderRemap()` 본문을 `DYPICK.render({ ns:'DOCLIST.onRemapPick', multi:true, stages: RM.stageIds, height: 260 })` 로 교체. 자체 검색창·그룹 목록 제거(DYPICK 이 칸별 검색을 이미 가진다).
- `onRemapPick(kind, a, b)` 콜백 신설 — `DOCUP.onPick` 과 같은 계약(stage/all/clear/redraw), 선택값은 `RM.stageIds` 가 든다.
- 모달 폭은 기존 규칙 `.modal:has(.dyp)`(860px) 이 자동 적용된다.
- 유지: 문서 정보 헤더 · "선택 N개" 카운트 · 0개 저장 거부 · 저장 시 `remapLedger()` 경로와 토스트. `openRemap()` 진입 시 `DYPICK.reset('')`.
- 부수 정리: 이제 안 쓰는 `setRemapQ`·`toggleRemapStage` 와 `.dl-rm-*` CSS 는 소비처가 0 임을 확인하고 제거한다(§7-1 사고 예방 — 마크업만 옮기고 CSS 를 남기지 않는다. 역방향 검사도 한다: 새로 쓰는 클래스가 CSS 에 실재하는지).

**수용 기준.** 업무 목록 → `단계 지정` → 2단 선택기(좌 의무/우 할 일, 칸별 검색)가 뜨고, 다중 선택·저장 → 해당 단계 진행중 반영. 업로드 STEP2 와 조작감이 같다.

### IMP-04 원장·시드 문서의 [문서 삭제]가 항상 실패한다

**증거.** `js/doc-detail-ledger.js:179` 가 `D().canDelete()`(관리자 여부)만 보고 삭제 버튼을 낸다. 원장(ledger) 문서에서 관리자가 버튼 → 영향 범위 확인 모달(*"되돌릴 수 없습니다"*) → `삭제` → `removeDocument()` 가 `'원장 문서는 삭제할 수 없습니다.'` 로 **항상 거부**(같은 파일 235행, `doc-progress.js:518` — 삭제 가능한 것은 `store().docs` 즉 사용자 등록분뿐). 확인까지 시킨 뒤 거절하는 버튼이다 — *"없는 동작을 시각적으로 약속하는"* 패턴(CLAUDE.md §2 드롭존 금지와 같은 근거).

**기획.**
- 삭제 버튼 노출 조건을 `D().canDelete() && doc.origin === 'user'` 로 좁힌다.
- 원장·시드 문서에는 버튼 대신 이유를 밝힌다: "원장·시드 문서는 지울 수 없습니다 — 잘못 붙은 분류는 [단계 지정]으로 고칩니다." (도달 가능한 행동만 약속 — §4-3 안내 문구 원칙)
- `removeDocument()` 의 데이터 계층 가드는 그대로 둔다(화면 우회 방어).

**수용 기준.** 원장 문서 상세에 삭제 버튼이 없고 대체 안내가 보인다. 사용자 등록 문서에서는 삭제가 기존대로 동작한다.

### IMP-05 확인 모달에서 증빙을 열면 확인 맥락이 사라진다

**증거.** `openStage()` 모달의 서류 링크(`doc-detail.html?id=…`)가 같은 탭으로 이동한다. 관리자는 "확인할 것 16건" 루프에서 서류를 볼 때마다 모달을 잃고, 뒤로가기 → 카드 찾기 → `확인하기` 재진입을 반복한다.

**기획.** 모달 안 서류 링크에 `target="_blank" rel="noopener"` + "새 탭" 표기(링크 뒤 `↗` 등 시각 표지와 `aria-label` 병기). 모달 인라인 미리보기는 만들지 않는다 — 프로토타입에는 원본 바이너리가 없어 볼 것이 메타뿐이고, 모달 안 문서 뷰어는 §1(단일 모달) 경계에서 얻는 것보다 복잡도가 크다. **이행 목록 본문의 `서류 N건` 링크는 현행 유지**(그건 화면 전환이 맞는 동선이다).

**수용 기준.** 확인 모달에서 서류 제목 클릭 → 새 탭. 원래 탭의 모달·스크롤 유지.

### IMP-06 진행상태를 두 컨트롤로 묻는다 (§14-12 위반)

**증거.** 요약 칩(완료 119·진행중 16·미이행 26·해당없음 7)이 클릭 필터인데, 필터 바에 `진행상태` 셀렉트가 또 있고 둘 다 `S.status` 를 조작한다. CLAUDE.md §14-12: *"같은 축을 두 컨트롤로 묻지 않는다 … 칩이 클릭 필터면 셀렉트는 지운다"*(내 할일 선례).

**기획.** 필터 바에서 `진행상태` 셀렉트를 제거한다. 칩 4종이 상태 전체를 커버하고 재클릭 해제·`aria-pressed`·`필터 초기화` 가 이미 있다. `?status=` URL 계약은 그대로(칩이 반영). IMP-01 의 `반려 N` 보조 칩과 자리도 겹치지 않게 된다.

**수용 기준.** 상태 필터 진입점이 칩 하나다. `?status=in_progress` 딥링크가 여전히 동작하고 해당 칩이 눌린 상태로 표시된다.

### IMP-07 DYPICK 좌측 검색이 '할 일' 이름을 찾지 못한다

**증거.** `doc-pick.js` `colItems()` 검색이 `it.id + it.name` 만 매칭한다. 담당자는 의무명("종사자 안전보건교육 실시")보다 일 이름("특별교육")으로 기억하는데, 좌측에 "특별교육"을 치면 0건이다. (이행 목록 본문 통합검색은 이미 단계명까지 찾는다 — 선택기만 뒤처져 있다.)

**기획.** 좌측 필터를 확장한다 — 의무명 매칭 **또는** 그 의무의 단계명(`stagesOfItem`) 매칭이면 결과에 남긴다. 단계명으로 걸린 항목은 개수 배지 옆에 `할 일 일치` 힌트를 짧게 표시해 "왜 나왔는지"를 밝힌다. 우측 검색어(`qR`) 자동 주입은 하지 않는다(과잉 동작 — 항목을 고르면 우측이 어차피 그 의무의 전체 목록이라 훑을 수 있다).

**수용 기준.** 업로드 STEP2 좌측에 "특별교육" 입력 → "종사자 안전보건교육 실시" 가 남는다. 소비처 3곳(업로드 STEP2·업무 목록 상세조건·미분류 교정[IMP-03 후]) 모두 동일 동작.

### IMP-08 '취합상태' 필터 라벨에 연도가 없다

**증거.** 취합상태는 **2025 원자료의 투영**인데(CLAUDE.md §5), 이행 목록 상세 조건 라벨이 `취합상태` 라 2026년 화면에서도 현재 축처럼 읽힌다. 업무 목록은 이미 `2025년 취합` 으로 쓴다 — 같은 값을 두 이름으로 부른다.

**기획.** 이행 목록 상세 조건의 라벨·전체 옵션 문구를 `2025년 취합` 으로 통일한다.

## 4. 구현 지침 (공통)

- **판정·저장은 전부 `DYDOCS` 에** — 화면(`doc-exec.js`·`doc-list.js`·`doc-detail-ledger.js`)은 그리기만. IMP-01 의 반려 저장·IMP-02 의 `stageDeptHit` 을 화면에 복제하지 않는다.
- **SKEY(`dy-docs-v1`) 범프 금지** — 신규 필드는 전부 `undefined` 안전 파생.
- **동결 영역 무접촉** — `DYRSKDOC`(§7-1), `sets-data-v2.js`, 생성물(`doc-taxonomy-data.js`·`doc-history-data.js`), `DYWORK`/`DEPTCHK` 판정(§14-2 축 분리).
- **새 클래스는 CSS 실재 확인**(§7-1 사고 재발 방지): 추가·삭제한 `class="…"` 를 `css/v2.css` 정의와 대조해 미정의 0 · 잔존 고아 규칙 0.
- 원시값 금지(§6) · 표준 컴포넌트만(§7) · 문구는 담당자 말로(§5) · 모달은 `DYV2.openModal` 1개(§1).
- **정의서 동기화**: `docs/screen-definitions/SCR-DOC-003_이행목록.md`(반려 축·내 부서 필터·상태 칩 단일화·취합 라벨) · `SCR-DOC-002_업무목록.md`(미분류 교정 모달 DYPICK 전환) — 사실이 달라지는 서술만 고치고 문서 형식은 유지한다.
- **검증**: 두 페르소나(하정수/박안전)로 IMP 별 수용 기준을 브라우저에서 실제 수행. 회귀 — 업로드 3단계, 프리셋 단건/다건, 완료→수정 환원(`needsRecheck`), 미분류 교정 저장, `?stage=`·`?item=`·`?menu=` 딥링크.
