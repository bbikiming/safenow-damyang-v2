# 작업환경측정·건강검진 — 변경 파급 연계 감사

> 2026-09-09 · 대상 도메인 `DYSH`(작업환경측정·건강검진)와 그 연계면
> **이 문서는 감사 기록이다.** 고친 것과 **판정되지 않은 채 남은 것**을 함께 적는다.

---

## 1. 무엇을 감사했나

건강검진 3탭 제거 · 중복검사 수정 · 시드 사업장 연결 · 소관 이동(WE-2026-02) · SKEY 범프가
**다른 화면·집계·문서에 조용히 파급된 곳**을 8축으로 훑었다 — 죽은 참조 / 인력평가 연계 /
업무 자동발행 / 사업장 마스터 / 조회범위·권한 / 법령·외부입력·도움말 / 화면정의서 / 그 밖 화면.

**발견 42건**이 올라왔고 발견마다 3개 렌즈(재현·오탐·영향)로 적대적 검증을 걸었다.

⚠ **검증 197개 중 151개가 세션 한도로 실패했다.** 그래서 «기각»으로 집계된 것 중 상당수는
**판정되지 않은 것이지 반증된 것이 아니다.** 아래 §3 이 그 목록이다.

## 3. 판정되지 않고 남은 것 — 기각이 아니다

세션 한도로 검증이 끊겨 사실 여부를 못 정한 발견이다. **다시 감사할 때 여기서 시작한다.**

| 무엇 | 왜 남겼나 |
|---|---|
| `workEnvLink.completeRate` 소비처 0곳 — 평가자에게 보이는 「이행률」은 측정 실시율이라 개선조치 미완료도 100%로 읽힌다 | 표시 설계 판단이 필요하다. 이번 소관 이동으로 물순환사업소 실제 조치 완료율이 100→50 으로 갈렸는데 화면 수치는 100% 그대로다 |
| 목록 사업장 칸이 마스터명으로 바뀌며 작업 위치(약품동·탈수기실)가 목록에서 빠졌다 | 상세 `대상 근거`에는 남아 있다. 목록에 되살릴지는 밀도 판단 |
| `W-HLT-EXE` 대상 부서(속성 파생)와 실제 검진 계획 부서가 어긋난다 | 속성값 자체가 발주처 확정 대상(§14-5) |
| 30일·60일 법정 제출기한의 근거 조문이 화면 근거에 없다 | 근거 수집 문제(§10) — `oshr-186`·§132 계열 미수집 |
| 시행규칙 §186 이 DYLAW 스냅샷에 없어 칩으로 낼 수 없다 | 동상 |
| 사업장 마스터의 관할 부서를 바꿔도 측정계획 `dept` 스냅샷이 따라가지 않는다 | 스냅샷 보존은 설계 의도(SCR-WEM-001 §4-3)인데 그 `dept` 가 조회 범위 판정의 입력이라 상호작용 검토가 필요 |
| `RSK:survey`·`RSK:improve` 가 work-dept·work-admin 에서 판정 불가 | 이번 범위(작업환경·건강) 밖. `probeAvailable` 수정으로 화면이 그 사실은 정확히 말한다 |
| `js/doc-taxonomy-data.js` typeNote 2줄이 없어진 구현을 서술 | **생성물이라 손대지 않는다** — 분류기준 엑셀 수정 후 `tools/build-taxonomy.py` 재실행 대상 |
| 조사 오표기가 `menu.js`·`edu-reg.js`·`edu-reg-detail.js` 에도 남아 있다 | 다른 도메인 |

## 4. 이 감사가 남긴 교훈

- **연계 결함은 조용하다.** 이번에 나온 것 중 문법 오류나 콘솔 오류를 낸 것은 하나도 없다.
  전부 «값만 틀어지거나 판정이 안 도는» 종류였다.
- **파생 원본을 선언했으면 그 원본이 실린 화면인지 확인한다**(§14-2). `doneProbe` 를 적는 것과
  그 전역이 로드되는 것은 다른 일이고, 후자를 빠뜨려도 아무 신호가 없다.
- **식별값 없이 이름으로 대조하면 반드시 어긋난다.** 시드가 사업장을 이름으로만 갖고 있어
  중복 검사와 사용중 판정 둘이 함께 죽어 있었다.
- **문서가 침묵하는 것보다 반대로 말하는 것이 나쁘다.** 인력평가 §1 은 실재하지 않는 연계를
  적고 실재하는 둘을 빠뜨렸다.
