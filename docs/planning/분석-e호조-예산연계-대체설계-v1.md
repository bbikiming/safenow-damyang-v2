> ## ⚠ 이 축은 **RFP 요구 밖이다 — 1차 연계 범위에서 제외됐다** (2026-09-21 확정)
>
> RFP §3 「외부 연계 시스템 정리」가 **SFR-008 에 배정한 연계는 「전자결재 — 예산 편성/집행 관리 점검표 승인」 하나**이고, SFR-008 본문의 `integrations` 도 `전자결재` 뿐이다. **차세대 e호조가 적혀 있지 않다.**
> 아래 분석이 찾은 것(단일 API `TFE3233A` 로 편성·집행·분기·전년동기 확보)은 **사실이지만 요구가 아니다.** 게다가 시작하려면 담양군이 「무엇이 안전보건 예산인가」를 먼저 지정해야 해(§11 EXT-21) **요구도 아닌 일로 발주처 작업을 유발한다.**
>
> **확정 동작 — 예산 편성액·집행액은 수기 입력을 유지한다.** RFP 대로다.
> **이 문서는 폐기하지 않는다** — 발주처가 나중에 원하면 그때 꺼낸다. 「가능한데 안 한다」와 「모른다」는 다르다.
> §11 의 EXT-21·22 는 **신설하지 않는다**(범위 밖이라 지금 물을 이유가 없다). 범위 정본은 [`결론-e호조-연계-최소범위-v1.md`](결론-e호조-연계-최소범위-v1.md).
>
> 다만 §7-1 의 발견 — **`cse-4-4` 가목이 명시한 「인력」 축이 화면에 없다**(시설·장비·안전장구류만) — 은 **연계와 무관한 기획 이슈**라 그대로 유효하다. RFP SFR-008 도 *"안전/보건 **인력**·시설·장비 현황 관리"* 를 요구한다.

## 0. 한 줄 결론 — 계약과 성질이 정반대다

| | 계약 연계 | **예산 연계** |
|---|---|---|
| 자연키 | `ctrtLdgrMngNo` 하나로 1:1 | **없다** |
| 어려운 곳 | 업체 테이블 찾기(조인 5개) | **매핑표 정하기** |
| 호출 | 7개 API 조인 | **API 1개로 끝난다** |
| 막는 것 | 인증키 | **담양군의 예산 과목 지정** |

**e호조에 「안전보건 예산」이라는 과목이 없다.** 우리 축은 `대상(기관·시설) × 예방항목(시설·장비·안전장구류)`이고 e호조 축은 `부서 × 정책·단위·세부사업 × 세출통계목`이라, 둘이 **직접 대응하지 않는다.** 계약처럼 "받아서 채운다"가 성립하지 않고, **"담양군 예산 중 무엇이 안전보건 예산인가"를 먼저 지정**해야 한다.

바꿔 말하면 — **이 연계의 난이도는 기술이 아니라 합의에 있다.** 그리고 합의만 되면 **단일 API `TFE3233A` 하나**로 편성액·집행액·집행률·분기별·전년동기 비교가 전부 나온다. 지금처럼 수기 입력할 이유가 없어진다.

## 1. 지금 화면이 하는 일 (`js/bgt.js`)

| 축 | 값 | 출처 |
|---|---|---|
| 점검 대상 | 기관(`org`) — 조직도 파생 / **시설(`fac`) — 시설물 대장 파생** | 연계됨 |
| 예방 항목 | 9노드 트리 — 대분류 **시설·장비·안전장구류** + 하위 6 | `bgt-settings` 에서 편집 |
| 시트 | 대상 × 연도 1건. `rows[] = {itemId, plan, exec, note}` | **전부 수기 입력** |
| 단위 | **천원** (`'480,000천원'`) | ⚠ e호조는 **원** |
| 집행률 | `rate = exec / plan` | 파생 |
| 상태 | 작성중 → 결재중 → 승인완료 / 반려 | 온나라 |

**편집 규칙** — 편성액(`plan`)은 `작성중`·`반려`만, 집행액(`exec`)·비고는 `결재중` 제외 상시. 이 규칙이 연계 설계의 제약이 된다(§5-3).

## 3. 축 불일치 — 이 연계의 본론

```
우리                                e호조
─────────────────────────           ─────────────────────────
대상                                 부서 deptCd(7)
 ├ 기관 (조직도)        ←─ 부분대응 ─→   └ 39개 과·사업소
 └ 시설 (시설물 대장)   ←─ ✗ 없음 ──→   (시설 단위 예산 개념 없음)

예방항목 (9노드)                      정책사업 > 단위사업 > 세부사업 dbizCd(16)
 ├ 시설                              └ 목적별 분류  ← 「안전」이 여기 있다
 ├ 장비               ←─ ✗ 없음 ──→
 └ 안전장구류                        세출통계목 aneStmkCd(5)
                                     └ 경제적 성질 분류 ← 「무엇을 샀나」
```

**셋 다 성질이 다르다.**

| | 뜻 | 「안전보건 예산」을 고를 수 있나 |
|---|---|---|
| 세부사업 | **목적** 분류 — 무엇을 하는 사업인가 | **고를 수 있다** — 「재난안전관리」·「시설물 안전점검」 |
| 세출통계목 | **경제적 성질** 분류 — 인건비·물건비·자산취득비 | **고를 수 없다** — 「안전모 구입」과 「사무용품 구입」이 같은 통계목 |
| 부서 | 조직 | 축이 아니다 |

→ **세부사업으로 「안전보건 예산인가」를 고르고, 통계목으로 「3대 분야 중 어디인가」를 가른다.** 두 축을 모두 써야 하고, 어느 하나로는 안 된다.

## 4. 매핑 설계 — 2단 매핑표

### 4-1. 1단 — 어느 세부사업이 안전보건 예산인가 (담양군 지정)

```
dbizCd(16) → 안전보건 예산 여부 (Y/N) + 귀속 대상(기관 or 시설)
```

- **세부사업명 자동 추출로 대신하지 말 것.** 「안전」이 들어간 사업명을 긁으면 「교통안전」·「식품안전」·「안전신문고」가 함께 들어오고, 반대로 「노후 승강기 교체」처럼 이름에 안전이 없는 진짜 안전보건 예산은 빠진다. **후보 제시까지만** 하고 지정은 사람이 한다.
- `TPM1105M.yrlyRpetYn` **연례반복여부**가 후보 좁히기에 쓸 만하다 — 안전보건 예산은 대체로 연례반복이다.

### 4-2. 2단 — 통계목 → 3대 분야

```
aneStmkCd(5) → 시설 / 장비 / 안전장구류 / (인력)
```

경제적 성질 분류라 대체로 기계적으로 갈린다(자산취득비 → 시설·장비, 소모품 성격 → 안전장구류). **다만 담양군 확인 사항이다** — 같은 통계목이 사업에 따라 다른 분야일 수 있다.

### 4-3. 이 매핑표를 어디에 두는가 (MUST)

**`bgt-settings.html` 이 정확히 그 자리다.** 이미 예방 항목 트리를 편집하는 화면이고, §13 갈래 기준(*"그 값을 넣을 화면이 이미 있는가"*)으로 **A(운영 설정)** 다 — 화면을 새로 만들 필요가 없다.

- 매핑을 연계 모듈 안에 배열로 두지 않는다. 담양군이 매년 바꿔야 하는 값이라(세부사업 코드는 해마다 신설·폐지된다) 코드에 박으면 다음 해에 틀린다.
- **매핑 안 된 세부사업을 조용히 버리지 않는다** — 「미분류」로 드러낸다(§5 「미분류·분류 제외를 가른다」와 같은 원칙). 버리면 편성액이 조용히 줄어든다.

## 5. 「집행액」의 정의를 먼저 정해야 한다 (MUST)

지금 화면의 `exec` 는 사람이 적는 숫자라 정의가 없었다. e호조를 붙이는 순간 **정의를 골라야 한다.**

### 5-1. 지출은 4단계다

```
지출품의(TFE2101M) → 지출원인행위(TFE2401M) → 지출결의 → 지급명령(TFE2501M)
   「사겠다」            「계약·의무 부담」        「지급 확정」      「돈이 나간다」
```

### 5-2. `TFE3233A` 는 두 값을 함께 준다

| 값 | 기준 | 성격 |
|---|---|---|
| **`exeAggrAmt` 집행누계금액** | 지출원인행위 | **예산을 썼다** — 계약을 맺어 돈이 묶였다 |
| **`rlexAggrAmt` 실집행누계금액** | 실제 지급 | **돈이 나갔다** |

연말에 계약만 하고 준공이 이듬해면 **둘이 크게 벌어진다.** 어느 쪽을 「집행액」으로 볼 것인가는 담양군 판단이다.

**권고 — 둘 다 보여준다.** 중처법 §4 제4호는 *"편성된 용도에 맞게 집행"* 을 요구하는데, 의무를 부담한 시점(`exeAggrAmt`)이 「용도에 맞게 썼다」에 더 가깝고, 실제 이행은 `rlexAggrAmt` 에 드러난다. **하나만 골라 「집행률」이라고 쓰면 나머지 하나가 영영 안 보인다.** 지금 화면의 단일 프로그레스 바를 2단으로 바꾸는 것이 자연스럽다.

### 5-3. ⚠ 상태머신과 충돌한다

현재 규칙은 **집행액을 `결재중` 제외 상시 수기 입력**이다. 연계가 붙으면 집행액은 **매일 자동으로 바뀌는 값**이 된다.

- **연계값과 수기값을 같은 칸에 넣지 않는다.** 결재 올린 뒤 숫자가 저절로 바뀌면 그게 §7-1 의 *"이건 문서 위조예요"* 다.
- **설계 선택지 2** — ① 결재 시점 값을 **스냅샷**으로 굳히고 연계값은 별도 열(「현재 집행액」)로 나란히 둔다 ② 집행액을 전면 연계 전용(읽기 전용)으로 바꾸고 수기 입력을 없앤다.
- **①을 권고한다.** 점검표는 「그 시점의 보고」라 사후에 숫자가 바뀌면 보고가 아니게 된다. ②는 매핑 안 된 예산을 손으로 보정할 길을 없앤다.

## 6. 시설 축은 채워지지 않는다

지금 시트의 절반이 **시설 단위**다(`담양군민체육관`·`담양하수처리장`). **e호조에 시설 단위 예산 개념이 없다** — 부서까지만 간다.

- 세부사업이 시설별로 쪼개져 있으면 우연히 대응하지만(「○○체육관 시설개선」) **일반적으로 그렇지 않다.** 하나의 세부사업이 여러 시설을 덮는다.
- **안분(按分)하지 말 것.** 시설 3곳이면 1/3씩 나누는 식의 배분은 **측정값이 아닌데 측정값으로 보인다**(§5 「분모가 그 정도로 틀리면 비율을 내지 않는다」와 같은 근거).
- **확정 동작** — 기관(부서) 축만 연계로 채우고 **시설 축은 수기 입력을 유지**한다. 화면이 두 출처를 구분해 밝힌다(`src` 축 — 조직 화면이 `직접 등록`/연계를 구분하려고 남겨 둔 것과 같은 방식).

## 7. 부수 효과 2건

### 7-1. 법정 축 「인력」이 지금 화면에 없다

근거 조문 `cse-4-4` 가목은 *"안전·보건에 관한 **인력**, 시설 및 장비의 구비"* 다. 그런데 화면의 3대 분야는 **시설·장비·안전장구류** — **인력이 빠져 있고 안전장구류가 대신 들어가 있다.**

안전장구류(보호구)는 산안법 §38·§39 의무라 틀린 항목은 아니지만, **`cse-4-4` 를 근거로 걸어 둔 화면이 그 조문이 명시한 세 축 중 하나를 빠뜨리고 있다**(§10 검증 6문 #6 — *"화면이 하지 않는 일을 한다고 쓰지 않았나"* 의 역방향).

**e호조가 이 축을 채울 수 있다** — `TCM1170C.tottAmtLbstYn` **총금액인건비여부**로 인건비 통계목이 식별된다. 안전관리자·보건관리자 인건비, 안전보건 용역비가 여기 잡힌다.

> 이건 **연계와 별개의 기획 결함**이다. 연계를 붙이든 안 붙이든 확인이 필요하다. 다만 «인력 축을 넣자»는 발주처 판단이지 우리가 결정할 일이 아니다 — 지금은 드러내기만 한다.

### 7-2. 계약 ↔ 예산이 이어진다

`TFE2401M 지출원인행위` 가 **`ctrtLdgrMngNo` 를 들고 있다**(계약 문서 §3-4에서 확인). 그래서:

```
안전보건 세부사업 → 지출원인행위 → 계약대장관리번호 → 계약관리대장(TFC1250M)
                                                    → 공동계약내역(업체)
                                                    → 현장대리인·감독자
```

**「이 안전보건 예산으로 누구와 무슨 계약을 했나」가 나온다.** 지금 예산 화면과 도급 화면은 완전히 남남이다. 이건 두 연계를 **함께** 붙일 때만 생기는 가치라, 순서를 정할 때 고려할 값이다.

## 8. 호출 설계

### 8-1. 필요한 API — 4개면 충분하다

| # | 테이블 | 주기 | 용도 |
|---|---|---|---|
| 1 | **`TFE3233A`** | **일** | 편성·집행·분기·전년동기 — **본체** |
| 2 | `TCM1170C 세출통계목코드` | 월 | 2단 매핑 기준 + 인건비 식별 |
| 3 | `TPM1105M 세부사업` | 월 | 1단 매핑 후보 좁히기 |
| 4 | `TCM2060C 부서코드` | 월 | 부서 매핑(계약 연계와 공용) |

`TBM2140M`(요구↔조정·산출근거)·`TBM3450M`(예산변경)은 **2차**다. 편성 과정을 보여줄 화면이 지금 없다.

### 8-2. ⚠ 최대 위험 — 데이터 규모

`TFE3233A` 의 키에 **`exeYmd` 집행일자**가 들어 있다. 이것이 **일별 누계 스냅샷**이면 행 수는

```
세부사업 수 × 통계목 수 × 일수
```

가 되어 **연 수십만~수백만 행**이다. 3,000건 상한이므로 초기 적재가 수백~수천 페이지가 된다.

- **증분(`lastMdfcnBgngYmd`)으로 일 배치는 감당된다.** 문제는 **초기 적재**와 **과거연도 소급**이다.
- **먼저 `totalCnt` 만 확인한다** — `pageSize=1` 로 한 번 호출하면 전체 건수가 나온다. **설계보다 이 숫자가 먼저다.**
- 감당이 안 되면 대안은 `TFE3232A`(가볍지만 부서 없음)가 아니라 **필요한 연도·부서만 받아 우리 쪽에서 최신 `exeYmd` 만 남기는 것**이다.

### 8-3. 단위 변환 (MUST)

**e호조는 원, 우리 화면은 천원이다.** 변환은 **연계 어댑터 한 곳에서만** 한다.
- 화면·집계가 각자 나누면 반올림이 갈려 **합계가 안 맞는다**(항목별 반올림 합 ≠ 전체 반올림).
- **내부 저장은 원 단위로 바꾸는 것이 낫다.** 표시만 천원으로 하면 절사 손실이 없다. 다만 기존 시드·입력값이 전부 천원이라 **마이그레이션 대상**이다(`migrateTargetRefs()` 선례).

## 9. 남는 갭 — 연계해도 채워지지 않는다

| 갭 | 왜 |
|---|---|
| **세부사업 → 안전보건 지정** | 담양군 예산 편성 판단. **자동 추출 금지**(§4-1) |
| **시설 단위 예산** | e호조에 개념이 없다. 안분 금지(§6) |
| **통계목 → 3대 분야** | 대체로 기계적이나 담양군 확인 필요 |
| **「집행액」 정의** | 집행누계 vs 실집행누계 — 발주처 판단(§5) |
| **인력 축** | 화면에 축이 없다. 넣을지가 발주처 판단(§7-1) |
| **점검표 서술** | 비고·사유·개선계획. e호조에 없다 — 수기 유지 |
| **온나라 결재** | 별개 연계 |

## 10. 검증 계획

| # | 호출 | 확인할 것 | 실패 시 |
|---|---|---|---|
| **①** | **`TFE3233A` `pageSize=1`** | **`totalCnt`** — 연간 행 수 · `exeYmd` 가 일별인가 | **규모 설계가 갈린다. 다른 모든 것보다 먼저** |
| ② | `TFE3233A` 1페이지 | `deptNm`·`dbizNm`·`aneStmkNm` 채움률 · `exeAggrAmt` ↔ `rlexAggrAmt` 격차 | 이름이 비면 코드 조인이 되살아난다 |
| ③ | `TPM1105M` | 담양군 세부사업 수 · 「안전」 계열 후보 규모 | 1단 매핑 작업량 산정 불가 |
| ④ | `TCM1170C` | 통계목 수 · `tottAmtLbstYn` 분포 | 2단 매핑·인력 축 불가 |
| ⑤ | `TCM2060C` | 부서코드 ↔ `DYV2.ORG` 11개 매핑 가능 부서 수 | 계약 연계와 공용 — §4-3 |

**①이 압도적으로 먼저다** — 이 숫자에 따라 설계가 「단일 API 로 끝」이 될 수도, 「적재 파이프라인을 따로 만드는 일」이 될 수도 있다.

## 12. 착수 판단

**계약 연계보다 먼저 붙일 수 있다.** 호출이 API 1개고 조인이 없으며, 계약 쪽의 미검증 전제(`TFC1420L` 단독계약 행 존부)에 해당하는 것이 없다.

**다만 순서가 있다.**

1. §10 검증 **①**(`totalCnt`) — 규모부터. 나머지는 이 다음이다
2. **EXT-22**(집행액 정의) 확정 — 화면 구조가 갈린다
3. `bgt-settings` 에 매핑표 UI 추가 — 연계 없이도 값이 있는 작업
4. EXT-21 지정 수령
5. 연계 배선 + §8-3 단위 마이그레이션

**3번은 지금 해도 된다** — 연계와 무관하게 「무엇이 안전보건 예산인가」를 담양군이 적어 둘 자리가 필요하고, 그 자리가 있어야 EXT-21 을 요청할 수 있다. 다만 **§15 대로 「연계 전」 상태를 화면에 만들지 않는다** — 매핑표는 그 자체로 쓸모 있는 운영 데이터이지 연계 예고가 아니다.
