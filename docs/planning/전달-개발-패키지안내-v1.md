# 개발 전달 — 무엇을 어떤 순서로 읽나 v1

작성 2026-08-19 · 이 문서 한 장을 먼저 드리고 나머지를 링크로 잇는다.

---

## 0. 전제 — 이 저장소가 드리는 것과 드리지 않는 것

| 드립니다 | 드리지 않습니다 |
|---|---|
| 화면별 **기능 정의**(구성·트리거·상태·유효성·정책) | 코드 설계·DB 스키마 |
| **어느 값이 연계 데이터이고** 받기 전까지 화면이 어떻게 동작하는가 | 연계 규격 — 어떻게 받아 오는가 |
| 흐름과 화면을 눈으로 볼 수 있는 **프로토타입(예시)** | 동작하는 연계·서버·인증 |

**연계 규격은 적지 않았습니다.** 기획이 정한 것은 **무엇이 외부 정본이고, 받기 전까지 화면이 무엇을 표시하며, 무엇을 성공으로 가장하지 않는가**까지입니다. 그 이음매가 어디인지는 표로 정리해 두었으니 나머지는 개발에서 정하시면 됩니다.

**프로토타입은 예시입니다.** 프로토타입 값과 정의서가 다르면 **정의서가 정본**입니다.

## 2. 화면 정의서 읽는 법

| 절 | 무엇이 있나 | 개발이 쓰는 곳 |
|---|---|---|
| §1·§2 | 화면 정보 · 권한 | 접근 제어 |
| §3 | 진입·이탈 · 시나리오 · **분기 로직** · **예외·경계** | 라우팅과 예외 처리 |
| §4 | 구성별 트리거·동작·이동/메시지 + **상태 목록** | 화면 구현의 본체 |
| §5 | 유효성 검사 표(필수·형식·오류 문구) | 검증 |
| §6 | **정책 — 왜 그렇게 정했는가** | 애매할 때 판단 기준 |
| §7 | 미결사항 | **「없음」이면 기획 확인 없이 착수** |

**§6을 건너뛰지 마십시오.** §4가 「무엇을」이면 §6은 「왜」이고, 구현 중 판단이 갈리는 자리는 대부분 §6에 답이 있습니다.

## 3. 지금 상태

- 화면 정의서 **82건** · 전 정의서 §7 미결 **「없음」**
- 남은 것은 기획이 아니라 **① 연계 데이터가 붙는 것 ② 담양군 제공 자료** 둘입니다.

### 3-1. 연계 데이터 축

외부 시스템이 정본인 값이 **10개 축**이다. 어느 값이 연계 데이터이고 받기 전까지 화면이 어떻게 동작하는지는 [기획-외부연계-기능정의-v1.md](기획-외부연계-기능정의-v1.md) §3에 한 표로 있고, 각 축의 정본 기능 정의는 그 표가 가리키는 화면 정의서에 있다.

**연계 규격은 이 저장소에 없다.** 어떻게 받아 오는가는 개발이 정한다 — 기획이 정한 것은 **무엇이 외부 정본이고, 받기 전까지 화면이 무엇을 표시하며, 무엇을 성공으로 가장하지 않는가**까지다.

### 3-2. 담양군 제공 자료

- 부서 명단 — **현재 11 / 대상 39** (화면이 갭을 상시 노출합니다)
- 현업업무 종사자 지정명단 · 관리감독자 지정일
- 기관정보·관인 · 담양군 적용 관계 법령 목록 · 기록관리 기준

**미확보 항목은 화면에서 「미등록」으로 드러납니다.** 그럴듯하게 채워 두지 않았습니다 — 빈자리가 보여야 결정이 넘어갑니다.

## 4. 특히 어긋나기 쉬운 계약 5

구현 중 되묻게 되는 자리라 앞에 모읍니다. 전부 §6에 근거가 있습니다.

1. **성공을 가장하지 않는다** — 동기화·발송·상신이 실제로 일어나지 않았으면 성공 문구를 쓰지 않습니다. 「받았는데 0건」과 「한 번도 안 받음」을 같은 문구로 쓰지 않습니다.
2. **정본이 밖에 있는 값은 만들지 않는다** — 명단·조문·시설물 제원. 연계 수신분은 읽기 전용이고 보완값은 별도 축이며, **출처를 행마다 표시**합니다.
3. **지우지 않고 사용중지한다** — 조직·양식·항목·사업장 전부. 물리 삭제하면 과거 권한·업무·결재 참조가 끊깁니다.
4. **소급하지 않는다** — 양식을 바꿔도 기존 문서는 당시 버전으로 보이고, 규칙을 바꿔도 이미 나간 알림은 그때의 규칙으로 나간 것입니다.
5. **상태판과 작업 화면을 섞지 않는다** — 연계 관리는 「지금 연결이 살아 있는가」만 답하고, 수신·검토·반영·파라미터는 도메인 화면이 갖습니다. 재시도는 연계 관리 한 곳뿐입니다.
