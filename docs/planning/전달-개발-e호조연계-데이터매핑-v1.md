# e호조+ 연계 — 무엇을 받아 어디에 넣는가

> 2026-09-21 · 개발 전달용 요약
> 근거: RFP SFR-007 · SFR-010 · SFR-013 · 화면 동작 정의는 `SCR-SBM-004`(도급관리) · `SCR-SBM-002`(조직)

---

## 1. 한 줄

**e호조+ 계약 원장을 받아 「도급관리 목록」과 「조직 > 공사별 안전관리자 선임 현황」 두 화면을 채운다.** 받는 값은 **8개**다.

**예산은 연계하지 않는다** — RFP가 예산(SFR-008)에 배정한 연계 대상은 **전자결재**이고 e호조가 아니다. 예산 화면은 수기 입력을 유지한다.

---

## 2. 받아오는 것

### 쓰는 API 3개

| 테이블 | 무엇 | 주기 |
|---|---|---|
| **`TFC1250M` 계약관리대장** | 계약 목록 본체 | **매일** |
| `TCM3030C` 공통상세코드 | 계약종류코드 → 한글 이름 | 월 1회 |
| `TCM2060C` 부서코드 | 부서코드 → 부서 이름 | 월 1회 |

> `TFC1250M` 은 계약(FC) 테이블이지만 **호출 경로가 `/FE/openAPI/TFC1250M`** 이다. `/FC/` 가 아니다.

### 받는 값 8개

| # | 받는 값 | e호조 필드 | 형식 | 비고 |
|---|---|---|---|---|
| 1 | **계약 식별자** | `ctrtLdgrMngNo` 계약대장관리번호 | 문자 12 | **키.** 계약이 바뀌어도 안 바뀐다 |
| 2 | 사업명 | `ctrtTrgtNm` 계약대상명 | 문자 300 | |
| 3 | 구분 | `ctrtKndCd` 계약종류코드 | 문자 1 | **코드 — §4-1** |
| 4 | 담당부서 | `deptCd` 부서코드 | 문자 7 | **코드 — §4-3.** 빌 수 있다 |
| 5 | 계약기간 시작 | `bgcsYmd` 착공일자 | 날짜 8 | **빌 수 있다 — §4-2** |
| 6 | 계약기간 종료 | `cmcnScdYmd` 준공예정일자 | 날짜 8 | **이 값 때문에 연계한다** |
| 7 | 계약금액 | `smzCtrtTottAmt` 총괄계약총금액 | 숫자 | **원 단위** |
| 8 | 계약일 | `smzCtrtYmd` 총괄계약일자 | 날짜 8 | |

### 저장만 하고 화면에 안 내는 값 2개

같은 응답에 딸려 오므로 버리지 않는다.

| 값 | e호조 필드 | 쓰임 |
|---|---|---|
| 계약 해지 여부 | `ctrtCnltYn` | **해지된 계약은 점검 대상에서 뺀다.** 끝난 계약의 점검표를 만들면 안 된다 |
| 현장 위치 | `lctnNm` 위치명 | 보관만. 화면에 낼지는 나중 판단 |

## 3. 어느 화면 어느 항목에 넣나

### 3-1. 도급관리 목록

| 화면 항목 | 넣는 값 |
|---|---|
| 사업명 | ② 사업명 |
| 구분 | ③ 구분 (코드 변환) |
| **수급업체** | **연계 안 됨 — 담당자가 직접 입력** (§5) |
| 계약기간 | ⑤ ~ ⑥ |
| 계약금액 | ⑦ |
| 담당부서 | ④ (코드 변환) |
| 출처 | **이미 사업명 아래에 표시된다** — 지금 `계약정보시스템 4173` 로 나오는 자리를 `e호조 {계약대장관리번호}` 로 바꾼다. 새 열이 아니다 |
| 점검표 · 서약서 | 연계 아님 (기존 그대로) |

- **e호조에서 온 행은 위 값들을 고칠 수 없다.** 원본이 e호조에 있어 고쳐도 다음 날 덮인다. 잘못된 값은 e호조에서 고친다.
- **수급업체·점검표·서약서는 e호조 행에서도 입력할 수 있다.** 연계로 오지 않는 값이다.
- **직접 등록은 없애지 않는다.** RFP SFR-013이 *"타 회계 시스템 이용 시 직접 등록 기능을 제공한다"* 로 명시 요구한다.

### 3-2. 조직 > 공사별 안전관리자 선임 현황

RFP가 요구한 5개 항목 중 **4개는 연계, 1개는 직접 등록**이다.

| 화면 항목 | 넣는 값 |
|---|---|
| 발주처 | **고정값 `담양군`** — 담양군 계약만 받으므로 따로 받지 않는다 |
| 공사명 | ② 사업명 |
| 공사기간 | ⑤ ~ ⑥ |
| 공사금액 | ⑦ |
| **안전관리자** | **연계 안 됨 — 담당자가 직접 입력** (§5) |
| **출처** | **표시 자리가 없다 — 새로 만든다.** 도급관리와 달리 이 표에는 출처 표기가 전혀 없다 |
| 점검상태 | 우리 점검 상태 (미시행 → 진행 → 완료). 계약 상태가 아니다 |

- **e호조에서 온 행은 안전관리자만 고칠 수 있다.**
- 같은 공사가 연계·직접 등록 양쪽에 있을 수 있다. **자동으로 합치지 않는다** — 담당자가 정리한다.

## 4. 값을 넣기 전에 바꿔야 하는 것

### 4-1. 구분 — 코드를 우리 5분류로 옮긴다 ⚠ **미확정**

`ctrtKndCd` 는 **한 글자 코드**이고, 우리 화면의 5분류(**공사 / 용역 / 구매설치 / 위탁 / 기타**)와 **1:1인지 아직 모른다.**

- `TCM3030C` 에서 코드의 한글 이름을 받아, 그것을 우리 5분류로 옮기는 **변환표**를 만든다.
- **변환표는 설정값으로 둔다** — 코드에 박아 두면 e호조 코드 체계가 바뀔 때 화면만 옛 분류로 남는다.
- **변환표에 없는 코드는 `기타`로 넣고 원래 코드를 함께 남긴다.** 버리면 그 계약이 목록에서 사라진다.
- 1:1이 아니면 함께 오는 `cstcDvCd`(공사구분코드)·`ctrtOpslDvCd`(계약목적물구분코드)를 조합해 가른다.

**실제 코드값은 첫 호출 때 확인한다**(§7).

### 4-2. 계약기간 시작 — 비면 계약일로 대신한다

용역·구매설치·위탁은 **착공이라는 개념이 없어** `bgcsYmd` 가 빈다.

```
계약기간 시작 = 착공일자가 있으면  → 그 값
              없으면           → 계약일(⑧) + 화면에 「계약일 기준」 표시
```

**지어내지 않는다.** 대신 넣었다는 사실이 화면에 보여야 한다.

### 4-3. 담당부서 — 코드를 우리 조직도에 잇는다

e호조 부서코드는 **7자리 숫자**이고 우리 조직도는 이름으로 관리한다. 조직도 쪽에 **e호조 부서코드 칸을 추가**해서 잇는다.

- ⚠ **우리 조직도에 등록된 부서는 11개인데 담양군 과·사업소는 39개다.** 계약은 39개 전부에서 나온다.
- **이어지지 않는 부서의 계약을 버리지 말 것** — 「조직도 미등록」으로 표시한다. 버리면 그 부서 도급사업이 화면에서 통째로 사라진다.

### 4-4. 금액 — 원 단위다

`smzCtrtTottAmt` 는 **원** 단위로 온다. 도급관리 화면도 원 단위라 그대로 쓴다.

## 5. 연계로 채워지지 않는 것 — 직접 등록을 유지한다

| 항목 | 왜 |
|---|---|
| **안전관리자** | e호조는 재정 시스템이라 **산안법 선임 정보가 없다.** 계약에 붙는 사람으로 「현장대리인」·「계약감독자」가 있지만 **둘 다 안전관리자와 다른 지위**다. 그 값을 안전관리자 칸에 넣으면 **선임이 비어 있는 공사가 선임된 것처럼 보인다** — 법정 의무 미이행이 이행으로 둔갑한다 |
| **수급업체** | RFP가 요구하지 않았고, e호조 계약대장에도 업체 칸이 없다(다른 테이블에 있다). **업체가 빈 계약은 수급인 평가 대상에 오르지 않으므로**, 화면이 「업체를 입력하면 평가 대상이 됩니다」로 안내한다 |
| 점검표 · 서약서 · 평가 | 우리 시스템이 만드는 것이다 |

## 6. 이번에 하지 않는 것

| | 이유 |
|---|---|
| **예산 편성·집행 연계** | **RFP가 요구하지 않았다** (SFR-008의 연계 대상 = 전자결재) |
| 하도급 · 입찰 · 대금지급 · 하자 · 지체상금 | e호조에서 받을 수 있으나 **RFP 요구가 아니다** |
| 현장대리인 · 계약감독자 | §5 — 안전관리자로 쓰면 안 된다 |
| **점검 대상 자동 선별** | 어떤 계약을 점검 대상으로 볼지(금액·기간·구분)는 **담양군이 정할 기준**이고 아직 정해지지 않았다. **목록에는 다 받아 두고 점검 대상은 담당자가 고른다** |

**범위를 넓히려면 RFP 문언 근거를 먼저 확인한다.**

## 7. 받기 시작하기 전에 확인할 것 2가지

| | 확인 | 안 되면 |
|---|---|---|
| **①** | `TFC1250M` 을 2026년으로 호출해 **준공예정일자가 실제로 채워져 오는지** · 계약종류코드의 실제 값 | **준공예정일자가 비면 연계해도 계약기간을 못 채운다** — 그 값 하나 때문에 하는 일이다. 코드값이 5분류와 안 맞으면 §4-1 변환표를 다시 짠다 |
| ② | `TCM2060C` 부서코드 체계 · 우리 조직도 11개와 몇 개나 이어지는지 | §4-3을 설계할 수 없다 |

**①의 결과에 따라 범위가 달라질 수 있으므로, 개발 착수 판단은 이 호출 뒤에 한다.**

## 8. 담양군에서 받아야 하는 것

| 항목 | 어디서 |
|---|---|
| 서비스 주소·포트 | 별도 공지 |
| **API 인증키** | e호조+ 자치단체게시판(**81707**) 「자체시스템 API 연계 관련 파일 배포」. 첨부가 안 보이면 담양군 **기준정보관리자**가 81708 에서 첨부파일 사용 설정 |
| 암복호화 키 | 위와 같은 곳 (문서 암호는 통합콜센터 1522-7536) |

**이번 8개 값에는 암호화된 항목이 없어 암복호화 키가 없어도 된다.** 다만 나중에 수급업체(사업자등록번호)를 붙일 때 필요하니 함께 받아 두는 편이 낫다.

**인증 정보를 받기 전까지 두 화면은 직접 등록만으로 동작한다.** 화면에 「연계 예정」 같은 표시를 만들지 않는다 — 그렇게 보이면 담당자가 등록을 미루고, 미룬 만큼 도급 현장이 목록에서 빠진다.

## 9. 화면에서 바뀌는 것

값만 채우면 끝나지 않는다. **지금 두 화면은 「등록한 소수 건」을 전제로 만들어져 있다.**

### 9-1. ⚠ 가장 큰 변경 — 「점검 대상」이라는 축이 새로 필요하다

지금은 **등록한 사업 = 점검 대상**이다. 담당자가 손으로 넣은 것만 목록에 있으니 그게 성립했다.

연계가 붙으면 **계약이 통째로 들어오는데 그 전부가 점검 대상은 아니다.** 담양군 계약은 연 4,000건대이고 155만원짜리 폐기물처리용역까지 들어 있다. 무엇을 점검 대상으로 볼지는 담양군이 정할 기준이고 **아직 정해지지 않았다**(§6).

그래서 **「이 계약을 점검 대상으로 본다」는 표시**가 필요하다.

- **자동으로 거르지 않는다** — 기준이 없으므로 시스템이 정하면 실측과 어긋난다.
- **담당자가 목록에서 고른다.** 고른 것만 점검표·서약서·평가 대상이 된다.
- 이 축이 없으면 **요약 지표가 무의미해진다** — 지금 요약은 목록 전건에서 세므로 「점검표 미작성 3,842」 같은 숫자가 뜬다. 남은 일을 알려 주는 자리가 읽을 수 없는 숫자가 된다.

> 기준이 정해지면 그때 자동 선별을 얹는다. **지금 만들 것은 「고르는 수단」이지 「거르는 규칙」이 아니다.**

### 9-1-1. ⚠ 같이 고쳐야 하는 것 — 점검표에 회차가 없다

도급 점검은 **반기 1회**인데, 점검 기록이 **계약 단위로만** 묶여 있어 회차 축이 없다. 계약기간이 여러 반기에 걸치면(2026-03 ~ 2027-08 용역) **한 반기의 점검표를 쓰는 순간 남은 반기까지 「작성완료」로 보인다.**

- 같은 점검표 서식을 쓰는 다른 세 화면(경영방침·이행관리·안전보건교육)은 **모두 제목에 「2026 상반기」를 담는데 도급관리만 없다.**
- **제목만 고치면 안 된다** — 기록을 묶는 식별값에도 회차가 들어가야 실제로 갈라진다.
- **연계 없이도 이미 결함이다.** 지금 드러나지 않는 건 등록된 사업의 계약기간이 대부분 비어 있어서고, **연계로 기간이 채워지면 곧바로 드러난다.**

**축이 둘이라는 것을 지킨다.**

| 축 | 단위 | 묻는 것 |
|---|---|---|
| 점검 대상 판정 | **계약** | 이 계약은 점검할 만한가 |
| 점검 수행 | **회차(반기)** | 그 반기에 점검했나 |

**그 회차의 점검 대상 = 판정이 「대상」 + 계약기간이 그 반기와 겹침.** 기간이 지났거나 해지된 계약은 그 회차에서 빠진다.

### 9-2. 도급관리

| 바뀌는 것 | 지금 | 뒤 |
|---|---|---|
| **검색·페이징** | **없다** — 전건을 한 번에 그린다 | **새로 필요하다.** 수천 건이 들어오면 화면이 무너진다 |
| **점검 대상 표시** | 없다(등록 = 대상) | **새로 필요하다** (§9-1) |
| 요약 지표 | `등록 사업` · 수급업체 · 점검표 미작성 · 수급인 미평가 — **전건에서 센다** | 「대상 사업」으로 라벨을 바꾸고 **점검 대상으로 고른 것**에서 센다. 미작성은 **이번 회차** 기준(§9-1-1) |
| 목록 안내 문구 | *"공개 목록에서 옮겨 적은 계약… 자동으로 받아오는 연계는 없으므로"* + *"계약기간은 목록 화면에 없어 N건 미확인"* | **둘 다 사실이 아니게 된다 — 전면 교체** |
| 출처 표기 | 사업명 아래 `계약정보시스템 4173` | `e호조 {계약대장관리번호}` |
| 빈 상태 문구 | *"아직 등록하지 않았다는 뜻입니다"* | 받지도 등록하지도 않은 상태로 고쳐 쓴다 |
| [수정] | 모든 항목 수정 가능 | e호조 행은 **수급업체만** 수정 |
| 등록 폼 안내 | *"받아오는 경로가 없습니다"* | *"e호조에 없는 사업을 담는 자리입니다"* |
| 수급업체 빈 행 | 해당 없음 | **평가 대상에 오르지 않는다** — 그 사실을 표시하고 입력을 유도 |

### 9-3. 조직 > 공사별 안전관리자 선임 현황

| 바뀌는 것 | 지금 | 뒤 |
|---|---|---|
| **출처 열** | **없다** | **새로 만든다** — 표에 출처 표기가 전혀 없다 |
| 검색·페이징 | 없다 | 공사 건수에 따라 필요 |
| 안내 문구 | *"담당자가 직접 등록한 것만 표시합니다. 계약 시스템에서 자동으로 들어오는 경로가 없으므로"* | **사실이 아니게 된다 — 교체** |
| [수정] | 모든 항목 | e호조 행은 **안전관리자만** |
| 미선임 표시 | 등록 시 담당자가 채움 | **e호조 행은 미선임으로 들어온다** — 선임 공백이 한꺼번에 드러난다 |

> 마지막 줄은 결함이 아니라 **이 연계의 효과**다. 지금은 등록하지 않은 공사의 선임 공백이 아예 안 보인다.

### 9-4. 시스템 관리 > 연계 관리

카드 **4장 → 5장**(e호조+ 추가). 인증 정보를 받기 전에는 **「미설정」**으로 두고 정상·지연·실패 어느 것으로도 표시하지 않는다.

### 9-5. 바뀌지 않는 것

점검표(서식)·서약서 첨부·수급인 평가·개선조치 연결은 **그대로다.** 연계는 목록을 채울 뿐 그 뒤 업무 흐름을 건드리지 않는다.
