# 통합 시나리오 QA — 노션 템플릿 설계 v1

- 작성: 2026-09-30
- 목적: [검수-QA통합시나리오-3역할-v1.md](검수-QA통합시나리오-3역할-v1.md) **v2.2**(운영 화면 기준)를 노션에서 세 사람이 함께 쓰는 템플릿으로 옮기기 위한 설계. 노션 커넥터로 직접 만들거나, 가져오기(ZIP)로 넣을 때 이 문서를 그대로 따른다.
- ⚠ **원본은 반드시 v2.2** 다. 문서 첫 줄의 버전이 v2.2가 아니면(예: v1.2 — 프로토타입 기준 · 토글 버전) 옛 판이므로 만들지 말고 멈춘다. v1.x 는 운영 서버에서 진행되지 않는 단계가 절반이다.
- 오류 시트 원본: [검수-QA통합시나리오-오류취합.csv](검수-QA통합시나리오-오류취합.csv)

## 1. 왜 문서 한 장이 아닌가

- 4만 자가 한 페이지라 자기 차례를 찾으려면 스크롤해야 한다.
- 세 사람이 같은 체크박스를 누르므로 누가 어디까지 했는지·전체 진행률을 볼 수 없다.
- 오류 시트와 단계가 연결돼 있지 않다.

노션의 QA·UAT 템플릿은 공통으로 **테스트 케이스 DB(한 줄 = 한 단계) + 상태별·테스터별 보기 + 별도 결함 DB(관계 연결)** 구조다. 그 구조를 따른다.

## 2. 구조

```
🛡 통합 시나리오 QA (허브)
├─ 📋 시나리오 단계   ← DB · 한 줄 = 한 사람이 한 번에 하는 일
├─ 🐞 오류 취합       ← DB · 폼으로 신고
├─ A 정기 위험성평가 / B 수시 위험성평가 / C 안전보건교육 / D 나머지 메뉴 / Z 마무리   ← 안내 쪽
└─ 📎 참고 (브라우저 설정 · 진행 규칙 · 이슈 후보 · 결함이 아닌 것)
```

**단계 본문은 DB에만 둔다.** 안내 쪽에 단계를 다시 적지 않는다(두 곳에 있으면 한쪽만 고쳐진다).

## 3. 📋 시나리오 단계 DB

### 줄을 나누는 규칙 (MUST)

**한 줄 = 담당 한 명 · 결과 하나.** 원본의 한 단계를 두 사람 이상이 하면 사람별 줄로 쪼갠다. 91단계 → 약 130줄.

| 원본 | 줄 |
| --- | --- |
| 담당이 한 명인 단계 (예: A-18) | 1줄 — `A-18 부서로 전달` |
| 🟩🟧 두 부서가 각자 하는 단계 (예: A-4) | 2줄 — `A-4 도착 확인 (부서1)` · `A-4 도착 확인 (부서2)` |
| 한 단계 안에서 차례로 주고받는 단계 (A-29 · A-33 · B-10 · C-25) | 주고받는 횟수만큼 — `A-29 ① 두 번째 반려` · `A-29 ② 재제출` · `A-29 ③ 확인` |
| D-1 ~ D-6 (요청 → 부서 → 확인) | 메뉴마다 `D-2 ① 계획 등록(하늘)` · `D-2 ② 증빙·완료(김유석)` · `D-2 ② 증빙·완료(이경진)` · `D-2 ③ 확인(하늘)` |
| Z-1 · Z-2 · Z-4 (전원) | 사람별 3줄 |

### 속성

| 속성 | 유형 | 채우는 법 |
| --- | --- | --- |
| 단계 | 제목 | `번호 + 짧은 이름` — 예: `A-18 부서로 전달` |
| 순서 | 숫자 | 전체 진행 순서. A=100번대, B=200, C=300, D=400, Z=500. **A-⑤ 는 번호순이 아니라 실제 주고받는 순서**(A-21 → A-23 → A-24 → A-22 → A-25 → A-26 → A-27 → A-28 → A-29)로 매긴다 |
| 흐름 | 선택 | A 정기 위험성평가 / B 수시 위험성평가 / C 안전보건교육 / D 나머지 메뉴 / Z 마무리 |
| 묶음 | 선택 | 원본의 `## A-① 평가 만들기` 등 제목 그대로 |
| 담당 | 선택 | 🟦 하늘(파랑) / 🟩 김유석(초록) / 🟧 이경진(주황) |
| ⏳ 시작 신호 | 텍스트 | 이 줄을 시작해도 되는 조건 — 앞 단계의 💬 에서 파생. 예: `하늘의 [A-18] 알림을 받은 뒤` / `앞 단계에 이어서 바로` |
| 📍 메뉴 | 텍스트 | 원본 `📍 메뉴` 줄 |
| 🖱 할 일 | 텍스트 | 원본 `🖱 할 일` 줄 (쪼갠 줄은 그 사람 몫만) |
| ✔ 이러면 정상 | 텍스트 | 원본 `✔` 줄들을 줄바꿈으로 이음 |
| 📝 본 대로 적기 | 텍스트 | 원본 `📝` 줄. 없으면 빈칸 |
| ⚠ 이슈 후보 | 텍스트 | 원본 `⚠` 줄. 없으면 빈칸 |
| 💬 끝나면 알리기 | 텍스트 | 원본 `💬 채팅방에 알리기` — `→ 받는 사람: «쓸 말»` |
| ➡ 다음 | 텍스트 | 다음 단계 번호와 담당. 예: `A-19 (김유석 · 이경진)` |
| 결과 | 선택 | 시작 전(회색·기본값) / 성공(초록) / 실패(빨강) / 보류(노랑) / 확인 불가(갈색) |
| 메모 | 텍스트 | 테스터가 적는 칸 (빈칸) |
| 오류 | 관계 → 🐞 오류 취합 | 연결된 오류 |

### 보기

| 보기 | 종류 | 조건 |
| --- | --- | --- |
| 📖 전체 순서 | 표 | 묶음으로 그룹 · 순서 오름차순 · 보이는 칸: 단계 · 담당 · 결과 · ➡ 다음 |
| 🟦 하늘 | 표 | 담당 = 하늘 · 결과 = 시작 전 · 순서 오름차순 |
| 🟩 김유석 | 표 | 담당 = 김유석 · 〃 |
| 🟧 이경진 | 표 | 담당 = 이경진 · 〃 |
| 🚦 진행 보드 | 보드 | 결과로 그룹 |
| ⚠ 이슈 후보 | 표 | ⚠ 이슈 후보가 비어 있지 않음 |

줄을 누르면 옆 창(side peek)에 속성이 📍 → 🖱 → ✔ → 📝 → ⚠ → 💬 → 결과 → 메모 순으로 세로로 보이게 속성 순서를 맞춘다.

## 4. 🐞 오류 취합 DB

CSV의 10개 컬럼 그대로 + 관계 1개.

| 속성 | 유형 | 값 |
| --- | --- | --- |
| 제목 | 제목 | 한 줄 요약 |
| 단계 번호 | 텍스트 | A-6 … |
| 단계 | 관계 → 📋 시나리오 단계 | |
| 메뉴 | 선택 | 정기 위험성평가 / 수시 위험성평가 / 안전보건교육 / 업무 관리 / 작업환경·건강 / 안전보건관리체계 / 의견청취 / 관리대상 / 대시보드·내 할일 / 공통 |
| 기능 | 텍스트 | 화면·버튼 |
| 유형 | 선택 | 오류 / 동작 다름 / 권한 / 문구 / 알림·내 할일 미도착 / 문의 |
| 내용 | 텍스트 | 한 일 → 기대 → 실제 |
| 역할 | 선택 | 재난안전과 / 부서1 / 부서2 |
| 발견자 | 선택 | 하늘 / 김유석 / 이경진 |
| 캡처 | 파일과 미디어 | |
| 상태 | 선택 | 확인 전 / 접수 / 확인 중 / 수정 완료 / 결함 아님 / 재현 안 됨 |

- 미리 넣는 줄: CSV의 2건(A-6 · D-3, 상태 «확인 전»).
- 보기: 전체(표) · 상태별(보드) · 메뉴별(표, 메뉴로 그룹).
- 폼 보기 «오류 신고»: 제목 · 단계 번호 · 메뉴 · 유형 · 내용 · 캡처만 묻는다.

## 5. 🛡 허브 페이지 (위에서 아래로)

1. 안내 상자 — 운영 서버 주소 · 엣지로만 테스트 · 만드는 것은 «통합_»으로 시작
2. 3단 역할 카드(파랑·초록·주황 안내 상자) — 이름 · 부서 · 계정 · «내 차례» 보기 링크
   - 🟦 하늘 · 재난안전과 · QA박안전1 / 🟩 김유석 · 물순환사업소 · QA하정수1 / 🟧 이경진 · 공공시설사업소 · QA하정수3
   - 결재선: QA박안전2(검토) · QA박안전3(결재) — 고르기만 한다
3. 시작 전 확인 — 원본의 체크박스 5개
4. 흐름 — A · B · C · D · Z 안내 쪽 링크와 단계 수
5. 진행 현황 — 📋 DB의 🚦 진행 보드(또는 흐름별 결과 집계)
6. 🐞 오류 신고 — 폼 링크 + 오류 DB 전체 보기
7. 참고 링크

## 6. 흐름 안내 쪽 (A · B · C · D · Z)

원본의 각 흐름 머리 부분만 옮긴다.

- «들어가는 곳» · «무슨 일인가» · 흐름 한 줄(코드 블록)
- «이번에 만드는 것» 표 — A: 개선조치 6건과 두 부서의 길 / B: 수시 4건 / C: 사람 8명 + «누가 무엇을 하나»
- 그 흐름으로 거른 📋 시나리오 단계 보기(묶음으로 그룹)

## 7. 📎 참고 쪽

원본에서 그대로: «2. 브라우저 설정 — Microsoft Edge» · «3. 진행 규칙» · «참고 — 이슈 후보 모아 보기» · «참고 — 결함이 아닌 것». 각각 토글 제목으로 접는다.

## 8. 만드는 순서

1. 원본 버전이 v2.2인지 확인한다.
2. 허브 페이지를 만든다(위치는 사용자에게 묻는다).
3. 📋 시나리오 단계 DB를 속성·선택값·색까지 만들고 줄을 넣는다(§3 규칙대로 쪼갠다).
4. 🐞 오류 취합 DB를 만들고 2건을 넣는다. 두 DB를 관계로 잇는다.
5. 안내 쪽 5개와 참고 쪽을 만든다.
6. 보기·폼·허브 3단 배치를 만든다. **도구로 만들 수 없는 것은 만들지 못했다고 밝히고**, 사용자가 직접 할 일을 목록으로 남긴다.
7. 검산: 줄 수, 흐름별 줄 수, 담당별 줄 수, 원본 단계 번호 91개가 모두 들어갔는지.
