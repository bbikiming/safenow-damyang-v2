## 1. 왜 바꿨나

### 1-1. 종전 흐름의 문제

| 문제 | 무엇이 일어났나 |
|---|---|
| 부서 조치 내용을 재난안전과가 대신 썼다 | 재난안전과가 용역 보고서를 읽고 부서별 작성표를 채워 «전달»했다. 부서는 받은 것을 처리만 해서 **자기 시설의 위험을 직접 적은 기록이 없었다.** 재난안전과 한 사람이 20여 개 부서 몫을 적느라 평가가 거기서 멈췄다 |
| 부서에 처음 알리는 때가 흐렸다 | 평가 생성 · 양식 첨부만으로 부서에 알림 · 할 일이 갔다. 공문 없이 시스템 알림만 받은 부서는 «정식 요청인지» 알 수 없었다 |
| 확인 없이 끝났다 | 부서가 개선조치 완료를 누르면 아무도 증빙을 보지 않고 평가가 «완료»가 됐다 |
| 다음에 무엇을 할지 보이지 않았다 | 한 화면에 단계가 아홉 개 넘게 쌓여, 접속한 담당자가 지금 눌러야 할 버튼을 찾지 못했다(1차 교육 관찰) |

### 1-2. 목표

1. **요청은 공문으로, 작성은 부서가** — 설문조사표 요청 · 조치 요청 두 번을 온나라 공문으로 보내고, 보내는 순간 부서에 할 일이 생긴다. 조치 내용은 요청받은 부서가 작성표에 직접 적는다.
2. **확인까지 해야 끝난다** — 재난안전과가 건마다 증빙을 보고 확인 · 반려한다. 확인이 남았으면 평가는 «확인 대기»다.
3. **지금 할 일 하나를 보인다** — 접속한 담당자에게 지금 눌러야 할 버튼 하나를 강조하고, 기다리는 단계에서는 무엇을 기다리는지 말한다.
4. **그 밖은 지금 운영 그대로** — 2차 교육 흐름에 꼭 필요한 것만 바꾼다(11-13 답신 원칙). 운영에 없는 단계를 새로 만들지 않는다.

### 1-3. 설계 원칙

| 원칙 | 뜻 | 이 원칙 때문에 정한 것 |
|---|---|---|
| 지금 운영 그대로 | 흐름 전환에 필요한 것 말고는 운영 규칙(권한 · 알림 순서 · 수동 기록 · 재촉 응답 · 관리자 삭제)을 바꾸지 않는다 | 참여 근로자 입력 · 근로자 공유 기록을 거둠(§7-3) · 알림 순서 «담당자 → 부서장» 유지 |
| 기존 화면 최대한 유지 | 새 메뉴 · 새 화면 · 새 입력 화면을 만들지 않는다. 종전 작성표 · 부서별 조치 표 · 평가 카드를 그대로 쓰고 **순서와 주체만** 바꾼다 | 부서 작성 = 종전 작성표의 자기 부서 칸 · «전달» = 부서별 [입력 완료] |
| 공문을 보내는 순간이 요청이다 | 부서 할 일 · 알림은 공문을 온나라로 보낸 순간에만 생긴다. 보내기에 실패하면 만들지 않는다 | 생성 · 양식 첨부 · 보고서 등록만으로는 부서에 아무것도 가지 않는다 |
| 같은 입력은 한 곳에서 | 같은 값을 두 화면에서 받지 않는다 | 개선 후 사진 · 완료일 · 서명은 개선조치 카드 [완료 처리] 한 곳(작성표에서 걷음) |
| 판정은 한 곳에서, 진입 · 저장 양쪽에 | 버튼을 감추는 것만으로 막지 않는다. 같은 판정을 화면과 저장이 함께 본다 | 순서 가드 표(§3-3)의 모든 줄 |
| 눌러도 거절되는 버튼을 두지 않는다 | 할 수 없는 일은 버튼 대신 «누가 · 언제 하는지»를 밝힌다 | 마감된 설문의 제출 카드 · 기한 초과 없는 [기한초과 재촉] · 완료한 건의 [담당자 지정]을 내지 않음 |

## 3. 정기 위험성평가

### 3-1. 흐름 — 8단계

```
① 생성 → ② 대상 · 일정 → ③ 설문조사표 요청 공문 → ④ 부서 제출
   → ⑤ 용역 보고서 + 부서별 조치기한 → ⑥ 조치 요청 공문(개선 필요 부서만)
   → ⑦ 부서 작성 · [입력 완료] → 조치 · 완료 처리 → ⑧ 완료 확인 → 결과 공문
```

| 단계 | 누가 | 무엇을 | 결과 |
|:--:|---|---|---|
| ① 생성 | 재난안전과 담당자 | `[＋ 정기평가 생성]` → 마법사 | 평가 1건 «진행중». **부서에는 아무것도 가지 않는다** |
| ② 대상 · 일정 | 〃 (같은 마법사) | 대상 부서(조직도, 기본 전체) · 부서별 점검일(필수, 일괄 적용 가능) · 설문 제출 기한(필수, 오늘 이후) | 점검일이 설문 기한보다 이른 부서가 있으면 **알리기만**(점검 전에 작성본이 들어와야 하므로) |
| ②-1 정보 수정 · 삭제 | 재난안전과 담당자 | 설문 요청 공문 **전**에만 `[평가 정보 수정]` · `[평가 삭제]` | 공문 뒤에는 없다(부서에 이미 요청이 갔으므로) |
| ③ 설문 요청 공문 | 재난안전과 담당자 | 설문조사표 양식 첨부(공통본 또는 부서별본, 대상 부서 전부) → `[요청 공문 보내기 →]` → 기안 → 미리보기 → `[온나라로 보내기]` | **보내는 순간** 대상 부서 할 일 «설문조사표 작성·제출» + 알림 · 양식 잠김 |
| ④ 부서 제출 | 그 부서 담당자(재난안전과 대리 등록 가능) | 내 할일 `[작성본 제출]` 또는 정기평가 화면 `[지금 제출하기]` — 같은 창 | «제출 n / m». 보고서 등록 전까지 교체 가능 · 기한이 지나도 보고서 전이면 받는다 |
| ⑤ 보고서 + 조치기한 | 재난안전과 담당자 | `[＋ 통합 보고서 첨부]` — 용역 통합 보고서 1개(30MB) + 부서별 조치기한(일괄 가능, 전 부서 필수, 오늘 이후) | 부서별 조치 표에 «요청» 체크 열(기본 전부) · **설문 제출 마감** |
| ⑥ 조치 요청 공문 | 재난안전과 담당자 | «요청» 체크로 개선 필요 부서 고르기 → `[조치 요청 공문 (N곳) →]` → 보내기 | **보내는 순간** 고른 부서 «조치전» + 할 일 «부서별 개선조치 작성» + 알림 · 고르지 않은 부서 **«지적사항 없음»(완료)** |
| ⑥-1 조치 대상 없음 종결 | 재난안전과 담당자 | 고른 부서가 없으면 `[평가 종결 — 조치 대상 없음]`(사유 필수, 되돌릴 수 없음) | 대상 부서 전부 «지적사항 없음» · 평가 «완료» · 결과 공문은 «조치 대상 없음» 보고 |
| ⑥-2 추가 조치 요청 | 재난안전과 담당자 | «지적사항 없는 부서 N개 제외» 줄 `[추가 조치 요청 →]` | 평가당 한 번 · 결과 공문 전 · ⑥과 같은 할 일 · 알림 |
| ⑦-1 작성 · 입력 완료 | 요청받은 부서 담당자(재난안전과도 대신 적을 수 있다) | 작성표의 **우리 부서 칸**에 `[＋ 행 추가]` → `[입력 완료]` → 확인 줄의 `[입력 완료]` | 그 순간 유효 행이 개선조치(진행중)가 된다 · 재난안전과에 «조치 입력 완료» · 행 담당자에게 «담당자 지정» |
| ⑦-2 조치 · 완료 처리 | 그 부서 담당자 | `[개선조치 완료 처리]`(또는 내 할일) → 카드 `[완료 처리]`: 조치 내용 · 완료일 · 개선 후 사진(필수, 이미지) · 개선 전 사진(선택) · 전자서명 | 재난안전과에 «완료 확인 요청». 기한 연장 · 담당자 지정은 같은 카드 |
| ⑧-1 완료 확인 | 재난안전과 담당자 | 부서 줄 `[관리]` 또는 `[확인 대기 건만 보기 →]` → 증빙 열람 체크 → `[확인]` / `[반려]`(사유) | 확인 기록 · 반려면 담당자 알림, 재제출하면 회차 +1 |
| ⑧-2 결과 공문 | 재난안전과 담당자 | 전 건 확인 뒤 `[공문 기안]` → 미리보기 → `[온나라로 보내기]` | 온나라 기안함까지 · **보내는 순간 확인 결과 잠금** · 평가는 여기서 끝난다 |

작성 중에는 입력 완료하지 않은 부서에 `[입력 재촉]`을 보낼 수 있다(§3-9). 작성(입력 완료) 기한은 따로 두지 않는다 — 조치기한이 작성 마감이다.

### 3-2. 종전과 달라진 것

| | 종전(11-10 까지) | 지금 |
|---|---|---|
| 부서에 처음 알리는 때 | 양식 배포 · 전달 때 시스템 알림 | 설문 요청 공문을 보내는 순간 |
| 조치 내용을 쓰는 사람 | 재난안전과가 대신 | 요청받은 부서(재난안전과는 대신 적을 수 있다) |
| 부서로 넘기는 행위 | 재난안전과 [전달](전 부서 한 번에) | 조치 요청 공문 + 부서별 [입력 완료] |
| 조치기한을 정하는 때 | 작성 · 전달 뒤 | 보고서를 올릴 때 부서별로 |
| 기한 연장 | 재난안전과 | 그 부서 담당자가 늦추는 쪽으로만(사유 필수, 재난안전과 알림). 앞당기기는 재난안전과 |
| 조치 요청을 안 받은 부서 | — | «지적사항 없음»으로 자동 완료 |
| 평가 «완료» | 부서 조치가 다 끝나면 | 완료 확인까지 끝나야. 그 전에는 «확인 대기» |
| 개선 후 사진 | — | 개선조치 카드 [완료 처리] 한 곳(작성표에 사진 · 완료 칸 없음) |

**걷은 것** — 재난안전과의 전 부서 일괄 [전달]과 «재난안전과 작성표 → 전달» 단계 · 생성과 양식 첨부만으로 가던 알림 · 할 일 · 작성표의 사진 · 완료 열 · [입력 완료]의 참여 근로자 칸 · 평가 끝의 근로자 공유 기록.

| 작성표 작성 | 그 부서가 요청을 받았고 입력 완료 전 | 읽기 전용 |
| 입력 완료(0건) | 사유 있음 | 막힘(«아직 안 씀»과 «쓸 게 없음»을 가른다) |
| 입력 완료 취소 | 그 부서 개선조치 중 완료 처리한 건이 없음 · 결과 공문 전 · 평가 진행 중 | 버튼 없음 |
| 입력 재촉 | 조치 요청 받음 · 입력 완료 전 | 버튼 없음 |
| 결과 공문 기안 | 요청 부서 전부 입력 완료 + 개선조치 전 건 완료 · 확인 — 또는 «조치 대상 없음»으로 끝난 평가 | 기안 막힘(사유) |

### 3-4. 권한 · 보이는 범위

| 계정 | 보는 것 | 하는 것 |
|---|---|---|
| 재난안전과 담당자 | 전 부서 | ①②③⑤⑥⑧ · 정보 수정 · 삭제 · 종결 · 추가 요청 · 대리 등록 · 작성표 대신 작성 · 재촉 · 입력 재촉 · 완료 확인 · 반려 |
| 재난안전과 과장 · 팀장 | 전 부서 | 조회 · 재촉 · 입력 재촉 |
| 부서 담당자 | 본인 부서(작성표도 본인 부서 칸만) | ④ ⑦ · 기한 연장 · 개선조치 기한 재촉(사람 단위 — 본인이 담당자인 건 제외) |
| 부서 과장 · 팀장 | 본인 부서(작성표는 읽기 전용) | 조회 · 재촉 · 우리 부서 입력 재촉 |
| 군수 | 전 부서 | 조회만(재촉 없음) |

- «부서 담당자» = 그 부서 업무담당자 등급 전원(지금 운영대로). 알림은 지정된 «부서 안전보건 담당자»가 먼저 받는다.
- 개선조치 담당자 후보는 **그 개선조치 부서 사람뿐**이다(작성표 행 · 조치 카드 · 수시 등록 세 경로 공통, 저장 때 다시 본다). 다른 부서 사람을 지정하면 그 사람은 조회 범위 밖이라 알림을 받고도 그 건을 열 수 없다.
- 완료 확인 · 반려 · 확인 취소는 재난안전과 담당자만(지금 운영대로 — 완료한 사람과 확인하는 사람이 같아도 된다). 결과 공문을 보낸 뒤에는 잠긴다.
- 쓸 수 없는 칸은 감추지 않고 읽기 전용으로 보인다(같은 부서 과장 · 팀장이 진행을 볼 수 있어야 한다).

### 3-5. 상태

| 대상 | 상태 | 규칙 |
|---|---|---|
| 평가 카드 | 진행중 → 확인 대기 → 완료 | 요청 부서 전부 입력 완료 + 개선조치 전부 완료면 저장 상태는 «완료»가 되지만, 확인이 남았으면 화면은 «확인 대기»이고 완료일을 내지 않는다. 반려가 남았으면 «진행중». «조치 대상 없음»으로 종결했거나 요청 부서가 모두 0건이면 바로 «완료». **저장값은 바꾸지 않고 표시만** 파생한다 |
| 보고서 축 | 보고서 미등록 → 조치 요청 전 → 조치 요청 완료 | ⑤ · ⑥ |
| 부서 줄 | 조치 요청 전(회색) → 조치전(작성 0건) → 조치중 → 완료 / 반려 · 지적사항 없음 | 부서 표 · 조회 표 · 요약 · 상세가 같은 판정 하나를 쓴다. 확인 전 줄 버튼 `[관리]`, 확인까지 끝나면 `[보기]` |
| 개선조치 1건 | 진행중 → 완료 · 확인 축(확인 대기 → 확인 완료 / 반려) | 두 축은 따로 간다. «완료이면서 반려»가 정상이다. 반려해도 완료를 되돌리지 않는다 |
| 내 부서 진행(부서 화면) | 설문 제출 → 보고서 · 조치 요청 → 개선조치 작성 · 완료 → 완료 확인 | 보고서 등록 뒤 못 낸 설문은 «미제출 · 마감»(회색) · 조치 요청을 안 받은 부서는 «할 일 없음» · 확인 전에는 «평가 완료»를 내지 않는다 |

### 3-6. 공문 3종 — 결재선 없이 «온나라로 보내기»

11-06 운영 결정(«온나라로 기안까지만» — 검토 · 결재는 담당자가 온나라 기안함에서 지정해 상신)을 세 공문에 모두 적용한다.

| | 설문조사표 요청(③) | 조치 요청(⑥ · ⑥-2) | 결과(⑧-2) |
|---|---|---|---|
| 수신 | 대상 부서장 전부 | 고른 부서장 | 내부결재 |
| 본문 | 직접 작성 + 삽입 조각(요청 안내 · 제출 개요 · 점검 일정) | 직접 작성 + 조각(요청 안내 · 이행 방법) | 직접 작성 + 수치 삽입 조각 |
| 붙임 | 설문조사표 양식 + 별지 «제출 대상 부서»(부서 · 점검일 · 받는 사람) | 별지 «조치 요청 부서와 조치기한». **용역 보고서는 붙이지 않고** 별지 끝에 «용역 보고서는 중대재해 통합관리시스템 › 위험성평가 › 정기 위험성평가 화면에서 내려받습니다.» · 추가 요청은 제목 «…(추가)» | 확인 결과표 · 전후 사진철(별지 → PDF) · 그 밖 파일 · 관련 근거는 고른 것만 |
| 보내는 순간 | 대상 부서 할 일 · 알림 · 양식 잠김 | 고른 부서 할 일 · 알림 · 나머지 «지적사항 없음» | 확인 결과 잠금 |
| 보내기 실패 | 할 일 · 알림을 만들지 않는다 | 〃 | 잠그지 않는다 |
| 반려 · 반송 | 할 일 유지 · 같은 공문을 다시 보낼 수 있게 | 〃 | 잠금 해제 · 다시 기안 |
| 결재 결과 수동 기록 | 없음 | 없음 | 지금 운영대로 둔다 |

- 순서: `[공문 기안]` → 본문 작성 → `[문서 미리보기 →]` → `[온나라로 보내기]` → 확인 → `[보내기]`. 기안 폼에 보내기 수단을 두지 않는다. 본문은 자동 생성하지 않는다.
- 붙임 한도: 파일당 10MB · 5개 · 합계 30MB(고르는 단계에서 검사). 용역 보고서(최대 30MB)는 이 한도를 넘어 붙이지 않는다.
- «조치 대상 없음» 결과 공문 — 종결한 평가는 본문 «용역 보고서 검토 결과 개선이 필요한 부서가 없어 조치 요청 없이 평가를 마칩니다(종결 사유: …).», 요청받은 부서가 모두 0건으로 끝낸 평가는 «조치 요청 공문을 받은 부서가 모두 조치할 것이 없다고 입력해 개선조치 없이 평가를 마칩니다.» · 확인 결과표 · 사진철 · 보고서 없이 **붙임 없음**.

### 3-7. 작성표 · 입력 완료

- **열** = 시설물 · 유해위험요인 · 분류 · 원인 · 개선조치 · 담당자(+ 삭제). 사진 · 완료 칸은 없다.
- **유효 행** = 유해위험요인과 개선조치가 둘 다 있는 행. 한쪽만 적은 행은 작성표에 남지만 개선조치가 되지 않는다. 부서 머리의 «n건 작성»은 유효 행만 센다.
- **시설물** 은 세 상태(지정 / 해당 없음 / 미지정)이고 셋 다 오류가 아니다. 미지정은 «아직 안 봄», 해당 없음은 «확인했고 붙지 않음»이다.
- **담당자** 는 비워 둘 수 있다 — 비우면 입력 완료 뒤 그 부서가 개선조치 카드에서 정한다. «○○과 담당자» 같은 총칭을 대신 채우지 않는다.
- 작성표 아래 안내: «개선 전·후 사진과 완료일은 여기서 받지 않습니다 — [입력 완료] 뒤 생기는 개선조치마다 [완료 처리]에서 올립니다».
- `[입력 완료]` → 확인 줄: «적은 N건이 개선조치가 됩니다 · 그 뒤로 작성표는 닫힙니다» · «다음 차례 — 조치를 마치면 [개선조치 완료 처리](또는 내 할일)에서 건마다 개선 후 사진 · 완료일을 올립니다». 0건이면 사유 필수.
- 입력 완료 순간 유효 행이 개선조치(진행중)가 되고 행의 담당자 · 부서 조치기한을 이어받는다. 이때 «완료»로 생기는 개선조치는 없다.
- `[입력 완료 취소]` — 그 부서 개선조치를 거두고 작성표로 돌아간다(행은 남는다). 다시 완료하면 담당자 지정 알림을 다시 보낸다.
- 재난안전과가 대신 적어도 입력 완료는 같은 버튼이고, 대신 적은 기록을 남긴다.
- 입력 중인 부서가 하나라도 있으면 평가 완료 · 결과 공문을 막는다.

### 3-8. 개선조치 카드 · 기한 · 완료 확인

**카드에서 하는 일**

| 버튼 | 누가 | 규칙 |
|---|---|---|
| `[완료 처리]` | 그 부서 담당자 | 조치 내용 · 완료일 · 개선 후 사진(필수 — 이미지 JPG · PNG · GIF, 10MB, 5개) · 개선 전 사진(선택) · 전자서명 |
| `[재제출]` | 그 부서 담당자(반려 건) | 같은 완료 창 · 회차 +1 · 확인 축을 다시 «확인 대기»로 |
| `[담당자 지정 · 기한 연장]` (수시는 `[담당자 지정]`) | 그 부서 담당자 | 처음 담당자를 정할 때는 사유를 받지 않는다(이력 «담당자 지정»). 담당자를 바꾸거나 기한을 늦출 때만 사유 필수. 완료한 건에는 버튼을 내지 않는다 |
| `[재촉]` | 재촉할 수 있는 사람(§3-9) | 기한이 지난 건 · 본인이 담당자인 건 제외 |

- 완료 전 건은 회색 안내 «개선 후 사진은 완료 처리 때 올립니다» · «완료 처리 전 — 기한 …». 번호는 작성 순서 그대로(완료해도 바뀌지 않는다).

**기한**

- 부서에 주는 기한(설문 제출 · 조치기한 · 변경 · 연장)은 **오늘 이후**만 받는다. 점검일은 막지 않는다.
- 부서 조치기한은 입력 완료 때 각 건의 처음 기한이 되고, 그 뒤 연장은 **건마다 · 그 건의 현재 기한보다 늦게만**. 앞당기기는 재난안전과(지금 규칙 그대로). 연장하면 재난안전과에 알림.
- 조치기한 변경은 바꾼 값만 검사한다(바꾸지 않은 지난 기한 때문에 다른 수정이 막히지 않게).
- 보고서가 등록되면 설문 제출은 마감 — 못 낸 부서의 제출 버튼 · 내 할일 제출 카드를 남기지 않는다.

**완료 확인**

- 단위는 **건**(확인자 · 확인일 · 반려 사유 · 회차가 건마다), 화면은 **부서로 묶는다.** 부서 상태는 저장하지 않고 파생한다.
- 확인 대기 2건 이상이면 `[확인 대기 N건 한 번에 확인]` — 건마다 조치 내용 · 사진 수 · 완료일 · 서명 · 회차를 펼치고 **열람 체크가 있어야** `[N건 확인]`이 켜진다. 반려는 일괄로 하지 않는다(사유가 건마다 다르다).
- 반려 사유 없이 반려할 수 없다. 반려 건은 담당자 화면에 다시 할 일로 올라온다.
- 재난안전과 내 할일 «완료 확인 대기»(평가 1건당 한 줄) → 확인 대기 목록을 바로 연다.

### 3-10. 알림

기준은 «받는 사람이 할 일이 있을 때만»이다. 보낸 사람 본인 · 본인 지정은 언제나 뺀다.

| 알림 | 언제 | 받는 사람 |
|---|---|---|
| 정기평가 설문조사표 제출 요청 | 설문 요청 공문을 보낸 즉시 | 대상 부서 안전보건 담당자 → 부서장 |
| 위험성평가 조치 요청 | 조치 · 추가 조치 요청 공문을 보낸 즉시 | 고른 부서 안전보건 담당자 → 부서장 |
| 위험성평가 조치 입력 완료 | 부서가 입력 완료한 즉시 | 주관부서 담당자 |

| 개선조치 담당자 지정 | 작성표 행 담당자는 입력 완료 순간 한 번 · 카드에서 지정 · 변경 · 수시 등록 | 지정된 담당자 |
| 개선조치 완료 확인 요청 | 정기 조치를 완료 · 재제출한 즉시(건마다 · 회차 표시) | 주관부서 담당자 |
| 개선조치 확인 반려 | 반려 즉시(사유 포함) | 조치 담당자 → 부서 안전보건 담당자 → 부서장 |

| 위험성평가 조치기한 재촉 / 조치 입력 재촉 | 보낼 때 | §3-9 |
| 수시평가 개선조치 도착 | 주관부서가 그 부서 건으로 대신 등록했을 때만 | 그 부서 안전보건 담당자 → 부서장 |

설문 기한 · 등록 기한이 지난 것을 알리는 새 알림은 만들지 않는다.

### 3-11. «지금 할 일» — 다음에 누를 곳 보이기

접속한 **담당자 계정**에게 지금 눌러야 할 버튼 **하나**를 강조한다.

- 모양: 바깥 고리(브랜드 색 토큰) + 채운 모양 + «지금 할 일» 꼬리표. 맥동은 강조 대상이 바뀔 때 2회만. 움직임 줄이기 설정이면 맥동 없음. 화면을 가리는 오버레이는 쓰지 않는다.
- 도구 줄 아래 한 줄: «지금 할 일 — (문장)» + `[바로 가기 ↓]` / «기다리는 중 — (무엇을)» / «완료 — 이 평가는 끝났습니다 · 우리 부서 몫은 모두 끝났습니다 · 우리 부서는 조치 요청 대상이 아닙니다(지적사항 없음)».
- 값이 바뀌면 다시 그리지 않아도 따라간다 — 행을 채워 유효 행이 생기면 [입력 완료]로, [입력 완료]를 누르면 확인 줄 안의 버튼으로, 입력 완료 뒤에는 «내 부서 진행 상황»의 `[개선조치 완료 처리]`로.
- 내지 않는 때: 조회 계층(과장 · 팀장 · 군수) · 단계별 안내가 켜져 있을 때.

| 단계 | 재난안전과 담당자 | 부서 담당자 |
|---|---|---|
| 평가 없음 | 정기평가 생성 | — |
| 설문 요청 전 | 양식 붙이기 → 설문 요청 공문 | 기다리는 중 — 요청 공문 |
| 설문 요청 뒤 · 보고서 전 | 제출이 덜 들어왔고 기한 전이면 기다리는 중 — 설문 제출 n / m · 아니면 보고서 · 조치기한 | 설문 제출 / 기다리는 중 — 보고서 |
| 조치 요청 전 | 조치 요청 공문(고른 부서 0곳이면 «평가 종결 — 조치 대상 없음») | 기다리는 중 — 요청 부서 고르는 중 |
| 작성 중 | 기다리는 중 — 입력 완료 n / m곳 · [입력 재촉] 안내 | 행 추가(0건) → 입력 완료(1건 이상) → 확인 줄의 입력 완료 |
| 조치 중 | 확인 대기가 있으면 확인 / 없으면 기다리는 중 | 개선조치 완료 처리 · 다 했으면 기다리는 중 — 재난안전과 확인 |
| 전 건 확인 | 결과 공문 기안 | 완료 — 우리 부서 몫은 모두 끝났습니다 |
| 결과 공문 뒤 | 결재중이면 기다리는 중 · 결재완료면 완료 — 이 평가는 끝났습니다 | 완료 |

### 3-12. 내 할일

| 카드 | 생기는 때 | 사라지는 때 | 버튼 |
|---|---|---|---|
| 설문조사표 작성 · 제출 | 설문 요청 공문을 받은 순간 | 제출 · 보고서 등록(마감) | `[작성본 제출]` — 그 자리에서 파일 제출 |
| 부서별 개선조치 작성 | 조치 요청 공문을 받은 순간 — 7일 안에 받았으면 «새 요청» | 입력 완료 | `[작성하러 가기]` → 우리 부서 작성표 |
| 개선조치(건별) | 입력 완료로 생긴 미완료 건 · 반려 건 — «담당 ○○ / 담당자 미지정» | 완료(반려 건은 재제출) | `[완료 처리]` / `[재제출]` · `[담당자 지정 · 기한 연장]`(완료한 건에는 없음) |
| 완료 확인 대기(재난안전과) | 확인 대기 건이 생긴 평가 | 대기 0 | 확인 대기 목록 |

- 내 할일에도 «지금 할 일» — 처리할 수 있는 담당자에게 마감 할일 맨 위(가장 급한) 건의 주 버튼 하나를 같은 모양으로 강조한다.
- 과장 · 소장 · 군수 — 그 부서 할 일 전체를 보되 처리 버튼은 없다. 안내 첫 줄 «우리 부서가 처리할 업무와 진행 상황을 한곳에서 봅니다 — 처리는 부서 담당자가 합니다». «완료한 업무»도 부서 전체 범위.
- 대시보드의 부서 할 일 · 기한 초과는 내 할일과 같은 목록에서 센다(담당자 · 과장 · 군수 화면이 같은 부서에 같은 수).

## 4. 수시 위험성평가

정기와 **흐름의 방향이 반대다** — 정기는 재난안전과가 열어 부서로 내려보내고, 수시는 **부서에 사유가 생겨 올리고** 재난안전과가 외부 안전관리자 검토를 붙인다. 이번 흐름 전환으로 바뀐 것은 재촉(§3-9)과 날짜 검사뿐이고 나머지는 운영 그대로다.

| 단계 | 누가 | 무엇을 |
|:--:|---|---|
| 1 | 부서 담당자 | 실시 사유 6종 중 하나를 먼저 고른다 — 건설물 설치 · 이전 · 변경 · 해체 / 기계 · 설비 · 원재료 도입 · 변경 / 정비 · 보수 / 작업방법 · 절차 변경 / 중대산업사고 · 산업재해 / 그 밖에 필요한 경우 |
| 2 | 〃 | 부서(소속 부서 고정) · 발생일 · 내용 · 첨부 · 유해위험요인 행(최대 10행: 시설물 · 요인 · 원인 · 감소대책 · 담당자 · 개선 전 사진) · 공통 조치기한(선택, 오늘 이후). 재해 사유면 재해 개요 · 작업 재개 예정일 필수 |
| 3 | 시스템 | 요인 · 감소대책이 둘 다 있는 행마다 개선조치 1건 즉시 생성 |
| 4 | 그 부서 담당자 | 목록 `[조치 상세 · 완료 처리]` → 카드에서 완료 처리(정기와 같은 완료 창) |
| 5 | 재난안전과 담당자 | 안전관리자 서명 검토파일 · 이름 · 검토일(오늘 이전) 등록 → «검토완료». 파일을 떼면 «등록됨»으로 |

- **완료 확인 · 결과 공문이 없다** — 확인 주체가 외부 용역 안전관리자이고 검토파일로 갈음한다. 수시 조치를 완료해도 «완료 확인 요청» 알림은 가지 않는다.
- 검토 상태와 조치 진행률은 별도 축이다(«검토완료인데 조치 중» · «조치 100%인데 검토 전» 모두 정상).
- 조치기한을 비우면 «기한 미지정» 개선조치가 된다(기한 초과 집계에는 잡히지 않음을 드러낸다).
- 위험성 수준 · 허용 여부 · 참여 근로자 · 결과 공유는 입력하지 않는다.
- 작성 양식 파일이 등록되기 전에는 양식 내려받기 버튼과 «작성 양식» 칸을 내지 않는다.

## 5. 법령 근거

| 화면 | 근거 | 무엇의 근거인가 |
|---|---|---|
| 두 화면 공통 | 중대재해처벌법 시행령 §4 3호(유해 · 위험요인 확인 · 개선) · 산업안전보건법 §36(위험성평가의 실시) · 같은 법 시행규칙 §37(위험성평가의 방법 · 절차 · 시기) | 위험성평가를 하고 유해 · 위험요인을 개선하는 의무 |
| 정기 위험성평가 | 「사업장 위험성평가에 관한 지침」(고용노동부고시 제2026-73호, 2026-11-04 전부개정) §14 정기평가 | 매년 1회 이상 |
| 수시 위험성평가 | 같은 지침 §15 수시평가(② 1 ~ 5호 · ③) | 실시 사유 6종 · «관련 작업을 시작하기 전까지» |

- **근로자 참여 · 결과 공유(시행규칙 §37의3 · §37의4 · 지침 §17)는 이 화면의 근거로 붙이지 않는다** — 화면이 그 일을 하지 않기 때문이다. «참여한 근로자» 기록은 부서 설문조사표 제출(설문조사 — 누가 냈는지 남는다)과 용역 통합 보고서가 맡고, 결과 공유(게시 · 교육 · 회의)는 시스템 밖에서 한다.
- 근거는 법령 원문 연결(근거 칩)로만 보이고 조문 문구를 화면에 직접 쓰지 않는다.
- 공문 지면은 표준 공문 서식(행정업무규정 시행규칙 별지 제1호)을 따르되 그 규정을 근거 칩으로 인용하지 않는다.

### 7-4. 검증

- 사용성 검증(11-16) — 부서 담당자 과제 4개(조치 요청 받고 작성 · 입력 완료 · 완료 처리 · 반려 건 재제출)를 1280px 에서 수행, 전 과제 성공. 나온 문제 10건(요청 카드가 묻힘 · 처음 지정에 사유 · 쓸모없는 재촉 버튼 · 사진 칸 형식 · 확인 줄이 화면 밖 · 담당자 표시 없음 · 번호가 바뀜 · 붉은 안내 · 빈 행도 셈 · 좁은 칸)을 고쳤다. 모바일(375px)은 대상이 아니다(11-16 기획 결정).
- 최종 점검(11-16) — 재난안전과 → 부서 → 확인(반려 · 재제출 · 일괄 확인) → 결과 공문 → 결재 회신을 끝까지 걸었고, «조치 대상 없음» 종결 · 수시평가 등록도 확인했다.
