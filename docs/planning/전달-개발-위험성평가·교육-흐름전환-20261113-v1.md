## 1. 정기 위험성평가

### 1-2. 흐름 — 8단계

| 단계 | 누가 | 화면에서 | 결과 |
|:--:|---|---|---|
| ① 생성 | 재난안전과 담당자 | 정기평가 목록 빈 화면 `[＋ 정기평가 생성]` → 마법사 STEP 1 | 평가 1건 «진행중». **부서에는 아무것도 가지 않는다** |
| ② 대상 · 일정 | 〃 (같은 마법사) | 대상 부서(조직도, 기본 전체) · 부서별 **점검일**(필수, 일괄 적용) · **설문 제출 기한**(필수, 오늘 이후) | 평가 카드에 제출 기한. 점검일이 설문 기한보다 이른 부서가 있으면 **알리기만** |
| ③ 양식 → 설문 요청 공문 | 재난안전과 담당자 | 설문조사표 양식 `[＋ 첨부]`(공통본 또는 부서별본, 대상 부서 전부) → `[요청 공문 보내기 →]` → 기안 → 미리보기 → `[온나라로 보내기]` | **보내는 순간** 대상 부서 내 할일 «설문조사표 작성·제출(기한)» + 알림 · **양식 잠김** |
| ④ 부서 제출 | 그 부서 담당자 (재난안전과 대리 등록 가능) | 내 할일 카드 `[작성본 제출]` 또는 정기평가 화면 우리 줄 `[지금 제출하기]` — 작성본 파일 | «제출 n / m» · 제출자 · 제출일. 보고서 등록 전까지 교체 가능 |
| ⑤ 보고서 + 조치기한 | 재난안전과 담당자 | `[＋ 통합 보고서 첨부]` — 통합 보고서 1개(파일당 **30MB**) + 조치기한(일괄 또는 부서별, 전 부서 필수, 오늘 이후) | 단계 «조치 요청 전» · 부서별 조치 표에 «요청» 체크 열(기본 전부) · **설문 제출 마감** |
| ⑥ 조치 요청 공문 | 재난안전과 담당자 | «요청» 체크로 부서 고르기 → `[조치 요청 공문 (N곳) →]` → 기안 → 미리보기 → `[온나라로 보내기]` | **보내는 순간** 고른 부서 «조치전» + 내 할일 «부서별 개선조치 작성(기한)» + 알림 · 고르지 않은 부서 «지적사항 없음»(완료) |
| ⑦-1 작성 · 입력 완료 | 그 부서 담당자 | 작성표의 **우리 부서 칸**에 `[＋ 행 추가]` → `[입력 완료]` | 그 순간 유효 행(§1-6)이 개선조치가 된다 · 부서 줄 «조치중»(0건이면 «지적사항 없음») · 재난안전과에 «조치 입력 완료» 알림 |
| ⑦-2 조치 완료 · 기한 연장 | 그 부서 담당자 | 개선조치 카드 `[완료 처리]` / `[담당자 지정 · 기한 연장]` | 완료 → 재난안전과에 «완료 확인 요청» · 연장 → 재난안전과에 알림 · 이력 |
| ⑧-1 완료 확인 | 재난안전과 담당자 | 부서 줄 `[관리]` 또는 `[확인 대기 건만 보기 →]` → 증빙 열람 체크 → `[확인]` / `[반려]`(사유) | 확인 기록(확인자 · 확인일) · 반려 → 담당자 알림, 재제출하면 회차 +1 |
| ⑧-2 결과 공문 | 재난안전과 담당자 | 전 건 확인 뒤 `[공문 기안]` → 미리보기 → `[온나라로 보내기]` | 온나라 기안함까지 · **보내는 순간 확인 결과 잠금** |

### 1-3. 권한 · 보이는 범위

| 계정 | 보는 것 | 하는 것 |
|---|---|---|
| 재난안전과 담당자 | 전 부서 | ①②③⑤⑥⑧ · 대리 등록 · 작성표 대신 작성 · 재촉 |
| 재난안전과 과장 · 팀장 | 전 부서 | 조회 · 재촉 |
| 부서 담당자 | 본인 부서(작성표도 **본인 부서 칸만** 보인다) | ④ ⑦ |
| 부서 과장 · 팀장 | 본인 부서(쓸 수 없는 칸은 읽기 전용) | 조회 · 재촉 |
| 군수 | 전 부서 | 조회만(**재촉 없음**) |

- 판정은 **진입 · 저장 양쪽**에서 같게 본다. 버튼만 감추면 직접 호출로 뚫린다(9-28 권한별 QA 에서 실제로 뚫렸던 곳: 보고서 등록 · 부서 제출 대리 등록 · 재촉).
- 개선조치 담당자 후보는 **그 개선조치 부서 사람뿐**(A-19 · 작성표 행 · 조치 카드 · 수시 등록 세 경로 공통). 저장 때 다시 본다.
- 완료 확인 · 반려 · 확인 취소는 **주관부서 담당자**만, 같은 사람이 완료하고 확인하지 않는다. 결과 공문을 보낸 뒤에는 잠긴다.
- 재촉 받는 사람 = 조치 담당자(사람 단위). 담당자 미정이면 그 부서 담당자 → 없으면 부서장.

### 1-4. 상태 어휘

| 대상 | 상태 | 규칙 |
|---|---|---|
| 평가 카드 | **진행중 → 확인 대기 → 완료** | 요청 부서 전부 입력 완료 + 개선조치 전부 완료면 저장 상태는 «완료»가 되지만, 확인이 남았으면 화면은 **«확인 대기»**이고 완료일을 내지 않는다. 확인까지 끝나야 «완료» · 완료일. 반려가 남았으면 «진행중». **저장값은 바꾸지 않고 표시만** 이렇게 파생한다 |
| 보고서 축 | 보고서 미등록 → 조치 요청 전 → 조치 요청 완료 | ⑤ · ⑥ |
| 부서 줄 | 조치 요청 전(회색) → 조치전(작성 0건) → 조치중 → 완료 / 반려 · 지적사항 없음 | 부서 표 · 조회 표 · 요약 · 상세가 **같은 판정 하나**를 쓴다. «완료»는 그 부서 개선조치가 전부 완료 · 확인됐을 때. 확인 전에는 줄 버튼이 `[관리]`, 확인까지 끝나면 `[보기]` |
| 개선조치 1건 | 진행중 → 완료 · 확인 축(확인 대기 → 확인 완료 / 반려) | 두 축은 따로 간다. «완료이면서 반려»가 정상이다. 반려해도 완료 상태를 되돌리지 않는다(되돌리면 평가 완료와 모순) |
| 내 부서 진행(부서 화면) | 설문 제출 → 보고서 · 조치 요청 → 개선조치 작성 · 완료 → 완료 확인 | 보고서 등록 뒤 못 낸 설문은 «미제출 — 마감», 다음 단계가 지금 단계. 조치 요청을 안 받은 부서는 4단계 «할 일 없음». 확인 전에는 «평가 완료»를 내지 않는다 |

### 1-5. 공문 3종 — 모두 결재선 없이 «온나라로 보내기»

| | 설문조사표 요청(③) | 조치 요청(⑥) | 결과(⑧-2) |
|---|---|---|---|
| 보내는 사람 | 재난안전과 담당자 | 〃 | 〃 |
| 수신 | 대상 부서장 전부 | 고른 부서장 | 내부결재 |
| 본문 | 직접 작성 + 삽입 조각 «요청 안내» · «제출 개요» · «점검 일정» | 직접 작성 + 조각 «요청 안내» · «이행 방법» | 직접 작성 + 수치 삽입 조각 |
| 붙임 | 설문조사표 양식 + 별지 «제출 대상 부서»(부서 · 점검일 · 받는 사람) | 용역 보고서 + 별지 «조치 요청 부서와 조치기한» | 확인 결과표 · 전후 사진철(별지 → PDF) · 그 밖 파일 · 관련 근거는 **고른 것만** |
| 보내는 순간 | 대상 부서 할 일 · 알림 생성 · 양식 잠김 | 고른 부서 할 일 · 알림 · 나머지 «지적사항 없음» | 확인 결과 잠금 |
| 보내기 실패 | 할 일 · 알림을 만들지 않는다(다시 보내기) | 〃 | 잠그지 않는다 |
| 반려 · 반송 회신 | 할 일은 유지 · 같은 공문을 다시 보낼 수 있게 | 〃 | 잠금 해제 · 다시 기안 |
| 결재 결과 수동 기록 | 없음 | 없음 | **없음**(R-6) — 진행은 온나라에서 확인 |

- 순서는 공통 골격 그대로: `[공문 기안]` → 본문 작성 → `[문서 미리보기 →]` → `[온나라로 보내기]` → 확인 → `[보내기]`. **기안 폼에 보내기 수단을 두지 않는다.** 본문은 자동 생성하지 않는다.
- 붙임 한도는 공통 설정값(파일당 10MB · 5개 · 합계 30MB)이고 고르는 단계에서 검사한다. ⚠ 조치 요청 공문은 용역 보고서(최대 30MB)를 붙이므로 **한도와 충돌한다** — §7 Q-1.
- ⚠ **프로토타입의 결과 공문(⑧-2) 화면은 동결본**(2026-08-12 발주처 지시)이라 아직 결재선 지정 칸과 결재 회신 기록이 남아 있다. **운영 구현은 위 표(결재선 없음 · 수동 기록 없음)가 기준**이다 — 11-06 운영 결정과 같다. 프로토타입 그 화면의 결재선 칸은 따라 만들지 말아 주세요.

### 1-6. 작성표 · 입력 완료

- 작성표 한 행 = 유해위험요인 · 개선조치(**둘 다 있어야 유효 행**) · 분류 · 원인 · 시설물(지정 / 해당 없음 / 미지정 — 셋 다 오류 아님) · 담당자(그 부서 사람만) · 개선 전 · 후 사진 · 완료 체크.
- `[입력 완료]` — 확인창에 «적은 N건이 개선조치가 됩니다 · 그 뒤로 작성표는 닫힙니다». 0건이면 **사유 필수**(«아직 안 씀»과 «쓸 게 없음»을 가르기 위해).
- 입력 완료 순간 유효 행이 개선조치가 되고 행의 담당자 · 사진 · 완료 체크를 이어받는다. 완료 체크된 행은 완료 상태로 생긴다(완료 확인 요청 알림 대상).
- `[입력 완료 취소]` — §1-2 가드. 그 부서 개선조치를 거두고 작성표로 돌아간다(행은 남아 있다).
- 입력 중인 부서가 하나라도 있으면 평가 완료 · 결과 공문을 막는다.
- 재난안전과 담당자가 대신 적어도 **입력 완료는 같은 버튼**이다(대신 적은 기록 남김).

### 1-7. 날짜 · 기한

- 부서에 주는 기한(설문 제출 · 조치기한 · 기한 변경 · 연장)은 **오늘 이후**만 저장한다. 입력 칸 최소값 + 저장 검사 + 데이터 검사 세 곳 같은 판정.
- 점검일은 막지 않는다. 설문 기한이 점검일보다 늦으면(점검 전에 작성본이 들어와야 하므로) 마법사에서 **알리기만** 한다.
- 조치기한 변경은 바꾼 값만 검사한다(바꾸지 않은 지난 기한 때문에 다른 수정이 막히지 않게).
- 보고서가 등록되면 설문 제출은 마감 — 못 낸 부서의 1단계 버튼 · 내 할일 제출 카드를 남기지 않는다(눌러도 거절되는 할 일을 만들지 않는다).

### 1-8. 완료 확인

- 단위는 **건**(확인자 · 확인일 · 반려 사유 · 회차가 건마다), 화면은 **부서로 묶는다.** 부서 상태는 저장하지 않고 파생한다.
- 확인 대기 2건 이상이면 `[확인 대기 N건 한 번에 확인]` — 같은 창이 일괄 화면으로 바뀌어 건마다 조치 내용 · 사진 수 · 완료일 · 서명 · 재제출 회차를 펼치고 **열람 체크가 있어야** `[N건 확인]`이 켜진다. **반려는 일괄로 하지 않는다**(사유가 건마다 다르다).
- 반려 건은 담당자 화면에 다시 «할 일»로 올라온다(완료 탭에 묻히면 재제출 수단이 사라진다). 카드 버튼 이름 `[재제출]`.
- 재난안전과 내 할일에 «완료 확인 대기»가 평가 1건당 한 줄. 링크는 `rsk-list.html?confirm=1`(확인 대기 목록을 바로 연다).

### 1-11. «지금 할 일» 강조 (11-12 신설 · 화면 모양 규칙)

접속한 **담당자 계정**에게, 그 평가의 지금 단계에서 눌러야 할 **버튼 하나**를 강조한다. 근거 · 설계 `docs/planning/기획-위험성평가-지금할일강조-20261112-v1.md`.

- 모양: 그 버튼에 바깥 고리(브랜드 색 · 디자인 토큰) + 채운 모양 + «지금 할 일» 꼬리표. 맥동은 **강조 대상이 바뀔 때 2회만**(같은 단계에서 다시 그릴 때 반복하지 않는다). 움직임 줄이기 설정이면 맥동 없음. 오버레이 · 화면 가림은 쓰지 않는다.
- 도구 줄 바로 아래 한 줄: «지금 할 일 — (문장)» + `[바로 가기 ↓]`(대개 강조 버튼은 첫 화면 밖이다). 내 차례가 아니면 «기다리는 중 — (무엇을 기다리는지)».
- 내지 않는 때: 조회 계층(과장 · 팀장 · 군수) · 단계별 안내(투어)가 켜져 있을 때 · 끝난 평가.

| 한 부서 한 번 | 같은 교육에 같은 부서 등록부는 하나. 정정은 등록 취소 → 재등록 |
| 실제 참석시간 | 0보다 크고 회차 합계 이하 · 빈칸 = 전 회차. 교육 시간을 등록부 참석시간보다 작게 줄이는 수정은 막는다(그 등록부를 먼저 정정). 회차를 바꾸지 않은 수정(강사 · 장소 등)이 참석시간을 덮지 않는다 |

| 상태 · 이력 어휘 | 교육 전 → 등록부 받는 중 → 완료 · 상세 이력 «등록» · «처리» |

### 2-3. 실시 결과 공문 — 결재선 없이 «온나라로 보내기» (11-12 변경)

| | 종전 | 지금 |
|---|---|---|
| 결재선 | 기안 → 검토 → 결재 3단계 지정 | **받지 않는다** — 온나라 기안함까지만, 검토 · 결재는 담당자가 온나라에서 지정해 상신 |
| 버튼 | `[온나라로 결재 상신]` → `[상신]` | `[온나라로 보내기]` → `[보내기]` |
| 수신 | — | «내부결재» |
| 붙임 | 고르기 | 그대로 — **이미 올린 파일**(교육 첨부 · 서명부)에서 고르고, 이수자 명단은 붙임 별지(PDF), 관련 근거도 고른 것만. 공문 화면에서 파일을 새로 받지 않는다 |
| 잠금 시작 | 결재중부터 | **«기안함 전송»부터** — 수정 · 삭제 · 종료 · **등록 취소** 모두. 문구 «온나라에서 반려 · 반송되면 다시 열립니다» |
| 결재 결과 | 수동 기록 없음 | 그대로 없음. 연계 회신(반려 · 반송)만 잠금을 푼다 |
| 결재 이력 화면 | 결재선 열 | **«온나라로 보낸 공문»** 목록 · 결재선 열 걷기 · 상태 «기안함 전송 → 온나라에서 진행 중» · 연계 번호 표기 |

- 기안 조건은 **종료 처리 하나**(이수율은 조건이 아니다). 기안 · 미리보기 · 확인 · 보내기 네 경로 모두에서 다시 본다.
- 기안 권한 = 그 교육을 등록한 부서 담당자 + 재난안전과 담당자. 부서가 비어 있는 교육(집합교육 · 여러 부서 채용시교육)은 재난안전과 소관. 권한이 없으면 버튼 대신 누가 기안하는지 밝힌다.
- 등록 취소도 잠그는 이유: 이수자 명단 별지는 열 때마다 현재 이수기록에서 다시 만들어지므로, 보낸 뒤 등록을 취소하면 **이미 보낸 문서의 명단이 줄어든다.**

### 2-4. 권한 · 독촉

- 등록 · 수정 · 삭제 · 종료 · 공문 = 그 교육을 등록한 부서 담당자(집합교육 = 재난안전과 담당자). 관리 · 감독 계층(과장 · 팀장 · 군수)은 조회만.
- 부서 담당자의 등록 폼은 부서 칸이 소속 부서로 고정된다.
- **자기 부서는 독촉하지 않는다**(11-10 확정) — 받는 사람이 그 부서 담당자라 자기에게 간다. 재난안전과 담당자에게도 재난안전과 줄에는 선택칸이 없다. 부서장은 자기 부서를 독촉한다. 군수는 독촉하지 않는다.
- 독촉할 수 없는 계정에는 선택칸도 내지 않는다. 관리감독자는 지정일이 있어야 판정 · 독촉 대상이 된다.

## 4. 기존 데이터 (운영)

- **이미 «전달»까지 간 평가**(2025 등) — 그대로 조회한다. 부서 줄은 «요청 받음 + 입력 완료»로 본다(전달 = 전 부서 입력 완료). 새 흐름으로 다시 돌리지 않는다.
- **진행 중인 2026 평가가 전달 전이면** — 재난안전과가 조치 요청 공문부터 다시 보낸다. 재난안전과가 이미 적어 둔 작성표 행은 지우지 않고 그 부서 칸에 남긴다(부서가 이어서 고친 뒤 입력 완료).
- **설문 요청 기록이 없는 진행 중 평가** — 이미 제출된 작성본은 유지하고, 남은 부서를 위해 재난안전과가 설문 요청 공문을 보내게 한다(공문을 이미 바깥으로 보냈으면 «보낸 것으로 기록»을 개발 판단으로 둘지 §7 Q-4).
- **개선조치 확인 축이 없는 옛 건** — «확인 대기»로 본다(별도 이관 불필요).
- **교육** — 이미 결재 상신된 교육 공문은 «온나라에서 진행 중»으로 보이고 잠금 유지. 결재선 값은 지우지 않고 화면에서만 감춘다. 등록 기한이 없는 기존 교육은 기본 7일.

### 6-2. 위험성평가 — 2026 정기평가를 처음부터

예시에는 2024 · 2025 평가(완료)만 있다. 2026 은 빈 화면에서 시작한다.

1. 박안전 · `rsk-list.html` — «지금 할 일» 줄이 `[＋ 정기평가 생성]`을 가리킨다. 마법사에서 대상 부서를 물순환사업소 · 환경과 두 곳으로 줄인다(단계별 안내를 켜면 «연습용으로 물순환사업소만 선택» 도우미가 있다) · 점검일 · 설문 기한(오늘 이후).
2. 설문조사표 양식 `[＋ 첨부]` → `[요청 공문 보내기 →]` → 미리보기 → `[온나라로 보내기]`.
3. 하정수로 바꿔 내 할일 «유해위험요인 설문조사표 작성·제출» → `[작성본 제출]`.
4. 박안전 — `[＋ 통합 보고서 첨부]`(부서별 조치기한) → «요청» 체크 → `[조치 요청 공문 (N곳) →]` 보내기.
5. 하정수 — 내 할일 «부서별 개선조치 작성» `[작성하러 가기]` → `[＋ 행 추가]` → `[입력 완료]`.
6. 하정수 — 개선조치 카드 `[완료 처리]`(사진 · 서명) → 평가 카드 «확인 대기».
7. 박안전 — `[관리]` 또는 `rsk-list.html?confirm=1` → 열람 체크 → `[확인]` → «완료» → `[공문 기안]`.
8. 정환경 계정은 «지적사항 없음» 쪽 · 오순환 계정은 읽기 전용 확인에 쓴다.

같은 흐름의 단계별 안내는 정기평가 화면 위 «단계별 안내 시작»(9단계).

재촉 실습 — 박안전 또는 오순환으로 수시 위험성평가 › 기한 지난 개선조치 [조치 상세] → [재촉] → «재촉 · 받는 사람 ○○», 받는 사람 헤더 알림에 «위험성평가 조치기한 재촉». 2026 정기평가 실습 건은 기한이 앞날이라 재촉 대상이 아니다.
