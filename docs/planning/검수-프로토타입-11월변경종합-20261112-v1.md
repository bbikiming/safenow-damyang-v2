### 3-3. 이행점검 (개발 2차 회신 답신 §5 — 개발 회신 대기)

하반기 시달 예정일 · 연습 공문 시험일 / 시험 결과(특히 반려 · 반송 회신) / 담당자 지정이 부서당 한 명인지 여러 명인지 · 재난안전과 받는 사람 / 다른 부서 파일 주소 내려받기 두 조건 / 첫 발송 뒤 수신처 · 시행문 · 공개구분 확인.

### 3-4. 보류 (CLAUDE.md §18)

1. 권한 화면(메뉴 보기 · 수정)과 화면 버튼 판정이 다른 말을 한다 — 버튼이 메뉴 권한을 따를지, 권한 화면이 실제 판정을 보일지.
2. 과장 · 팀장의 [담당자 지정] — 사용 가이드 7부는 «담당자 지정 가능», 프로토타입은 조회 전용.
3. 위험성평가 결과 공문 동결분(K-1 · K-2).

### 3-5. 발표안 · 대본

기획서 v2 §3 의 16개 수정 목록 그대로다. 오늘 커밋(교육 실시 결과 공문 «온나라로 보내기»)으로 추가할 것: 교육 공문 장에 «결재선 없이 온나라 기안함까지 · 보내면 그 교육이 잠긴다» 한 줄.

## 4. 미팅 뒤 반영 절차

1. 요청을 받으면 **어느 판정의 문제인지** 먼저 정한다 — 권한(누가) · 조회 범위(무엇이 보이나) · 단계 조건(언제) · 문구. 판정은 화면마다 따로 두지 않고 한 곳에서만 고친다(부록 A).
2. 고친 뒤 같은 날 함께 고칠 문서: 화면정의서(해당 SCR) → 뷰어 데이터 재생성 → 기획서 v2(결정 표의 «정한 것»으로 옮기기) → CLAUDE.md 해당 절 → 사용 가이드 원고(실습 흐름이 바뀌면).
3. 검사 네 가지를 돌린다(부록 B). 화면은 해당 계정으로 열어 확인한다.
4. 결정이 «보류»면 기획서 결정 표에 날짜와 이유를 적고 화면은 그대로 둔다.
