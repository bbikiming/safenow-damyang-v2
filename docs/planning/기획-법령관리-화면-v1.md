## 2. 설계안 선택 — **2안(데이터 안전 축)을 뼈대로 채택**

### 2.1 선택 근거

**실 개발에서 살아남는 것은 UI가 아니라 불변식이다.** 2안은 요구사항의 대부분을 불변식으로 썼다 — "편집 필드를 아예 두지 않는다 / 삭제 조작을 없앤다 / 영향 확인이 버튼의 전제조건이다". 화면 형태가 바뀌어도 이 문장들은 그대로 백엔드 제약으로 이관된다. 1안의 큐 UX와 3안의 화면 분할은 이관 과정에서 재설계된다.

4개 리스크 분석이 모두 같은 결론에 도달했다(데이터 정합성 §2, 운영·UX 판정, 실 개발 이행 §C).

### 2.2 다른 안에서 흡수하는 것

| 출처 | 흡수 항목 | 이유 |
|---|---|---|
| **3안** | `MAP` 항목을 `{key, role:'duty'\|'cycle'}`로 승격 | 검증 6문 #5(주기 근거)를 **데이터 구조**로 만드는 유일한 방법. `js/dashboard.js:544-549`가 이미 `basis`/`cycleBasis` 2필드를 쓰는데 `MAP`에는 그 개념이 없다 |
| **3안** | 무결성 자동 검사 + 저장 게이트 | 지금 검사가 전무하다 |
| **3안** | `[law-map.js 재생성용 내보내기]` | 백엔드 없는 단계에서 **정직한 반영 경로는 이것뿐** |
| **3안** | 조문 목록 트리/표 2모드, 본문 검색 | 500조문 확대 시 트리는 "훑기"를 못 한다. 이번 감사가 결함을 잡은 방식이 전수 대조였다 |

| **2안** | `PAGES` 생성 데이터 export | 규칙 복제 = 두 번째 진실 |

### 2.3 명시적으로 **채택하지 않는** 것

| 미채택 | 사유 |
|---|---|

| **2안 `articleState`(대체·보관)를 override에 저장** | 2안 스스로 자기비판 ①에서 "선 넘었다"고 인정한 지점. §4에서 **조문 사실 필드와 운영 판단 필드를 물리적으로 분리**해 해소 |
| **3안 3화면 구성** | 화면 1개당 정의서 1건 + 권한표 1행 + 인벤토리 1행 + `00_화면목록.md` 2곳이 선형으로 붙는다. 무결성 점검은 독립 업무가 아니고 이력은 화면이 아니라 단일 타임라인이다 |

**최종: 2화면 + 연계 관리에 카드 1건 추가.**

- 인덱스: `조문키 · jo('제43조') · shortRef('§43') · 숫자만('43') · clause · title · text(본문)`.
- 입력 정규화: `§`·`제`·`조`·공백 제거 후 재시도. **표기 체계가 둘이라(`ARTICLES[].jo`는 `제43조`, `shortRef()`는 `§43`) 정규화 없이는 0건이 뜬다.**
- 0건 화면에 **적용 중인 조건을 전부 나열** + `[필터 초기화]`(조건 수 배지) + `전체에서 다시 찾기(보관 N건 포함)` 링크.
- 결과 건수 상시 표기 `조문 12 / 전체 41`.
- **검색 입력은 재렌더 대상 밖에 둔다**(`admin-menus.html:25`가 우연히 그런 구조). 카드째 재렌더하면 한글 IME 조합 중 캐럿이 날아간다 — `CLAUDE.md §4`가 `EDUFILTER.rerender`를 MUST로 못박은 이유와 같다. `compositionstart/end` 중 필터 억제.
- 검색어·필터를 URL 쿼리(`?q=`·`?law=`·`?state=`)에 반영해 화면 2로 이동해도 승계.

**표 모드 열** — 조문키 · 법령 · 조 · 호 · 제목 · 화면 N · 항목 N · 별칭 N · 코드 N · 미연계 N · 상태 · 조문 수집일 · `axis`. 정렬·필터 가능. **트리는 "찾아가는" 자료구조지 "훑는" 자료구조가 아니다. 이번 감사가 결함을 잡은 전수 대조는 표에서만 가능하다.**

### 4.2 base 파일에 **선행 추가**해야 하는 것

`js/law-map.js`는 생성물이므로 **재생성 시 함께 만들어지는 필드**로 추가한다(사람이 손으로 채우지 않는다).

| 추가 | 이유 |
|---|---|
| `ARTICLES[].src = {lawId, joNo, hangNo, hoNo}` | **배치 upsert 매칭 키가 없다.** 조문 키(`cse-4-3`)는 우리 발명품이고 API 응답 식별자와의 대응이 어디에도 없다. 없으면 매 회 전량 재생성이고, 그때 키가 바뀌면 `hazard.basis`가 통째로 끊긴다 |

| `ARTICLES[].efYd` (조문 단위) + `state('시행 전'/'현행'/'실효')` | **실측 모순**: `LAWS.osh`는 현행 `mst:'287805', efYd:'2026-07-07'`인데 `upcoming[2]`도 **같은 `mst:'287805'`에 `efYd:'2027-01-08'`**(`js/law-map.js:38-46`). 한 공포본이 부칙으로 조문별 시행일을 달리 정한 사례다. 법령 단위 `efYd` 하나로는 표현할 수 없다 |

| `ARTICLES[].kind('조문'/'별표'/'행정규칙')` | 별표는 표 구조라 `text` 단일 필드에 밀어 넣는 것이 원문 훼손(§10 위반)이다 |

| `MAP` 값 스키마 승격 → `{mode:'basis'\|'none', items:[{key, role:'duty'\|'cycle'}], reason}` | 빈 배열 12건의 판정 사유가 **JS 주석으로만** 있다(`js/law-map.js:562-565`·`:579-582`·`:648-655`). `forPage()`는 `MAP[id] \|\| []`(`:687`)이라 **"키 없음"과 "빈 배열"이 완전히 같게 동작**한다 |

### 4.4 프로토타입 저장

| 키 | 저장소 | 내용 |
|---|---|---|
| `dy-lawadm-v1` | **localStorage** | `{v, rev, mapOverride, verify, articleAdmin, aliasAuto, lawTargets, basisTriage, nonLawList, log}` |
| `dy-lawadm-stage-v1` | **sessionStorage** | `{runId, startedAt, rows[], appliedKeys[]}` |

**localStorage를 쓰는 이유** — 이웃 시스템 관리 화면이 전부 localStorage다(`js/adm-perm.js:21` `dy-adm-perm-v2`, `js/facil.js:43-44`). `CLAUDE.md`의 sessionStorage 관례는 시연마다 리셋되는 **업무 데이터** 대상이고, 매핑·검증 기록은 **권한 설정과 같은 급의 설정 데이터**다. 탭을 닫으면 검증 기록이 증발하는 것은 "저장했는데 없어졌다" 사고다. 대신 `[데모 데이터 초기화]`를 필수로 둔다. 수집 스테이징만 시연 반복성 때문에 sessionStorage.

**병합은 함수 하나(`LAWADM.effective()`)** 만 쓴다. 최초 시드도 이 함수를 경유한다.
> `js/adm-perm.js:93-94` 주석이 이미 못박았다 — *"병합에서 이 함수를 쓰지 않으면 NAV 에 추가된 신규 메뉴가 권한 0건으로 들어가 기존 스토어를 가진 브라우저에서만 '미설정'으로 보인다."* 법령 관리에서 같은 사고는 **"새 화면이 옛 스토어를 가진 브라우저에서만 미매핑으로 보인다"** 로 재현되고, 브라우저 의존이라 디버깅이 어렵다.

**저장 규약**
- `load()`에서 `v` 불일치 → 마이그레이션 또는 시드 리셋 + 토스트. **침묵 통과 금지**(현행 `js/adm-perm.js:150-152`는 키 존재만 보고 `v`를 검사하지 않는다).
- `persist()`의 `catch(e){}` 침묵 금지 — **read-back 검증**(쓴 값 재조회 비교) 후 실패 시 **오류 배너 + dirty 유지 + 저장 버튼 재활성**. QuotaExceeded·시크릿 모드에서 성공 토스트와 함께 조용히 실패하는 것이 이 화면 최악의 실패 모드다.
- **override에 조문 본문을 담지 않는다.** 수집 본문은 스테이징 중에만 메모리에 두고, 승인분은 `[내보내기]`로 반출한다.
- `rev` 카운터 낙관적 잠금 + `window.addEventListener('storage')` 로 타 탭 변경 배너.

### 5.1 3원칙 (정직성)

**(a) 시뮬레이션임을 데이터 행에 적는다.** 버튼 라벨뿐 아니라(`js/facil.js:389` 전례) **스테이징 행·이력 행에 `시뮬` 배지**를 붙인다. 실 개발 이행 시 이 플래그가 붙은 행을 마이그레이션 제외로 식별할 수 있어야 한다. 상단 고정 배너: `프로토타입 — 실제 법제처 API 를 호출하지 않습니다.`

**(b) 시드는 지어내지 않는다. 단, "실측"을 검증 없이 사실로 쓰지도 않는다.**
설계 조사에서 관측되었다는 `oshe` mst `263363 → 288347`, 시행 `2026-06-28`(즉시시행) 드리프트는 **저장소 전체에 `288347` 문자열이 0건**이다. 관측이 커밋되지 않았으므로 (a) 현재 스냅샷이 이미 낡았거나 (b) 관측이 틀렸거나 둘 중 하나이고, 저장소만으로는 판별 불가다.
→ **선행 조치 4번(§10.1)으로 스냅샷을 재수집해 확정한 뒤**, 시드 행마다 **관측 출처(요청 파라미터·응답 수신 시각·관측자)를 데이터 필드로 갖고 화면에 노출**한다. 시드는 `js/law-map.js`에 넣지 않고 **`js/law-sync-seed.js`로 분리**해 "생성물 아님 · 시연 데이터"를 파일 헤더에 명시한다(§10 오염 방지).

| 층위 | 대상 | 표시 |

### 5.4 반영 규칙

- **반영 단위 = 법령 세트**(`csa+cse` / `osh+oshe+oshr+oshs`). 세트 내 1종이라도 실패하면 세트 전체 `보류`. 법률 §29만 새 본문이고 시행령이 구 본문이면, 대시보드 캘린더의 `basis`(법률)와 `cycleBasis`(시행령)가 **서로 다른 시점의 법**을 같은 줄에 표시한다(`js/dashboard.js:544-549`) — 검증 6문 #5가 지키려던 것이 정확히 그 짝이다.
- **전건 원자 커밋 + 롤백.** 조문별 부분 커밋은 조문별 버전 스탬프(§4.2)가 선행 조건.
- **재진입 복구**: `staged.runId`·`appliedKeys[]`로 미완 반영 감지 → `이전 반영이 완료되지 않았습니다 — 재개 / 폐기`.
- **반영 실행 중에는 모달을 띄우지 않는다.** `DYV2.openModal`은 ESC·백드롭 클릭에 무조건 닫히고 dirty 가드가 없다(`js/common.js:290`·`:302`).
- **자동 거부 게이트** (수집 검증 실패 판정): ① 본문 길이 50% 이상 급감 ② 조문 제목 소실 ③ 응답 첫 줄 법령명이 요청값과 **문자열 완전일치하지 않음**. `type=HTML` 파싱만 관측된 상태라(`기획-법령연계-v1.md §8-3`) 마크업 변경이 diff 폭발로 나타난다.
- **별표는 자동 반영 경로에서 제외**한다. `kind:'별표'` 로 분리하고 **승인 액션을 주지 않는다** — 수록 방식 자체가 미정(LAW-11)이라 "승인하면 수록된다"는 약속을 할 수 없다.

### 6.1 대량 편집 — 붙이기/떼기 비대칭 (이 설계의 핵심 판단)

| 도구 | 조작 | 안전장치 |

- **페이징 없음** — 시스템 관리 6화면 전부 미사용. 트리/표 + 검색 + `max-height` 스크롤.

### 6.2 검증 6문 게이트

**게이트가 열리는 조건**: 저장 단위 diff에 **추가가 1건이라도 있을 때**. 순수 제거는 사유 1줄.
> 실제 사고(§132→양중기, §310→전기 조작)는 **교체**였지 순수 추가가 아니었다. 추가에만 게이트를 걸면 `A 제거 → B 추가`를 두 번 저장으로 나눠 우회할 수 있다.

3단계 인라인(모달 아님): `조문 선택 → 원문 강제 확인 → 6문`.

| # | 문항 | 화면이 하는 일 | 사람이 하는 일 |
|---|---|---|---|
| 1 | 조문을 실제로 열어봤나 | **자동 강제** — `panelHtml()`을 **자체 스크롤 컨테이너**(`max-height`+`overflow-y:auto`)에 렌더하고 끝까지 스크롤해야 다음 문항이 열린다. 짧아서 스크롤이 안 생기면 `scrollHeight <= clientHeight`로 즉시 통과 처리하고 `원문 전체가 표시되었습니다` 표기 | 읽는다 |
| 2 | 관련이 아니라 **직접 이행 수단**인가 | 라디오(`직접 이행 수단`/`관련만 있음`) — 후자면 **추가 취소**. `직접 이행 수단`이면 **사유 20자 이상 필수** | 쓴다 |
| 3 | 화면 근거인가 항목 근거인가 | 다도메인 집합형 화면(`my-work` 등, `PAGES` 플래그)이면 `항목 근거 권장` 경고 | 확인 |
| 4 | 다른 축이 빠지지 않았나 | **반자동** — 선택 조문의 `axis`가 산업재해 축뿐이고 시민재해 축(`csa-9`·`cse-8`·`cse-10`·`cse-11`)이 0이면 경고 + 후보 제시. 반대도 동일. 정답례 `base-targets: ['csa-4','csa-9']` | 사유 or 후보 채택 |
| 5 | 주기 조문을 함께 댔나 | **데이터 판정** — `role:'cycle'` 항목 유무로 판단. **화면 문자열 스캔은 하지 않는다**(관리 화면은 다른 화면의 DOM에 접근할 수 없다 — 안 되는 걸 된다고 설계하면 과잉 주장이 된다). 힌트 제공(교육시간→시행규칙 별표4, 산보위→`oshe-37`, 작업환경측정→`oshr-190`) | 지정 or `주기 표시 없음` |
| 6 | 화면이 하지 않는 일을 쓰지 않았나 | 문2에 쓴 문장을 **그대로 되보여주고** 조문별 개별 체크. 1:N 화면은 **HTML별로 분리해 받는다** | 확인 |

**검증 기록의 성격 — `검증 통과`가 아니라 `검증 기록 있음 — 홍길동 2026-07-29`로 표기한다.**
체크박스 6개는 3초면 다 눌린다(세 설계안이 모두 자백). 이 게이트가 실제로 제공하는 것은 **품질 보증이 아니라 책임 소재 기록**이고, 문면이 그렇게 말해야 한다. 실질 방어력이 있는 것은 문1의 스크롤 강제와 문4·문5의 데이터 판정뿐이다.
→ **게이트 통과 소요시간·문2 사유 글자수를 이력에 남긴다.** 30초 미만 통과는 목록에 `속성 통과` 표시(비난이 아니라 표본추출 단서). 형해화 여부를 나중에 판정할 수단을 남기는 것이 현재로선 최선이다.

**긴급 예외 — `임시 반영(사후 검증)`**: 즉시시행 개정은 실재한다. 하드 차단만 두면 담당자는 게이트를 형식적으로 통과시키는 법을 배운다(§10 무력화의 시작). 만료 기한 7일 + `미검증` 배지 + 만료 시 자동 큐 복귀.

**검증 만료**: 조문 **본문이 바뀐 경우에만**(`textHash` 불일치) 해당 화면의 검증을 `재검증 필요`로 강등. 시행일만 변경은 만료 없음.
→ 팬아웃 실측: `cse-5` 8화면 · `osh-29` 8화면 · `cse-4-3` 7화면. 한 번에 8~15건이 큐에 쌓이면 큐 전체가 무시된다. **`일괄 재확인` 경로**(같은 조문·같은 diff면 한 번 읽고 N건 확인, 단 문2 사유는 화면별) + 큐 상단 `이번 개정 영향: 조문 1건 → 화면 8건` 요약.

### 6.3 조문 선택기

- **`DYLAW`에 공용 검색형 조문 픽커 헬퍼 1개를 신설**한다(`ORGPICK`이 조직도에 대해 한 위치). 화면 로컬 계열 신설 금지(§7).
- **이유**: `js/rsk-list.js:476`이 검수 표의 **행마다** `optionsHtml()`을 호출한다. 조문 500건이면 30행 × 500 = 15,000 `<option>`을 매 재렌더마다 생성한다. **법령 관리 화면이 아니라 위험성평가 검수가 먼저 멈춘다.** `optionsHtml()`은 결과를 모듈 캐시(무효화 키 = override `rev`)하고 레거시 호환으로 남긴다.
- 라벨은 2줄(1행 조문 표기 굵게 / 2행 제목). `cse-4-1`~`cse-4-9`는 앞머리 `안전보건관리체계의 구축 및 이행 조치 —`가 9건 전부 동일해서 select에서 잘리면 구별이 안 된다 — **호 요지를 앞에** 둔다(`basisTitle(k,{short:true})` 재사용).
- 법령 30종 확대 대비 2단 좁히기(법령 → 조문 검색) + 최근 사용 5건 + 이미 붙은 조문 제외.

### 7.2 `DYV2.STATUS_TONE` 추가 어휘 (`js/common.js:175-189`)

현재 이 표에 법령 어휘가 **0건**이라 `toneOf()`가 전부 `neutral`로 수렴한다(`:191`) — `조문 없어짐`(danger)과 `변경 없음`(neutral)이 같은 색이 된다. 화면에서 색을 직접 고르면 §7 위반이므로 표에 추가한다.

| 축 | 라벨 → tone |
|---|---|
| 법령 | `현행`→success · `개정 감지`→warning · `시행예정`→info · `조회 실패`→danger · `인증 실패`→danger · `미수집`→neutral · `폐지`→neutral |
| 조문(갱신) | `변경 없음`→neutral · `시행일만 변경`→info · `내용 변경`→warning · `절취 실패`→warning · `조문 없어짐`→danger · `신규 조문`→purple · `시행일 도래 전 개정본`→info · `수집 검증 실패`→danger |
| 조문(생애) | `시행 전`→info · `대체됨`→purple · `보관`→neutral · `실효`→neutral |
| 조문(신선도) | `시행일 경과 · 스냅샷 미반영`→danger |
| 매핑 | `근거 있음`→success · **`근거 없음(확정)`→neutral** · **`미판단`→warning** · `반영 안 됨`→danger · `매핑 대기`→purple · `대상 화면 미등록`→warning · `표시 불가`→warning |
| 검증 | `검증 기록 있음`→success · `미검증`→warning · `재검증 필요`→danger · `임시 반영`→warning |
| 작업 | `검토 대기`→info · `반영`→success · `보류`→neutral · `시뮬`→purple |
| 근거 종류 | `법령 외 기준`→neutral · `조문 아님 — 처리 방식 미정`→neutral |

> **`근거 없음(확정)`=neutral / `미판단`=warning 구분이 §10 원칙의 시각적 유지 장치다.** 합치면 12건의 감사 결론이 "채워야 할 것"으로 오독되고 누군가 다시 채운다. `법령 외 기준`(KOSHA GUIDE·자체 점검 기준)도 neutral — 정상 상태를 경고색으로 두면 경고가 배경이 된다.

### 8.5 권한

- 화면 진입 시 `DYROLE` 티어 확인 → `admin` 그룹 비허용이면 **본문 대신 `.v2-empty` 안내 + `[대시보드로]`**. GNB 숨김(`js/layout.js:57`·`:489`)은 접근 차단이 아니다 — URL 직접 진입 시 군수 페르소나로도 매핑 편집이 전부 동작한다. 법령 관리는 **전 화면의 근거 칩을 바꾸는** 권한이라 파급이 크다.
- 프로토타입은 라우팅 가드가 없는 것이 전역 전제(`99_미결사항목록.md` PER-01)이므로, **최소한 쓰기 버튼 전량 비활성 + `읽기 전용(권한 없음)` 배지**를 넣고 상단에 명시: `이 화면은 시스템 관리자 전용입니다 — 프로토타입은 접근을 차단하지 않습니다.`
- `js/adm-perm.js:96` `defaultPerms()`가 `groupId==='admin'` → `[]` → `관리자 전용` 배지를 자동 부여한다. **NAV 등록을 화면 생성과 같은 커밋에서** 처리한다 — 미등록이면 `findGroup()`이 `NAV[0]`(대시보드)를 반환해(`js/layout.js:369-372`) GNB가 대시보드로 위장하고 `hideNav` 판정까지 우회한다.
- **기능 권한 분리 필요**(미결): 매핑 판단의 실질 주체는 재난안전과인데 화면은 admin 그룹이다.

### 8.6 반응형·접근성

- `1023px` 이하 1단 스택. **좌측 트리 `max-height`를 `40vh`로 낮추고**(현재 `css/v2.css:1307`이 640px — 375px에서 화면 대부분을 트리가 먹고 우측 패널이 뷰포트 밖에 있어 "눌러도 안 바뀐다") **항목 선택 시 패널로 `scrollIntoView`**.
- **모바일 diff는 변경 구간만 추출한 단일 컬럼**(추가 밑줄 / 삭제 취소선, 앞뒤 1문장 컨텍스트) + `[전문 보기]`. 안내: `모바일에서는 변경 부분만 표시합니다. 전문 대조는 데스크톱을 권장합니다.` **2단을 세로로 접는 것은 규칙만 충족하고 쓸 수는 없게 만든다.**
- 핵심 표(영향 분석·검토 큐)는 `lg` 미만에서 **카드 리스트로 전환**. 최소한 `영향 합계 N건`은 표 밖 요약으로 항상 노출.
- 터치 타깃 44px을 `@media (pointer: coarse)` 기준으로 적용(현재 `css/v2.css:763-765`는 `max-width:559px`에서만 — 표준 밖 값이자 560~767px 구멍).
- 본문·배지 최소 `--fs-12`. 색·폰트·반경·z-index 원시값 0.
- **`shortRef(null)` → `''` 반환으로 수정** + `js/layout.js:198-199`에 null 가드. 현재 `resolveBasis` 실패 시 스크린리더가 **"근거 널"** 을 읽는다(`js/dashboard.js:29-30`에는 폴백이 있는데 여기만 없다). 법령 관리에서 basis를 편집 가능하게 만들면 이 경로가 즉시 활성화된다.
- **조문 목록의 펼침은 행마다 독립**이어야 한다. `DYLAW.toggle()`(`js/law-map.js:842-855`)은 `.law-basis-row` 묶음 단위로 다른 칩을 전부 닫는다 — 축 누락 판단에 조문 2건을 나란히 펼쳐야 하는데 하나가 닫힌다. 관리 화면은 `.lawinfo-inline`을 직접 렌더하거나 `toggle(..., {exclusive:false})` 옵션을 추가한다.
