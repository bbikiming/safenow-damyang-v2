## 2. 원칙 3

1. **화면은 «완성된 시스템의 말»로만 한다.** 제작 단계(검토본·시연본·프로토타입·데모)는 사용자 어휘가 아니다.
2. **그 대신 없는 것을 있다고 하지 않는다.** CLAUDE.md 의 두 MUST — *«미구현 갭은 그럴듯하게 채우지 말고 화면에 드러낸다»*, *«2026 실적은 시연 시드다 — 실측과 섞지 말 것»* — 은 **유지**한다. 바꾸는 것은 **어휘**이지 **고백**이 아니다.
   - 「시연 시드」를 지우는 것은 되지만, 그 자리에 아무것도 안 남기면 «담양군이 올해 이만큼 했다»로 읽힌다. → 「예시 자료」로 **바꿔서** 남긴다.
3. **가이드는 기능이다 — 껍데기만 바꾼다.** `DYTOUR` 엔진·단계 정의·완료 판정(`done()` 실데이터 파생)은 **한 줄도 건드리지 않는다.** 공개 API 12개는 계약(CLAUDE.md §4-3)이므로 함수명도 그대로 두고 **라벨·진입점·톤만** 바꾼다.

## 3. B — 미구현 토스트 104곳의 3분류

`(프로토타입)` 을 기계적으로 지우면 **거짓말이 남는다.** `toast('업로드되었습니다 (프로토타입)')` 에서 괄호만 떼면 저장하지도 않고 저장했다고 말한다. 동작 실체로 나눈다.

| 갈래 | 판정 | 처리 | 예 |
|---|---|---|---|
| **(a) 실제로 반영됨** | 세션 스토어에 남는다 | 괄호만 삭제 | `'배정했습니다 — 알림이 발송됩니다 (프로토타입)'` → `'배정했습니다 — 담당자에게 알림이 갑니다'` |
| **(b) 화면 안에서만 반영** | 목록에 이름만 붙는다 | **범위를 밝힌다** | `'파일 첨부 (프로토타입)'` → `'목록에 추가했습니다 — 파일 저장은 문서관리 연계 후 적용됩니다'` |
| **(c) 아무 동작 없음** | 연계·파일 실물 필요 | **성공 문구를 쓰지 않는다** | `'통합 보고서 열기: … (프로토타입 — 실제 파일 뷰어는 미연결)'` → `'문서 뷰어는 전자문서 연계 후 제공됩니다'` |

- 판정 기준 한 줄: **«새로고침하면 남아 있나»** — 남으면 (a), 이 화면에서만 남으면 (b), 안 남으면 (c).
- (c)는 **버튼을 지우는 편이 나은 것**이 섞여 있다(누르면 거절하는 버튼 = CLAUDE.md §4 «누르면 거절하는 버튼을 남기면 두 번 누른다»). 소거 작업 중 발견되면 별건으로 목록화한다.
- 공용 문구는 `DYV2.notReady(what)` 한 곳에서 낸다 — 104곳에 손으로 쓰면 표현이 갈린다.

### 5-3. 진입점 재배치 — 상시 바를 걷어낸다

지금은 13개 화면 최상단에 **91px 짜리 바가 상시** 붙어 있다. CLAUDE.md §14-12(«첫 데이터까지의 거리»)가 이미 이 바 때문에 `docs-exec` 안내를 기본 접힘으로 내린 전례가 있다. 도움말은 **필요할 때 부르는 것**이지 매일 보는 것이 아니다.

| 층 | 자리 | 노출 | 내용 |
|---|---|---|---|
| ① | **헤더 `?` 도움말 버튼** (전역, `자료 준비` 칩 자리) | 상시 · 전 화면 | 현재 화면 도움말 시트 |
| ② | **첫 방문 배너** (지금의 바 재활용) | 그 화면 **최초 1회**, 닫으면 `localStorage` 기억 | `처음이신가요? … 사용법 N걸음` |
| ③ | 화면 제목 줄 `사용법` 링크(`.page-head-action`) | 상시 · 저비용 | 시트 열기 |

**도움말 시트 구성**(모달 1개 — §1 단일 모달):
1. **이 화면에서 하는 일** 2~3줄
2. **자주 하는 일** 3개 — 각각 바로 그 동작으로 가는 버튼
3. **관련 법령** — `DYLAW` 근거 칩 재사용(새로 쓰지 않는다)
4. **단계별 안내 시작** — 그 화면에 투어가 있으면 노출, 없으면 자리 자체가 없다

**콘텐츠 단일 출처** `js/help-center.js`(전역 `DYHELP`) — `MAP` 은 **page id → 도움말**, page id 는 `DYLAW.pageId()` 환원값을 그대로 쓴다(`DYLAW.MAP`·`DYPOLICY.MAP` 과 같은 방식). 도움말이 없는 화면은 `[]` 로 명시하고 `selfCheck()` 로 오타를 콘솔 경고한다(§13 선례).

### 5-4. 「초기화」는 어디로 가나

`rsk-list`·`rsk-occ`·`edu` 의 `↺ 시연 초기화` 는 **발표 반복을 위한 장치**라 실서비스 어휘가 없다. 그렇다고 지우면 반복 시연이 망가진다(CLAUDE.md §4 «회수 경로 없으면 시연이 망가진다»).

- **제안** — 화면 상단에서 빼고 **도움말 시트 맨 아래**로 내린다. 라벨 `예시 데이터 되돌리기`, 설명 «이 화면의 예시 자료를 처음 상태로 되돌립니다. 실제 등록 자료가 있는 환경에서는 노출되지 않습니다.»
- 권한 가드(`canManage`/`canReview`, 조회 전용 계층 차단)는 **그대로**.
- 본개발 전환 시 이 블록만 `HELP.SAMPLE_RESET = false` 한 줄로 끈다.

### 7-1. D1 — 진입 버튼 처리 (이미 있는 스위치를 쓴다)

새로 만들 것이 없다. 지금도 `?screendef=off` / `?screendef=on` 으로 껐다 켤 수 있고 `localStorage('dy-screendef-hide')` 에 기억한다. **기본값만 뒤집는다.**

- 기본 **숨김**. 기획자는 아무 화면에서 `?screendef=on` 을 한 번 붙이면 그 브라우저에서 계속 보인다.
- 뷰어 URL(`screen-definitions.html`) 자체는 **막지 않는다** — 직접 열면 그대로 동작한다.
- `_build-data.py` 재생성 경로도 그대로다. 정의서 갱신 작업에 영향 0.

### 7-2. D2 — 칩 이동처

`시스템 관리 > 연계 관리`(`admin-integration.html`) 가 «외부 시스템에서 무엇이 들어오는가»를 이미 다루므로 같은 축이다. 헤더 칩이 하던 두 가지 중 **① 남은 건수 표시**는 그 화면 카드로, **② 현재 화면 관련 항목을 맨 위로 올리는 동작**은 사라진다(화면 맥락이 없어지므로) — 대신 목록에 화면명을 함께 적는다.

## 8. 이 문서가 바꾸지 않는 것

- `DEMO_TODAY`(`js/common.js`) · `DEMO_YEAR`(`js/doc-progress.js`) 등 **내부 상수명** — 화면에 안 나온다.

## 9. 도움말 시트 화면 설계 (4단계 상세)

### 9-1. 진입점 3층

|---|---|---|---|
| ① | 헤더 — `자료 준비` 칩이 비운 자리 | `<button class="dy-help-btn" aria-label="도움말">?</button>` | 전 화면 상시 |

②는 `.dy-demo-bar` CSS를 그대로 쓴다(§8 — 클래스 개명 금지). 버튼만 `[사용법 보기]` `[닫기]` 2개.

### 9-2. 시트 = 모달 1개 (`DYV2.openModal(..., {chrome:true})`)

```
┌ 도움말 — 안전보건교육 정기교육 ─────────────── ✕ ┐
│                                                  │
│ ■ 이 화면에서 하는 일                            │  ← lead 2~3줄
│   집합·자체 교육을 등록하고 부서 신청을 받아     │
│   이수 결과를 기록합니다.                        │
│                                                  │
│ ■ 자주 하는 일                                   │  ← 3개 고정 (많아도 3개)
│   ① 교육 등록하기            [바로가기 →]        │
│   ② 부서 신청 받기           [바로가기 →]        │
│   ③ 실시 결과 공문 기안      [바로가기 →]        │
│                                                  │
│ ■ 관련 법령                                      │  ← DYLAW 칩 재사용
│   [산안법 §29] [시행규칙 별표4]                  │     없으면 블록 자체 없음
│                                                  │
│ ▸ 예시 데이터 되돌리기                           │  ← 접힘 · 권한 있을 때만
├──────────────────────────────────────────────────┤
│              [단계별 안내 시작 →]   [닫기]       │
└──────────────────────────────────────────────────┘
```

- **블록은 있을 때만 그린다.** 법령 없으면 3번 블록이 사라지고, 투어 없는 화면은 하단 왼쪽 버튼이 없다(`[닫기]` 만). 빈 제목을 남기지 않는다.
- `자주 하는 일`의 `[바로가기]` 는 **딥링크 또는 전역 함수 1개**. 없는 동작을 만들지 않고, 이미 있는 진입점을 가리키기만 한다.
- `예시 데이터 되돌리기` 는 `<details>` 접힘 + 회수 대상 건수 명시(CLAUDE.md §4 회수 경로 규칙). `canManage`/`canReview` 없으면 렌더하지 않는다.
- 조회 전용 계층이면 하단 버튼 라벨이 `흐름 따라보기 →`.

### 9-3. 데이터 — `js/help-center.js` (전역 `DYHELP`)

```js
DYHELP.MAP = {
  'edu-reg': {
    lead: '집합·자체 교육을 등록하고 …',
```
