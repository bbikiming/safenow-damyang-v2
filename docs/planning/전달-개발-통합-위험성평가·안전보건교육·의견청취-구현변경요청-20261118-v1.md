## 1. 세 메뉴 공통 규칙

### 1-1. 공문 흐름 — 한 골격

| 단계 | 규칙 |
|---|---|
| 들어가는 길 | 기록을 저장하는 버튼이 곧 공문 진입이다 — «저장하고 (안내) 공문 작성 →». 저장 뒤 **같은 창**이 기안 폼으로 바뀐다. 내 할일 카드의 주 버튼도 그 기안 창을 바로 연다 |
| 기안 폼 | 맨 위 한 줄(«✓ … 저장했습니다 — 이 공문을 보내야 할 일이 끝납니다») · **수신 고정 표시**(고르는 칸 없음) · 제목 · 본문(빈칸에서 시작, 자동 작성 없음) · **삽입 조각**(개요 · 결과 수치 · 근거 문구 등) · 관련 근거(고른 것만 지면에) · 붙임(이미 올린 파일에서 고름, 명단은 별지) · 맨 아래 «검토·결재는 온나라 기안함에서 지정합니다». **기안 폼에는 보내기 버튼이 없다** |
| 미리보기 | 표준 공문 지면(기관명 · 수신 · 제목 · 본문 · 붙임 · 끝. · 기안자 서명란만 · 별지) + [PDF 저장 / 인쇄] · [← 수정] · [온나라로 보내기] |
| 확인 | «온나라로 보내면 되돌릴 수 없습니다» + **보낸 뒤 무엇이 잠기는지 한 줄**만. 미리보기에서 본 내용을 반복하지 않는다 |
| 결과 창 | «온나라 기안함에 보냈습니다» — 상태 · 문서 · 연계 번호 · (붙임) · 다음 할 일. 라벨–값 두 열 |
| 닫으면 | 기록은 남고 공문만 «공문 미기안». 내 할일에 «공문 보내기» 카드가 남는다. 다시 열면 기안 폼부터(이미 쓴 제목 · 본문 유지) |

- **적용 대상**: 위험성평가 설문조사표 요청 · 조치 요청 · 결과 공문 / 안전보건교육 교육 안내(변경 · 취소 포함) · 참석자 등록부 제출 · 출장 결과 보고 · 실시 결과 보고(자체 · 채용시 · 기타). 위험성평가 결과 공문도 이 골격으로 맞춘다(운영은 결재선 없이 보내기 — 위험성평가 최종본 §3-6).
- **결재선 칸을 두지 않는다** — 운영 결정(2026-11-06) «온나라로 기안까지만». 검토 · 결재 지정과 상신은 담당자가 온나라에서 한다.

### 1-2. 공문 상태 — 한 어휘, 내부 처리 없음

| 저장 상태 | 화면 칩 | 잠금 |
|---|---|---|
| (공문 없음) | 공문 미기안 | 풀림 |
| 기안함 전송 · 결재중 | **결재 미완료** (마우스 올리면 «온나라 기안함에서 검토·결재를 지정해 상신하세요») | 잠김 |
| 결재완료 | 결재 완료 | 잠김 |
| 반려 / 반송 | 반려 / 반송 (사유 표시) | 풀림 — 앞 제목 · 본문을 이어 쓰고 [다시 보내기] |

- **보낸 직후는 언제나 «기안함 전송»(칩 «결재 미완료»)이다.** «결재 완료»는 온나라 회신으로만 붙는다. 시스템이 스스로 결재 완료를 만들지 않는다.
- **온나라 전송이 실패하면 «보내지 않음»으로 남는다** — 내부 결재로 대신 처리하지 않는다. 부서 할 일 · 알림도 만들지 않는다(공문을 보낸 순간이 요청이므로). 재시도는 [다시 보내기].
- **번호의 이름**: 보낸 직후 온나라가 돌려주는 값은 «연계 번호». «문서번호(생산등록번호)»는 결재가 끝나야 생긴다.
- 결재 이력 화면 · 목록 카드 · 상세 · 내 할일이 같은 어휘를 쓴다.

### 1-3. 공문 지면 · 붙임

- **제목**: 기록의 제목이 곧 공문 제목의 앞부분이다. 시스템이 붙이는 말(연도 · «집합교육» 등)은 **제목에 이미 있으면 다시 붙이지 않는다**.
- **붙임 번호**: 지면 «붙임» 목록 순번과 별지 머리 «[붙임 n]» 번호가 같다(고른 파일이 앞, 별지가 뒤).
- **붙임 한도**: 5개 · 파일당 10MB · 합계 30MB(별지 1개 포함). 고르는 단계에서 막고 «붙임 n / 5개 · 합계 n / 30MB»만 보인다.
- **기관정보 줄**(우편번호 · 전화 · 팩스 · 전자우편 · 공개구분)은 미결 — 6장 D-2.

### 1-4. 할 일 · «지금 할 일»

- **할 일은 처리할 수 있는 사람에게만, 끝낼 수 있는 버튼과 함께 생긴다.** 카드의 주 버튼은 그 일을 하는 창을 바로 연다(목록으로 보내지 않는다).
- **이전 방식(새 흐름 전환일 전에 만든) 기록은 새 흐름 할 일을 만들지 않는다** — 공문 할 일 · 지연 · 독촉 · «② 등록부 제출 공문 n / m» 같은 요약을 내지 않고 «이전 방식»으로 표시한다. 대시보드 기한 초과에도 세지 않는다.
- **«지금 할 일»** — 접속한 담당자에게 지금 눌러야 할 버튼 하나를 강조하고(바깥 고리 + «지금 할 일» 꼬리표 · 맥동은 대상이 바뀔 때 2회), 도구 줄 아래 «지금 할 일 — …» / «기다리는 중 — …» 한 줄을 보인다. 위험성평가는 정본(§3-11 표)에 단계별로 정해져 있고, 내 할일에서도 맨 위 카드 주 버튼에 같은 강조. 안전보건교육 상세 머리의 «부서: 지금 할 일 버튼 하나»(전달본 §2-4)도 같은 모양을 쓴다. 조회 계층(과장 · 팀장 · 군수)에는 내지 않는다.
- **눌러도 거절되는 버튼을 두지 않는다** — 할 수 없는 사람에게는 버튼 대신 «누가 · 언제 하는지» 한 줄(예: «처리는 재난안전과 담당자가 합니다»).

### 1-5. 권한 — 같은 판정을 화면과 저장에

| 원칙 | 뜻 |
|---|---|
| 그 부서 일은 그 부서 담당자가 | «그 부서 담당자» = 그 부서 업무담당자 등급 전원. 실무자 계정이 0명인 부서만 부서장이 한다 |
| 대리 등록 없음 | 교육 등록부 · 자체 · 채용시 · 기타 등록 · 현업근로자 명단은 소속 부서 고정. 재난안전과도 자기 부서 몫만. (예외: 위험성평가 설문조사표 대리 등록 · 작성표 대신 적기 · 관리감독자 지정일 — 정본에 정해진 것만) |
| 재난안전과가 닫는 일 | 위험성평가 완료 확인 · 결과 공문 / 교육 안내 · 출장 보고 · 서명부 / 의견 처리 · 조치 완료 · 반려 · 재처리 / 점검결과지 미흡 문항 조치 완료 |
| 조회 계층 | 과장 · 팀장 · 소장 · 군수는 같은 화면을 보되 처리 버튼이 없다 |
| **소속 부서가 없는 계정** | 시스템 관리자처럼 부서가 없는 계정에는 **업무 등록 · 공문 수단을 내지 않는다**. 부서를 추정해 저장하지 않는다(그 부서가 하지 않은 일이 그 부서 이름으로 남는다) |
| 서버도 같은 판정 | 버튼을 숨기는 것만으로 막지 않는다. 저장 요청도 같은 규칙으로 거절한다 |

### 1-6. 이력 · 감사 기록

- **이력의 «누가»는 사람 단위로 저장한다**(계정 · 이름 · 부서 · 일시). 등록부 등록 · [참석자 없음] · [되돌리기] · 공문 보내기 · 확인 · 반려 · 재처리 모두.
- 다른 부서 화면에서 담당자 이름을 «#번호» 등으로 가리는 것은 **표시 규칙**이지 저장을 부서 단위로 하라는 뜻이 아니다. 재난안전과 · 같은 부서 화면에는 실제 사람이 보인다.
- **독촉 · 재촉의 보낸 사람 = 실제 접속자.** 받는 부서를 보낸 사람 자리에 쓰지 않는다. 횟수는 줄에 «n회 독촉».

### 1-7. 알림

- **할 일이 있을 때만 알린다.** 할 일이 아닌 안내(의견청취 «조치 부서로 지정됨», 교육 «예정 교육»)는 알림만 내고 내 할일에 넣지 않는다.
- **받는 사람 순서**: 그 부서 «부서 안전보건 담당자» 등급 → 없으면 부서장 → 없으면 받는 사람 없음. 할 일 카드는 그 부서 업무담당자 전원에게 보인다(누가 처리해도 끝난다).
- 알림 분류: 위험성평가 «위험» · 교육 «교육»(종전 «이행»에서 옮김). 의견청취 알림 분류는 운영 그대로 둔다.

### 1-8. 화면 구성 · 입력

- **창 위에 창을 띄우지 않는다** — 조직도에서 담당자 · 부서 고르기, 완료 처리, 확인처럼 이어지는 입력은 **같은 창 안에 펼치거나 같은 창의 내용을 바꿔** 그린다. 동시에 떠 있는 창은 하나다.
- **업로드 칸은 한 모양** — 프로필만 다르다: 일반 증빙(12종 · 20MB · 10개) · 이미지(JPG · JPEG · PNG · GIF · 10MB · 5개 — 개선 전 · 후 사진) · 보고서(12종 · **30MB** · 10개 — 위험성평가 용역 통합 보고서 한 칸만).
- **업무 화면의 안내는 그 화면에서 할 일만** 말한다. 개발 상태(«수집 후 제공됩니다», «받으면 좁힙니다»), 설계 이유, 화면 · 요구사항 코드를 쓰지 않는다. 자료 한계(예시 자료 · 수록 범위)는 사실로 밝힌다.
- **선택지는 자료에 있는 값만** — 연도 필터에 자료가 없는 해를 내지 않는다.

## 2. 위험성평가 — 변경 요점

정본: 위험성평가 최종본(2026-11-16). 바뀐 것은 **순서와 주체**이고, 화면은 종전 작성표 · 부서별 조치 표 · 평가 카드를 그대로 쓴다(새 입력 화면 없음).

### 2-1. 정기평가 8단계

```
① 생성 → ② 대상 · 일정(점검일 · 설문 제출 기한) → ③ 설문조사표 요청 공문 → ④ 부서 제출
→ ⑤ 용역 통합 보고서(30MB) + 부서별 조치기한 → ⑥ 조치 요청 공문(개선 필요 부서만)
→ ⑦ 부서가 작성표 우리 부서 칸에 작성 · [입력 완료] → 건별 조치 · 완료 처리 → ⑧ 완료 확인 → 결과 공문
```

| 단계 | 핵심 규칙 |
|---|---|
| ①② | 생성 · 양식 첨부만으로는 부서에 아무것도 가지 않는다. 평가 정보 수정 · 삭제는 설문 요청 공문 전에만 |
| ③ | 보내는 순간 대상 부서 할 일 «설문조사표 작성 · 제출» + 알림 · 양식 잠김 |
| ④ | 요청 공문 뒤에만 받는다. 보고서 등록 전까지 교체 가능 · 보고서 등록 = 제출 마감 |
| ⑤ | 부서별 조치기한(오늘 이후, 전 부서 필수) · 부서별 조치 표에 «요청» 체크 열 |
| ⑥ | 고른 부서 «조치전» + 할 일 «부서별 개선조치 작성». **고르지 않은 부서 = «지적사항 없음»(완료)**. 고른 부서가 0곳이면 [평가 종결 — 조치 대상 없음](사유 필수). 추가 조치 요청은 평가당 한 번 |
| ⑦ | 작성표 열은 **시설물 · 유해위험요인 · 분류 · 원인 · 개선조치 · 담당자(그 부서 구성원만)**뿐. [입력 완료]하는 순간 유효 행(요인 + 개선조치)이 개선조치(진행중)가 된다. 0건 완료는 사유 필수. 입력 완료 취소는 완료 처리한 건이 없고 결과 공문 전일 때만 |
| ⑦ 완료 처리 | **개선조치 카드의 [완료 처리] 한 창** — 조치 내용 · 완료일 · 개선 후 사진(필수, 이미지 프로필) · 개선 전 사진(선택) · 전자서명(본인만). 내 할일 · 알림 · 개선조치 상세 화면 어디서 열어도 **같은 창**. 기한 연장은 그 부서 담당자가 늦추는 쪽으로만(사유 필수, 재난안전과 알림) |
| ⑧ | 재난안전과가 건마다 증빙을 보고 [확인] / [반려](사유 필수). 반려 건은 재제출 시 회차 +1. 부서 줄 **[관리] = 그 부서 개선조치 전체**, **[확인 대기 건만 보기] = 전 부서 확인 대기**(둘을 합치지 않는다). 확인 대기 2건 이상이면 묶음 한 번에 확인(반려는 건별) |
| 결과 공문 | 전 건 확인 뒤 기안. 보내는 순간 확인 결과 잠금. **평가는 여기서 끝난다** |

### 2-2. 상태 · 표시

- 부서 줄 상태: 조치 요청 전 · 조치전 · 조치중 · 반려 · 완료 · 지적사항 없음(한 판정에서).
- 평가 카드: 확인이 남았으면 저장 상태와 무관하게 **«확인 대기»**, 반려가 남았으면 «진행중». «완료»는 확인까지 끝나야.
- 부서 화면의 «내 부서 진행 상황»은 지금 단계에 맞는 말: 요청 공문 전이면 «기다리는 중 — 재난안전과의 설문조사표 요청 공문».

### 2-3. 수시평가

부서가 사유(6종)를 골라 등록 → 요인 · 감소대책 행마다 개선조치 즉시 생성(담당자는 그 부서 구성원만, 기한 비우면 «기한 미지정») → 그 부서 담당자가 카드에서 완료 처리(정기와 같은 창) → 재난안전과가 안전관리자 서명 검토파일 등록(«검토완료»). 완료 확인 · 결과 공문은 없다. 검토 상태와 조치 진행률은 별도 축.

### 2-4. 걷는 것

작성표의 증빙(전/후) · 완료 열 · [입력 완료]의 참여 근로자 칸 · 평가 끝 «근로자 공유» 기록과 내 할일 «결과 근로자 공유» 카드 · 재난안전과 전 부서 일괄 [전달] · 완료 안내의 «재평가 대기 · 공정»(작업공정 관리 폐지).

### 3-1. 공문 4종 (+ 변경 · 취소 안내)

### 3-2. 집합교육

- 상태: **안내 공문 전 → 교육 전 → 등록부 받는 중 → 완료**(+ 취소). 앞의 셋은 공문 기록에서 파생. **부서에는 «안내 공문 전»이 보이지 않는다**(목록 · 상세 주소 · 내 할일). 안내 공문을 안 보낸 채 교육 날이 지나면 부서 할 일이 생기지 않고 재난안전과 카드에 경고.
- 교육 등록 폼: «제목» 필수 · «내용» 칸 없음 · 회차 탭(최대 5일, 시간은 회차에서 합산) · 첨부 «참석자 명단(서명 포함) · 교육 자료». 목록 · 상세는 여러 날이면 «외 N일».
- 서명부: 재난안전과가 한 장을 교육에 한 번 올린다 → 부서 등록부에서 «재난안전과가 올린 서명부 사용»(파일 참조, 공문 붙임 자동 체크) / «직접 올리기».
- 등록부: 소속 부서 고정 · 대리 등록 없음 · 재난안전과 직원 몫은 재난안전과 줄에서만. **한 교육에 같은 부서는 한 번(서버에서 거절)** *(이번에 정함)*. [참석자 없음](공문 · 사유 없이 할 일 끝, [되돌리기] 가능). 종료 뒤에도 받고 할 일도 남는다.
- 교육 취소: 안내 공문 뒤 교육 전에는 [교육 취소](사유 필수) → 취소 안내 공문. 취소된 교육은 «취소» 칩 + 사유로 남고 **남은 할 일(등록부 · 출장 보고 · 등록부 공문 요약)을 보이지 않는다**. 상세 «공문» 요약에 교육 안내 · 변경 안내 · 취소 안내를 각각 [공문 보기]로.
- 종료 처리 확인 창: 남은 것을 수로(등록부 미등록 n · 등록부 공문 미기안 n · 출장 보고서) — 막지 않음, 안내는 한 번.

### 3-3. 부서 실시 교육 (자체 · 채용시 · 기타)

- **부서가 등록하면서 바로 실시 결과 보고 공문.** 재난안전과는 검토만(목록의 결재 상태 칩 + [공문 보기]). 재난안전과 화면에는 등록 수단이 없다(자기 부서 몫 제외).
- 목록 한 줄 = **결재 상태 칩 하나 + [공문 보기]**. 공문 미기안이면 [공문 보내기], 반려 · 반송이면 [다시 보내기].
- 고치는 길은 **«등록 취소»(묶음 전체) 하나** — 공문 미기안 · 반려 · 반송일 때만, 그 부서 담당자만, 확인 창에 회수되는 교육 건수 · 이수기록 · 인원 · 이수시간. [이수 수정] · [상세] · [수정] · [삭제] · 행 [공문 기안]은 기능째 없다.
- 할 일 기한 = 등록일 + 7일.
- 조회: 부서 = 자기 부서 / 재난안전과 · 군수 = 전 부서.

### 3-5. 현업근로자 관리 (대메뉴)

- 하위: 현업근로자 명단 · 작업내용 변경 이력. 메뉴 권한 «개인정보»(부서 담당자에게도 부여).
- 현업업무 6가지(고용노동부고시 제2020-62호 별표 1) 복수 선택 — 구분 «비사무직(현업)»이면 1개 이상 필수.

## 4. 의견청취 — 변경 요점

정본: 의견청취 조치 처리 단순화(2026-11-18) · SCR-OPN-001 v1.4.

### 4-1. 흐름

```
[의견 등록](전 직원 · 오프라인은 재난안전과 대리) → 재난안전과 [처리]
   ├ 조치 진행 — 조치 부서 · 조치 계획 · (예정일) → «조치중» → [조치 완료] 결과 + 증빙 파일 + 완료일 → «완료»
   ├ 바로 완료 — 결과 + 증빙 파일 + 완료일 → «완료»
   └ 반려 — 사유(확인창) → «반려»
```

- **의견에서 안전점검 · 개선조치를 만들지 않는다.** 부서와는 공문 · 메신저로 주고받고, 결과(회신 공문 · 사진)를 **파일로** 의견에 남긴다.
- 상태: **접수대기 → 조치중 → 완료**(+ 반려). «점검중» 없음 · «개선조치중» → «조치중»(«개선조치»는 위험성평가 메뉴 이름이라 겹치지 않게).
- 조치중: [조치 완료] · [계획 수정](이력에 바꾸기 전 값) · [경과 추가](중간 회신 · 사진). 완료 · 반려 건은 [재처리] → 접수대기(지난 계획 · 결과 · 파일은 이력에 남김).
- **증빙 파일 없이는 완료되지 않는다**(일반 증빙 프로필). 조치가 필요 없던 건은 반려로 닫는다. «되돌릴 수 없음» 경고는 반려에만.
- 목록: 상태 숫자 바 전체 / 접수대기 / 조치중 / 완료 · «조치 부서» 열 · 조치중 «n일째». «연동 정보» → «조치 정보»(다른 메뉴 링크 없음).

### 4-2. 점검결과지 미흡 문항

미흡을 고르면 조치 부서 · 조치 계획을 받는다(개선조치 생성 없음). 상세 «미흡 문항 조치»에서 여러 문항을 체크해 결과 + 증빙 파일 + 완료일로 **한 번에 완료**. 결재 상태와 별개로 진행. 완료한 문항은 점검결과지 수정에서 미흡 · 부서를 바꿀 수 없다.

### 4-3. 권한 · 알림

- 처리 · 조치 완료 · 계획 수정 · 경과 · 반려 · 재처리 · 미흡 문항 조치 완료 = **재난안전과 담당자**. 부서 담당자는 등록 · 조회만(처리 버튼 대신 «처리는 재난안전과 담당자가 합니다»).
- 조회: 재난안전과 · 군수 전 건 / 그 밖 = 우리 부서가 조치 부서인 건 + 내가 낸 건.
- 알림: 의견 등록(재난안전과) · 접수 7일 경과(재난안전과) · 조치 부서 지정 · 변경(조치 부서 — **안내, 할 일 아님**) · 완료 · 반려(작성자).
