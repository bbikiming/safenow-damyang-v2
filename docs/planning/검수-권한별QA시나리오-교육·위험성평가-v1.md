> **실행 결과 (2026-09-28)** — **42건 전부 PASS.** 시나리오 40건에 실행 중 찾은 결함 2건을 TC 로 더했다(ROLE-B-15 · ROLE-COM-05).
> - 사전 대조(v1)에서 찾은 **결함 7건은 같은 날 조치**했고, 그 7건을 가리키던 TC 는 전부 PASS 다 — §5.
> - 실행 중 찾은 **결함 2건(§6-1·6-2)도 조치하고 재실행**해 PASS 다 — 흐름을 처음부터 다시 돌리며 단계마다 우회 호출을 시도했다(§8 끝).
> - **ROLE-E-03**(군수에게 [재촉])은 **「군수에게는 재촉을 숨긴다」로 확정**(2026-09-28)되어 조치 후 PASS 다 — §5-8.
> - 고치지 않고 남긴 것: 동결 모듈(위험성평가 공문)의 결재 회신 우회 §6-4 — 발주처 확인 사항 · 문구 §6-3 · 진행 카드 경계 사례 §6-5 · v0.5 표 정정 §5-9.
> - 실행 방법: 로컬 서버(`python3 -m http.server 8783`) · 초기 예시 데이터 · 계정은 우측 상단 전환과 같은 저장값으로 바꿨다. 버튼은 실제로 눌렀고(참석자 등록부·종료 처리·공문 상신·생성 마법사·완료·반려·확인·재촉), 콘솔 호출은 ROLE-B-14 · ROLE-COM-04·05 에서만 썼다. TC별 확인 내용은 §8.

## 0. 준비

1. **박안전**으로 전환 → 헤더 `[?]` 도움말 → **예시 데이터 되돌리기**를 교육 화면·위험성평가 화면에서 각각 한 번 누른다. 되돌리기는 박안전으로 한다.
2. 계정 전환은 우측 상단 사용자 칩 → 이름 선택. 전환하면 지금 화면이 새 계정으로 다시 그려진다.
3. 데이터는 브라우저마다 따로다. **한 브라우저에서 계정만 바꿔 가며** 진행한다.
4. 초기 예시 데이터로 바로 볼 수 있는 것
   - 교육: 집합교육 8건(종료 7 · 「2026년 8월 정기 안전보건교육 — 신청 접수 중」 1), 자체교육 4건(환경과·물순환사업소·공공시설사업소·문화체육과), 기타교육 3건, 채용시 이수 2건(공공시설사업소)
   - 위험성평가: **2025 정기평가 완료**(재난안전과·환경과·물순환사업소, 공문 결재완료) · 2026 정기평가 없음 · 2026 수시평가 2건(물순환사업소 검토완료 / 환경과 등록됨)
5. 진행 중 상태가 필요한 TC 는 §3 데이터 준비 흐름의 몇 번 뒤인지 적어 두었다.

## 1. 테스트 계정 — 5묶음

| **B** 부서 담당자 | 하정수 (물순환사업소) · 정환경 (환경과) | 소속 부서 | 소속 부서 건만 | 내 부서 일은 되고 남의 부서 일은 안 보이거나 막힌다 — 둘을 **교차**로 본다 |
| **C** 주관부서 관리·감독 | 홍길동 (재난안전과장) · 김중대 (중대재해팀장) | 전 부서 | 없음 | 다 보이지만 아무것도 바꾸지 못한다 |
| **D** 부서 관리·감독 | 오순환 (물순환사업소장) · 문정수 (정수팀장) · 비대상 확인용 임시설 (공공시설사업소장) | 소속 부서 | 없음 + 재촉 | 소속 부서만 보이고, 할 수 있는 것은 재촉뿐 |

- 관리감독자 3화면(정기·채용시·기타)은 현업근로자 3화면과 **같은 모듈**이라 권한 동작이 같다. 현업근로자 화면에서 보고, 관리감독자 화면은 ROLE-COM-02 로 버튼 유무만 대조한다.

## 6. QA 실행 중 새로 찾은 것

6-1·6-2 는 같은 날 조치하고 재실행했다. 6-3~6-5 는 남겨 두었다.

**6-1. 정기 위험성평가의 저장 함수가 역할을 보지 않는다** — ROLE-COM-05 · ✅ 조치 완료
실측: 버튼은 숨겨져 있지만 전역 호출로 저장된다. 김담양 `RSKLIST.doUploadReport()` → 「보고서 첨부 · 2개 부서 개선조치 작성표를 열었습니다」(검수 단계가 열림) / 하정수 `RSKLIST.doDeptReport('env')` → 환경과 제출본이 「물순환사업소 하정수 대리 등록」으로 저장 / 하정수 `RSKLIST.doSurveyAll()` → 「공통 유해위험요인 설문조사표를 부서에 발송했습니다」.
근거: `js/rsk-list.js` 는 진입 함수(`uploadReport`·`openSurveyAll` 등)에만 `canManage()` 를 걸고 저장 함수에는 걸지 않았다. 코드를 전수로 다시 보니 개선조치 카드(`js/rsk-imp-cards.js`)의 **완료 확인·반려·확인 취소**(`cfmDo`·`cfmDoReturn`·`cfmCancel`)와 내 할일의 **완료 저장**(`MYWORK.doComplete`)도 역할을 보지 않았고, 데이터 계층(`DYRSK.confirmImprovement` 등)도 보지 않는다 — 부서 담당자가 콘솔로 자기 조치를 «확인»할 수 있었다. `CLAUDE.md` 「버튼만 숨기면 전역 호출로 뚫린다」의 사례다.
조치:
- `js/rsk-list.js` — 평가 운영 저장 함수 11개(`doSurveyAll`·`doClearSurveyAll`·`doDeptSurvey`·`clearDeptSurvey`·`openDeptReport`·`doDeptReport`·`clearDeptReport`·`doUploadReport`·`doClearReport`·`doReportAttach`·`wizNext`/`doCreate`)에 `manageGate()` — 권한(`canManage`)에 더해 **화면이 그 버튼을 내는 단계**를 본다(설문은 보고서 전 · 보고서 첨부는 보고서 전 · 작성 취소는 작성 단계 · 보고서 교체는 전달 뒤). 단계를 빼면 전달 뒤 보고서를 다시 올려 작성표가 비워진다. 생성은 같은 연도가 이미 있으면 막는다.
- 행 편집 저장(`saveRowOwner`·`clearRowOwner`·`saveRowFacil`·`markRowFacilNa`·`clearRowFacil`·사진 추가·삭제)에 `rowGate()` — 안쪽 `reviewSet` 이 막아도 «담당자 지정: …» 성공 문구가 뜨던 것을 없앴다.
- 재촉(`remindDept`·`remindOne`)은 **조회 범위**를 보고, 한 건 재촉은 기한초과 건만 받는다. 누구에게 재촉을 줄지는 §5-8 정책 확인 사항이라 건드리지 않았다.
- `js/rsk-imp-cards.js` — 확인·반려·확인 취소에 `cfmGate()`: 주관부서 담당자(`DYROLE.canAct(OWNER_DEPT)` — `canManage()` 와 같은 식) + **공문 상신 뒤 잠금**(`DYRSKDOC.lockOf`). `CTX.canConfirm` 은 전역 호출로 누구나 켤 수 있어 사람을 따로 본다. 담당자·기한 변경 저장도 여는 쪽과 같은 판정(완료 건 불가)으로 맞췄다.
- `js/my-work.js` — `doComplete` 가 저장 직전에 `IMPCARD.canComplete` 로 다시 본다.
재실행: 흐름을 처음부터 다시 돌리며 단계마다 시도했다 — 보고서 전: 김담양 보고서 첨부 · 하정수 대리 등록·공통 설문 발송·삭제 · 홍길동 부서 설문 첨부·삭제 · 박안전 단계 밖 보고서 교체·작성 취소 / 작성 단계: 박안전 보고서 재첨부 · 하정수 작성 취소·대리 등록 / 전달 뒤: 박안전 작성 취소 · 하정수의 환경과 재촉 · 정환경의 물순환사업소 재촉 · 기한 안 된 건 재촉 / 완료 뒤: 김담양·정환경의 `doComplete` · 하정수·홍길동의 확인·반려(스스로 확인 카드를 연 경우 포함) / 공문 상신 뒤: 박안전의 확인 취소 → **전부 거절, 데이터 무변화**. 정상 경로(생성·설문·제출·보고서·행 작성·자기 행 담당자 지정·전달·완료·반려·재제출·확인·공문 상신·관리감독자 재촉)는 모두 그대로 동작했다.

**6-2. 반려 건을 정기평가 화면에서 재제출할 수 없다** — ROLE-B-15 · ✅ 조치 완료
실측: 반려 뒤 하정수의 진행 카드는 「반려 1건 재조치 필요」와 [개선조치 완료 처리]를 보여 주지만, 그 버튼이 여는 부서 상세의 반려 건 카드에는 [완료 처리]가 없었다(막다른 길). 재제출은 내 할일 [재제출]로만 됐다.
근거: `js/rsk-imp-cards.js` `canComplete()` 가 `status === 'DONE'` 이면 false 인데, 반려 건은 설계상 `status` 가 DONE 으로 남는다(CLAUDE.md §4-3).
조치: `canComplete()` 가 할 일 판정을 `DYRSK.needsAction` 으로 한다(§4-3 단일 판정). 반려 건 카드의 반려 사유 아래에 그 부서 담당자에게만 **[재제출]**(내 할일과 같은 이름·같은 완료 창)을 낸다. 수시평가 카드는 반려 축이 없어 영향이 없다(CTA 문구 회귀 확인).
재실행: 하정수 — 진행 카드 → 부서 상세 → [재제출] → 완료 창 → 확인 대기·회차 2 / 반려 상태에서 박안전은 [재확인], 오순환·문정수·김담양은 버튼 없음, 하정수만 [재제출] / 내 할일 [재제출]도 그대로(회차 3).

**6-3. (문구 · 미조치) 참석자 등록부 중복 등록 거절 토스트의 조사 표기** — 「물순환사업소은(는) 이미 등록된 부서입니다」. `DYV2.josa()` 로 붙이는 것이 이 프로젝트 규칙이다(`js/edu-reg.js`·`js/edu-reg-detail.js` `doApply`).

**6-4. (미조치 · 발주처 확인 필요) 위험성평가 공문 모듈의 결재 회신·기안 함수가 역할을 보지 않는다**
실측: 하정수가 콘솔로 `DYRSKDOC.receive(sid, '결재완료')` → 「온나라 결재 회신 수신 — 결재완료」, 공문 상태가 결재중 → 결재완료로 바뀌었다(시험 뒤 데이터 되돌림). 코드상 `DYRSKDOC.open` 도 역할 판정이 없다.
남긴 이유: `js/rsk-doc.js` 는 **동결**이다(`CLAUDE.md` §7-1 — 위험성평가 쪽 변경은 그 자체로 발주처 확인 사항). 화면·문구를 바꾸지 않고 저장 경로에 판정만 더하는 수정이지만, 동결 규칙대로 확인을 먼저 받는다.

**6-5. (관찰 · 미조치) 진행 카드는 「처음 안 끝난 단계」에만 버튼을 낸다** — 부서가 설문조사표 작성본을 내지 않은 채 주관부서가 보고서를 받아 전달하면, 1단계가 끝나지 않은 것으로 남아 3단계 [개선조치 완료 처리]가 카드에 뜨지 않는다. 표의 [상세]로는 부서 상세에 들어가 완료·재제출할 수 있어 막다른 길은 아니다. 제출본 없이 전달하는 일이 실제로 있는지부터 확인할 사항이다(`js/rsk-list.js` `myDeptPanel()` 의 `cur`).
