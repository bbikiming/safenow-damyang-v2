## 1. 위험성평가

### 1-1. 거둔 것 — 만들지 않는다

| 거둔 것 | 이유 | 대신 |
|---|---|---|
| [입력 완료] «참여 근로자 *» | 운영에 없는 단계 · 부서 담당자의 입력 완료가 복잡해졌다 | 시행규칙 §37의4①2호 «참여한 근로자» 기록은 **부서 설문조사표 제출**(§37의2 «설문조사» — 누가 냈는지 남는다)과 **용역 통합 보고서**가 맡는다 |
| 근로자 공유 기록 · 내 할일 «결과 근로자 공유» · «지금 할 일» 마지막 단계 | 운영에 없는 단계 | 결과 공유(게시 · 교육 · 회의 — §37의3)는 시스템 밖에서 한다. 정기 위험성평가 화면 근거에서 §37의3 · §37의4 · 지침 §17 을 뺐다 |
| 작성표 «증빙(전/후)» · «완료» 열 · 행 사진 창 | 같은 입력을 두 곳에서 받아 담당자가 헤맸고(확인은 카드 기록을 본다) · 9열 표가 1280px 화면을 넘었고 · 작성 중에 «사진 필요»가 오류처럼 보였다 | 작성표 = 시설물 · 유해위험요인 · 분류 · 원인 · 개선조치 · 담당자. 사진 · 완료는 [입력 완료]로 생긴 개선조치마다 `[완료 처리]` |

- 3번의 대가 — 점검 때 이미 고친 항목도 [입력 완료] 뒤 카드에서 `[완료 처리]`를 한 번 누른다. 입력 완료 순간 «완료»로 생기는 개선조치는 없다(모두 진행중).
- 11-12 주무관 확인(C-② «두 곳 다 받는다»)을 바꾼 것이라 주무관님께는 기획에서 알립니다.

### 1-2. 다음 할 곳 안내 — 만든다

| 언제 | 화면 |
|---|---|
| 작성 중 | 작성표 아래 «개선 전·후 사진과 완료일은 여기서 받지 않습니다 — [입력 완료] 뒤 생기는 개선조치마다 [완료 처리]에서 올립니다» |
| 행을 채울 때 | 유효 행(유해위험요인 · 개선조치 둘 다) 수가 바뀌는 순간 **다시 그리지 않아도** 부서 머리 «n건 작성»과 «지금 할 일»이 바뀐다 — 빈 행은 세지 않는다 |
| [입력 완료]를 누를 때 | 펼쳐지는 확인 줄이 화면 안으로 오고 «지금 할 일»이 **줄 안의** [입력 완료]로 옮겨 간다. 줄에 «다음 차례 — 조치를 마치면 [개선조치 완료 처리](또는 내 할일)에서 건마다 개선 후 사진 · 완료일을 올립니다» |
| 입력 완료 직후 | 알림 «… 조치를 마치면 [개선조치 완료 처리]에서 사진 · 완료일을 올립니다» · 화면이 «내 부서 진행 상황»의 `[개선조치 완료 처리]`(«지금 할 일»)로 옮겨 간다 |
| 개선조치 카드(완료 전) | «개선 후 사진은 완료 처리 때 올립니다»(회색 안내) · «완료 처리 전 — 기한 …». 종전 «증빙 사진 없음 · 완료 소명 불가»는 오류처럼 읽혀 바꿨다 · 번호는 작성 순서 그대로(완료해도 바뀌지 않는다) |
| 끝났을 때 | 한 줄 머리 «완료 — 이 평가는 끝났습니다 / 우리 부서 몫은 모두 끝났습니다 / 지적사항 없음»(종전 «기다리는 중») |
| 설문 마감 뒤 | 보고서 등록으로 마감된 부서의 «미제출»은 경고색 대신 «미제출 · 마감» |

### 1-3. 알림 · 권한

| 무엇 | 받는 사람 / 규칙 |
|---|---|
| 설문 요청 · 조치 요청 · 추가 조치 요청 공문 알림 | 그 부서의 **부서 안전보건 담당자 → 없으면 부서장**(답신 1-2). **보낸 사람 본인은 뺀다**(재난안전과도 대상 부서일 때 박안전이 자기 요청 알림을 받았다) |
| 개선조치 담당자 지정 | 작성표 행 담당자는 **[입력 완료] 순간 한 번** · 카드에서 정하거나 바꿀 때 · 수시 등록 때 — 모두 본인 지정 제외 |
| 확인 반려 | 그 조치 담당자 · 미정이면 부서 안전보건 담당자 → 부서장 |
| 조치기한 재촉 | 사람 단위(지금 운영대로 — 그 부서 담당자도 보낼 수 있다) · **본인이 담당자인 건은 제외** · 부서장 화면의 [기한초과 재촉]은 기한 초과 건이 있을 때만 |
| 처음 담당자 지정 | 사유를 받지 않는다(이력 «담당자 지정»). 바꾸거나 기한을 늦출 때만 «변경 사유 *» |
| 조치 요청 공문 | 고른 부서의 조치기한이 **오늘 이후**가 아니면 거절(화면 · 기안 조건 · 저장 세 곳) |
| 업로드 | 개선 전 · 후 사진 = 이미지(JPG · PNG · GIF · 10MB · 5개) · 양식 · 보고서 첨부 창 = 1개 |

### 1-4. 단계별 안내(프로토타입 시연 기능 — 참고)

진행 표기를 «(현재 n/m)»에서 «(완료 n/m)»로 바꿨고, 설문 제출이 마감된 부서는 그 단계를 끝난 것으로 셉니다. 운영에 안내 기능이 없으면 해당 없습니다.

## 2. 안전보건교육 (11-16 대조 검토)

| 무엇 | 운영에서 |
|---|---|
| 실시 결과 공문을 온나라로 보낸 뒤 등록부 | **저장(데이터) 단계에서도 거절** — 버튼만 숨기면 직접 호출로 들어온다. 사유 «공문이 (상태) 상태라 등록부를 더 받지 않습니다 — 온나라에서 반려 · 반송되면 다시 열립니다» |
| 교육 전 종료 처리 | 저장 단계에서도 거절(마지막 회차 날 전) |
| 내 할일 «참석자 등록부 등록» | 그 교육의 대상자(현업근로자 교육 = 관리감독자 아닌 사람 · 관리감독자 교육 = 관리감독자)가 **있는 부서에만**(예정 안내와 같은 판정) |
| 미이수 독촉 | 받는 사람 알림함에 «안전보건교육 미이수 독촉 — (부서) n명 · (메모)» · 받는 사람 = 부서 안전보건 담당자 → 부서장 · **보내는 사람 본인 제외** |
| «등록부 등록 요청 · 등록 기한 안내» 알림 | **만들지 않는다**(답신 3-1 — 등록부는 내 할일 카드가 알린다). 프로토타입의 고정 예시를 걷었다 |
| 종료 확인 창 · 등록 폼 문구 | 종료 뒤 늦게 내는 등록부는 `[＋ 등록부 추가]`로 받는다(공문 보내기 전까지 — 답신 3-4). «종료하면 등록부를 더 받지 않습니다»를 쓰지 않는다 |
| 2027-01-01 주기 전환 때 2026 개인별 주기 시간 | **기획 확인 중** — 2026-11-12 ~ 2027-05-11 같은 주기의 2026년 시간을 2027 상반기에 넘겨 셀지 정해 알립니다. 정해지기 전에는 확정본 ES-23 대로(넘겨 세지 않음) |

## 4. 따라 만들지 말 것 — 결과 공문 화면(프로토타입 동결본)

정기 위험성평가 결과 공문 화면은 발주처 지시로 동결돼 있어 아래가 남아 있습니다. **운영은 확정본 §1-5 대로(결재선 없이 «온나라로 보내기» · 결재 결과 수동 기록은 지금 운영대로)** 만들어 주세요.

- 결재선 지정 칸 · «임시 채번» · 결재완료 회신에 생산등록번호 필수값 없음
- 개발 용어가 화면에 나옴 — «조직도(DYV2.ORG) 한 곳만 갱신하면 됩니다» · «결재권자는 … 코드에 고정하지 않습니다»
- 상신 확인 창의 회의 발언 인용문
- «온나라 연동은 미구현입니다 — 결재 결과는 … 회신 버튼으로 시연합니다»
- «시행규칙 제37조의4에 따라 … 참여자 … 기록»(참여 근로자 입력을 거뒀으므로 사실과 다르다)
- «조치 대상 없음» 평가만 답신 2-7 대로 고쳤다 — 본문 «용역 보고서 검토 결과 개선이 필요한 부서가 없어 조치 요청 없이 평가를 마칩니다(종결 사유: …).» · 붙임 없음. 요청받은 부서가 모두 0건으로 끝난 평가는 «조치 요청 공문을 받은 부서가 모두 조치할 것이 없다고 입력해 개선조치 없이 평가를 마칩니다.»

## 5. 확인

- 프로토타입: 재난안전과 → 부서 → 확인(반려 · 재제출 · 일괄 확인) → 결과 공문 → 결재 회신을 화면으로 끝까지 걸었고, «조치 대상 없음» 종결 · 수시평가 등록도 확인했습니다. 부서 담당자 과제 4개 사용성 검증(1280px)을 거쳤습니다. 모바일(375px)은 대상이 아닙니다.
- 이 문서의 내용 가운데 확정본과 다르게 읽히는 곳이 있으면 **확정본이 정본**입니다 — 알려 주시면 맞추겠습니다.
