# 개발 전달 — 업무 관리: 분류 작업 표시 제거 · 이행 증빙 문서 중심 사용성 정리

> 작성 2026-10-12 · 대상 화면: 업무 관리 > 이행 관리(SCR-CMP-001) · 문서 목록(SCR-CMP-002) · 내 할일(SCR-MYW-001)
> 정본은 화면정의서다. 이 문서는 무엇이 왜 바뀌었는지를 한자리에 모은 전달본이다.

## 1. 결정 — 한 줄

**문서와 할 일(업무단계)의 연결은 업무목록 엑셀(확정문서목록)을 밀어 넣어 정한다. 이 시스템은 분류하지 않는다.**
그래서 화면에서 **분류 작업의 흔적을 모두 걷고**, 업무 관리 화면에는 **이행항목의 증빙 문서로서 필요한 내용만** 남긴다.

| 원칙 | 뜻 |
|---|---|
| 분류 작업 상태를 화면에 내지 않는다 | 미분류·분류 제외·분류 확인·원문 확인·초안·확인 필요·계층 추정 등은 분류하는 쪽의 작업 기록이다. 담당자에게 보이면 「확인 필요」가 자기가 할 일로 읽힌다 |
| 판정은 바꾸지 않는다 | 할 일이 붙지 않은 문서는 여전히 이행 판정에 들어가지 않는다. 원본 값(제외 사유·분류확인·원문 확인·업무유형)은 데이터에 그대로 남긴다 |
| 사실만 말한다 | 할 일이 붙었으면 그 칩, 안 붙었으면 「연결된 할 일 없음」, 수행 위치가 정해지지 않은 할 일은 실제 실행 수단인 「문서 등록」 |
| 데이터 갭 고백은 유지한다 | 부서 이행률의 「분모 확인 필요」·「적용(추정)」, 연도별 수록 범위, 회차 기한 «말일 추정», 시설↔할 일 매핑 추정은 **분류 작업이 아니라 자료 한계**라 그대로 둔다 |

분류가 바뀌면 **엑셀을 고쳐 다시 적재**한다(화면에서 고치는 수단 없음).

### 2-2. 문서 목록 (SCR-CMP-002 · `cmp-docs.html`)

**싣는 범위 — 이행 증빙 문서만 (가장 큰 변경)**

- 목록에는 **할 일에 연결된 문서만** 싣는다. 원장 5만여 건의 대부분은 어느 할 일에도 연결되지 않은 일반 행정문서(재난 알림·물품 집행 등)였고, 2025년 기본 화면이 **52,560건 → 3,994건**이 된다.
- 연도 칩·부서 선택지·조건 칩 건수·안내 한 줄(«이행 증빙 문서 N건 · 할 일 연결 M건»)이 **같은 범위**를 센다.
- **예외 둘**
  1. 분야 조건(`?menu=` — 현황 통계·경영방침에서 옴)은 현행 업무문서(할 일 축 없음)를 함께 싣는다. 실측 `?menu=safety` 47건 그대로.
  2. 문서를 주소(`?doc=`)로 직접 열면 연결이 없어도 상세는 열린다(「연결된 할 일 없음」으로 표시).

## 5. 개발 확인 요청 (회신 불필요 — 이견 있을 때만)

1. **문서 목록 범위** — 할 일 연결이 없는 원장 문서를 목록에서 뺐다. 본개발 문서 목록 API의 기본 조건을 같게 맞춰 달라. 연결 없는 문서를 볼 별도 화면은 두지 않는다.
2. **분류 교정 경로** — 화면의 «분류 붙이기»가 없어졌으므로, 엑셀 재적재 시 기존 연결을 **덮어쓰는** 배치여야 한다(이 시스템에서 사람이 붙인 연결이 따로 없다).
