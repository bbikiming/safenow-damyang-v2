### 1-2. 바뀌는 것 (화면 · 데이터)

**A. 설문 요청 공문 (③) — 신설**
- 설문조사표 양식을 붙인 뒤 `[설문조사표 요청 공문]` → 단순 기안(`DYDOC.define({simple:true})`, 결재선 없음 · 수신처 = 대상 부서 전부 · 붙임 = 양식) → 미리보기 → `[온나라로 보내기]`. 이행점검 시달 공문(§4-2)과 **같은 모양**이다.
- **보내는 순간** 부서 내 할일에 «설문조사표 제출(기한 D-n)» 카드와 알림이 생긴다. 지금처럼 «양식 첨부 = 알림»이면 양식을 고쳐 올릴 때마다 알림이 또 간다.
- 보낸 뒤에는 양식을 바꾸지 않는다(바꾸려면 새 공문). 기존 «보고서 등록 후 잠김»(16장 카드)은 그대로.

**B. 보고서 + 조치기한 (⑤) — 작성표 단계 없앰**
- `[＋ 통합 보고서 첨부]` 창에 **조치기한(일괄 + 부서별)** 을 같이 받는다. 보고서 프로필은 그대로 `report`(30MB).
- 재난안전과의 «부서별 조치 작성표» 를 걷는다. 재난안전과는 **어느 부서에 개선이 필요한지만** 고른다(⑥).
- 2026-11-12 주무관 확인 C-① «조치기한을 너무 늦게 정한다»의 답과 같은 방향이다 — 이 발표안이 그 확정으로 읽힌다.

**C. 부서별 조치 요청 공문 (⑥) — «전달» 대체**
- 부서 표에서 개선 필요 부서를 체크 → `[조치 요청 공문]` → 단순 기안(수신처 = 고른 부서 · 붙임 = 보고서) → `[온나라로 보내기]`.
- 보내는 순간 고른 부서에 «위험성평가 조치 입력(기한)» 할 일 · 알림. 고르지 않은 부서는 **«지적사항 없음 — 완료»** 로 닫힌다(지금 `deliverFromReview` 의 0건 부서 처리를 이 자리로 옮긴다).
- 부서 표 상태: `조치전`(공문 받음·입력 0건) → `조치중` → `완료`(전 건 확인). 17장 캡처의 «전달 2026-11-10»은 «요청 2026-11-10»으로.

**D. 부서 직접 입력 (⑦) — 가장 큰 변경**
- 부서 화면(내 할일 «위험성평가 조치» 카드 → 부서 상세): `[보고서 내려받기]` · `[＋ 유해위험요인 추가]`(요인 · 조치 내용 · 담당자 — 담당자는 그 부서 사람만, A-19) · 건마다 `[완료 처리]`(개선 후 사진 · 완료일 · 서명) · `[기한 연장]`(새 기한 + 사유).
- 행 = 곧 개선조치(`improvement`). «작성 → 전달 → 생성» 두 단계가 «입력 = 생성» 하나로 준다. 사진은 완료 처리에서만 받는다(11-12 확인 C-② «사진을 두 군데서 받는다»의 답).
- **부서가 «입력 끝» 을 알리는 수단이 필요하다** — 행이 0건인 동안은 «아직 안 씀»과 «쓸 게 없음»을 가를 수 없다. `[입력 완료]`(0건이면 사유 필수) 를 둔다. 확인 대기 · 공문 기안 조건(`docReady`)은 «요청한 부서 전부 입력 완료 + 전 건 확인»으로.
- 기한 연장: 지금 `IMPCARD.amendOpen` 은 부서에게 기한 칸을 잠그고 «재난안전과에 요청»이라 안내한다. 발표안은 **부서가 직접 연장**이다 — 사유 필수 · 이력 남김 · 재난안전과 알림. (결정 R-3)

**E. 그대로 두는 것**
- 완료 확인은 별도 축 `improvement.confirm`(§4-3) — 확인·반려·한 번에 확인 그대로. `status==='DONE'` 집계 8곳 무변경.
- 결과 공문(⑧)은 동결 모듈 `DYRSKDOC` 그대로. `[공문 기안]` → 미리보기 → 상신 순서 유지.
- 수시평가는 이번 전환 대상이 아니다(흐름 방향이 반대).

## 2. 안전보건교육 — 참석자 등록과 서명 등록부 (슬라이드 27)

### 2-1. 지금

- 집합교육은 **교육이 끝난 날부터** 부서가 `[＋ 참석자 등록부 등록]`(참석자 · 실제 참석시간 · 서명파일)을 **한 번에** 올린다(`DYEDU.enrollOpen`, 2026-11-12). 등록 기한 = 마지막 회차 + `enrollDays`.
- 재난안전과는 **부서마다 한 건씩** 대리 등록(`proxy`)만 할 수 있다 — 전 부서를 한 번에 넣는 수단이 없다.
- 26장 캡처 = 현행 그대로(진행중 줄에 등록부 버튼 · 종료 뒤 `[공문 기안]`).

### 2-2. 발표안이 말하는 것

| 27장 왼쪽 «참석자는 누가 넣나요» | 27장 오른쪽 «서명 등록부는 언제 올리나요» |
|---|---|
| ① 부서가 교육 줄에서 직접 · ② **재난안전과가 대상자를 일괄 등록** | 교육이 **끝난 뒤** 서명받은 문서를 스캔해 올림 |

이상한 점 — 지금 시스템은 «참석자를 넣는 일»과 «서명부를 올리는 일»이 **한 창 한 동작**이라, 재난안전과가 집합교육 서명부 한 장(여러 부서가 섞인 종이)을 받아도 **부서 수만큼 쪼개 올려야** 한다. 실제 집합교육은 재난안전과가 진행하고 서명부도 재난안전과 손에 있다.

### 2-3. 바뀌는 것 (권장안 — «끝난 뒤 한 번» 원칙은 유지)

- **입구를 둘로** — 교육이 끝나면 같은 등록 창이 두 모드로 열린다.
  - **부서 등록**(지금 그대로): 그 부서 담당자 · 우리 부서 사람만 · 서명파일.
  - **일괄 등록**(신설, 재난안전과 담당자만): 조직도(`ORGPICK.deptsPanel` + 근로자 명단)에서 **여러 부서 사람을 한 번에** 고르고 서명부 **한 파일**을 붙인다. 저장은 부서별 등록 행으로 갈라 넣고(`addEnroll` 중복 가드 · `populationIssue` 모집단 가드 그대로) 전부 `proxy` 표시.
- **서명부 시점은 그대로 «끝난 뒤»** — 사전 신청을 되살리지 않는다(07-16 «한 단계», 11-12 주무관 확인 ①). 27장 왼쪽 «신청»은 «등록»으로 고쳐 쓴다.
- 이미 부서가 등록한 사람은 일괄 목록에서 «등록됨»으로 막는다. 일괄로 넣은 부서 줄은 그 부서가 `[등록 취소]` 할 수 없고 재난안전과만 정정한다(올린 쪽이 고친다 — 이행점검 «제출한 쪽만»과 같은 원칙).
- 부서 내 할일 «참석자 등록부 미등록» 카드는 일괄 등록된 부서에서는 사라진다(`deptTodos` 가 등록 행을 보므로 자동).
