# 개발 전달 — 시스템 관리 5화면 구현 범위 v1

작성 2026-08-19 · 대상: 사용자 관리 · 사업장 관리 · 알림 관리 · 프리셋 양식 관리 · 연계 관리
근거(정본): `docs/screen-definitions/` SCR-ADMIN-001 · 002 · 003 · 004 · 009 · `99_미결사항목록.md`

> **결론** — 이 5화면에서 **기획 보완이 필요해 막히는 항목은 없다.** 다섯 정의서의 §7 미결사항이 전부 「없음」이다.
> **41개 항목 중 34개는 외부 의존이 없고**, 나머지 **7개는 값의 원천이 밖에 있는 연계 데이터 축**이다.
> 연계 축도 **미수신 동안의 동작이 확정돼 있어** 화면은 함께 만들 수 있다.

> **범위** — 이 문서는 **시스템 관리 5화면**만 다룬다. 새올·온나라·FMS 연계는 이 5화면에 닿는 지점(B1~B7)만 적혀 있고,
> **연계 축 전체 지도는 [기획-외부연계-기능정의-v1.md](기획-외부연계-기능정의-v1.md)** 가 갖는다(축 10개 · 공통 지시 · 명칭 · 수령 순서).
> 먼저 읽을 것은 [전달-개발-패키지안내-v1.md](전달-개발-패키지안내-v1.md) 한 장이다.

## 1. 판정 기준

| 표기 | 뜻 |
|---|---|
| **A** | 기획 확정 + 외부 의존 없음 → **바로 구현** |
| **B** | 기획 확정. **값이 연계 데이터**라 그 축이 붙어야 완성된다. 화면·미수신 동작은 지금 만든다 |

B를 「기획 미결」로 읽지 말 것. 무엇을 만들지는 정해져 있고, 그 값의 원천이 밖에 있을 뿐이다.

## 2. 화면별 구현 항목

### 2-1. 사업장 관리 (SCR-ADMIN-009) — 6항목 전부 A

| # | 항목 | 판정 |
|---|---|---|
| 1 | 목록 7열 — 관할부서·사업장명·유형·유해인자·측정대상 판정·판정근거·사용상태 | A |
| 2 | 부서 필터의 **전체 건수와 목록 건수가 사용상태 조건을 함께 반영** | A |
| 3 | 등록·수정 — 관할부서는 조직도 **활성 부서**에서 선택, 유형은 관리 목록에서 선택 | A |
| 4 | 측정대상 판정 3상태 — **대상 / 비대상 / 검토 중** | A |
| 5 | 조건부 필수 — 대상·비대상은 판정근거(또는 근거 첨부) 필수, 검토 중은 검토예정일·담당자 표시 | A |
| 6 | 비활성화 — 물리 삭제 없음, 사유·처리자·시각 기록, 신규 계획 선택 제외 / **과거 상세엔 이름 유지** | A |

**주의 3가지**
- **사업장 식별값은 명칭이 바뀌어도 유지한다.** 측정계획은 식별값으로 연결하고, 표시 이름은 현재 마스터와 당시 스냅샷을 함께 쓸 수 있게 한다.
- **유해인자 메모가 비었다고 「비대상」으로 해석하지 않는다.** `검토 중`과 반드시 구분한다(판정 근거는 시행규칙 §186).
- **사업장 ≠ 시설물 대장.** 같은 장소여도 자동 병합하지 않고 **명시적 연결값이 있을 때만** 연계한다.

| 8 | 표준 양식 **보기 전용** — 편집 시도 차단 + 복제 안내 | A |

| 15 | 항목 0건 양식 = 저장은 되되 사용 불가 | A |

**입력 형식 10종 — 여기 없는 형식은 항목을 만들 수 없다**

| 형식 | 집계 | 형식별 검증 |
|---|---|---|
| 한 줄 글 / 여러 줄 글 | 불가 | 길이 |
| 숫자 | 가능 | 최솟값·최댓값 앞뒤 정합 |
| 날짜 | 가능(기간) | 시작·종료 앞뒤 정합 |
| 단일 선택 / 복수 선택 | 가능 | 선택지 1개 이상 |
| 점검 항목 | 가능 | — |
| 점수 항목 | 가능 | 최솟값·최댓값 |
| 조직도 선택 | 불가 | 조직도의 활성 부서·구성원 |
| 파일 첨부 | 불가 | 공통 첨부 계약 |

- **「조직도 선택」을 빼면 표준 양식 3종이 통째로 사용 불가가 된다** — 계획서의 담당부서·담당자, 점검표의 점검자, 조치보고의 확인자가 전부 이 형식이다.
- **형식 목록은 SCR-ADMIN-003 §4-2 한 곳에만 둔다.** 코드·정책에 목록을 각각 적으면 갈라진다.

**저장 구조 (필수)**
- 양식은 **식별값 + 버전**을 함께 갖는다. 식별값은 바꾸거나 재사용하지 않는다.
- 한 버전 = 양식명 · 적용 메뉴 · **정렬된 항목** · 입력 형식 · 필수 여부 · 선택지 · 검증 규칙 · 사용 상태.
- **편집을 열면 이름만이 아니라 그 버전의 항목 구성 전체를 불러온다.**
- **작성 문서는 사용한 양식 버전을 보존한다** — 양식을 바꿔도 기존 문서는 당시 항목·순서·선택지 그대로 보여 준다. 현재 양식으로 재해석하지 않는다.
- 삭제는 **한 번도 사용하지 않은 사용자 양식만**. 사용 이력이 있으면 사용중지, 표준 양식은 복제만.

### 2-3. 사용자 관리 (SCR-ADMIN-001) — A 6 / B 2

| # | 항목 | 판정 |
|---|---|---|
| 16 | 사용자 목록 5열 — **명단을 따로 만들지 않고 조직도 인원에 권한을 붙인다** | A |
| 17 | 등급 없음 / 접속 기록 없음을 **빈칸이 아니라 명시** | A |

| 20 | 조직 직접 등록 — **4상태**(연계 읽기 전용 / 직접 등록 사용 / 사용 중지 / 병합됨) | A |

| B1 | 부서·인원 **원본 명단** | **B** — 행정포털(새올) 조직도·SSO |
| B2 | **최근 접속** 열 | **B** — 로그인·접속 기록 수집 축 |

**정책 (개발이 반드시 지킬 것)**
- **이 화면에서 권한을 바꾸지 않는다.** 등급은 권한 관리, 메뉴 접근은 메뉴 관리. 여러 곳에서 바꾸면 「누가 언제 이 권한을 줬는가」를 답할 수 없다.
- **부서 기준 권한과 개인 지정을 구분한다** — 앞은 인사이동을 따라가고 뒤는 따라가지 않는다. 안 드러내면 이동한 사람이 옛 부서 권한을 그대로 갖는다.
- **조직도에서 사라진 사람을 자동 삭제하지 않는다** — 퇴직인지 반영 지연인지 이 화면은 모른다. 확인 대상으로 남긴다.
- **관리자 1명 상태를 경고한다** — 그 한 명이 접근을 잃으면 아무도 설정을 못 바꾼다.
- **직접 등록 조직을 물리 삭제하지 않는다** — 사용 중지로 보존, 후일 연계되면 병합·승계.
- 미수신 동안: 등록분(현재 **11 / 39**)만 표시하고 **갭을 상시 노출**, 미등록 부서로는 업무 자동발행 금지.

### 2-4. 알림 관리 (SCR-ADMIN-002) — A 7 / B 2

| # | 항목 | 판정 |
|---|---|---|
| 22 | **이벤트 20행 고정** — 각 업무 화면이 이미 「알린다」고 선언한 것만. 이 화면에서 행을 새로 만들 수 없다 | A |
| 23 | **기본 시점** — 마감 7일 전 · 1일 전, 초과 1일 뒤, 이후 완료까지 **7일마다** | A |
| 24 | **업무별 예외 시점** — 인력평가 14/7/1일 전, 의견 접수 7일 경과, 법령 수집 실패 당일·3일 연속 확대 | A |
| 25 | 수신 대상은 **역할로 지정**(사람 이름 금지) | A |
| 26 | 전 채널 해제 = 저장하되 경고 / 수신 대상 비움 = **저장 차단** | A |
| 27 | **계열 분리** — 업무 알림을 전부 꺼도 운영 알림(시스템 관리자 수신)은 남는다. 반대로 운영 알림이 업무 담당자에게 쏟아지지도 않는다 | A |
| 28 | 발송 이력 5열 + 기간·결과 조회, 이력 → 그 건으로 이동, **전체 보관**(상한 밀어내기 금지) | A |
| B3 | 외부 채널 **실제 발송**(SMS·메일·Push) | **B** — 문자발송체계 |
| B4 | 엑셀 업로드 발송 · 예약 발송 · 수신번호 마스킹 · **3회 자동 재시도** · 건별 `대기/성공/실패` · 바탕화면 바로가기 안내 | **B** — 위와 동일 |

- **기술 재시도와 업무 재발송을 구분한다** — 일시 오류는 최대 3회 자동 재시도하되 **같은 발송 건의 시도 이력으로 묶는다**. 3회 실패 뒤에는 자동 재발송을 멈추고 담당자가 **새 발송**을 만든다.
- **이력은 고치거나 지우지 않는다.** 전역 드롭다운은 조회 보조라 상한이 있지만 **이곳은 이력 대장**이라 상한이 없다.
- **규칙 변경을 소급하지 않는다** — 이미 나간 알림은 그때의 규칙으로 나간 것이다.
- 미수신 동안: 내부 알림 기록으로 동작하고 **외부 발송 성공을 가장하지 않는다.**

| # | 항목 | 판정 |
|---|---|---|

| 30 | **FMS·법제처 카드는 실제 파생** — 시설물 대장 수신 이력, 수집 배치 실행 이력에서 계산 | A |
| 31 | **재시도 창구는 로그 영역 한 곳뿐** — 카드에는 조작 수단을 두지 않는다 | A |
| 32 | **3회 연속 실패 → 「점검 필요」 + 재시도 대상 제외**, 그 사실을 로그 영역이 밝힘 | A |
| 33 | 재시도할 실패 건 0 → 버튼 비활성 + 「재시도할 실패 건이 없습니다」 | A |
| 34 | 로그 조회 조건(**기간** → 시스템 → 결과) + 목록 상태 3종(비어 있음 / 있음 / 조건 결과 없음) | A |
| B5 | **온나라 카드의 실제 상태 파생** | **B** — 온나라 |
| B6 | **행정포털 카드의 실제 상태 파생** | **B** — 행정포털 |
| B7 | 재시도의 **실제 외부 호출 실행** | **B** — 위 두 축 |

**상태 판정 계약**

| 카드 상태 | 언제 | 재시도 대상 |
|---|---|---|
| 정상 | 마지막 연계 성공 | 아니다 |
| 지연·주의 | 예정 주기를 넘겼으나 실패는 아님 | 아니다 — 밀린 것이지 실패가 아니다 |
| 실패 | 마지막 연계 실패 + 재시도 여지 있음 | **그렇다** |
| 점검 필요 | **3회 연속 실패** | 아니다 — 사람이 원인을 없앤다 |
| 수신 기록 없음 | 연계는 붙었으나 아직 0건 | 아니다 |
| 자료 미확보 | 파생 원본을 화면이 못 읽음 | **셀 수 없다** — 0건이라 단언하지 않는다 |
| 연계 이력 미구현 | 파생할 원본 구조가 아직 없음 | 아니다 |

- **건수를 하드코딩하지 않는다.** 실제 자료에서 파생하고, 못 하면 비워 둔다. (종전에 FMS 건수가 고정값이라 대장과 다른 현황을 주장한 결함이 있었다.)
- **「수신 기록 없음」과 「연계 이력 미구현」을 합치지 않는다** — 앞은 기다리면 채워지고 뒤는 개발이 붙어야 채워진다. 합치면 담당자가 기다릴지 요청할지 판단할 수 없다.
- **재시도는 사람이 누를 때만 나간다.** 화면 진입으로 실행되지 않는다. 대상은 **파생 이력을 가진 연계 전부**(현재 시설물 + 법제처) — 시설물만 세면 법령 화면에서 링크를 따라온 담당자에게 「실패 건 없음」이라고 단언하는 막다른 길이 된다.
- **「다음 배치에서 재시도」라고 쓰지 않는다** — 배치는 그 실패 건을 겨냥하지 않는다. 기다리면 해결된다는 뜻이 되어 아무도 손대지 않는다.
- **연계 파라미터(인증키·주기·상한)는 이 화면이 갖지 않는다** — 시설물은 SCR-FAC-005, 법제처는 배치 서버. 이 화면은 **링크만** 갖는다.
- **연계 작업 화면이 없는 시스템(온나라·행정포털)의 카드에는 링크를 만들지 않는다.**

## 3. 유효성 검사 — 5화면 통합

| 화면 | 항목 | 필수 | 규칙 | 오류 안내 |

## 5. 만들지 말 것 — 「빠진 것 아닌가」 하고 되물을 자리

| 없는 것 | 이유 |
|---|---|
| **결재 회신(완료·반려) 알림 이벤트** | 온나라 회신 연계 전에는 시스템이 결재 결과를 알 방법이 없다. 규칙 행을 만들면 영영 발생하지 않는 행이 남아, 담당자가 고장인지 일이 없는 건지 구분할 수 없다 |
| **위험성평가 확인 반려 알림** | 그 화면이 반려를 **담당자 화면 상시 표시**로 처리하고 알림을 선언하지 않았다. 필요하면 **그 화면 정의서가 먼저 선언**하고, 알림 관리에서 행을 만들지 않는다 |
| 연계 로그의 **「부분 실패」 상태** | 어느 연계도 그 값을 만들지 않는다. 쓰이지 않을 분기다 |
| **재정 시스템 카드** | 연계 대상은 온나라·FMS·행정포털·법제처 **네 곳**. 대상이 아닌 시스템의 카드를 세우면 아무도 책임지지 않는 빈자리가 는다 |
| **도급사업 외부 연계** | 직접 등록이 임시 대체가 아니라 **정식 경로**다. 화면이 「연계 자료에서 가져왔다」고 말하지 않는다 |
| 카드의 **재시도 버튼** | 재시도 자리는 로그 영역 하나뿐. 카드마다 두면 어느 버튼이 무엇을 다시 보내는지 알 수 없다 |
| 이 5화면의 **법령 근거 칩** | 시스템 운영 기능이지 법령이 명한 의무 이행이 아니다. **근거 없음도 정보**이며 `DYLAW.MAP` 에 `[]` 로 명시한다 |

## 6. 프로토타입과 정의서가 다른 자리 — **정의서가 정본**

| 자리 | 프로토타입 | 정본 |
|---|---|---|
| 알림 규칙의 시점 값 | 화면 초기값 | **§4-1 확정값**(7일 전·1일 전·초과 1일 뒤·7일마다) |
| 알림 발송 이력의 성공·실패 행 | 레이아웃 확인용 예시 자료 | 본개발 건별 상태 **대기 / 성공 / 실패** |
| 프리셋 저장 | 토스트만 | **양식 식별값 + 버전** 단위 저장 (§2-2) |
| 조직·사용자 명단 | 예시 자료(메모리) | 행정포털 연계 노드·인원 |
| 연계 로그 조회 조건 | 없음 | **기간·시스템·결과 조건 확정**(INT-05) |
| 재시도 실행 | 요청 안내까지 | 결과를 **로그에 남긴다** |

프로토타입에서 「예시 자료」로 표시된 값은 전부 **레이아웃·흐름 확인용**이다. 화면이 그 사실을 표시하고 있으니, 개발에서는 §2의 데이터 계약을 따른다.
