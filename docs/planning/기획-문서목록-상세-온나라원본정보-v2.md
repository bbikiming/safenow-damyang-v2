## 큰 틀 — 온나라 문서 조회 연계를 어디에 두나

**온나라는 «원본이 있는 곳», 이 시스템은 «어느 문서가 증빙인지 아는 곳»이다.** 연계는 둘을 잇는 선이지 어느 쪽을 대신하지 않는다.

**두 방향은 다른 일이다** — 설계서 7종도 이렇게 갈린다.

| 방향 | 하는 일 | 설계서 서비스 | 상태 |
|---|---|---|---|
| 올리는 연계 | 우리가 쓴 공문을 온나라 결재에 올리고 결과를 돌려받는다 | 호출기안V2 · 기안함 · 연계기안함 · 결재함 | 정해져 있다(CLAUDE.md §7-1 · 10/07 회신) |
| **읽는 연계** | 온나라에 있는 문서의 정보를 문서 목록에 붙인다 | 문서조회 · 문서등록대장 (문서목록공개는 기능에 쓰지 않는다 — 기관 전체를 돌려주는 경로라 10-27 원칙과 맞지 않는다. 담양군 동의를 받은 시험 T-2·T-3 에서만 쓴다) | **이 문서의 대상** |

**읽는 연계는 3층이다** — v2 에서 바뀐 것은 ②뿐이다.

| 층 | 묻는 것 | 정본 | 온나라 역할 |
|---|---|---|---|
| ① 판정 | 어느 문서가 어느 할 일의 증빙인가 | 확정문서목록 엑셀 | **없음** — 온나라가 판정을 바꾸지 않는다 |
| ② 연결 | 원장 문서가 온나라의 어느 문서인가 | ~~매칭 배치~~ → **그 부서 담당자가 본인 계정으로 찾아 잇는다**(10-27) | 찾기 창이 원장 값으로 후보를 띄우고, 사람이 확인해야 이어진다 |
| ③ 표시 | 연결된 문서에 무엇을 보이나 | **부서** — 온나라를 부르는 동작은 같은 부서만(6장 D-4) | 문서 정보·결재 경로·붙임 목록·수신·발신 · 붙임 내려받기 |

**«최신 정보로 업데이트»는 뜻이 둘이다**

- **(가) 이어진 문서의 온나라 값을 새로 받는다** — 결재 상태·붙임 목록. ②·③층이다. 결재 상태·경로는 볼 때 조회하고, 붙임 목록은 [붙임 목록 갱신]으로 다시 받는다.
- **(나) 온나라에 새로 생긴 문서를 목록에 들인다** — ①층을 건드린다. 판정 정본이 엑셀이므로 하지 않는다. 필요해지면 온나라 신규 문서를 후보로만 받아 엑셀로 내보내고, 분류 담당이 할 일을 붙여 엑셀로 다시 적재하는 길뿐이다(이 시스템 화면에 분류를 되살리지 않는다). 10-27 이후로는 그 후보 수집도 부서마다 본인 계정으로만 된다.

**순서**

1. 잇기 — 찾기 창 · 확인 · 해제 (MR !338 구현 · 기획 규칙은 3장) — **보조 기능**: 필요할 때 상세에서 잇는다(0-1)
2. 상세 표시 — 문서 정보 · 결재 경로 · 본문·붙임 목록 (1차) · 수신·발신 · 문서취지 (표본 뒤 2차)
3. 내려받기 — 구현은 두되 **운영에서는 받기 단추를 꺼 둔다.** 임시 파일 확인(T-5)과 담양군 답 4건이 풀리면 켠다(D-1)
4. 후속 — 업무 업로드에서 새 문서를 올릴 때 바로 잇기(별도 기획). 앞으로의 증빙이 원본과 이어지는 주 경로다
5. (조건부) 잇기 작업 목록 — 담양군이 재난안전과 열람을 허용하면(DOC-06) 다시 검토
6. (선택) 신규 문서 후보 → 엑셀 — (나)가 필요할 때만

**하지 않는 것** — 온나라 값으로 이행 판정 바꾸기 · 확정목록에 없는 온나라 문서 들이기 · 이 시스템 화면에서 분류하기 · 파일 보관 · 원장의 제목·보고일자·부서를 온나라 값으로 덮기 · 다른 부서 계정으로 대신 조회하기.

## 0. 결론

1. **연결은 사람이 하고, 보조 기능으로 둔다.** 그 부서 담당자가 문서 상세의 찾기 창에서 온나라 문서를 찾아 확인하면 이어진다. 시스템이 한꺼번에 맞추는 배치는 없다(10-27). 잇기를 할 일로 내지 않고 잇기 작업 목록도 두지 않으므로 **대부분의 원장 문서는 «연결 전»으로 남는다** — 이것을 받아들이는 설계다(0-1). 이행 판정과 무관하다는 것을 화면이 밝힌다. 앞으로 올리는 증빙은 업무 업로드에서 올릴 때 잇는다(후속).
2. **온나라를 부르는 동작은 같은 부서만 한다** — 결재 정보 조회 · 붙임 받기 · 목록 갱신. 온나라가 누른 사람의 계정으로 판정하므로(개발 실측) 다른 부서가 누르면 어차피 거절된다. 이미 저장된 값(연결 여부 · 등록번호)을 다른 부서에 보일지는 정책이라 담양군에 묻는다 — 답 전에는 **연결 여부만** 보인다.
3. **레이아웃은 v1 그대로다** — 문서 정보 표 + 왼쪽 «온나라 원본 문서» 패널. 패널은 세 상태(연결 전 / 내 부서 / 다른 부서)로 그린다.
4. **첨부는 B안으로 구현하되 운영에서는 꺼 둔다** — 누를 때만 받아 넘기고 저장하지 않는다. v1 의 «축소 조건»은 뺀다(사용자 권한으로 돈다). 20MB 상한. 받는 사람이 이미 온나라에서 받을 수 있는 같은 부서 사람이라 얻는 것이 «덜 여는 편의»뿐인데 외부 조건이 넷이므로, **운영에서는 받기 단추를 꺼 둔 채 배포**하고 임시 파일 확인(T-5)과 담양군 답 4건이 풀리면 켠다. 그동안은 붙임 목록과 등록번호 복사만 보인다(안내 문구는 두지 않는다 — 2026-10-29 간소화).
5. 현행 갭(이 시스템에서 올린 문서의 첨부가 상세에 안 보임)은 v1 그대로 함께 메운다(4-6).

## 0-1. 누가 무엇을 얻나 — 10-27 뒤 이 기능의 가치

이 기능을 처음 기획한 이유는 «총괄하는 쪽(재난안전과 · 점검 대응)이 증빙의 원본을 확인한다»였다. 10-27 원칙(타 부서 조회 불가)으로 그 이유가 대부분 사라졌다.

| 누가 | 얻는 것 | 판단 |
|---|---|---|
| 부서 담당자(자기 부서 문서) | 결재 경로 · 붙임 목록을 온나라(Edge 의 IE 모드)를 열지 않고 본다 · 등록번호를 복사해 온나라에서 바로 찾는다 | 편의 — 이미 온나라에서 할 수 있는 일을 덜 여는 것 |
| 재난안전과(다른 부서 문서) | «온나라 연결됨» 한 줄. 담양군이 허락하면 등록번호까지(DOC-06) | 지금은 거의 없다 |
| 과장 · 소장 · 군수 | 자기 부서 문서면 조회, 아니면 한 줄 | 부서 담당자와 같다 |

**그래서 위치를 «보조 기능»으로 정한다(D-8).**

- 잇기 작업 목록 · 할 일 · 독촉을 두지 않는다. 연결률을 올리는 장치를 만들어도 얻는 사람이 같은 부서뿐이라 들인 품만큼 돌아오지 않는다. 대부분의 원장 문서가 «연결 전»으로 남는 것을 받아들인다.
- 과거 문서는 이행 판정이 이미 끝나 다시 열어 볼 일이 적다. 필요할 때 상세에서 잇는다.
- **앞으로의 증빙은 올릴 때 잇는다(후속 기획)** — 업무 업로드에서 담당자가 이미 그 문서를 다루고 있는 순간이라 가장 싸고 확실하다.
- 담양군이 재난안전과 열람을 허용하면(DOC-06) 총괄 쪽에 가치가 생기므로, 그때 잇기 작업 목록(대조표가 원장 7,612건 중 4,045건에 번호를 갖고 있어 «확인만 누르면 되는» 목록이 가능하다)을 다시 검토한다.

## 3. 잇기 · 해제 (② 연결 — v2 신설)

| ☐ | 항목 | 규칙 | 근거 |
|---|---|---|---|
| ☐ | 누가 잇나 | **담당자 계층**(과장·소장·군수 제외 — 권한 등급 «부서 안전보건 담당자»로 좁히지 않는다). 연결 전 문서는 원장 부서가 글자라 조직도 이름과 다 맞지 않아, **부서 대응표 확정 전에는 단추를 부서로 가리지 않고 확인 단계에서 온나라 처리과 ≠ 원장 부서를 막는다**(10-30 Q1). 이어진 뒤의 조회·갱신은 저장된 온나라 부서코드로 판정한다(D-4). 그리고 온나라 계정이 연결된 사람. 과장·소장·군수(관리·감독 계층)는 조회만. ⚠ `DYROLE.canAct` 로 판정하지 않는다 — 주관부서(재난안전과) 담당자에게 전 부서를 열어, 온나라가 거절할 단추가 생긴다(2026-10-29 정정) | CLAUDE.md §12 — 조작은 담당자 |
| ☐ | 찾기 창 | 원장이 아는 연도·제목으로 미리 채운다. 문서번호 대조표의 보조 키 번호가 있으면 그 번호로 찾은 한 건을 후보 맨 위에 둔다 — **번호 자체는 입력 칸에도 화면에도 내지 않는다**(보낸 기관의 번호일 수 있다, 정의서 P18) | 개발 구현 · 10/21 원장대조 회신의 대조표 재사용 · 2026-10-29 정정 |
| ☐ | 확인 | **사람이 [확인]을 눌러야 이어진다.** 확인 창에 원장 값(제목·보고일자·부서)과 온나라 값을 나란히 보이고, 다르면 «제목이 다릅니다» 같은 경고를 낸다 — 경고가 있어도 담당자가 판단해 이을 수 있다. 단 **온나라 문서의 처리과가 원장 부서와 다르면 잇지 않는다**(다른 부서 문서 — 개편으로 이름만 바뀐 부서는 같은 부서, 10-30) | 10/21 «찾은 문서는 제목·보고일자 검증 필수»를 사람의 확인으로 옮김 |
| ☐ | 한 원장 문서에 여러 건 | **1:N 확정**(10-30 Q2) — 확정목록 기준 대조표에도 «후보 여럿» 12건이 남아 있고 전부 서로 다른 온나라 번호다 | 같은 네 값의 원장 행이 온나라에서 별건일 수 있다 |
| ☐ | 해제 | **넣는다.** 같은 부서 담당자만 · 확인 창 · 누가 언제 무엇을 끊었는지 기록. 끊어도 원장 문서와 이행 판정은 그대로 | 회수 경로 원칙(CLAUDE.md §4) — 없으면 잘못 이은 연결을 고칠 수 없다 |
| ☐ | 온나라 값 수정 | 하지 않는다 — 고칠 것은 연결이지 값이 아니다 | P20 |
| ☐ | 조직개편 전 부서의 문서 | 원장에는 2021년 문서와 개편 전 부서(세무회계과 등)의 문서가 있다. 지금 부서 계정으로 옛 부서 문서가 열리는지 **개발 확인 중**. 안 열리면 «연결 전»으로 두고 판정에는 영향이 없다 | CLAUDE.md §14-5 — 개편 6건 |

**잇기를 «할 일»로 내지 않고, 잇기 작업 목록도 두지 않는다(D-8)** — 법정 의무가 아니고, 7,612건을 사람이 잇는 구조라 할 일로 내면 내 할일이 연결 작업으로 덮인다. 연결률을 올리는 목록(«우리 부서 연결 전 문서» + 대조표 후보)은 얻는 사람이 같은 부서뿐인 지금은 두지 않고, 담양군이 재난안전과 열람을 허용하면(DOC-06) 다시 검토한다.

**앞으로 올리는 문서는 올릴 때 잇는다(후속)** — 업무 업로드에서 문서를 등록할 때 온나라 문서를 함께 고르게 하면 새 증빙은 처음부터 원본과 이어진다. 별도 기획으로 다룬다.

## 6. 결정

### D-1. 첨부 — **B안 · 축소 조건 없음 · 운영에서는 받기 단추를 꺼 둔다**

| 조건 | 내용 |
|---|---|
| 저장하지 않는다 | 디스크·DB·캐시에 파일 내용을 남기지 않는다. 응답에 `no-store` |
| **임시 파일 경로를 닫는다** | SOAP 라이브러리(CXF)는 첨부가 메모리 기준값(기본 100KB 안팎)을 넘으면 임시 폴더에 쓴다. ① 지금 기본값에서 기준값보다 큰 파일로 받는 동안 임시 폴더를 확인한다(T-5) ② 기준값을 받기 상한(20MB)보다 크게 명시하고 20MB 넘는 파일은 받기 단추를 내지 않는다 ③ 바꾼 설정에서 같은 확인을 한 번 더 한다. ②는 저장된 크기(`fleSize`)가 실제 크기와 같다는 전제에 기대므로, 실제로 받는 바이트가 상한을 넘으면 끊기는지도 함께 본다. **이 확인이 끝나기 전에는 받기 단추를 켜지 않는다**(2026-10-29 정정 — 종전 «운영 배포하지 않는다»는 «꺼 둔 채 배포»와 어긋났다) |
| 파일 지정 | 화면은 저장된 파일ID 로 요청하고, 서버가 ① 그 연결에 저장된 붙임 목록에 있는 파일ID 인가 ② 그 문서가 보는 사람의 부서 문서인가를 둘 다 확인한다 |
| 누를 때마다 다시 판정 | 버튼이 보였다는 것으로 허락하지 않는다 |
| 본문 · 붙임만 | 의견 · 안건채택 제외 |
| 한 번에 하나 | 묶음(zip) 없음 |
| 실패 | 같은 부서 사람에게 «지금은 내려받을 수 없습니다 — 온나라에서 이 번호로 찾아보십시오» + 번호 복사. 원인은 연계 관리에만. 저장된 파일ID 가 낡아 거절되면 목록을 한 번 다시 받아 재시도하고, 그래도 안 되면 사실을 적는다(빈 파일을 내려보내지 않는다) |
| 크기 상한 | **20MB** — 이 시스템의 업로드 상한과 같은 값 |
| **운영 노출** | **받기 단추를 꺼 둔 채 배포한다.** 켜는 조건: ① T-5 통과 ② 담양군 답 — 활용 목적 안(B4) · 보안성 검토 불요 또는 완료(B6) · 악성코드 검사 불요(B12) · 행정망 접속만(B11 — 인터넷망 접속도 있으면 그때 접속 망 판정 수단을 만들어 행정망에만 켤지 정한다. 미리 만들지 않는다). 그동안은 붙임 목록 + 등록번호 복사(복사 알림이 «온나라에서 이 번호로 찾아보십시오»를 말한다) |

**막히는 경우** — 담양군이 «받은 파일을 악성코드 검사한다»를 필수로 정하면(B12) 파일이 디스크로 내려가 «저장하지 않음»이 성립하지 않는다. 그때는 내려받기를 접고 목록 + «온나라에서 열기»로 간다. 활용 목적 밖(B4)이거나 인터넷망 접속을 막을 수 없을 때(B11)도 같다.

### D-2. 저장 — **다시 조회·받기에 쓰는 최소값 + 붙임 정보 (개발 구현대로)**

저장: 온나라 문서ID · 부서코드 · 처리과 일련번호 · 보고일시 · 제목 · 작성자 · 공개구분 · 열람 범위 · 종이 · 이관 표식 · 붙임 정보(파일ID · 이름 · 크기 · 구분). 저장하지 않음: 결재 상태 · 결재 경로 · 수신·발신 · 문서취지(볼 때 조회). 화면에는 «온나라 기준 ○○ 조회» 시각을 밝힌다.

### D-3. 담당자 칸에 기안자 — **이어진 문서 · 같은 부서에만**

### D-4. 노출 축 — **부서 · 저장값의 다른 부서 노출은 담양군 확인**

- 온나라를 부르는 동작(결재 정보 조회 · 붙임 받기 · 목록 갱신)은 **저장된 온나라 부서코드 = 보는 사람의 온나라 부서코드**일 때만. 역할 등급(주관부서 · 시스템 관리자)으로 넓히지 않는다 — 넓히면 눌러도 온나라가 거절하는 단추가 된다.
- 연결 전 문서의 잇기는 부서 대응표 확정 전까지 단추를 가리지 않고 확인 단계의 처리과 대조로 막는다(3장 · 10-30 Q1).
- **연결 여부는 누구에게나 보인다**(확정 — 정의서 P18). 저장값(등록번호 · 붙임 이름 · 기안자)은 온나라를 부르지 않으므로 기술 문제가 아니라 정책이다 — 답 전에는 같은 부서에만 보이고, 다른 부서(특히 재난안전과)에 보여도 되는지 담양군에 묻는다(7장 · DOC-06). 결재 상태·결재 경로는 저장하지 않고 온나라를 불러 받으므로 답과 상관없이 같은 부서만이다.

### D-5. 연결 해제 — **넣는다**(3장)

### D-6. 내려받기 기록 — **서버 로그로 남기고 화면은 만들지 않는다**

받는 사람이 그 부서로 한정돼 온나라에서 직접 받는 것과 범위가 같아, 감사용 화면의 필요가 낮다. 기록 항목은 사용자 · 시각 · 문서 · 파일 이름 · 크기 · 결과. 보존기간은 담양군 접속기록 정책에 맞추고, 요청이 있으면 운영이 추출한다.

### D-7. 다른 부서 사용자 문구 — **«온나라 연결됨 — 원본 정보는 담당 부서에서 봅니다»**

개발 구현(«온나라 연결됨 — 담당 부서만 열람»)과 뜻은 같고, «열람»이 금지처럼 읽히지 않게 «어디서 보는지»로 바꾼다. 정의서 P18 의 «등록번호 미표시»는 공개구분을 숨기기 위한 문구라 이 경우에 쓰지 않는다.

### D-8. 기능의 위치 — **보조 기능(필요할 때 잇기) + 앞으로의 문서는 올릴 때 잇기(후속)**

0-1 의 판단. 잇기 작업 목록 · 할 일 · 독촉은 두지 않는다. 재검토 조건은 DOC-06(재난안전과 열람) 답이다.
