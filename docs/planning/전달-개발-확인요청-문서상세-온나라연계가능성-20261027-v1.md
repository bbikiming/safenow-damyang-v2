## 이 문서의 목적

**착수 요청이 아닙니다.** 기획이 그린 방향이 실제로 가능한지, 걸리는 문제가 무엇인지를 먼저 여쭙고, 회신을 보고 **기획을 고친 뒤** 정의서에 반영해 착수를 따로 요청드리겠습니다. 그래서 질문마다 «답에 따라 기획이 바꾸는 것»을 함께 적었습니다.

**어디에 놓이는 일인가** — 온나라 «읽는 연계»는 세 층입니다: ① 판정(어느 문서가 증빙인가 = 확정문서목록 엑셀) ② 연결(원장 문서가 온나라의 어느 문서인가 = 매칭 배치, 진행 중) ③ 표시(연결된 문서에 무엇을 보이나 = 공개구분 노출 판정). 이번 일은 **③ 표시를 넓히는 일**입니다. 이행 판정과 매칭은 바꾸지 않고, 온나라에 새로 생긴 문서를 목록에 들이지도 않습니다.

**여쭙는 것** — 상세 표시 4건(A) · 첨부 내려받기 13건(B) · 시험 조회 6건(T). B 가운데 **★ 5건은 답에 따라 내려받기를 할지, 어느 문서까지 열지가 갈립니다.**

## 1. 기획이 지금 그린 방향 (확인 전 가정)

### 1-1. 상세 표시 — 레이아웃은 그대로

바꾸는 자리는 둘입니다. 그 밖의 상세 화면(머리 · 오른쪽 열의 이어받기·올해 현황·삭제 안내)은 그대로입니다.

| 자리 | 넣으려는 것 | 오는 곳 |
|---|---|---|
| 문서 정보 표 | 등록번호(생산/접수) · 결재 상태 + 결재일 · 문서 구분(생산·내부결재 / 생산·시행 / 접수) · 담당자 칸에 기안자(검토 중) | 등록번호·생산/접수: 문서등록대장·문서목록공개 / 나머지: `getDocumentView` `rdocVo`(`state` · `endDt` · `gubun` · `authorName`) |
| 왼쪽 «PDF 미보유» 상자 → «온나라 원본 문서» 패널 | ① 결재 경로(처리 · 이름 · 직위 · 처리일시 · 전결/대결) ② 본문·붙임 목록(구분 · 파일 이름 · 크기) ③ 수신·발신 ④ 문서취지 · 관련 문서 | 전부 `getDocumentView` 한 응답 — `pathVo` · `fileVo` · `apprRecvVo` · `docSendInfoVo` · `summary` · `fromRdocVo` |

- **노출은 기존 판정 그대로** — 공개구분 확인 전에는 공개 문서(`listTitleOpen=Y`)만 위 값을 보이고, 나머지는 지금 정한 «등록번호 미표시» 한 문구로 둡니다(P18·P19).
- **언제 받아 두나(가정)** — 연결할 때 `getDocumentView` 응답에서 표시용 값을 함께 저장하고, 결재중(DRDS2) 문서만 상세를 열 때 하루가 지났으면 다시 조회합니다. 화면에는 «온나라 기준 ○○ 조회» 시각을 밝힙니다.
- **보이지 않을 값** — 공개구분·열람 범위(판정에만) · 결재 의견 · 열람일시 · 부재사유 · 경로/파일 이력 · 관인 · 기관·개인 연락처 · 과제카드 · 서식 필드 · 보존기간.

### 1-2. 첨부 내려받기 — 누를 때만 받아 넘기고 저장하지 않는다

```
[사용자] 본문·붙임 목록에서 파일 이름을 누름
   └ 요청: «우리 문서ID + 파일 순번»          ← 온나라 fileId 는 화면에 없다
[서버]
   ① 저장해 둔 연결에서 fileId 찾기
   ② 다시 판정(노출 판정 + 필요하면 아래 축소 조건) — 불통과면 거절
   ③ getExchangeFile(fileId) 호출
   ④ 받은 파일을 그대로 응답으로 흘려보냄(원 파일 이름 · 캐시 금지)
   ⑤ 내려받기 기록(누가 · 언제 · 문서 · 파일 이름 · 크기 · 결과)
   ⑥ 서버에 남는 것 없음
```

| 조건 | 내용 | 이유 |
|---|---|---|
| 저장하지 않는다 | 디스크·DB·캐시·로그에 파일 내용을 남기지 않는다. 임시 파일이 불가피하면 응답이 끝나면 지운다 | 보관하면 보관 책임이 이 시스템으로 온다(P17) |
| fileId 를 화면에 내지 않는다 | 서버가 «우리 문서ID + 순번»을 fileId 로 바꾼다 | 화면에 내면 다른 문서의 fileId 로 바꿔 부르는 통로가 된다 |
| 누를 때마다 다시 판정한다 | 버튼이 보였다는 것으로 허락하지 않는다 | 버튼만 숨기면 직접 호출로 뚫린다 |
| 본문·붙임만 | 의견(DFT04)·안건채택(DFT05) 제외 | 증빙은 본문과 붙임이다 |
| 기록을 남긴다 | 사용자 · 시각 · 문서 · 파일 이름 · 크기 · 결과 | 누가 무엇을 가져갔는지 되짚어야 한다 |
| 한 번에 하나 | 묶음(zip) 없음 | 대량 반출 통로가 되고 크기 상한·부분 실패 처리가 복잡해진다 |
| 실패는 한 문구 | «지금은 내려받을 수 없습니다 — 온나라에서 등록번호로 찾아보십시오». 원인은 연계 관리에만 | 화면에서 원인을 가르면 «권한 오류»가 곧 열람 제한 문서라는 뜻이 된다 |

**축소 조건 — 파일 조회가 연계 계정 하나의 권한으로 도는 경우(B1)** — 내려받기는 아래를 모두 만족하는 문서에만 엽니다(목록은 보이고 버튼만 없음).

| 값 | 조건 |
|---|---|
| `open` | DPBT1(공개) |
| `readRangeType` | DDEP1(기관) 또는 DDEP4(전행정기관) |
| `readLimitType` | DLIM1(설정 안 함), 또는 DLIM3(날짜 지정)이고 `readLimitDate` 가 지남 — DLIM2(완결 전 문서)는 결재 뒤 풀리는 제한인지 설계서로 알 수 없어 열지 않는다 |
| `listTitleOpen` | Y |

### 1-3. 바뀌게 되는 기존 결정

10/21 회신(2장)은 «본문·붙임 파일은 받지 않는다»로 정했고 근거는 넷이었습니다 — ① 이 시스템은 원본을 가리키는 색인이다 ② 문서 목록은 결재 완료 원본을 보관하지 않는다 ③ 파일 실물은 파일관리(정보통신과) 소관이다 ④ 제안요청서는 문서 보관을 요구하지 않는다.

- 이번 방향은 저장하지 않으므로 ②와는 부딪히지 않습니다. ③은 B6 으로 여쭙고, ④는 «요구가 아니라 편의 기능»이라는 뜻으로 기획이 안고 갑니다.
- 상세 표시(1-1)도 P17 의 «새로 저장하는 값»(등록번호·결재 상태·공개구분·판정값)을 넘습니다 — 결재 경로·파일 목록(fileId 포함)·수신·발신·문서취지가 더해집니다.
- 두 가지 모두 회신을 보고 기획이 P17 을 고친 뒤에 확정됩니다.
