# 기획 — 안전보건교육 온나라 결재 상신 (공문 기안 → 미리보기 → 상신) v1.2

2026-07-24. 안전보건교육(`edu` GNB 그룹)에 **온나라 전자결재 상신** 기능을 붙이고,
상신 전에 **어떤 서식으로 기안문이 생성되는지**를 화면에서 눌러 확인하게 한다.

> **이 문서의 목적** — 결재 서식(문서 양식) 컨펌용이다. 실제 온나라 연계(호출기안·회신)는
> 프로토타입 시뮬레이션이며, 확정 대상은 **문서에 무엇이 어떤 순서로 담기는가**다.

> **v1.1 (2026-07-24)** — 상신 트리거를 **3종(총괄 / 교육별 / 개인별)**으로 분리하고,
> 목록·상세에 **온나라 결재 상태(미상신·결재중·결재완료·반려)**를 칩으로 노출한다. §7 참조.
> (§3의 3종 서식은 그중 **총괄** 트리거의 탭 구성으로 편입된다.)

---

## v1.2 (2026-08-12) — 순서 확정: 공문 기안이 먼저다 ⚠ v1.1의 전제를 대체한다

**v1.1은 "시스템이 규격 기안문을 자동 생성하고 담당자는 서식·범위만 고른 뒤 상신"을 전제했다. 발주처가 이 전제를 거부했다.**

> 참석자4 — *"결재 상신하는 프로세스가 먼저 공문이 가야 되고 공문 뿌린 다음에 결재가 태워져야"* (687)
> 참석자4 — *"모든 결재 보내기 전에 공문 작성하기가 다 떠야 될 것 같아"* (822)
> 참석자1 — *"결재 상신을 눌러요. 그럼 공문 내용이 있을 거 아니에요? **작성을 하고** … 붙임 파일에 넣어놨었잖아요. 그러면은 끝나는 거죠."* (916~921)

문제는 기능이 아니라 **순서**였다 — 공문을 쓰는 단계 없이 결재만 올라갔다(*"왜 갑자기 뜬금없이 결재 상신이 있지"* 691). 그래서 상신 진입점을 껐고(모듈은 유지), 아래 순서를 갖춘 뒤 되살린다.

### 확정 순서

```
[공문 기안]  ←  1차 진입점은 이것 하나
    ↓
공문 작성      본문 직접 입력 · 붙임 선택 · 이수자 명단 별지
               ※ 이 화면에 상신 수단 없음
    ↓
[문서 미리보기 →]
    ↓
문서 미리보기   표준 공문 지면 + 붙임 별지
               [← 수정]  [온나라로 결재 상신]
    ↓
상신 확인      대상·붙임·결재선 + 잠금 경고
               [← 미리보기]  [상신]
```

세 단계 모두 되돌아갈 수 있고, 상신 확인에서 취소하면 아무것도 기록되지 않는다.

### v1.1에서 바뀌는 것 / 그대로인 것

| 항목 | v1.1 | v1.2 |
|---|---|---|
| 본문 | 데이터에서 자동 생성 | **담당자가 직접 작성**. 시스템은 붙임을 엮고 수치를 세어 **삽입 조각**으로 건넨다 |
| 진입점 | `[결재 상신]` → 문서 미리보기 | **`[공문 기안]`** → 작성 → 미리보기 → 상신 |
| 붙임 | 없음 | **이미 올려 둔 파일에서 고른다** — 교육일지·교육사진·부서별 서명파일. 새로 올리지 않는다 |
| 이수자 명단 | 문서 본문의 표 | **붙임 별지**로 분리 |
| 서식 3종(§3) | 총괄 트리거의 탭 | **그대로 유지** — 지면 구성은 바뀌지 않는다 |
| 결재선(§5) | 지정식 | **그대로 유지** |
| 상신 단위(§7.1) | 총괄·교육별·개인별 3종 | **교육 1건 1종으로 줄인다** — 아래 참고 |
| 서식 3종(§3) | 총괄 트리거의 탭 | 총괄이 빠지므로 **탭 구성이 사라진다**. 지면 골격(머리·본문·붙임)은 교육 1건 문서가 그대로 쓴다 |

### 왜 3종을 1종으로 줄이나

v1.1 §7.1 이 3종을 둔 것은 기획 판단이고 발주처 요구가 아니었다. 다시 보니 둘은 다른 축과 같은 일을 한다.

| 종전 | 판정 | 근거 |
|---|---|---|
| 총괄(기간) | **뺀다** | `분기 안전보건교육 실시 결과 제출`을 업무 축이 이미 담당한다(6개년 440문서·34부서 실측, 기한 앵커까지 확정). 같은 일을 두 곳에서 하면 어느 쪽이 정본인지 알 수 없다 |
| 개인별 | **뺀다** | 한 사람 이수 확인서는 결재가 아니라 **증명서**다. 발급 창구는 `보고서·제증명`이 이미 있다. 확인서 한 장을 내부결재로 태우는 것은 실무와 맞지 않는다 |
| 교육별 | **남긴다** | 발주처가 유일하게 지목한 것이다 — *"등록을 시킬 때 옆에 버튼에 결재 상신이 있을 거예요"* |

덧붙여 v1.1 이 총괄·교육별을 채용시교육에 붙이려고 만든 **`교육 건` 탭은 2026-07-30 회의에서 제거 확정**됐다. 3종을 떠받치던 근거 하나가 이미 무너져 있었다.

**갈래가 하나면 담당자가 무엇을 고를지 판단하지 않는다.** 진입점도 교육 카드 한 자리로 줄인다 — 같은 이름의 버튼을 두 자리에 두고 하는 일을 다르게 하면 누를 때마다 어느 쪽인지 생각해야 한다.

### 확인 단계는 새 정보만 낸다

미리보기 지면에서 이미 본 **문서·유형·대상·붙임·결재선을 확인 화면에서 표로 반복하지 않는다.** 확인이 필요한 이유는 **되돌릴 수 없다는 사실**(문서번호 채번 · 수정 잠금) 하나뿐이므로 그것만 말한다.

이 프로젝트가 FMS 연계에서 이미 같은 결론을 냈다 — *"미리보기는 이미 무엇이 어떻게 바뀌는지를 항목 단위로 보여주므로, 그 위에 승인 단계를 하나 더 얹으면 확인하는 사람과 승인하는 사람이 갈려 **아무도 실제 내용을 읽지 않는 결재**가 된다"*(FSY-01). 다만 같은 절이 *"되돌리기 가장 어려운 동작에는 확인 문구를 한 단계 더"* 도 정했고 상신이 그에 해당하므로, 단계는 두되 **내용을 잠금 경고로 줄인다**.

> ⚠ 위험성평가 공문도 같은 확인 화면을 쓴다(`DYRSKDOC`). 지금은 문서·유형·대상·붙임·결재선을 표로 반복하고 있어 **같이 정리하는 것이 맞다** — 두 도메인이 다른 확인 화면을 갖는 것이 더 나쁘다. 다만 그쪽은 검수를 통과해 전달 범위에 든 부분이라 이 문서에서 단정하지 않고 확인 대상으로 남긴다.

### 기안 조건

| 단위 | 열리는 조건 |
|---|---|
| **교육 1건**(유일) | **완료 상태 교육**에만. 진행 중인 교육의 실시 결과는 보고할 수 없다 |

판정 기준은 교육의 완료 상태 하나다 — 집합교육은 **종료 처리**를 거쳐야 완료가 되고, 자체·기타·채용시 교육은 이미 실시한 것을 기록하는 것이라 **등록 즉시 완료**다. 그래서 "종료 처리된 교육"이라고만 쓰면 자체교육에 기안 수단이 붙는 것이 규칙 위반처럼 읽힌다.

**이수율은 조건이 아니다.** 전원 이수를 조건으로 걸면 이수율이 낮은 부서가 실시 결과를 영영 보고하지 못한다. 5개년 실측에서 부서 이수율은 38~56% 구간이 실재했고, 보고할 것은 **실시했다는 사실과 그 결과**이며 미이수는 결과의 일부로 함께 적는다.

### 구현 상태 (2026-08-12)

**구현 완료.** 공용 골격 `js/doc-flow.js`(`DYDOC`) 신설 + 교육 파사드 `js/edu-doc.js`(`EDUDOC`). 완료 상태 교육 카드에 `[공문 기안]` 이 붙고, 기안 → 미리보기 → 상신 → 잠금까지 동작한다. 붙임 후보는 교육 첨부와 부서별 서명파일에서 나오고 이수자 명단은 별지로 짜인다. 시연 투어도 5단계로 이 흐름을 따라간다.

**위험성평가(`DYRSKDOC`)는 동결이다** — 같은 순서·지면을 자체 구현하고 있어 구조상 중복이지만, 기능 정의와 UI/UX 를 더 바꾸지 않기로 확정했다(2026-08-12). 검수를 통과해 전달 범위에 든 부분이다. 두 구현이 공존하는 것은 **알고 두는 예외**이며, 이관한다면 화면 무변경이 전제다(CLAUDE.md §7-1).

### 구현 지침

- **교육용 공문 화면 계열을 새로 만들지 않는다.** 위험성평가 `DYRSKDOC`(`js/rsk-doc.js`)가 같은 순서를 이미 갖추고 있었으므로, 그 순서·지면을 **공용 골격 `DYDOC`(`js/doc-flow.js`)으로 추출**하고 교육은 붙임 후보·별지·삽입 조각·저장 위치만 얹는 파사드(`js/edu-doc.js`)로 만들었다. 위험성평가는 검수를 통과해 전달 범위에 들었으므로 **동결**이라 자체 구현으로 남는다 — 두 구현의 공존은 모르고 방치하는 것이 아니라 알고 두는 예외다(CLAUDE.md §7-1).
- **새 메뉴를 만들지 않는다.** 진입점은 교육 화면 안에 둔다 — 공문만 따로 모으는 분류는 실무에 도움이 되지 않는다는 것이 이미 확인됐다.
- **순서를 지키는 책임은 골격에 있다.** 기안 폼에 상신 수단을 두지 않는 것은 `DYDOC` 이 기안·미리보기·확인을 **각각 다른 화면으로 나눠 그려** 강제한다 — 도메인이 순서를 건너뛸 길이 없다. 구 스위치 `EDUAPV.SUBMIT_ENABLED` 와 모듈 `js/edu-approval.js` 는 2026-08-12 폐기됐다(되살리지 말 것 — CLAUDE.md §4). 되살리면 발주처가 거부한 "공문 없이 결재만" 상태로 돌아간다.
- 화면 정의서 정본: `SCR-EDU-001 §4-6`(기안·상신 규칙) · `SCR-EDU-004 §4-5`(교육 1건 단위·붙임 구성) · `SCR-EDU-007 §4-1`(상신 경로 안내).

## 1. 배경 · 문제

- 현재 안전보건교육은 등록·신청·이수 관리까지만 시스템 안에서 돌고, **결재는 시스템 밖**(한글 문서 작성 → 온나라 첨부)에서 이뤄진다.
- 담당자는 매번 교육 목록과 이수 현황을 손으로 옮겨 적어 기안문을 만든다 — 옮겨 적는 과정에서 수치가 어긋나고, 부서마다 서식이 다르다.
- 따라서 **시스템이 보유한 데이터(DYEDU)로 규격 기안문을 자동 생성**하고, 담당자는 서식·범위만 고른 뒤 상신하면 되게 한다.

## 2. 확정 사항

| 항목 | 결정 |
|---|---|
| 진입점 | 전 `edu-*` 화면 **우측 최상단**(페이지 제목 행 오른쪽) 고정 버튼 `[온나라 결재 상신]` |
| 상호작용 | 버튼 → **결재 문서 미리보기 팝업** (인력평가 `evl-eval` 의 결재 문서 미리보기와 같은 패턴) |
| 서식 | 한 팝업 안에서 **3종을 탭으로 전환** — ① 교육 종류별 목록 · ② 개인별 이수 현황 · ③ 통합 |
| 조회 조건 | 팝업 상단에서 **대상 연도 · 대상 부서**를 바꾸면 문서가 즉시 다시 생성된다 |
| 상신 | 팝업 하단 `[온나라로 결재 상신]` → 확인 → 문서번호 부여 안내(연계 시뮬레이션) |
| 결재선 | **고정하지 않는다** — 기본값 `기안 → 팀장(검토) → 과장(결재)`, 조직도에서 변경·추가·삭제 (§5) |
| 데이터 | 전부 `DYEDU` 파생 — 결재용 별도 시드를 만들지 않는다 |

### 2.1 화면별 기본 서식

버튼은 모든 화면에서 같지만, **그 화면에서 가장 쓸 법한 서식이 먼저 열린다**(탭으로 언제든 전환).

| 화면 | 기본 탭 |
|---|---|
| 정기교육 · 채용시교육 · 기타 교육 · 관리감독자 정기/기타 · 정기교육 상세 | ① 교육 종류별 목록 |
| 이수현황 · 근로자 명단 관리 | ② 개인별 이수 현황 |

## 3. 문서 서식 3종

> ⚠ **아래는 v1.1 기록이다** — v1.2(문서 상단)가 대체했다. 상신 단위는 교육 1건 1종이고 총괄·개인별은 폐기됐으므로
> **서식도 1종**이다(탭 구성이 사라졌다). 지면은 여기 적힌 보고서 서식이 아니라 **표준 공문 서식**
> (「행정업무의 운영 및 혁신에 관한 규정 시행규칙」 별지 제1호서식)이고, 본문은 자동 생성하지 않으며 큰 표는
> 붙임 별지로 뺀다. 현행 구현 메모는 §8, 상위 규칙은 CLAUDE.md §4·§7-1.

세 서식은 **머리(기관 표시 + 결재란 + 제목 + 문서 개요표)와 꼬리(붙임 · 연계 안내)를 공유**하고, 본문 구성만 다르다.

### 공통 머리

- 기관 표시 `담양군청 / {기안자 소속}`, 우측 **결재란** — 칸 수·직위·이름은 §5 의 결재선을 그대로 따른다
- 제목 `{연도}년 …` · 부제 `대상기간 · 기준일 · 대상 범위`
- 문서 개요표 — 문서번호(상신 시 온나라 부여) · 기안일자 · 기안자 · **결재선** · 대상 범위 · 근거 법령
  - 근거 법령: 산업안전보건법 §29, 같은 법 시행규칙 §26 [별표 4] / 중대재해처벌법 §4①1호, 시행령 §4

### ① 교육 종류별 결재 목록 문서 — `{연도}년 안전보건교육 실시 결과 보고`

**무엇을 언제 몇 시간 실시했는가**를 결재받는 문서.

| 절 | 내용 |
|---|---|
| Ⅰ. 종합 요약 | 실시 교육(건) · 총 교육시간(h) · 이수 연인원(명) · 참여 부서(개)<br>※ 부서를 지정한 문서에서는 마지막 칸이 **부서 대상 인원**으로 바뀐다(‘참여 부서 1개’는 정보가 없으므로) |
| Ⅱ. 교육 종류별 실시 집계 | 교육 종류 / 실시 건수 / 교육시간 합계 / 이수 연인원 / 종료·전체 + **합계 행** |
| Ⅲ. 교육 종류별 상세 목록 | 종류별 소제목(건수·시간·연인원) 아래 표 — 연번 / 교육 일시 / 교육명(내용) / 시간 / 강사 / 장소 / 대상 부서 / 이수 / 상태 |
| 붙임 | 교육계획서 · 참석자 서명부 · 교육 사진 |

- 교육 종류 순서: 정기(집합) → 정기(자체) → 채용시 → 기타 → 관리감독자 정기 → 관리감독자 기타.
- 해당 연도에 실적이 없는 종류는 표에 나타나지 않는다(빈 절을 만들지 않는다).

### ② 개인별 교육 이수 현황 결재 문서 — `{연도}년 안전보건교육 개인별 이수 현황 보고`

**누가 몇 시간 이수했고 누가 미달인가**를 결재받는 문서.

| 절 | 내용 |
|---|---|
| Ⅰ. 종합 요약 | 교육 대상자 · 이수 완료 · 미이수 · 이수 완료율 + 필요시간 산정 근거 문장 |
| Ⅱ. 부서별 이수 현황 | 부서 / 대상 / 완료 / 미이수 / 완료율 |
| Ⅲ. 개인별 이수 현황 | 연번 / 부서 / 성명 / 구분 / 고용형태 / 채용일 / **교육 사이클(기간)** / 필요 / 인정 / 미달 / 이수 여부<br>미이수 행은 옅은 경고색으로 구분해 결재권자가 훑어볼 수 있게 한다 |
| Ⅳ. 미이수자 조치 계획 | 미이수 인원·부족 시간 합계, **사이클 종료 D-30 이내 인원**, 차기 집합교육 안내 |
| 붙임 | 개인별 이수 내역 · 미이수자 명단 |

- 필요·인정·미달·사이클은 전부 `DYEDU.statusRow()` 한 곳에서 나오므로 **이수현황 화면의 수치와 항상 일치**한다.

### ③ 통합 결재 문서 — `{연도}년 안전보건교육 실시 결과 및 이수 현황 통합 보고`

①과 ②를 **한 건의 기안문**으로 묶는다. 실시 실적과 이수 결과를 한 번에 결재받을 때 쓴다.

Ⅰ. 종합 요약(지표 8칸: 실시 교육·총 교육시간·이수 연인원·교육 대상자·이수 완료·미이수·완료율·부족 시간 합계)
→ Ⅱ. 교육 종류별 실시 집계 → Ⅲ. 교육 실시 목록(종류 열 포함 단일 표) → Ⅳ. 부서별 이수 현황
→ Ⅴ. 개인별 이수 현황 → Ⅵ. 미이수자 조치 계획.

## 4. 조회 조건 — 대상 연도 · 대상 부서

- **대상 연도** — 데이터에 실재하는 교육 연도 + 기준일 연도. 문서의 대상기간(`{연도}.01.01~12.31`)을 결정한다.
- **대상 부서** — 전체 부서 또는 특정 부서 1개. 지정하면
  - 교육은 그 부서가 **신청(집합)했거나 그 부서가 등록(자체·채용시)한 건**만 남고,
  - 이수 인원·대상 부서 열도 그 부서만 집계·표기하며,
  - 대상자·부서별 요약도 그 부서만 남는다.
- 조건을 바꾸면 문서가 즉시 다시 그려진다 — **바뀐 조건이 문서 부제·개요표에 그대로 찍히므로** 무엇을 결재받는지 오독할 수 없다.

## 5. 결재선 — 법령이 정하지 않으므로 지정한다

### 왜 고정하지 않는가

| 구분 | 정하는 것 | 근거 |
|---|---|---|
| 안전보건 법령 | **의무 주체**(사업주 = 군수)와 교육 실시·기록·점검 의무 | 산업안전보건법 §29 등 / 중대재해처벌법 시행령 — 교육 실시 여부 반기 1회 이상 점검·조치 |
| 행정 문서 규정 | 결재의 원칙 — 원칙적으로 기관장 결재, 위임 사항은 **전결**, 부재 시 **대결** | 「행정업무의 운영 및 혁신에 관한 규정」(대통령령) |
| 지자체 자치법규 | **문서 종류별 전결권자** — "안전보건교육 실시 결과 보고 = 과장 전결" 식 | 담양군 사무 위임·전결 규칙 |

즉 **누가 결재하는지는 안전보건 법령이 아니라 담양군 위임전결규칙이 정한다.** 시스템이 결재선을 못박으면
규칙 개정·조직 개편 때마다 코드를 고쳐야 하고, 부서·문서 종류에 따라 전결 단계가 다른 현실을 담지 못한다.
그래서 **기본값만 제안하고 지정·변경할 수 있게** 한다. (실제 온나라 연계 시에도 결재선은 온나라 쪽 값이 최종이다.)

### 동작

- 위치 — 팝업 안 `결재선` 카드(조회 조건 아래, 서식 탭 위). 바꾸면 **문서의 결재란·개요표가 즉시 갱신**된다.
- 기본값 — **기안자 소속 부서의 팀장(검토) → 부서장(결재)**. 조직도(`DYV2.ORG`)에서 직위명(`…팀장`, `…과장/소장/실장/국장/읍장/면장`)으로 찾아 파생하므로 조직 개편이 그대로 반영된다.
- 1단계 `기안`은 **현재 로그인 사용자로 고정**(작성자 = 기안자).
- 2단계부터 `[조직도]` 버튼 → **공용 인라인 조직도**(`ORGPICK` `member` 모드)에서 선택. 새 드롭다운을 만들지 않고 전 화면이 쓰는 같은 트리를 그대로 쓴다. 별도 모달을 띄우지 않으므로 단일 모달 규칙에 어긋나지 않는다.
- `[단계 추가]` — 최종 결재자 앞에 검토 단계를 끼운다(기안 외 최대 3단계). `[삭제]` — 해당 단계 제거(최종 결재 1단계는 유지). `[기본값]` — 팀장 → 과장으로 복원.
- **단계 이름은 자동** — 마지막이 `결재`, 그 앞은 모두 `검토`(행정 결재 관행: 검토 N + 최종 결재 1).
- 결재자를 고르지 않은 단계가 있으면 **상신이 차단**되고 안내 토스트가 뜬다.
- 지정한 결재선은 세션에 남아 **다른 교육 화면으로 이동해도 유지**된다.

## 6. 상신 · 이력

1. `[온나라로 결재 상신]` → 문서명·대상 범위·결재선을 확인 문구로 다시 보여준다.
2. 확인 시 문서번호(`재난안전과-NNNN`)를 부여하고 상신 안내 팝업 + 토스트를 띄운다.
3. 상신 이력은 세션에 남아 **팝업 상단 ‘최근 상신’ 줄**과 **문서 개요표의 문서번호 칸**에 반영되고, **결재 이력 화면(`edu-approval.html`)에서 총괄·교육별·개인별 상신 건을 한 곳에서 조회**한다(문서번호·상신일·구분·대상·결재선·상태 + 행별 [문서]·[상태]).
4. 실제 연계 시에는 온나라가 결재 완료 시점에 **문서등록번호·결재일**을 회신하고, 그 값이 교육 이력과 연결된다(현 단계는 시뮬레이션).

## 7. v1.1 — 상신 트리거 3종 + 결재 상태

> ⚠ **아래는 v1.1 기록이다** — v1.2(문서 상단)가 대체했다. 상신 단위는 **교육 1건 1종**이고 총괄·개인별은 폐기됐으며,
> 진입점은 완료 상태 교육의 `[공문 기안]` 한 자리다. 이 절의 모듈·API 이름(`EDUAPV` 계열)도 폐기됐다.
> 유지되는 것은 **§7.2 의 상태 어휘 4단계**와 **§7.3 결재선 공유**뿐이다. 현행 구현 메모는 §8, 상위 규칙은 CLAUDE.md §4·§7-1.

§3의 서식은 "무엇을 담느냐"였다. v1.1은 **"어디서 무엇을 대상으로 상신하느냐"**를 3종으로 나눈다.

### 7.1 트리거 3종

| # | 트리거 | 진입 위치 | 대상 | 문서 |
|---|---|---|---|---|
| Type 1 | **총괄 상신** | 목록 화면 **우측 최상단** `[총괄 결재 상신]` | 대상 연도·부서 범위의 **모든 총괄 데이터** | §3의 3종 탭(종류별·개인별·통합) |
| Type 2 | **교육별 상신** | 각 교육 **카드/상세의 결재 상태 칩** · 상세 상단 `[이 교육 결재 상신]` | **교육 1건**(그 N월 집합/자체/기타/관리감독자 교육) | 그 교육의 **실시 결과 보고**(개요·회차·참석/이수·서명·증빙) |
| Type 3 | **개인별 상신** | 이수현황 **대상자별 상세 표의 각 인원 행** | **대상자 1명** | 그 사람의 **교육 이수 확인서**(이수 내역·인정시간·판정) |

- 교육별(Type 2)은 **모든 교육 종류**에 적용한다 — 상세 페이지가 있는 정기 집합교육은 상단 버튼으로, 그 외(정기 자체·기타·관리감독자)는 **카드의 상태 칩/상신 버튼**으로 같은 문서를 띄운다.
- **채용시교육**은 화면이 근로자 행 단위라 교육 카드가 없었으므로 **`교육 건` 탭**(미이수 / 이수 / 교육 건)을 신설해 실시한 채용시 교육을 **건 단위 카드**로 노출하고 같은 교육별 상신 컨트롤을 건다. 대상자별 이수 취소는 종전대로 `이수` 탭에서 처리한다.
  - 일괄 이수처리는 **교육 건 생성 방식**(근로자별 개별 건 / 한 건으로 묶기)을 고를 수 있다. 묶기는 이수일이 하나여야 하므로 일괄 이수일과 함께 쓰이고, **필요시간(1h·4h·8h)이 다르면 법정 교육시간이 다른 별개 과정이라 건이 나뉜다**. 묶인 건은 한 장의 결재 문서로 부서별 이수 현황을 담는다.
  - 묶인 건에서 개인 이수를 취소해도 **그 사람 기록만** 회수되고 건과 다른 대상자는 유지된다(`DYEDU.removeWorkerFromCourse`).
- 교육별 문서 범위는 **해당 교육 1건**이다("N월 전체"가 아니라 그 상세의 교육 1건).
- 개인별(Type 3) 문서의 인정시간은 현재 사이클 기준이고, 이수 내역은 대상자의 전체 이력을 담는다.

### 7.2 결재 상태 (목록 노출)

- 상태 4단계: **미상신 → 결재중 → 결재완료 / 반려**. `DYV2.STATUS_TONE` 매핑(미상신 neutral · 결재중 info · 결재완료 success · 반려 danger).
- 노출 위치: 교육 카드·상세(교육별 상태) · 이수현황 대상자 행(개인별 상태) · 총괄 팝업 상단(최근 총괄 상신 상태).
- 칩 동작: **미상신**이면 칩 자리가 `[결재 상신]`(교육별)·`[개인 상신]`(개인별) 액션 버튼이고, **상신 이후**엔 상태 칩이며 클릭 시 **결재 상태 팝업**이 열린다.
- 결재 상태 팝업: 문서번호·상신일·결재선·상태 이력 + `[문서 다시 보기]`.
  - **시연 회신 버튼(`[결재 완료 처리]`·`[반려 처리]`)은 v1.2 에서 뺐다 — 만들지 않는다.** 결재 완료·반려는 온나라가 회신해야 생기는 값이라 이 화면이 만들 수 있는 것이 없고, 버튼을 두면 없는 연동을 있는 것처럼 약속하게 된다. 연동 전에는 **상신된 사실과 문서만** 보여 준다.
  - 같은 이유로 `[재상신]`도 두지 않는다 — 재상신은 반려 회신이 있어야 성립한다.
- 상신 시 목록이 자동 갱신된다(화면 모듈이 `EDUDOC.registerRefresh(render)` 등록 — v1.1 의 `EDUAPV` 축은 폐기).

### 7.3 결재선 (§5 그대로)

세 트리거 모두 §5의 결재선(기본 팀장→과장, 조직도로 편집)을 공유한다. 문서 종류가 달라도 결재란·개요표는 지정한 결재선을 그대로 따른다.

### 확장 여지 (미구현)

- 결재선 **기본값을 담양군 위임전결규칙에서 확정** — 현재 기본값(팀장 → 과장)은 관행 기준 제안값이다. 규칙 원문 확인 후 문서 종류별 전결 단계를 고정 기본값으로 반영할 것.
- **온나라 연동** — 호출기안·문서번호 채번·결재 완료/반려 회신이 전부 미구현이다. 현재는 임시 채번과 상신 결과 재현이며 화면에 그렇게 밝힌다. 회신이 붙으면 결재완료·반려 지표와 재상신 경로가 그때 생긴다.
- **담양군 고유값** — 처리과 기호·주소·전화·팩스·전자우편·공개구분·관인이 미수신이라 지면에 `미등록`으로 드러낸다(외부 준비 항목 `doc-org` — 온나라·새올 **연계 구현 범위**로 재분류, 99_미결사항 §4, 2026-08-14). **그럴듯하게 채우지 않는다.**
- **담양군 공문 샘플** — 미수신이다(외부 준비 항목 `official-letter` — 2026-08-14 미결 대장에서는 소거: 지면이 법정 서식이고 본문이 직접 작성이라 샘플이 설계를 바꾸지 않는다, 99_미결사항 §6). 샘플이 오면 본문 문구만 맞춘다. 공문 흐름이 구현됐다고 해서 **발주처가 건 조건이 충족된 것은 아니다** — 확인은 발주처 검수에서 받으며, 우리 구현으로 자기승인한 기록을 남기지 않는다.
- 기타 교육 유형별 별도 서식은 두지 않는다 — 유형(근로자 3종 / 관리감독자 2종)이 달라도 상신 단위가 **교육 1건**이라 같은 지면을 쓴다. 갈래를 늘려야 할 실무 사유가 확인되면 그때 검토한다.

## ⚠ §5(결재선) — 2026-08-27 확정으로 대체됨

§5 의 「`ORGPICK` **`member`** 모드」·「최대 3단계」·「최종 결재 1단계는 유지」는 더 이상 유효하지 않다. 정본은 [`기획-결재선-3계정-정합-v1.md`](기획-결재선-3계정-정합-v1.md) · [`_공통_권한정의.md`](../screen-definitions/_공통_권한정의.md) §7 이다.

- 결재선 선택은 **`memberUid`** 모드다 — `member`(표시 문자열)는 uid 를 버려 온나라 결재선(계정 식별자 배열)을 만들 수 없다.
- 단계는 기안 제외 **최소 2(검토+결재) · 최대 4**. 「최종 결재 1단계」는 검토 없는 결재선을 허용하므로 금지된다.
- 기안·검토·결재는 **서로 다른 계정**이어야 한다.
- 문서 앞부분의 「기안 → 미리보기 → 상신」 순서와 교육 1건 단위 확정은 그대로 유효하다.
- 교육은 **결재 결과를 받지 않는 도메인**이다(2026-08-28 확정) — 결재 결과가 후속 업무를 열지 않으므로 `결재중` 하나만 만든다.
