# 기획 — 외부 연계 기능 정의 v1

작성 2026-08-19 · 성격: **기획 지시서(SoT)** · 대상: 외부 시스템에서 값을 받는 전 축
정본 기능 정의는 각 **화면 정의서**가 갖는다. 이 문서는 **축을 한눈에 모으고 공통 지시를 확정**한다.

> **이 문서가 하는 일** — 연계 축이 10개인데 12개 파일에 흩어져 있어, 개발자가 «새올에서 무엇을 받아 어디에 꽂는가»를 한눈에 볼 수 없었다. 축 목록과 공통 지시를 여기 모으고, **각 축의 기능 정의는 소유 화면 정의서를 가리킨다.**

---

## 1. 이 문서가 지시하는 범위

**기획은 「이 값이 연계 데이터다」와 「받기 전까지 화면이 어떻게 동작한다」까지 정한다.** 어떻게 받아 오는가는 개발이 정한다 — 이 저장소는 연계 규격을 적지 않는다.

| 정한다 | 적지 않는다 |
|---|---|
| 무엇이 **외부 정본**인가 — 그래서 이 시스템이 만들지 않는 값 | 연계 규격 일체 |
| **미수신 동안의 동작** — 무엇을 표시하고 무엇을 성공으로 가장하지 않는가 | |
| 값이 **어느 화면으로 들어가 무엇을 바꾸는가** | |
| 연계의 **작업·이력을 어느 화면이 갖는가** | |
| **명칭** — 무엇을 무엇이라 부르는가 | |

---

## 2. 공통 지시 6 (전 축 적용 · MUST)

1. **정본이 밖에 있는 값은 이 시스템이 만들지 않는다.** 명단·조문·시설물 제원처럼 원천이 있는 값을 화면에서 생성·수정하면 인사이동·개정 때 여기만 옛 상태로 남는다.
2. **미수신을 그럴듯하게 채우지 않는다.** `미등록` · `기록 없음` · `수신 기록 없음`으로 **비어 있음을 그대로 표시**한다. 임의 날짜·0건으로 채우면 *한 번도 받지 않은 상태*와 *받았는데 0건인 상태*를 구분할 수 없다.
3. **성공을 가장하지 않는다.** 동기화·발송·상신이 실제로 일어나지 않았으면 성공 문구를 쓰지 않는다. 화면 문구는 `DYV2.notReady()` 한 창구로 낸다(CLAUDE.md §15).
4. **출처를 값 옆에 남긴다.** 연계 수신분 / 직접 등록 / 엑셀 업로드를 행마다 구분한다. 섞으면 연계가 열렸을 때 **무엇을 교체하고 무엇을 남길지** 가릴 수 없다.
5. **연계 수신분은 읽기 전용, 보완값은 별도 축.** 원천값을 화면에서 덮어쓰면 다음 수신 때 조용히 되돌아간다.
6. **미수신이 업무를 막지 않는다.** 대체 경로(직접 등록·엑셀·수동 기록)를 열어 두되 **임시 대체인지 정식 경로인지 화면이 밝힌다**(도급은 직접 등록이 정식 경로다).

## 3. 연계 축 10 — 기능 정의는 소유 화면 정의서에 있다

**상태 모니터(SCR-ADMIN-004)가 상태를 말하는 대상은 온나라·FMS·행정포털·법제처 네 곳뿐이다.** 파일관리·문자발송체계는 원천이 밖에 있지만 상태 카드를 두지 않는다 — 개수를 세는 자리에서 여섯으로 말하면 화면과 어긋난다.

| # | 축 | 원천 | 기능 정의(정본) | 미수신 동작(확정) | RFP |
|---|---|---|---|---|---|
| 1 | 조직도·부서·인원(팀 편제) | 행정포털(새올) 조직도·SSO | **SCR-ADMIN-001** §4-4·§6 | 등록분(11/39)만 표시하고 **갭 상시 노출** · 미등록 부서로 업무 자동발행 금지 · 행정포털에 없는 조직만 직접 등록 | SFR-006·015 |
| 2 | 인사 기본정보(채용일·고용형태) | 행정포털·인사 | **SCR-EDU-006** §4·§6 | 직접 등록·엑셀로 받되 **출처를 행마다 표시** · 인사연동분은 읽기 전용 · 관리감독자 지정일은 별도 보완값 | SFR-015·016 |
| 3 | 기관정보·관인·문서번호 | 온나라·새올 | **SCR-RPT-002** §6 · 공문 지면 | 처리과 기호·주소·전화·팩스·관인을 `미등록` · 문서번호는 `임시 채번` · **상신 자체는 막지 않는다** · 서식 적합·관인 판정은 하지 않는다 | SFR-005 |
| 4 | 결재 상신·결재상태·지면 | 온나라 전자결재 | **SCR-EDOC-008** | 상신하면 `결재중`만 남긴다 · **결재완료·반려를 만들지 않는다**(회신 연동으로만 생성) · 진행은 온나라에서 문서번호로 확인하라고 밝힌다 | SFR-005 |
| 5 | 문서 담당부서·담당자 | 새올행정시스템·온나라 | **SCR-DOC-002·003** | 값 없는 문서는 `기록 없음` · **부서로 조회를 좁히지 않는다** · 업로드는 조직도에서 직접 선택(자동 추천 없음) | SFR-004·014 |
| 6 | 파일 실물(저장·복사·내려받기·원본 경로) | 파일관리(정보통신과) | **SCR-DOC-004** §6 | 이름·크기·등록일·버전만 보관 · **내려받기가 된 것처럼 굴지 않는다** · 미리보기는 원본 렌더가 아님을 지면에 표시 | SFR-001 |
| 7 | 시설물 기본현황·1/2/3종 | FMS | **SCR-FAC-004** | 파일 검증 반입만 허용 · **동기화 성공 처리 금지** · 수신분과 직접 입력을 구분 | SFR-002·016 |
| 8 | 안전등급·최근 점검일·중대결함·상세제원·전경 사진 | FMS·국토안전관리원 | **SCR-FAC-002** §6 | 등급 없으면 **산정 불가** · 점검일 없으면 주기 초과 미판정 · 통보일 없으면 착수기한 미계산 · 규모 없으면 미판정. 사진은 확인 수단 없이 운영 | SFR-002 |
| 9 | 법령 조문 원문·시행일 | 법제처 국가법령정보 | **SCR-ADMIN-007** | **이미 도는 연계라 「연계 전」이 없다.** 스냅샷이 정본이고 화면에서 고치거나 요약해 덮어쓰지 않는다 · 화면은 받아 둔 스냅샷을 읽을 뿐이고 조회 시점에 법제처를 부르지 않는다 | SFR-014 |
| 10 | 알림 외부 채널(SMS·메일·Push) | 문자발송체계·통신사 모듈 | **SCR-ADMIN-002** §4-3 | 내부 알림으로 동작 · **외부 발송 성공을 가장하지 않는다** | SFR-017 |

**연계 대상이 아닌 것** — 도급사업 목록·공사정보는 **직접 등록이 정식 경로**다(임시 대체가 아니다). 재정 시스템은 이 시스템의 연계 대상에서 제외했다. 화면이 「연계 자료에서 가져왔다」고 말하지 않는다 — 오지 않을 자료를 기다리게 만든다.

## 4. 연계 작업을 어느 화면이 갖는가 — 상태판과 작업 화면을 섞지 않는다

| 하는 일 | 화면 |
|---|---|
| **지금 연결이 살아 있는가** (상태 · 로그 · 재시도) | **SCR-ADMIN-004 연계 관리** — 이 하나뿐 |
| 시설물 **수신·차이 검토·반영·전송·감사 이력** | SCR-FAC-004 |
| 시설물 **연계 파라미터**(기관코드·주기·하루 상한) | SCR-FAC-005 |
| 법령 **수집 결과의 내용 검토·승인** | SCR-ADMIN-007 |
| 법령 수집 **주기·인증키** | **배치 서버** — 이 시스템에 입력 화면이 없다(읽기 전용 표시만) |

- **연계 파라미터를 한곳에 모으지 않는다** — 그 연계의 규격에 매인 값이라 모으면 서로 관계없는 설정이 뒤섞이고, 어느 값이 어디에 영향을 주는지 알 수 없게 된다. 상태판은 **링크만** 갖는다.
- **재시도 창구는 연계 관리 한 곳**이고, 그 화면 안에서도 **누를 자리가 하나**다. 도메인마다 두면 한쪽이 방치된다.
- **연계 작업 화면이 없는 시스템(온나라·행정포털)의 카드에는 링크를 만들지 않는다** — 없는 곳으로 보내는 것보다 없다는 사실이 보이는 편이 낫고, 그 빈자리가 다음에 만들 화면의 목록이 된다.

## 5. 명칭 — 이 표기만 쓴다 (INT-08 확정)

| 대상 | 정식 표기 | 쓰지 말 것 |
|---|---|---|
| 조직도·SSO·인사 | **행정포털(새올)** | 「온나라 조직도」 — 실무 호칭이며 같은 것인지 **발주처 확인 대상** |
| 전자결재·문서 | **온나라** | 조직도 맥락에서 온나라를 쓰지 않는다 |
| 시설물 | **FMS** | — |
| 법령 조문 | **법제처 국가법령정보** | — |
| 파일 실물 | **파일관리(정보통신과)** | — |
| 알림 외부 채널 | **문자발송체계** | — |

같은 것을 두 이름으로 부르면 개발자가 두 연계로 세고, 발주처와의 대화에서도 서로 다른 시스템을 말하게 된다.

## 6. 프로토타입의 역할 — 예시까지다

프로토타입은 **연계를 구현하지 않는다.** 흐름과 화면이 어떻게 생겼는지 보여 주는 것이 전부이고, 그 사실을 화면이 스스로 밝힌다.

| 프로토타입이 하는 것 | 하지 않는 것 |
|---|---|
| 값이 들어왔을 때의 **화면 모습**을 예시 자료로 보여 준다 | 실제 외부 호출 |
| **미수신 상태의 표시**(`미등록`·`기록 없음`·`수신 기록 없음`)를 그대로 보여 준다 | 동기화 성공 처리 |
| 연계가 열리면 **무엇이 바뀌는지**를 화면 안내로 밝힌다 | 발송·상신의 성공 회신 |
| 예시 자료임을 「**예시 자료**」 칩으로 표시한다 | 결재완료·반려 상태 생성 |

- **법령 조문은 화면이 아니라 배치가 받아 온다** — 화면은 받아 둔 스냅샷을 읽을 뿐이며, 조회 시점에 법제처를 부르는 화면 기능을 만들지 않는다.
- 프로토타입 값과 정의서가 다르면 **정의서가 정본**이다.
