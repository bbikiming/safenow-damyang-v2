# 개발 회신 — 온나라 문서번호 CSV 정정과 처리 방식

작성 2026-10-21 · 기획 → 개발 · 대상 개발 문의 «회신에 온나라 문서번호 CSV를 가지고 계신다고 하셨는데 그게 필요합니다»

## 정정 — «부서별 확인목록 CSV»는 기획에 없습니다

원장 대조 회신(`전달-개발-기획회신-온나라문서연계-원장대조-20261021-v1.md`) 3-1에 «부서별 확인목록 CSV는 분류 담당이 갖고 있고 기획이 받아 드린다»고 썼습니다. **근거 없이 쓴 문장입니다.** 근거는 개발 질의서에 인용된 전달본 README 한 문장(«원장 문서번호는 부서별 확인목록 CSV에 보존돼 있습니다»)뿐이었고, 기획은 그 파일을 확인한 적이 없습니다. 기획 저장소와 작업 PC(다운로드·문서 폴더 전체)를 다시 찾았지만 없습니다. 그 문장을 철회합니다. 함께 드린 빈 양식(`양식-온나라문서번호-CSV-20261021.csv`, 전달본 연번 기준 4열)도 기획이 연번을 갖고 있지 않아 채울 수 없으므로 거둡니다.

## 결정 — CSV는 이렇게 처리합니다

| # | 결정 |
|---|---|
| 1 | **기획이 가진 담양군 문서등록대장 원본으로 «문서번호 대조표»를 만들어 지금 드립니다** — `대조표-온나라문서번호-20261021.csv`, 확정목록 문서 7,612건 전부(1행 = 1문서) |
| 2 | 개발은 대조표의 **원본 문서번호를 «부서 + 원본 보고일자 + 원본 문서번호»로 묶어** 온나라를 찾는 보조 키로 씁니다. 찾은 문서는 제목·보고일자로 반드시 검증합니다(원장 대조 회신 2-1 그대로) |
| 3 | 대조표의 번호는 **화면에 내지 않습니다.** 화면의 등록번호는 온나라가 돌려준 값만 씁니다(같은 회신 3-2) |
| 4 | 번호가 없는 문서(원본 없음 · 못 찾음 · 후보 여럿)는 **네 값 매칭(2-2)으로만** 갑니다. 착수는 기다리지 않습니다 |
| 5 | «원본 없음» 범위는 기획이 담양군에 **같은 형식의 문서등록대장 내려받기**를 요청합니다. 받으면 생성기를 다시 돌려 대조표를 바꿔 드리고, 개발은 데이터만 다시 올립니다 |
| 6 | 전달본의 «부서별 확인목록 CSV»는 **기다리지 않습니다.** 대조표가 그 자리를 대신합니다. 전달본 작성처에 있는지 한 번 묻고, 있으면 «원본 없음» 범위를 메우는 데 쓰되, 결과와 상관없이 1~5는 바뀌지 않습니다 |

## 1. 근거 — 이 회신의 모든 사실

| # | 사실 | 근거 | 확인 수준 |
|---|---|---|---|
| E-1 | 기획에 «부서별 확인목록 CSV»가 없다 | 기획 저장소 · 작업 PC 다운로드·문서 폴더 전체를 파일 이름(확인목록·연번배정·연번수정·문서번호)으로 검색 — 0건 | 확인 |
| E-2 | 문서번호가 든 담양군 문서등록대장 원본이 있다 (5개 부서) | `260808_담양군청_업무문서_목록` CSV 50개 — 건설과·공간재생과·공공시설사업소·물순환사업소·환경과 × 2021.07~2026.06, 430,089행. 열: 순번·문서번호·보고일자·문서구분·제목·수(발)신자·…·생산등록번호·공개구분·목록공개여부 (`docs/planning/분석-업무문서-5개년-실측-v1.md` 원자료와 같은 파일) | 확인 |
| E-3 | 재난안전과 2025의 문서번호 원본이 있다 | `(작업중) 2025_재난안전과 문서분류(5.8.)_수정.xlsx` — 안전문서·작업중·미해당 시트(문서번호 열) + 건설과·물순환사업소·산림정원과 2025 문서등록대장 시트 | 확인 |
| E-4 | 2025 대시보드 문서목록(20개 부서)에는 문서번호가 없다 | `담양군_2025_문서분류_대시보드_v5.1_260917.xlsx` 「문서목록」 머리 줄 — 연번·부서·보고일자·문서명·수발신자·문서구분·발신구분·… (문서번호 열 없음) | 확인 |
| E-5 | 원본의 «문서번호»는 처리과 등록 일련번호이고, 생산문서의 «생산등록번호» = 처리과-문서번호다 | 생산 126,539행 전부 «생산등록번호» 끝자리가 «문서번호»와 같다 | 확인 |
| E-6 | 접수문서의 «생산등록번호» 칸은 **보낸 기관의 번호**다 | 접수 303,550행 중 끝자리가 «문서번호»와 같은 행 51건. 예: 건설과 2021-12-31 접수, 생산등록번호 «도로관리과-27077», 수발신자 «용인시 도로관리과» | 확인 |
| E-7 | 접수문서의 «문서번호»가 담양군 **접수등록번호**의 일련번호다 | 같은 부서의 생산·접수가 한 번호 흐름을 쓴다(건설과 2021-12-31: 생산 37526·37525… 접수 37522·37520…). 「공공기록물 관리에 관한 법률 시행령」 제20조제1항은 접수 때도 등록번호를 부여하게 한다 | **추정** — 온나라 응답으로 확인(원장 대조 회신 9-3) |
| E-8 | «부서 + 연도 + 문서번호»는 유일하지 않다 | 412,441개 키 중 16,578개가 겹친다. 예: 공간재생과 2021 문서번호 1이 서로 다른 두 문서(2021-10-05 접수 · 2021-12-31 생산) | 겹친다는 것은 확인. 원인(조직개편 등으로 번호가 다시 시작)은 **추정** — 어느 쪽이든 이 키를 쓰지 않으면 된다. 전달본 README의 «식별키로 쓸 수 없다»와 맞는다 |
| E-9 | «부서 + 보고일자 + 문서번호»는 거의 유일하다 | 430,089행에서 25개 키만 겹친다 | 확인 |
| E-10 | 확정목록 7,612건 중 4,045건에 번호가 한 건으로 붙는다 | 생성기 실행 결과(3장) | 확인 — 규칙은 3장 |
| E-11 | 네 값이 같은 원장 행은 온나라에서 별건일 수 있다 | 대조표 «후보 여럿» 12건이 전부 서로 다른 문서번호. 예: 공공시설사업소 2022-02-11 «안전관리자 근무환경 현장 순회 점검에 따른 조치 사항 안내» → 문서번호 2646 · 666, 보낸 기관 번호는 둘 다 «자치행정과-4153»(같은 공문을 두 번 접수) | 확인 — 다만 개발이 보낸 25묶음 전체가 아니라 원본이 있는 범위의 12건 |

원장 대조 회신의 1:N 연결 결정(1-2)은 E-11로 뒷받침됩니다. 바뀌지 않습니다.

## 2. 대조표 — 드리는 파일

- 파일: `docs/planning/대조표-온나라문서번호-20261021.csv` (UTF-8 BOM · 쉼표 구분 · 7,612행)
- 생성기: `tools/build-onnara-docno-table.py` — 원본을 고치지 않고 읽기만 합니다. 행 수가 확정목록 문서 수와 다르면 파일을 쓰지 않습니다.
- 전달: 사내 채널. 매칭과 대조 기록에만 씁니다.

| 열 | 내용 |
|---|---|
| 기준연도 · 부서 · 보고일자 · 문서명 · 수발신자 · 발신구분 | 확정목록 문서 키 그대로 — 개발 서버 원장 문서(7,612건)와 이 네 값(부서·보고일자·문서명·수발신자)으로 맞물립니다 |
| 대조 결과 | 일치 / 일치(수발신자 표기 다름) / 일치(보고일자 N일 차이) / 후보 여럿 / 못 찾음 / 원본 없음 |
| 원본 문서번호 | 처리과 등록 일련번호(E-5). 후보 여럿이면 `;`로 잇는다 |
| 원본 보고일자 | 원본 행의 보고일자 — 보조 키는 **이 날짜**로 묶는다(E-9) |
| 원본 문서구분 | 생산 / 접수 |
| 담양군 생산등록번호(생산문서만) | 생산문서만 채운다(E-5). 접수문서는 빈칸 |
| 원본 생산등록번호 칸 그대로 | 원본 값 그대로. **접수문서는 보낸 기관 번호**(E-6) — 매칭 키로 쓰지 않는다 |
| 원본 파일 | 그 번호를 찾은 원본 파일·시트 |

**전달본 연번이 없는 이유** — 기획은 전달본 연번을 갖고 있지 않습니다. 개발 서버의 원장 문서도 7,612건(부서·보고일자·문서명·수발신자 키)으로 합쳐지므로(원장 대조 회신 1-1) 그 키로 맞물리면 됩니다.

## 3. 대조 결과

규칙(생성기 머리말) — 앞 단계에서 정해지면 끝:

1. 부서 + 보고일자 + 제목 + 수발신자가 같다(공백 무시)
2. 1에서 못 찾으면 부서 + 보고일자 + 제목이 같다(수발신자 표기만 다름)
3. 2에서 못 찾으면 부서 + 제목 + 수발신자가 같고 보고일자가 ±3일 안
4. **모든 단계에서 원본 문서구분(생산/접수)이 확정목록 발신구분과 같은 행만 후보로 본다** — 같은 날 같은 제목으로 요청(접수)과 회신(생산)이 함께 있는 경우가 흔하다. 이 조건을 빼면 완화 단계에서 83건이 반대쪽 문서에 붙었다
