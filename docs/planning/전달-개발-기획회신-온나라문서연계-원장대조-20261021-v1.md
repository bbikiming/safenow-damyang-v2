## 1. 문서 단위 — 7,612건, 연번은 별칭, 온나라 연결은 1:N

### 1-1. 7,612건으로 합친다

개발 서버의 원장 문서를 **부서 + 보고일자 + 문서명 + 수발신자** 기준으로 묶어 7,612건으로 맞춰 주십시오. 이 시스템의 이행 판정 정본은 확정목록이고(CLAUDE.md §5), 확정목록 「요약」·프로토타입이 모두 7,612건입니다. 개발 서버만 7,642건이면 같은 화면의 문서 수가 30건 다르게 보입니다.

| 할 것 | 내용 |
|---|---|
| 문서 | 7,612건. 키 = 부서 + 보고일자 + 문서명 + 수발신자 |
| 연번 | 전달본 연번 7,642개를 **문서에 딸린 별칭 목록**으로 보관. 25묶음 문서는 연번이 2개 이상 |
| 업무단계 | 묶은 행들의 업무단계를 합집합으로(겹치는 행은 8열이 같으니 실제로 늘지 않는다) |
| 조회 | 연번으로 문서를 찾는 기능은 그대로 — 어느 연번으로 찾아도 같은 문서가 나온다 |

### 1-2. 온나라 연결은 1:N으로 만든다 — 그래서 다시 가를 일이 없다

55행이 온나라에서 같은 문서인지 별건인지는 아직 모릅니다. 그래서 **어느 쪽이어도 구조를 바꾸지 않게** 만듭니다.

- 원장 문서 1건에 온나라 연결을 **여러 건** 붙일 수 있게 합니다.
- 25묶음 문서는 온나라에서 1건으로 찾아지면 연결 1건, 2건으로 찾아지면 연결 2건이 됩니다. 원장 쪽은 손대지 않습니다.
- **연번과 온나라 번호를 짝짓지 않습니다.** 네 값이 같은 행끼리는 어느 번호가 어느 연번인지 근거가 없습니다. 연결은 문서 단위로만 붙습니다.
- 이행 판정은 «그 할 일에 서류가 있는가»라 연결이 1건이든 2건이든 결과가 같습니다.

## 2. 매칭 절차

문서마다 아래 순서로 돌립니다. 한 단계에서 결론이 나면 다음 단계로 가지 않습니다. 상태 이름은 회신 v2 7장의 내부 상태입니다.

### 2-1. 1단계 — 문서번호로 찾기 (CSV 번호가 있는 문서만)

1. CSV의 원장 문서번호로 온나라 문서를 찾습니다(경로 A는 문서등록대장 상세검색 `docNo` · 부서 · 보고일자 조건, 경로 B는 로컬 색인 대조 — 2-4).
2. 찾은 문서를 **반드시 검증**합니다 — 보고일자가 같고 제목이 같아야 합니다(공백·괄호 차이는 정규화해서 비교).
3. 검증을 통과하면 연결합니다(매칭 방법 = «번호»). 검증에 실패하거나 찾지 못하면 **버리지 말고 2단계로** 넘깁니다. 실패 사유(«번호로 못 찾음» / «번호로 찾았으나 제목·일자 불일치»)는 기록합니다.

CSV 번호가 어떤 값인지(담양군 등록번호인지, 접수문서는 보낸 기관 번호인지)는 이 단계가 스스로 걸러 냅니다. 엉뚱한 번호면 검증에서 떨어져 2단계로 가므로, **번호의 뜻을 미리 알지 못해도 구현에 지장이 없습니다.** 2단계로 넘어간 건수가 곧 «그 번호를 키로 쓸 수 없었던 건수»입니다.

### 2-2. 2단계 — 네 값으로 찾기

1. 보고일자와 제목으로 후보를 뽑습니다(어느 서비스로 뽑는지는 2-4의 경로를 따릅니다).
2. 생산·접수 구분(`rcvFlag`)이 원장의 발신구분과 맞는 후보만 남깁니다.
3. 후보가 문서의 연번 수와 **같은 수**로 남으면 → 전부 연결합니다(매칭 방법 = «네 값»). 일반 문서는 1건, 25묶음 문서는 2건 이상입니다.
4. 후보가 그보다 많으면 → 후보마다 `getDocumentView`로 수발신자(`apprRecvVo`·`docSendInfoVo`)를 대조해 걸러 낸 뒤 3번을 다시 봅니다.
5. 그래도 수가 맞지 않으면 → **매칭 실패**. 후보 목록(온나라 문서ID·제목·보고일자)을 기록하고 연결하지 않습니다.

### 2-3. 결과 상태

| 결과 | 상태 |
|---|---|
| 1단계 또는 2단계에서 연결 | 매칭 성공 (매칭 방법 · 일치한 기준 · 조회 시각 기록) |
| 후보 수가 맞지 않음 | 매칭 실패 (후보 목록 기록) |
| 후보 0건 | 원문 확인 불가 |
| 권한 오류 응답(`INI1001`·`SIF1002` 등) | 열람 제한 |
| 그 밖의 오류 응답 | 조회 오류 — 연계 관리 재시도 대상 |

화면 표시는 회신 v2 3·7장 그대로입니다 — 번호가 보이는 것은 «매칭 성공 + 공개 문서»뿐이고, 나머지는 전부 «등록번호 미표시».

### 2-4. 후보를 어디서 뽑나 — 조회 경로는 갈아 끼울 수 있게

2-1·2-2는 부서별 문서등록대장(`getDctByDeptidListView`)으로 후보를 뽑는다고 적었습니다. 그런데 이 서비스의 요청 항목에는 **부서를 지정하는 칸이 없습니다** — «부서별»이 로그인한 계정의 부서를 뜻할 가능성이 큽니다. 그 경우 한 계정으로는 자기 부서 문서만 찾을 수 있습니다. 확인 결과와 상관없이 착수할 수 있도록 경로를 셋으로 정합니다.

**구현 원칙 — 후보를 뽑는 부분과 맞추는 부분을 나눕니다.** 2-1~2-3의 매칭 규칙(번호 검증 · 연번 수와 후보 수 비교 · 수발신자 대조 · 상태 판정)은 «후보 목록»만 받아 돌게 만들고, 후보를 어디서 가져오는지는 갈아 끼울 수 있게 합니다. 경로가 바뀌어도 매칭 코드는 바뀌지 않습니다.

| 경로 | 언제 | 후보 조회 | 번호 단계(2-1) |
|---|---|---|---|
| **A. 부서별 문서등록대장** | 한 계정으로 다른 부서 문서가 조회될 때, 또는 부서별 계정을 받았을 때 | `getDctByDeptidListView` — 부서·보고일자 하루·제목 | 상세검색 `docNo`로 조회 |
| **B. 문서목록공개 (대체)** | 부서별 조회가 로그인 부서로 한정되고, 부서별 계정이 아직 없을 때 | `getDocListForOpen` — 기관 전체를 7일 창으로 대상 기간 전부 받아 **로컬 색인**을 만들고, 그 색인에서 부서명(`report_deptName`) · 제목(`docTitle`) · 일자로 후보를 뽑는다 | 색인의 `docNo` · `processNo`와 CSV 번호를 대조 |
| **C. 부서별 계정** | B의 수록률이 낮을 때 | 담양군을 거쳐 온나라 운영지원단에 부서별(20개) 조회 계정을 요청하고, 받으면 A로 돌린다 | A와 같음 |

**순서** — 시험 조회 첫날에 재난안전과 계정으로 **다른 부서(물순환사업소) 문서가 조회되는지**부터 봅니다.

1. 조회되면 → A로 진행합니다.
2. 안 되면 → B로 진행하고, **같은 날 C를 요청합니다**(계정 발급은 시간이 걸리므로 B의 결과를 기다리지 않습니다). 담양군 요청은 기획이 맡습니다.
3. B로 돈 결과 생산 · 접수(내부) · 접수(외부) 중 어느 하나라도 **원장 대비 찾은 비율이 낮으면**(9-1 보고로 판단) C를 받는 대로 A로 바꿔 다시 돌립니다. 낮다고 보는 기준은 보고를 보고 기획이 정합니다 — 지금 숫자를 박지 않습니다.

**경로 B에서 지킬 것**

- **목록공개 서비스가 모든 문서를 담는다는 보장이 없습니다.** 정보공개용 목록이라 접수문서나 목록 비공개 문서가 빠져 있을 수 있습니다. 색인에서 못 찾은 문서는 «원문 확인 불가»로 두되, 보고에는 **경로 B에서 못 찾은 것**으로 따로 셉니다 — A로 다시 돌릴 대상입니다.
- **날짜 기준이 다릅니다.** 목록공개는 생성일시(`create_dthms`)로 조회되고 원장은 보고일자입니다. 색인을 대상 기간보다 앞뒤로 넉넉히 받아 두고, 일자 비교는 보고일자와 생성일시의 차이를 허용 폭 안에서 봅니다. 허용 폭은 시험 조회 결과로 정하고 보고에 적어 주십시오.
- **같은 문서가 신규·수정으로 두 번 올 수 있습니다**(`IsNew`). 색인은 온나라 문서ID로 한 건씩만 둡니다.
- **수발신자 대조(2-2의 4번)는 `getDocumentView`가 다른 부서 문서도 열어 줄 때만** 합니다. 권한 오류가 나면 그 단계를 건너뛰고, 후보 수가 맞지 않으면 매칭 실패로 둡니다 — 수발신자 없이 짐작으로 고르지 않습니다.
- 색인은 매칭에만 씁니다. 색인에만 있고 원장에 없는 온나라 문서는 화면·내려받기 어디에도 싣지 않고, 매칭이 끝나면 연결된 문서 외에는 보관하지 않습니다 — 맞춰지지 않은 문서는 들이지 않는다는 결정(회신 v2 2장)과 같습니다. 기관 전체 목록에는 비공개 문서의 제목도 섞여 오므로 특히 지켜야 합니다.

## 3. 문서번호 CSV — 기획이 드리는 것과 쓰는 법

### 3-1. 기획이 드리는 것

전달본 README가 말한 «부서별 확인목록 CSV»는 전달본·확정목록을 만든 분류 담당(㈜다온플레이스)이 갖고 있습니다. 기획이 받아 아래 형식으로 드립니다.

| 열 | 내용 |
|---|---|
| 기준연도 | 전달본과 같은 값 |
| 연번 | 전달본 연번 — 1-1의 별칭과 맞물리는 키 |
| 부서 | 전달본과 같은 값 |
| 원장 문서번호 | 확인목록에 보존된 값 그대로(가공하지 않음) |

- 7,642행, 이 네 열만 드립니다. 확인목록의 다른 열은 넘기지 않습니다.
- **이 문서와 별도 파일로 드립니다.** 양식은 [`양식-온나라문서번호-CSV-20261021.csv`](양식-온나라문서번호-CSV-20261021.csv)(머리 줄만 있는 빈 양식)이고, 분류 담당이 이 양식에 채운 파일을 기획이 받아 그대로 전달합니다. 파일 이름은 `담양군_원장문서번호_전달본연번_YYMMDD.csv`로 합니다.

**양식 작성 규칙** — 분류 담당에게도 같은 내용을 전달합니다.

| 항목 | 규칙 |
|---|---|
| 머리 줄 | `기준연도,연번,부서,원장 문서번호` — 이름·순서를 바꾸지 않는다 |
| 행 | 전달본 한 행 = 한 행. 7,642행. 번호가 없는 행도 빼지 않는다 |
| 키 | **기준연도 + 연번**. 연번만으로는 연도를 넘어 겹칠 수 있어 둘을 함께 쓴다 |
| 기준연도 | 네 자리 숫자(예: 2025) |
| 연번 | 전달본의 연번 그대로. 다시 매기지 않는다 |
| 부서 | 전달본의 부서 표기 그대로(대조용 — 줄여 쓰거나 조직도 이름으로 바꾸지 않는다) |
| 원장 문서번호 | 확인목록에 있는 값을 **한 글자도 바꾸지 않고** 넣는다(하이픈·공백·앞자리 0 포함). 값이 없으면 **빈칸**(«없음»·«-» 같은 글자를 넣지 않는다). 한 행에 번호가 둘 이상이면 `;`로 잇는다 |
| 형식 | UTF-8(BOM 포함), 쉼표 구분. 값에 쉼표가 있으면 큰따옴표로 감싼다. 엑셀에서 저장할 때 «CSV UTF-8» 형식을 고른다 — 번호가 숫자로 바뀌어 앞자리 0이 사라지지 않게 원장 문서번호 열은 텍스트로 둔다 |
| 확인 | 넘기기 전에 행 수가 7,642인지, 기준연도+연번이 겹치는 행이 없는지 본다 |

- 전달은 사내 채널로만 합니다. 매칭과 대조 기록에만 쓰고, 다른 화면이나 내려받기에 싣지 않습니다.
- 「식별키로 쓸 수 없어 새로 부여했다」는 판단의 근거도 작성처에 물어 함께 드립니다. **구현에는 필요 없습니다** — 2-1의 검증이 같은 일을 합니다. 9-1 보고를 읽을 때 참고용입니다.

### 3-2. 쓰는 법 — 세 가지 규칙

1. **보조 키로만 씁니다.** 찾는 데만 쓰고 연결의 근거는 검증 통과입니다.
2. **화면에 표시하지 않습니다.** 화면의 등록번호는 **온나라가 돌려준 값**(회신 v2 1-4 · 9-3의 칸)만 씁니다. CSV 번호가 보낸 기관 번호일 수 있어, 그대로 보이면 담양군 등록번호로 오해됩니다.
3. **CSV가 없어도 똑같이 돕니다.** CSV를 받기 전에는 전 문서가 2단계로 갑니다. 받으면 데이터만 올리고 매칭을 다시 돌립니다 — 코드를 바꾸지 않습니다.

## 5. 매칭 검증 보고(회신 v2 9-1) — 시점

- **시험 조회**는 바로 시작합니다(한 부서, 권장: 재난안전과 2025). 이때는 2단계만 돕니다.
- **보고는 CSV를 올리고 다시 돌린 결과로 한 번** 주십시오. CSV가 시험 조회가 끝날 때까지 오지 않으면, 2단계만의 결과를 먼저 보고하고 CSV 반영 뒤 같은 표로 다시 보고합니다.
- 보고에 더할 항목:

| 항목 | 왜 |
|---|---|
| 쓴 조회 경로(A / B)와, B라면 생산 · 접수(내부) · 접수(외부)별 «경로 B에서 못 찾은» 건수 · 보고일자와 생성일시의 허용 폭 | C(부서별 계정)로 다시 돌릴지 판단 |
| 매칭 방법별 성공 건수(번호 / 네 값) | CSV가 실제로 얼마나 도왔는지 |
| 1단계 실패 사유별 건수(번호로 못 찾음 / 제목·일자 불일치) — 생산 · 접수(내부) · 접수(외부) 별 | CSV 번호를 키로 쓸 수 없었던 범위 |
| 25묶음의 연결 건수 분포(연결 1건인 묶음 · 2건 이상인 묶음) | 55행이 온나라에서 같은 문서였는지 별건이었는지 — 이것으로 확정목록의 «문서의 정체» 기준을 더 볼지 기획이 판단한다 |

| T-06 | CSV 번호로 찾았는데 제목이 다른 문서 | 연결되지 않고 2단계로 넘어가며, 실패 사유가 기록된다 |
| T-07 | 화면·내려받기의 등록번호 | 온나라 응답값만 나오고 CSV 번호는 어디에도 나오지 않는다 |
| T-08 | CSV 없이 매칭 실행 → CSV 올리고 재실행 | 코드 변경 없이 두 번 다 돈다. 두 번째에 «번호» 방법 연결이 생긴다 |
| T-09 | 후보 수가 맞지 않는 문서 | 매칭 실패 · 후보 목록 기록 · 화면은 «등록번호 미표시» |
| T-10 | 후보 조회를 경로 A ↔ B로 바꿔 실행 | 매칭 코드 변경 없이 돈다. 같은 문서가 두 경로에서 같은 결과면 같은 연결이 생긴다 |
| T-11 | 경로 B 색인에만 있고 원장에 없는 온나라 문서 | 화면·내려받기 어디에도 나오지 않고, 매칭 뒤 보관되지 않는다 |
