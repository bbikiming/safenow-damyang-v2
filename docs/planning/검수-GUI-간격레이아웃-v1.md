# 검수 — GUI 간격·레이아웃 (PC 해상도)

작성 2026-08-25 · 대상 프로토타입 v2 전 화면 · 측정 1280 / 1440 / 1920px

---

## 1. 왜 봤나

«너무 붙거나 먼 곳이 없는지»를 눈이 아니라 **자로 재서** 확인했다. 화면을
스크린샷으로 보면 «괜찮아 보인다»에서 멈추기 쉽다. 실제로 잰 결과 눈으로는
지나쳤을 문제가 다섯 나왔다.

## 2. 실측

### 2-1. 간격 선언 분포 (css/style.css + css/v2.css)

`padding` · `margin` · `gap` 의 px 값을 전수로 셌다.

| | 값 |
|---|---|
| 선언 총수 | **2,450개** |
| 서로 다른 값 | 44종 |
| 4px 그리드 밖 | **342개 (14.0%)** |

그리드 밖 상위 — 5px×73 · 3px×57 · 9px×50 · 7px×48 · 11px×26 · 13px×9.

**원인은 토큰의 부재다.** 색·폰트·반경·그림자·z-index 는 토큰인데 간격만
기준이 없어, 화면마다 «대충 이 정도»를 다시 정했다.

### 2-2. 수직 리듬 (1280px · 이행 관리)

```
제목 → 부제           2px
부제 → 법령칩        10px
법령칩 → 안내        28px
안내 → 탭바          12px      ← 섹션 경계인데 블록 간격과 같다
탭바 → KPI           12px
KPI → 필터           16px      ← 섹션 경계인데 블록 간격과 같다
필터 → 칩            12px
칩 → 미니            12px
미니 → 표            10px
표 → 캡션            12px
캡션 → 범례          16px
```

**28px 하나를 빼면 전부 10~16px** 이다. 화면의 세 덩어리(맥락 / 요약 / 목록)가
같은 간격으로 나열돼 한 덩어리로 읽힌다 — 어디서 하나가 끝나는지 눈으로 알 수
없다는 뜻이다.

### 2-3. 읽기 폭 (1920px)

| 화면 | 안내 문단 한 줄 |
|---|---|
| 이행 관리 | **225자** |
| 문서 목록 | **229자** |
| 이행 목록 | **225자** |

권장은 영문 60~75자 · 한글 40~50자다. **3~4배**다. 줄이 이만큼 길면 눈이 줄
끝에서 다음 줄 첫 글자로 돌아오지 못해, 글이 있어도 읽히지 않는다.

`main` 에 `max-width` 가 없어 초광폭에서 끝없이 늘어나는 것이 원인이다.

### 2-4. 컨트롤 높이 (1280px · 한 화면 안)

`28 · 32 · 34 · 36 · 40 · 41 · 43px` 일곱 가지가 섞여 있었다. 문제는 종류가
많은 것 자체가 아니라 **한 줄에 서는 것끼리 다른 것**이다.

| 자리 | 왼쪽 | 오른쪽 | 차이 |
|---|---|---|---|
| 필터 바 | 검색 입력 43px | 버튼 34px | **9px** |
| 제목 줄 | 연도 셀렉트 43px | ＋서류 올리기 32px | **11px** |

줄이 하나뿐인데 밑변이 안 맞으면 그것만으로 화면이 흐트러져 보인다.

### 2-5. 브레이크포인트

`@media (max-width: 1599px)` 가 있었다 — §8 표준(1280/1024/768/560) 밖의
**다섯 번째** 다. 1600px 이상에서만 셸이 «특대»로 벌어졌다.

| | ≥1600 | 1024~1599 |
|---|---|---|
| 본문 패딩 | 30px **55px** | 28px 32px |
| 사이드바 | 282px | 240px |
| 페이지 제목 | 26px | 22px |

그런데 특대 쪽이 오히려 헐거워, 1920px 에서 **본문 여백만 커지고 읽기 폭은 더
나빠졌다.**

## 3. 조치

### 3-1. 토큰 신설 (`css/style.css :root`)

```
--sp-0-5:2  --sp-1:4  --sp-1-5:6  --sp-2:8  --sp-2-5:10  --sp-3:12
--sp-3-5:14 --sp-4:16 --sp-5:20   --sp-6:24 --sp-7:28    --sp-8:32
--sp-10:40  --sp-12:48

--stack-tight:8   --stack-base:16   --stack-section:28
--ctl-sm:32       --ctl-md:36       --ctl-lg:40
--measure:820px   --content-max:1680px
```

4px 그리드. 6·10·14px 은 실사용이 많아(각 302·343·176회) 반 단계로 뒀다.

### 3-2. 수직 위계 3티어 적용

| | 조치 후 |
|---|---|
| 법령칩 → 안내 | 28 (섹션) |
| 안내 → 탭바 | **12 → 28** (섹션) |
| 탭바 → KPI | 12 (블록) |
| KPI → 필터 | **16 → 28** (섹션) |
| 필터 → 칩 | 12 (블록) |
| 칩 → 미니 · 미니 → 표 | **12·10 → 8** (밀착) |

세 덩어리가 눈에 들어온다.

### 3-3. 읽기 폭 — **블록**에 건다

한 줄 **225자 → 84자**(한글 약 46자).

텍스트에만 걸면 안 된다 — 박스는 전폭 그대로라 **접기 버튼이 텍스트에서
1,043px 떨어진 자리**에 남는다(실측). 블록을 묶으면 버튼이 따라온다.

**표는 묶지 않는다.** 열이 많을수록 넓은 편이 낫다. 전역 `p` 에 걸면 표 안
셀·카드 안 문단까지 좁아지므로 안내·캡션 계열만 지정한다.

### 3-4. 컨트롤 높이 통일

| 자리 | 조치 후 |
|---|---|
| 필터 바 | 입력·버튼 전부 40px · 밑변 742 일치 |
| 제목 줄 | 셀렉트·버튼 전부 40px · 밑변 176 일치 |

⚠ **집행 중 회귀 1건** — `input.form-input` 이 아니라 `.form-input` 에 높이를
박았더니 `<textarea class="form-input">`(코드 5곳)이 40px 로 눌려 잘렸다.
태그로 좁혀 해결. `min-height` 로는 안 잡힌다(패딩 합이 이미 43px 이라 무시된다).

### 3-5. 브레이크포인트 4개로

1599 블록의 값을 **기본으로 올리고 블록을 없앴다.** 전 해상도가 같은 셸을 쓴다
— 본문 패딩 32px · 사이드바 240px · 제목 26px.

## 5. 남긴 것

**기존 342곳(그리드 밖 값)은 점진 치환 대상**이다. 한 번에 바꾸지 않는다 —
1px 차이는 눈에 안 보이지만 342곳을 동시에 옮기면 어딘가 깨진다(§7 «별칭 후
점진 치환»과 같은 방식). 새로 쓰는 곳은 예외 없이 토큰을 쓴다.

`.tabs`(세그먼트 컨트롤) 4px · `.sub-tabs` 4px 은 **의도된 밀집 그룹**이라
그대로 뒀다. 터치 8px 규칙을 기계적으로 적용하면 오히려 그룹이 흩어진다 —
두 탭 모두 좌우 패딩이 20px 이라 글자 사이는 44px 로 충분하다.
